# 要件定義書: Markdown表示機能

## 1. 概要

### 1.1 目的
eMtermターミナルエミュレータにおいて、独自OSC拡張（OSC 777）を使用してMarkdownコンテンツをWebViewベースでリッチに描画する機能を実装する。

### 1.2 背景
従来のターミナルエミュレータではMarkdownを整形表示するには外部ツールが必要だった。eMtermでは制御シーケンスを通じてMarkdownを直接描画することで、CLI環境でのドキュメント閲覧体験を向上させる。

### 1.3 設計思想
- **明示的な表示命令のみ**: 自動判別による誤動作を防ぐ
- **ステートレスなCLI**: SSH先からでもローカルのリッチ描画機能を呼び出せる設計
- **堅牢な隔離**: XSS対策とリソース管理でセキュリティを確保

## 2. 機能要件

### 2.1 必須要件

#### 2.1.1 OSCシーケンス処理
- [ ] OSC 777の`emterm;markdown`名前空間を認識する
- [ ] `begin`、`chunk`、`end`の3つのverbを処理する
- [ ] ST（ESC \）終端までパケットを結合するステートフルなパースを行う

#### 2.1.2 セッション管理
- [ ] `id`（UUID）によるセッション識別
- [ ] 複数の同時セッションをサポート
- [ ] `chunk`データをセッション単位で蓄積
- [ ] `end`受信時に描画をトリガー

#### 2.1.3 データ処理
- [ ] Base64エンコードされたchunkデータのデコード
- [ ] `seq`（連番）による順序保証
- [ ] デコード後のMarkdownテキスト結合

#### 2.1.4 Markdown描画
- [ ] CommonMark準拠のMarkdownパース
- [ ] 見出し（H1-H6）、段落、リスト、コードブロック、引用、表、リンク、画像参照の描画
- [ ] シンタックスハイライト対応（コードブロック）
- [ ] ターミナルテーマとの色同期

#### 2.1.5 セキュリティ
- [ ] DOMPurifyによるHTMLサニタイズ（XSS対策）
- [ ] `<script>`タグの完全遮断
- [ ] 危険な属性（onclick等）の除去

### 2.2 オプション要件

#### 2.2.1 拡張フォーマット
- [ ] GFM（GitHub Flavored Markdown）対応
- [ ] 数式表示（KaTeX/MathJax）
- [ ] Mermaid図表

#### 2.2.2 インタラクション
- [ ] リンクのクリック対応（外部ブラウザで開く）
- [ ] 画像のインライン表示（ローカルファイル参照時）
- [ ] コードブロックのコピー機能

#### 2.2.3 パフォーマンス最適化
- [ ] 仮想スクロール（画面外DOMのデタッチ）
- [ ] インクリメンタル描画（大きなドキュメント対応）

## 3. 非機能要件

### 3.1 パフォーマンス
- **描画遅延**: end受信から描画完了まで100ms以内（1KB以下のMarkdown）
- **メモリ制限**: 1セッションあたり最大2MBのデータ蓄積
- **CPU**: 描画処理がメインスレッドを16ms以上ブロックしない

### 3.2 セキュリティ
- **XSS対策**: DOMPurifyによる完全なサニタイズ
- **権限分離**: Markdown描画コンポーネントにTauri特権APIアクセス権限を与えない
- **リソース制限**: セッションサイズ上限、タイムアウトによるDoS対策

### 3.3 互換性
- **他ターミナル**: OSC 777は無視されることを前提（graceful degradation）
- **SSH経由**: リモートから送信されたシーケンスも正常処理

### 3.4 信頼性
- **タイムアウト**: `begin`後30秒以内に`end`が来ない場合はセッション破棄
- **不正シーケンス**: 不正なverb/パラメータは無視して継続
- **メモリリーク防止**: スクロールアウトしたMarkdownブロックの適切な破棄

## 4. 制約事項

### 4.1 技術的制約
- OSC 777の終端はST（ESC \）のみサポート（BELは非推奨）
- Base64エンコーディングはRFC 4648準拠
- Markdownパーサーはフロントエンド（TypeScript）で実行

### 4.2 運用上の制約
- 1セッションあたりの最大データサイズ: 2MB
- 同時アクティブセッション数: 最大10
- タイムアウト: 30秒

### 4.3 互換性制約
- OSC番号777は他のアプリケーションと競合する可能性があるため、`emterm`名前空間を必須とする

## 5. 用語定義

| 用語 | 定義 |
|------|------|
| OSC | Operating System Command。ESC ] で始まる制御シーケンス |
| ST | String Terminator。ESC \ で表現される終端文字 |
| セッション | `begin`から`end`までの一連のMarkdownデータ転送単位 |
| verb | OSCコマンド内の動作指定子（begin, chunk, end） |
| chunk | 分割送信されるBase64エンコードされたデータ片 |
| DOMPurify | XSS攻撃を防ぐためのHTMLサニタイズライブラリ |
| CommonMark | Markdownの標準仕様 |
| GFM | GitHub Flavored Markdown。CommonMarkの拡張 |

## 6. OSCプロトコル仕様

### 6.1 基本構造
```
ESC ] 777 ; emterm ; markdown ; <verb> ; <params> ST
```

- OSC番号: 777
- 名前空間: `emterm`
- コマンド: `markdown`
- 終端: ST（ESC \）

### 6.2 begin verb
```
ESC ] 777 ; emterm ; markdown ; begin ; id=<uuid> ; format=<fmt> ; version=<ver> ST
```

| パラメータ | 必須 | 説明 |
|-----------|------|------|
| id | Yes | セッション識別子（UUID v4） |
| format | No | Markdownフォーマット（`commonmark`, `gfm`）。デフォルト: `commonmark` |
| version | No | プロトコルバージョン。デフォルト: `1` |
| render | No | 描画モード（`inline`, `block`）。デフォルト: `block` |

### 6.3 chunk verb
```
ESC ] 777 ; emterm ; markdown ; chunk ; id=<uuid> ; seq=<n> ; data=<base64> ST
```

| パラメータ | 必須 | 説明 |
|-----------|------|------|
| id | Yes | セッション識別子 |
| seq | Yes | シーケンス番号（0始まり） |
| data | Yes | Base64エンコードされたMarkdownデータ |

### 6.4 end verb
```
ESC ] 777 ; emterm ; markdown ; end ; id=<uuid> ST
```

| パラメータ | 必須 | 説明 |
|-----------|------|------|
| id | Yes | セッション識別子 |
