# Mux ステータスバー - 要件定義書

## 1. 概要

### 1.1 背景
eMtermのmux機能にはステータスバー表示の仕組みが未完成で存在する。`MuxStatusBar` クラスや `StatusUpdate` メッセージ (0x16) がプロトコルに定義されているが、実際に接続・動作していない。一方、アプリレベルのステータスバーにはOSCレイヤーという外部プログラムからコンテンツを注入できるレイヤーが既に存在する。

### 1.2 目的
mux daemonで設定に基づいたコマンドを定期実行し、その結果をGUIのステータスバーOSCレイヤーに表示する。

### 1.3 スコープ
- mux設定に `statusbar` サブセクションを追加
- daemon側でのコマンド定期実行とテンプレート解決
- `StatusUpdate` メッセージのフォーマット変更
- フロントエンドでのStatusUpdate受信→OSCレイヤー表示
- muxモード終了時のOSCレイヤー自動クリア

## 2. ビジネス要件

### 2.1 ビジネス目標
mux使用中にシステム情報（負荷、バッテリー等）をステータスバーに表示し、tmuxのステータスバーと同等の情報表示を実現する。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| eMterm muxユーザー | mux機能を利用してターミナルセッション管理を行うユーザー |

### 2.3 期待される効果
- mux利用中にシステム状態を常時確認できる
- カスタムスクリプトによる自由な情報表示

### 3.1 ユースケース一覧

### 3.2 ユースケース詳細

#### UC01: コマンド結果をステータスバーに表示

**アクター**: muxユーザー

**事前条件**:
- settings.jsonに `mux.statusbar` が設定済み
- muxモードが開始されている

**基本フロー**:
1. daemonが起動時に設定を読み込む
2. 設定されたコマンドを定期的に実行
3. テンプレートを解決してStatusUpdateメッセージを生成
4. GUIに送信し、OSCレイヤーに表示

**代替フロー**:
- コマンドが5秒以内に完了しない場合、タイムアウトして前の値を保持
- コマンドが存在しない場合、エラーログを出力し空文字を返す
- 設定ファイルが壊れている場合、警告ログを出力しデフォルト値（無効）で動作

#### UC02: ステータスバーのカスタマイズ

**アクター**: muxユーザー

**事前条件**:
- settings.jsonが編集可能

**基本フロー**:
1. `mux.statusbar.left` / `mux.statusbar.right` にテンプレート文字列を設定
2. `mux.statusbar.commands` にコマンドを登録
3. mux起動時に反映される

### 4.2 機能詳細

#### F01: 設定項目追加

**説明**: `MuxSettings` に `statusbar` サブ構造を追加

**設定構造**:
```json
{
  "mux": {
    "statusbar": {
      "enabled": true,
      "left": "{hostname} | {cmd:load}",
      "right": "{cwd}",
      "commands": {
        "load": {
          "executable": "~/.config/emterm/scripts/load.sh",
          "interval_ms": 10000
        }
      }
    }
  }
}
```

- `enabled`: 有効/無効フラグ（デフォルト: `false`）
- `left`: 左側テンプレート文字列（デフォルト: 空）
- `right`: 右側テンプレート文字列（デフォルト: 空）
- `commands`: コマンド定義マップ（デフォルト: 空）

#### F02: テンプレートエンジン

**対応変数**:
| 変数 | 説明 | ソース |
|------|------|--------|
| `{cmd:name}` | 登録済みコマンドの実行結果 | コマンドのstdout |
| `{hostname}` | ホスト名 | `gethostname()` |
| `{cwd}` | アクティブペインのカレントディレクトリ | OSC 7（ペインごとにキャッシュ） |

#### F03: コマンド定期実行

- 登録済みexecutableのみ実行可（引数なし）
- 各コマンドは独立したタイマーで `interval_ms` 間隔に実行、結果をキャッシュ
- 5秒タイムアウト（超過時は前のキャッシュ値を保持）
- `~` のホームディレクトリ展開に対応
- テンプレート解決・StatusUpdate送信は固定1秒間隔のレンダータイマーで実行
- レンダータイマーはキャッシュ済みの値を使い、前回と差分がある場合のみ送信

#### F04: StatusUpdateプロトコル

**変更前**:
```rust
pub struct StatusUpdateMsg {
    pub session_name: String,
    pub window_names: Vec<String>,
    pub active_window_index: u32,
}
```

**変更後**:
```rust
pub struct StatusUpdateMsg {
    pub left: String,
    pub right: String,
}
```

#### F05: OSCレイヤー表示

- StatusUpdate受信時にOSCレイヤーの left/right を更新
- 既存の `OscLayerController` を使用

#### F06: mux終了時クリア

- `exitMuxMode` 時にOSCレイヤーを自動クリア

## 5. 非機能要件

### 5.1 パフォーマンス要件
- コマンド実行タイムアウト: 5秒
- StatusUpdate送信: コマンドの最小 interval_ms に準ずる

### 5.2 セキュリティ要件
- コマンド実行: `mux.statusbar.commands` に登録済みの `executable` のみ実行可
- 引数なし（単一実行ファイルのみ）
- `~` 展開後のパスを使用
- アプリ側の `statusbar_custom_commands` と同一のセキュリティモデル

### 5.3 互換性要件
- `{cwd}`: OSC 7ベース（シェルの対応に依存、クロスプラットフォーム）
- OSC 7未受信時は空文字
