# Unicode幅計算のWebAssembly化 - 要件定義書

## 1. 概要

### 1.1 背景

eMtermのフロントエンドでは、PTYから受信した文字の表示幅を判定するため、TypeScriptで実装されたUnicode幅計算関数群（`unicode.ts` ~370行）を使用している。これらの関数は`print_handler.ts`で毎文字呼び出される高頻度パスであり、パフォーマンスの改善余地がある。

### 1.2 目的

`unicode.ts`の関数群をRust/WebAssemblyに移植し、フロントエンド（WebView）内のWASMモジュールとして実行することで処理速度を向上させる。バッチ処理APIにより、JS-WASM境界のオーバーヘッドを最小化する。

### 1.3 スコープ

- `src/terminal/unicode.ts`の全関数をRust/WASMに移植
- バッチ処理API（文字列を受け取り、各コードポイントのUnicodeプロパティ分類を一括返却）
- WASMモジュールのビルドパイプライン構築（wasm-pack）
- 呼び出し元（`print_handler.ts`, `grid.ts`, `state.ts`）の統合変更
- TypeScriptフォールバックは対象外（WASM必須）

## 2. ビジネス要件

### 2.1 ビジネス目標

ターミナルエミュレータの文字処理パフォーマンスを向上させ、大量出力時のレスポンスを改善する。

### 2.2 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| eMterm利用者 | ターミナルエミュレータのエンドユーザー |
| eMterm開発者 | 将来的なWASM拡張（State全体WASM化等）の基盤として利用 |

### 2.3 期待される効果

- Unicode幅計算処理の1.5-2倍高速化
- JS-WASM境界越えの最小化（バッチ処理による）
- 将来のWASM拡張に向けたビルドパイプラインとパターンの確立

## 3. ユースケース

### 3.1 ユースケース一覧

| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | 文字出力時のUnicodeプロパティ分類 | print_handler | 高 |
| UC02 | セル生成時の文字幅判定 | grid.ts | 高 |
| UC03 | graphemeバッファフラッシュ時の絵文字判定 | state.ts | 中 |
| UC04 | 文字列全体の表示幅計算 | stringWidth利用箇所 | 中 |

### 3.2 ユースケース詳細

#### UC01: 文字出力時のUnicodeプロパティ分類

**アクター**: print_handler.ts

**事前条件**:
- WASMモジュールが初期化済み

**基本フロー**:
1. PTYから文字列データを受信
2. WASMバッチAPIに文字列を渡す
3. 各コードポイントのプロパティ分類（幅、結合文字、絵文字等）をUint8Arrayで受け取る
4. JSでプロパティ配列を参照しながら各文字を順次処理

**事後条件**:
- 全文字のUnicodeプロパティが正しく判定される

### 4.2 機能詳細

#### F01: WASMクレート基盤

**説明**: `wasm/`ディレクトリにRustクレートを作成し、wasm-packでビルドできるようにする。

**ディレクトリ構成**:
```
emterm/
├── wasm/                    # WASMクレート
│   ├── Cargo.toml           # wasm-bindgen依存
│   ├── src/
│   │   ├── lib.rs           # #[wasm_bindgen] exports
│   │   └── unicode.rs       # Unicode幅計算実装
│   ├── tests/               # Rustユニットテスト
│   └── pkg/                 # wasm-pack生成物（.gitignore対象）
├── src/
│   └── terminal/
│       └── wasm/            # WASM glueコード
│           ├── loader.ts    # WASMモジュール初期化
│           └── unicode.ts   # 型付きインターフェース（re-export）
```

#### F02: Unicode幅計算（Rust実装）

**移植対象関数**:

| TypeScript関数 | Rust関数 | 説明 |
|----------------|----------|------|
| `charWidth(char)` | `char_width(cp: u32) -> u8` | コードポイントの表示幅（0/1/2） |
| `isWideChar(char)` | `is_wide_char(cp: u32) -> bool` | 幅2かどうか |
| `isEmojiPresentation(cp)` | `is_emoji_presentation(cp: u32) -> bool` | Emoji_Presentation=Yes |
| `isExtendedPictographic(cp)` | `is_extended_pictographic(cp: u32) -> bool` | Extended_Pictographic |
| `isRegionalIndicator(cp)` | `is_regional_indicator(cp: u32) -> bool` | 地域インジケーター |
| `isSkinToneModifier(cp)` | `is_skin_tone_modifier(cp: u32) -> bool` | 肌色修飾子 |
| `isVariationSelector(cp)` | `is_variation_selector(cp: u32) -> bool` | 異体字セレクタ |
| `isCombiningChar(cp)` | `is_combining_char(cp: u32) -> bool` | 結合文字 |
| `isZeroWidth(cp)` | `is_zero_width(cp: u32) -> bool` | ゼロ幅文字 |
| `stringWidth(str)` | `string_width(text: &str) -> u32` | 文字列全体の表示幅 |

**要件**: 既存TypeScript実装と完全に同一の結果を返すこと。

#### F03: バッチ分類API

**説明**: 文字列を受け取り、各コードポイントのUnicodeプロパティを1バイトにパックして返す。

**API**:
```rust
#[wasm_bindgen]
pub fn classify_codepoints(text: &str) -> Vec<u8>
```

**返却値**: コードポイント数と同じ長さのVec<u8>。各バイトのビットレイアウト：

| ビット | プロパティ |
|--------|-----------|
| 0-1 | width (0, 1, 2) |
| 2 | is_combining |
| 3 | is_emoji_presentation |
| 4 | is_extended_pictographic |
| 5 | is_regional_indicator |
| 6 | is_skin_tone_modifier |
| 7 | is_variation_selector |

**TypeScript側定数**:
```typescript
const WIDTH_MASK       = 0b00000011;
const COMBINING        = 0b00000100;
const EMOJI_PRES       = 0b00001000;
const EXT_PICTOGRAPHIC = 0b00010000;
const REGIONAL_IND     = 0b00100000;
const SKIN_TONE        = 0b01000000;
const VARIATION_SEL    = 0b10000000;
```

#### F04: 個別関数API

`grid.ts`等で単一文字の幅が必要な場合のため、個別関数もWASMからエクスポートする。

```rust
#[wasm_bindgen]
pub fn char_width(cp: u32) -> u8

#[wasm_bindgen]
pub fn string_width(text: &str) -> u32
```

#### F05: TypeScript glueコード

**WASM初期化**:
- アプリ起動時に`wasm/pkg/`から`.wasm`ファイルをロード
- WASMモジュールのインスタンスを保持

**型付きインターフェース**:
- 既存の`unicode.ts`と同一のエクスポートシグネチャを提供
- 呼び出し元のimportパスを変更するだけで切り替え可能

#### F06: 呼び出し元統合

**変更対象ファイル**:

| ファイル | 変更内容 |
|----------|----------|
| `src/terminal/handlers/print_handler.ts` | バッチAPI使用に変更。文字列処理前に`classify_codepoints()`を呼び、結果配列を参照 |
| `src/terminal/grid.ts` | `charWidth`のimport先をWASM glueに変更 |
| `src/terminal/state.ts` | `isEmojiPresentation`のimport先をWASM glueに変更 |
| `src/terminal/index.ts` | re-exportのimport先をWASM glueに変更 |

#### F07: ビルドパイプライン

**package.json**:
```json
{
  "scripts": {
    "build:wasm": "cd wasm && wasm-pack build --target web --out-dir pkg",
    "dev": "bun run build:wasm && bun run --hot serve.ts",
    "build": "bun run build:wasm && bun build src/index.html --outdir dist --minify"
  }
}
```


## 5. 非機能要件

### 5.1 パフォーマンス要件

- Unicode幅計算が既存TypeScript実装と比較して1.5倍以上高速であること
- バッチAPIのJS-WASM境界オーバーヘッドが文字列あたり1回に抑えられること

### 5.2 互換性要件

- Unicode 17.0 / Emoji 17.0対応（既存TypeScript実装と同等）
- 既存の全テストケースがWASM版でも同一結果を返すこと

### 5.3 保守性要件

- Rustユニットテストで全Unicode範囲の判定をカバー
- 既存TypeScriptテスト（`unicode.test.ts`）をWASM版に対しても実行可能

## 6. データ要件

### 6.1 入出力データ

| 項目 | 入力 | 出力 |
|------|------|------|
| バッチ分類 | UTF-8文字列 (`&str`) | `Uint8Array`（コードポイント数分） |
| 個別幅計算 | コードポイント (`u32`) | 幅 (`u8`: 0/1/2) |
| 文字列幅計算 | UTF-8文字列 (`&str`) | 合計幅 (`u32`) |

## 7. 制約条件

### 7.1 技術的制約

- wasm-packの`--target web`でビルド（TauriのWebView向け）
- TypeScriptフォールバックなし（WASM必須）
- 既存の`unicode.ts`は削除せず、テスト参照用に残す（WASMテストの正解値として使用可能）

### 7.2 ビルド制約

- `bun tauri dev`/`bun tauri build`の前にWASMビルドが完了していること
- CI/CDでもwasm-packが利用可能であること

## 8. 想定される課題とリスク

### 8.1 技術的課題

| 課題 | 影響度 | 対応策 |
|------|--------|--------|
| JS-WASM境界のオーバーヘッド | 中 | バッチAPIで呼び出し回数を最小化 |
| wasm-packのTauri WebView互換性 | 低 | `--target web`で標準WebAPI使用 |
| WASMモジュールの初期ロード時間 | 低 | モジュールサイズが小さい（Unicode判定ロジックのみ） |

## 11. 用語定義

| 用語 | 定義 |
|------|------|
| WASM | WebAssembly。ブラウザ/WebViewで実行可能なバイナリフォーマット |
| wasm-pack | RustをWASMにコンパイルするツール |
| wasm-bindgen | Rust-JavaScript間のバインディング生成ライブラリ |
| コードポイント | Unicodeにおける文字の数値識別子（U+0000〜U+10FFFF） |
| East Asian Width | Unicodeプロパティ。文字の表示幅（F:Fullwidth, W:Wide等） |
| Emoji_Presentation | Unicodeプロパティ。デフォルトで絵文字表示される文字 |
| Extended_Pictographic | Unicodeプロパティ。絵文字シーケンスの基底文字 |
| JS-WASM boundary | JavaScriptとWASM間の関数呼び出し境界。オーバーヘッドがある |
