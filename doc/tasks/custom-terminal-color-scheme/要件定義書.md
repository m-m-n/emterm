# カスタムターミナルカラースキーム - 要件定義書

## 1. 概要

### 1.1 背景
eMtermにはターミナルカラースキームのプリセット（emterm, solarized-dark, solarized-light, monokai, dracula, nord）が用意されているが、ユーザーが自分好みの色にカスタマイズする手段がない。

### 1.2 目的
プリセットをベースにカラースキームを編集し、名前をつけてユーザー独自のカラーテーマとして保存・管理できるようにする。

### 1.3 スコープ
- ターミナルカラースキーム（ANSI 16色 + 前景/背景/カーソル/選択色）のカスタマイズ
- UIテーマプリセット（Material Design 3トークン）は対象外

## 2. ユースケース

### 2.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | プリセットから新規カラースキームを作成 | ユーザー | 高 |
| UC02 | ユーザーカラースキームを編集 | ユーザー | 高 |
| UC03 | ユーザーカラースキームを削除 | ユーザー | 中 |
| UC04 | 既存スキームを複製 | ユーザー | 中 |
| UC05 | ユーザーカラースキームをリネーム | ユーザー | 中 |

### 2.2 ユースケース詳細

#### UC01: プリセットから新規カラースキームを作成

**アクター**: ユーザー

**事前条件**:
- 設定パネルが開いている
- Terminal Color Schemeセクションが表示されている

**基本フロー**:
1. ユーザーがセレクトボックスでプリセット（例: "Dracula"）を選択する
2. カラーパレットがインラインで表示される
3. ユーザーがカラーピッカーで任意の色を変更する
4. 色の変更を検出した瞬間、プリセットの自動複製が行われる
5. 新しいユーザースキームが `{元の名前}_copy_1` という名前で作成される
6. セレクトボックスが自動的に新しいユーザースキーム `{元の名前}_copy_1 [User]` に切り替わる
7. 変更した色がリアルタイムでターミナルに反映される
8. settings.jsonに自動保存される

**代替フロー**:
- `{元の名前}_copy_1` が既に存在する場合、`_copy_2`, `_copy_3` とインクリメントする

#### UC02: ユーザーカラースキームを編集

**アクター**: ユーザー

**事前条件**:
- ユーザーカラースキームが1つ以上存在する

**基本フロー**:
1. セレクトボックスでユーザースキーム（`MyTheme [User]` と表示される）を選択する
2. カラーパレットが表示される
3. カラーピッカーで色を編集する
4. 変更がリアルタイムでターミナルに反映される
5. settings.jsonに自動保存される

#### UC03: ユーザーカラースキームを削除

**アクター**: ユーザー

**事前条件**:
- ユーザーカラースキームが選択されている

**基本フロー**:
1. ユーザースキーム選択中に「削除」ボタンをクリックする
2. スキームが削除される
3. セレクトボックスがデフォルトの "emterm" に戻る

**代替フロー**:
- プリセットが選択されている場合、削除ボタンは表示されない

#### UC04: 既存スキームを複製

**アクター**: ユーザー

**事前条件**:
- 任意のカラースキーム（プリセットまたはユーザー）が選択されている

**基本フロー**:
1. 「複製」ボタンをクリックする
2. `{元の名前}_copy_N` という名前でユーザースキームが作成される
3. セレクトボックスが新しいスキームに切り替わる

#### UC05: ユーザーカラースキームをリネーム

**アクター**: ユーザー

**事前条件**:
- ユーザーカラースキームが選択されている

**基本フロー**:
1. スキーム名の横にあるリネームUIで名前を変更する
2. セレクトボックスの表示が更新される（`新しい名前 [User]`）
3. settings.jsonに保存される

## 3. 機能要件

### 3.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | カラーパレット表示 | 選択中のスキームの全色をインライン表示 | 高 |
| F02 | カラーピッカー編集 | input type="color" + HEXテキスト入力で各色を編集 | 高 |
| F03 | 自動複製 | プリセット編集時に自動でユーザースキームを作成 | 高 |
| F04 | リアルタイムプレビュー | 編集中の色変更をリアルタイムでターミナルに反映 | 高 |
| F05 | セレクトボックス表示 | プリセットとユーザースキームを区別して表示 | 高 |
| F06 | 保存 | ユーザースキームをsettings.jsonに保存 | 高 |
| F07 | 削除 | ユーザースキームを削除 | 中 |
| F08 | 複製 | 既存スキームの複製 | 中 |
| F09 | リネーム | ユーザースキーム名の変更 | 中 |

### 3.2 機能詳細

#### F01: カラーパレット表示

**説明**: セレクトボックスの下にカラーパレットをインライン表示する

**表示項目**:
- Foreground（前景色）
- Background（背景色）
- Cursor（カーソル色）
- Selection（選択色）
- ANSI Colors 0-7（標準色: Black, Red, Green, Yellow, Blue, Magenta, Cyan, White）
- ANSI Colors 8-15（明るい色: Bright Black〜Bright White）

**レイアウト**:
- 各色は `input type="color"` + ラベルで表示
- ANSI色はグリッドレイアウトでコンパクトに並べる

#### F02: カラーピッカー編集

**説明**: `input type="color"` によるカラーピッカーと、HEXコードのテキスト入力の両方で色を編集可能

**入力形式**:
- カラーピッカー: ブラウザネイティブの `input type="color"`
- テキスト入力: `#RRGGBB` 形式のHEXコード

#### F03: 自動複製

**説明**: プリセットのカラーパレットを編集した瞬間に、自動的にユーザースキームとして複製する

**命名規則**:
- `{元のプリセット名}_copy_1`
- 既に `_copy_N` が存在する場合、`N+1` にインクリメント
- 例: dracula_copy_1, dracula_copy_2

#### F05: セレクトボックス表示

**表示形式**:
- プリセット: `eMterm`, `Solarized Dark`, `Monokai` 等（そのまま）
- ユーザースキーム: `{ユーザー設定名} [User]`
- 例: `dracula_copy_1 [User]`, `MyCustomTheme [User]`

**並び順**:
1. プリセット（固定順: emterm, solarized-dark, solarized-light, monokai, dracula, nord）
2. ユーザースキーム（作成順）

#### F06: 保存

**保存先**: 既存の `settings.json` 内の `AppSettings`

**データ構造**:
- `AppSettings` に `custom_color_schemes` フィールドを追加
- 各スキームは `ColorSchemePreset` と同じ構造に `name` フィールドを持つ
- `terminal_color_scheme` フィールドでユーザースキーム名も指定可能

## 4. 非機能要件

### 4.1 パフォーマンス要件
- カラーピッカーの色変更からターミナルへの反映まで16ms以内（1フレーム以内）

### 4.2 互換性要件
- 既存の `settings.json`（`custom_color_schemes` フィールドなし）を読み込んでもエラーにならない
- Rust側の `serde(default)` により、フィールド追加時も後方互換性を維持

## 5. UI/UX要件

### 5.1 カラーエディタ配置
- 設定パネルの「Theme & Color」サブセクション内、Terminal Color Schemeセレクトボックスの下にインライン表示

### 5.2 操作ボタン
- ユーザースキーム選択時: 「削除」「複製」ボタンを表示
- プリセット選択時: 「複製」ボタンのみ表示
- リネーム: インライン編集可能なテキストフィールド（ユーザースキーム選択時のみ）

## 6. データ要件

### 6.1 データモデル

**UserColorScheme** (TypeScript):
```typescript
interface UserColorScheme {
  name: string;
  foreground: string;  // HEX "#RRGGBB"
  background: string;
  cursor: string;
  selection: string;
  ansi_colors: string[];  // 16色の HEX配列
}
```

**settings.json の追加フィールド**:
```json
{
  "terminal_color_scheme": "dracula_copy_1",
  "custom_color_schemes": [
    {
      "name": "dracula_copy_1",
      "foreground": "#f8f8f2",
      "background": "#282a36",
      "cursor": "#f8f8f2",
      "selection": "#44475a",
      "ansi_colors": ["#21222c", "#ff5555", ...]
    }
  ]
}
```

### 6.2 色のフォーマット
- ユーザースキームの色は `#RRGGBB` HEX文字列で保存
- 内部的にはRgb構造体との相互変換を行う

## 7. 制約条件

### 7.1 技術的制約
- フロントエンドはVanilla TypeScript（フレームワークなし）
- カラーピッカーはブラウザネイティブの `input type="color"` を使用
- 保存先は既存の `settings.json` に統合

### 7.2 既存コードとの整合性
- `ColorSchemePreset` インターフェース（`src/terminal/colors.ts`）と互換性のある構造にする
- `applyTerminalColorScheme()` 関数をユーザースキームにも対応させる
- Rust側の `AppSettings` struct に `custom_color_schemes` フィールドを追加

### 8.1 受け入れ基準
- [ ] セレクトボックスでプリセットとユーザースキームが区別して表示される

- [ ] プリセット選択時にカラーパレットが表示される
- [ ] カラーピッカーとHEXテキスト入力の両方で色を編集できる

- [ ] 自動複製の命名規則が `_copy_N` のインクリメントに従う
- [ ] 色の変更がリアルタイムでターミナルに反映される
- [ ] ユーザースキームがsettings.jsonに正しく保存・読み込みできる
