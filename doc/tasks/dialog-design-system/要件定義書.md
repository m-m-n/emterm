# 要件定義書: ダイアログのデザインシステム策定

## 1. 概要

eMterm のダイアログ (modal dialog) が、ネイティブ egui 側と子 WebView (HTML/CSS) 側でバラバラに実装されており、見た目・キー操作・ボタン規約が統一されていない。本タスクは:

1. 既存の Material Design 3 (MD3) ベース設計資産 (`doc/UI-DESIGN-GUIDELINES.yaml`, `src-tauri/src/ui/md3.rs`, `src-tauri/web-shared/styles.css`) を拡張し、ダイアログのデザインシステムを正規化する
2. 既存ダイアログをそのデザインシステムに沿って書き換える
3. 今後のダイアログ追加時に「共通基盤を経由しないと作れない」状態にする

## 2. 背景

### 2.1 現状の問題

`tmp/dialog-design-system-audit.md` で報告された問題:

- ネイティブ egui ダイアログ 5 箇所すべてで Window 設定 (`collapsible(false).resizable(false).anchor(...)`) がコピペされている
- 主アクションのボタンラベル粒度がバラバラ (`OK` vs 「アップロード」「上書き」「閉じる」)
- Enter キーの扱いが暗黙ルール (テキスト入力は `lost_focus()+Enter`, それ以外は `ui.input` 直接) でしか統一されていない
- 破壊的アクションのボタン色分けが無く、Overwrite と Close guard で Enter キーの破壊性扱いが揃っていない
- 初回フォーカスのルールが存在せず、Move ダイアログで `DragValue` の↑↓が効かない事故が直近発生した
- 子 WebView 側は `profile-editor-*` のクラス名を `ssh-editor` がそのまま流用しており、共通基盤として抽出されていない
- ネイティブと WebView でデザイントークンが分離している

### 2.2 既存資産

すでに存在する以下を活用する:

| ファイル | 役割 |
|---|---|
| `doc/UI-DESIGN-GUIDELINES.yaml` | MD3 トークン + 既存コンポーネントの記述的仕様 (現状は descriptive で normative ではない) |
| `src-tauri/src/ui/md3.rs` | ネイティブ egui 用 MD3 色トークン (5 プリセット × dark/light の `Palette`) |
| `src-tauri/web-shared/styles.css` の `:root` | CSS 側 MD3 トークン (color/shape/motion) |
| `src-tauri/src/ui/profile_selector.rs` | ネイティブ側で既に MD3 風 (Frame + Shadow + Rounding) の手動実装をしているリファレンス |
| `src-tauri/web-shared/styles/settings-panel.css` の `.profile-editor-*` | 子 WebView 側ダイアログの既存 CSS (流用可能) |

これらを「ばらばらだが活かせる素材」として再編する。

## 3. 目的・達成したいこと

- ダイアログ周りの見た目・キー操作・ボタン規約を統一する
- ネイティブと子 WebView の両側で、同じデザインシステム (= yaml 上の同一トークン群) を SSOT として参照する
- 新規ダイアログ追加時に共通基盤を経由する設計にし、再びチグハグになる原因を構造的に塞ぐ

## 4. 対象ユーザー

開発者 (本人) と将来このコードベースに触れる人。エンドユーザーへの影響は「ダイアログの見た目と挙動が整う」副次的な改善のみ。

## 5. スコープ

### 5.1 含むもの

- `doc/UI-DESIGN-GUIDELINES.yaml` を拡張し、ダイアログ用の規範的 (normative) なトークン・コンポーネント仕様を追加する
- 不足トークンの追加: typography を CSS 変数化、elevation トークン、`--md-sys-color-surface-variant` の定義 (既知 issue 解消)
- ダイアログ共通ヘルパの作成
    - ネイティブ Rust: `src-tauri/src/ui/dialog/` モジュール
    - 子 WebView TS: `src-tauri/web-shared/dialog/` モジュール
- 既存ダイアログ全件 (計 8 件) のリファクタリング
    - ネイティブ: `mux_dialogs.rs::draw_rename`, `draw_move`, `render/mod.rs` の upload / overwrite / close_guard, `profile_selector.rs`
    - WebView: `profile-editor.ts`, `ssh-editor.ts`
- 破壊的アクション・主アクション・キャンセルアクションの色分け規約
- Enter / Esc / Tab / 初回フォーカスの規約
- ボタンラベル規約 (具体的な動詞ラベルを必須化)
- yaml と実装のドリフトを防ぐための単体テスト追加

### 5.2 含まないもの

- ダイアログ以外のコンポーネント (tabs, navigation, text-fields 単体, settings-panel 全体) の再設計
    - ただし `--md-sys-color-surface-variant` 等トークン側の修正は副次的に他コンポーネントに影響する。これは許容する
- WebView 用に新規ライブラリを導入すること (no framework, vanilla TS を維持)
- ダイアログ用のアニメーション拡充 (現状の `--md-motion-*` の範囲で済ます)
- 既存 dist ファイル (`src-tauri/{viewer,settings}/dist/`) に残存している `.link-confirm-dialog-*` 等のデッドコード CSS の整理 (別タスク)

## 6. 機能要件

### FR1: デザインシステム yaml の拡張

既存 `doc/UI-DESIGN-GUIDELINES.yaml` に以下を追加・更新する:

- `tokens.typography` を CSS 変数として `:root` から参照できる形に整理 (`--md-sys-typescale-title-large-size` 等の命名で CSS 側を生やす)
- `tokens.elevation` を新設 (dialog 用 elevation-3 相当の box-shadow 値)
- `tokens.color-roles` に `error-container` / `on-error-container` / `surface-variant` を正式トークンとして追記し、`:root` 定義と `md3.rs::Palette` の両方に反映する
- `dialogs:` セクションを新設 (既存 `modals:` セクションを置き換える):
    - `dialog.kinds`: `input`, `confirm`, `destructive-confirm` の 3 種別を定義
    - `dialog.anatomy`: overlay (scrim) / surface (dialog box) / header (title) / body / actions (button row)
    - `dialog.layout`: padding, gap, max-width, max-height, corner-radius
    - `dialog.actions`: button hierarchy (`primary`, `cancel`, `destructive`) と各役割で適用するトークン
    - `dialog.keyboard`: Enter / Esc / Tab の規定挙動 (種別ごと)
    - `dialog.focus`: 初回フォーカス先 (種別ごと)
    - `dialog.labels`: ラベル規約 (汎用 `OK` 禁止・キャンセルは「キャンセル」/ "Cancel" 固定)
- yaml の `known-issues` セクションから本タスクで解消するものを削除する

### FR2: ネイティブ Rust 共通ヘルパ

`src-tauri/src/ui/dialog/` モジュールを新設する。最低限以下を備える:

- `Dialog` ビルダー: `Dialog::input(title)`, `Dialog::confirm(title)`, `Dialog::destructive_confirm(title)` の 3 ファクトリ
- `.body(|ui| { ... })` でコンテンツを差し込み
- `.primary_button(label, callback)`, `.cancel_button(label, callback)` で 2 アクションを宣言
- Window 設定 (anchor, no collapse/resize) はヘルパが強制的に適用し、呼び出し側で書かない
- MD3 色トークンを `crate::ui::md3` 経由で適用 (背景, タイトル色, ボタン色)
- Enter / Esc キー処理を種別に応じて自動適用
- 初回フォーカスをビルダー側で管理 (テキスト入力時は input 要素、destructive-confirm 時は Cancel ボタン)
- 各ダイアログのアウトカム (`DialogOutcome::Confirmed`, `Cancelled`, `Pending`) を返す
- 既存の `MuxDialogOutcome` / `SftpFrameEvent` 系との橋渡しは呼び出し側責任 (このヘルパは ev タイプの enum を直接持たず、コールバックを受ける)

### FR3: 子 WebView 共通ヘルパ

`src-tauri/web-shared/dialog/dialog-shell.ts` (新規) を作る。最低限以下を提供する:

- `createDialogShell(opts: { title: string; ariaLabel: string; kind: 'input' | 'confirm' | 'destructive-confirm'; })`: 戻り値は overlay 要素 + body container + actions container + close 関数
- 共通 CSS クラス名は `dialog-overlay`, `dialog-surface`, `dialog-title`, `dialog-body`, `dialog-actions`, `dialog-button`, `dialog-button-primary`, `dialog-button-cancel`, `dialog-button-destructive` 等 (`profile-editor-*` 由来の命名は脱却)
- Esc キーでクローズ、Enter キーで kind に応じた主アクション or キャンセル
- 既存の `.profile-editor-*` クラスは段階移行のため一時的にエイリアスとして残してもよいが、本タスク完了時には全消去すること

### FR4: 既存ダイアログのリファクタリング

以下 8 件をすべて共通ヘルパ経由に書き換える:

| # | 場所 | 種別 | 主アクションラベル (確定) |
|---|---|---|---|
| 1 | `mux_dialogs.rs::draw_rename` | input | `変更` / `Rename` |
| 2 | `mux_dialogs.rs::draw_move` | input | `移動` / `Move` |
| 3 | `render/mod.rs::upload_dialog` | confirm | `アップロード` / `Upload` |
| 4 | `render/mod.rs::overwrite_dialog` | destructive-confirm | `上書き` / `Overwrite` |
| 5 | `render/mod.rs::close_guard` | destructive-confirm | `閉じる` / `Close` |
| 6 | `profile_selector.rs` | input (選択) | (リストクリック = Confirm。専用主ボタン無し) |
| 7 | `profile-editor.ts::showProfileEditor` | input | `保存` / `Save` |
| 8 | `ssh-editor.ts::showSshEditor` | input | `保存` / `Save` |

- 共通ヘルパが扱わない要素 (mux Move の `DragValue`, profile_selector のリストスクロール) は body コールバックに残してよいが、Window 設定・タイトル・ボタン・キー処理はすべてヘルパに委譲する
- ラベル「OK」は全廃する。各ダイアログの主アクションを表す動詞を必ず使う

### FR5: キーボード規約

| ダイアログ種別 | Enter | Esc | Tab | 初回フォーカス |
|---|---|---|---|---|
| input | 主アクション (テキスト入力では IME 確定を踏まない `lost_focus+Enter` 方式) | キャンセル | 入力 → 主 → キャンセル | 1 番目の入力要素 |
| confirm | 主アクション | キャンセル | 主 → キャンセル | 主アクションボタン |
| destructive-confirm | キャンセル | キャンセル | 主 → キャンセル | キャンセルボタン |

### FR6: 色分け規約

| ボタン役割 | ネイティブ egui | 子 WebView CSS |
|---|---|---|
| primary | `md3::primary()` 背景 + `md3::on_primary()` 文字 | `background: var(--md-sys-color-primary)` + `color: var(--md-sys-color-on-primary)` |
| cancel | 透明背景 + `md3::primary()` 文字 (text button) | `background: transparent` + `color: var(--md-sys-color-primary)` |
| destructive | `md3::error_container()` 背景 + `md3::on_error_container()` 文字 | `background: var(--md-sys-color-error-container)` + `color: var(--md-sys-color-on-error-container)` |

- ネイティブ側で `md3::error_container()` / `md3::on_error_container()` アクセサが現在無いので、`md3.rs::Palette` と全プリセットに `error_container` / `on_error_container` を追加する (CSS 側の対応値と一致させる)

### FR7: yaml と実装のドリフト防止

`#[cfg(test)]` のユニットテスト (Rust 側) を追加し、`doc/UI-DESIGN-GUIDELINES.yaml` をパースして以下を検証する:

- yaml の dialog 関連の主要トークン値 (corner-extra-large, scrim alpha, dialog padding 等) が `src-tauri/src/ui/dialog/` モジュール内の定数と一致すること
- yaml の color-roles で参照されている全トークンが `:root` (styles.css) に定義されていること (`--md-sys-color-surface-variant` の未定義検出に再発防止として効く)

CSS 側はパース対象として `styles.css` をテキスト読みする。`include_str!` で OK。

## 7. 非機能要件

### NFR1: 後方互換性

- 既存ダイアログのユーザー視点の挙動 (Esc でキャンセル / Enter で主アクション (destructive を除く) / OK 後の状態遷移) は維持する
- ボタンラベル変更 (`OK` → 動詞) は意図的な UX 変更として許容する

### NFR2: ビルド負荷

- 共通ヘルパは CLI ビルド (`--no-default-features`) には含めない (`#[cfg(feature = "gui")]`)
- 子 WebView 側ヘルパは追加バンドルサイズ < 5KB (minified) を目安とする

### NFR3: i18n

- 共通ヘルパは `crate::i18n::Locale` (ネイティブ) と `t()` 関数 (TS) を受け取れるようにする
- 主アクションラベルは呼び出し側が必ず ja/en の両方を渡す必要があり、片方だけの受け入れは許可しない

### NFR4: コードベース整合

- `.claude/rules/build-location.md` に従い `CARGO_TARGET_DIR=src-tauri/target` でテストすること
- `bun test` / `bun run typecheck` を通すこと

## 8. ユースケース

### UC1: 開発者が新しいダイアログを追加する

1. 必要なダイアログの種別 (input / confirm / destructive-confirm) を選択
2. `Dialog::confirm("タイトル", "Title").body(|ui| { ... }).primary_button(...).cancel_button(...)` を呼ぶ
3. Window 設定・キー処理・フォーカス・ボタン色分けは自動適用される
4. ラベルに「OK」を入れると lint (テスト) で落とす

### UC2: 子 WebView でフォーム入力ダイアログを追加する

1. `createDialogShell({ title, ariaLabel, kind: 'input' })` を呼ぶ
2. 戻り値の body container にフォーム要素を append
3. actions container に primary + cancel ボタンを append (factory 提供のクラスを使う)
4. CSS は `dialog-*` クラスから自動適用される

## 9. 制約・前提

### 9.1 技術的制約

- ネイティブ側は `egui::Window` の制限 (例: 真円コーナー描画はできるが state-layer ホバーは egui の widget visuals 経由) を受け入れる。MD3 と完全にピクセル一致させることはゴールにしない
- 子 WebView 側は vanilla TS。フレームワーク導入は不可
- システム配色 (System) のダーク/ライト切り替えは現状 dark 固定 (`md3.rs` 参照) のまま。本タスクで desktop portal 連携はしない

### 9.2 業務上の制約

- 単一開発者プロジェクト。レビュアー無し。リリースタイミングは本人裁量

## 11. 用語

- **ダイアログ**: モーダル (背景操作不可) で表示される overlay UI。ボタン or 入力を持つ
- **デザインシステム**: 色 / 形状 / 余白 / 動き / タイポグラフィのトークン + コンポーネント仕様 + 利用規約のまとまり
- **トークン**: 「primary」「surface-container-high」のような意味的な名前付き値
- **destructive-confirm**: ファイル上書き・タブ強制クローズ等、ユーザーが意図せず実行すると損失を伴う確認ダイアログ
- **SSOT**: Single Source of Truth。本タスクでは `doc/UI-DESIGN-GUIDELINES.yaml` をダイアログ関連の SSOT に昇格させる

## 14. 確認事項

### 14.1 確認済み (調査結果ベース)

- 既存 `doc/UI-DESIGN-GUIDELINES.yaml` が存在し、これを拡張する方針とする
- ネイティブ側 `md3.rs` も既存。色トークンはここに追加する
- 既存 8 件のダイアログをすべてリファクタする (段階移行ではなく一括)
- 「OK」ラベル全廃、動詞ラベル必須化
- destructive-confirm は初回フォーカスをキャンセルに置く
- yaml は SSOT。codegen はしない (manual mirror + drift test)
- ネイティブと WebView は方向性を揃える (ピクセル一致は目指さない)
- マテリアルデザインのスコープは color/shape/motion/typography/elevation/state-layer (色)

### 14.2 未確定 (実装計画フェーズで詰める)

- 共通ヘルパのモジュール構成詳細 (例: `dialog::Builder` を一つにするか、種別ごとに型分けするか)
- profile_selector の扱い: 既に MD3 風実装済みなので最小限の共通化に留めるか、完全に書き直すか
- ボタンの hover / focus state-layer の egui 上の表現方法 (egui の widget visuals override 経由 or 自前描画)
- destructive-confirm における Tab キーで primary に到達できるか (キーボードで強制実行する選択肢を残すか) — デフォルトは「到達できる、ただし初期フォーカスは Cancel」
- 子 WebView 側で `dialog-*` クラスへの一括改名と古い `.profile-editor-*` クラスの一掃を本タスク内で完了させる
