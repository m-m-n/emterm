# WASM C0 + CSI Cursor + CSI Screen ハンドラ (Sprint 3) - 要件定義書

## 1. 概要

### 1.1 背景

eMterm の WASM 化ロードマップ（Sprint 0-7）において、Sprint 2 までに Print ハンドラの WASM 化が完了した。Print は全ターミナルアクションの約 80% を占めるが、残りの高頻度アクション（C0 制御コード、カーソル移動 CSI、画面消去 CSI）は依然として TypeScript で処理されており、TS-WASM 境界コストが発生している。

### 1.2 目的

C0 制御コード（LF, CR, BS, TAB, BEL, SO, SI）、カーソル移動 CSI（CUU/CUD/CUF/CUB/CNL/CPL/CHA/CUP/VPA）、画面消去 CSI（ED, EL, ECH）を WASM 化し、全アクションの 95% 以上を WASM 内で処理可能にする。

### 1.3 スコープ

**対象:**
- C0 制御コード (`c0_handlers.ts`, ~147行)
- CSI カーソル移動 (`csi_cursor.ts`, ~161行)
- CSI 画面消去 (`csi_screen.ts`, ~95行)

**対象外:**
- CSI Edit (IL, DL, ICH, DCH) → Sprint 4
- CSI SGR → Sprint 4
- CSI Modes → Sprint 4
- CSI Scrolling (SU, SD, DECSTBM) → Sprint 4
- CSI Device (DSR, DA) → Sprint 4
- ESC ハンドラ → Sprint 5
- UnifiedBuffer / Ring Buffer → Sprint 5

## 2. ビジネス要件

### 2.1 ビジネス目標

Sprint 3 完了により、Print + C0 + カーソル CSI + 画面消去 CSI = 全アクションの 95% 以上が WASM 処理となり、体感速度が大幅に改善する。

### 2.2 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| 端末ユーザー | 高速な操作レスポンスを期待するユーザー |
| AI ツールユーザー | Claude Code 等の大量出力を行うツールのユーザー |

### 2.3 期待される効果

- 全アクションの 95% 以上が WASM 内で完結
- C0/CSI 処理の TS-WASM 境界コスト消滅
- ED/EL/ECH のバッチ化による erase 操作の高速化

## 3. ユースケース

### 3.1 ユースケース一覧

| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | C0 制御コード処理 | PTYバックエンド | 高 |
| UC02 | カーソル移動 | PTYバックエンド | 高 |
| UC03 | 画面消去 | PTYバックエンド | 高 |

### 3.2 ユースケース詳細

#### UC01: C0 制御コード処理

**アクター**: PTY バックエンド → ANSI パーサー → Execute アクション

**基本フロー**:
1. PTY が C0 制御コード (0x00-0x1F) を出力
2. Rust バックエンドが Execute アクションとしてパース
3. TS processAction が WASM handle_execute(byte) を呼び出し
4. WASM 内で制御コードを処理（LF, CR, BS, TAB, BEL, SO, SI）
5. LF の場合、スクロールカウントを返し TS 側で scrollUp を実行

#### UC02: カーソル移動

**アクター**: PTY バックエンド → ANSI パーサー → CSI アクション

**基本フロー**:
1. PTY がカーソル移動 CSI シーケンスを出力
2. Rust バックエンドが Csi アクションとしてパース
3. TS processAction がパラメータを抽出し WASM の対応関数を呼び出し
4. WASM 内でカーソル位置を更新、wrapPending をクリア

#### UC03: 画面消去

**アクター**: PTY バックエンド → ANSI パーサー → CSI アクション

**基本フロー**:
1. PTY が ED/EL/ECH CSI シーケンスを出力
2. Rust バックエンドが Csi アクションとしてパース
3. TS processAction がパラメータを抽出し WASM の対応関数を呼び出し
4. WASM 内でセル消去を実行、dirty ビットを更新

## 4. 機能要件

### 4.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | C0 制御コード WASM 化 | handle_execute(byte) で BEL/BS/HT/LF/VT/FF/CR/SO/SI を処理 | 高 |
| F02 | BEL JS コールバック | extern "C" fn on_bell() で TS 側にベル通知 | 高 |
| F03 | TAB の WASM 内完結 | tab_stops (Vec<bool>) を使った次タブストップ検索 | 高 |
| F04 | CSI カーソル移動 WASM 化 | 9 種のカーソル移動 CSI を WASM 内で処理 | 高 |
| F05 | CSI 画面消去 WASM 化 | ED/EL/ECH を WASM 内で処理 | 高 |
| F06 | TS ディスパッチ更新 | processAction の Execute/Csi 分岐に WASM パスを追加 | 高 |
| F07 | JS フォールバック維持 | WASM 未初期化時は既存 TS ハンドラで処理 | 高 |

### 4.2 機能詳細

#### F01: C0 制御コード WASM 化

**対象コード:**
| バイト | 名前 | 処理内容 |
|--------|------|----------|
| 0x07 | BEL | JS コールバック呼び出し |
| 0x08 | BS | cursor.col -= 1, wrapPending = false |
| 0x09 | HT | tab_stops から次ストップ検索 |
| 0x0A | LF | line_feed (既存内部関数), wrapPending = false |
| 0x0B | VT | LF と同じ |
| 0x0C | FF | LF と同じ |
| 0x0D | CR | cursor.col = 0, wrapPending = false |
| 0x0E | SO | active_charset = 1 (G1) |
| 0x0F | SI | active_charset = 0 (G0) |

**返り値:** `u8` (スクロールカウント)。LF/VT/FF のみ 1 を返す可能性あり。

#### F02: BEL JS コールバック

WASM から JS 側に通知する最初のコールバックパターン。

```rust
#[wasm_bindgen]
extern "C" {
    fn on_bell();
}
```

TS 側で `on_bell` をグローバル関数として定義し、TerminalState の onBell コールバックを呼び出す。

#### F03: TAB の WASM 内完結

TerminalCore には既に `tab_stops: Vec<bool>` が存在する。HT 処理は WASM 内で完結させる:
1. cursor.col から右方向に tab_stops[i] == true を検索
2. 見つかったら cursor.col = i
3. 見つからなければ cursor.col = cols - 1
4. wrapPending = false

#### F04: CSI カーソル移動 WASM 化

| CSI | 名前 | WASM API |
|-----|------|----------|
| A | CursorUp | handle_cursor_up(count: u16) |
| B | CursorDown | handle_cursor_down(count: u16) |
| C | CursorForward | handle_cursor_forward(count: u16) |
| D | CursorBack | handle_cursor_back(count: u16) |
| E | CursorNextLine | handle_cursor_next_line(count: u16) |
| F | CursorPreviousLine | handle_cursor_previous_line(count: u16) |
| G | CursorHorizontalAbsolute | handle_cursor_horizontal_absolute(col: u16) |
| H | CursorPosition | handle_cursor_position(row: u16, col: u16) |
| d | CursorVerticalAbsolute | handle_cursor_vertical_absolute(row: u16) |

全関数で `wrapPending = false` を設定。パラメータは 1-indexed → 0-indexed 変換を WASM 内で実行。

#### F05: CSI 画面消去 WASM 化

| CSI | 名前 | WASM API |
|-----|------|----------|
| J | EraseInDisplay | handle_erase_in_display(mode: u8) |
| K | EraseInLine | handle_erase_in_line(mode: u8) |
| X | EraseCharacters | handle_erase_characters(count: u16) |

**mode エンコーディング:**
| mode | 値 | 意味 |
|------|----|------|
| Below | 0 | カーソル以降を消去 |
| Above | 1 | カーソル以前を消去 |
| All | 2 | 全画面消去 |
| Scrollback | 3 | スクロールバック消去（TS にフォールバック） |

ED Scrollback (mode=3) は JS 側のスクロールバック管理が必要なため、WASM からは TS にフォールバックする。

## 5. 非機能要件

### 5.1 パフォーマンス要件

- C0/CSI 処理: 1 WASM 呼び出しで完結（現在は cursor getter/setter で 2-4 回の境界越え）
- ED clearAll: 1 WASM 呼び出し（現在は rows 回のループ）
- WASM バイナリ増分: < 5KB (Sprint 2 baseline: 43.6KB)

### 5.2 互換性要件

- 全既存 TypeScript テスト通過 (1824+)
- JS フォールバック動作維持
- vttest 基本テスト変化なし

### 5.3 保守性要件

- Sprint 2 と同じパターン（return-value scroll bridge + JS fallback）を踏襲

## 6. データ要件

### 6.1 WASM TerminalCore 追加フィールド

Sprint 3 では新しいフィールドは追加しない。Sprint 2 で追加済みの `tab_stops`, `cursor`, `scroll_region_*`, `wrap_pending`, `active_charset` を活用。

## 7. 制約条件

### 7.1 技術的制約

- BEL コールバックは wasm_bindgen extern "C" パターンを使用（Sprint 3 で初導入）
- ED Scrollback は WASM 化不可（スクロールバックは JS 側管理）
- スクロール操作（buffer.scrollUp）は TS 側で実行（scrollback → JS Line 変換が必要）
- CSI パラメータの 1-indexed → 0-indexed 変換は WASM 内で実施

### 7.2 アーキテクチャ制約

- Sprint 2 の return-value scroll bridge パターンを継承
- TS 側の processAction() に WASM パスを追加する形式

## 8. 想定される課題とリスク

### 8.1 技術的課題

| 課題 | 影響度 | 対策 |
|------|--------|------|
| BEL コールバック初導入 | 中 | シンプルな引数なしコールバックで検証し、Sprint 4 以降の DSR レスポンスに応用 |
| ED Scrollback のフォールバック | 低 | mode=3 は TS 側にフォールバック（WASM は -1 等を返して TS に処理を委譲） |
| カーソル位置の二重管理 | 中 | cursor.col/row は既に WASM 委譲済み。CSI 処理も WASM 内で直接操作するため整合性向上 |
