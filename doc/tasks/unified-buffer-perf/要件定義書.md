# UnifiedBuffer パフォーマンス改善 - 要件定義書

## 1. 概要

### 1.1 背景

UnifiedBuffer実装のコードレビュー（/sdd.7-review）において、4件のパフォーマンス改善ポイントが特定された。いずれも機能的な不具合ではないが、大量のスクロールバックやリサイズ時にメモリ割り当てや不要な処理が発生する。

### 1.2 目的

不要なメモリアロケーションと処理を排除し、描画パフォーマンスとリサイズ性能を向上させる。

### 1.3 スコープ

- `unified-buffer.ts` のメソッド最適化
- `grid.ts` への `isEmpty()` メソッド追加
- `state.ts` の `getScrollbackBuffer()` を最適化するAPIの提供
- `canvas-renderer.ts` の呼び出しパターン変更

## 2. ユースケース

### 2.1 ユースケース一覧

| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | スクロールバック表示時の描画 | レンダラー | 高 |
| UC02 | ターミナルリサイズ（幅変更あり） | ユーザー | 中 |
| UC03 | ターミナルリサイズ（幅変更なし） | ユーザー | 中 |
| UC04 | リサイズ時の空行トリミング | 内部処理 | 低 |

### 2.2 ユースケース詳細

#### UC01: スクロールバック表示時の描画

**アクター**: canvas-renderer

**事前条件**:
- スクロールバックに行が存在する
- ユーザーがスクロールバックを閲覧中（scrollOffset > 0）

**現状の問題**:
1. `getScrollbackBuffer()` が呼ばれるたびにスクロールバック全行をクローンした配列を生成
2. 10,000行のスクロールバックがある場合、毎フレーム10,000個のLine.clone()が発生

**改善後のフロー**:
1. レンダラーがインデックスベースで必要な行のみにアクセス
2. `getScrollbackLine(index)` でリングバッファから直接参照を取得
3. 全行クローンは不要

#### UC02: ターミナルリサイズ（幅変更あり=reflow）

**アクター**: ユーザー

**現状の問題**:
1. `drain()` で全行を配列に取り出した後、`cloneCell()` で各セルをディープコピー
2. ドレイン後の元Line配列は破棄されるためクローンは不要

**改善後のフロー**:
1. ドレイン済み行のセルを参照移動（`cloneCell` → 直接代入）
2. 元の行は参照されなくなるため安全

#### UC03: ターミナルリサイズ（幅変更なし）

**アクター**: ユーザー

**現状の問題**:
1. `adjustRowCount()` で行数のみ変更する際にcapacityの再計算が不正確
2. デッドコードが存在（コメントアウトされたcapacity更新ロジック）

**改善後のフロー**:
1. capacity = scrollbackCapacity + newRows として正確に再計算
2. 必要に応じてリングバッファを再構築

#### UC04: リサイズ時の空行トリミング

**アクター**: 内部処理（resize, adjustRowCount）

**現状の問題**:
1. `getText().trim() === ""` で空行を判定
2. `getText()` が全セルを文字列に連結してからtrim()が新しいstringを生成

**改善後のフロー**:
1. `Line.isEmpty()` メソッドでセルを直接スキャンし、空白のみかを判定
2. 最初の非空白セルが見つかった時点で `false` を返して終了（短絡評価）

## 3. 機能要件

### 3.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | getScrollbackBuffer()廃止・インデックスアクセスへ変更 | レンダラーが全行クローンを回避し、必要な行のみアクセス | 高 |
| F02 | adjustRowCount() capacity再計算の修正 | 行数変更時にscrollback上限を正確に維持 | 中 |
| F03 | reflow時のセル参照移動 | drain後のLineは破棄されるためcloneCellを直接代入に置き換え | 中 |
| F04 | Line.isEmpty()メソッド追加 | string allocateを避ける空行判定 | 低 |

### 3.2 機能詳細

#### F01: getScrollbackBuffer()廃止・インデックスアクセスへ変更

**説明**: `state.getScrollbackBuffer()` は呼び出しごとにスクロールバック全行をクローンした配列を返す。レンダラーがスクロールバック閲覧時に毎フレーム呼び出すため、大量のスクロールバックがある場合にGC圧力が高くなる。インデックスベースのアクセスに変更し、全行クローンを廃止する。

**変更対象**:
- `canvas-renderer.ts`: `getScrollbackBuffer()` の呼び出しを `getScrollbackLine(index)` に置き換え
- `state.ts`: `getScrollbackBuffer()` を非推奨化またはレンダラーから呼び出さないようにする

#### F02: adjustRowCount() capacity再計算

**説明**: `adjustRowCount()` 内でcapacityが再計算されていないため、行数が変わってもリングバッファの容量が更新されない。これにより、行数を減らした後にスクロールバック上限が意図より大きくなる。

**変更対象**:
- `unified-buffer.ts`: `adjustRowCount()` でcapacityを `(capacity - oldRows) + newRows` として再計算

#### F03: reflow時のセル参照移動

**説明**: `resize()` メソッドのreflow処理で、`cloneCell(trimmedCells[offset + j]!)` としてセルをディープコピーしている。しかし `drain()` で取り出した行は参照が切れるため、セルのクローンは不要。直接代入に変更する。

**変更対象**:
- `unified-buffer.ts`: `resize()` 内の `cloneCell()` 呼び出しを直接代入に変更

#### F04: Line.isEmpty()メソッド追加

**説明**: 空行判定に `getText().trim() === ""` を使用している箇所が2か所（resize、adjustRowCount）ある。`getText()` は全セルの文字を連結してstringを生成し、`trim()` がさらに新しいstringを生成する。`isEmpty()` メソッドを追加して、セルを直接スキャンし早期returnで判定する。

**変更対象**:
- `grid.ts`: `Line` クラスに `isEmpty()` メソッドを追加
- `unified-buffer.ts`: `getText().trim() === ""` を `isEmpty()` に置き換え（2か所）

## 4. 非機能要件

### 4.1 パフォーマンス要件

| 指標 | 現状 | 目標 |
|------|------|------|
| スクロールバック描画時のメモリ割り当て | O(n) per frame (n=scrollback lines) | O(rows) per frame |
| reflow 10,000行 | ~500ms (Docker) | <500ms (改善しないこと) |
| isEmpty()判定 | getText()で文字列生成 | セル直接スキャン（文字列生成なし） |

### 4.2 互換性要件

- 既存のテスト（1741件）がすべてパス
- レンダラーの描画結果に変化なし（ピクセル単位で同一）
- 外部から呼ばれる公開APIのシグネチャはなるべく維持（getScrollbackBuffer()は非推奨化で残す選択肢あり）

### 4.3 保守性要件

- 各改善は独立して適用可能
- リグレッションを検出するための既存テスト + 新規テストでカバー

## 5. 制約条件

### 5.1 技術的制約

- リングバッファの参照は同期的な描画ループ内でのみ有効（非同期で保持する場合はクローンが必要）
- F03のセル参照移動は、drain()後に元の行が参照されないことが前提

### 5.2 優先順位

F01（高）> F02（中）= F03（中）> F04（低）

F01はレンダリング性能に直結するため最優先。F02/F03はリサイズ時のみ影響。F04は微小な最適化。
