# ファイルパス + 行番号のクリック対応 - 要件定義書

## 1. 概要

### 1.1 背景
Claude Codeなどのツールは `src/foo.ts:42` のようなファイルパスと行番号を含む出力を頻繁に行う。現在eMtermではURLのみがCtrl+クリックで開けるが、ファイルパスには対応していないため、ユーザーは手動でエディタを開いて該当ファイル・行に移動する必要がある。

### 1.2 目的
ターミナル出力中のファイルパス（行番号・列番号付き）をCtrl+クリックで外部エディタで直接開けるようにする。

### 1.3 スコープ
- ファイルパスパターンの検出
- 検出されたパスの視覚的表示（下線）
- Ctrl+クリックによるエディタ起動
- エディタコマンドの設定
- ファイル存在確認

## 2. ビジネス要件

### 2.1 ビジネス目標
AI開発ツールとの親和性を高め、ターミナル上でのファイルナビゲーションを効率化する。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| 開発者 | Claude Code等のAIツールを使って開発するユーザー |
| 開発者 | コンパイルエラーやテスト結果からファイルを開くユーザー |

### 2.3 期待される効果
- ファイルナビゲーションの高速化
- AI出力からのワンクリックでのファイルアクセス
- エラー出力からの迅速なデバッグ

### 3.2 ユースケース詳細

#### UC01: AIツール出力からファイルを開く

**アクター**: 開発者

**事前条件**:
- エディタコマンドが設定済み
- ファイルパス検出が有効

**基本フロー**:
1. Claude Codeが `src/foo.ts:42` を含む出力を表示
2. ファイルパスが下線付きで表示される
3. ユーザーがCtrl+クリックする
4. シェルのCWDを基準に相対パスを解決
5. ファイルの存在を確認
6. 設定されたエディタコマンドで該当ファイル・行を開く

**代替フロー**:
- ファイルが存在しない場合: 警告通知を表示

**事後条件**:
- 外部エディタで該当ファイルの該当行が開かれている

#### UC04: エディタコマンドを設定する

**アクター**: 開発者

**事前条件**:
- 設定画面を開いている

**基本フロー**:
1. Terminal > File Path Detection セクションを開く
2. エディタコマンドテンプレートを入力する
3. プレースホルダー `{file}`, `{line}`, `{col}` を含むコマンドを設定する
4. 設定が保存される

| F01 | ファイルパス検出 | ターミナル出力からファイルパスパターンを検出 | 高 |
| F02 | 視覚的表示 | 検出されたパスを下線で表示 | 高 |
| F03 | Ctrl+クリックでエディタ起動 | クリックされたパスでエディタコマンドを実行 | 高 |

### 4.2 機能詳細

#### F01: ファイルパス検出

**説明**: ターミナル出力テキストからファイルパスパターンを検出する。

**検出パターン**:

行番号が付いているパターンのみ検出する（誤検出を最小化）:

| パターン | 例 | マッチ部分 |
|----------|-----|-----------|
| 相対パス:行 | `src/foo.ts:42` | `src/foo.ts:42` |
| 相対パス:行:列 | `src/foo.ts:42:10` | `src/foo.ts:42:10` |
| 絶対パス:行 | `/home/user/foo.rs:10` | `/home/user/foo.rs:10` |
| 絶対パス:行:列 | `/home/user/foo.rs:10:5` | `/home/user/foo.rs:10:5` |
| ドット相対パス:行 | `./src/foo.ts:42` | `./src/foo.ts:42` |

**非検出パターン（誤検出の回避）**:
- 行番号なしのパス: `src/foo.ts`（URLでもなくファイルパスかどうか確実でない）
- URLパターン: `http://` や `https://` で始まるもの（既存のURL検出に任せる）
- 時刻表記: `12:30:45`（数字のみ）

**拡張子制限**: なし（行番号が付いていれば任意の拡張子を検出）

#### F02: 視覚的表示

**説明**: 検出されたファイルパスを常時下線で表示する（URLの表示と同様）。

#### F03: Ctrl+クリックでエディタ起動

**説明**: 検出されたファイルパスをCtrl+クリック（macOSではCmd+クリック）するとエディタで開く。

**処理フロー**:
1. クリック位置のテキストからファイルパスパターンを検出
2. パスが相対パスの場合、シェルのCWD（OSC 7で追跡中の`state.workingDirectory`）を基準に絶対パスに解決
3. Tauriバックエンドを呼び出してファイルの存在を確認
4. 存在する場合: テンプレートの `{file}`, `{line}`, `{col}` を置換してコマンドを実行
5. 存在しない場合: 警告通知を表示

#### F04: エディタコマンド設定

**説明**: 設定画面でエディタコマンドのテンプレートを設定できる。

**設定項目**:
- `editor_command`: string
  - デフォルト値: `code --goto {file}:{line}:{col}`
  - プレースホルダー: `{file}`（絶対パス）、`{line}`（行番号）、`{col}`（列番号、未指定時は1）
  - 空の場合: ファイルパスクリック機能を無効化

#### F05: ファイル存在確認

**説明**: Ctrl+クリック時に、解決したファイルパスの存在をバックエンドで確認する。

**存在しない場合**: 通知（既存のnotificationシステム）で警告を表示

#### F06: パス解決

**説明**: 相対パスをシェルのCWD基準で絶対パスに解決する。

- CWDソース: `TerminalState.workingDirectory`（OSC 7で設定される）
- `file://` プレフィックスがある場合は除去してパスとして使用
- CWDが未設定の場合: 相対パスをそのままエディタに渡す

## 5. 非機能要件

### 5.1 パフォーマンス要件
- ファイルパス検出: テキスト描画に影響しない程度の速度（URL検出と同等）
- クリック→エディタ起動: 体感遅延なし（数百ms以内）

### 5.2 セキュリティ要件
- コマンドインジェクション防止: パスに含まれる特殊文字を適切にエスケープ
- ファイルパスのバリデーション: パストラバーサル攻撃は、エディタ起動であるため通常のファイル操作と同レベル

## 6. UI/UX要件

### 6.1 設定画面
- Terminal カテゴリ内に「File Path Detection」セクションを追加
- 設定項目:
  - File Path Detection: ON/OFF トグル（デフォルト: ON）
  - Editor Command: テキスト入力フィールド（デフォルト: `code --goto {file}:{line}:{col}`）
  - プレースホルダーの説明テキスト: `{file}`, `{line}`, `{col}` の説明

### 6.2 ターミナル表示
- 検出されたファイルパスは下線で表示
- Ctrl+クリック時のカーソル変化: URLと同じ挙動

## 7. 制約条件

### 7.1 技術的制約
- CWDの追跡はOSC 7に依存（シェルがOSC 7を送信しない場合、相対パスの解決ができない）
- コマンド実行はTauriバックエンド経由（`Command` API）

### 7.2 既存機能との関係
- URL検出（`url-detector.ts`）を拡張する形で実装
- 既存のCtrl+クリックハンドリング（`terminal-app/index.ts`）を拡張
- `file_path_detection` と `url_detection` は独立した設定
