# Kittyプロトコル互換性改善 - 要件定義書

## 1. 概要

### 1.1 背景

eMtermはKitty Graphics Protocolをサポートしているが、外部ツール（treemd、kitten icat等）との互換性に問題がある。具体的に以下の事象が確認されている：

1. **treemdの警告表示**: treemdでマークダウンファイルを開くと「⚠ No interactive elements in this section」という警告が表示される（WezTermでは発生しない）
2. **treemdの赤背景**: 上記を修正するKitty query同期応答を実装後、treemdの画面が赤背景になる
3. **kitten icatの画像非表示**: `kitten icat`で画像が表示されない

### 1.2 目的

eMtermのKittyプロトコル互換性を改善し、以下を達成する：
- treemdが正常に表示される（警告なし、赤背景なし）
- `kitten icat`で画像がビューアー表示される
- Kittyアニメーションフレーム表示に対応する

### 1.3 スコープ

**対象**:
- Kitty Graphics Protocol query応答の同期化
- XTWINOPS (CSI 14t/16t/18t) デバイスレスポンス
- Kitty画像表示パイプラインの互換性修正
- Kittyアニメーションフレーム対応
- `kitten icat`からのKittyコマンドをビューアー表示にルーティング

**対象外**:
- ビューアーが起動しない問題（マークダウン/画像両方で発生しており別問題の可能性）→ 調査後に判断

### 2.1 ユースケース一覧

### 2.2 ユースケース詳細

#### UC01: treemdでマークダウン表示

**アクター**: ユーザー

**事前条件**:
- treemdがインストール済み
- マークダウンファイルが存在する

**基本フロー**:
1. ユーザーが `treemd README.md` を実行
2. treemdがKittyプロトコルクエリを送信（capability検出）
3. eMtermが適切なレスポンスを返す
4. treemdがマークダウンを正常にレンダリング
5. ユーザーがコンテンツを閲覧

**代替フロー**:
- Kittyプロトコルが検出されない場合、treemdはHalfblocksフォールバックを使用

**事後条件**:
- マークダウンが正常に表示される（赤背景なし、警告なし）

#### UC02: kitten icatで画像表示

**アクター**: ユーザー

**事前条件**:
- kitty toolsがインストール済み
- 画像ファイルが存在する

**基本フロー**:
1. ユーザーが `kitten icat image.png` を実行
2. kitten icatがKittyプロトコルで画像データを送信
3. eMtermがKitty画像コマンドを受信
4. eMtermが画像ビューアーオーバーレイで表示（`emterm image`と同様の動作）

**事後条件**:
- 画像がビューアーオーバーレイに表示される

## 3. 機能要件

### 3.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | Kitty query同期応答 | APC内のKitty `a=q`クエリにWASMレイヤで同期応答 | 高 |
| F02 | XTWINOPS応答 | CSI 14t/16t/18tでセル/テキストエリアサイズを応答 | 高 |
| F03 | Kitty画像パイプライン互換性 | kitten icatからのKitty画像コマンドをビューアー表示 | 高 |
| F04 | alternate buffer切り替え時のcell size同期 | alternate buffer作成時にset_cell_size_pxを呼び出す | 中 |
| F05 | Kittyアニメーションフレーム対応 | Kittyプロトコルのアニメーション制御コマンド対応 | 低 |

### 3.2 機能詳細

#### F01: Kitty query同期応答（実装済み）

**説明**: Kitty Graphics Protocolのquery (`a=q`)に対して、DA1/DSRと同じ同期パスで応答する。非同期パス（WASM→APC callback→Tauri IPC→Rust backend→event→frontend→PTY write）では応答が遅延し、crossterm等のライブラリが応答バイトを個別のキーイベントとして誤認識する。

**処理フロー**:
```
PTYデータ → WASM parser → APC検出 → try_handle_kitty_query()
→ a=q検出 → response_buffer書き込み → fire_device_response_callback
→ TS callback → PTY write（同期）
```

#### F02: XTWINOPS応答（実装済み）

**説明**: ratatui-imageはKittyレンダリングに必要なセルサイズをCSI 16tで取得する。eMtermが応答しない場合、Kittyが検出されてもHalfblocksにフォールバックするか、誤ったサイズで描画する。

**応答フォーマット**:
- CSI 14t → `ESC [ 4 ; <height_px> ; <width_px> t` （テキストエリアピクセルサイズ）
- CSI 16t → `ESC [ 6 ; <cell_height_px> ; <cell_width_px> t` （セルピクセルサイズ）
- CSI 18t → `ESC [ 8 ; <rows> ; <cols> t` （テキストエリア文字数）

#### F03: Kitty画像パイプライン互換性

**説明**: `kitten icat`からのKitty画像コマンド（`a=T`, `a=t`, `a=p`等）がeMtermの既存画像パイプラインで正しく処理され、画像ビューアーオーバーレイで表示される。

**処理フロー**:
```
PTYデータ → WASM parser → APC検出
→ a≠q → fire_apc_callback（通常パス）
→ TS handleApcCallback → Tauri invoke("process_image_data")
→ Rust KittyHandler → decode → image_event → TS handleImageEvent
→ 画像ビューアーオーバーレイ表示
```

#### F04: alternate buffer切り替え時のcell size同期

**説明**: TUIアプリ（treemd等）はCSI ?1049hでalternate bufferに切り替えた後にクエリを送信する。新しいWASMコアが作成されるが、cell_size_pxがデフォルト値（8x16）のままになり、CSI 16tの応答値が不正確になる。

#### F05: Kittyアニメーションフレーム対応

**説明**: Kittyプロトコルのアニメーション制御（`a=f` frame, `a=a` animate）に対応する。treemdがKittyモードで利用するネイティブアニメーション機能。

## 4. 非機能要件

### 4.1 パフォーマンス要件
- Kitty query応答はPTYデータ処理と同一の同期パスで行い、追加レイテンシを最小化
- capability検出の応答がタイムアウト（2000ms）内に完了すること

### 4.2 互換性要件
- treemd (ratatui-image v10.0.6+) が正常動作すること
- kitten icat が画像ビューアーで表示できること
- 既存の `emterm image` 動作に影響を与えないこと
- WezTermと同等レベルのKittyプロトコル互換性

## 5. 技術的制約

- WASMレイヤでのAPC処理は同期的（`fire_device_response_callback`）
- 画像データの非同期パス（Tauri IPC経由）は既存の設計を維持
- response_bufferは共有リソース（各デバイス応答で上書き）

## 6. 想定される課題とリスク

| 課題 | 影響度 | 対応策 |
|------|--------|--------|
| ratatui-imageがKitty検出するとKittyレンダリングを使用するが、eMtermのKittyレンダリングパイプラインとの互換性が不十分 | 高 | パイプラインのデバッグ、必要に応じてqueryに対してエラー応答を返す判断 |
| ビューアーが起動しない問題が別原因の場合、kitten icat対応がブロックされる | 中 | ビューアー問題を先に調査・修正 |
| alternate buffer切り替え時のcell size同期漏れ | 中 | buffer切り替えハンドラでset_cell_size_pxを呼び出す |

## 8. 確認事項

### 8.1 確認済み事項

- [x] treemdの警告の根本原因: Kitty query応答の遅延によりcrosstermがバイトをキーイベントとして誤認識（`i`がinteractive mode切り替え）
- [x] WezTermでtreemdが動作する理由: ratatui-image v10.0.6でWezTermをKitty/Sixel検出のブラックリストに追加
- [x] ratatui-imageのcapability検出フロー: Kitty query + DA1 + CSI 16t + DSR を一括送信、DSR応答まで読み取り
- [x] font_sizeが取得できない場合のフォールバック: Kitty検出されてもHalfblocks（DEFAULT_PICKER）に戻る
- [x] kitten icatの期待動作: emterm imageと同様のビューアー表示
- [x] Kittyアニメーション: スコープに含める
- [x] ビューアー起動問題: 調査後に判断（マークダウン/画像両方で発生、別問題の可能性）
- [x] `emterm image`の現状: 以前は画像ビューアーが起動していたが、現在は起動しない

### 8.2 未確認・保留事項

- [ ] ビューアーが起動しない根本原因の特定
- [ ] eMtermのPTYが`ws_xpixel`/`ws_ypixel`を設定しているか（tcgetwinsize fallback）
- [ ] 赤背景の正確な原因（Kittyレンダリングパイプラインの互換性 vs その他の要因）
