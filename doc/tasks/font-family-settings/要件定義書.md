# フォントファミリー設定の3分割 - 要件定義書

## 1. 概要

### 1.1 背景
現在のフォントファミリー設定は単一の `font_family` フィールドで、CSS font-family値を1つのテキスト入力欄で設定する形式。プライマリ（英数字）、セカンダリ（日本語等）、絵文字の3種類を個別に設定する手段がない。

### 1.2 目的
フォントファミリーを「プライマリ（英数字）」「セカンダリ（日本語等）」「絵文字」の3つに分離し、それぞれ個別に設定できるようにする。

### 1.3 スコープ
- 設定データ構造の変更（TypeScript型、Rust構造体）
- 設定UIの変更（1つのテキスト入力 → 3つのテキスト入力）
- フォント適用ロジックの変更（3フィールドからCSS font-familyを構築）
- i18nラベルの追加
- 後方互換性の維持（既存の `font_family` 設定からのマイグレーション）

## 2. ビジネス要件

### 2.1 ビジネス目標
英数字、日本語、絵文字それぞれに最適なフォントを個別指定できるようにする。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| eMterm利用者 | ターミナルのフォントをカスタマイズするユーザー |

## 3. 機能要件

### 3.1 設定フィールド

| フィールド | 必須 | デフォルト | 説明 |
|-----------|------|-----------|------|
| `font_family_primary` | No | `""` (monospace) | 英数字用フォント |
| `font_family_secondary` | No | `""` (省略) | 日本語等の非ASCII文字用フォント |
| `font_family_emoji` | No | `""` (省略) | 絵文字用フォント |

### 3.2 フォールバックチェーン構築ルール

CSS font-familyは以下の順序で構築する:

```
{primary}, {emoji}, {secondary}, monospace
```

- 空のフィールドはチェーンから省略する
- 全て空の場合は `monospace` のみとなる
- 例: primary=`"Fira Code"`, emoji=`""`, secondary=`"Noto Sans JP"` → `"Fira Code", "Noto Sans JP", monospace`
- 例: primary=`"JetBrains Mono"`, emoji=`"Noto Color Emoji"`, secondary=`"Noto Sans JP"` → `"JetBrains Mono", "Noto Color Emoji", "Noto Sans JP", monospace`

### 3.3 設定UI

3つのテキスト入力欄を設定パネルの「フォント」セクションに配置する:

1. **Primary Font** - 英数字フォント（placeholder: `monospace (default)`）
2. **Secondary Font** - 日本語等フォント（placeholder: 空、optional表記）
3. **Emoji Font** - 絵文字フォント（placeholder: 空、optional表記）

### 3.4 後方互換性

既存の `font_family` フィールドが設定ファイルに存在する場合:
- `font_family` の値を `font_family_primary` として扱う
- `font_family` フィールドは無視（新しい3フィールドが優先）

## 4. 非機能要件

### 4.1 パフォーマンス
- フォント変更時の再描画は現在と同等の速度を維持する

### 4.2 互換性
- 既存の設定ファイルからのマイグレーション対応

## 5. 受け入れ基準

- [ ] プライマリフォントを設定すると英数字の表示フォントが変わる
- [ ] セカンダリフォントを設定すると日本語等の表示フォントが変わる
- [ ] 絵文字フォントを設定すると絵文字の表示フォントが変わる
- [ ] 各フィールドが空の場合、フォールバックチェーンから省略される
- [ ] 全て空の場合は `monospace` にフォールバックする
- [ ] 既存の `font_family` 設定ファイルからマイグレーションできる
- [ ] 設定UIに3つの入力欄が表示される
