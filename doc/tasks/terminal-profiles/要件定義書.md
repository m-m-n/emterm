# ターミナルプロファイル機能 - 要件定義書

## 1. 概要

### 1.1 背景
eMterm は現在、シェル設定（シェルパス、引数）がグローバル設定として一律に適用される。異なるシェルや作業環境を使い分けるには、毎回設定を手動で変更する必要がある。

### 1.2 目的
名前付きのシェル関連設定セット（プロファイル）を定義し、タブ作成時にプロファイルを選択して起動できるようにする。

### 1.3 スコープ
- プロファイルのデータモデルと永続化
- プロファイル管理UI（設定画面内）
- プロファイルセレクターモーダル
- タブ作成フローへのプロファイル統合
- 既存設定との後方互換性維持

## 2. ビジネス要件

### 2.1 ビジネス目標
異なるシェル環境を効率的に使い分けられるようにし、ターミナルの利便性を向上させる。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| 一般ユーザー | 複数のシェル（bash, zsh, fish 等）を使い分けたいユーザー |
| 開発者 | プロジェクトごとに異なる環境変数・作業ディレクトリを使いたい開発者 |

### 2.3 期待される効果
- シェル環境の切り替えが1クリックで可能になる
- プロジェクトごとの作業環境を事前定義して再利用できる
- 将来のSSHクライアント機能との統合基盤を提供する

### 3.2 ユースケース詳細

#### UC01: プロファイルの作成

**アクター**: ユーザー

**事前条件**:
- 設定画面が開いている

**基本フロー**:
1. ユーザーが Terminal カテゴリの Profiles セクションを表示
2. 「追加」ボタンをクリック
3. 編集ダイアログが開く
4. プロファイル名、シェルパス、引数、環境変数、作業ディレクトリを入力
5. 保存ボタンをクリック
6. プロファイルがリストに追加される

**事後条件**:
- プロファイルが settings.json に保存される

#### UC07: +ボタンからタブ作成

**アクター**: ユーザー

**事前条件**:
- アプリケーションが起動している

**基本フロー（デフォルトプロファイル設定時）**:
1. ユーザーがタブバーの + ボタンをクリック
2. デフォルトプロファイルの設定で新規タブが開く

**基本フロー（デフォルト未設定、プロファイルあり）**:
1. ユーザーがタブバーの + ボタンをクリック
2. セレクターモーダルが表示される
3. プロファイルをリストから選択
4. 選択したプロファイルで新規タブが開く

**基本フロー（プロファイルなし）**:
1. ユーザーがタブバーの + ボタンをクリック
2. グローバル設定のシェルで新規タブが開く（現在と同じ動作）

#### UC08: キーバインドでデフォルトタブ作成

**アクター**: ユーザー

**基本フロー**:
1. ユーザーが Ctrl+Shift+T を押す
2. デフォルトプロファイルの設定で新規タブが開く
3. デフォルト未設定時はグローバル設定のシェルで開く

#### UC09: キーバインドでセレクター表示

**アクター**: ユーザー

**基本フロー**:
1. ユーザーがプロファイルセレクターのキーバインドを押す
2. セレクターモーダルが表示される
3. 上下矢印でプロファイルを選択、Enter で決定、Escape でキャンセル
4. 選択したプロファイルで新規タブが開く

## 4. 機能要件

### 4.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | プロファイルデータモデル | プロファイルの構造定義と永続化 | 高 |
| F02 | プロファイル管理UI | 設定画面でのCRUD操作 | 高 |
| F03 | プロファイルセレクターモーダル | タブ作成時のプロファイル選択UI | 高 |
| F04 | タブ作成フロー統合 | +ボタン・キーバインドとの統合 | 高 |
| F05 | プロファイル並び替え | ドラッグ&ドロップによる表示順変更 | 中 |
| F06 | プロファイル複製 | 既存プロファイルの複製 | 中 |

### 4.2 機能詳細

#### F01: プロファイルデータモデル

**説明**: プロファイルの設定項目の定義と settings.json での永続化

**データ項目**:
| 項目 | 型 | 必須 | デフォルト | 説明 |
|------|-----|------|-----------|------|
| name | string | 必須 | - | プロファイル名 |
| shell_path | string | 任意 | "" | シェルパス（空 = システムデフォルト） |
| shell_args | string[] | 任意 | [] | シェル引数 |
| env_vars | string | 任意 | "" | 環境変数（KEY=VALUE、1行1変数） |
| working_directory | string | 任意 | "" | 作業ディレクトリ（空 = ホーム） |
| is_default | bool | 必須 | false | デフォルトプロファイルフラグ |

**ビジネスルール**:
- `is_default` が true のプロファイルは最大1つ
- プロファイル名は空文字不可

#### F02: プロファイル管理UI

**説明**: 設定画面の Terminal カテゴリ内にプロファイルのサブセクションを追加

**UI構成**:
- プロファイルリスト: 各プロファイルの名前とアクションボタン（編集・複製・削除・▶起動）
- 追加ボタン: 新規プロファイル作成
- ドラッグ&ドロップ: プロファイルの並び替え
- 編集ダイアログ: プロファイル設定項目の入力フォーム

**編集ダイアログの項目**:
- プロファイル名（テキスト入力）
- シェルパス（テキスト入力）
- シェル引数（テキスト入力、カンマまたはスペース区切り）
- 環境変数（テキストエリア、KEY=VALUE 形式、1行1変数）
- 作業ディレクトリ（テキスト入力）
- デフォルトに設定（チェックボックス）

#### F03: プロファイルセレクターモーダル

**説明**: タブ作成時にプロファイルを選択するモーダルダイアログ

**UI構成**:
- プロファイル名のシンプルなリスト
- デフォルトプロファイルにマーク表示

**操作**:
- クリックで選択・即起動
- 上下矢印キーでフォーカス移動
- Enter で選択・起動
- Escape でキャンセル

#### F04: タブ作成フロー統合

**説明**: 既存のタブ作成フローにプロファイル選択を統合

**動作マトリクス**:
| 操作 | プロファイル0個 | デフォルトあり | デフォルトなし |
|------|-----------------|----------------|----------------|
| + ボタン | 現在と同じ | デフォルトで直接開く | セレクター表示 |
| Ctrl+Shift+T | 現在と同じ | デフォルトで直接開く | グローバル設定で開く |
| セレクターキーバインド | 効果なし | セレクター表示 | セレクター表示 |
| 設定画面 ▶ | - | 該当プロファイルで開く | 該当プロファイルで開く |

## 5. 非機能要件

### 5.1 パフォーマンス要件
- セレクターモーダルの表示: 100ms 以内
- プロファイル保存: 設定保存と同等の速度

### 5.2 互換性要件
- プロファイル未設定時は既存の動作を完全に維持
- 既存の settings.json にプロファイルフィールドが存在しなくても正常に動作
- グローバルの shell_path/shell_args 設定はそのまま維持

### 5.3 保守性要件
- 既存の設定パターン（`serde(default)`, `deserialize_null_default`）に従う
- 既存の設定UIパターン（セクションレンダラー、設定サービス）に従う

## 6. UI/UX要件

### 6.1 プロファイル管理UI配置
- 設定画面の Terminal カテゴリ内のサブセクションとして配置
- 既存の Terminal Behavior セクションの前に配置

### 6.2 セレクターモーダル
- 画面中央にオーバーレイ表示
- 検索機能なし
- キーボードナビゲーション対応（矢印、Enter、Escape）

### 6.3 + ボタン
- 外観の変更なし
- 動作のみプロファイル対応に変更

## 7. データ要件

### 7.1 データモデル
プロファイルは `AppSettings.profiles` として `settings.json` に保存。

```json
{
  "profiles": [
    {
      "name": "Default Shell",
      "shell_path": "",
      "shell_args": [],
      "env_vars": "",
      "working_directory": "",
      "is_default": true
    },
    {
      "name": "Fish Shell",
      "shell_path": "/usr/bin/fish",
      "shell_args": [],
      "env_vars": "TERM=xterm-256color",
      "working_directory": "~/projects",
      "is_default": false
    }
  ]
}
```

## 8. 制約条件

### 8.1 技術的制約
- Rust 側の `AppSettings` 構造体の拡張が必要
- TypeScript 側の `AppSettings` インターフェースとの同期が必要
- 既存のキーバインドシステム（`define_keybinds!` マクロ）への項目追加が必要

### 8.2 将来拡張への考慮
- SSH クライアント機能との統合を将来予定（ただし今回のスコープ外）
- プロファイルにシェル関連以外の設定（フォント、カラースキーム等）を追加する可能性（今回のスコープ外）

## 9. 想定される課題とリスク

### 9.1 技術的課題
| 課題 | 影響度 | 対応策 |
|------|--------|--------|
| PTY 生成時の環境変数パース | 中 | テキストエリアの KEY=VALUE をパースして HashMap に変換 |
| デフォルトフラグの排他制御 | 低 | 保存時に他プロファイルの is_default を false に設定 |
| ドラッグ並び替えの実装 | 中 | 既存のタブドラッグハンドラーのパターンを流用 |
