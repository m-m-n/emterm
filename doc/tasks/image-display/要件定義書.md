# 画像表示機能 要件定義書

## 1. 機能概要

eMtermターミナルエミュレータにおいて、Kitty Graphics ProtocolおよびSIXELプロトコルを通じてインライン画像を表示する機能を実装する。静止画およびアニメーションに対応し、ターミナルの低遅延性を維持しながらリッチな画像表示を実現する。

### 1.1 スコープ

- **対象**: eMtermターミナルエミュレータ側の画像表示機能
- **除外**: CLI `emterm image` コマンドの実装（別ブランチで対応）

### 1.2 設計方針

- プロトコルはKitty Graphics ProtocolとSIXELを同等にサポート
- 画像データは内部でRGBA形式に変換して保持
- 透過処理はデフォルトでテキストの下に描画
- ウィンドウリサイズ時は画像を再スケーリング
- 静止画およびアニメーションをサポート

---

## 2. 対応プロトコル

### 2.1 Kitty Graphics Protocol

Kitty Graphics Protocolは、ターミナル上でピクセルグラフィックスを表示するためのプロトコルである。APC（Application Programming Command）エスケープシーケンスを使用する。

#### 2.1.1 基本フォーマット

```
<ESC>_G<control_data>;<payload><ESC>\
```

- `<ESC>_G`: APC Graphics シーケンス開始
- `<control_data>`: カンマ区切りのkey=valueペア
- `<payload>`: Base64エンコードされたバイナリデータ
- `<ESC>\`: ST（String Terminator）

#### 2.1.2 アクション（`a` キー）

| アクション | 説明 |
|-----------|------|
| `a=t` | 画像データ送信のみ（表示しない） |
| `a=T` | 画像データ送信と同時に表示 |
| `a=p` | 送信済み画像の表示（IDで参照） |
| `a=q` | プロトコルサポートの問い合わせ |
| `a=d` | 画像の削除 |
| `a=f` | アニメーションフレームの送信 |
| `a=a` | アニメーション制御 |
| `a=c` | フレーム合成 |

#### 2.1.3 送信方式（`t` キー）

| 値 | 説明 |
|----|------|
| `d` | ダイレクト送信（エスケープコード内） |
| `f` | 通常ファイルパス |
| `t` | 一時ファイル（ターミナルが自動削除） |
| `s` | POSIX共有メモリオブジェクト |

#### 2.1.4 画像フォーマット（`f` キー）

| 値 | 説明 |
|----|------|
| `f=24` | 24ビットRGB（幅・高さ指定必須） |
| `f=32` | 32ビットRGBA（デフォルト） |
| `f=100` | PNG形式（寸法はPNGから抽出） |

#### 2.1.5 チャンク転送（`m` キー）

- `m=1`: 中間チャンク（続きあり）
- `m=0`: 最終チャンク

チャンクサイズは最大4096バイト。

#### 2.1.6 圧縮（`o` キー）

- `o=z`: RFC 1950 ZLIBデフレート圧縮

#### 2.1.7 配置パラメータ

| キー | 説明 |
|------|------|
| `i` | 画像ID（1〜4294967295） |
| `I` | 画像番号（非一意、ターミナルがIDを割り当て） |
| `p` | 配置ID |
| `c`, `r` | 表示矩形（列・行、スケーリング） |
| `x`, `y`, `w`, `h` | ソース矩形（ピクセル） |
| `X`, `Y` | セル内ピクセルオフセット |
| `z` | Z-index（負値はテキスト下に描画） |
| `C` | カーソル移動抑制フラグ |
| `U` | Unicodeプレースホルダーモード |

#### 2.1.8 削除アクション（`a=d`）

| `d` 値 | 説明 |
|--------|------|
| `a`/`A` | 全ての可視配置 |
| `i`/`I` | 指定IDの画像 |
| `c`/`C` | カーソル位置の配置 |
| `p`/`P` | 指定セルと交差する配置 |
| `r`/`R` | 指定範囲のID |
| `x`/`X` | 指定列の配置 |
| `y`/`Y` | 指定行の配置 |
| `z`/`Z` | 指定Z-indexの配置 |

大文字は画像データも解放。

#### 2.1.9 アニメーション対応

**フレーム送信（`a=f`）:**
- `Y`: 背景色（RGBA）
- `c`: 背景として使用する前フレーム番号
- `X`: 合成モード（1=置換、デフォルト=アルファブレンド）
- `z`: フレーム間隔（ミリ秒、負値=ギャップなし）

**アニメーション制御（`a=a`）:**
- `s=1`: 停止
- `s=2`: ローディングモード（追加フレーム待機）
- `s=3`: 通常ループ（`v`でループ回数指定）
- `c`: 現在フレーム設定

#### 2.1.10 レスポンスフォーマット

- 成功: `<ESC>_Gi=<id>[,p=<placement_id>];OK<ESC>\`
- 失敗: `<ESC>_Gi=<id>;ERROR:<message><ESC>\`

レスポンス抑制: `q=1`（成功抑制）、`q=2`（失敗抑制）

### 2.2 SIXEL

SIXELは、DEC社のターミナル向けビットマップグラフィックスフォーマットである。6ピクセル高×1ピクセル幅のパターンを1文字で表現する。

#### 2.2.1 基本フォーマット

```
DCS P1 ; P2 ; P3 q <sixel_data> ST
```

- `DCS`: C1制御文字（7ビット環境では`ESC P`）
- `P1`: ピクセルアスペクト比
- `P2`: 背景色処理モード
- `P3`: 水平グリッドサイズ（VT300では無視）
- `q`: SIXELコマンド識別子
- `<sixel_data>`: SIXELエンコードデータ
- `ST`: String Terminator（`ESC \`）

#### 2.2.2 パラメータ

**P1（アスペクト比）:**

| 値 | アスペクト比（垂直:水平） |
|----|------------------------|
| 省略/0/1 | 2:1（デフォルト） |
| 2 | 5:1 |
| 3/4 | 3:1 |
| 5/6 | 2:1 |
| 7/8/9 | 1:1 |

**P2（背景処理）:**

| 値 | 説明 |
|----|------|
| 0/2 | 0ピクセルは背景色で描画（デフォルト） |
| 1 | 0ピクセルは現在の色を維持 |

#### 2.2.3 SIXELデータエンコーディング

- 各SIXELデータ文字は6つの垂直ピクセルを表現
- 有効範囲: `?`（0x3F）〜 `~`（0x7E）
- バイナリ値 = 文字コード - 0x3F
- 最下位ビットが最上部ピクセル

#### 2.2.4 制御文字

| 文字 | 機能 |
|------|------|
| `!` | 繰り返し（`!Pn[char]`でPn回繰り返し） |
| `"` | ラスター属性（`"Pan;Pad;Ph;Pv`） |
| `#` | 色指定（`#Pc`または`#Pc;Pu;Px;Py;Pz`） |
| `$` | グラフィックスキャリッジリターン |
| `-` | グラフィックス改行 |

#### 2.2.5 色指定

**基本選択:** `#Pc`（色番号0〜255）

**拡張指定:** `#Pc;Pu;Px;Py;Pz`
- `Pu=1`: HLS（色相0〜360°、明度0〜100%、彩度0〜100%）
- `Pu=2`: RGB（赤・緑・青各0〜100%）

#### 2.2.6 スクロールモード（DECSDM）

- 有効化: `CSI ? 80 h`
- 無効化: `CSI ? 80 l`

## 3. 対応画像フォーマット

### 3.1 入力フォーマット

| フォーマット | 拡張子 | 対応 | 備考 |
|------------|--------|------|------|
| PNG | .png | 必須 | 透過対応 |
| JPEG | .jpg, .jpeg | 必須 | |
| GIF | .gif | 必須 | アニメーション対応 |
| WebP | .webp | オプション | アニメーション対応 |
| BMP | .bmp | オプション | |

### 3.2 内部フォーマット

- **形式**: RGBA（32ビット/ピクセル）
- **色深度**: 各チャンネル8ビット（0〜255）
- **アルファ**: 0（完全透明）〜255（完全不透明）

## 4. アニメーション対応要件

### 4.1 対応形式

- GIFアニメーション
- APNGアニメーション（オプション）
- Kitty Graphics Protocolフレームシーケンス

### 4.2 再生制御

- 再生開始/停止
- ループ回数制御
- フレームレート調整
- 特定フレームへのジャンプ

### 4.3 パフォーマンス要件

- フレームレンダリングはメインスレッドをブロックしない
- フレームバッファのプールによるメモリ効率化
- 可視領域外のアニメーションは一時停止

---

## 5. メモリ管理・ライフサイクル要件

### 5.1 ストレージクォータ

- **最大ストレージ**: 320MB（Kitty準拠）
- 新規画像追加時にクォータ超過の場合、古い画像から削除

### 5.2 画像ライフサイクル

1. **送信**: プロトコル経由でデータ受信、IDを割り当て
2. **デコード**: 非同期で画像データをRGBAにデコード
3. **配置**: 指定位置に画像を配置
4. **表示**: WebViewで描画
5. **スクロールアウト**: 可視領域外に移動した配置は非表示化
6. **削除**: 明示的な削除コマンドまたはクォータ超過で解放

### 5.3 メモリ解放トリガー

- 明示的な削除コマンド（`a=d`）
- ストレージクォータ超過
- ターミナルリセット（ESC c）
- セッション終了

### 5.4 セッション管理

- 各画像にはユニークIDを割り当て
- 同一IDの再送信は上書き
- 配置IDにより同一画像の複数配置を管理

---

## 6. ウィンドウリサイズ時の再スケーリング要件

### 6.1 リサイズ動作

- ウィンドウサイズ変更時、画像を新しいセルサイズに合わせて再スケーリング
- アスペクト比を維持
- 元画像データは保持し、表示サイズのみ変更

### 6.2 スケーリングアルゴリズム

- **縮小**: バイリニア補間
- **拡大**: バイリニア補間（ピクセルアートモード時はニアレストネイバー）

### 6.3 パフォーマンス考慮

- リサイズ中はデバウンス処理（100ms程度）
- 段階的レンダリング（低解像度→高解像度）

---

## 7. パフォーマンス要件

### 7.1 低遅延維持

- **入力遅延**: 画像処理中もタイピング遅延は10ms以内を維持
- **デコード**: 非同期処理（Web Worker等）
- **描画**: GPU加速を活用

### 7.2 スループット目標

- 4Kサイズ画像のデコード: 1秒以内
- 一般的な画像（800x600程度）のデコード: 100ms以内

### 7.3 メモリ効率

- 未使用画像データの遅延解放
- 圧縮データ保持（オプション）
- サムネイルキャッシュによる高速プレビュー

---

## 8. エラーハンドリング

### 8.1 プロトコルエラー

| エラーコード | 説明 | 対応 |
|-------------|------|------|
| EINVAL | 無効なパラメータ | エラーレスポンス返却 |
| ENOENT | 指定IDの画像が存在しない | エラーレスポンス返却 |
| ENOSPC | ストレージクォータ超過 | 古い画像を削除 |

### 8.2 デコードエラー

- 不正な画像フォーマット: プレースホルダー表示
- 破損データ: エラーログ出力、スキップ

### 8.3 メモリエラー

- メモリ不足: 最古の画像から削除を試行
- 解放失敗: 警告ログ出力

---

## 9. 制約事項

### 9.1 プラットフォーム制約

- WebView環境に依存（TauriのWebView2/WKWebView）
- 一部機能はプラットフォームごとに実装が異なる可能性

### 9.2 プロトコル制約

- 共有メモリ（`t=s`）はリモート接続時に使用不可
- ファイル送信（`t=f`, `t=t`）はローカル環境のみ

### 9.3 セキュリティ制約

- ファイルパス参照はサンドボックス内に限定
- 画像処理は隔離されたコンテキストで実行
- 悪意のあるペイロードに対する防御

### 9.4 互換性制約

- 全てのKitty Graphics Protocol機能を初期実装でサポートしない場合あり
- SIXEL色深度は256色に制限される場合あり
