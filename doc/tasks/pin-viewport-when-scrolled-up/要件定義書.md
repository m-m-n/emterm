# スクロールバック閲覧中のビューポート固定 - 要件定義書

## 1. 概要

### 1.1 背景
現在、ユーザーがスクロールアップして過去のログを閲覧している最中に PTY から新規出力が来ると、表示されているログが下方向に流れ、見ていた行が画面外に押し出される。

### 1.2 目的
スクロール位置が最下部以外の状態では、新規出力が来てもユーザーが見ている行を画面に固定する。

### 1.3 スコープ

**対象:**
- プライマリバッファのスクロールバック閲覧中の表示挙動

**対象外:**
- alt screen（vim/less 等のフルスクリーンアプリ）の挙動
- スクロールバー UI の追加変更
- 「最下部へ戻る」ボタンや視覚インジケータの追加
- スクロールバック容量設定

## 2. ビジネス要件

### 2.1 ビジネス目標
スクロールバック閲覧体験を改善する。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| 一般ターミナル利用者 | スクロールバックで過去ログを確認するユーザー |

### 2.3 期待される効果
- スクロールアップ中に新規出力が来てもログが流れない

## 3. ユースケース

### 3.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | スクロール中の新規出力でビューポート固定 | 一般利用者 | 高 |
| UC02 | スクロールバック容量超過時の押し出し | 一般利用者 | 高 |
| UC03 | 最下部へ戻った後の追従再開 | 一般利用者 | 高 |

### 3.2 ユースケース詳細

#### UC01: スクロール中の新規出力でビューポート固定

**アクター**: 一般利用者

**事前条件**:
- スクロールバックに行が存在する
- ユーザーが最下部以外までスクロールアップしている

**基本フロー**:
1. ユーザーがホイール/キーボードでスクロールアップする
2. PTY から新規出力が到着し scrollback に行が追加される
3. ユーザーが見ている行は画面上で同じ位置に表示され続ける

**事後条件**:
- 表示中の絶対行が変わらない
- スクロールオフセットは新規行数分だけ増加している

#### UC02: スクロールバック容量超過時の押し出し

**アクター**: 一般利用者

**事前条件**:
- ユーザーがスクロールバックの上限近くを閲覧している
- PTY から継続的に新規出力が来る

**基本フロー**:
1. 新規行が scrollback の容量を超えてリングバッファから古い行が消える
2. ユーザーが見ていた行が scrollback から消えた場合、画面は最上部に固定された状態で次の行が流れる

**事後条件**:
- スクロールオフセットは scrollback 上限にクランプされる
- 最上部に固定された状態で古い行が流れていく

#### UC03: 最下部へ戻った後の追従再開

**アクター**: 一般利用者

**事前条件**:
- ユーザーがスクロールアップ中

**基本フロー**:
1. ユーザーが最下部までスクロールダウンする
2. 以降の新規出力は画面下端に追従して表示される（既存挙動）

**事後条件**:
- スクロールオフセットが 0 に戻る

## 4. 機能要件

### FR1: ビューポート固定
スクロールオフセットが 0 でない状態で PTY 由来のスクロールアップ（scrollback への行押し出し）が発生したとき、表示中の絶対行が変わらないようにスクロールオフセットを新規行数分増加する。

### FR2: 最下部での追従維持
スクロールオフセットが 0 の状態では、新規出力に追従して画面下端に表示する（既存挙動を維持）。

### FR3: scrollback 上限でのクランプ
スクロールオフセットを増加させた結果、scrollback 上限を超える場合は上限にクランプする。クランプ後はビューポートが scrollback 先頭に固定され、新規行が来るたび最上部に表示されている行が流れていく。

### FR4: 対象スクロール契機
本機能は PTY 出力（およびエスケープシーケンス処理）に起因する scrollback への行追加にのみ適用する。ユーザー自身の scrollUp/scrollDown 操作（ホイール・キーボード）は従来通り `scrollOffset` を直接増減する。

### FR5: alt screen の扱い
alt screen 使用中は scrollback への行追加が発生しないため、本機能は適用されない（既存挙動と同じ）。

## 5. 非機能要件

### NFR1: パフォーマンス
キー入力レイテンシおよび PTY 出力レンダリングのフレームレートに有意な影響を与えない。

### NFR2: 互換性
既存の scrollUp/scrollDown/setScrollOffset API シグネチャを変更しない。

## 14. 確認事項

### 14.1 確認済み事項
- 最下部判定は `scrollOffset === 0`
- 「最下部でない場合の固定」は表示中の絶対行を保つこと
- 容量超過時は最上部固定で流れる
- 「最下部へ戻る」ボタンや視覚インジケータは追加しない
- alt screen は対象外
- リサイズ時の特別扱いは行わない

- なし
