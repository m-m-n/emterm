# Feature: WASM SGR + Edit/Scroll CSI + Modes + Device Response (Sprint 4)

## Overview

Port the remaining CSI handlers (SGR, Edit, Scroll, Modes, Device) from TypeScript to Rust/WebAssembly. This is Sprint 4 of the WASM migration roadmap (`tmp/wasm.md`). Combined with Sprint 3's C0/Cursor/Screen handlers, this achieves 100% CSI routing through WASM. Key architectural additions include a batch SGR API (eliminating `syncCursorAttrsToWasm()`), an action code pattern for mode switching, and a linear memory response buffer for device queries.

## Objectives

- Move SGR processing to WASM via batch API, removing `syncCursorAttrsToWasm()` entirely
- Move CSI edit operations (IL/DL/ICH/DCH) to WASM for single-call grid manipulation
- Move CSI scroll operations (SU/SD/DECSTBM) to WASM with scroll bridge pattern for SU
- Move DEC Private Mode handling to WASM with return-value action codes
- Move device response generation (DSR/DA1/DA2) to WASM with linear memory response buffer
- Achieve 100% CSI WASM routing in `handleCsiWasm()`

## User Stories

### US1: SGR via WASM Batch API

As a terminal handler, I want SGR parameters to be parsed and applied entirely within WASM, so that color/style changes require only one WASM boundary crossing and `syncCursorAttrsToWasm()` is no longer needed.

**Acceptance Criteria:**
- [ ] `core.handle_sgr(params: &[u16])` parses SGR parameters and updates cursor attrs in WASM memory
- [ ] Supports: Reset (0), Bold (1), Dim (2), Italic (3), Underline (4), Blink (5), Reverse (7), Hidden (8), Strikethrough (9)
- [ ] Supports: NormalIntensity (22), Not* resets (23-29)
- [ ] Supports: Standard foreground (30-37), extended foreground (38;5;n / 38;2;r;g;b), default foreground (39)
- [ ] Supports: Standard background (40-47), extended background (48;5;n / 48;2;r;g;b), default background (49)
- [ ] Supports: Bright foreground (90-97), Bright background (100-107)
- [ ] Empty params treated as Reset (SGR 0)
- [ ] `syncCursorAttrsToWasm()` calls removed from all call sites

### US2: CSI Edit Operations via WASM

As a terminal handler, I want IL/DL/ICH/DCH to execute entirely within WASM, so that line/character insert/delete operations complete in a single WASM call instead of multiple WasmLineProxy operations.

**Acceptance Criteria:**
- [ ] `core.handle_insert_lines(count)` inserts blank lines at cursor row within scroll region
- [ ] `core.handle_delete_lines(count)` deletes lines at cursor row within scroll region
- [ ] `core.handle_insert_characters(count)` inserts blank characters at cursor position
- [ ] `core.handle_delete_characters(count)` deletes characters at cursor position
- [ ] Operations respect scroll region boundaries (IL/DL) and row boundaries (ICH/DCH)
- [ ] Dirty rows marked correctly after operations

### US3: CSI Scroll via WASM with Scroll Bridge

As a terminal handler, I want SU/SD/DECSTBM to use WASM for grid manipulation, with a scroll bridge for SU when scrollback interaction is needed.

**Acceptance Criteria:**
- [ ] `core.handle_scroll_up(count) -> u8`: scroll region = WASM-internal (returns 0), full screen = returns count for TS scrollback
- [ ] `core.handle_scroll_down(count)`: always WASM-internal (no scrollback interaction)
- [ ] `core.handle_decstbm(top, bottom)`: sets scroll region and moves cursor to home position
- [ ] SU with scroll region correctly shifts rows and clears bottom rows
- [ ] SD correctly shifts rows down and clears top rows

### US4: DEC Private Modes via WASM with Action Codes

As a terminal handler, I want mode set/reset to use WASM for mode state management, returning action codes for side effects that require TS execution.

**Acceptance Criteria:**
- [ ] `core.handle_set_mode(mode, enable) -> u8` returns action code
- [ ] Boolean modes (DECAWM, DECOM, DECTCEM, etc.) set directly in WASM bitfield, return 0
- [ ] Buffer switch modes (47/1047/1048/1049) return appropriate action codes (1-5)
- [ ] Multi-valued modes (mouse tracking/encoding, cursor keys) return 0xFF for TS fallback
- [ ] TS executes actions (buffer switch, cursor save/restore) based on returned codes
- [ ] After processing, TS calls `syncModesFromWasm()` to update its local modes copy

### US5: Device Response via WASM Linear Memory

As a terminal handler, I want DSR/DA1/DA2 responses to be generated by WASM and returned via linear memory, so that WASM handles the format generation while TS handles PTY transmission.

**Acceptance Criteria:**
- [ ] `core.handle_device_status_report(ps) -> u8` returns response length (0 if no response)
- [ ] DSR ps=5: generates `ESC [ 0 n` (OK status)
- [ ] DSR ps=6: generates `ESC [ row ; col R` (cursor position report, 1-indexed)
- [ ] `core.handle_primary_device_attributes() -> u8` generates VT420 response
- [ ] `core.handle_secondary_device_attributes() -> u8` generates VT420 identification
- [ ] `core.get_response_ptr()` and `core.get_response_len()` expose response buffer
- [ ] TS reads response from WASM memory and calls `addPendingResponse()`

### US6: JS Fallback

As the terminal state manager, I want the JS fallback path to remain functional when WASM is unavailable.

**Acceptance Criteria:**
- [ ] When `getActiveWasmGrid()` returns null, existing TS handlers are used
- [ ] No changes to existing TS handler implementations
- [ ] All existing tests pass with and without WASM

## Technical Requirements

### Functional Requirements

#### SGR
- **FR1:** `TerminalCore.handle_sgr(params: &[u16])` parses SGR parameter array and applies attributes to cursor (fg, bg, flags) in WASM memory
- **FR2:** SGR Reset (param 0 or empty) sets cursor attrs to default (fg=null, bg=null, flags=0)
- **FR3:** SGR extended color (38/48;5;n) sets 256-color indexed; (38/48;2;r;g;b) sets TrueColor RGB
- **FR4:** After Sprint 4, `syncCursorAttrsToWasm()` is removed from all call sites (SGR, cursor restore, buffer switch, reset)

#### Edit
- **FR5:** `TerminalCore.handle_insert_lines(count: u16)` inserts blank lines at cursor row, pushing content down within scroll region. Cursor row outside region is no-op.
- **FR6:** `TerminalCore.handle_delete_lines(count: u16)` deletes lines at cursor row, pulling content up within scroll region. Cursor row outside region is no-op.
- **FR7:** `TerminalCore.handle_insert_characters(count: u16)` inserts blank characters at cursor position, shifting content right within the row. Clamped to row width.
- **FR8:** `TerminalCore.handle_delete_characters(count: u16)` deletes characters at cursor position, shifting content left within the row. Clamped to remaining characters.

#### Scroll
- **FR9:** `TerminalCore.handle_scroll_up(count: u16) -> u8` scrolls content up. Returns 0 for scroll-region-internal (WASM handles everything). Returns count for full-screen scroll (TS calls `buffer.scrollUp(count)` for scrollback).
- **FR10:** `TerminalCore.handle_scroll_down(count: u16)` scrolls content down within scroll region. Always WASM-internal (no scrollback interaction for SD).
- **FR11:** `TerminalCore.handle_decstbm(top: u16, bottom: u16)` sets scroll region (1-indexed inputs, bottom=0 means screen height) and moves cursor to (0, 0). Clears wrapPending.

#### Modes
- **FR12:** `TerminalCore.handle_set_mode(mode: u16, enable: bool) -> u8` processes a DEC private mode and returns action code:
  - 0 = no action (boolean mode set in WASM)
  - 1 = switchToAlt (mode 47/1047)
  - 2 = saveAndSwitchToAlt (mode 1049, enable=true)
  - 3 = switchToMain (mode 47/1047 disable, mode 1049 disable)
  - 4 = saveCursor (mode 1048, enable=true)
  - 5 = restoreCursor (mode 1048, enable=false)
  - 0xFF = TS fallback (mouse modes 1000/1002/1003/1004/1005/1006, cursor keys mode 1, bracketed paste 2004)
- **FR13:** Boolean modes (DECAWM=7, DECOM=6, DECTCEM=25, ATT160=12, DECSCNM=5, DECCOLM=3) are set directly in WASM modes bitfield

#### Device Response
- **FR14:** `TerminalCore.handle_device_status_report(ps: u8) -> u8` generates response bytes and returns length
- **FR15:** `TerminalCore.handle_primary_device_attributes() -> u8` generates `ESC[?64;1;2;6;22c` and returns length
- **FR16:** `TerminalCore.handle_secondary_device_attributes() -> u8` generates `ESC[>41;1;0c` and returns length
- **FR17:** `TerminalCore.get_response_ptr() -> *const u8` and `get_response_len() -> u32` expose internal response buffer

#### Integration
- **FR18:** `handleCsiWasm()` updated to handle all CSI actions: Sgr, InsertLines, DeleteLines, InsertCharacters, DeleteCharacters, ScrollUp, ScrollDown, SetScrollRegion, SetMode, ResetMode, DeviceStatusReport, PrimaryDeviceAttributes, SecondaryDeviceAttributes
- **FR19:** JS fallback: when `getActiveWasmGrid()` is null, existing TS handlers are used unchanged

#### syncCursorAttrsToWasm Removal
- **FR20:** Remove `syncCursorAttrsToWasm()` method and all call sites. After SGR WASM化, cursor attrs are always managed in WASM memory. Cursor restore and buffer switch paths must use WASM-native cursor state management instead.

### Non-Functional Requirements

- **NFR1 - Performance:** SGR batch processing in 1 WASM call (vs. current: parseSgrParams + N applySgrAttr + syncCursorAttrsToWasm)
- **NFR2 - Performance:** IL/DL/ICH/DCH in 1 WASM call (vs. current: N WasmLineProxy operations)
- **NFR3 - Compatibility:** All existing TypeScript tests pass (1824+)
- **NFR4 - Binary size:** WASM binary increase < 10KB over Sprint 3 baseline (45.8KB)
- **NFR5 - Compatibility:** JS fallback path unchanged and functional
- **NFR6 - Compatibility:** vttest basic tests unchanged

### Data Flow

**SGR Batch Path (WASM):**
```
TS processAction("Csi", { action: "Sgr", data: [38, 5, 196] })
  → grid = getActiveWasmGrid()
  → grid.core.handle_sgr(new Uint16Array([38, 5, 196]))  [single WASM call]
  → done (no syncCursorAttrsToWasm needed)

  Inside WASM handle_sgr:
    → parse param 38 → extended foreground
    → parse param 5 → indexed mode
    → parse param 196 → index
    → self.cursor.fg = PackedColor::indexed(196)
```

**IL Insert Lines Path (WASM):**
```
TS processAction("Csi", { action: "InsertLines", data: 3 })
  → grid.core.handle_insert_lines(3)  [single WASM call]
  → done

  Inside WASM handle_insert_lines:
    → (top, bottom) = get_effective_scroll_region()
    → if cursor.row < top || cursor.row > bottom: return
    → shift rows down within region (cursor.row..bottom-3 → cursor.row+3..bottom)
    → clear rows cursor.row..cursor.row+2
    → mark dirty
```

**SU Scroll Up Path (WASM, scroll region):**
```
TS processAction("Csi", { action: "ScrollUp", data: 2 })
  → result = grid.core.handle_scroll_up(2)
  → result == 0 → handled by WASM, done

  Inside WASM handle_scroll_up:
    → scroll region is (5, 20) → not full screen
    → shift rows up within region (7..20 → 5..18)
    → clear rows 19..20
    → mark dirty(5..20)
    → return 0
```

**SU Scroll Up Path (WASM, full screen → scroll bridge):**
```
TS processAction("Csi", { action: "ScrollUp", data: 2 })
  → result = grid.core.handle_scroll_up(2)
  → result == 2 → need scrollback
  → buffer.scrollUp(2)  [existing scroll bridge]
  → buffer.scrollUp handles: wasmRowToLine × 2 → push scrollback → WASM shift → clear
```

**SetMode Path (WASM, action code):**
```
TS processAction("Csi", { action: "SetMode", data: [1049] })
  → const actions = []
  → for mode of [1049]:
    → code = grid.core.handle_set_mode(1049, true)  [single WASM call]
    → code == 2 → actions.push("saveAndSwitchToAlt")
  → execute actions: state.switchToAlternateBuffer(true)
  → syncModesFromWasm()  [update TS modes copy]

  Inside WASM handle_set_mode:
    → mode 1049, enable=true
    → return MODE_SAVE_AND_SWITCH_TO_ALT (2)
```

**SetMode Path (WASM, boolean mode):**
```
TS processAction("Csi", { action: "SetMode", data: [7] })
  → code = grid.core.handle_set_mode(7, true)  [single WASM call]
  → code == 0 → no action needed
  → syncModesFromWasm()

  Inside WASM handle_set_mode:
    → mode 7 (DECAWM)
    → self.modes |= MODE_AUTO_WRAP
    → return 0
```

**SetMode Path (TS fallback for multi-valued modes):**
```
TS processAction("Csi", { action: "SetMode", data: [1000] })
  → code = grid.core.handle_set_mode(1000, true)
  → code == 0xFF → TS fallback
  → setDecPrivateMode(state.modes, 1000, true)  [existing TS logic]
  → syncModesToWasm()
```

**DSR Cursor Position Report Path (WASM):**
```
TS processAction("Csi", { action: "DeviceStatusReport", data: 6 })
  → len = grid.core.handle_device_status_report(6)
  → len > 0
  → ptr = grid.core.get_response_ptr()
  → response = new Uint8Array(wasmMemory, ptr, len)
  → state.addPendingResponse(response.slice())  [copy before WASM may reuse buffer]

  Inside WASM handle_device_status_report:
    → ps=6: cursor position report
    → format "ESC [ {row+1} ; {col+1} R" into response_buffer
    → return length
```

impl TerminalCore {
    // ── SGR Handler (NEW) ────────────────────────────────

    /// Handle SGR (Select Graphic Rendition) parameters.
    /// Parses the raw parameter array and applies attributes to cursor.
    pub fn handle_sgr(&mut self, params: &[u16]);

    // ── CSI Edit Handlers (NEW) ──────────────────────────

    /// CSI L - Insert Lines at cursor row within scroll region.
    pub fn handle_insert_lines(&mut self, count: u16);

    /// CSI M - Delete Lines at cursor row within scroll region.
    pub fn handle_delete_lines(&mut self, count: u16);

    /// CSI @ - Insert Characters at cursor position.
    pub fn handle_insert_characters(&mut self, count: u16);

    /// CSI P - Delete Characters at cursor position.
    pub fn handle_delete_characters(&mut self, count: u16);

    // ── CSI Scroll Handlers (NEW) ────────────────────────

    /// CSI S - Scroll Up.
    /// Returns 0 if handled by WASM (scroll region internal).
    /// Returns count if TS should handle scrollback (full screen scroll).
    pub fn handle_scroll_up(&mut self, count: u16) -> u8;

    /// CSI T - Scroll Down. Always WASM-internal.
    pub fn handle_scroll_down(&mut self, count: u16);

    /// CSI r - DECSTBM (Set Scrolling Region).
    /// top/bottom are 1-indexed (0 or absent = default).
    /// Also moves cursor to home position and clears wrapPending.
    pub fn handle_decstbm(&mut self, top: u16, bottom: u16);

    // ── CSI Mode Handlers (NEW) ──────────────────────────

    /// CSI ? Pm h / l - Set/Reset DEC Private Mode.
    /// Returns action code:
    ///   0 = no action (boolean mode set)
    ///   1 = switchToAlt
    ///   2 = saveAndSwitchToAlt
    ///   3 = switchToMain
    ///   4 = saveCursor
    ///   5 = restoreCursor
    ///   0xFF = TS fallback (multi-valued modes)
    pub fn handle_set_mode(&mut self, mode: u16, enable: bool) -> u8;

    // ── CSI Device Handlers (NEW) ────────────────────────

    /// CSI Ps n - Device Status Report.
    /// Returns response length (0 if no response).
    pub fn handle_device_status_report(&mut self, ps: u8) -> u8;

    /// CSI c - Primary Device Attributes.
    /// Returns response length.
    pub fn handle_primary_device_attributes(&mut self) -> u8;

    /// CSI > c - Secondary Device Attributes.
    /// Returns response length.
    pub fn handle_secondary_device_attributes(&mut self) -> u8;

    /// Get pointer to response buffer in linear memory.
    pub fn get_response_ptr(&self) -> *const u8;

    /// Get length of last device response.
    pub fn get_response_len(&self) -> u32;
}

private handleCsiWasm(grid: WasmGrid, action: CsiAction): boolean {
    switch (action.action) {
      // ── Sprint 3 handlers (UNCHANGED) ──────────────
      case "CursorUp": ...
      case "CursorDown": ...
      case "CursorForward": ...
      case "CursorBack": ...
      case "CursorNextLine": ...
      case "CursorPreviousLine": ...
      case "CursorHorizontalAbsolute": ...
      case "CursorPosition": ...
      case "CursorVerticalAbsolute": ...
      case "EraseInDisplay": ...
      case "EraseInLine": ...
      case "EraseCharacters": ...

      // ── Sprint 4: SGR ──────────────────────────────
      case "Sgr":
        grid.core.handle_sgr(new Uint16Array(action.data));
        return true;

      // ── Sprint 4: Edit ─────────────────────────────
      case "InsertLines":
        grid.core.handle_insert_lines(action.data || 1);
        return true;
      case "DeleteLines":
        grid.core.handle_delete_lines(action.data || 1);
        return true;
      case "InsertCharacters":
        grid.core.handle_insert_characters(action.data || 1);
        return true;
      case "DeleteCharacters":
        grid.core.handle_delete_characters(action.data || 1);
        return true;

      // ── Sprint 4: Scroll ───────────────────────────
      case "ScrollUp": {
        const count = action.data || 1;
        const result = grid.core.handle_scroll_up(count);
        if (result > 0) {
          // Full screen: need scrollback push
          const buffer = this.getActiveBuffer();
          buffer.scrollUp(result);
        }
        return true;
      }
      case "ScrollDown":
        grid.core.handle_scroll_down(action.data || 1);
        return true;
      case "SetScrollRegion":
        grid.core.handle_decstbm(action.data.top || 0, action.data.bottom || 0);
        return true;

      // ── Sprint 4: Modes ────────────────────────────
      case "SetMode":
        return this.handleModesWasm(grid, action.data, true);
      case "ResetMode":
        return this.handleModesWasm(grid, action.data, false);

      // ── Sprint 4: Device ───────────────────────────
      case "DeviceStatusReport": {
        const len = grid.core.handle_device_status_report(action.data);
        if (len > 0) {
          this.readAndSendResponse(grid, len);
        }
        return true;
      }
      case "PrimaryDeviceAttributes": {
        const len = grid.core.handle_primary_device_attributes();
        this.readAndSendResponse(grid, len);
        return true;
      }
      case "SecondaryDeviceAttributes": {
        const len = grid.core.handle_secondary_device_attributes();
        this.readAndSendResponse(grid, len);
        return true;
      }
      case "TertiaryDeviceAttributes":
        return true; // Ignored

      default:
        return false;
    }
}

/**
 * Handle SetMode/ResetMode via WASM.
 * Processes modes one at a time, collecting actions.
 */
private handleModesWasm(grid: WasmGrid, modes: number[], enable: boolean): boolean {
    const actions: number[] = [];

    for (const mode of modes) {
        const code = grid.core.handle_set_mode(mode, enable);
        if (code === MODE_TS_FALLBACK) {
            // Multi-valued mode: handle in TS
            setDecPrivateMode(this.modes, mode, enable);
        } else if (code > 0) {
            actions.push(code);
        }
    }

    // Execute collected actions
    for (const code of actions) {
        this.executeModAction(code);
    }

    // Sync modes from WASM to TS (for boolean modes set by WASM)
    syncModesFromWasm(this.modes, grid.core);

    // Sync TS-only modes to WASM (for multi-valued modes handled by TS)
    this.syncModesToWasm();

    return true;
}

/**
 * Read device response from WASM linear memory and send to PTY.
 */
private readAndSendResponse(grid: WasmGrid, len: number): void {
    const ptr = grid.core.get_response_ptr();
    const memory = grid.core.memory.buffer;
    const response = new Uint8Array(memory, ptr, len).slice(); // copy
    this.addPendingResponse(response);
}

### syncCursorAttrsToWasm Removal

After SGR WASM化, cursor attributes (fg, bg, flags) are always managed in WASM memory. The following call sites of `syncCursorAttrsToWasm()` need to be updated:

1. **handleSgr**: No longer needed (SGR is now WASM-internal)
2. **handleSetMode (restoreCursor action)**: Cursor restore in WASM should also restore attrs. If the saved cursor was saved with `cursor.save()` which saves TS-side attrs, we need to ensure WASM cursor save/restore includes attrs.
3. **switchToAlternateBuffer / switchToPrimaryBuffer**: Buffer switch already syncs cursor via WASM grid. Attrs need to be included in WASM cursor save/restore.
4. **reset()**: After reset, WASM cursor attrs are already default. TS-side attrs reset is sufficient.

**Key consideration**: `cursor.save()` and `cursor.restore()` currently save/restore TS-side CellAttributes. With SGR in WASM, the saved cursor must include WASM-side attrs. Two approaches:
- **Approach A**: Keep cursor save/restore in TS, re-introduce sync call only for restore. This is simpler but keeps one sync point.
- **Approach B**: Move cursor save/restore to WASM. WASM saves/restores cursor position + attrs. This eliminates all sync points.

**Decision**: Use Approach A for Sprint 4 (minimal change). Cursor save/restore remains in TS. After restore, call `syncCursorAttrsToWasm()` ONLY at the restore point. This reduces sync from 4+ call sites to 1. Full elimination deferred to Sprint 5 when ESC handlers (DECSC/DECRC) move to WASM.

## Error Handling

| Error | Condition | Handling |
|-------|-----------|----------|
| Empty SGR params | params.length == 0 | Treat as Reset (SGR 0) |
| Invalid SGR param | Unknown param number | Ignore, continue parsing |
| Truncated extended color | 38/48 without sub-params | Ignore, no crash |
| IL/DL outside region | cursor.row < top or > bottom | No-op |
| Edit count = 0 | CSI param is 0 or undefined | TS normalizes to 1 using `\|\| 1` |
| Invalid DECSTBM | top >= bottom | Ignore (no change) |
| Unknown mode | mode number not recognized | Return 0 (no-op) |
| Unknown DSR ps | ps not 5 or 6 | Return 0 (no response) |
| WASM not initialized | getActiveWasmGrid() is null | Fall back to TS handlers |

## Performance Optimization

### Performance Goals

- SGR: 1 WASM call per SGR sequence (vs. current: parseSgrParams in TS + N individual attr applications + syncCursorAttrsToWasm = 3+ operations)
- IL/DL: 1 WASM call per operation (vs. current: getLine + N cell copies through WasmLineProxy)
- ICH/DCH: 1 WASM call per operation (vs. current: N cell shifts through WasmLineProxy)
- SU/SD (scroll region): 1 WASM call (vs. current: N line rearrangements through WasmLineProxy)
- Modes: 1 WASM call per mode (vs. current: TS mode set + syncModesToWasm = 2 operations)

### Memory Budget (Sprint 4 additions)

| Component | Estimated Size |
|-----------|---------------|
| handle_sgr code | ~1.5 KB |
| Edit handlers (4) | ~1.0 KB |
| Scroll handlers (3) | ~0.8 KB |
| Mode handler | ~0.5 KB |
| Device handlers (3) | ~0.5 KB |
| Response buffer (64B static) | ~0.1 KB |
| Row shift helper | ~0.3 KB |
| **Total additional code** | **~4.7 KB** |

### Optimization Notes

- SGR batch API avoids per-param WASM boundary crossing
- Row shift operations (IL/DL/SU/SD) share internal `shift_rows_in_region` helper
- Device response buffer is reused (not allocated per call)
