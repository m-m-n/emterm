# WASM SGR + 編集/スクロールCSI + モード + デバイス応答 (Sprint 4) - 要件定義書

## 1. 概要

### 1.1 背景

eMterm の WASM 化ロードマップ（`tmp/wasm.md`）の Sprint 4 として、残りの CSI ハンドラを WASM に移植する。Sprint 3 完了時点で Print + C0 + カーソルCSI + 画面消去 = 全アクションの95%以上が WASM 処理されている。Sprint 4 では残りの CSI ハンドラ（SGR、編集、スクロール、モード、デバイス応答）を WASM 化し、CSI 処理の100% WASM 化を達成する。

### 1.2 目的

- SGR（色属性設定）を WASM バッチ API で処理し、`syncCursorAttrsToWasm()` を廃止する
- CSI 編集操作（IL/DL/ICH/DCH）を WASM グリッド内で完結させる
- CSI スクロール操作（SU/SD）に scroll bridge パターンを適用する
- DEC Private Modes の WASM 化と action code パターンの導入
- デバイス応答（DSR/DA1/DA2）を WASM で生成し、linear memory 経由で TS に渡す

### 1.3 スコープ

**対象:**
- SGR (`csi_char_attrs.ts`) → WASM バッチ API
- CSI Edit (`csi_edit.ts`: IL, DL, ICH, DCH) → WASM 内完結
- CSI Scroll (`csi_scrolling.ts`: SU, SD, DECSTBM) → WASM + scroll bridge
- CSI Modes (`csi_modes.ts`: SetMode, ResetMode) → WASM + action code
- CSI Device (`csi_device.ts`: DSR, DA1, DA2) → WASM 生成 + linear memory

**対象外:**
- ESC ハンドラ（Sprint 5 対象）
- OSC/APC/DCS ハンドラ（TS に残る）
- Ring Buffer 統合（Sprint 5 対象）
- `terminal_core.rs` のモジュール分割（別タスク）

## 2. ビジネス要件

### 2.1 ビジネス目標

全 CSI ハンドラの WASM 化により、ターミナル操作のホットパスから TS-WASM 境界越えを最小化する。

### 2.2 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| ターミナル利用者 | 色付き出力、vi/vim、top/htop 等のフルスクリーンアプリ利用者 |

### 2.3 期待される効果

- SGR 処理の境界越え削減（N回の WASM 呼び出し → 1回のバッチ API）
- `syncCursorAttrsToWasm()` 廃止による SGR 後の同期オーバーヘッド解消
- IL/DL/ICH/DCH のセル操作が WASM linear memory 内で完結
- CSI 処理が 100% WASM ルーティング対象に

## 4. 機能要件

### 4.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | SGR バッチ API | SGR パラメータ配列を WASM に渡し、WASM 内で解析・適用 | 高 |
| F02 | IL (Insert Lines) | カーソル行に空白行を挿入、スクロール領域内で下に押す | 高 |

| F06 | SU (Scroll Up) | コンテンツを上にスクロール、scroll bridge パターン | 高 |

| F10 | DSR | デバイスステータスレポート（WASM 生成） | 中 |
| F11 | DA1/DA2 | デバイス属性応答（WASM 生成） | 中 |

### 4.2 機能詳細

#### F01: SGR バッチ API

**説明**: `handle_sgr(params: &[u16])` で SGR パラメータ配列を WASM に渡す。WASM 内で解析（Reset, Bold, Foreground 等）し、カーソル属性（fg, bg, flags）を直接更新する。

**入力**: SGR パラメータの u16 配列（例: `[38, 5, 196]` = 256色前景色）

**処理**:
- wasm_bindgen の `&[u16]` スライス受け渡しを使用
- WASM 内で parseSgrParams 相当のロジックを実装
- カーソルの fg/bg/flags を直接 WASM メモリで更新
- `syncCursorAttrsToWasm()` が不要になる

#### F06: SU (Scroll Up) - Scroll Bridge パターン

**説明**: スクロール領域内の場合は WASM 内で完結。フルスクリーンスクロールの場合は scroll count を返し、TS がスクロールバック連携を行う。

**処理**:
- スクロール領域: WASM が行シフト + クリアを実行、0 を返す
- フルスクリーン: scroll count を返す（行シフトは行わない）、TS が `buffer.scrollUp(count)` を呼ぶ

#### F09: SetMode/ResetMode - Action Code パターン

**説明**: `handle_set_mode(mode: u16, enable: bool) -> u8` でモード設定と action code 返却。

**Action codes:**
- 0 = no action（ブール値モードの設定完了）
- 1 = switchToAlt
- 2 = saveAndSwitchToAlt
- 3 = switchToMain
- 4 = saveCursor
- 5 = restoreCursor
- 0xFF = TS にフォールバック（マウス追跡等の多値モード）

#### F10/F11: デバイス応答 - Linear Memory パターン

**説明**: WASM がレスポンスバイト列を内部バッファに生成。レスポンス長を返し、TS が linear memory からバイト列を読み取って `addPendingResponse()` に渡す。

## 5. 非機能要件

### 5.1 パフォーマンス要件

- SGR 処理: 1回の WASM バッチ呼び出しで完了（現在: parseSgrParams + N回の applySgrAttr + syncCursorAttrsToWasm）
- IL/DL/ICH/DCH: 1回の WASM 呼び出しで完了（現在: buffer メソッド経由で N 回の WasmLineProxy 操作）
- SU/SD: スクロール領域内は 1回の WASM 呼び出し

### 5.2 互換性要件

- 全既存 TypeScript テスト（1824+）がパスすること
- WASM バイナリサイズ増分 < 10KB（Sprint 3 baseline: 45.8KB）
- JS フォールバックパスが変更なく機能すること
- vttest 基本テスト変化なし

## 6. データ要件

### 6.1 新規データ構造

**Rust (TerminalCore 拡張):**
- `response_buffer: Vec<u8>` - デバイスレスポンス用バッファ

**新規定数:**
- Mode action codes: `MODE_NO_ACTION = 0`, `MODE_SWITCH_TO_ALT = 1`, ..., `MODE_TS_FALLBACK = 0xFF`

## 7. 制約条件

### 7.1 技術的制約

- `terminal_core.rs` が 2764 行で、Sprint 4 でさらに増加する（モジュール分割は別タスク）
- wasm_bindgen の `&[u16]` スライス受け渡しはコピーが発生する（SGR パラメータは通常 1-5 個なので影響軽微）
- SU のフルスクリーンスクロールは TS 側のスクロールバック管理に依存（Sprint 5 まで）
- マウス追跡モード等の多値モードは TS 側に残る（WASM の u32 ビットフィールドに収まらない）

## 8. 想定される課題とリスク

### 8.1 技術的課題

| 課題 | 影響度 | 対応策 |
|------|--------|--------|
| SGR パラメータ解析の Rust 再実装 | 中 | TS の parseSgrParams ロジックを忠実に移植 |
| Mode action code の正確性 | 中 | 既存 setDecPrivateMode のロジックをベースに移植 |
| SU scroll bridge の行抽出タイミング | 高 | WASM は行シフトせず count のみ返し、TS が buffer.scrollUp() を使用 |
| syncCursorAttrsToWasm 廃止の影響範囲 | 中 | 全呼び出し箇所を特定し、SGR 以外のパス（カーソル復元等）も WASM 側で対応 |
