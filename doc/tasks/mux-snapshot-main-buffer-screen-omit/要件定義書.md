# mux snapshot 復元時の表示崩れ修正 (main-buffer screen 省略) - 要件定義書

## 1. 概要

### 1.1 背景

mux daemon に接続した emterm GUI で `apt` などの fancy progress bar 出力を含む操作を行った後、 同一タブのクリック / 別タブ往復 / window 切替 / reattach で snapshot 復元が走ると、 復元結果に progress bar の残骸が log line に焼き込まれた状態で表示崩れする bug が継続発生している。

PROBE 検証 (2026-06-28) により以下が確定:

- 同一 scrollback bytes を fresh vt100 に投入した場合は bar と log が正しく分離した形で再現される。
- 同じ bytes を daemon vt100 が incremental に処理した結果 (現状の snapshot screen 部 = `contents_formatted()` の出力) は bar と log が同一行にマージされている。
- 原因は resize race window 中の daemon vt100 内部状態管理であり、 daemon vt100 の dump (`contents_formatted()`) が cell レベルで trash した状態を持つ。
- 一方 scrollback bytes 自体は完全な PTY byte 履歴 (Start `CSI r` / progress / Stop `CSI r` を含む) で、 client core (term_core) で再構築すれば正しい状態が得られる。

### 1.2 目的

main-buffer pane の snapshot 復元で `apt` 等の progress bar 残骸表示崩れを排除し、 リグレッションなしに復元品質を改善する。

### 1.3 スコープ

**対象**:
- `src-tauri/src/mux/ipc/reattach.rs` の `build_snapshot_bytes` の出力組み立てロジック。
- 対応する内部 doc comment。
- 該当する単体テスト。
- 現状残っている `[DECSTBM-trace]` 投資調査用ログ・ dump コード・ probe テスト群の削除。
- SPEC ドキュメントへの snapshot layout 明記。

**対象外**:
- daemon vt100 が resize race で trash する根本原因の特定 (別タスク)。
- scrollback ring 上限 (2MiB) を超える長期 session の復元戦略 (現状制限を維持)。
- alt-screen 経路 (vim / htop / less / man 等) の snapshot 組み立て変更 (現行のまま維持)。

## 2. ビジネス要件

### 2.1 ビジネス目標

- mux 機能の信頼性と通常 shell 操作 (`apt` 等) との両立を確保する。
- mux を tmux 代替として実用するための「同一 / 別 window 切替で画面が崩れない」前提を満たす。

### 2.2 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| mux ユーザー (主) | emterm GUI から mux daemon を介して shell 操作 (主に main-buffer) を行うユーザー |
| TUI ユーザー | mux 経由で vim / htop / less / man 等 alt-screen を使う TUI を起動するユーザー |

### 2.3 期待される効果

- `apt install` / `apt reinstall` 等の長い progress bar 出力後にタブ往復しても表示崩れしない。
- alt-screen TUI の snapshot 復元品質には影響を与えない。
- 投資調査用の trace ログが消えてログノイズが減る。

## 3. ユースケース

### 3.1 ユースケース一覧

| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | apt 実行後の同一タブクリック → 表示崩れしない | mux ユーザー | 高 |
| UC02 | apt 実行中 / 直後に別タブ往復 → 表示崩れしない | mux ユーザー | 高 |

### 3.2 ユースケース詳細

#### UC01: apt 実行後の同一タブクリック → 表示崩れしない

**アクター**: mux ユーザー

**事前条件**:
- emterm GUI が mux daemon に接続済み。
- 対象 pane が main-buffer (alt_screen=false)。
- `sudo apt reinstall <package>` などで進捗バーを含む出力が行われた。

**基本フロー**:
1. ユーザーが apt の進捗中もしくは直後に同じタブをクリックする。
2. client が `RequestPaneSnapshot` を daemon に送る。
3. daemon が scrollback + (alt 時のみ screen) + alt-mode を組み立てた snapshot bytes を返す。
4. client が `reset_and_replay` で snapshot 全 byte を fresh core に流し込む。
5. main-buffer の場合 client core が scrollback bytes のみから fresh vt100 状態を再構築する。

**事後条件**:
- progress bar が log 行に焼き込まれず、 正しく独立した行で再現されている。

#### UC02: 別タブから戻った場合の復元

UC01 と同じ scrollback-driven 再構築経路を辿る。

#### UC03: alt-screen TUI 復元

**アクター**: TUI ユーザー

**事前条件**:
- 対象 pane が alt-screen (alt_screen=true)。 vim / htop / less / man など TUI 稼働中。

**基本フロー**:
1. ユーザーが別タブから戻る。
2. snapshot bytes には scrollback + daemon vt100 dump (screen) + `ESC[?1049h` が含まれる。
3. client が replay して alt-screen TUI 画面が復元される。

**事後条件**:
- TUI 表示が崩れない (現行動作を維持)。

#### UC04: reattach

詳細フローは UC01-UC03 と同じ snapshot 組み立て経路に従う。

## 4. 機能要件

### 4.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | main-buffer での screen 部省略 | snapshot bytes 組み立て時、 alt_screen=false なら screen 部を含めない | 高 |
| F02 | alt-screen での既存挙動維持 | snapshot bytes 組み立て時、 alt_screen=true なら従来通り screen 部を含める | 高 |
| F03 | snapshot layout の SSOT 反映 | SPEC.md に alt/main 別の layout を明記する | 中 |
| F04 | 投資調査用コードの削除 | 現状残っている `[DECSTBM-trace]` ログ・ dump コード・ probe テストを削除する | 中 |

### 4.2 機能詳細

#### F01: main-buffer での screen 部省略

**説明**:
`build_snapshot_bytes` は alt_screen=false の場合、 出力 bytes に screen 部 (daemon vt100 `contents_formatted()` 出力) を含めない。

**入力**: `scrollback: &[u8]`, `screen: &[u8]`, `alt_screen: bool`

**出力 (alt_screen=false の場合)**:
- `ESC[3J ESC[H ESC[2J` + `strip_replayable_rich_content(scrollback)` + `ESC[?1049l`

**出力 (alt_screen=true の場合)**:
- `ESC[3J ESC[H ESC[2J` + `strip_replayable_rich_content(scrollback)` + `screen` + `ESC[?1049h`

**ビジネスルール**:
- main-buffer では client term_core が scrollback bytes 全体を再 replay することで状態を再構築できる。
- alt-screen では alt buffer 内容が scrollback に書き込まれない (`pty_spawn.rs:373` 参照) ため daemon vt100 dump が唯一の復元手段。
- `strip_replayable_rich_content` は両モード共通の前処理として維持する。

#### F02: alt-screen での既存挙動維持

**説明**: alt_screen=true の場合の snapshot 組み立ては変更しない。 daemon vt100 dump を含める。

#### F03: snapshot layout の SSOT 反映

**説明**: SPEC.md (および IMPLEMENTATION.md の Snapshot-Based State Sync セクション) に、 main-buffer は scrollback 再構築 / alt-screen は daemon dump 経路、 という分岐を明記する。 該当する関数の doc comment (`build_snapshot_bytes` / `build_shadow_parser_snapshot` / `handle_request_pane_snapshot`) も更新する。

#### F04: 投資調査用コードの削除

**説明**: 修正と同じコミット範囲で以下を削除する:

| 場所 | 削除対象 |
|---|---|
| `crates/term_core/src/terminal_core.rs` | `set_scroll_region` の `[DECSTBM-trace]` ログ |
| `crates/term_core/src/reflow.rs` | `resize_post_cleanup` の `[DECSTBM-trace]` ログ |
| `src-tauri/src/tabs.rs` | `reset_frame_for_replay` の `[DECSTBM-trace]` ログ |
| `src-tauri/src/tabs.rs` | `apply_offthread_swap` の `[DECSTBM-trace]` ログ |
| `src-tauri/src/mux/ipc/reattach.rs` | `build_snapshot_bytes` の `[DECSTBM-trace]` ログ + suspect dump コード |
| `src-tauri/src/mux/ipc/reattach.rs` | `probe_*` テスト群 5 件 (PROBE 2-6) |

## 5. 非機能要件

### 5.1 パフォーマンス要件

- main-buffer snapshot の組み立てバイト数は **削減** される (screen 部の vt100 dump 分が無くなる)。
- client 側 replay コストは scrollback bytes の長さに比例 (上限 2MiB)。 現状 `build_from_snapshot` の off-thread 経路で対応済みであり、 体感影響は中立〜改善。

### 5.2 保守性要件

- 投資調査用コード (`[DECSTBM-trace]` ログ・ suspect dump・ probe テスト) を削除し、 ログ ノイズと dead code を排除する。
- snapshot layout の責務分割 (main = scrollback 再構築 / alt = daemon dump) を doc comment + SPEC.md に明文化する。

### 5.3 互換性要件

- IPC ワイヤープロトコルは変更しない (`build_snapshot_bytes` の出力 bytes 内訳が変わるのみで、 protocol message 構造は変更なし)。
- client term_core の replay API も変更しない。

## 6. UI/UX要件

- ユーザー視点では「タブ往復後に表示崩れしない」のみ観測可能。 UI 構造の変更は無い。

## 7. データ要件

- snapshot バイト列の構造変更は section 4.2 F01/F02 の通り。 永続化データへの影響なし。

## 8. 外部連携

- 該当なし。

## 9. 制約条件

### 9.1 技術的制約

- vt100 0.16.2 のフォーマット / API は変更しない (fork しない)。 過去議論 (2026-06-19 セッション adbf081b) で確定。
- term_core にも ANSI emitter を新規実装しない (大規模になるため不採用)。
- IPC wire protocol を bincode に切り替えない (大規模になるため不採用)。

### 9.2 ビジネス上の制約

- 既存の alt-screen 利用 (vim / htop / less / man 等) にリグレッションを起こさないこと。

### 9.3 スケジュール制約

- 修正の優先度は高い (現状 apt 等の運用で日常的に表示崩れが発生する)。

## 10. 想定される課題とリスク

### 10.1 技術的課題

| 課題 | 影響度 | 対応策 |
|------|--------|--------|
| client term_core が daemon vt100 と同じ最終状態を再現できないケースが残る可能性 | 中 | PROBE 6 で実際の apt 17,632B シナリオは fresh vt100 で正しく再構築されることを実証済み。 既存 `build_snapshot_replay_*` テストの単体テストで回帰検出する |
| scrollback ring 上限 (2MiB) を超えた古い履歴が失われる | 低 | 現状の daemon vt100 dump 経路でも viewport 外の古い行は失われており実害なし。 SPEC に制限事項として明記 |

### 10.2 ビジネスリスク

| リスク | 発生確率 | 影響度 | 対応策 |
|--------|----------|--------|--------|
| alt-screen の組み立てを誤って変更してしまう | 低 | 高 | 単体テストで alt=true 時の screen 部が含まれることを直接 assert する |

## 13. 用語定義

| 用語 | 定義 |
|------|------|
| snapshot | mux daemon が pane の状態 (scrollback + 現在画面 + alt-mode) を 1 個の byte 列に組み立てたもの。 reattach / 同一タブクリック / 別タブ往復 / window 切替時に発行される |
| scrollback | pane の PTY 出力履歴 (raw bytes)。 alt-screen への出力は除外される (`pty_spawn.rs:373`) |
| screen part | snapshot 中の `contents_formatted()` 出力部分。 daemon vt100 が保持する現在画面の cell 内容を ANSI 形式で再現したもの |
| daemon vt100 | mux daemon プロセスが各 pane について保持している vt100 0.16.2 ベースのシャドウ ターミナル状態 |
| client term_core | emterm GUI 側 (`crates/term_core`) が保持している ANSI parser / grid 実装 |
| alt-screen / main-buffer | DEC ターミナルの alternate screen buffer (1049h) と通常 buffer (1049l) |
