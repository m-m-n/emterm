# WASM ESC ハンドラ + Ring Buffer 統合 (Sprint 5) - 要件定義書

## 1. 概要

### 1.1 背景

eMterm の WASM 化ロードマップの Sprint 5。Sprint 4 までに全 CSI/C0/Print ハンドラの WASM 化が完了し、100% CSI WASM ルーティングを達成。しかし、以下の課題が残存:

1. ESC ハンドラ（DECSC/DECRC/IND/NEL/RI/HTS/RIS/Charset）が TS に残っている
2. スクロールバックが JS Line オブジェクトで管理されており、GC 圧迫の原因
3. スクロール操作が WASM-TS ブリッジを経由（戻り値パターン）
4. `syncCursorAttrsToWasm()` がカーソル復元時に1箇所残存
5. リフロー処理が TS 側に存在し、WASM-TS 間の大量データ移動が発生

### 1.2 目的

1. 全 ESC ハンドラを WASM に移植し、全アクションを WASM で処理可能にする
2. ビューポートとスクロールバックを統合した Ring Buffer を WASM linear memory に実装
3. スクロールブリッジを廃止し、スクロール操作を WASM 内完結にする
4. `syncCursorAttrsToWasm()` を完全に廃止する
5. リフローロジックを Rust で実装し、resize を WASM 内完結にする

### 1.3 スコープ

- ESC ハンドラ 9 種の WASM 移植
- WASM Ring Buffer 実装（ビューポート + スクロールバック統合）
- スクロール操作の WASM 内完結化
- リフローロジックの Rust 実装
- UnifiedBuffer の薄いラッパー化
- `syncCursorAttrsToWasm()` の完全廃止

## 2. ビジネス要件

### 2.1 ビジネス目標

- ターミナルバッファ管理を WASM に集約し、JS GC 圧迫を大幅に軽減
- スクロール操作の WASM-TS 境界越え回数をゼロにする

### 2.2 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| 開発者 | ターミナルエミュレータのユーザー |

### 2.3 期待される効果

- JS GC 圧迫の大幅軽減（数千の Line/Cell オブジェクトが linear memory に移行）
- スクロール操作の高速化（WASM 内完結、ブリッジ不要）
- メモリ使用量 20-30% 削減（JS オブジェクトオーバーヘッド排除）
- リサイズ時のリフロー高速化（WASM 内完結）

## 3. ユースケース

### 3.1 ユースケース一覧

| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | ESC シーケンスの WASM 処理 | 端末アプリケーション | 高 |
| UC02 | スクロールバック閲覧 | ユーザー | 高 |
| UC03 | ターミナルリサイズ | ユーザー | 高 |
| UC04 | 大量出力処理 | 開発者 | 高 |

### 3.2 ユースケース詳細

#### UC01: ESC シーケンスの WASM 処理

**アクター**: 端末アプリケーション（vim, less 等）

**事前条件**: WASM モジュール初期化済み

**基本フロー**:
1. Backend が ESC シーケンスをパースし `Esc` アクションを送信
2. TS の processAction が WASM ESC ディスパッチャーを呼び出し
3. WASM 内でカーソル保存/復元、インデックス等を処理
4. スクロールが必要な場合、WASM Ring Buffer が直接処理

**代替フロー**: WASM 未初期化時は既存 TS ハンドラにフォールバック

#### UC02: スクロールバック閲覧

**アクター**: ユーザー

**基本フロー**:
1. ユーザーがスクロールアップ操作
2. Renderer が WASM Ring Buffer からスクロールバック行を読み取り
3. 画面に表示

#### UC03: ターミナルリサイズ

**アクター**: ユーザー

**基本フロー**:
1. ウィンドウサイズ変更イベント発生
2. TS が WASM `resize()` を呼び出し
3. WASM 内でリフロー処理（行の結合・再分割）
4. 新しいカーソル位置を返却

## 4. 機能要件

### 4.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | ESC ハンドラ WASM 化 | 9 種の ESC ハンドラを WASM に移植 | 高 |
| F02 | WASM Ring Buffer | 統合リングバッファの WASM 実装 | 高 |
| F03 | スクロール WASM 内完結 | スクロールブリッジの廃止 | 高 |
| F04 | リフロー WASM 実装 | resize 時のリフローロジックを Rust で実装 | 高 |
| F05 | syncCursorAttrsToWasm 廃止 | 最後の同期呼び出しを廃止 | 中 |
| F06 | UnifiedBuffer ラッパー化 | TS 側を薄いラッパーに変更 | 高 |

### 4.2 機能詳細

#### F01: ESC ハンドラ WASM 化

対象ハンドラ:
- SaveCursor (DECSC): `save_cursor()` — 既存 WASM 実装を ESC ディスパッチに統合
- RestoreCursor (DECRC): `restore_cursor()` — WASM 内でカーソル属性復元完結
- Index (IND): カーソル下移動、最下行ならスクロールアップ（WASM 内完結）
- NextLine (NEL): CR + Index
- ReverseIndex (RI): カーソル上移動、最上行ならスクロールダウン（WASM 内完結）
- HorizontalTabSet (HTS): 現在のカーソル列にタブストップ設定
- ResetToInitialState (RIS): 全状態リセット（Ring Buffer 含む）
- SetG0CharSet / SetG1CharSet: キャラクタセット設定（既存セッター利用）

#### F02: WASM Ring Buffer

統合リングバッファ（ビューポート + スクロールバック）をフラット配列で実装:
- `cells: Vec<Cell>` — `capacity × cols` のフラット配列
- `wrapped: Vec<bool>` — 行の折り返しフラグ
- ビューポート = Ring Buffer の末尾 `rows` 行
- スクロールバック = ビューポートより前の行

#### F03: スクロール WASM 内完結

- `handle_print()`, `handle_execute()`, `handle_scroll_up()` の戻り値が常に 0（スクロールカウント不要）
- WASM 内で直接 Ring Buffer にスクロールバック行を追加
- TS 側のスクロールブリッジコードは dead code になるが、JS フォールバック用に維持

#### F04: リフロー WASM 実装

Rust で完全なリフローアルゴリズムを実装:
1. Ring Buffer 全行をドレイン
2. wrapped フラグに基づき論理行に結合
3. 新幅で再分割
4. Ring Buffer に書き戻し
5. 新しいカーソル位置を計算して返却

#### F05: syncCursorAttrsToWasm 廃止

DECRC (RestoreCursor) が WASM 内で完結するため、最後の `syncCursorAttrsToWasm()` 呼び出しが不要になる。メソッドと全呼び出し箇所を削除。

## 5. 非機能要件

### 5.1 パフォーマンス要件

- スクロール操作: WASM 内完結（0 回の境界越え）
- リフロー: TS 実装比で同等以上の速度
- WASM バイナリサイズ: 70KB 未満（Sprint 4: 51.4KB）

### 5.2 互換性要件

- 既存 TypeScript テスト全パス
- JS フォールバックパス維持
- vttest 基本テスト変化なし
- スクロールバック容量: 設定画面で変更可能（既存設定 `scrollback_lines` を利用、デフォルト 10,000 行）

### 5.3 メモリ要件

- 80 桁 × 10,000 行で約 25MB（Cell 32B × 80 × 10,024）
- 設定変更で容量調整可能

## 6. 制約条件

### 6.1 技術的制約

- wasm-bindgen では `Vec<Cell>` をそのまま export できない（packed binary format で export）
- WASM linear memory のサイズはページ単位（64KB）で成長
- リフロー中は Ring Buffer が一時的に 2 倍のメモリを使用する可能性

### 6.2 ビジネス上の制約

- JS フォールバックを維持する（WASM 初期化失敗時）

## 7. 想定される課題とリスク

### 7.1 技術的課題

| 課題 | 影響度 | 対策 |
