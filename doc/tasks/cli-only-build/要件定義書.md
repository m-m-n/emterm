# CLI専用ビルド - 要件定義書

## 1. 概要

### 1.1 背景
emtermをGUIライブラリのないサーバー（CLI環境）でビルドすると、`gdk-sys`等のGUI依存でコンパイルが失敗する。CLIコマンド（`emterm image`, `emterm markdown`）はGUIに依存していないが、Cargoの依存解決でTauri経由のGUIライブラリが必須となる。

### 1.2 目的
GUIライブラリのないサーバーでも`emterm image`/`emterm markdown`コマンドをビルド・使用可能にする。SSH経由でリモートサーバーの画像やMarkdownをemtermで表示できるようにする。

### 1.3 スコープ
- Cargo feature flagによるGUI/CLI条件コンパイル
- 環境変数`EMTERM_CLI_ONLY`によるビルド切り替え
- CLI専用dpkgパッケージの生成

## 2. ビジネス要件

### 2.1 ビジネス目標
リモートサーバーでのCLIコマンド利用を可能にし、emtermの活用範囲を拡大する。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| サーバー管理者 | SSHでリモートサーバーに接続し、画像やMarkdownを表示したいユーザー |

### 2.3 期待される効果
- GUIライブラリのないサーバーでemterm CLIコマンドが使用可能になる
- `dpkg -i`でサーバーに簡単にインストールできる

## 3. ユースケース

### 3.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | CLI専用ビルド | 開発者 | 高 |
| UC02 | CLI専用dpkgインストール | サーバー管理者 | 高 |
| UC03 | 通常GUIビルド（デフォルト） | 開発者 | 高 |

### 3.2 ユースケース詳細

#### UC01: CLI専用ビルド
**アクター**: 開発者

**事前条件**:
- Rust toolchainがインストール済み
- GUIライブラリは不要

**基本フロー**:
1. `EMTERM_CLI_ONLY=1 make dpkg`を実行
2. Makefileが環境変数を検知し`build-dpkg.sh`に渡す
3. `build-dpkg.sh`が`cargo build --release --no-default-features`でビルド
4. GUI関連のファイル（.desktop、アイコン）をスキップしてdpkgを生成

**事後条件**:
- `build/emterm_<version>_<arch>.deb`が生成される
- パッケージにはCLIバイナリのみ含まれる

#### UC02: CLI専用dpkgインストール
**アクター**: サーバー管理者

**事前条件**:
- CLI専用dpkgが手元にある

**基本フロー**:
1. `sudo dpkg -i emterm_<version>_<arch>.deb`を実行
2. `/usr/bin/emterm`がインストールされる
3. `emterm image <file>`や`emterm markdown <file>`が使用可能

**事後条件**:
- `emterm image`/`emterm markdown`コマンドが利用可能
- GUI依存パッケージは不要

#### UC03: 通常GUIビルド（デフォルト）
**アクター**: 開発者

**事前条件**:
- 従来のビルド環境

**基本フロー**:
1. `make dpkg`を実行（環境変数なし）
2. 従来通りGUI付きでビルドされる

**事後条件**:
- 従来と同じGUIパッケージが生成される（後方互換性維持）

## 4. 機能要件

### 4.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | Cargo feature flag | `gui`デフォルトfeatureの導入 | 高 |
| F02 | 環境変数によるビルド切り替え | `EMTERM_CLI_ONLY=1`でCLI専用ビルド | 高 |
| F03 | 条件コンパイル | GUIコードの`cfg`ゲート | 高 |
| F04 | CLI専用dpkgパッケージ | GUIリソースを除いたdpkg生成 | 高 |

### 4.2 機能詳細

#### F01: Cargo feature flag
**説明**: `gui`フィーチャーをデフォルト有効で追加し、GUI依存クレートをoptionalにする。

**GUI依存（optional化）**:
- `tauri`, `tauri-plugin-clipboard-manager`, `tauri-plugin-notification`, `tauri-plugin-shell`
- `portable-pty`, `tokio`, `futures`
- `font-kit`
- `tauri-build`（build-dependencies）

**CLI必須（常時有効）**:
- `clap`, `serde`, `serde_json`, `log`, `rust-i18n`, `sys-locale`
- `uuid`, `base64`, `image`, `png`, `gif`, `flate2`
- `thiserror`, `anyhow`

#### F02: 環境変数によるビルド切り替え
**説明**: `EMTERM_CLI_ONLY=1`設定時にCLI専用ビルドを実行。

**処理フロー**:
1. `Makefile`の`dpkg`ターゲットで`build-dpkg.sh`を呼び出し（環境変数は自動伝播）
2. `build-dpkg.sh`内で`EMTERM_CLI_ONLY`を検知
3. 検知時: `cargo build --release --no-default-features`を使用
4. 未設定時: 従来通り`bun tauri build --no-bundle`を使用

#### F03: 条件コンパイル
**説明**: GUIモジュールとコードを`#[cfg(feature = "gui")]`でゲート。

**ゲート対象**:
- `build.rs`: `tauri_build::build()`呼び出し
- `lib.rs`: GUIモジュール宣言（`ansi`, `image`, `logging`, `pty`）、Tauri use文、全Tauriコマンド関数、`run()`関数
- `main.rs`: `app_lib::run()`呼び出し
- `commands/mod.rs`: GUI専用サブモジュール宣言（`config`, `font`, `editor`）

#### F04: CLI専用dpkgパッケージ
**説明**: CLI専用ビルド時のdpkgパッケージ内容を調整。

**差分**:
| 項目 | GUI | CLI専用 |
|------|-----|---------|
| バイナリ | `/usr/bin/emterm` | `/usr/bin/emterm` |
| .desktopファイル | あり | なし |
| アイコン | あり | なし |
| Depends | `libc6, libwebkit2gtk-4.1-0, libgtk-3-0, libglib2.0-0` | `libc6` |
| Section | `x11` | `utils` |
| Description | 現行のまま | CLI-only版の説明 |
| postinst | gtk-update-icon-cache等 | なし |

## 5. 非機能要件

### 5.1 後方互換性
- 環境変数未設定時は従来と完全に同じ動作をすること
- GUIビルドの成果物に差異がないこと

### 5.2 保守性
- `#[cfg]`ゲートは最小限の箇所に集約
- CLIモジュールとGUIモジュールの境界が明確

## 6. 制約条件

### 6.1 技術的制約
- Cargoの依存解決はbuild.rs実行前に行われるため、環境変数だけでは依存をスキップできない
- feature flagとの組み合わせが必須
- `lib`の`crate-type`にCLI専用時は`staticlib`/`cdylib`が不要だが、feature flagでcrate-typeを切り替えるのはCargoでサポートされていないため、変更しない
