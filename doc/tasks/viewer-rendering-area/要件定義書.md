# ビューアー描画領域の変更 - 要件定義書

## 1. 概要

### 1.1 背景
現在、ImageViewerとFullscreenMarkdownViewは画面全体を覆うフルスクリーンオーバーレイとして実装されている。この実装ではタブバーも隠れてしまい、ビューアー表示中にタブを切り替えることができない。

### 1.2 目的
ビューアーの描画領域をターミナルコンテンツ領域（`#tab-content-area`）内に制限し、タブバーを常にアクセス可能な状態に維持する。

### 1.3 スコープ
- ImageViewer（`src/image-viewer/index.ts`）の描画領域変更
- FullscreenMarkdownView（`src/markdown/fullscreen.ts`）の描画領域変更
- 各タブが独立したビューアー状態を維持する設計

## 2. ビジネス要件

### 2.1 ビジネス目標
マルチタブ環境でのビューアー操作性向上

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| ターミナルユーザー | 複数タブで作業を行うユーザー |

### 2.3 期待される効果
- ビューアー表示中でもタブ切り替えが可能
- 各タブで独立してビューアー状態を管理可能

## 3. ユースケース

### 3.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | ビューアー表示中のタブ切り替え | ユーザー | 高 |
| UC02 | タブ毎の独立したビューアー状態管理 | システム | 高 |

### 3.2 ユースケース詳細

#### UC01: ビューアー表示中のタブ切り替え

**アクター**: ユーザー

**事前条件**:
- 複数のタブが開いている
- いずれかのタブでビューアー（画像またはMarkdown）を表示中

**基本フロー**:
1. ユーザーがタブバーをクリックまたはキーボードショートカットでタブを切り替える
2. システムが現在のタブのビューアー状態を保持したまま非表示にする
3. 切り替え先のタブが表示される
4. 切り替え先タブにビューアー状態があれば、その状態で表示される

**代替フロー**:
- 切り替え先タブにビューアーがない場合、通常のターミナル表示となる

**事後条件**:
- タブが正常に切り替わる
- 元のタブのビューアー状態は保持される

#### UC02: タブ毎の独立したビューアー状態管理

**アクター**: システム

**事前条件**:
- マルチタブ環境が有効

**基本フロー**:
1. タブAで画像ビューアーを開く
2. タブBに切り替える
3. タブBでMarkdownビューアーを開く
4. タブAに戻ると画像ビューアーが表示される
5. タブBに戻るとMarkdownビューアーが表示される

**事後条件**:
- 各タブが独立したビューアー状態を維持

## 4. 機能要件

### 4.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | 描画領域変更 | ビューアーを`#tab-content-area`内に描画 | 高 |
| F02 | タブ独立方式 | 各タブが独立したビューアー状態を保持 | 高 |
| F03 | タブバーアクセス | ビューアー表示中もタブバーは常にアクセス可能 | 高 |

### 4.2 機能詳細

#### F01: 描画領域変更

**説明**: ビューアーオーバーレイの描画領域を`document.body`から`#tab-content-area`内に変更

**変更対象**:
- ImageViewer: `position: fixed` → `position: absolute`（`#tab-content-area`基準）
- FullscreenMarkdownView: `position: fixed` → `position: absolute`（`#tab-content-area`基準）

**ビジネスルール**:
- タブバー（高さ32px）は常に表示される
- ビューアーはタブコンテンツ領域のみを覆う
- z-indexはタブコンテンツ内で最前面

#### F02: タブ独立方式

**説明**: 各タブが独立したビューアーインスタンスを保持

**ビジネスルール**:
- タブ切り替え時、現在のビューアー状態は保持される
- タブを閉じた時、そのタブのビューアーも破棄される
- 新規タブはビューアーなしの状態で開始

#### F03: タブバーアクセス

**説明**: ビューアー表示中でもタブバーは常に操作可能

**ビジネスルール**:
- タブクリックによる切り替え可能
- キーボードショートカット（Ctrl+Tab等）による切り替え可能
- 新規タブボタンの操作可能

## 5. 非機能要件

### 5.1 パフォーマンス要件
- タブ切り替え時のレスポンス: 100ms以下
- ビューアー表示/非表示の切り替え: 即座（アニメーション含めて150ms以下）

### 5.2 互換性要件
- 既存の閉じる動作を維持（Escapeキー、画面クリック）
- 既存のズーム/パン機能を維持

## 6. UI/UX要件

### 6.1 レイアウト設計

```
┌─────────────────────────────────────────┐
│ [Tab1] [Tab2] [Tab3]           [+]      │  ← タブバー（常に表示）
├─────────────────────────────────────────┤
│                                         │
│                                         │
│     ビューアーオーバーレイ領域           │  ← #tab-content-area内
│     （ターミナルコンテンツを覆う）        │
│                                         │
│                                         │
└─────────────────────────────────────────┘
```

### 6.2 閉じる操作
- Escapeキー: ビューアーを閉じる
- 画面クリック（コンテンツ外）: ビューアーを閉じる
- 閉じるボタン: 追加しない（現行維持）

## 7. データ要件

### 7.1 状態管理

| コンポーネント | 状態 | タブ毎の保持 |
|---------------|------|-------------|
| ImageViewer | 表示/非表示、画像データ、ズームレベル、パン位置 | Yes |
| FullscreenMarkdownView | 表示/非表示、Markdownコンテンツ、スクロール位置、ズームレベル | Yes |

## 8. 制約条件

### 8.1 技術的制約
- `#tab-content-area`は`position: relative`である必要がある
- 現在の実装では`overflow: hidden`が設定済み

### 8.2 既存機能との整合性
- 既存のキーボードショートカットを維持
- 既存のアニメーション（opacity transition）を維持
