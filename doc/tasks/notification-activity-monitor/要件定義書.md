# 通知 / アクティビティモニター - 要件定義書

## 1. 概要

### 1.1 背景

Claude Codeなどのツールが大規模タスクを実行する際、処理完了までに数分かかることがある。ユーザーは待機中に別のタブやアプリケーションに切り替えるため、タスク完了を見逃すことが多い。

### 1.2 目的

- 非アクティブタブでのアクティビティ（プロセス終了、新規出力、BEL文字）をユーザーに通知する
- ウィンドウが非アクティブの場合にデスクトップ通知を送信する

### 1.3 スコープ

- タブバーのアクティビティインジケータ（ドット表示）
- デスクトップ通知（tauri-plugin-notification）
- 設定画面での通知カスタマイズ

## 2. ユースケース

### 2.1 ユースケース一覧

| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | 非アクティブタブのアクティビティ検知 | ユーザー | 高 |
| UC02 | デスクトップ通知受信 | ユーザー | 高 |
| UC03 | インジケータクリア | ユーザー | 高 |
| UC04 | 通知設定カスタマイズ | ユーザー | 中 |

### 2.2 ユースケース詳細

#### UC01: 非アクティブタブのアクティビティ検知

**アクター**: ユーザー

**事前条件**:
- 複数のタブが開いている
- あるタブが非アクティブ状態

**基本フロー**:
1. 非アクティブタブでプロセスが終了する / 新規出力がある / BEL文字を受信する
2. 該当タブにドットインジケータが表示される
3. ユーザーはタブバーを見てアクティビティがあったタブを識別する

**事後条件**:
- 非アクティブタブにドットインジケータが表示されている

#### UC02: デスクトップ通知受信

**アクター**: ユーザー

**事前条件**:
- デスクトップ通知が有効（デフォルト: ON）
- eMtermウィンドウが非アクティブ（別アプリにフォーカスがある）

**基本フロー**:
1. 非アクティブタブでアクティビティが発生する
2. OSのデスクトップ通知が表示される
3. ユーザーが通知をクリックするとeMtermウィンドウがフォーカスされる

**代替フロー**:
- 通知が無効に設定されている場合、デスクトップ通知は送信されない

**事後条件**:
- ユーザーがアクティビティの発生を認識している

#### UC03: インジケータクリア

**アクター**: ユーザー

**事前条件**:
- タブにドットインジケータが表示されている

**基本フロー**:
1. ユーザーがインジケータ付きのタブをクリックする
2. タブがアクティブになる
3. ドットインジケータが自動的に消える

**事後条件**:
- 該当タブのインジケータがクリアされている

#### UC04: 通知設定カスタマイズ

**アクター**: ユーザー

**事前条件**:
- 設定画面を開いている

**基本フロー**:
1. ユーザーが通知関連の設定項目を変更する
2. 変更が即時反映される

**設定項目**:
- デスクトップ通知: ON/OFF
- タブインジケータ: ON/OFF
- 通知トリガー条件: プロセス終了 / 新規出力 / BEL文字（個別ON/OFF）

## 3. 機能要件

### 3.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | タブアクティビティインジケータ | 非アクティブタブのアクティビティをドット表示 | 高 |
| F02 | デスクトップ通知 | ウィンドウ非アクティブ時のOS通知 | 高 |
| F03 | ウィンドウフォーカス追跡 | ウィンドウのアクティブ/非アクティブ状態管理 | 高 |
| F04 | 通知設定 | 通知動作のカスタマイズ | 中 |

### 3.2 機能詳細

#### F01: タブアクティビティインジケータ

**説明**: 非アクティブタブでアクティビティが発生したら、タブタイトルの横にドットインジケータを表示する。

**トリガー条件**（設定で個別ON/OFF可能）:
- プロセス終了（PTYのexit）
- 新規出力（pty_outputイベント受信）
- BEL文字（\x07）受信

**表示仕様**:
- 単色ドット（アクセントカラー）
- タブタイトルの左側に表示
- アクティブタブでは表示しない

**クリア条件**:
- タブをアクティブにした時に自動クリア

#### F02: デスクトップ通知

**説明**: eMtermウィンドウが非アクティブの時にアクティビティが発生したら、OSのデスクトップ通知を送信する。

**実装**: tauri-plugin-notification

**通知内容**:
- タイトル: "eMterm"
- 本文: アクティビティの種類に応じたメッセージ
  - プロセス終了: "{タブタイトル}: Process exited (code {N})"
  - 新規出力: "{タブタイトル}: New output"
  - BEL: "{タブタイトル}: Bell"

**デフォルト**: ON

#### F03: ウィンドウフォーカス追跡

**説明**: eMtermウィンドウのアクティブ/非アクティブ状態を追跡し、デスクトップ通知のトリガー判定に使用する。

**実装**: `document.visibilitychange` イベントまたはTauriのウィンドウイベントを使用

#### F04: 通知設定

**説明**: 設定画面に通知関連の設定セクションを追加する。

**設定項目**:

| 項目 | キー | 型 | デフォルト |
|------|------|----|-----------|
| デスクトップ通知 | `notification_enabled` | bool | true |
| タブインジケータ | `tab_activity_indicator` | bool | true |
| プロセス終了で通知 | `notify_on_process_exit` | bool | true |
| 新規出力で通知 | `notify_on_output` | bool | false |
| BELで通知 | `notify_on_bell` | bool | true |

## 4. 非機能要件

### 4.1 パフォーマンス要件

- 新規出力によるインジケータ更新は、高頻度出力時にスロットリングする（最大1回/秒）
- デスクトップ通知も同様にスロットリングする（同一タブから最大1回/5秒）

### 4.2 セキュリティ要件

- 通知内容にターミナル出力の中身を含めない（タブタイトルとイベント種別のみ）

### 4.3 互換性要件

- Linux: libnotifyまたはD-Bus通知に対応
- macOS / Windows: Tauri notification pluginのネイティブサポートに準拠

## 5. UI/UX要件

### 5.1 タブインジケータ

- ドットはタブアイコンの位置（タイトルの左側）に表示
- 色はテーマのアクセントカラーを使用
- サイズ: 8px程度の円形
- アニメーション: 不要（静的表示）

### 5.2 設定画面

- 既存の設定カテゴリに「通知」セクションを追加
- トグルスイッチで各項目のON/OFFを切り替え

## 6. 制約条件

### 6.1 技術的制約

- tauri-plugin-notification の追加が必要（Cargo.toml, tauri.conf.json, capabilities）
- ウィンドウフォーカス追跡機能が現在未実装のため新規実装が必要
- 新規出力の通知はスロットリングが必須（大量出力時のパフォーマンス対策）

## 7. 成功基準

### 7.1 受け入れ基準

- [ ] 非アクティブタブでプロセスが終了した時、ドットインジケータが表示される
- [ ] 非アクティブタブでBEL文字を受信した時、ドットインジケータが表示される
- [ ] 非アクティブタブで新規出力があった時、ドットインジケータが表示される（設定がONの場合）
- [ ] タブをアクティブにするとインジケータが消える
- [ ] ウィンドウ非アクティブ時にデスクトップ通知が送信される
- [ ] 設定画面から通知のON/OFFが切り替えられる
- [ ] 設定画面からトリガー条件を個別にカスタマイズできる
- [ ] 高頻度出力時にスロットリングが正しく機能する

### 8.1 テスト観点
