# ステータスバー - 要件定義書

## 1. 概要

### 1.1 背景
ターミナル操作中に、現在時刻、カレントディレクトリ、Gitブランチなどの情報をリアルタイムで確認したいニーズがある。

### 1.2 目的
アプリケーションウィンドウ下部にステータスバーを追加し、ユーザー定義のテンプレート変数とOSCシーケンスによる外部プロセスからの情報表示を可能にする。

### 1.3 スコープ
- ステータスバーのUI実装（WebView HTML/CSS）
- テンプレート変数システム（time, cwd, git_branch, cmd:name）
- OSCプロトコル（OSC 777;statusbar;...）による外部コンテンツ制御
- 設定パネルへの「Status Bar」カテゴリ追加
- カスタムコマンド定義と個別リフレッシュレート

## 2. ビジネス要件

### 2.1 ビジネス目標
ターミナル画面を離れずにコンテキスト情報を常時表示し、作業効率を向上させる。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| ターミナルユーザー | 時刻やGit情報を常時確認したいユーザー |
| スクリプト開発者 | OSCシーケンスでカスタム情報を表示したいユーザー |

### 2.3 期待される効果
- コンテキスト切り替え不要でGit状態や時刻を確認可能
- OSCシーケンスによるカスタマイズ性

## 3. ユースケース

### 3.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | ステータスバーの有効化 | ユーザー | 高 |
| UC02 | テンプレート変数によるコンテキスト表示 | ユーザー | 高 |
| UC03 | OSCシーケンスによる外部コンテンツ表示 | 外部プロセス | 高 |
| UC04 | カスタムコマンドの定義と表示 | ユーザー | 中 |
| UC05 | ステータスバーの外観カスタマイズ | ユーザー | 中 |

### 3.2 ユースケース詳細

#### UC01: ステータスバーの有効化

**アクター**: ユーザー

**事前条件**:
- ステータスバーはデフォルトで無効

**基本フロー**:
1. ユーザーが設定パネルを開く
2. 「Status Bar」カテゴリでステータスバーを有効にする
3. ウィンドウ下部にステータスバーが表示される

**事後条件**:
- ステータスバーが表示され、デフォルトテンプレートで情報が表示される

#### UC02: テンプレート変数によるコンテキスト表示

**アクター**: ユーザー

**事前条件**:
- ステータスバーが有効

**基本フロー**:
1. テンプレート文字列にて `{time}`, `{cwd}`, `{git_branch}`, `{cmd:name}` を使用
2. 各変数が個別リフレッシュレートで自動更新される
3. ステータスバーに最新情報が表示される

**代替フロー**:
- 変数の値が取得できない場合は空文字列として表示

#### UC03: OSCシーケンスによる外部コンテンツ表示

**アクター**: 外部プロセス

**事前条件**:
- ステータスバーが有効

**基本フロー**:
1. 外部プロセスがOSC 777;statusbar;set;left;content を送信
2. OSCレイヤーに内容が表示される（HTMLタグはストリップ）
3. OSCレイヤーが自動的に表示状態になる

**代替フロー**:
- clear コマンドで内容をクリア
- hide コマンドでOSCレイヤーを非表示

#### UC04: カスタムコマンドの定義と表示

**アクター**: ユーザー

**事前条件**:
- ステータスバーが有効

**基本フロー**:
1. 設定で `statusbar_custom_commands` に実行ファイルパスを定義（引数指定不可）
2. テンプレートで `{cmd:name}` として参照
3. 指定されたインターバルで実行ファイルが実行され、結果が表示される

## 4. 機能要件

### 4.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | レイヤー構造 | OSCレイヤー + アプリケーションレイヤー（2行）の3層構造 | 高 |
| F02 | テンプレート変数システム | time, cwd, git_branch, cmd:name の解決と表示 | 高 |
| F03 | OSCプロトコル | OSC 777;statusbar;... による外部コンテンツ制御 | 高 |
| F04 | 設定UI | Status Barカテゴリの設定パネル | 高 |
| F05 | カスタムコマンド | ユーザー定義コマンドの実行と表示 | 中 |
| F06 | 外観カスタマイズ | 色、フォントサイズ、透明度等のカスタマイズ | 中 |

### 4.2 機能詳細

#### F01: レイヤー構造

**説明**: ステータスバーは最大3行で、各レイヤーは空の場合に非表示となる。

**構造（上から下）**:
1. OSCレイヤー（1行固定、コンテンツがない場合非表示）
2. アプリケーションレイヤー 1行目
3. アプリケーションレイヤー 2行目（デフォルト空、非表示）

**各レイヤー**: 左セクション / 右セクションで構成

**デフォルト表示**: 1行（アプリケーションレイヤー1行目）: 左 = `{time}`, 右 = `{cwd}`

**Muxモード**: 有効時は常に表示（モードに関係なく）

#### F02: テンプレート変数システム

**変数一覧**:
| 変数 | 説明 | デフォルトリフレッシュレート |
|------|------|--------------------------|
| `{time}` | 現在時刻（フォーマット設定可能） | 1000ms |
| `{cwd}` | カレントディレクトリ（basename） | 1000ms |
| `{git_branch}` | Gitブランチ名（状態に応じて色変更） | 1000ms |
| `{cmd:name}` | カスタムコマンドの実行結果 | コマンドごとに設定 |

**個別リフレッシュレート**: 各変数は設定で個別にリフレッシュレート（ms）を指定可能

**Git Branch の色変更**: dirty/clean等のGit状態に応じてブランチテキストの色が変化

#### F03: OSCプロトコル

**プロトコル**: `OSC 777 ; statusbar ; <command> ST`

| コマンド | 説明 |
|----------|------|
| `set;left;content` | OSCレイヤーの左セクションにテキストを設定 |
| `set;right;content` | OSCレイヤーの右セクションにテキストを設定 |
| `clear` | OSCレイヤーの全コンテンツをクリア |
| `clear;left` | 左セクションのみクリア |
| `clear;right` | 右セクションのみクリア |
| `show` | OSCレイヤーを表示 |
| `hide` | OSCレイヤーを非表示 |

**セキュリティ**: OSCコンテンツはすべてのHTMLタグをストリップし、プレーンテキストのみ表示

**注意**: show/hide はOSCレイヤーのみを制御し、ステータスバー全体の表示/非表示には影響しない

#### F04: 設定UI

**新規カテゴリ**: 設定パネルに「Status Bar」カテゴリを追加

**設定項目**:
- 有効/無効（デフォルト: OFF）
- アプリケーションレイヤー各行の左右テンプレート文字列
- 時刻フォーマット（例: HH:MM:SS）
- カスタムコマンド定義
- 外観カスタマイズ（色、フォントサイズ、透明度など）

#### F05: カスタムコマンド

**定義方式**: 設定のstatusbar_custom_commandsで定義

```json
{
  "statusbar_custom_commands": {
    "weather": { "executable": "/usr/local/bin/my-weather", "interval_ms": 60000 }
  }
}
```

**制約**: 実行ファイルのパスのみ指定可能（引数指定不可、シェル展開なし）。複雑な処理が必要な場合はラッパースクリプトを作成して指定する。

**参照方式**: テンプレートで `{cmd:weather}` として参照

**デフォルトインターバル**: 1000ms

## 5. 非機能要件

### 5.1 パフォーマンス要件
- テンプレート変数の更新がターミナルの描画パフォーマンスに影響しないこと
- カスタムコマンドの実行は非同期で行い、UIをブロックしないこと

### 5.2 セキュリティ要件
- OSCコンテンツ: すべてのHTMLタグを完全にストリップ（XSS防止）
- 内部コンテンツ（テンプレート）: フルHTML/CSS対応（ユーザー責任）

### 5.3 保守性要件
- 既存のタブバーと同様のWebView HTML/CSS実装パターンに従う

### 5.4 互換性要件
- Linux / Windows 両プラットフォームで動作すること

## 6. UI/UX要件

### 6.1 画面設計要件
- ウィンドウ最下部に配置（ターミナル画面の外側、タブバーと同様の位置づけ）
- デフォルトの色はUI色（ターミナル画面色ではない）
- WebView HTML/CSSで描画

### 6.2 レイヤー表示

```
┌─────────────────────────────────────┐
│           Terminal Screen            │
├─────────────────────────────────────┤
│ [OSC左]                  [OSC右]    │ ← OSCレイヤー（空なら非表示）
│ [App1左]                [App1右]    │ ← アプリレイヤー1行目
│ [App2左]                [App2右]    │ ← アプリレイヤー2行目（空なら非表示）
└─────────────────────────────────────┘
```

## 7. データ要件

### 7.1 設定データ

| 項目 | 型 | 必須 | デフォルト | 説明 |
|------|-----|------|-----------|------|
| statusbar_enabled | bool | - | false | ステータスバーの有効/無効 |
| statusbar_app_line1_left | string | - | "{time}" | アプリレイヤー1行目左テンプレート |
| statusbar_app_line1_right | string | - | "{cwd}" | アプリレイヤー1行目右テンプレート |
| statusbar_app_line2_left | string | - | "" | アプリレイヤー2行目左テンプレート |
| statusbar_app_line2_right | string | - | "" | アプリレイヤー2行目右テンプレート |
| statusbar_time_format | string | - | "HH:MM:SS" | 時刻表示フォーマット |
| statusbar_custom_commands | object | - | {} | カスタムコマンド定義 |
| statusbar_colors | object | - | (UIデフォルト) | 外観カスタマイズ |
| statusbar_font_size | number | - | (UIデフォルト) | フォントサイズ |

## 8. 外部連携

### 8.1 連携システム
| システム名 | 連携方法 | データ |
|------------|----------|--------|
| Shell (cwd) | OSC 7 / ポーリング | カレントディレクトリ |
| Git | コマンド実行 | ブランチ名、ダーティ状態 |
| 外部プロセス | OSC 777;statusbar | テキストコンテンツ |

### 8.2 更新メカニズム
- ポーリング + イベント駆動（Shell Integration: OSC 7, OSC 133）
- 各変数が個別リフレッシュレート（ms、デフォルト1000ms）を持つ

## 9. 制約条件

### 9.1 技術的制約
- WebView HTML/CSSで描画（Canvas不使用）
- 既存のタブバー実装パターンに準拠
- OSCコンテンツはHTMLタグを完全ストリップ

### 9.2 ビジネス上の制約
- デフォルトOFF（既存ユーザーの体験を変更しない）

## 10. 想定される課題とリスク

### 10.1 技術的課題
| 課題 | 影響度 | 対応策 |
|------|--------|--------|
| カスタムコマンド実行のセキュリティ | 中 | ユーザー定義コマンドのみ実行、バリデーション実施 |
| ポーリングによるリソース消費 | 低 | 個別リフレッシュレートで制御、非アクティブタブでは停止 |

## 13. 用語定義

| 用語 | 定義 |
|------|------|
| OSCレイヤー | 外部プロセスからOSCシーケンスで制御されるステータスバーの最上行 |
| アプリケーションレイヤー | eMtermが自動的に管理するステータスバーの下2行 |
| テンプレート変数 | `{variable}` 形式のプレースホルダー。eMtermが値を解決して表示する |
| カスタムコマンド | ユーザーが設定で定義し、定期実行される外部コマンド |
