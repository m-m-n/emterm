# 要件定義書: mux を CLI ビルドに同梱

## 1. 概要

eMterm の mux サブシステム（daemon / bridge / CLI / PTY）を CLI ビルド
(`cargo build --release --no-default-features`、`emterm-cli` deb) に
標準で含める。SSH 越しのヘッドレス Linux サーバで
`emterm mux --daemon` を動かすため。

新しい cargo feature・make target・deb パッケージは追加しない。既存の
`make build` / `make cli-build` / `make dpkg` / `make cli-dpkg` の挙動は
そのままで、`emterm-cli` バイナリの能力だけが拡張される。

## 2. 動機

CLI ビルドは元々「webkit / gtk を入れられない SSH ホスト用」に存在
していたが、その SSH 用途で最も価値がある「mux daemon を立てて
ローカル GUI eMterm から接続」が CLI ビルドだとできなかった。mux は
GUI 依存を持たないので「常時 build」に格上げする。

## 3. ユースケース

### UC1: SSH ホストで mux daemon を起動

ユーザは libc6 のみ入った Linux サーバに `emterm-cli` deb を入れて
`emterm mux --daemon` を実行、ローカルの GUI eMterm から SSH 越しに
接続する。

### UC2: GUI ビルド挙動は変更しない

`make build` / `make dpkg` で生成される `emterm` deb は従来通り。

## 4. 機能要件

### FR1: `mux` cargo feature の削除

直前のコミット（`feat(mux): split mux into standalone cargo feature`）で
追加した `mux` feature を削除。mux サブシステムは feature gate しない。

### FR2: mux 関連 deps を常時 build 化

`Cargo.toml` で以下を `optional = true` 外して `[dependencies]` 直下に
配置:
tokio / tokio-util / futures / chrono / anyhow / hostname / vt100 /
portable-pty / term_core / mux_ipc。

### FR3: `lib.rs` の mux/pty/scroll/wakeup/self_exec の gate を削除

これらのモジュールから `#[cfg(feature = "mux")]` を外し、常時 build。

### FR4: `mux::tmux_import` のみ `feature = "gui"` を維持

`settings_store`（GUI 専用）に依存するため。call site（`run_gui` と
`mux::cli::execute_mux`）も `#[cfg(feature = "gui")]` のままにする。

### FR5: `main.rs` の mux dispatch gate を削除

`if sub == "mux"` の `#[cfg(feature = "mux")]` ガードと
`"not available in this build"` フォールバックを削除。

### FR6: `viewer_kinds.rs` SSOT 維持

`REPLAYABLE_VIEWER_KINDS` を `viewer_kinds.rs` から `pub use` で
再エクスポートする構造はそのまま。

### FR7: `mux::prefix` テストの GUI 非依存化を維持

`crate::settings::parse_mux_action_chord` → `crate::mux::prefix::parse_prefix_key`
への書き換えはそのまま。

### FR8: ビルドコマンドは元の状態に戻す

- `make build` / `make cli-build` / `make dpkg` / `make cli-dpkg` の
  シグネチャは prior コミット以前の状態に戻す
- `make mux-build` / `make mux-dpkg` の新規 target は削除
- `EMTERM_MUX_ONLY=1` 分岐は `scripts/build-dpkg.sh` から削除
- `emterm-mux` deb は廃止

### FR9: `emterm-cli` deb の Description に mux エントリ追加

mux サブコマンドを deb Description に明記する。

## 5. 非機能要件

### NFR1: GUI ビルド bit-identical

`cargo build --release` の compile 対象 crate 群は prior 状態と同じ。

### NFR2: CLI ビルドは GUI deps を一切リンクしない

winit / wgpu / wry / GTK / WebKitGTK / swash / zeno / fontdb 等は CLI
ビルドにリンクされない。`emterm-cli` deb の Depends は libc6 のみ。

### NFR3: 新規テスト不要

`viewer_kinds` / `mux::prefix` の既存テストでカバー済み。

## 6. 確認した重要事項

- バイナリ名は変えない（`emterm-cli` deb も `/usr/bin/emterm` を install）
- `emterm` deb と `emterm-cli` deb は同一マシンで共存しないので
  Conflicts/Replaces は宣言しない
- mux::cli の positional subcommand に `daemon` arm を追加しない（既存の
  `--daemon` フラグで十分、ドキュメントを実装に揃える）
- CLI ビルド独自の "mux 無し" モードは設けない
