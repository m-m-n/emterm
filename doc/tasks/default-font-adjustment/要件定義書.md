# デフォルトフォントの調整 - 要件定義書

## 1. 概要

### 1.1 背景
eMterm のフォント設定は、ハードコードされた特定フォント名（Inconsolata, Noto Sans JP 等）に依存しており、これらがインストールされていない環境ではフォールバックが不十分である。また、フォントピッカーでフォントを選択した後、デフォルト状態に戻す手段がない。

### 1.2 目的
- 業界標準のシステムフォントスタックを導入し、全プラットフォームで最適なフォントが自動選択されるようにする
- フォントピッカーにクリア機能を追加し、ユーザーがデフォルト状態に戻せるようにする

### 1.3 スコープ
- ターミナル、UI、Markdown ビューアー、その他全コンポーネントのフォントスタック更新
- フォントピッカーのクリアボタン追加
- Rust バックエンドのデフォルト値は UIフォント（Roboto）のみ維持、他は変更なし

## 2. ビジネス要件

### 2.1 ビジネス目標
クロスプラットフォームで一貫した表示品質を提供し、ユーザーがフォント設定を容易に管理できるようにする。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| 一般ユーザー | デフォルトフォントで快適にターミナルを利用するユーザー |
| カスタマイズユーザー | フォントを変更し、必要に応じてデフォルトに戻したいユーザー |

### 2.3 期待される効果
- フォント未インストール環境での表示品質向上
- フォント設定のリセット操作が直感的に行えるようになる

## 3. ユースケース

### 3.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | デフォルトフォントでターミナルを使用 | 一般ユーザー | 高 |
| UC02 | フォント設定をデフォルトに戻す | カスタマイズユーザー | 高 |

### 3.2 ユースケース詳細

#### UC01: デフォルトフォントでターミナルを使用

**アクター**: 一般ユーザー

**事前条件**:
- フォント設定が未変更（空文字列）

**基本フロー**:
1. ユーザーが eMterm を起動する
2. システムがシステムフォントスタックを適用する
3. OS に応じた最適な等幅フォントが自動選択される

**事後条件**:
- 各プラットフォームで最適なフォントが表示される

#### UC02: フォント設定をデフォルトに戻す

**アクター**: カスタマイズユーザー

**事前条件**:
- フォントピッカーでカスタムフォントが設定されている

**基本フロー**:
1. ユーザーが設定パネルを開く
2. フォント入力欄の横にある×ボタンをクリックする
3. フォント設定が空文字列にリセットされる
4. デフォルトのシステムフォントスタックが適用される

**事後条件**:
- フォント設定が空文字列になり、デフォルトフォントが表示される

## 4. 機能要件

### 4.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | ターミナルフォントスタック更新 | 等幅システムフォントスタックの導入 | 高 |
| F02 | フォントピッカーにクリアボタン追加 | ×ボタンでフォント設定をリセット | 高 |
| F03 | ハードコードフォント一括置換 | 全コンポーネントのフォントをシステムスタックに置換 | 高 |
| F04 | Markdown フォント更新 | body と code のフォールバックを更新 | 高 |

### 4.2 機能詳細

#### F01: ターミナルフォントスタック更新

**説明**: ターミナルのデフォルトフォントフォールバックを `monospace` 単独からシステムフォントスタックに変更する。

**フォントスタック**:
```
ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, 'Liberation Mono', 'Courier New', monospace
```

**対象箇所**:
- `buildFontFamilyChain()` のフォールバック末尾
- `DEFAULT_FONT_FAMILY` 定数
- CSS 変数フォールバック

#### F02: フォントピッカーにクリアボタン追加

**説明**: 全フォントピッカー入力欄の横に×ボタンを追加し、クリックで設定を空文字列にリセットする。

**動作仕様**:
- フォント値が空でない場合のみ×ボタンを表示
- クリック時に `onSelect("")` を呼び出し
- 入力欄の表示が placeholder に戻る

#### F03: ハードコードフォント一括置換

**説明**: `"Inconsolata", "Noto Sans JP", "Noto Color Emoji", monospace` のハードコードをシステムフォントスタックに置換する。

**対象ファイル**:
- `src/styles.css` (body)
- `src/image-viewer/` (styles.css, index.ts, display-mode-styles.ts)
- `src/clipboard/dialog.ts`
- `src/shared/zoom-styles.ts`
- `src/markdown/link-dialog.css`
- その他同パターンのファイル

#### F04: Markdown フォント更新

**説明**: Markdown ビューアーの CSS フォールバックを業界標準のシステムフォントスタックに更新する。

**body フォントスタック**:
```
system-ui, -apple-system, 'Segoe UI', Roboto, 'Helvetica Neue', 'Noto Sans', 'Liberation Sans', Arial, sans-serif, 'Apple Color Emoji', 'Segoe UI Emoji', 'Segoe UI Symbol', 'Noto Color Emoji'
```

**code フォントスタック**:
```
ui-monospace, SFMono-Regular, Menlo, Monaco, Consolas, 'Liberation Mono', 'Courier New', monospace
```

## 5. 非機能要件

### 5.1 互換性要件
- macOS: SF Mono / Menlo が自動選択されること
- Windows: Consolas が自動選択されること
- Linux: Liberation Mono / DejaVu Sans Mono が自動選択されること

### 5.2 保守性要件
- フォントスタックは CSS 変数として一元管理する
- ハードコードされた特定フォント名を排除する

## 6. UI/UX要件

### 6.1 クリアボタンの設計
- フォント入力欄の右側に×ボタンを配置
- ボタンは値が空でない場合のみ表示
- 既存の「変更」ボタンの左側に配置

## 7. 制約条件

### 7.1 技術的制約
- `ui-monospace` は Safari/WebKitGTK のみサポート（Chrome/Firefox 未対応）。フォールバックチェーン必須
- Rust 側の UI フォントデフォルト「Roboto」は変更しない
- 既存の設定値との後方互換性を維持する

## 8. 確認事項

### 8.1 確認済み事項
- [x] ターミナル等幅フォント: Tailwind/GitHub 方式のシステムフォントスタックを採用
- [x] UI フォント: Rust デフォルト「Roboto」は維持。CSS フォールバックも維持
- [x] デフォルト復帰方法: フォントピッカー入力欄に×クリアボタンを追加
- [x] body フォント: システムモノスペーススタックに置換
- [x] Markdown フォント: body は system-ui スタック + 絵文字、code はシステムモノスペーススタックに更新
- [x] ハードコードフォント: 全て一括でシステムフォントスタックに置換
- [x] 問題の本質: テキスト入力欄が readOnly で直接空にできない + フォントピッカーに「クリア」選択肢がない

### 8.2 未確認・保留事項
- なし
