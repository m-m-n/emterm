# WASM実装の最適化 - 要件定義書

## 1. 概要

### 1.1 背景
Sprint 0〜7 でターミナルコアの全WASM移行が完了し、アーキテクチャ的には最終目標を達成した。しかし、実装の詳細を精査した結果、パフォーマンス、メモリ効率、コード品質の各観点で改善可能な箇所が9つ特定された。

### 1.2 目的
WASM実装の内部品質を向上させ、大量データ処理時の性能改善、メモリ効率の向上、データ整合性の確保、およびバイナリサイズの最適化を達成する。

### 1.3 スコープ
- WASM側（wasm/src/配下）のRustコードの最適化
- フロントエンド側のCanvas描画ロジック改善（差分スクロール）
- ビルド設定の最適化（Cargo.toml）

## 2. ビジネス要件

### 2.1 ビジネス目標
ターミナルエミュレーターとしてのパフォーマンスと信頼性を向上させ、大量出力やリサイズ時のユーザー体験を改善する。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| ターミナル利用者 | 大量テキスト出力（cat, grep等）を行うユーザー |
| 絵文字/特殊文字利用者 | ZWJ family emojiなど16バイト超の書記素クラスタを使用するユーザー |
| 大容量scrollback利用者 | scrollback行数を多く設定するユーザー |

### 2.3 期待される効果
- 大量データ処理時のアロケーション削減による性能向上
- リサイズ時のoverflowデータ消失防止
- WASMバイナリサイズの削減
- 差分スクロール描画による描画負荷軽減

## 3. ユースケース

### 3.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | 大量テキスト出力の高速処理 | ターミナル利用者 | 高 |
| UC02 | リサイズ後の絵文字表示維持 | 絵文字利用者 | 高 |
| UC03 | 高速スクロール描画 | ターミナル利用者 | 中 |

### 3.2 ユースケース詳細

#### UC01: 大量テキスト出力の高速処理

**アクター**: ターミナル利用者

**事前条件**:
- eMtermでシェルセッションが開かれている

**基本フロー**:
1. ユーザーが `cat large_file` 等を実行
2. PTYからのデータをWASMパーサーが処理
3. 中間バッファなしで直接ディスパッチ
4. 固定長配列によりCSIパラメータをスタック上で処理

**事後条件**:
- ヒープアロケーションが最小化されている

#### UC02: リサイズ後の絵文字表示維持

**アクター**: 絵文字利用者

**事前条件**:
- ターミナルにZWJ family emoji等の16バイト超書記素が表示されている

**基本フロー**:
1. ユーザーがウィンドウをリサイズ
2. reflow処理でoverflowエントリをPhysicalLineに取り込み
3. 再構成後に新しいoverflowテーブルに再登録

**事後条件**:
- リサイズ前と同じ書記素が正しく表示される

#### UC03: 高速スクロール描画

**アクター**: ターミナル利用者

**事前条件**:
- ターミナルでテキストが出力されスクロールが発生

**基本フロー**:
1. フルスクリーンスクロール発生
2. WASM側で新規行のみをdirtyにマーク
3. フロントエンドでCanvas scrollByにより既存内容をシフト
4. 新規行のみ描画

**事後条件**:
- 全行再描画を回避し、描画コストが削減される

## 4. 機能要件

### 4.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | process_pty_data直接ディスパッチ | std::mem::takeでParser取り出し、中間Vec排除 | 高 |
| F02 | Reflow overflow保持 | リサイズ時にoverflowデータをPhysicalLineに取り込み再登録 | 高 |
| F03 | ParsedAction固定長配列化 | CsiDispatchのparams/intermediatesを固定長配列に変更 | 中 |
| F04 | Cell padding活用 | underline_style(1B) + underline_color(3B) | 中 |
| F05 | OverflowTableキー拡張 | キーを(u16, u16)から(u32, u32)に変更 | 低 |
| F06 | shift_rows逆引きindex | 行単位のHashMap<u32, Vec<u32>>を追加 | 低 |
| F07 | Cargo.tomlビルド最適化 | codegen-units=1, strip=symbols追加 | 低 |
| F08 | 差分スクロール描画 | Canvas scrollByで既存内容シフト、新規行のみ描画 | 中 |
| F09 | APC/DCSバッファ事前確保 | Vec::with_capacity(4096)で初期確保 | 低 |

### 4.2 機能詳細

#### F01: process_pty_data直接ディスパッチ

**説明**: `std::mem::take`でParserを`self`から一時的に取り出し、コールバック内で`self`に直接ディスパッチすることで中間Vecアロケーションを排除する。

**対象ファイル**: `wasm/src/terminal_core.rs`

**処理フロー**:
1. `std::mem::take(&mut self.parser)` でParserを取り出す
2. `parser.parse(data, |action| { ... })` 内で `self` のメソッドを直接呼ぶ
3. 処理完了後 `self.parser = parser` で復元

#### F02: Reflow overflow保持

**説明**: `reflow_drain`でoverflowエントリをPhysicalLineの文字データに取り込み、`reflow_split_at_width`で再構成後に新しいoverflowテーブルに再登録する。

**対象ファイル**: `wasm/src/ring_buffer.rs`

**処理フロー**:
1. `reflow_drain`でcellを読み取る際、overflow(char_len=0xFF)のセルのデータを取得
2. PhysicalLine構造体にoverfowデータを保持
3. `reflow_split_at_width`で新しいring bufferに書き込む際、overflowデータを再登録
4. `resize_post_cleanup`で`overflow.clear()`を削除（または条件付きに変更）

#### F03: ParsedAction固定長配列化

**説明**: `CsiDispatch`の`params: Vec<u16>`を`params: [u16; 8]` + `param_count: u8`に、`intermediates: Vec<u8>`を`intermediates: [u8; 2]` + `intermediate_count: u8`に変更。

**対象ファイル**: `wasm/src/parser_types.rs`, `wasm/src/parser.rs`

**バリデーション**:
| 項目 | ルール | エラーメッセージ |
|------|--------|------------------|
| params数 | 最大8個（超過分は切り捨て） | N/A（サイレント切り捨て） |
| intermediates数 | 最大2個 | N/A（サイレント切り捨て） |

#### F04: Cell padding活用

**説明**: `_padding: [u8; 4]`を`underline_style: u8` + `underline_color: [u8; 3]`に変更。32バイトアラインメントは維持。

**対象ファイル**: `wasm/src/cell.rs`

**underline_style値**:
| 値 | スタイル | SGRシーケンス |
|----|---------|---------------|
| 0 | none | SGR 24 |
| 1 | single | SGR 4 / SGR 4:1 |
| 2 | double | SGR 4:2 |
| 3 | curly | SGR 4:3 |
| 4 | dotted | SGR 4:4 |
| 5 | dashed | SGR 4:5 |

**underline_color**: `[r, g, b]`の3バイト。SGR 58;2;r;g;b で設定、SGR 59 でリセット（default=`[0, 0, 0]`はデフォルトカラーを意味する、tag方式はPackedColorのtag=0相当で判別）。

#### F05: OverflowTableキー拡張

**説明**: `HashMap<(u16, u16), String>`を`HashMap<(u32, u32), String>`に変更。関連する全ての関数シグネチャを更新。

**対象ファイル**: `wasm/src/cell.rs`, `wasm/src/terminal_core.rs`, `wasm/src/ring_buffer.rs`

#### F06: shift_rows逆引きindex

**説明**: `OverflowTable`に加えて、`HashMap<u32, Vec<u32>>`（行→列リスト）の逆引きインデックスを保持。overflow追加/削除時に逆引きも更新。

**対象ファイル**: `wasm/src/cell.rs`, `wasm/src/terminal_core.rs`, `wasm/src/ring_buffer.rs`

#### F07: Cargo.tomlビルド最適化

**説明**: `[profile.release]`に`codegen-units = 1`と`strip = "symbols"`を追加。

**対象ファイル**: `wasm/Cargo.toml`

#### F08: 差分スクロール描画

**説明**: フルスクリーンスクロール（count=1）時に全行mark_all_dirtyではなく、WASM側でスクロールイベントを通知し、フロントエンドでCanvas scrollByによる差分描画を行う。

**対象ファイル**:
- WASM側: `wasm/src/ring_buffer.rs`（dirty管理の変更）
- フロントエンド側: `src/terminal/canvas-renderer.ts`（差分描画ロジック）

**処理フロー**:
1. scroll_up_internal(count=1, フルスクリーン)時、新規行のみをdirtyマーク
2. スクロールイベント情報（方向、行数）を保持
3. フロントエンド側でスクロールイベントを検知
4. Canvas.scrollBy（またはdrawImageでself-copy）で既存コンテンツをシフト
5. 新規行のみ描画

#### F09: APC/DCSバッファ事前確保

**説明**: `apc_buffer`と`dcs_buffer`を`Vec::with_capacity(4096)`で初期化。

**対象ファイル**: `wasm/src/parser.rs`

## 5. 非機能要件

### 5.1 パフォーマンス要件
- F01/F03: 大量データ処理時のヒープアロケーション回数を大幅に削減
- F08: フルスクリーンスクロール時の描画コストをO(rows)からO(1) + 1行描画に削減

### 5.2 メモリ効率
- F01: 中間Vecバッファのメモリ使用を排除
- F03: CSIパラメータをスタック上で処理
- F07: バイナリサイズ削減

### 5.3 データ整合性
- F02: リサイズ後も16バイト超の書記素クラスタが正しく表示される
- F05: scrollback行数に関わらずoverflow参照が正しく動作する

### 5.4 互換性要件
- Cell構造体のサイズは32バイトを維持
- 既存のpacked binary format（JS境界向け）は変更不要

## 6. 制約条件

### 6.1 技術的制約
- Rustの借用規則: `self`の再借用問題に対処する必要がある（F01）
- WASM環境: `std::mem::take`パターンはWASM互換
- Cell構造体は`#[repr(C)]`で32バイト固定
- ParsedActionは内部型でwasm-bindgenに非公開

## 7. 想定される課題とリスク

### 7.1 技術的課題
| 課題 | 影響度 | 対応策 |
|------|--------|--------|
| F01のParser取り出し後の状態整合性 | 高 | take後に必ず復元、panicガードの検討 |
| F02のreflow複雑性増大 | 中 | 段階的実装、既存テストの充実 |
| F08のCanvasスクロール時の描画アーティファクト | 中 | sub-pixel座標の丸め処理 |
| F04のunderline_color表現方法 | 低 | デフォルトカラー判定方式の設計 |
