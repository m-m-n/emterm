# タブバーの横スクロールとアクティブインジケーター改善 - 要件定義書

## 1. 概要

### 1.1 背景
タブが増えて画面幅を超えたときの操作性と、mux タブと通常タブが混在する場合のアクティブ表示に課題がある。

### 1.2 目的
- タブが増えたときに横スクロールを快適に操作できるようにする。
- キー操作でアクティブタブを移動したとき、そのタブが画面内に表示されるようにする。
- mux タブと通常タブの混在時に、アクティブを示すバーが常に 1 本だけになるようにする。

### 1.3 スコープ
- 対象: native ビルドのタブバー描画 (`src-tauri/src/ui/tab_bar.rs` および関連する `src-tauri/src/app.rs` / `src-tauri/src/render/mod.rs`)。
- 対象外: WebView 版のタブバー (廃棄予定の `src/` 配下)。

## 2. ビジネス要件

### 2.1 ビジネス目標
タブを多数開いた状態での操作性を高め、表示状態の不整合をなくす。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| ターミナル利用者 | 多数のタブ、または mux タブと通常タブを併用するユーザー |

### 2.3 期待される効果
- タブが多くてもマウスホイールで素早く左右移動できる。
- キー操作で選んだタブが画面外に隠れない。
- アクティブなタブが視覚的に常に 1 つに定まる。

## 3. ユースケース

### 3.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | ホイールでタブバーを横スクロール | ユーザー | 高 |
| UC02 | キー操作でアクティブタブを画面内に表示 | ユーザー | 高 |
| UC03 | mux タブと通常タブ混在時のアクティブ表示 | ユーザー | 高 |

### 3.2 ユースケース詳細

#### UC01: ホイールでタブバーを横スクロール

**アクター**: ユーザー

**事前条件**:
- タブの合計幅が画面幅を超えており、横スクロールが発生している。

**基本フロー**:
1. ユーザーがタブバー上にマウスカーソルを置く。
2. マウスホイールを上下に回す。
3. タブバーが左右にスクロールする。
4. スクロールバーは表示されない。

**代替フロー**:
- Shift を押しながらホイールを回しても左右にスクロールする。

**事後条件**:
- タブバーの表示位置が変わる（タブの選択状態は変わらない）。

#### UC02: キー操作でアクティブタブを画面内に表示

**アクター**: ユーザー

**事前条件**:
- 横スクロールが発生しており、一部のタブが画面外にある。

**基本フロー**:
1. ユーザーがタブ切り替えキー（Ctrl+PageUp/PageDown、Ctrl+Tab/Ctrl+Shift+Tab、Ctrl+1..9 など）を押す。
2. アクティブタブが切り替わる。
3. 新しいアクティブタブが画面外にある場合、画面内に入るようタブバーが自動的にスクロールする。

**事後条件**:
- アクティブタブが画面内に表示される。

#### UC03: mux タブと通常タブ混在時のアクティブ表示

**アクター**: ユーザー

**事前条件**:
- mux タブ（複数 window を sub-tab 展開するタブ）と通常タブが両方存在する。
- mux タブのいずれかの window がアクティブで、その sub-tab にアクティブバーが表示されている。

**基本フロー**:
1. ユーザーが通常タブをアクティブにする。
2. 通常タブにアクティブバーが表示される。
3. 非アクティブになった mux タブの sub-tab のアクティブバーは消える。

**代替フロー**:
- 再び mux タブをアクティブにすると、以前アクティブだった window の sub-tab にバーが復活する。

**事後条件**:
- アクティブを示すバーは画面全体で常に 1 本だけになる。

## 4. 機能要件

### 4.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | スクロールバー非表示の横スクロール | タブ溢れ時、スクロールバーを表示しない | 高 |
| F02 | ホイールでの横スクロール | タブバー上のホイール（縦回転）で左右移動 | 高 |
| F03 | Shift+ホイールでの横スクロール | Shift+ホイールで左右移動 | 高 |
| F04 | アクティブタブの画面内表示 | キー操作でアクティブタブが画面内に入るようスクロール | 高 |
| F05 | アクティブインジケーターの一意化 | アクティブバーを画面全体で常に 1 本にする | 高 |
| F06 | 新規セルの画面内表示 | 新規タブ/mux window 作成時、新規セルをアクティブ化し画面外なら画面内へスクロール | 高 |

### 4.2 機能詳細

#### F01: スクロールバー非表示の横スクロール

**説明**: タブの合計幅が画面幅を超えたとき、横スクロールを有効にしつつスクロールバーは表示しない。

**ビジネスルール**:
- タブの合計幅が画面幅以内のときは従来通り均等幅で表示する（スクロールしない）。

#### F02: ホイールでの横スクロール

**説明**: タブバー領域にカーソルがあるとき、マウスホイールの縦回転をタブバーの左右スクロールに割り当てる。

#### F03: Shift+ホイールでの横スクロール

**説明**: Shift を押しながらのホイール操作でもタブバーを左右スクロールする。

#### F04: アクティブタブの画面内表示

**説明**: キーボード操作でアクティブなタブ（通常タブの選択、または mux タブ内の window 選択）が変わったとき、対応する表示セルが画面外なら画面内に入るようスクロールする。

**ビジネスルール**:
- スクロールするのはキーボード操作でアクティブが変わった直後のみ。マウスでスクロール位置を動かした後、無関係な再描画で勝手にアクティブタブへ戻らないこと。

#### F05: アクティブインジケーターの一意化

**説明**: mux タブの sub-tab のアクティブバーは、その mux タブ自身が現在アクティブなタブであるときのみ表示する。親タブが非アクティブなら sub-tab のバーは表示しない。

**ビジネスルール**:
- mux タブを再びアクティブにしたとき、保持していたアクティブ window の sub-tab にバーが復活する（mux 側のアクティブ window 状態は変更しない）。

#### F06: 新規セルの画面内表示

**説明**: 新規タブ、または現在のタブに mux window を追加したとき、新しいセル（タブ／sub-tab）をアクティブにし、それが画面外（溢れ時の末尾）にあれば画面内に入るようスクロールする。

**ビジネスルール**:
- `+` ボタン（マウス）・キーバインド・mux の new-window（daemon の PaneCreated 確認）のいずれの作成経路でも発火する。新規セルはまだ表示されていないため、入力手段に関わらず画面内に出す。
- F04 の「キーボード操作のときのみ」という制約は既存タブ／window 間の切り替えに対するもので、新規作成はそれとは別の発火契機として扱う。

## 5. 非機能要件

### 5.1 パフォーマンス要件
- タブストリップは毎フレーム描画されるため、追加処理で描画コストを著しく増やさないこと。

### 5.2 セキュリティ要件
- 該当なし。

### 5.3 保守性要件
- ログ出力: 該当なし（描画系の変更）。

### 5.4 互換性要件
- 既存のタブのクリック切り替え、ドラッグ並べ替え、mux sub-tab クリック切り替え、"+" / 歯車ボタンの挙動を壊さないこと。

## 6. UI/UX要件

### 6.1 画面設計要件
- スクロールバーは表示しない。
- アクティブインジケーターは下部 3px のバー（既存の `paint_active_indicator` の見た目を維持）。

### 6.2 画面遷移
- 該当なし。

## 9. 制約条件

### 9.1 技術的制約
- 描画は egui（`TopBottomPanel` + `ScrollArea::horizontal`）。
- 対象は native ビルドのみ。WebView 版は変更しない。

## 13. 用語定義

| 用語 | 定義 |
|------|------|
| 通常タブ | アプリ本体のターミナルタブ（`App::tabs` の 1 要素、`App::active` で選択） |
| mux タブ | mux daemon の window 群を sub-tab 展開するタブ（`Tab::mux_group`、`MuxWindowGroup::active` で window 選択） |
| sub-tab | mux タブ内の各 window を表す表示セル |
| アクティブインジケーター | アクティブなタブ/sub-tab の下部に表示される 3px のバー |
| visual cell | タブストリップが描く 1 つの表示セル（通常タブ=1、mux タブ=展開後の各セル） |

## 14. 確認事項

### 14.1 確認済み事項
- [x] 横スクロールの「キーバインド」の意味: 専用の横スクロールキーは設けず、既存のタブ切替キーでアクティブタブが画面内に追従すれば十分（F04 に統合）。
- [x] mux タブ非アクティブ時の sub-tab バー: 非アクティブ側は全て消す。アクティブバーは画面全体で常に 1 本。mux タブ再選択でアクティブ window のバーが復活する。
- [x] F04 の対象: キーボード操作でアクティブが変わったときのみスクロールする（マウススクロール後に勝手に戻らない）。
- [x] F06 新規セルの画面内表示: 新規タブ／mux window が画面外のとき、作成と同時に画面内へスクロールインする。`+` ボタン・キーバインド・mux new-window で発火（新規セルは未表示のため入力手段を問わない）。F04 の「キーボードのみ」制約は既存タブ／window 切替に対するもので、新規作成は別契機。

- なし。
