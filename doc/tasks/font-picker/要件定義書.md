# フォントピッカー - 要件定義書

## 1. 概要

### 1.1 背景
現在の設定パネルではフォント名をテキスト入力で直接指定する必要があり、利用可能なフォント名を正確に把握していない場合に操作が困難である。

### 1.2 目的
システムにインストールされたフォントを一覧表示し、プレビューを見ながら選択できるフォントピッカーUIを提供する。

### 1.3 スコープ
- バックエンド: font-kitを利用したフォント列挙API
- フロントエンド: フォントピッカーUI（検索、プレビュー、選択）
- 設定パネル: テキスト入力をreadonly入力+変更ボタンに変更

## 2. ユースケース

### 2.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | プライマリフォントの変更 | ユーザー | 高 |
| UC02 | セカンダリフォントの変更 | ユーザー | 高 |
| UC03 | 絵文字フォントの変更 | ユーザー | 高 |
| UC04 | フォント名で検索 | ユーザー | 高 |
| UC05 | フォントプレビューの確認 | ユーザー | 中 |

### 2.2 ユースケース詳細

#### UC01: プライマリフォントの変更

**アクター**: ユーザー

**事前条件**:
- 設定パネルが開いている
- 外観カテゴリが表示されている

**基本フロー**:
1. ユーザーがプライマリフォントの「変更」ボタンをクリック
2. 設定パネルの右側コンテンツ領域がフォントピッカーに遷移
3. モノスペースフォントのみが一覧表示される
4. 各フォント名がそのフォント自身で描画される（プレビュー）
5. ユーザーがフォントを選択
6. 設定パネルに戻り、選択したフォント名が表示される
7. ターミナルに即座に反映される

**代替フロー**:
- ユーザーが「戻る」ボタンをクリック: 変更せずに設定パネルに戻る
- ユーザーが検索バーにテキストを入力: フォント一覧がフィルタリングされる

**事後条件**:
- 選択したフォントが設定に保存される
- ターミナル表示が新しいフォントで更新される

#### UC04: フォント名で検索

**アクター**: ユーザー

**事前条件**:
- フォントピッカーが表示されている

**基本フロー**:
1. ユーザーが検索バーにテキストを入力
2. フォント一覧が入力されたテキストでフィルタリングされる（大文字小文字を区別しない）
3. マッチするフォントのみ表示される

**代替フロー**:
- 検索テキストをクリア: 全フォントが再表示される
- マッチするフォントがない: 空の一覧が表示される

### 3.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | フォント列挙API | font-kitでシステムフォントを列挙 | 高 |
| F02 | フォントカテゴリ分類 | モノスペース/全フォント/絵文字の3種分類 | 高 |
| F03 | 起動時キャッシュ | アプリ起動時に一度だけフォント列挙しメモリキャッシュ | 高 |
| F04 | フォントピッカーUI | インプレース遷移のフォント選択画面 | 高 |
| F05 | フォントプレビュー | 各フォントをそのフォント自身で描画 | 高 |
| F06 | フォント検索 | フォント名による大文字小文字非区別フィルタ | 高 |
| F07 | 設定パネルUI変更 | テキスト入力をreadonly入力+変更ボタンに変更 | 高 |

### 3.2 機能詳細

#### F01: フォント列挙API

**説明**: font-kitクレートを使用してシステムにインストールされたフォントファミリー名を列挙するTauriコマンド。

**入力**: なし

**出力**:
- `monospace_fonts`: Vec<String> - モノスペースフォントのファミリー名リスト
- `all_fonts`: Vec<String> - 全フォントのファミリー名リスト
- `emoji_fonts`: Vec<String> - 絵文字フォントのファミリー名リスト

**処理フロー**:
1. font-kitの`source`からシステムフォントソースを取得
2. 全フォントファミリーを列挙
3. 各フォントについてプロパティを取得し分類
4. モノスペース判定: font-kitの`is_monospace()`プロパティ
5. 絵文字判定: ファミリー名に "emoji" を含む（大文字小文字非区別）
6. 結果をアルファベット順にソート
7. 重複を除去して返却

#### F02: フォントカテゴリ分類

**説明**: フォントピッカーの表示対象を用途に応じて制限する。

| フォント種別 | フィルタ条件 |
|-------------|-------------|
| プライマリ（英数字用） | モノスペースフォントのみ |
| セカンダリ（CJK用） | 全フォント |
| 絵文字 | 絵文字フォントのみ |

#### F03: 起動時キャッシュ

**説明**: フォント列挙はコストが高いため、アプリ起動時に一度だけ実行し結果をメモリにキャッシュする。

**実装方針**:
- Rust側で`OnceLock`を使用
- 初回の`list_fonts`コマンド呼び出し時にフォント列挙を実行
- 以降の呼び出しではキャッシュから返却

#### F04: フォントピッカーUI

**説明**: 設定パネルの右側コンテンツ領域を置き換えるインプレース遷移のフォント選択画面。

**UI構成**:
1. ヘッダー: 戻るボタン + タイトル（例: "プライマリフォント"）
2. 検索バー: テキスト入力フィールド
3. フォントリスト: スクロール可能な一覧、各項目はそのフォント自身で描画

**遷移方式**:
- 設定パネルの`contentElement`の内容を差し替え
- 戻るボタンクリックで元の設定パネル内容に復帰
- カテゴリナビゲーションは遷移中も表示されるが無効化

#### F05: フォントプレビュー

**説明**: フォント一覧の各項目をそのフォント自身のフォントフェイスで描画する。

**プレビューテキスト**: フォントファミリー名自体をプレビューテキストとして使用

**実装方式**: 各リスト項目の`style.fontFamily`にフォント名を直接設定

#### F06: フォント検索

**説明**: 検索バーへの入力によりフォント一覧をリアルタイムでフィルタリングする。

**フィルタロジック**:
- フォントファミリー名に対する部分一致検索
- 大文字小文字を区別しない
- 入力イベントごとにフィルタリング実行

#### F07: 設定パネルUI変更

**説明**: 既存の3つのフォントテキスト入力を、readonly入力+変更ボタンの組み合わせに変更する。

**変更前**: `<input type="text">` (編集可能)
**変更後**: `<input type="text" readonly>` + `<button>変更</button>`

**表示内容**:
- readonly入力: 現在のフォント名（未設定時はプレースホルダー）
- 変更ボタン: クリックでフォントピッカーに遷移

## 4. 非機能要件

### 4.1 パフォーマンス要件
- フォント列挙: 初回5秒以内
- フォントピッカー表示: 100ms以内
- 検索フィルタリング: 入力ごとに16ms以内（60fps維持）

### 4.2 互換性要件
- Linux, macOS, Windowsで動作
- font-kitがサポートする全プラットフォームのフォントソースに対応

## 5. UI/UX要件

### 5.1 フォントピッカー画面構成

```
┌──────────────────────────────────────┐
│ ← プライマリフォント                  │  ← ヘッダー（戻るボタン + タイトル）
├──────────────────────────────────────┤
│ 🔍 フォントを検索...                  │  ← 検索バー
├──────────────────────────────────────┤
│ Courier New          (Courier New)   │  ← フォント一覧
│ Fira Code            (Fira Code)     │     各項目はそのフォント自身で描画
│ JetBrains Mono       (JetBrains)     │
│ Menlo                (Menlo)         │
│ Monaco               (Monaco)        │
│ Source Code Pro       (Source Code)   │
│ ...                                  │
└──────────────────────────────────────┘
```

### 5.2 設定パネルのフォント行

```
┌──────────────────────────────────────┐
│ プライマリフォント                    │  ← ラベル
│ 英数字に使用するフォントを設定します    │  ← 説明
│ ┌─────────────────────┐ ┌──────┐    │
│ │ Fira Code           │ │ 変更 │    │  ← readonly入力 + 変更ボタン
│ └─────────────────────┘ └──────┘    │
│ 英数字フォント                       │  ← ヒント
└──────────────────────────────────────┘
```

### 5.3 スタイル
- Material Design 3のデザインシステムに準拠（既存の設定パネルと同様）
- 戻るボタン: テキストボタンまたはアイコンボタン
- 検索バー: MD3 Outlined Text Field
- フォントリスト: 各項目はホバーで背景色変更、クリックで選択
- 選択中フォント: ハイライト表示（secondary-container色）

### 5.4 アクセシビリティ
- フォントリストは`role="listbox"`, 各項目は`role="option"`
- 検索バーは`aria-label`で説明
- 戻るボタンは`aria-label`で説明
- キーボードナビゲーション: Arrow Up/Down でリスト移動, Enter で選択, Escape で戻る

## 9. 制約条件

### 9.1 技術的制約
- font-kitはフォントファイルの読み込みが必要なため、初回列挙にはI/Oコストが伴う
- WebViewからはシステムフォント一覧にアクセスできないため、Rust側でのフォント列挙が必須
- フォントプレビューはCSSの`font-family`に依存するため、フォント名とCSSフォントファミリー名が一致する必要がある

### 9.2 プラットフォーム制約
- 各OSでフォントソースが異なる（Linux: fontconfig, macOS: Core Text, Windows: DirectWrite）
- font-kitが各プラットフォームの差異を吸収

## 10. 想定される課題とリスク

| 課題 | 影響度 | 対応策 |
|------|--------|--------|
| フォント数が多い場合のリスト表示パフォーマンス | 中 | 仮想スクロールの検討（フォント数が1000以上の場合） |
| font-kitのモノスペース判定精度 | 低 | 誤分類があっても致命的ではない |
| CSSフォントファミリー名とfont-kit名の不一致 | 中 | font-kitのファミリー名をそのまま使用し検証 |

## 13. 用語定義

| 用語 | 定義 |
|------|------|
| フォントピッカー | フォントを一覧から選択するUIコンポーネント |
| モノスペースフォント | 全文字が同じ幅を持つ等幅フォント |
| font-kit | Rustのフォント操作ライブラリ |
| OnceLock | Rustの一度だけ初期化可能なスレッドセーフなコンテナ |
