# WSLプロファイル対応 - 要件定義書

## 1. 概要

### 1.1 背景
eMtermはLinuxとWindowsをサポートするターミナルエミュレータである。Windows環境ではWSL (Windows Subsystem for Linux) が広く使われており、WSLディストリビューションへの接続をプロファイルとして簡単に設定できる仕組みが求められる。

### 1.2 目的
Windows版eMtermの設定画面にWSLセクションを追加し、インストール済みWSLディストリビューションの検出・インポート・プロファイルからの起動を可能にする。

### 1.3 スコープ
- WSLディストリビューションの自動検出
- 検出したディストリビューションの設定へのインポート
- プロファイルエディタへのWSLタブ追加
- WSLプロファイルによるセッション起動
- Windows環境のみ対象（Linux環境ではWSL関連UIを非表示）

## 2. ビジネス要件

### 2.1 ビジネス目標
Windows版eMtermのユーザビリティ向上。WSLユーザーがワンクリックでLinux環境に接続できるようにする。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| Windowsユーザー | WSLを利用してLinux環境で開発を行うユーザー |

### 2.3 期待される効果
- WSLディストリビューションへの接続が容易になる
- SSH接続と同様のUXで直感的に使える

## 3. ユースケース

### 3.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | WSLディストリビューションをインポートする | ユーザー | 高 |
| UC02 | WSLプロファイルを作成する | ユーザー | 高 |
| UC03 | WSLプロファイルで新しいタブを開く | ユーザー | 高 |
| UC04 | インポート済みディストリビューションを削除する | ユーザー | 中 |

### 3.2 ユースケース詳細

#### UC01: WSLディストリビューションをインポートする

**アクター**: ユーザー

**事前条件**:
- Windows環境でeMtermを使用している
- WSLがインストールされている

**基本フロー**:
1. ユーザーが設定画面のWSLセクションを開く
2. 検出されたWSLディストリビューション一覧が表示される
3. ユーザーが対象ディストリビューションの「Import」ボタンをクリックする
4. ディストリビューションがインポート済みリストに追加される

**代替フロー**:
- WSLがインストールされていない場合、空のリストが表示される
- 既にインポート済みのディストリビューションは Import ボタンが非活性

**事後条件**:
- `wsl_distributions` に追加される

#### UC02: WSLプロファイルを作成する

**アクター**: ユーザー

**事前条件**:
- WSLディストリビューションが1つ以上インポート済み

**基本フロー**:
1. ユーザーがプロファイル追加を選択する
2. プロファイルエディタのWSLタブを選択する
3. ドロップダウンからインポート済みディストリビューションを選択する
4. 保存ボタンをクリックする

**事後条件**:
- `wsl_distro_name` が設定されたプロファイルが作成される

#### UC03: WSLプロファイルで新しいタブを開く

**アクター**: ユーザー

**事前条件**:
- WSLプロファイルが作成済み

**基本フロー**:
1. ユーザーがプロファイルセレクタからWSLプロファイルを選択する
2. `wsl.exe -d <distro_name>` が実行される
3. 新しいタブでWSLセッションが開始される

## 4. 機能要件

### 4.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | WSLディストリビューション検出 | `wsl --list --quiet` でディストロ一覧を取得 | 高 |
| F02 | WSLディストリビューションインポート | 検出したディストロを settings に保存 | 高 |
| F03 | WSL設定セクション | 設定画面にWSLカテゴリを追加 | 高 |
| F04 | プロファイルエディタWSLタブ | Shell/SSH/WSLの3タブ構成 | 高 |
| F05 | WSLセッション起動 | wsl.exe をPTYで起動 | 高 |
| F06 | プラットフォーム判定 | Windows環境のみWSL関連UIを表示 | 高 |

### 4.2 機能詳細

#### F01: WSLディストリビューション検出

**説明**: `wsl.exe --list --quiet` を実行し、インストール済みディストリビューション名の一覧を返す。

**入力**: なし

**出力**:
- ディストリビューション名の配列（例: `["Ubuntu-22.04", "Debian"]`）

**エラーケース**:
| エラー | 条件 | 対応 |
|--------|------|------|
| WSL未インストール | `wsl.exe` が見つからない | 空配列を返す |
| コマンド実行失敗 | `wsl --list --quiet` がエラー | 空配列を返す |

#### F06: プラットフォーム判定

**説明**: フロントエンドでWindows環境かどうかを判定し、WSL関連UIの表示/非表示を制御する。

**処理**: Tauriコマンドでプラットフォーム情報を返す、または既存の仕組みを利用する。

## 5. 非機能要件

### 5.1 パフォーマンス要件
- WSLディストリビューション検出: 2秒以内に完了

### 5.2 セキュリティ要件
- `wsl.exe` の引数は配列で渡す（コマンドインジェクション防止）

### 5.3 互換性要件
- Windows 10/11 の WSL1/WSL2 両対応
- Linux環境: WSL関連UIは完全に非表示

## 6. UI/UX要件

### 6.1 設定画面WSLセクション
- SSH接続セクションの後に配置
- Windows環境のみ表示
- 2つのサブセクション:
  1. 検出されたディストリビューション（読み取り専用 + Import ボタン）
  2. インポート済みディストリビューション（削除ボタン付き）

### 6.2 プロファイルエディタ
- Windows環境: Shell | SSH | WSL の3タブ
- Linux環境: Shell | SSH の2タブ（既存のまま）
- WSLタブ: インポート済みディストリビューションのドロップダウン

## 7. データ要件

### 7.1 データモデル

**WslDistribution**:
| 項目名 | 型 | 必須 | 説明 |
|--------|-----|------|------|
| name | String | 必須 | ディストリビューション名 |

**Profile拡張**:
| 項目名 | 型 | 必須 | 説明 |
|--------|-----|------|------|
| wsl_distro_name | String | 任意 | 参照するWSLディストリビューション名 |

## 8. 制約条件

### 8.1 技術的制約
- WSL検出コマンド (`wsl.exe`) は Windows 専用
- Rustバックエンドのコードは `#[cfg(windows)]` で分離
