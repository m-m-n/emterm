# mux スクロール独立化 - 要件定義書

## 1. 概要

### 1.1 背景
mux モードでスクロール（画面外の過去ログ確認）に関する3つの不具合が確認された。コード解析で3症状とも根本原因を特定済み。

- 症状①: mux のウィンドウ（pane）切替後、過去ログをスクロールできない。デタッチ→再アタッチすると見えるようになる。
- 症状②: タブ／pane 切替時に、前のタブ／pane の表示が画面下部に残留する（新しい側のバッファが短い場合）。
- 症状③: スクロール位置が全タブ／pane で共有される。あるタブ／pane でスクロールアップして別へ切り替えると、切替先も同じスクロール位置で表示される。

### 1.2 目的
mux モードで、スクロール位置・表示内容・スクロールバック履歴をタブ／pane ごとに独立させ、切替後も各単位が自身の状態を保つようにする。

### 1.3 スコープ

**対象**
- ネイティブ実装（`src-tauri/src/`、`refactor/promote-native-poc` ブランチ）の mux モード
- スクロール位置の独立化単位: ネイティブタブ単位 と mux pane（mux ウィンドウ）単位の両方
- 症状①②③の3つすべて

**対象外**
- WebView 実装（`src/`）。本ブランチでは変更しない。
- alt-screen 中のスクロール無効化挙動（仕様どおりのため変更しない）

## 2. ビジネス要件

### 2.1 ビジネス目標
mux モードで過去ログの確認とタブ／pane ごとの作業継続を可能にし、ターミナルとしての基本操作性を満たす。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| mux 利用者 | mux モードで複数ウィンドウ（pane）／複数タブを使い分けるユーザー |

### 2.3 期待される効果
- pane／window 切替直後から過去ログをスクロールして確認できる
- 切替時に前の表示が残らない
- 各タブ／pane が自身のスクロール位置を保持する

## 3. ユースケース

### 3.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | 切替後に過去ログをスクロールする | mux 利用者 | 高 |
| UC02 | タブ／pane を切り替えても表示が混ざらない | mux 利用者 | 高 |
| UC03 | 各タブ／pane が自身のスクロール位置を保持する | mux 利用者 | 高 |

### 3.2 ユースケース詳細

#### UC01: 切替後に過去ログをスクロールする

**アクター**: mux 利用者

**事前条件**:
- mux モードで複数の pane（mux ウィンドウ）が存在する
- ある pane に scrollback に収まる量の出力がある

**基本フロー**:
1. pane A で大量の出力を流す
2. 別の pane B へ切り替える
3. pane A へ戻る
4. ホイール／Shift+PageUp で pane A の過去ログをスクロールして確認できる

**事後条件**:
- デタッチ→再アタッチを行わなくても、切替直後から過去ログが見える

#### UC02: タブ／pane を切り替えても表示が混ざらない

**アクター**: mux 利用者

**事前条件**:
- 表示行数の異なる2つのタブ／pane が存在する（一方が長い）

**基本フロー**:
1. 長い側のタブ／pane を表示する
2. 短い側のタブ／pane へ切り替える

**事後条件**:
- 切替先の内容のみが表示され、前のタブ／pane の内容が下部に残らない

#### UC03: 各タブ／pane が自身のスクロール位置を保持する

**アクター**: mux 利用者

**事前条件**:
- 複数のタブ／pane が存在する

**基本フロー**:
1. タブ／pane A でスクロールアップする
2. タブ／pane B へ切り替える（B は B 自身の位置で表示される）
3. タブ／pane A へ戻る

**事後条件**:
- A は切替前のスクロール位置で表示される
- B のスクロール位置は A の操作の影響を受けない

## 4. 機能要件

### 4.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | 切替時 snapshot への scrollback 同梱 | オンデマンド pane snapshot に scrollback 履歴を含める（症状①） | 高 |
| F02 | 切替時の表示クリア | タブ／pane 切替時に前の表示を残さず再描画する（症状②） | 高 |
| F03 | スクロール位置の独立化 | スクロール位置をネイティブタブ単位／mux pane 単位で保存・復元する（症状③） | 高 |

### 4.2 機能詳細

#### F01: 切替時 snapshot への scrollback 同梱

**説明**: mux のウィンドウ（pane）切替で client が daemon に要求するオンデマンド snapshot に、対象 pane の scrollback を含める。client は受信内容を replay して履歴を再構築する。

**ビジネスルール**:
- 初回 attach（reattach 経路）と同様に、切替後も scrollback 履歴を持つ
- daemon は既に pane の scrollback を保持しているため、応答に載せる

#### F02: 切替時の表示クリア

**説明**: アクティブなタブ／pane が変わったとき、ターミナル表示領域を全面再描画し、前のタブ／pane の行が残らないようにする。

**ビジネスルール**:
- 新しいタブ／pane の内容が前のものより短い場合でも、前の内容が下部に残らない

#### F03: スクロール位置の独立化

**説明**: スクロール位置を App グローバルの単一値ではなく、ネイティブタブごと・mux pane ごとに保持する。切替時に切替元の位置を保存し、切替先の位置を復元する。

**ビジネスルール**:
- ネイティブタブ切替で各タブ自身のスクロール位置を復元する
- mux pane 切替で各 pane 自身のスクロール位置を復元する
- 位置が末尾（Live）なら末尾を、スクロールアップ中ならその位置を復元する

## 5. 非機能要件

### 5.1 パフォーマンス要件
- スクロール位置の保存／復元は切替経路上の数値1個の操作で、影響は無視できる
- オンデマンド snapshot に scrollback を含めることで転送量が増えるが、reattach 経路と同等であり許容する

- 該当なし

- スクロール位置は現状 `App` の単一フィールド（全タブ／pane 共有）

## 12. テストシナリオ

### 12.1 テスト観点
- [ ] 正常系: pane A スクロールアップ → B 切替 → A 復帰でスクロール位置が復元される
- [ ] 正常系: 切替後に過去ログをスクロールして確認できる
- [ ] 異常系: 切替先 pane の scrollback が空でもクラッシュしない
- [ ] 境界値: すべてのタブ／pane が末尾（Live）のとき切替でスクロールが発生しない
- [ ] 境界値: 長いタブ→短いタブ切替で残留行が出ない

## 13. 用語定義

| 用語 | 定義 |
|------|------|
| mux pane | mux のウィンドウ。ユーザーがステータスバー上で「タブ」のように切り替える単位 |
| ネイティブタブ | mux に依存しない、ネイティブ実装のタブ（各タブが独立 `TerminalCore` を持つ） |
| scrollback | 画面外に流れた過去の出力履歴 |
| オンデマンド snapshot | pane 切替時に client が daemon へ要求する pane の状態スナップショット |
| reattach | client が daemon に接続し直す経路。現状は scrollback を含めて送る |
