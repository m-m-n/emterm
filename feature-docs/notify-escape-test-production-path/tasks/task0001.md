# Task Plan: task0001 — Inject capability fetch and send into notify_worker, with worker-level tests

## Goal

The unix `notify_worker` receives the capability fetch and the notification send
as injection points, delegates the escape decision to `escape_for_send`, and
forwards only its return values to the send. Worker-level tests drive
`notify_worker` with fakes (no D-Bus) and pin the delivered summary / body
exactly.

## Requirements

FR1, FR2, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/callbacks.rs` — the unix worker gains the two injection points, the worker-thread start passes the production ones, and the FR6 doc comments are corrected
- `src-tauri/src/callbacks/tests.rs` — a new unix-only submodule with the worker-level tests (TS-4 to TS-7)

## Design

Shared-component contracts (`escape_for_send`, `escape_body_markup`), the
`tests.rs` region ownership (D2) and the behavior-preservation list (D3) are in
IMPLEMENTATION.md and are not restated here.

### Injection points (unix only)

| Injection point | When the worker calls it | Input | Output | Production value | Test value |
|-----------------|--------------------------|-------|--------|------------------|------------|
| Capability fetch | Exactly once per received notification, after redaction and before the escape decision | None | Fetch outcome: a success carrying the list of capability names, or a failure | notify-rust's server-capability query (the same call as today) | A fake that returns a fixed outcome and counts its calls |
| Send | Exactly once per received notification, after `escape_for_send` | Summary and body — the return values of `escape_for_send`, unmodified | Success, or a failure carrying a displayable error | A notify-rust notification built with the given summary and body and shown (the same as today) | A recorder that appends the received summary / body to a shared list, counts calls and reports success |

Contract details:

- The failure type of the capability-fetch outcome is chosen by the caller, not
  fixed to notify-rust's error type, so a test can express "fetch failed"
  without a D-Bus connection. `escape_for_send` already accepts any failure type.
- The send failure is displayable, so the worker emits the existing warn log
  with it.
- The worker owns both injection points for its lifetime. The production ones
  are constructed so they can move into the worker thread.

### `notify_worker` (unix) per-notification flow

1. Take the next notification from the queue. When the sending side is closed
   and the queue is drained, return (loop end unchanged).
2. Redact the received title / body exactly as today — on the received values,
   before any escape.
3. Call the capability-fetch injection point once.
4. Pass the received title, body and the fetch outcome to `escape_for_send`.
5. Pass only the returned summary and body to the send injection point.
6. Log the send result with the unchanged texts and levels (success: debug
   `notify-rust dispatched: {redacted}`; failure: warn `notify-rust failed: {e}`).

`notify_worker` contains no escape branch and no direct call to
`escape_body_markup` or `body_markup_absence_confirmed`.

### Production wiring

- The worker-thread start in `NotifyRustSink::new` passes the production
  injection points on unix. Queue capacity, thread spawn and the shutdown / join
  procedure are unchanged.
- The Windows `notify_worker` and the Windows call to it stay textually
  unchanged — no capability fetch, no escape, no injection points. If the
  thread-start call site is shared by both platforms, split it by platform so
  the Windows side keeps today's call.
- `NotifyRustSink::send` is unchanged.

### Doc comments (FR6)

- `escape_for_send` and `escape_body_markup` (around lines 440 and 463 at
  planning time): name `notify_worker` as the caller instead of
  `NotifyRustSink::send`.
- `notify_worker`: describe the role of each injection point and what
  production passes (notify-rust's capability query and notify-rust's send).
- No other comment in `callbacks.rs` changes.

### Worker-level tests

- A new unix-only submodule in `tests.rs`, added as a new block after the
  existing submodules. It does not edit `mod body_markup_escape` or any other
  existing module.
- Each test creates a queue, enqueues N notifications, closes the sending side,
  runs `notify_worker` to completion (on the test thread, or on a spawned thread
  joined before asserting), then asserts on the recorded values and counts.

## Test Notes

- AC-2: three unit tests (or one table-driven test with three cases). Write the
  expected values as literal strings — do not compute them through
  `escape_body_markup` — so helper mutations are also caught.
- AC-3: counters and the record list are shared between the fakes and the test
  body; assert counts and order after the worker returns.
- TDD red step: write the AC-2 / AC-3 tests against the new injection-point
  shape first; they fail to compile or fail until `notify_worker` takes the
  injection points and forwards the `escape_for_send` result.
- AC-4 is a manual mutation run (VERIFICATION TS-8). Record which test failed
  for each mutation in the implementer notes; revert every mutation.
- AC-6 is partly a diff inspection (Windows-gated code, log texts, redaction
  position, queue capacity, `Cargo.toml`).
- Never leave the queue open while running the worker to completion — the
  test would hang.
- If an unrelated suite (tabs replay, tmux socket discovery) fails in the
  parallel `--lib` run, re-run it with a single test thread before treating it
  as a regression.
