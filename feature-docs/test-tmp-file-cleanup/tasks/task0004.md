# Task Plan: task0004 — viewer/launch.rs spawn エラーテストのペイロード事後削除

## Goal

`src-tauri/src/viewer/launch.rs` の `launch_with_propagates_spawn_error` が `/tmp/emterm-viewer-{pid}-{nanos}-{n}.json` に残すペイロードファイルを、テスト正常終了時に削除し、成功実行後の残留をゼロにする。

## Requirements

FR4, FR5, NFR1, NFR2, NFR3

## Scope

### Files to Create

（なし）

### Files to Modify

- `src-tauri/src/viewer/launch.rs` — `launch_with_propagates_spawn_error` の正常終了時にペイロードファイル削除を追加する

## Design

現状: `launch_with` はペイロードを一時ファイルへ書き出してから spawn クロージャにそのパスを渡す。spawn が失敗してもペイロードファイルは削除されないため、常に失敗する spawn クロージャを渡す `launch_with_propagates_spawn_error` は、実行のたびに `/tmp/emterm-viewer-{pid}-{nanos}-{n}.json` を 1 つ残す。同ファイルの sibling テスト `launch_with_writes_payload_and_invokes_spawn_once` は、クロージャに渡されたパスを記録してテスト末尾で削除するパターンを確立済み。

変更内容（IMPLEMENTATION.md の Conventions・D1・D2 に従う）:

1. テストの spawn クロージャは、呼び出し時に渡されたペイロードパスを記録してからエラーを返す（クロージャ呼び出し時点でファイルは書き込み済み）。
2. エラー種別のアサーションの後、最終ステップとして、記録したパスのファイルを sibling テストと同じ形で削除する。削除はベストエフォート。
3. **`launch_with` 本体・ペイロード書き出し・一時パス生成のプロダクション関数は変更しない**（D1 / NFR3）。「spawn 失敗時にプロダクション側で削除する」方向の修正は採らない。
4. sibling テスト（既にクリーンアップ済み）には触れない。

- [ ] AC-4: 新規依存が追加されていない（マニフェスト・ロックファイルに新規エントリなし）。

## Test Notes

- AC-1 は「対象テストの実行 → `/tmp` 直下の `emterm-viewer-*.json` 確認」で検証する（VERIFICATION.md TS3 と同じ手順）。修正前に残留を観測（red）→ 削除追加後に残留ゼロ（green）。ファイル名の `{nanos}-{n}` 部分は実行ごとに変わるため、パターン一致で確認する。
