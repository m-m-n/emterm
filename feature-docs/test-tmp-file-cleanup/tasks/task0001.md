# Task Plan: task0001 — settings_store.rs テスト一時ディレクトリの事後削除

## Goal

`src-tauri/src/settings_store.rs` のテストが `/tmp/emterm-settings-store-test-{pid}-{name}/` に残す一時ディレクトリを、各テストの正常終了時に削除し、成功実行後の残留をゼロにする。

## Requirements

FR1, FR5, NFR1, NFR2, NFR3

## Scope

### Files to Create

（なし）

### Files to Modify

- `src-tauri/src/settings_store.rs` — テスト専用モジュール内に、各テストの正常終了時の一時ディレクトリ削除を追加する

## Design

現状: テストヘルパー `tmp_path(name)` が `/tmp/emterm-settings-store-test-{pid}-{name}/` を作成し、その中の `settings.json` パスを返す。ヘルパー利用テストは 5 つ:

| テスト | name | 備考 |
|---|---|---|
| `save_patch_preserves_unknown_keys` | `preserve` | |
| `save_patch_creates_missing_file` | `create` | 冒頭に事前削除あり（残す） |
| `save_patch_backs_up_corrupt_file` | `corrupt` | ディレクトリ内に `.bak` も生成される |
| `app_settings_save_round_trips_through_native_loader` | `roundtrip` | 冒頭に事前削除あり（残す） |
| `shift_enter_behavior_round_trips_through_native_loader` | variant ごとに 4 種 | ループで 4 ディレクトリを作成。各イテレーション分を削除する |

変更内容（IMPLEMENTATION.md の Conventions・D2 に従う）:

1. 各テストの正常終了経路の最終ステップとして、ヘルパーが作成したディレクトリ（返却パスの親）を再帰的に削除する。ディレクトリごと削除するため、`corrupt` テストの `.bak` も同時に片付く。
2. ループ型テストは、作成した全イテレーション分（4 variant 分）のディレクトリを削除する。
3. 削除はベストエフォート（失敗してもテストを失敗させない）。既存の事前クリーン行は残す。
4. 削除を容易にするためのテストローカルなヘルパー変更（戻り値の拡張や tempfile による RAII ガード化）は、テスト専用モジュール内に閉じる限り可。
5. `clamp_for_save_enforces_webview_ranges` は一時パスを使わないため対象外。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: 上表 5 テストのそれぞれを個別に成功実行した後、当該テストが使う `/tmp/emterm-settings-store-test-{pid}-{name}/`（variant ループは 4 variant 全部）が存在しない。
- [ ] AC-2: 既存のアサーションは変更されず、`settings_store.rs` の全テストが引き続き成功する。
- [ ] AC-3: 変更が `settings_store.rs` のテスト専用モジュール（`cfg(test)` 配下）に閉じ、プロダクション関数の挙動・シグネチャに変更がない。
- [ ] AC-4: 新規依存が追加されていない（マニフェスト・ロックファイルに新規エントリなし）。

## Test Notes

- AC-1 は「対象テストの実行 → `/tmp` 直下の該当パターン確認」で検証する（VERIFICATION.md TS3 と同じ手順）。修正前に実行して残留を観測（red）→ 削除を追加して残留ゼロを確認（green）という順で進めると TDD の red/green に対応づく。
- AC-2 は既存テストの再実行（回帰）。AC-3/AC-4 は差分の位置と依存ファイルの無変更で機械的に確認できる。
- 削除は全アサーションの後に置くこと（失敗時は panic により削除に到達せず、NFR1 の許容範囲として残留する — これは仕様どおり）。

## Out of Scope

- プロダクションコードの変更（NFR3）
- 既存の事前クリーン行の除去・書き換え
- 異常終了（panic / kill）経路でのクリーンアップ保証（NFR1）
