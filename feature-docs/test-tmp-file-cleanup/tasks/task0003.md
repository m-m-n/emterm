# Task Plan: task0003 — mux/tmux_import.rs テスト一時ディレクトリの事後削除

## Goal

`src-tauri/src/mux/tmux_import.rs` の 5 テストが `/tmp/emterm-tmux-import-test-{pid}-{name}/` に残す一時ディレクトリを、各テストの正常終了時に削除し、成功実行後の残留をゼロにする。

## Requirements

FR3, FR5, NFR1, NFR2, NFR3

## Scope

### Files to Create

（なし）

### Files to Modify

- `src-tauri/src/mux/tmux_import.rs` — テスト専用モジュール内に、5 テストの正常終了時の一時ディレクトリ削除を追加する

## Design

現状: テストヘルパー `tmp_settings_path(name)` が `/tmp/emterm-tmux-import-test-{pid}-{name}/` を「事前クリーン → 作成」して `settings.json` パスを返す。事前クリーンは pid が実行ごとに変わるため過去実行分を回収できず、正常終了ごとに 5 ディレクトリが残留する。ヘルパー利用テストは 5 つ:

| テスト | name |
|---|---|
| `missing_file_creates_settings_with_latch_only` | `missing` |
| `latch_skips_second_run` | `latch` |
| `applies_conversion_and_sets_latch` | `apply` |
| `preserves_unrelated_keys` | `preserve` |
| `keybinds_replaces_non_object_value` | `keybinds_nonobject` |

変更内容（IMPLEMENTATION.md の Conventions・D2 に従う）:

1. 各テストの正常終了経路の最終ステップとして、ヘルパーが作成したディレクトリ（返却パスの親）を再帰的に削除する。
2. 削除はベストエフォート（失敗してもテストを失敗させない）。ヘルパー冒頭の事前クリーンは残す。
3. 削除を容易にするためのテストローカルなヘルパー変更（戻り値の拡張や tempfile による RAII ガード化）は、テスト専用モジュール内に閉じる限り可。
4. `auto_import_tmux_conf_skips_oversized_file` は既に末尾で自ディレクトリを削除しており（かつ HOME 環境変数を操作するデリケートなテストであるため）**一切変更しない**。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: 上表 5 テストのそれぞれを個別に成功実行した後、当該テストが使う `/tmp/emterm-tmux-import-test-{pid}-{name}/` が存在しない。
- [ ] AC-2: 既存のアサーションは変更されず、`mux/tmux_import.rs` の全テストが引き続き成功する。
- [ ] AC-3: `auto_import_tmux_conf_skips_oversized_file` に差分がない。
- [ ] AC-4: 変更が `mux/tmux_import.rs` のテスト専用モジュール（`cfg(test)` 配下）に閉じ、プロダクション関数の挙動・シグネチャに変更がない。
- [ ] AC-5: 新規依存が追加されていない（マニフェスト・ロックファイルに新規エントリなし）。

## Test Notes

- AC-1 は「対象テストの実行 → `/tmp` 直下の該当パターン確認」で検証する（VERIFICATION.md TS3 と同じ手順）。修正前に残留を観測（red）→ 削除追加後に残留ゼロ（green）。
- AC-2/AC-3 は同ファイルのテスト再実行と差分レビュー。AC-4/AC-5 は差分位置と依存ファイルの無変更で機械的に確認できる。
- 削除は全アサーションの後に置くこと（失敗時は panic により削除に到達せず残留するが、NFR1 の許容範囲）。
