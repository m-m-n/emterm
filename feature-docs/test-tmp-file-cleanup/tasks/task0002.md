# Task Plan: task0002 — settings_window/commands.rs roundtrip テストの一時ディレクトリ事後削除

### Files to Modify

## Design

現状: 同ファイルのテストモジュール内で、`app_settings_full_roundtrip_through_patch_save` だけが `/tmp/emterm-settings-window-test-{pid}/` を作成したまま削除しない。同じモジュールの sibling テスト（`legacy_font_family_persists_with_bak`、shift-enter 系 3 テスト）は、いずれもテスト末尾で自分の一時ディレクトリを「戻り値を無視する再帰削除」で片付けるパターンを確立済み。

変更内容（IMPLEMENTATION.md の Conventions・D2 に従う）:

1. `app_settings_full_roundtrip_through_patch_save` の全アサーションの後、最終ステップとして、テストが作成したディレクトリを sibling テストと同じ形で再帰的に削除する。
2. 削除はベストエフォート（失敗してもテストを失敗させない）。
3. 既にクリーンアップ済みの sibling テストには一切触れない。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `app_settings_full_roundtrip_through_patch_save` を個別に成功実行した後、`/tmp/emterm-settings-window-test-{pid}/` が存在しない。
- [ ] AC-2: 既存のアサーションは変更されず、`settings_window/commands.rs` の全テストが引き続き成功する。
- [ ] AC-3: 変更が対象テスト 1 件への削除追加のみで、sibling テストおよびプロダクションコードに差分がない。
- [ ] AC-4: 新規依存が追加されていない（マニフェスト・ロックファイルに新規エントリなし）。

## Test Notes

- AC-1 は「対象テストの実行 → `/tmp` 直下の該当パターン確認」で検証する（VERIFICATION.md TS3 と同じ手順）。修正前に残留を観測（red）→ 削除追加後に残留ゼロ（green）。
- AC-2 は同ファイルのテスト再実行（回帰）。AC-3 は差分レビューで機械的に確認できる。
- 削除は全アサーションの後に置くこと（失敗時は panic により削除に到達せず残留するが、NFR1 の許容範囲）。
