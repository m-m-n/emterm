## Design

### Conversion (scrollback_filter.rs)

This section implements the vt100 replay copy contract in IMPLEMENTATION.md,
Shared Components (the name, visibility, pre- and postconditions are pinned
there).

Processing flow:
1. Start the scan state at ground, and reserve an output of the input's length.
2. For each input byte: when the byte is DEL and the scan state is inside a CSI (any sub-state) or right after an ESC, append CAN. Otherwise append the byte unchanged.
3. Advance the scan state by the original byte (never by the CAN), using `WrittenState`'s existing transition. That transition is private to the module, and the new function lives in the same module, so no visibility change is needed.
4. Return the output.

| Scan state just before a DEL | Output byte |
|---|---|
| Ground (includes OSC, DCS and APC bodies) | DEL (kept) |
| Escape (right after an ESC) | CAN |
| Designator (after `ESC (` or `ESC )`) | DEL (kept) |
| Csi, entry or parameter sub-state | CAN |

Consequences that the tests pin:
- After a replaced DEL, the transition takes the scan to ground. A second DEL right after it is therefore kept.
- An ESC inside a CSI moves the scan to the escape state, so a DEL right after that ESC is replaced.
- Every byte other than DEL is copied unchanged, including a CAN already present in the input.

Do not use the strip's `Written` writer or the D2 rewrite for the scan. Do not
place the function behind the `gui` feature. Its doc comment states the
contract and that the ring and the client bytes are not affected.

### ReadPane (agent_api.rs)

`render_scrollback_rows` hands the scratch vt100 parser the replay copy of its
scrollback-tail argument instead of the argument itself. Grid sizing, row
collection and the trailing-empty-row trim stay as they are.
`render_pane_tail` and `handle_read_pane` need no change, and the tail cut
(`SCROLLBACK_READ_TAIL_BYTES`) stays.

### Restore (session/pane/mod.rs)

In `MuxPane::from_restored`:
- The bytes read from the restored ring go into the pane's ring exactly as they do now (unchanged, DEL kept).
- The scrollback replay step hands the shadow parser the replay copy of those bytes instead of the bytes themselves. The empty-ring skip, the panic guard, the parser reset on panic and the error log all stay. The logged byte count is the same either way, because the copy has the same length.
- The alt-screen step does not change, and the alt-screen dump bytes are not converted.
- `from_restored_exited`, which does no replay, is not touched.
