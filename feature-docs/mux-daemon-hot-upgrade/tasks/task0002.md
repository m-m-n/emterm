# Task Plan: task0002 — Inherited PTY master adapter

## Goal

Provide a Unix-only adapter that presents an already-open PTY master file
descriptor as the PTY-master abstraction the pane layer is written against, so
descriptors inherited across a process replacement can be re-adopted.

## Requirements

FR10, NFR4

## Scope

### Files to Create
- `src-tauri/src/mux/inherited_pty.rs` — the adapter type and its tests.

### Files to Modify
- `src-tauri/src/mux/mod.rs` — declare the new module, gated to Unix.

## Design

The PTY library this project uses offers no public way to build its master
abstraction from an existing descriptor, so this task supplies one.

**Responsibilities.** The adapter owns a raw descriptor and implements the
same master-PTY abstraction the pane layer already consumes, so a restored
pane is indistinguishable from a freshly spawned one to its callers.

**Contract** (also pinned in IMPLEMENTATION.md Shared Components):

- Construction takes ownership of a raw descriptor. Dropping the adapter
  closes it. Construction validates that the descriptor is live and refers to
  a terminal, and fails rather than producing an adapter over a bad
  descriptor.
- It can produce an independent reader handle and a writer handle, each
  backed by its own duplicate of the descriptor so that dropping one does not
  disturb the others.
- It can read and set the terminal window size through the platform's
  terminal size operations.
- It exposes its raw descriptor.
- Duplicates it creates for reader and writer handles are marked close-on-exec
  so they do not leak into pane child processes; the owned descriptor's own
  close-on-exec flag is managed by the snapshot path, not here.

Everything in this module is compiled only on Unix. Non-Unix builds must not
see the module at all, and the `--no-default-features` build must be
unaffected.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Given a descriptor obtained by opening a PTY pair, the adapter can
      be constructed and reports that same descriptor number.
- [ ] AC-2: Bytes written to the adapter's writer handle are readable from the
      corresponding PTY slave.
- [ ] AC-3: Bytes written to the PTY slave are readable through the adapter's
      reader handle.
- [ ] AC-4: Two reader handles obtained from the same adapter are independent:
      dropping one leaves the other usable.
- [ ] AC-5: Setting the window size through the adapter is observable through
      a subsequent size query on the same adapter.
- [ ] AC-6: Construction over a closed or non-terminal descriptor fails
      instead of yielding an adapter.
- [ ] AC-7: Dropping the adapter closes the owned descriptor.
- [ ] AC-8: The reader and writer handle duplicates have close-on-exec set.

## Test Notes

Tests open a real PTY pair the same way the existing pane tests do, so no
process replacement is involved. AC-6 uses a descriptor for an ordinary file
and a descriptor that has already been closed. AC-7 and AC-8 are asserted by
querying descriptor state directly. Keep tests Unix-gated.

## Out of Scope

- Reading the handoff document or deciding which descriptors to adopt
  (task0003).
- Clearing close-on-exec on the owned descriptor before the replacement
  (task0003).
- Any Windows equivalent.
