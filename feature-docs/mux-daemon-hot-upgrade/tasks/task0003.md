# Task Plan: task0003 — Session state snapshot and restore

## Goal

Convert the live mux session tree into a handoff document (preparing every
descriptor for inheritance) and rebuild an equivalent live session tree from
such a document, so a replacement process resumes with the same panes,
scrollback and identifiers.

## Requirements

FR4, FR5, FR6, FR9, FR10, FR19, NFR1, NFR2

## Scope

### Files to Create
- `src-tauri/src/mux/upgrade.rs` — snapshot and restore, descriptor
  preparation, and handoff-file writing/reading/removal.

### Files to Modify
- `src-tauri/src/mux/mod.rs` — declare the new module, gated to Unix.
- `src-tauri/src/mux/session/manager.rs` — expose what restore needs to
  reconstruct a manager with given identifier counters and incarnation token.
- `src-tauri/src/mux/session/session.rs` — expose what restore needs to
  reconstruct a session with a given window-id counter.
- `src-tauri/src/mux/session/window.rs` — expose what restore needs to
  reconstruct a window with a given pane-id counter.
- `src-tauri/src/mux/session/pane.rs` — expose what snapshot needs to read a
  pane's descriptor, child process id and attributes, and what restore needs
  to build a pane around an adopted master.
- `src-tauri/src/mux/scrollback_buffer.rs` — expose a whole-buffer capture and
  a whole-buffer load that round-trip.

## Design

### Snapshot

Precondition: the caller holds the session-manager lock.

1. Walk the session tree in a stable order and record every session, window
   and pane attribute the handoff document declares (IMPLEMENTATION.md Shared
   Components), including the three families of identifier counters and the
   incarnation token (IMPLEMENTATION.md D5).
2. For each pane that has not exited, read its master descriptor number, clear
   that descriptor's close-on-exec flag, and record the number in the document
   along with the pane's child process id (IMPLEMENTATION.md D6). Panes
   already marked exited contribute no descriptor.
3. Clear the close-on-exec flag on the listen descriptor supplied by the
   caller and record it (IMPLEMENTATION.md D4).
4. Capture each pane's scrollback contents while that pane's scrollback lock
   is held, so the captured bytes are internally consistent.
5. Serialise the document and write it to a file created with owner-only
   permission inside the directory that already holds the socket. Fail rather
   than write anywhere world-readable, and fail rather than follow an existing
   path.

Failure at any stage aborts and reports which stage failed, leaving the
session tree untouched. Descriptor flags already cleared are harmless if the
upgrade is abandoned (the process simply keeps running), so no rollback of the
flags is required, but the partially written file is removed.

### Restore

Precondition: a handoff document decoded successfully, i.e. its schema version
is supported.

1. Rebuild a session manager whose identifier counters and incarnation token
   equal the document's, so subsequently allocated identifiers continue the
   original sequence and already-running shells' environment values stay
   valid.
2. Rebuild sessions, windows and panes in the recorded order, restoring window
   ordering and active-entry selections.
3. For each pane recorded as live, adopt its descriptor through the inherited
   master adapter (task0002's contract), re-establish the pane's writer and
   its reader thread using the same wiring a freshly spawned pane gets, and
   load its scrollback contents. Rebuild the pane's terminal-state view by
   replaying restored scrollback (IMPLEMENTATION.md D8) rather than expecting
   serialised parser state.
4. A pane whose descriptor cannot be adopted is rebuilt as exited and the
   reason logged at a level that survives release filtering; the rest of the
   tree still restores.
5. Panes recorded as exited are rebuilt as exited without adopting a
   descriptor.
6. Restored panes are registered with the process-id based reaping path
   (task0007's contract) rather than an owned child handle.

### Handoff file lifetime

The module owns writing, reading and removing the file. Removal happens after
a successful read, after a failed read, and after an aborted snapshot — the
file must never survive the operation that created it.

Everything in this module is Unix-gated.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Snapshot of a manager holding multiple sessions, windows and panes
      produces a document whose tree, ordering, active-entry selections,
      identifier counters and incarnation token match the source.
- [ ] AC-2: After snapshot, every live pane's master descriptor and the listen
      descriptor have close-on-exec cleared, verified by querying descriptor
      flags.
- [ ] AC-3: Snapshot → restore round-trip yields a manager whose identifier
      counters and incarnation token equal the original's, and whose next
      allocated pane identifier continues the original sequence.
- [ ] AC-4: Snapshot → restore round-trip preserves each pane's scrollback
      contents byte-for-byte.
- [ ] AC-5: A restored live pane can be written to and read from through its
      adopted master, demonstrated against a real PTY pair.
- [ ] AC-6: A pane recorded as exited is restored as exited and adopts no
      descriptor.
- [ ] AC-7: A pane whose recorded descriptor is not adoptable is restored as
      exited, the rest of the tree still restores, and the reason is logged.
- [ ] AC-8: The handoff file is created with owner-only permission and is
      removed after a successful read, after a failed read, and after an
      aborted snapshot.

## Test Notes

Use real PTY pairs for the descriptor-bearing criteria, following the existing
pane tests. Non-descriptor criteria (AC-1, AC-3, AC-4, AC-6) can use the
existing test-only pane constructor. AC-8 is asserted by inspecting file mode
and by checking the path is gone in each of the three outcomes. Snapshot and
restore are exercised in the same process — no process replacement is involved
in this task's tests. Keep tests Unix-gated and avoid depending on a running
daemon.
