# Task Plan: task0001 — Replace the st_rdev closure check with a TIOCGPTN pts-number check

## Goal

`dropping_the_adapter_closes_the_owned_descriptor` decides that the owned
descriptor was closed from the pts number the TIOCGPTN query reports, so a
freed descriptor number reused by another PTY master (or a duplicate of one)
no longer makes it fail. A new deterministic test pins that decision, and the
comments and the cross-file reference that stated the wrong premise are
corrected.

## Design

Feature-wide constraints (test-only scope, unix-only gating, determinism,
unchanged test name) are in IMPLEMENTATION.md Conventions.

### Test helpers (private to the `mux::inherited_pty` test module)

| Helper | Responsibility | Contract |
|---|---|---|
| pts-number query | Report which PTY pair a descriptor number belongs to | Input: any descriptor number, including invalid or closed ones. Output: the pts number when the number refers to a PTY master or a duplicate of one; otherwise the error number the TIOCGPTN query reported. Never panics; never closes or alters the descriptor. |
| closure judgment | Decide whether a descriptor number still refers to the original master | Input: a descriptor number and the baseline pts number recorded from the original master. Output: "original" exactly when the query succeeds and reports the baseline number; "not original" when the query fails or reports a different number. Also yields the observed query outcome (pts number or error number) for failure messages. |
| `slave_device_path` (existing) | Resolve the slave device path of a master | Observable behavior unchanged; it may be re-expressed through the pts-number query. |
| `stat_rdev` (existing) | — | Removed: after this task nothing calls it. |

The target test and the recurrence test both reach their verdict through the
same closure judgment, so the recurrence test pins the exact logic the target
test relies on.

### Target test: `dropping_the_adapter_closes_the_owned_descriptor` (name unchanged)

1. Open pair A and an independently owned duplicate of its master with the
   existing helper. The pair stays open until step 5 has finished (FR5):
   while it is open, A's pts number cannot be assigned to any other pair.
2. Query the duplicate. A failed query fails the test; a successful one gives
   the baseline pts number.
3. Construct the adapter over the duplicate, then drop it.
4. Judge the duplicate's descriptor number against the baseline.
5. "original" fails the test with a message that carries the descriptor
   number, the baseline pts number and the observed post-drop outcome (the pts
   number on success, the error number on failure) (FR2). "not original"
   passes.

### Recurrence test: `closure_judgment_distinguishes_other_pty_masters` (new)

Builds, inside one test and without depending on any other thread, the state
the flake needs: another PTY master holding a descriptor while the original
pair is open. Pairs A and B are both open for the whole test; the baseline is
A's pts number.

| Descriptor judged | Expected verdict |
|---|---|
| B's master | not original |
| a duplicate of B's master | not original |
| a duplicate of A's master | original |
| an independently opened handle to A's slave device | not original |
| an ordinary temporary file | not original |
| `CLOSED_FD` (`-1`, existing constant) | not original |

Descriptor ownership: every descriptor the test creates (the duplicates, the
slave handle, the temporary file) has exactly one owner and is closed exactly
once. The masters owned by the pair handles are only borrowed and are never
closed by the test (the `CLOSED_FD` doc comment records the IO-safety abort a
stray close caused in this module).

### Comments (FR4)

- The target test's in-body comment states the pts-number rationale: the held
  pair keeps the baseline pts number reserved for this test, so another PTY
  master or duplicate that reuses the freed descriptor number reports a
  different pts number, and any non-master descriptor or closed number makes
  the query fail; either outcome shows the owned descriptor was closed.
- No comment in `inherited_pty.rs` says that a reused descriptor refers to a
  different device. `stat_rdev`'s doc comment leaves with `stat_rdev`.
- `stat_dev_ino`'s doc comment in `upgrade/tests.rs` drops the reference to
  `inherited_pty.rs::tests::stat_rdev` and states its own rationale (a regular
  file's identity through device and inode). Its logic is unchanged (SPEC
  A5).
