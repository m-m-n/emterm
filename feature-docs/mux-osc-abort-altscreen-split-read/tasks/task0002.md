# Task Plan: task0002 — Plain-tab half of the SC-1x parity corpus

## Goal

Tests pin that a plain tab, fed every row of the IMPLEMENTATION.md SC-1x
corpus extension (K16–K37) in one `process_combined` call, ends in the row's
final OSC 7501 table and final OSC 777 state. Together with the mux half
(task0001, asserted against the same rows), this is the plain-tab / mux
parity check of FR6 and FR7. No production file changes.

## Requirements

FR6, FR7, FR8, NFR5

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/tabs/tests/output_pipeline.rs` — a K16–K37 row list and its tests (AC-1 to AC-3), placed after the existing SC-1 cut parity corpus section

## Design

### What is tested

The plain-tab path is the reference behavior (IMPLEMENTATION.md D1):
term_core moves to the alternate screen on ?1049 / ?1047 / ?47 `h` and back
on the matching `l`, treats a switch whose `ESC` sits right after `ESC (` as
the charset designator plus printed text, suppresses OSC 133 on the
alternate screen, and dispatches a cut OSC 133 string as unterminated, which
the plain-tab callbacks apply. This task adds tests only; it does not change
term_core, the callbacks or the tab.

### Row list

The existing SC-1 section already provides the row shape (name, seed,
stream, deliveries, final table, final OSC 777 state, table-change count),
the S-W seed, the one-call delivery and the row assertion (final table,
final OSC 777 state resolved from the tab's events and latch inputs, the
table-change count where given, and no OSC 7501 answer written). Reuse them.

Add a second list holding K16–K37 exactly as the SC-1x table lists them:
stream built from the SC-1x notation, seed S-W, delivery "one", the final
table, the final OSC 777 state and the table-change count. Do not add the
rows to the K1–K15 list: an existing test pins that list's names to exactly
K1–K15. The mux deliveries the SC-1x table names are task0001's; on this
side every row is delivered in one call (IMPLEMENTATION.md D3).

### Threat-model link

The rows this task asserts are the plain-tab reference for THREAT-MODEL.md
TM-1 (K32–K34 and K36: an alternate-screen mark changes nothing; K35: a
designator-slot switch is not a switch). The mitigation itself is implemented
on the mux path by task0001.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR7): The K16–K37 list names exactly the rows K16 to K37 in order, each with seed S-W and the one-call delivery, and each stream has the length the SC-1x table lists.
- [ ] AC-2 (FR6, FR7): Rows K16–K31, K35 and K37, each in one `process_combined` call, end in an empty OSC 7501 table and no OSC 777 state, with no OSC 7501 answer written.
- [ ] AC-3 (FR6, FR7; reference for TM-1): Rows K32–K34 and K36, each in one call, end with only the root `working` record, record no pending summary change, end in no OSC 777 state, and write no OSC 7501 answer.
- [ ] AC-4 (FR8, NFR5): Every existing test in the file — the SC-1 cut parity corpus tests, including the K1–K15 name test, and the SC-4 parity corpus tests — passes with its assertions unchanged. The task changes no file other than its declared test file: nothing under `crates/term_core/`, nothing in `src-tauri/src/callbacks.rs`, and no other production file. The new tests use no platform-gated API.

## Test Notes

- The plain tab already behaves as SC-1x expects, so these tests are
  expected to pass on first run; there is no red phase for this task. Before
  relying on that, confirm each new test can fail: for one row per AC,
  temporarily assert a wrong expectation and see it fail, then restore it.
- If a row's plain-tab outcome differs from SC-1x, do not change term_core,
  the callbacks or the tab, and do not change the row's expectation in the
  test to match: report the row as a plan deviation (IMPLEMENTATION.md D1).
- Name the row in assertion messages so a failure identifies it.
- `tabs` replay tests can fail nondeterministically in parallel; rerun a
  failing one with a single test thread before treating it as a failure.
- Run tests from the project root with the quick-check target directory
  (`.claude/rules/core-build-location.md`); the tests live under `--lib`.

## Out of Scope

- Any production change (term_core, callbacks, tab, app).
- The mux half of SC-1x and the live-span tracker (task0001).
- Split deliveries on the plain side.
