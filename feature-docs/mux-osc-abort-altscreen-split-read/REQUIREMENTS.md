# mux-osc-abort-altscreen-split-read - 要件定義書

## 1. 概要

### 1.1 背景

mux の読み取りループ（`pty_reader_loop`）は、代替画面の切り替えシーケンスを受信ごとに検出しており、受信をまたいだ途中の状態を引き継がない（`write_filter.rs:1214` の `next_live_toggle`、`:1332` の `extract_main_buffer`）。先頭のバイトでメイン画面への切り替えを完了する受信は、代替画面フォールバック（`mod.rs:544`）に入り、空の live_spans を受け取る。

### 1.2 目的

- 代替画面の切り替えシーケンスが PTY の受信をまたいで分割されても、mux ペインは、同じバイト列を一括で処理した通常タブと同じ OSC 7501 の記録表で終わる。これは受信をどの位置で分割しても成り立つ。
- 再現手順の修正: root の working の記録を持つ mux ペインに、`drive_reads` で `\x1b[?1049h`、`\x1b[?1049`、`l\x1b]133;A`、`\x1b\x1b\\` の受信を与える。通常タブと同じく、記録表は空で終わる。

### 1.3 スコープ

- 対象: 切り替えシーケンスの途中状態を受信をまたいで引き継ぎ、スキャナに正確なライブ区間を渡すことのみ（exact_live_spans_feed_only、A1）。
- 対象外:
    - ALT_SCREEN_TOGGLES に無い切り替えの形（`ESC [?1;1049h` のような複合パラメータなど）。従来のフォールバック（空のライブ区間）のまま（A3）。
    - 分割された切り替えに対する scrollback 書き込み経路の不正確さ（例: FR3(2) の代替画面への切り替えの分割で、代替画面のバイトがリングに書かれる）。書き込み経路は変更しない（FR5、A4）。
    - スキャナの cut_live / tail_live の判定規則（A5）。
    - term_core（NFR5）。

## 2. ビジネス要件

### 2.1 ビジネス目標

- 代替画面の切り替えシーケンスが PTY の受信をまたいで分割されても、mux ペインは、同じバイト列を一括で処理した通常タブと同じ OSC 7501 の記録表で終わる。受信の分割位置によらない。
- 1.2 の再現手順で、mux ペインの記録表が通常タブと同じく空で終わる。

### 2.2 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| mux ペインの利用者 | mux ペインの OSC 7501 記録表と OSC 777 エージェント状態を使う利用者 |

### 2.3 期待される効果

- 切り替えシーケンスの分割位置によらず、mux ペインと通常タブの OSC 7501 記録表が一致する。
- OSC 777 agent-status の状態も、mux ペインと通常タブで一致する。

### 3.2 ユースケース詳細

#### UC01: 分割受信された画面切り替えの後のプロンプト開始マーク

**アクター**: mux ペインで動くプログラム

**事前条件**:
- mux ペインに root の working の記録がある。

**基本フロー**:
1. プログラムが `\x1b[?1049h` を出力し、代替画面に入る。
2. メイン画面への切り替え `\x1b[?1049l` が `\x1b[?1049` と `l` の 2 回の受信に分割されて届く。
3. 2 回目の受信は `l\x1b]133;A` で、切り替えの完了に続いて OSC 133 のプロンプト開始マークが始まる。
4. 次の受信 `\x1b\x1b\\` で、マークが本文中の ESC により打ち切られる。

**代替フロー**:
- マークが BEL または ST で同じ受信の中で終わる（AC2）。
- 同じ受信の中で、メイン画面への切り替えの完了後に、再び代替画面に入る（AC3）。
- 代替画面への切り替えが受信をまたいで分割される（AC4）。
- 切り替えシーケンスの ESC が `ESC (` / `ESC )` の直後の指示子スロットにある（AC5）。

**事後条件**:
- mux ペインの OSC 7501 記録表と OSC 777 エージェント状態が、同じバイト列を一括で処理した通常タブと同じになる（基本フローでは記録表は空）。

## 4. 機能要件

### 4.1 機能一覧

| ID | 機能名 | 説明 |
|----|--------|------|
| FR1 | 切り替えシーケンスの途中状態を受信をまたいで引き継ぐ（スキャナのライブ区間） | 受信境界で分割された切り替えシーケンスの途中状態を次の受信に引き継ぎ、スキャナに渡す live_spans を一括抽出の結果と一致させる |
| FR2 | 現状の代替画面フォールバック受信のライブ区間 | 切り替え完了後のメイン画面のバイトをライブとして渡す |
| FR3 | フォールバックでない受信でライブ区間を誤る場合 | フォールバックしない受信のライブ区間の誤りも FR1 で正す |
| FR4 | 文字集合指示子スロットとの整合 | 引き継ぐ途中状態は term_core の解釈に従う |
| FR5 | scrollback 書き込み経路は変えない | 正確なライブ区間はスキャナの入力にだけ使う |
| FR6 | 通常タブとの一致 | 対象の入力で mux ペインと通常タブの記録表と OSC 777 状態が一致する |
| FR7 | 回帰テスト | ライブ区間の単体テストと、mux / 通常タブの一致テストを追加する |
| FR8 | 変わらない挙動 | スキャナの打ち切り規則などの既存の挙動と既存のテストを保つ |

### 4.2 機能詳細

#### FR1: 切り替えシーケンスの途中状態を受信をまたいで引き継ぐ（スキャナのライブ区間）

**説明**: 代替画面の切り替えシーケンス（`ESC [?1049h/l`、`ESC [?1047h/l`、`ESC [?47h/l`。ALT_SCREEN_TOGGLES の形）は、受信の境界で分割されることがある。その場合、mux の読み取りループ（`pty_reader_loop`）は、前の受信の終わりの時点での切り替えシーケンスの途中状態を次の受信に引き継ぐ。これにより、受信のすべてのバイトについて、`AgentStatusFeedScanner::feed` に渡す live_spans が、同じバイト列を一括で抽出したライブ区間（その受信の範囲に限ったもの）と一致する。

#### FR2: 現状の代替画面フォールバック受信のライブ区間

**説明**: 現状、先頭のバイトでメイン画面への切り替えを完了する受信は、代替画面フォールバック（`mod.rs:544`）に入り、空の live_spans を受け取る。FR1 により、切り替えの完了後のメイン画面のバイトを、代わりにライブとして渡す。

**ビジネスルール**:
- その受信の中で終わる OSC 133 マーク（BEL 形式または ST 形式）は、通常タブと同じく項目を出す。
- その受信で始まり、次の受信で本文中の ESC（`ESC ESC \` / `ESC X`）により打ち切られるマークも、同じく項目を出す。
- スキャナの cut_live / tail_live は、正確なライブ区間に従う。

#### FR3: フォールバックでない受信でライブ区間を誤る場合

**説明**: FR1 は、フォールバックではないが、受信ごとの抽出でライブ区間を誤る受信も対象にする。

**ビジネスルール**:
- (1) 例: `l\x1b]133;A\x07\x1b[?1049h`。分割された切り替えの完了後にメイン画面の範囲があり、同じ受信の中で代替画面に戻る。走査とシャドウパーサーが同じ状態で終わるため、この受信はフォールバックしない経路を通るが、ライブ区間が空になる。このメイン画面の範囲をライブとして渡す。
- (2) 例: `\x1b[?10` | `49h<OSC 133 を含む代替画面のバイト>\x1b[?1049l`。代替画面への切り替えが境界をまたいだ直後の、代替画面のバイトはライブとして渡さない。

#### FR4: 文字集合指示子スロットとの整合

**説明**: 引き継ぐ途中状態は term_core の解釈に従う。

**ビジネスルール**:
- 切り替えシーケンスの ESC が `ESC (` / `ESC )` の直後の指示子スロットにある場合、受信をまたいで分割されていても切り替えとして扱わない（既存の DesignatorSlot の規則、mux-suppressed-output-round4 FR5 と整合）。
- 途中状態の後に、切り替えを完了しないバイトが来た場合、そこまでのバイトは従来どおりに扱う。

#### FR5: scrollback 書き込み経路は変えない

**説明**: 次は変わらない。to_write / cuts の決定、フォールバック経路で何も書かないこと（`(&[], Vec::new(), vec![0])`）、ScrollbackWriteFilter、既存の書き込み経路テストの期待値。FR1 の正確なライブ区間は、スキャナの入力にだけ使う。

#### FR6: 通常タブとの一致

**説明**: 対象の入力は、OSC 133 マークを切り替えシーケンスの前または後に置いたストリームで、切り替えシーケンスの内部の任意の位置、または文字列の終わりと本文中の ESC の間で分割したもの。この入力について、mux ペインの OSC 7501 記録表（実際の `pty_reader_loop` とデーモンの agent-status タスク）は、同じストリームを一括で処理した通常タブの記録表と一致する。同じ行で、OSC 777 agent-status の状態が一致することも確かめる。

#### FR7: 回帰テスト

**説明**: 次のテストを追加する。

- (a) 単体テスト: すべての分割位置で、スキャナに渡す受信ごとの live_spans が、一括抽出の live_spans をその受信に限ったものと等しいことを示す。
- (b) 実際の `pty_reader_loop` とデーモンタスクを通す mux / 通常タブ一致テスト: 再現手順、BEL / ST / 打ち切りの形、FR3 の形、指示子スロットの場合を含める。

#### FR8: 変わらない挙動

**説明**: 次は従来どおり。AgentStatusFeedScanner の打ち切り規則（mux-osc-double-esc-abort FR1〜FR6）、cut_live / tail_live の判定規則そのもの、BEL / ST による確定、受信長 / 4096 バイトの規則、8 KiB の carry 上限、`step_ris`、OSC 777 agent-status の正規綴りのみの取り込み。既存のすべてのテスト（SC-1 K1〜K15 と dblesc_* テストを含む）が変更なしで通る。term_core は変更しない。

## 12. テストシナリオ

### 12.1 テスト観点

- [ ] 正常系: AC1〜AC5 のストリームで、mux ペインの記録表と OSC 777 状態が通常タブと一致する（TS2、TS3）。
- [ ] 境界値: すべての分割位置で、受信ごとの live_spans が一括抽出の live_spans をその受信に限ったものと等しい（TS1）。
- [ ] 回帰: AC1 のストリームで scrollback リングの内容が従来と同じ（TS4）。src-tauri と term_core の `--lib` スイート全体と `--no-default-features` のチェック（TS5）。

**単体テスト**:
- TS1（FR1, FR3, FR4）: pty_spawn のテストモジュール。ストリームのコーパス（AC2〜AC5 のストリームと CUT_FORMS のすべての形）を、すべての位置で分割して順に受信させる。各受信が出すライブ区間が、spans_within(一括抽出の区間, 受信の範囲) と等しいことを確かめる。1047 / 47 の形と、途中状態が始まったが切り替えにならない分割も確かめる。

**結合テスト**:
- TS2（FR6, FR7, AC1〜AC5）: mux 側。`daemon/tests.rs` の SC-1 コーパスに行を追加し（K16 以降）、各行を、その行が指定するすべての配送で `drive_reads`（ChunkedReader）に流し、記録表と OSC 777 状態を比べる。
- TS3（FR6, AC1〜AC5）: 通常タブ側。同じストリームを `seeded_plain_tab` / `process_combined`（`tabs/tests/output_pipeline.rs`）に一括で流し、基準の記録表と OSC 777 状態を得る。
- TS4（FR5, AC6）: AC1 のストリームで、scrollback リングの内容が従来の挙動と同じ（フォールバックは何も書かない）。
- TS5（FR8, AC7）: src-tauri と term_core の `--lib` スイート全体と、`--no-default-features` のチェック。

**E2E テスト**: 既存の E2E テストは無い。実行コマンドは検出されず。

**エッジケース**:
- 切り替えシーケンスの内部のすべての位置での分割（受信の末尾が単独の ESC になる場合を含む）
- `?1047` と `?1049` の接頭辞の曖昧さ（`\x1b[?104` | `9l` / `7l`）
- 途中状態の後に、切り替えを完了しないバイトが来る場合（`\x1b[?10` | `4x`）

- 1 回の受信で、メイン画面への切り替えを完了してから再び代替画面に入る場合
- マークの BEL / ST / `ESC ESC \` / `ESC X` の形で、同じ受信または次の受信で終わる場合

| 用語 | 定義 |
