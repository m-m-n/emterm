## Design

verify で不足と判定された点: 既存テスト
`test_write_grapheme_shorter_redraw_after_wide_base_overwrite_blanks_orphan_spacer`
は CR 後に同じ列位置へ「より短い」再描画をするだけで、wide ペアの位置がフレーム間で
1 桁ずれる状況を再現していない。この 1 桁ズレこそが P5 の罫線ズレ・文字重なりを
生んだ経路で、ズレた再描画では base 上書き（FR1）と spacer 上書き（FR2）が
同一行内で連続して発生する。

P5 シナリオの本質（新テストが満たすべき構成条件）:

1. 1 行に罫線相当の幅1 文字・⏭️（U+23ED + VS16 のストリーム表現）・テキストを
   混在させて書く。⏭️ を codepoint → VS16 の順で流すことで遡及 widen
   （`widen_after_merge` / FR4）経路を自然に通す。
2. CR で行頭に戻り、同内容を 1 桁シフトした列配置で書き直す
   （フレーム間の列幅変化の模擬）。シフトにより新フレームの各文字は旧フレームの
   wide ペアに対しズレて重なり、同一行内で「旧 base への上書き（FR1 経路）」と
   「旧 spacer への上書き（FR2 経路）」の双方が発生する。新フレーム側の ⏭️
   書き込みでは placeholder 作成位置が旧ペアと交差する配置とし、連鎖掃除（FR3）
   経路も通す。
3. 再描画後、行の全列を列ごとに検証する。

空白化の意味論（属性保持・overflow 除去・dirty マーク・事前の幅確認）は
IMPLEMENTATION.md「Shared Components: 相方空白化規則」と D2 のとおりで、
本タスクはこれを変更しない。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TS3 / FR1, FR2): 新テストは、⏭️ を含む行を書いた後 CR で行頭に戻り、
      同内容を 1 桁シフトして書き直すバイト列を `process_pty_data` で流す。
      シフト量とペア位置の関係から、旧フレームの wide base への上書き（FR1 経路）と
      旧 spacer への上書き（FR2 経路）が同一行内で両方発生する入力構成に
      なっている（列算術で機械的に確認できること）。
- [ ] AC-2 (TS3 / FR3, FR4): ⏭️ は U+23ED と VS16 のストリーム表現で書いて
      遡及 widen（FR4）経路を通し、再描画側の幅2 書き込みが旧ペアと交差する
      配置として placeholder 作成時の連鎖掃除（FR3）経路を通す。
- [ ] AC-3 (TS3): 再描画後、行の全列について `get_cell_char` / `get_cell_width` を
      検証し、(a) 新フレームの期待内容・幅と一致すること、(b) 孤児 spacer
      （直前セルが幅2 でない幅0 セル）と孤児 base（直後セルが spacer でない
      幅2 セル）が行内に存在しないことを確認する。
- [ ] AC-4 (SC-5): テストが実装不足を暴いた場合、修正は print_handler.rs 内の
      相方空白化規則（IMPLEMENTATION.md Shared Components / D2）の範囲に閉じ、
      修正後にテストが緑になる。不足が無い場合、実装コードは無変更のまま。
- [ ] AC-5 (回帰): 既存の term_core テストスイート（`--lib`）が全緑のまま。

## Test Notes

- 命名規約 `<subject>_<scenario>_<expected>`、TerminalCore を明示構築し
  `process_pty_data` で駆動、`get_cell_char` / `get_cell_width` で assert する
  （IMPLEMENTATION.md Conventions）。追加先は
  `crates/term_core/src/print_handler/tests.rs`。
- シフト方向は右 1 桁（行頭に幅1 文字を 1 つ足した形の再描画）を最低限とし、
  左 1 桁シフト（行頭の幅1 文字を 1 つ削った形）のケースも追加することが望ましい
  （ズレの向きで上書きされる相方が base 側 / spacer 側に入れ替わるため）。
- 既存テスト
  `test_write_grapheme_shorter_redraw_after_wide_base_overwrite_blanks_orphan_spacer`
  は削除・改名しない（同列位置の短縮再描画に対する有効な回帰ガードとして残す）。
- 行全体の列検証は、期待行と 1 列ずつ突き合わせる形にし、どの列で壊れたかが
  失敗メッセージから分かるようにする。
- 既存の print_handler/tests.rs には過去 feature の「FR1〜FR4」という同名 ID の
  コメントが存在する。本タスクの FR ID は本 feature の SPEC.md のもの。
  テスト名・コメントで混同しないこと。
