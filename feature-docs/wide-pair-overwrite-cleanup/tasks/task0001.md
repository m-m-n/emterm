# Task Plan: task0001 — print 経路の wide ペア相方掃除

## Goal

print 経路（write_grapheme_to_grid / handle_print_ascii / widen_after_merge）で wide ペアの半分だけを上書きしたとき、残存する相方セルを幅1 空白に置換してグリッド不変条件を回復し、⏭️（U+23ED + VS16）を含む行のストリーム描画乱れを解消する。

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

（なし）

### Files to Modify

- `crates/term_core/src/print_handler.rs` — 相方掃除規則の適用（下記 Design）と予約名 `blank_wide_pair_partner` の補助関数定義
- `crates/term_core/src/print_handler/tests.rs` — TS1 / TS2 / TS3 / TS4 / TS6 に対応するユニットテストの追加

## Design

空白化の意味論（属性保持・overflow 除去・dirty マーク・事前の幅確認）は IMPLEMENTATION.md「Shared Components: 相方空白化規則」と D2 に従う。補助関数名は D3 の予約名 `blank_wide_pair_partner` を使う。

### 掃除規則（この経路での具体形）

- **R1（FR1）**: セル(col) を上書きする前に、旧セルが幅2 で、col+1 が列内で、セル(col+1) が幅0 なら、セル(col+1) を空白化する。新しく書く文字の幅は問わない。
- **R2（FR2）**: セル(col) を上書きする前に、旧セルが幅0 で、col > 0 で、セル(col-1) が幅2 なら、セル(col-1) を空白化する。
- **R3（FR3）**: 幅2 書き込みで col+1 に placeholder（spacer）を作成する前に、col+1 の旧セルが幅2 で、col+2 が列内で、セル(col+2) が幅0 なら、セル(col+2) を空白化する（別ペアの base を潰す際の連鎖掃除）。

### 適用箇所

1. **write_grapheme_to_grid**: セル(col) 書き込みの直前に R1 / R2。placeholder 作成の直前に R3。
2. **handle_print_ascii**: セル(col) 書き込みの直前に R1 / R2。ただし IMPLEMENTATION.md D4 に従い、「旧セル幅が 1 でない」という分岐 1 回でゲートし、通常経路（旧セル幅 1）では追加処理ゼロとする（NFR4）。
3. **widen_after_merge**（FR4）: col+1 へ spacer を作成する直前に R3 相当（col+1 の旧セルが幅2 なら col+2 の spacer を空白化）。auto-wrap off の最終列 in-place widen（spacer を作らない既存 quirk）は変更しない。
4. **relocate_widened_base_via_wrap**（FR4 の一部、widen_after_merge から呼ばれる行末 wrap 経路）: 新行の col 0 / col 1 への書き込み箇所にも同じ規則を適用する（col 1 の旧セルが幅2 なら col 2 の spacer を空白化、など）。

### 挙動契約（観測可能な事後条件）

- 空白化されたセルは `get_cell_char` が空白 1 文字を返し、`get_cell_width` が 1 を返す。
- wide ペアに関与しない上書き（旧セル幅 1）では、隣接セルの内容・幅が一切変化しない（NFR1）。
- 相方セルの内容が overflow テーブルに退避されていた場合も、空白化後に旧内容が読めない（D2）。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TS1 / FR1): ⏭️（U+23ED + VS16）で wide ペアを作った後、base 位置に幅1 文字を上書きすると、col+1 が空白（`get_cell_char` = 空白 1 文字、`get_cell_width` = 1）になる。
- [ ] AC-2 (TS2 / FR2): spacer 位置に幅1 文字を上書きすると、col-1 の base が空白（幅1）になり、幅2 グリフが残らない。
- [ ] AC-3 (TS6 / FR3): 幅2 文字を書く位置の col+1 が別ペアの base だった場合、その spacer（col+2）も空白化される。
- [ ] AC-4 (TS3 / FR1-FR4): ⏭️ を含む行を 1 桁ズラして書き直したとき（フレーム間の列幅変化の模擬）、旧フレームの残骸（孤児 spacer / 孤児 base）が行内に残らず、行全体のセル内容・幅が期待どおりになる。
- [ ] AC-5 (TS4 / FR4, NFR1): U+23ED と VS16 を `process_pty_data` の別々の呼び出しで流しても、遡及 widen が正常に動く（base が幅2、col+1 が spacer、カーソル位置が正しい — 既存挙動の維持）。
- [ ] AC-6 (NFR1): 既存の term_core テストスイート（`--lib`）が全緑のまま。
- [ ] AC-7 (NFR1, NFR4): 幅1 セルへの幅1 上書き（wide ペア非関与）で、上書き対象の左右の隣接セルの内容・幅が変化しない。

## Test Notes

- 全テストは `crates/term_core/src/print_handler/tests.rs` に、`<subject>_<scenario>_<expected>` 命名で追加する。TerminalCore を明示構築し、`process_pty_data` で PTY バイト列（⏭️ の UTF-8 表現、カーソル移動シーケンス、上書き文字）を流し、`get_cell_char` / `get_cell_width` で assert する。
- AC-1〜AC-4 は ASCII 上書き（fast path 経由）と非 ASCII 上書き（slow path 経由）の両方が対象になるよう、少なくとも FR1/FR2 は両経路のケースを用意する（fast path のみ掃除漏れ、というバグを防ぐ）。
- AC-4（TS3）は調査レポート P5 の再現: 1 行に罫線・⏭️・テキストを書き、CR + 再書き込みで 1 桁シフトさせ、行全体を列ごとに検証する。
- チャンク分割（AC-5）は `process_pty_data` を 2 回呼び、U+23ED のバイト列と VS16 のバイト列を分けて渡す。
- 既存の print_handler/tests.rs には遡及マージ機能（過去 feature）のテストが「FR1〜FR4」という同名 ID のコメントで存在する。本タスクの FR ID は本 feature の SPEC.md のものであり、テスト名・コメントで混同しないこと。
- NFR4 のゲート構造（分岐 1 回）自体はテストで直接観測できないため、AC-7 の挙動不変テストとレビュー（VERIFICATION.md TS9）で担保する。
