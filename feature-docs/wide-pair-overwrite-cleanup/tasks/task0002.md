# Task Plan: task0002 — CSI 編集・消去系（ICH/DCH/ECH）の wide ペア相方掃除

## Goal

ICH（handle_insert_characters）・DCH（handle_delete_characters）・ECH（handle_erase_characters）がセルのシフト・消去で wide ペアを分断したとき、残存する半分を幅1 空白に置換してグリッド不変条件を回復する。

## Requirements

FR5, NFR1, NFR2, NFR3

## Scope

### Files to Create

（なし）

### Files to Modify

- `crates/term_core/src/csi_edit.rs` — ICH / DCH への相方掃除適用、予約名 `blank_wide_pair_split` の補助関数定義、同ファイル内 tests へのテスト追加
- `crates/term_core/src/csi_screen.rs` — ECH への相方掃除適用、同ファイル内 tests へのテスト追加

## Design

空白化の意味論（属性保持・overflow 除去・dirty マーク・事前の幅確認）は IMPLEMENTATION.md「Shared Components: 相方空白化規則」と D2 に従う。補助関数名は D3 の予約名 `blank_wide_pair_split` を使う（task0001 の予約名 `blank_wide_pair_partner` は定義しない）。

### 事後不変条件（この経路のゴール）

各操作の完了後、対象行に IMPLEMENTATION.md「Grid Invariant」違反のセル（直前が幅2 でない幅0 セル、直後が幅0 でない幅2 セル）を残さない。達成手段（操作前に境界列のペアを掃除するか、操作後に影響範囲を補正するか）は実装に委ねるが、掃除の適用対象は操作境界で分断されたペアの残存半分に限り、操作に関与しないペアはそのまま保つ。

### 操作ごとの分断発生点

- **ECH**（消去範囲 [col, col+n)）:
  - 範囲先頭 col が spacer → col-1 の base が孤児化 → 空白化。
  - 範囲末尾 col+n-1 が base → col+n の spacer が孤児化 → 空白化。
- **DCH**（[col+n 以降] を [col] へ左シフト、右端は BCE 埋め）:
  - カーソル col が spacer → col-1 の base が孤児化 → 空白化。
  - シフト元境界 col+n が spacer → シフト後にその spacer が base を失った孤児として col に置かれるため、孤児化させない（空白化）。
  - シフト・BCE 埋めの境界で base が spacer を失う場合も残さない。
- **ICH**（[col 以降] を右へ n シフト、挿入分は BCE 埋め）:
  - カーソル col が spacer → col-1 の base が孤児化 → 空白化。同時に、右へシフトされた元 spacer も base を失った孤児になるため残さない。
  - 右端で pair が部分的に押し出される場合（spacer だけが列外に落ち、base が最終列に残る等）→ 残存半分を空白化する。auto-wrap off の print 経路 quirk（最終列の spacer 無し base）は print 側の意図的状態であり、ICH/DCH が新たに作ることは許容しない。

### 挙動契約（観測可能な事後条件）

- 空白化されたセルは `get_cell_char` が空白 1 文字を返し、`get_cell_width` が 1 を返す。
- 幅1 セルのみの行に対する ICH/DCH/ECH の結果（シフト内容・BCE 背景・dirty マーク）は現行と完全に一致する（NFR1。既存の csi_edit / csi_screen テストが全緑のまま）。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TS7 / FR5): ECH の消去開始位置が spacer のとき、col-1 の base が空白（`get_cell_char` = 空白 1 文字、`get_cell_width` = 1）になる。
- [ ] AC-2 (TS7 / FR5): ECH の消去範囲末尾が base のとき、範囲直後の spacer が空白（幅1）になる。
- [ ] AC-3 (TS7 / FR5): DCH でカーソルが spacer 上のとき、col-1 の base が空白化され、シフト後の行に孤児 spacer / 孤児 base が残らない。
- [ ] AC-4 (TS7 / FR5): DCH のシフト元境界（col+n）がペアの途中を指すとき、シフト後の行に孤児 spacer が残らない。
- [ ] AC-5 (TS7 / FR5): ICH でカーソルが spacer 上のとき、col-1 の base が空白化され、右へシフトされた元 spacer も孤児として残らない。
- [ ] AC-6 (TS7 / FR5): ICH のシフトで spacer だけが右端から押し出されるとき、最終列に残る base が空白化される。
- [ ] AC-7 (NFR1): 既存の term_core テストスイート（`--lib`）が全緑のまま（幅1 のみの行に対する ICH/DCH/ECH の挙動不変を含む）。

## Test Notes

- テストは csi_edit.rs / csi_screen.rs それぞれの inline tests モジュールに、`<subject>_<scenario>_<expected>` 命名で追加する。TerminalCore を明示構築し、`process_pty_data` で駆動する（⏭️ の UTF-8 バイト列で wide ペアを作り、カーソル位置指定シーケンスで spacer / base 位置へ移動してから ICH / DCH / ECH のシーケンスを流す）。assert は `get_cell_char` / `get_cell_width` に対して行う。
- 各 AC は行全体の期待セル列を列ごとに検証する形にし、「掃除された相方」と「無関係なペアの保全」の両方を assert する（掃除しすぎの回帰も検出する）。
- BCE との区別（IMPLEMENTATION.md D2）: 挿入・消去範囲そのものは既存どおりカーソル背景の BCE、相方空白化セルは元属性保持。背景色付きケースを最低 1 つ入れて区別が保たれることを確認する。
