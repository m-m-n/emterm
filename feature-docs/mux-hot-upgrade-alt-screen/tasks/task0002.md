# Task Plan: task0002 — Carry alt-screen state across the hot-upgrade handoff

## Goal

A hot-upgrade round-trips a pane's alternate-screen state through the
handoff document (schema version 3): after restore, a formerly-alt-screen
pane's shadow parser reports the alternate screen again and the next
reattach takes the alt branch, while V1/V2 documents and main-buffer panes
restore exactly as today.

## Design

### Handoff schema v3 (FR3 / FR4 / NFR3)

`HandoffPane` gains two fields:

| Field | Shape | Semantics |
|---|---|---|
| alt-screen flag | boolean | True ⇔ the pane's shadow parser was on the alternate screen at capture time. V1/V2-originated documents: false. |
| alt-screen dump | byte buffer | The parser's formatted alt-screen contents when the flag is true and the D1 cap (IMPLEMENTATION.md) is respected; empty otherwise (main-buffer pane, V1/V2-originated document, or D1 overflow). |

Follow the file's established per-version migration pattern exactly as
V1-to-V2 did (NFR4):

1. Freeze the CURRENT shapes as private version-2 structs (pane / window /
   session / document), field-for-field.
2. The public shapes take the two new fields above.
3. `HANDOFF_SCHEMA_VERSION` becomes 3; `SUPPORTED_HANDOFF_SCHEMA_VERSIONS`
   advertises 1..=3.
4. Conversion chain: V1 converts into V2 (the existing V1 conversions
   retarget the frozen V2 shapes), V2 converts into the current shape with
   alt flag false and empty dump. The decoder dispatches on the leading
   version field: version 1 through the full chain, version 2 through the
   V2 conversion, version 3 directly. V1-originated latch defaults are
   preserved unchanged through the chain (NFR3).

### Capture (FR5 / FR8)

One alt-state capture helper on the pane implements the main/alt split
with the same contract as `build_snapshot_bytes`'s existing split: under
the shadow-parser lock, read whether the parser is on the alternate
screen; when it is, take the formatted-contents dump; otherwise return
flag false + empty dump. The D1 size cap (IMPLEMENTATION.md) is applied
inside this helper: an over-cap dump is replaced by an empty one with the
flag preserved true, plus a warn-level log line naming the pane id and the
oversize length. Having ONE helper keeps the split logic from forking
between the snapshot and refresh call sites.

`snapshot_pane` calls the helper for non-exited panes. A pane recorded
exited contributes flag false + empty dump — an exited pane has no live
alternate-screen semantics to carry, and its restore path builds a fresh
parser anyway.

### Re-capture (FR7)

`refresh_live_agent_state` re-captures the alt flag + dump for each still
live pane via the SAME helper, in the same per-pane loop where agent state
is refreshed today, updating the document entry in place (the existing
companion rewrite of the handoff file then persists it). Both directions
must hold: a pane that entered the alternate screen after the initial
snapshot gets flag true + a fresh dump; one that left it returns to flag
false + empty dump. Nothing else about the refresh pass changes — exited
and vanished panes stay untouched, as today.

### Restore (FR6)

`restore_pane` passes the document's alt flag + dump into
`MuxPane::from_restored`. `from_restored` keeps its existing order and
panic-guard convention: replay the restored scrollback first (unchanged);
then, when the flag is true, feed the alternate-screen-enter control
sequence (ESC [?1049h) followed by the dump into the shadow parser, under
the same panic guard used for the scrollback replay. Flag true + empty
dump therefore enters a blank alternate screen (the D1 overflow shape).
Flag false feeds nothing extra — byte-identical to today. Exited-pane
restore (`from_restored_exited`) is unchanged.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `HANDOFF_SCHEMA_VERSION` is 3 and
      `SUPPORTED_HANDOFF_SCHEMA_VERSIONS` advertises 1..=3; a version-3
      document round-trips the alt flag and dump byte-for-byte (dump
      including non-UTF-8 bytes and embedded zero bytes).
- [ ] AC-2: A V2-shaped document decodes into the current shape with alt
      flag false, empty dump, and every other field preserved; a V1
      document still decodes through the chain with the same alt defaults
      AND its latch fields defaulted exactly as today (NFR3).
- [ ] AC-3: `snapshot_pane` on an alt-screen pane records flag true and a
      dump equal to the parser's formatted alt-screen contents; on a
      main-buffer pane it records flag false + empty dump with all
      remaining fields matching today's capture; on an exited pane it
      records flag false + empty dump.
- [ ] AC-4: A pane that switched buffers between the snapshot and the
      refresh pass has its document entry updated by
      `refresh_live_agent_state`, in both directions (main→alt gains flag
      true + a fresh dump; alt→main returns to flag false + empty dump).
- [ ] AC-5: After `from_restored` with flag true, the shadow parser
      reports the alternate screen as active with the dump's content on
      the alt screen and the replayed scrollback beneath it, and a
      reattach-style snapshot built from that parser takes the alt branch
      (SPEC AC-3).
- [ ] AC-6: `from_restored` with flag false behaves byte-identically to
      today; flag true + empty dump yields an active alternate screen
      with blank contents.
- [ ] AC-7: A capture whose dump would exceed the D1 cap stores an empty
      dump with the flag still true and emits a warn-level log line; a
      dump at or under the cap is stored untouched.

## Test Notes

- AC-1/AC-2 are unit tests in `handoff.rs`'s existing `#[cfg(test)]`
  module, mirroring the existing V1 tests (hand-build a V2-shaped
  document, encode it with the version field at 2, then decode).
- AC-3–AC-7 are unit tests in `upgrade.rs` / `pane.rs` using the existing
  test-pane constructors; drive the shadow parser onto the alternate
  screen by processing the alternate-screen-enter sequence plus content
  bytes.
- AC-7: synthesize the over-cap condition without allocating a real
  16 MiB screen if practical (exercise the helper's cap decision at its
  boundary); if the boundary is unreachable without an unreasonable
  fixture, test the cap-decision seam directly and document that in the
  test.
- Also run the integration harness
  (`--test mux_hot_upgrade -- --test-threads=1`): its pre-existing
  scenarios must stay green in this worktree.
