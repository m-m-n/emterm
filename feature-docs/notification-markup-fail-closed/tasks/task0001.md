# Task Plan: task0001 — Fail-closed capability decision in the notification escape gate

## Goal

The Linux notification escape gate in `NotifyRustSink::send` becomes
fail-closed: a failed capability query results in both title (summary) and
body being escaped, while the two `Ok` outcomes keep their current behavior.

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/callbacks.rs` — the capability predicate
  (`body_markup_confirmed`, line ~220) and the decision branch inside
  `escape_for_send` (line ~186), both under `#[cfg(unix)]`; the doc comments
  on `escape_for_send`, on the predicate, on `escape_body_markup`, and the
  inline comment inside `NotifyRustSink::send` that currently describe
  fail-open semantics.
- `src-tauri/src/callbacks/tests.rs` — invert the expectations of the tests
  that pin the fail-open `Err` path, add the fail-closed pinning test (TS1),
  keep the FR2 pass-through / regression tests, and update test comments that
  state fail-open expectations.

## Design

### Normative decision rule (SPEC Decision Table; FR1 / FR2 / FR3)

One capability-query evaluation per `send` drives BOTH title and body — keep
`escape_for_send`'s existing single-evaluation structure; never split the
decision per field (FR3, SPEC assumption A3: on failure the title is escaped
too, as a consequence of the shared decision).

| Capability query result | Escape title | Escape body | Requirement |
|---|---|---|---|
| Success, list omits `body-markup` (including an empty list) | No | No | FR2 |
| Success, list contains `body-markup` | Yes | Yes | FR2 |
| Failure | Yes | Yes | FR1, FR3 |

### Predicate semantics change (FR1, NFR2)

The current predicate answers "is body-markup support explicitly confirmed?"
and callers skip escaping on every unconfirmed outcome — which makes query
failure land on the unescaped side. Under fail-closed the question inverts:
pass-through is allowed only when the absence of `body-markup` is explicitly
confirmed (query succeeded AND the list omits it). Replace or rename the
predicate so its name and doc state this fail-closed contract; the exact new
name is the implementer's choice, with the constraint that it must not retain
"unconfirmed means skip escaping" semantics in name or documentation.

Contract of the decision unit after the change:

- Precondition: it receives the result of exactly one capability query made
  by `send` for this notification.
- Postcondition: it selects pass-through only for a successful result whose
  list omits `body-markup`; every other input (success with `body-markup`
  present, or failure) selects escaping, and the selection applies to both
  fields of the same call.

### Documentation updates (NFR2, FR5 record)

Every comment that presently asserts fail-open must be rewritten to state
fail-closed, including at least:

- `escape_for_send`'s doc ("fail-open parity, FR1/FR3");
- the predicate's doc ("fail-safe side (FR3): callers must not escape on
  unconfirmed");
- the inline comment in `NotifyRustSink::send` describing the gate;
- test-module comments in `callbacks/tests.rs` that restate fail-open
  expectations (e.g. "must resolve to 'do not escape'", "fail-open parity
  with the body path").

The normative record for the new semantics is this feature's SPEC.md, which
supersedes FR3 of `feature-docs/notification-body-markup-escape/SPEC.md`; the
updated comments should reference the fail-closed specification, not the old
one.

### Existing tests whose expectations change

- `body_markup_confirmed_is_false_on_fetch_failure` — rewrite against the new
  predicate so a failed fetch lands on the escaping side.
- `failed_capability_fetch_leaves_the_title_unchanged` — expectation inverts:
  a failed fetch now escapes the title (and the body, same call).

### Existing tests whose expectations are preserved (FR2)

- `unconfirmed_capability_list_leaves_the_title_unchanged`,
  `unconfirmed_capabilities_leave_the_body_unchanged`,
  `unconfirmed_capability_list_leaves_the_body_unchanged_in_the_same_call` —
  all use a successful list without `body-markup`; pass-through expectations
  stay (comments referring to "unconfirmed includes Err" wording must be
  updated).
- All confirmed-path escape tests (`confirmed_capabilities_*`,
  `tab_activity_and_agent_bodies_are_both_escaped_when_confirmed`, the
  `escape_body_markup` character tests) — unchanged expectations.

### What must NOT change (FR4, NFR3)

- The Windows notification path (the platform notification display call and
  everything outside `#[cfg(unix)]`) receives no capability decision and no
  escaping.
- `sanitize_title` (CSI stripping, control-character stripping, input cap,
  100-character truncation), the escape ordering (`&` first; escape after
  truncation), and the notification rate limiter stay byte-identical.

- [ ] AC-5 (NFR2): no doc comment or test comment in the modified files still

- [ ] AC-6 (NFR1): the main check, the `--lib` test suite, and the
      `--no-default-features` check (commands in VERIFICATION.md) all pass.
- [ ] AC-7 (NFR3): `sanitize_title`, the escape ordering, and the rate
