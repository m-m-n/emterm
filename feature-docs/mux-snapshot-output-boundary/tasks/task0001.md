# Task Plan: task0001 — Pane output boundary: sequence capture, sender-bound suppression, ordered delivery

## Goal

Every mux snapshot is cut at one per-pane output boundary. A chunk the snapshot already captured never reaches that snapshot's destination after the snapshot. The work covers visible reattach, visibility resume and on-demand snapshots, including the backpressure path. The side effects and the terminal queries of a suppressed chunk are preserved as SPEC FR6/FR8/FR9/FR10 require.

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, FR9, FR10, FR11, NFR1, NFR2, NFR3, NFR4, NFR5

## Design

Cross-task decisions D1 to D10, the lock order, lock scope and the Shared Components contracts are in IMPLEMENTATION.md. Threats TM-1 to TM-4 are in THREAT-MODEL.md. This section only adds task-local responsibilities and flows.

### Output capture state (output_capture.rs)
- **Capture step, used by the reader**: inside the capture exclusion, the reader
  - assigns the next number (the first chunk gets 1),
  - runs its existing shadow update and ring write through a caller-supplied step,
  - leaves the new number as last-captured.

  Postcondition: the number is committed only together with both updates.
- **Captured read, used by the snapshot paths and resize**: runs a caller-supplied read of ring and shadow state inside the capture exclusion and returns it with the last-captured number. Callers do no assembly inside the step.
- **Boundary record**: "record (sender, boundary)", "is covered (sender, number)", and a scoped "hold the boundary exclusion" step.
  - The hold lets the caller perform a covered check or a record together with a non-blocking channel insertion.
  - Sender identity is "same channel", not a value comparison.
  - Every record operation first prunes the entries of closed senders (TM-4). Recording again for the same sender updates its entry in place, keeping the maximum.
- **Test pause hook** (test builds only): per pane, the test can arm pause points in the reader.
  - P1: after the shadow update, before the ring write.
  - P2: after the capture step, before taking `output_target`.
  - P3: after a Full insertion attempt, before waiting for a slot.

  A paused reader signals arrival and waits for release, so tests can interleave deterministically.

### Reader flow per non-empty read (pty_spawn/mod.rs)
1. Read the pane dimensions as today.
2. Run the capture step with shadow update, pending-filter feed, main-buffer span extraction and ring write, all as today. A shadow panic-reset still gets a number. Alt-screen chunks get a number even when nothing reaches the ring.
3. Run the unchanged side effects: title, agent-status and OSC 133, OSC 7, osc-probe (FR8).
4. Take `output_target`, then the boundary exclusion, and decide by the target:
   - `Detached`: behave as today.
   - `Connected(S)` and S covers this number: mark the chunk suppressed.
   - Otherwise: try a non-blocking insertion into S.
     - Success: done.
     - Full: release everything, then block until a slot on S is reserved.
       - Reservation succeeded: re-take `output_target`, then the boundary exclusion. If S now covers the number, release the slot and mark the chunk suppressed; otherwise insert through the slot. S stays the destination even if the target changed.
       - Reservation failed (closed): behave as the closed case below.
     - Closed: `capture_passthrough` once, then switch to `Detached(NetworkDetach)` only if the target still points at S.
5. Suppressed chunk, with no lock held:
   - `capture_passthrough` once, then discard the scanner's incomplete in-progress sequence.
   - Build the replacement payload. If it is non-empty, deliver it to S as an ordinary `PtyOutput` chunk with the same backpressure handling, before the next read.
   - The payload is never checked against the boundary. It is dropped silently if S closed.

The EOF chunk takes no number and is never suppressed; its existing release-before-send discipline is unchanged.

### Replacement payload builder (suppressed_output.rs)
- **Inputs**:
  - the suppressed chunk's bytes;
  - which byte ranges of the chunk were written toward the ring;
  - the write filter's pending run after this chunk (possibly empty).
- **Output**: bytes that are the concatenation of Q then T. They may be empty.
- **T**:
  - If the pending run is non-empty, T is the whole pending run.
  - Otherwise T is the chunk's incomplete trailing sequence (ESC with intermediates, CSI, OSC, DCS, APC, or partial UTF-8) whose introducer lies inside the chunk. The chunk's bytes from that introducer are the tail region.
  - Otherwise T is empty.
- **Q**: the complete terminal queries found in the chunk outside the tail region, in original order.
  - CSI device queries matched by the snapshot strip predicate (shared from `scrollback_filter.rs`, single source of truth). A query that the strip would remove together with an embedded control byte is emitted without that byte.
  - OSC 4/10/11/12 color queries (a `?` payload) located outside the ring-written ranges.
- **Recognition (TM-1)**: the builder tracks sequence state the way the client parser does, so a query is recognized only where a control sequence can start. Query-shaped bytes inside the payload of an OSC, DCS, APC, SOS or PM string are never extracted.
- **Cost and bounds (TM-2)**: one forward pass over the chunk, with no rescanning from each byte. The output is at most the pending cap (512 KiB) or the chunk's own length.
- **Postconditions**:
  - T begins with ESC or a UTF-8 lead byte whenever it is non-empty.
  - The builder does no work for chunks that are not suppressed (NFR4).

### Snapshot paths
- **On-demand (`handle_request_pane_snapshot`)**:
  - The session authorization check is unchanged and still runs before any captured read (TM-3). A rejected request records no boundary and enqueues nothing.
  - Captured read: ring bytes, segments and wrap state, the shadow dump, alt flag and dims, and the last-captured number.
  - Assemble with the existing builder outside every lock, then run the existing size check. Size rejection records nothing.
  - Enqueue under the boundary exclusion. An immediate insertion records (S, B). A deferral carries a deferred boundary commit instead.
- **Deferred flush (`flush_deferred_output`, `apply_fair_permit_to_front_deferred_item`)**:
  - When a chunk carrying a commit is inserted, record its boundary under the boundary exclusion in the same step as the insertion.
  - Coalesce, eviction and a closed channel drop the commit.
- **Visibility resume (`resume_pane_with_permit`, `evaluate_output_target`)**:
  - Inside the existing `output_target` section, take the capture exclusion only around the existing ring and shadow reads, which also yields B.
  - After the existing size check passes, record (S, B), then send or return the snapshot and swap as today.
  - `NoChange` and `Unchanged` record nothing.
- **Visible reattach (`collect_reattach_data`)**:
  - Move the ring and shadow reads into one captured read.
  - Decide deliverability with the same single-frame size policy `send_reattach_data` applies: a conservative upper bound first, the exact encoded length only if the bound does not fit.
  - If deliverable, record (tx, B) before the pane's target is swapped to `Connected(tx)`.
  - The returned bytes and segments and `send_reattach_data` behavior are unchanged.
  - Hidden reattach records nothing.
- **Resize (`MuxPane::resize`)**: run the ring marker, PTY resize and shadow resize as one captured step. The existing order and the existing ring-lock span across the PTY resize are kept, and the shadow lock is not nested inside the ring lock.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR2, FR3; TS-1, TS-2, TS-3):
  - **Setup**: the reader is paused at P2 on a chunk that contains an insert-line sequence.
  - **Paths**: visible reattach, `resume_pane_with_permit` and the on-demand snapshot.
  - **Required**: on each path, the destination receives the snapshot and never that chunk after it. Feeding the snapshot plus all later delivered bytes into a fresh `term_core` gives the same screen, cursor and scroll region as feeding the raw stream once.
  - **Pre-change failure**: each of the three tests fails against the pre-change code, recorded in the TDD red step.
- [ ] AC-2 (FR1, FR2; TS-4):
  - **Numbering**: numbers start at 1 and increase by exactly one per non-empty read. This includes chunks that trigger a shadow panic-reset and alt-screen chunks not written to the ring. EOF takes no number.
  - **Snapshot during capture**: with the reader paused at P1, a snapshot attempt waits for the capture step to finish. The captured ring, shadow dump and last-captured number then all reflect the same chunk set.
  - **Resize**: with resize and snapshot running concurrently, the captured ring's latest dimension marker equals the captured shadow dimensions.
- [ ] AC-3 (FR4, FR11; TS-5): with a full small-capacity channel, the reader is held in two positions: at P3, and while waiting for a slot.
  - **Covered chunk**: an on-demand snapshot for the same destination enters the channel first, and after draining, the waiting chunk never appears after the snapshot.
  - **Closed destination**: if the destination closes while the reader waits, `capture_passthrough` runs once. The target becomes `Detached(NetworkDetach)` only if it still pointed at that destination.
- [ ] AC-4 (FR5, FR11; TS-6, TS-11; TM-3, TM-4):
  - **Delivery**: chunks above the boundary and the EOF empty chunk are all delivered.
  - **No record**: no boundary is recorded, and the paused chunk is delivered, for each of these:
    - size-rejected on-demand snapshot;
    - `NoChange`;
    - `Unchanged`;
    - hidden reattach;
    - oversize visible reattach;
    - evicted or coalesced-away deferred snapshot.
  - **Monotonic**: recording a lower boundary for a sender never lowers its entry.
  - **Sender binding**: a boundary recorded for A never suppresses a chunk sent to B after B takes the pane over.
  - **Deferred commit**: a deferred snapshot's boundary becomes effective only when that snapshot enters the channel.
  - **TM-3 (authorization)**: an on-demand snapshot request for a pane outside the requesting connection's session gets the existing rejection. No boundary is recorded for that connection and nothing is enqueued on its channel. Replacement bytes appear only on the channel of the destination that received the snapshot.
  - **TM-4 (bounded record)**: several senders each receive a snapshot for the same pane and then close. After that, recording a boundary for a new sender leaves entries only for live senders. Repeated records for one sender keep a single entry.
- [ ] AC-5 (FR6, FR8; TS-7, TS-8):
  - **OSC 9**: a complete OSC 9 in a suppressed chunk produces exactly one notification on the notification channel, and the destination does not receive the chunk.
  - **Split OSC 9**: an OSC 9 split across the suppressed chunk and the next chunk fires at most once. It never combines with output from a later Detached period.
  - **Other side effects**: title, agent-status report, OSC 133 mark, OSC 7 cwd and osc-probe results for a suppressed chunk match those for the same chunk unsuppressed.
- [ ] AC-6 (FR9, FR10; TS-9, TS-10; TM-1, TM-2):
  - **Device queries**: a cursor-position query and a primary device-attributes query in a suppressed chunk each reach the destination exactly once, in order, after the snapshot and before the next reader chunk.
  - **Color queries**: an OSC color query in an alt-screen span is re-delivered once; one that reached the ring is not.
  - **Cut tails**: for a cut CSI, a cut UTF-8 character and a pending rich-content candidate, `term_core` fed with the snapshot plus later bytes matches the raw-stream reference. No continuation bytes or replacement character appear.
  - **TM-1 (no fabricated queries)**: query-shaped bytes inside an OSC, DCS or APC string payload, or inside the re-delivered tail, are never extracted as queries. Across the snapshot and the replacement, the client receives each query of the raw chunk at most once.
  - **TM-2 (bounded, never empty)**: a suppressed chunk with no query and no tail produces no replacement chunk, so the client never sees an empty chunk before the real EOF. The replacement never exceeds the pending cap or the chunk's own length. A maximal-size adversarial chunk (for example, repeated sequence introducers) is processed within the unit test's fixed time bound.
- [ ] AC-7 (NFR2; TS-12):
  - **Stress**: a stress test runs the reader continuously while resize and all four snapshot paths run repeatedly. It finishes within its timeout.
  - **Existing tests**: the existing EOF G1 regression test and the existing connection fairness and starvation tests pass unmodified.
- [ ] AC-8 (FR7, NFR1, NFR3, NFR4, NFR5; TS-13 to TS-17):
  - **Byte-shape tests**: the existing byte-shape tests in `reattach/tests.rs`, `pane/tests.rs` and the apt / ring-wrap tests in `pty_spawn/tests.rs` pass with their existing assertions and inputs unmodified.
  - **Commands**: `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib` and `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path src-tauri/Cargo.toml --no-default-features` both exit 0.
  - **Comments**: the five FR7 comments no longer contradict the new guarantee.
  - **Platform**: no platform-specific API is introduced.
  - **Lock rules**: the lock-order and lock-scope conventions in IMPLEMENTATION.md hold on every changed path.

## Test Notes

- **Driving the reader**: drive the reader through `pty_reader_loop` with a test-controlled reader that hands out scripted chunks on demand, as the existing tests do. Use the P1/P2/P3 pause hook to interleave; do not use sleeps.
- **Channels**: use a small channel capacity for AC-3. Use two independent channels for the A/B takeover in AC-4.
- **Reference equality**: follow the approach of the existing "continued output matches a reference fed the whole stream" test. Feed a fresh `term_core` instance, then compare visible rows, cursor position and scroll region.
- **Rust-level tests** (`output_capture.rs` or `pane/tests.rs`): boundary-record semantics, i.e. monotonic max, per-sender isolation and pruning of closed senders (TM-4).
- **Builder unit tests**:
  - each FR9 query kind and each FR10 tail kind;
  - the ring-span exclusion for color queries;
  - the empty result;
  - query-shaped bytes inside string payloads (TM-1);
  - the size bound and the adversarial time bound (TM-2).
- **Authorization test**: add the TM-3 unauthorized-request case next to the existing handler authorization tests, leaving those unmodified.
- **Stress test**: bound it by iteration count and a test timeout. It must pass under the default parallel runner.
- **Unrelated flakiness**: the `tabs.rs` replay tests and the `tmux_sockets` discover test are known to be flaky in parallel runs and are unrelated to this task.
- **Formatting**: do not run a crate-wide formatter; only edited files are formatted by the hook.

## Out of Scope

- Moving the wrapped-ring probe replay out of the `output_target` section. That is a separate task (ASM-6).
- The ASM-5 visibility gaps:
  - a deferred snapshot overwriting newer chunks;
  - the reattach read-to-swap window being captured as Detached.
- Chunks already queued in a connection's own channel before that same connection re-attaches.
- Adding color queries to the snapshot strip set, or any other change to snapshot bytes, the wire format or frames.
- Changing the session authorization rule itself.
- The existing Detached-to-Connected handling of passthrough scanner partial state that is unrelated to suppression.
- Hot-upgrade persistence of sequence numbers or boundaries.
