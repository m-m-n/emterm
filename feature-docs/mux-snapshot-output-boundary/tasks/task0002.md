# Task Plan: task0002 — Visible reattach: size decision off the output_target lock, and reader-level reattach tests

## Goal

`collect_reattach_data` decides whether a pane's reattach snapshot will be delivered without encoding the snapshot, and it does nothing inside the pane's `output_target` section except the boundary record and the target swap. Reader-level tests drive the production visible-reattach path with the PTY reader paused, covering the double-application fix (TS-1), terminal-query re-delivery (TS-9), boundary-spanning sequences (TS-10) and sender binding on takeover (TS-11).

## Design

Cross-task decisions D1 to D10, the lock order and the lock scope conventions are in IMPLEMENTATION.md. This task only corrects `collect_reattach_data`'s lock scope and adds tests against the production paths.

### Deliverability decision (TS-16, NFR3)
- **Current defect**: `collect_reattach_data` calls `encode_snapshot_segments` on the assembled snapshot (O(snapshot), up to about 2 MiB) while holding the pane's `output_target` lock, only to feed `fits_single_snapshot_frame`. `send_reattach_data` then encodes the same snapshot again.
- **Encoded length is arithmetic**: `encode_snapshot_payload`'s output length depends only on the segment count and the byte length (magic, count field, fixed-size segment entries, then the bytes). A pure length function gives the exact encoded length with no allocation and no copy.
- **New flow per visible pane**:
  1. Captured read of ring and shadow state, yielding the boundary B (unchanged).
  2. Assembly with the wrap-aware builder (unchanged, outside every lock).
  3. Deliverability: compute the exact encoded length with the pure function and apply `fits_single_snapshot_frame`. No encoding happens in `collect_reattach_data`.
  4. `output_target` section: read the previous target for the log line, record (tx, B) only if deliverable, swap to `Connected(tx)`. Nothing else runs inside it.
- **Unchanged contracts**: `collect_reattach_data`'s return type and returned bytes and segments; `send_reattach_data`'s signature and behavior (it remains the single place that encodes the reattach snapshot); the snapshot byte layout and the wire format (NFR1); the hidden-reattach branch; the raw-passthrough drain.
- **Decision equality**: the pure function must equal the encoder's output length for every input, so that `collect_reattach_data` records a boundary exactly when `send_reattach_data` sends a `SnapshotRestore` for that pane (D9, FR5, FR3).

### Reader-level reattach harness (test code only)
- Drive `pty_reader_loop` through the existing scripted-reader approach, with the reader's handles cloned from a pane that is also registered in a `SessionManager` session, so `collect_reattach_data` sees the same pane state the reader writes.
- Start the pane `Detached` (for example `NetworkDetach`, no owner), as a pane is before a reattach. Pause the reader with the existing test-only pause hook at P2 on the chunk under test, run `collect_reattach_data(visible = true)` for a fresh destination, then release the reader.
- The client view is: the returned snapshot bytes and segments replayed with `reset_and_replay_segments`, followed by every chunk later read from the destination channel, in order. The reference is a fresh `term_core` fed the whole raw stream once. Compare visible rows, cursor position, scroll region and origin mode, as the existing on-demand-shaped reference test does.
- Sensitivity check: each reader-level test in AC-3 to AC-6 must fail when the boundary record in `collect_reattach_data` is disabled. The implementer confirms this once by temporarily disabling the record and notes the result in the task's test record; the committed code keeps the record.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (NFR1, NFR3; TS-16): a pure encoded-length function exists next to `encode_snapshot_payload`. Unit tests show it equals `encode_snapshot_payload(segments, bytes).len()` for: no segments and empty bytes; no segments and non-empty bytes; one segment; many segments; and a byte length at `MAX_SNAPSHOT_FRAME_PAYLOAD` minus the header, and one above.
- [ ] AC-2 (FR3, FR5, NFR2, NFR3; TS-16):
  - **No encode, minimal lock section**: `collect_reattach_data` contains no call to `encode_snapshot_segments` or `encode_snapshot_payload`. Its `output_target` section contains only the previous-target read, the conditional boundary record and the swap.
  - **Deliverable pane**: a visible reattach of a normal-sized pane records the boundary for the new destination, and `send_reattach_data` given the returned data admits a `SnapshotRestore` frame whose payload equals `encode_snapshot_segments` of the returned bytes and segments.
  - **Oversize pane**: for a pane whose assembled snapshot exceeds the single-frame limit (for example the extreme-dimension alt-screen fixture used by the existing oversize resume tests), a visible reattach records no boundary for the new destination, and with the reader paused at P2 during the reattach, the paused chunk reaches the new destination's channel after release.
- [ ] AC-3 (FR1, FR2, FR3; TS-1): with the reader paused at P2 on a chunk containing an insert-line sequence (`CSI L`) on a Detached pane, a visible reattach through the production `collect_reattach_data` followed by release leaves the new destination's channel without that chunk's raw bytes. The client view (returned snapshot, then every later channel chunk) matches the raw-stream reference.
- [ ] AC-4 (FR9; TS-9), reader level, on both the visible-reattach path (production `collect_reattach_data`) and the on-demand path (production `handle_request_pane_snapshot`):
  - **Device queries**: a suppressed chunk containing a cursor-position query (`CSI 6n`) and a primary device-attributes query (`CSI c`) delivers each exactly once to the destination channel, in their original order, after the snapshot and before the next reader chunk. Neither query appears in the snapshot bytes.
  - **Alternate-screen color query**: an OSC 10/11/12 or OSC 4 `?` query inside an alternate-screen span of a suppressed chunk is re-delivered exactly once. A color query in the same kind of chunk that reached the ring is not re-delivered.
  - **String payloads**: query-shaped bytes inside an OSC or DCS string payload of a suppressed chunk are not re-delivered as queries.
- [ ] AC-5 (FR10; TS-10): under the AC-3 conditions, with the suppressed chunk ending in (a) a cut CSI, (b) a cut UTF-8 character, and (c) the start of a rich-content candidate that the scrollback write filter holds as pending, each with its continuation in the next chunk: the client view matches the raw-stream reference, and no continuation byte and no U+FFFD replacement character appears in any visible row.
- [ ] AC-6 (FR11; TS-11): destination A holds a boundary for the pane above the numbers of the chunks that follow. Destination B then takes the pane over through the production `collect_reattach_data(visible = true)` while the reader is paused at P2. After release:
  - every chunk numbered above B's own captured boundary reaches B's channel, none suppressed by A's entry;
  - B's client view matches the raw-stream reference;
  - A's channel receives no chunk produced after the takeover.
- [ ] AC-7 (NFR1, NFR2, NFR5; TS-13): the existing tests in `reattach/tests.rs`, `pane/tests.rs`, `pty_spawn/tests.rs` and `crates/mux_ipc/src/protocol/tests.rs` pass with their assertions and inputs unmodified. `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib`, the `mux_ipc` crate's own tests, and `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path src-tauri/Cargo.toml --no-default-features` all exit 0.

## Test Notes

- **AC-1**: plain unit tests in `crates/mux_ipc/src/protocol/tests.rs`. Build the byte vectors at the size limits once; do not loop over sizes byte by byte.
- **AC-2**: the "no encode" and "minimal lock section" parts are checked by reading the diff (they back the TS-16 review audit). The deliverable and oversize parts are tests. The oversize reader case reuses the P2 harness from the Design section. Because no boundary is recorded, the reader forwards the paused chunk normally after the swap to `Connected`.
- **Reader-level tests (AC-3 to AC-6)**: use the existing P2 pause hook and the scripted reader. Do not use sleeps for ordering. `collect_reattach_data` and `handle_request_pane_snapshot` are async: run them in a tokio test while the reader waits on its std pause channel. Wait for the pause with a bounded `recv_timeout`, as the existing tests do.
- **On-demand variant of AC-4**: call the production `handle_request_pane_snapshot`. Do not copy its steps as the existing `on_demand_snapshot_shaped_suppression_matches_a_reference_and_redelivers_the_query` does. The snapshot then arrives on the destination channel as a Snapshot-kind chunk. Decode its payload before replaying it into the client `term_core`.
- **AC-4 color-query ring case**: a chunk that leaves the alternate screen before its color query writes that query toward the ring. Assert that the destination channel carries no copy of it after the snapshot.
- **AC-6**: A's boundary can be put in place with the existing boundary-record operation for A's sender (A having received a stand-in snapshot on its own channel). The point under test is that A's entry never suppresses B's chunks at reader level; the unit-level isolation test already exists.
- **Harness sharing**: a reader-spawn helper that starts the pane Detached and registers it in a session may be added next to the existing `spawn_reader_with_chunks`. Do not change that existing helper's behavior.
- **Unrelated flakiness**: the `tabs.rs` replay tests and the `tmux_sockets` discover test are known to be flaky in parallel runs and are unrelated.
- **Formatting**: do not run a crate-wide formatter.

## Out of Scope

- Moving the wrapped-ring probe replay, or the existing encode and size check in `resume_pane_with_permit` / `evaluate_output_target`, out of their `output_target` sections. These predate this feature, and ASM-6 is a separate task.
- Moving snapshot assembly after the `Connected` swap (D9's "conservative upper bound first" ordering). The assembly-before-swap order predates this rework and is not one of the failed verify items. This task leaves assembly where it is and only removes the encoding.
- Changing `collect_reattach_data`'s return type or `send_reattach_data`'s signature. Existing tests destructure both, and TS-13 forbids editing them.
- Any change to snapshot bytes, the wire format or the frames (NFR1).
- The visibility-resume, size-rejection, eviction and split-OSC 9 reader-level tests. Those are covered elsewhere.
