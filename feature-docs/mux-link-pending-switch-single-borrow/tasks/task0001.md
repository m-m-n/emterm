# Task Plan: task0001 — mux_link pending-switch block: one mutable borrow, no unreachable drop arm

## Goal

Rewrite the pending-switch block of the PTY-output entry point in the mux link
module so that the tab's pending-switch slot is borrowed mutably exactly once
and the unreachable "no pending switch" arm — the only path on which a queued
PTY payload can vanish without a log line or a fallback — no longer exists.
Nothing observable changes: same return values, same two log lines on the drop
path, same overflow fallback.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2, NFR3, NFR4, NFR5

## Scope

### Files to Create

(none — this task creates no file.)

### Files to Modify

- `src-tauri/src/tabs/mux_link.rs` — the pending-switch block of the PTY-output entry point: collapse to one mutable borrow, latch the target pane id as a copy, match the live-queue outcome with two arms, rename the colliding inner binding, and update only the doc-comment sentences that describe the removed arm.

## Design

Read `IMPLEMENTATION.md` first: D1 (single borrow + copied pane latch), D2
(borrow-region discipline), D3 (rename the inner binding), D4 (the four
acceptance gates), D5 (documentation touch rule), D6 (no new test), and the two
consumed contracts SC-1 (live-queue entry point) and SC-2 (overflow fallback
sequence). This section adds only what is specific to this task and does not
restate them.

### Current shape (what is being replaced)

Inside the pending-switch block the module looks up the pending-switch slot
twice: once immutably to read the target pane id, and again — after a log
statement — mutably to hand the payload to the live-queue entry point. The
second look-up therefore yields an optional value, and its "nothing there"
case is folded into the same arm as the *queued* outcome, where it returns
"no redraw owed" while the payload has already been moved into the call that
never ran. That arm is unreachable today (only a log statement separates the
two look-ups) and it is exactly the arm this task deletes.

### Target shape

1. Borrow the pending-switch slot mutably **once**, for the whole block
   (the mutable-borrow accessor on the optional slot, `as_mut`).
2. Immediately latch the target pane id into a plain copied integer.
3. Compare the arriving payload's pane against the latched copy.
4. **Matching pane** — emit the existing osc-probe log line unchanged, then
   hand the payload to SC-1 and match its outcome with exactly two arms:
   - *queued* — report that no redraw is owed and leave the block;
   - *overflowed* — fall through to SC-2.
   There is no optional-`None` arm and no wildcard arm, so a third variant
   added to the outcome enum later fails to compile here until someone decides
   what it means.
5. **Mismatched pane** — emit the same two log lines (the osc-probe warning
   first, then the debug line), reading only the latched copy and the payload
   this path still owns, and report that no redraw is owed.
6. **Overflow fallback (SC-2)** — carried over verbatim except for the D3
   rename; after the outcome match, the borrow binding is never touched again,
   which is what lets these whole-tab mutable calls compile (D2).

### Invariants this task must not break

- The payload is moved into SC-1 only on the matching-pane path, so the drop
  path still owns it where it reports its length (NFR3).
- SC-2's call order is unchanged (NFR2), and the renamed binding feeds exactly
  the same values to exactly the same uses (FR4).
- The live-queue entry point, its must-use return, the outcome enum and their
  declaration site in the replay module are untouched (NFR1) — if the change
  seems to need an edit there, that is a plan deviation to report, not a scope
  to take.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR3): Within the pending-switch block, the tab's
      `pending_switch` field is referenced exactly once, through the mutable
      borrow accessor (`as_mut`), and the target pane id is latched into a
      copied integer before anything else happens in the block. No second
      look-up of that field remains anywhere in the function.
- [ ] AC-2 (FR2): The live-queue outcome is matched with exactly two arms, one
      per enum variant, with no optional-`None` arm and no wildcard arm.
      Verifiable mechanically: adding a third variant to the outcome enum makes
      this call site fail to compile (a throwaway local experiment, reverted —
      it is not committed and no test file changes).
- [ ] AC-3 (FR3, FR5): The mismatched-pane drop path reads only the latched
      copy of the pane id, still owns the payload where it reports its length,
      emits the same two log lines as before (identical wording, identical
      levels, identical order), and reports that no redraw is owed.
- [ ] AC-4 (FR4, NFR2): The overflow fallback keeps its existing call order —
      take the coalesced redispatch payload, supersede the pending replay
      preferring that payload, reset the frame for replay, apply the queued
      live output, report that a redraw is owed — and the name collision is
      resolved by renaming exactly one binding, with every later use reading
      the same value it read before the change.
- [ ] AC-5 (FR5): `CARGO_TARGET_DIR=src-tauri/target cargo test
      --manifest-path src-tauri/Cargo.toml --lib` passes, including
      `ts3_live_output_queued_during_pending_switch` and
      `offthread_live_queue_cap_falls_back_to_sync`.
- [ ] AC-6 (NFR5): All three check configurations in IMPLEMENTATION.md D4
      (default features, `--no-default-features`, and the Windows cross-check)
      exit 0 with no warning that was not present before the change.
- [ ] AC-7 (NFR1, NFR3, NFR4): The diff touches `src-tauri/src/tabs/mux_link.rs`
      and no other file; it adds no `unsafe`, no new clone of the payload and
      no new dependency; and it rewrites only the doc-comment sentences that
      described the removed arm, leaving neighbouring commentary — including
      its own requirement numbering, which belongs to a different document —
      untouched.

## Test Notes

- **No new test is written** (IMPLEMENTATION.md D6). The TDD contract for this
  task is discharged against the two existing regression tests: run the `--lib`
  suite **before** touching the code to capture a green baseline, then again
  after, and compare. A green-before/green-after pair on those two tests is the
  behavioural evidence for FR5.
  - `ts3_live_output_queued_during_pending_switch` covers the under-cap queue
    path and the mismatched-pane drop path (FR3, FR5).
  - `offthread_live_queue_cap_falls_back_to_sync` covers the overflow path end
    to end: four payloads stay pending, the fifth exceeds the cap, the pending
    switch is abandoned, the snapshot is reparsed synchronously and the queued
    live output is applied on top (FR4, FR5, NFR2).
- **Known flake**: the replay tests in this suite are non-deterministic under
  parallel execution. A failure that does not reproduce is re-run single-
  threaded before being treated as a regression; a failure that persists
  single-threaded is a real one.
- **Compile-time criteria**: AC-1, AC-2, AC-4 (the borrow-region half) and AC-6
  are compile-time or diff-inspection properties, not runtime assertions. AC-2's
  exhaustiveness claim is best evidenced by the throwaway third-variant
  experiment described in the criterion; that experiment is reverted before the
  work is handed over.
- **Command discipline**: run every cargo command from the project root with
  the explicit target directory shown in IMPLEMENTATION.md D4. Do not change
  directory into the crate, and do not let cargo fall back to the
  workspace-default target directory.
