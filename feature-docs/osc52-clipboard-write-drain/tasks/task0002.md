# Task Plan: task0002 — Keep mux snapshot replay content out of the OSC 52 clipboard queues

## Goal

OSC 52 writes and clears contained in mux snapshot content (Snapshot / SnapshotRestore, synchronous or off-thread replay, including the fallback reparses) never enter a tab's OSC 52 queues, so a window switch or reattach never overwrites or clears the user's current clipboard. Live output applied after a replay keeps its OSC 52 entries.

## Requirements

FR7

## Scope

### Files to Create

None.

### Files to Modify
- `src-tauri/src/tabs/replay.rs` — the replay guard inside the synchronous replay recipe reset_frame_for_replay
- `src-tauri/src/tabs/tests/replay.rs` — tests for the sync, off-thread and fallback replay paths
- `src-tauri/src/tabs/tests.rs` — shared tab test helpers if a new one is needed (e.g. a SnapshotRestore message builder, a snapshot payload with an embedded OSC 52 sequence)

## Design

Cross-task rules: IMPLEMENTATION.md Shared Components (queue contract and replay recipe), D2 (GUI-side guard), D3 (live output after a replay is applied).

### Replay guard

| Item | Contract |
|------|----------|
| Where | `Tab::reset_frame_for_replay`, around the replay parse of the payload on the tab's live core (the core whose callbacks are the tab's `NativeCallbacks`) |
| Pre | none |
| Post | The OSC 52 write queue and read queue hold exactly the entries they held when the recipe started, in the same order. Entries the replay's parse appended are gone. Every other effect of the recipe stays as it is today: the frame reset, device-response discard, prompt / fold mark backfill, and callback state such as the title. |
| Logging | No new log line is required. If one is added, it carries only a count (NFR3 convention). |

### Paths this covers

Every synchronous application of snapshot content funnels through the recipe:

1. The sync `Snapshot` / `SnapshotRestore` arm (payload below the off-thread thresholds).
2. The live-queue overflow fallback in the `PtyOutput` arm. The recipe reparses the snapshot, then the queued live output is applied as ordinary output.
3. The worker-disconnect fallback in `poll_pending_switch`. Same shape as item 2.
4. The worker spawn-failure fallback in `dispatch_offthread_replay`.
5. The `Detached` and `PaneCreated` blank resets (empty payload, nothing to remove).

In items 2 and 3 the live output applied after the recipe is live output (D3), so its OSC 52 entries stay queued.

### Off-thread path

The off-thread worker builds its core without callbacks. `apply_offthread_swap` transplants the tab's callbacks onto that core only after the build, so snapshot content cannot reach the queues on this path. The live queue replayed after the swap is live output and stays queued. This task pins that behaviour with tests and expects no code change there. If a test shows snapshot-content entries in the queues after a swap, the same guard is applied around the snapshot half of the swap only, never around the live-queue half.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TM-5): A synchronous `Snapshot` whose content holds an OSC 52 write (target `c`) and an OSC 52 clear (target `p`), applied through `apply_mux_message`, leaves no entry from that content in the tab's OSC 52 write and read queues. The same holds for a synchronous `SnapshotRestore`.
- [ ] AC-2: OSC 52 entries already in the write queue before a synchronous snapshot replay are still there afterwards, in the same order, and the replay adds none.
- [ ] AC-3 (TM-5): An off-thread `Snapshot` and an off-thread `SnapshotRestore`, each with an OSC 52 write in its content, followed by an OSC 52 write in live output queued for the target pane during the pending switch, leave exactly the live entry in the write queue after the swap.
- [ ] AC-4 (TM-5): On the live-queue overflow fallback and on the worker-disconnect fallback, the write queue after the fallback holds exactly the OSC 52 entries from the queued live output, and none from the snapshot content.
- [ ] AC-5: The existing replay tests (for example `reset_frame_for_replay_discards_historic_device_responses`, `reset_frame_for_replay_produces_no_outbound_device_response_write`, `ac1_offthread_swap_transplants_the_preswap_callbacks_instance`, `ac5_offthread_swap_transplanted_callbacks_apply_title_change`) pass without edits.

## Test Notes

- All criteria are tab-level unit tests in `tabs/tests/replay.rs`, using the existing helpers (`test_tab`, `mux_tab_active_pane`, `snapshot_msg`, `small_snapshot_bytes`, `large_payload`, `pty_output`). Assert on the tab's callback state queues directly (`cb_state`), as the existing replay tests do for `pending_apc`.
- AC-1 and AC-2 use a payload below the off-thread thresholds. AC-3 uses a payload above them. AC-4 overflows the live queue past its cap for one case, and calls `test_force_worker_disconnect` for the other.
- Off-thread cases use `test_block_worker_ready` / `test_poll_until_swapped` as the existing swap tests do. Never reproduce timing by loading the CPU. If a replay test flakes under parallel runs, rerun it alone with `--test-threads=1` before treating it as a failure.
- Use a clear (empty payload) as well as a write in the snapshot content, so a guard that dropped only non-empty entries would fail.

## Out of Scope

- Draining or applying the OSC 52 queues to the clipboard (IMPLEMENTATION.md D1). This task adds no drain.
- The daemon's snapshot strip (`src-tauri/src/mux/scrollback_filter.rs`), unchanged (IMPLEMENTATION.md D2).
- Other callback-driven state carried by snapshot replay (titles, images, marks), unchanged.
- OSC 52 in output of non-active mux panes (dropped by existing pane routing, unchanged).
