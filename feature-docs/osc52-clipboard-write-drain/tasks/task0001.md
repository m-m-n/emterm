# Task Plan: task0001 — Drain OSC 52 queues every pump and apply them to the system clipboard

## Goal

Every pump, each tab's OSC 52 write queue is drained and applied on the UI thread to the system clipboard (CLIPBOARD / PRIMARY per target), clears reach a dedicated clear path, and the OSC 52 read queue is drained and discarded. No queue grows across pumps.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR8, FR9, NFR1, NFR2, NFR3, NFR4, NFR5, NFR6

## Design

Cross-task rules: IMPLEMENTATION.md Shared Components (queue contract), D1 (drain point), D2 (no drain inside a replay path), D3 (live output after a replay is applied).

### Components

| Component | Location | Contract |
|-----------|----------|----------|
| Tab OSC 52 drain — `drain_osc52_clipboard(tab) → ordered list of (target, text)` | `tabs/mod.rs` | Pre: none. Post: the result equals the write queue's entries in queue order; both the write and the read queue are empty; read entries are discarded without reading any clipboard and without writing any byte to the PTY (FR4). |
| App OSC 52 batch | `app/mod.rs` | `pump_all` replaces the batch with the entries drained this pump from every tab, in tab order and then queue order (A5). Each tab is drained at the position of the existing `drain_osc` call (D1), for every tab, background and mux tabs included (FR6). `take_osc52_clipboard_batch(app) → ordered list of (target, text)`; post: the batch is empty. |
| Destination mapping — `osc52_destinations(target, primary_available) → non-empty set of destinations` | `window_host/osc52_clipboard.rs` | Pure. A target containing `c` selects CLIPBOARD. A target containing `p` selects PRIMARY. A target containing both selects both. A target containing neither (empty, `s`, `0`-`7`, `q`, or any other character such as `x`) selects CLIPBOARD (FR3, A3). When `primary_available` is false, PRIMARY is replaced by CLIPBOARD and duplicates collapse, so a both-target yields CLIPBOARD once (NFR6). |
| OSC 52 clipboard sink (seam) | `window_host/osc52_clipboard.rs` | Two operations per destination: write a non-empty text, and clear. Each reports success or a failure description; a failure description never contains clipboard text. |
| Batch apply — `apply_osc52_batch(entries, sink, primary_available)` | `window_host/osc52_clipboard.rs` | See Flow. Post: the sink received at most one operation per destination; each destination's operation is the one the last entry addressed to it asked for; the call never panics (FR1, FR2, FR8, TM-4). |
| Failure-log formatter | `window_host/osc52_clipboard.rs` | Pure. Builds the `warn` line for one failed operation from the destination, the text length (0 for a clear) and the failure description only (NFR3, TM-3). |
| Pump-to-sink step — `apply_pending_osc52(app, sink)` | `window_host/osc52_clipboard.rs` | Takes the App batch and applies it with the platform's PRIMARY availability: true on the platform condition the existing PRIMARY code in `window_host/mod.rs` uses (Linux), false elsewhere (Windows). An empty batch makes no sink call. |
| Production sink on `WindowHost` | `window_host/mod.rs` | Uses the host's single clipboard instance. Write sets the destination's text (it may share the arboard calls `set_clipboard` / `set_primary` already make). Clear uses a dedicated path that leaves the destination without text — an arboard clear or an empty-text set is the implementer's choice (A8) — and never goes through `set_clipboard` / `set_primary`. An absent clipboard instance is reported as a failure ("clipboard unavailable"). `set_clipboard`, `set_primary`, `get_clipboard`, `get_primary` and the `SelectionWriteSink` impl keep their current behaviour, including the empty-text early return (FR2, NFR5). |
| Event-loop wiring | `window_host/event_loop.rs` | In `about_to_wait`, the pump-to-sink step runs with the host as sink immediately after the `App::pump_all` call, on the UI thread (NFR2). |

### Flow (one pump)

1. `App::pump_all` runs each tab's parse paths (`tab.pump()`, `tab.poll_pending_switch()`, `tab.poll_pending_scrollback_restore()`).
2. At the `drain_osc` position, `pump_all` drains the tab's OSC 52 queues and appends the writes to this pump's batch. Reads are discarded.
3. `about_to_wait` calls the pump-to-sink step with the `WindowHost`.
4. Batch apply walks the entries in order. For each entry it maps the target to destinations; for each destination it records "write this text" (non-empty text) or "clear" (empty text), overwriting any earlier record for that destination.
5. For each destination that has a record, in the fixed order CLIPBOARD then PRIMARY, batch apply performs that one operation on the sink.
6. A failed operation produces one `warn` line from the failure-log formatter, and the apply goes on to the next destination.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The destination mapping, with PRIMARY available, maps `c` to {CLIPBOARD}, `p` to {PRIMARY}, `cp` and `pc` to {CLIPBOARD, PRIMARY}, and `''`, `s`, `0`, `7`, `q`, `s0`, `x` to {CLIPBOARD}. With PRIMARY unavailable, every one of these targets maps to {CLIPBOARD} (one destination only) (FR3, NFR6).
- [ ] AC-2 (TM-4): Applying a batch to a recording sink sends at most one operation per destination. Each destination's operation matches the last entry addressed to it. Two writes with target `c` and texts `"a"` then `"b"` give one CLIPBOARD write of `"b"`. A write with target `cp` and text `"a"` followed by a clear with target `p` gives a CLIPBOARD write of `"a"` and a PRIMARY clear. The clears with targets `c`, `p`, `cp` and empty are recorded as clear operations on their mapped destinations and never as an empty-text write (FR1, FR2).
- [ ] AC-3 (TM-3): With a sink that reports failure for every operation, including the "clipboard unavailable" case, applying a batch of writes and clears returns without panic and attempts every recorded destination. The failure-log line built for a write of a known text contains neither that text nor its base64 encoding, and contains the destination and the length (FR8, NFR3).
- [ ] AC-4 (TM-2, TM-4): After one `App::pump_all` over an active tab and a background tab that both received OSC 52 writes and an OSC 52 query (with `clipboard_read_osc52` enabled), both tabs' write and read queues are empty. The App batch holds the writes in tab order, then queue order. No byte was written to either tab's PTY in response to the query. A second `pump_all` with no new output leaves both queues empty and the batch empty (FR4, FR6, NFR1).
- [ ] AC-5: In one `App::pump_all`, OSC 52 writes reach that pump's batch from each path: an active-pane mux `PtyOutput` frame; a post-`Detached` tail of the same coalesced buffer; the pre-mux outer parse of plain shell output; and live output queued during an off-thread switch and applied on the swap. A test also fails when the per-tab drain is removed from `pump_all`, and when it is moved ahead of the mux frame-apply loop (the early `cb_state` block of `Tab::process_combined`). The red runs are recorded in this task's test record (FR5, FR6).
- [ ] AC-6: When a tab's output carries the OSC 52 write with target `c` and the base64 of `hello` (BEL-terminated), the pump-to-sink step applied after `App::pump_all` with a recording sink leaves a CLIPBOARD write of `hello`. With an empty batch it makes no sink call. In production `about_to_wait` runs this step with the `WindowHost` right after `pump_all`. Clears go through the dedicated clear primitives, and `set_clipboard` / `set_primary` keep their empty-text early return. This production part is checked by code review and MT-1 (FR1, FR2, NFR2, NFR5).
- [ ] AC-7 (TM-1): An over-quota OSC 52 write (decoded size above `clipboard_max_size_osc52`), invalid base64 and a non-UTF-8 payload fed through `App::pump_all` add no batch entry. The existing tests `osc_52_write_denied_when_over_quota`, `osc_52_query_denied_when_read_disabled`, `osc_52_write_default_allows_within_quota`, `osc_52_clear_pushes_empty_write`, `parse_osc52_*` and the existing `window_host` tests pass without edits. `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path src-tauri/Cargo.toml --no-default-features` succeeds (FR9, NFR4, NFR5).

## Test Notes

- AC-1 is a table-driven test over the target list, run once with `primary_available` true and once with false (TS-1).
- AC-2 and AC-3 use a recording sink double, which records destination and operation per call, and a failing sink double, which reports failure for every call. They live in `window_host/osc52_clipboard/tests.rs` and need no window (TS-2). For the AC-3 log check, assert on the formatter's returned line; the project has no log-capture facility.
- AC-4, AC-5, AC-6 and AC-7 drive `App::pump_all` over shell-less tabs (existing App test helpers). The tab's PTY event receiver is a public field, so a test can replace it with a channel it feeds with PTY data events. Build mux transport bytes (Welcome, `PtyOutput`, `Detached`) with the mux protocol's own encoders, the way the tabs test helpers do. For the off-thread swap case use `test_block_worker_ready` before the single `pump_all`; never use a polling loop that loads the CPU.
- Tab-level coverage of the same paths through `test_process_combined` followed by the tab drain goes in `tabs/tests/output_pipeline.rs` (TS-3, TS-4).
- AC-5's red check: temporarily remove the drain, and separately move it into the early `cb_state` block, and confirm the test fails both ways before restoring it.
- AC-6's production part (the `about_to_wait` call site and the `WindowHost` sink) has no unit-test seam because it needs a window. It is covered by review and the manual checks MT-1 / MT-2 in VERIFICATION.md.
- The `tabs` replay tests are known to be order-sensitive under parallel runs. If one flakes, rerun it alone with `--test-threads=1` before treating it as a failure.

## Out of Scope

- Answering OSC 52 read queries (separate feature). Reads are only drained and discarded.
- OSC 52 in output of non-active mux panes (dropped by existing pane routing, unchanged).
- Snapshot replay content (FR7): handled by the replay guard of IMPLEMENTATION.md D2. This task adds no drain or apply inside any replay path.
- Any setting to enable or disable OSC 52 writes. Any change to `handle_clipboard`'s acceptance gates. Any change to the daemon's snapshot strip.
- macOS.
