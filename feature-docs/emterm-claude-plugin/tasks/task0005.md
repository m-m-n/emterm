## Design

Three defects to fix, each independently — no shared refactor. Handle in this order (each becomes one commit's worth of change, but one merged task):

### F1 (from finding sp-hang-timeout-fr4, high, spec) — internal timeout

SPEC.md FR4 says timeouts MUST result in exit 0. Claude Code's own 3 s hook timeout kills the process with a non-zero exit, so the script needs its own internal deadline that fires *before* Claude Code's timeout, cleans up, and returns 0.

Behavior contract:

- The script MUST enforce an internal deadline of 2 s (leaving 1 s slack under the 3 s hook timeout). Constant name suggestion: `INTERNAL_TIMEOUT_MS = 2000`.
- On deadline expiry, the spawned `emterm` child MUST be terminated (SIGTERM, then SIGKILL if still alive after a short grace).
- After termination, the script MUST return `exit 0` without opening `/dev/tty` and without writing anything.
- Existing failure paths (bad state, missing emterm, tty open failure, non-zero exit, thrown exception) continue to return 0 with no change.

Test coverage additions: a `spawn` fake that hangs (never resolves `exited`) — assert the run function still returns 0 within the timeout window, and `openTty` was never called.

### F2 (from finding cm-nonzero-tty-write, medium, comprehensive) — non-zero exit gate

`run()` currently writes `result.stdout` to `/dev/tty` regardless of `result.exitCode`. SPEC.md Edge Cases makes non-zero exit a no-op. Fix: gate the tty write on `result.exitCode === 0`. When non-zero, skip open and skip write, return 0.

Test coverage: extend the existing AC-6 test so `spawn` resolves with a non-empty stdout AND `exitCode !== 0`; assert `openTty` was called 0 times AND no bytes were written.

### F3 (from finding sp-argv-cardinality, medium, spec) — argv cardinality

SPEC.md FR4 says the script accepts *exactly one* positional argument. The current allow-list only checks the first argument, so `notify-status.ts working extra` still runs. Fix: reject invocations where the positional-arg count is not exactly 1, before the allow-list check. Reject → return 0 (silent no-op, same as other rejections).

Test coverage: new test case with two positional args ("working extra") — assert exit 0, `spawn` never called, `openTty` never called.
