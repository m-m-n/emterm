# Task Plan: task0004 — Plugin README

## Goal

Write the plugin's user-facing README covering install steps, prerequisites, feature summary, and known limitations. This is the surface a Claude Code user reads when browsing `/plugin` output.

## Requirements

FR7, NFR4.

## Scope

### Files to Create

- `plugins/emterm/README.md` — plugin README in English.

### Files to Modify

None.

## Design

### Sections the README must cover

1. **What this plugin does** — one paragraph summarizing the three feature families (agent-status hook, rich-display skills, mux API skills).
2. **Install** — the two commands (`/plugin marketplace add m-m-n/emterm`, then `/plugin install emterm@emterm-plugins`), verbatim.
3. **Prerequisites** — list `emterm` (or `emterm-cli`) binary with a link to the eMterm GitHub Releases page, and `bun` on PATH for the hook script. State that the plugin no-ops silently if `emterm` is missing.
4. **What gets wired** — brief list: three hooks (which Claude Code events map to which agent-status), four display skills, three mux skills.
5. **Supported platforms** — Linux only for v0.1.0. Explain Windows is not supported in this release (planned for v0.2.0).
6. **Known limitations** — enumerate:
   - Some agent-status state changes may not display if the mux-agent-status-api drain wiring is incomplete on the installed eMterm build.
   - No `EMTERM_PANE_ID` fallback in the hook: if `/dev/tty` cannot reach the eMterm PTY (some non-standard shell/multiplexer stacks), state won't propagate.
   - Hook adds up to 3 s per Claude Code prompt in the worst case (Bun cold-start + `emterm` invocation). Real-world overhead is measured during POC and quoted here after the verify phase.
7. **Uninstall** — one line: `/plugin uninstall emterm@emterm-plugins`.

### Tone and format

- Present tense, second person ("you"), no marketing language.
- No installation instructions for `emterm` itself — link to Releases and stop there. The plugin README is not the eMterm README.
- Code blocks for commands, plain prose otherwise.

## Acceptance Criteria

## Test Notes

Content is prose; no automated tests. Coverage is via review (spec compliance) and manual read.

## Out of Scope

- Documentation for the eMterm binary itself.
- Migration or changelog sections (v0.1.0 has no prior version).
