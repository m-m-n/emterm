## Design

The organising principle for this task: **prefer a form with no failure mode to describe over a more carefully described failure mode.** Three rounds of the latter have each produced the next round's findings, so where a construct's safety depends on the model applying a rule correctly, replace the construct.

### F1 (from findings sc-heredoc-delimiter-collision + cm-heredoc-trailing-newline-executes, both high) — mux-send stops putting untrusted bytes on the command line

The quoted-delimiter heredoc fails two ways at once. Its body ends at any line equal to the delimiter, and `EOF` is published in the skill itself — an attacker who controls the text writes a bare `EOF` line followed by commands and gets execution, even when the agent follows the instruction exactly (the wording permits "pick a delimiter unlikely to collide" as an alternative to checking). Separately, a heredoc always appends a trailing newline, and `emterm mux send --stdin` forwards stdin verbatim (`read_to_end`, no stripping), so in a pane running a shell that newline is an Enter and the sent text is executed rather than merely typed.

Make the primary form a file redirection:

```
emterm mux send --pane <id> --stdin < '<file>'
```

Why this ends the class: the untrusted bytes go into a file the model writes and never appear in the command string, so no delimiter, quoting, or escaping rule applies to them at all. The only shell-quoted token is the file path, which the model chose. The model also controls the file's exact bytes, so whether a trailing newline is sent becomes a deliberate choice instead of an artifact of the syntax.

Content of this section:

- State the file-redirection form as the required way to send text from an untrusted source, and say plainly why: nothing derived from the text enters the command line.
- Instruct the model to write the file with exactly the bytes it intends, and to note that a trailing newline in the file is an Enter in the destination pane.
- Keep `--text` for short, model-authored, trusted strings only, with the existing single-quote plus `'\''` rule and the option-placement rule.
- Retain the pane-ID validation guidance unchanged.
- Remove the heredoc form entirely rather than keeping it as an alternative — an alternative with a live hole is still a hole, and the round-3 finding showed the caveat wording is what failed.
- Demote the argv-array note to the same conditional-alternative status it has in the display skills.

Rewrite the adversarial examples so their "safe" claims are true of the new primary form. Round 3 found examples 1 and 3 asserting the opposite of reality — example 1 claimed the pane "receives the literal characters as typed input" and example 3 called a newline-containing payload "Safe … verbatim", when under the heredoc both were executed. Every "Safe" label must describe what actually happens, and the fact that the destination pane executes what it receives must be stated, not implied. Add a line that sending untrusted text to a pane running a shell is an action needing the user's consent.

### F2 (from finding sc-tilde-outside-quotes-invariant, medium) — delete the `~` exception

`emterm markdown -- "$HOME"'/notes.md'` is safe as written, but it is the only construct that puts anything outside the single quotes and nothing states what may go there. The natural generalisation to a `~user/...` path — which the text never mentions — puts an untrusted segment outside the quotes: an untrusted `~$(touch PWNED)/notes.md` becomes `emterm markdown -- ~$(touch PWNED)'/notes.md'` and executes.

Remove the exception instead of qualifying it. In all four display skills, require the model to resolve `~` to an absolute path itself before quoting, and state one invariant: no byte derived from an untrusted path ever appears outside the single quotes. One rule with no special case is what makes this durable; the round-3 finding exists because the special case had no stated boundary.

Keep the existing double-quote warning and its command-substitution adversarial example — round 3 confirmed both are correct.

### F3 — verification before writing

Every form this task documents must be run against the real `emterm` CLI before it goes into a file, under the CLI-safety constraints below. Round 1's `~` breakage and round 3's heredoc holes both shipped because a form was reasoned about rather than executed. At minimum, confirm: the file-redirection form delivers exactly the file's bytes; a file whose content contains a bare `EOF` line is delivered as data with nothing executed; the resolved-absolute-path display form succeeds where the `~`-quoted form failed.

### F4 (from finding cm-posttooluse-overwrites-blocked, medium) — document the precedence gap

`PostToolUse` has no matcher, so a tool completing while another call's permission dialog is open reports `working` and clears `blocked` before the user answers. The clean fix is a precedence rule in eMterm's agent-status (`blocked` persists until the next `UserPromptSubmit` / `Stop` / `StopFailure`), but that is in `src-tauri/`, which this feature does not touch.

Record it instead: add one known-limitation line to the README. Do not add a matcher — narrowing `PostToolUse` would reintroduce the round-1 hole it was added to close, and the reviewer explicitly did not measure whether Claude Code schedules tools during a permission prompt. task0008 records the same limitation on the SPEC side.

## CLI-safety constraints (read before the first `emterm` invocation)

A previous attempt at a sibling task killed the user's terminal: it ran `emterm` while verifying, judged a process hung, and ran `pkill -f "/usr/bin/emterm"`, which matched the user's own eMterm hosting the Claude Code session — it killed its own ancestor and destroyed two agents' work. Per `~/.claude/rules/process-termination.md`:

- `kill`, `pkill`, `killall` are forbidden. No patterns, no `kill $(pgrep ...)`, no negative PIDs.
- Never kill an ancestor: the terminal emulator and `claude` itself are ancestors of you.
- Anything long-running goes through `run_in_background: true` and is stopped with `TaskStop(task_id)`.
- A process that seems hung is REPORTED, not tidied away.
- Prefer invocations that cannot start the GUI: `markdown` / `json` / `yaml` / `image` write to stdout and exit. A bare `emterm` starts the terminal — do not run it.
- Verifying `mux send` needs a live mux pane. If one is not available, say so in the completion report and verify what you can (for example that the redirection delivers file bytes byte-for-byte using a command that reads stdin) rather than starting a terminal to create one.
- Fixture files go under `/tmp/` and stay there (`~/.claude/rules/temp-file-placement.md`); do not `rm` them.
