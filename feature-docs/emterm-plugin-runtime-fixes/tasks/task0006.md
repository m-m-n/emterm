## Design

### F1 (from finding cm-tilde-expansion-broken, medium) — `~` paths

Mandating single quotes broke tilde expansion: single quotes suppress it, and eMterm's CLI does no
expansion of its own, so `emterm markdown -- '~/notes.md'` always fails. This was verified during
review — the bare form exits 0 while the single-quoted form exits 2 (file not found). The previous
bare-path guidance expanded `~` as a side effect, so this is a functional regression the hardening
introduced, currently unexplained anywhere in the four files.

Add a bullet to each display skill's safety section covering it: resolve `~` to an absolute path
before quoting, or expand only the `~` segment and quote the remainder — e.g.
`emterm markdown -- "$HOME"'/notes.md'`. The rule must keep the injection property intact: the
untrusted remainder stays inside single quotes; only the leading `~`/`$HOME` segment is outside.

### F2 (from finding sc-doublequote-not-taught, medium) — teach single vs double quotes

Every display skill's sole adversarial example is `report.md; touch PWNED`. Double quotes defeat
that payload just as well as single quotes, so the example never distinguishes the required form
from the common near-miss, and the unsafe side shows only a bare unquoted path. The lesson the
model draws is "quote it" rather than "single-quote it" — but `$(...)`, backticks, and `${...}` all
still expand inside double quotes. The threat model already covers this class: the hook's own test
suite uses `$(id)` as an injection case.

In each of the four display skills:

- State explicitly that double quotes are insufficient, naming `$(...)`, backticks, and `${...}`
  as still-expanding inside them.
- Add a second adversarial example using a command-substitution payload, contrasting the
  single-quoted safe form against the double-quoted unsafe form (not merely against a bare path),
  so the discriminator is quote *type*, not quote presence.

### F3 (from finding cm-display-image-self-contradiction, medium) — resolve display-image's contradiction

The canonical example is `emterm image --protocol kitty -- '<path>'` while the prose a few lines
later says `--protocol` is optional, kitty is the default, and it should be omitted unless the user
asks for a protocol. In a prompt artifact the first code block is the strongest cue, so the model
will tend to always pass `--protocol kitty`. `skills.test.ts` currently pins the contradiction by
expecting the canonical prefix `emterm image --protocol kitty`.

Resolve it in the direction the prose intends: make the canonical example
`emterm image -- '<path>'`, and show `emterm image --protocol sixel -- '<path>'` as a second,
explicitly protocol-specified example that also demonstrates options going before the `--`. Update
the test's expected canonical prefix for `display-image` accordingly, and evaluate the
option-placement assertion against the second example.

### F4 (from finding sc-mux-send-unreachable, medium) — apply the same rework to mux-send

`mux-send/SKILL.md` still makes "assemble the invocation as an argv array" its primary MUST — the
instruction round 1 found unreachable and the display skills were rewritten to escape. mux-send was
outside that task's scope, so the defect survived in the highest-value skill of the five: it types
into a live PTY, so injection there is command execution in the destination pane. Its recommended
`printf '%s' "$TEXT" | emterm mux send --pane <id> --stdin` is also circular for a Bash-only
caller, because assigning untrusted text into `$TEXT` is itself the step needing escaping.

Rework it the same way:

- Demote the argv-array instruction to the conditional alternative, as the display skills do.
- Make the primary form directly copyable in Bash. For `--stdin`, a quoted-delimiter heredoc
  avoids the variable-assignment problem entirely — nothing inside the body is expanded. Note the
  one condition it requires: the body must not contain a line equal to the chosen delimiter.
- For `--text`, apply the same rule as the display skills: single-quote the value, escape embedded
  single quotes as `'\''`, and place options such as `--pane` before it.
- Keep the existing pane-ID validation guidance.

Do not change `mux-read` or `mux-wait`: `mux-read` was hardened for prompt injection in the
previous feature and takes no free-form text, and `mux-wait` takes no path or text argument.

## Test Notes

- AC-11 matters: the round-1 hardening shipped a form that was safe but broken for `~` paths
  because nobody ran it. Run each safe form you document (a `~` path and a
  command-substitution-shaped filename) against the real CLI and confirm the expected outcome
  before writing it down.

- **How to run the CLI safely for AC-11 — read this before the first invocation.**
  A previous attempt at this task killed the user's terminal. The implementer ran
  `emterm` while verifying, decided a process was hung, and cleaned up with
  `pkill -f "/usr/bin/emterm"`. That pattern matched the user's own eMterm — the terminal
  hosting the Claude Code session — so the agent killed its own ancestor, the session died,
  and two in-flight subagents' work was lost. The rules in
  `~/.claude/rules/process-termination.md` now cover this; the constraints that matter here:

  - **`kill`, `pkill`, and `killall` are forbidden.** No exceptions, no patterns, no
    `kill $(pgrep ...)`, no negative PIDs. A `kill-guard.py` PreToolUse hook enforces it, but
    do not rely on the hook — do not reach for these commands at all.
  - **Never kill an ancestor.** The terminal emulator, the login shell, and `claude` itself are
    all ancestors of this agent.
  - **If something seems to hang, report it — do not tidy it away.** Why it hung is usually
    worth more than the cleanup, and the cleanup is what caused the incident.
  - **Anything long-running goes through the harness**: launch with `run_in_background: true`,
    stop with `TaskStop(task_id)`. Then no PID is ever needed.
  - Prefer invocations that cannot launch the GUI: the `markdown` / `json` / `yaml` / `image`
    subcommands emit an escape sequence to stdout and exit. A bare `emterm` with no subcommand
    starts the terminal — do not run that.
  - Put any fixture files you create for this under `/tmp/` and leave them there
    (`~/.claude/rules/temp-file-placement.md`); do not `rm` them.
- task0005 concurrently edits the README assertions in `skills.test.ts`. Keep your edits inside the
  display/mux hardening describe blocks so the merge stays clean; if `merge-task.sh` reports a
  conflict, follow the parent-side-adoption protocol.
- The static-scan assertions from earlier rounds must keep passing unchanged — do not weaken them
  to accommodate new wording.
