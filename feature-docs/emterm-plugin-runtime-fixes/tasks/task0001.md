# Task Plan: task0001 — terminalSequence transport rewrite

## Goal

Replace the dead `/dev/tty` hook transport with `terminalSequence` JSON output: a POSIX sh script that builds the eMterm agent-status OSC 777 sequence itself, plus the manifest wired in exec form with a corrected Notification matcher. The old TypeScript script and its tests are deleted in the same change so no stale path survives.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4.

## Scope

### Files to Create

- `plugins/emterm/hooks/scripts/notify-status.sh` — the hook. POSIX sh, committed mode 0755.

### Files to Modify

- `plugins/emterm/hooks/hooks.json` — exec form for all three hooks; new script filename; Notification matcher.
- `plugins/emterm/hooks/scripts/notify-status.test.ts` — rewritten to drive the shell script as a subprocess and to cover the manifest-level assertions.

### Files to Delete

- `plugins/emterm/hooks/scripts/notify-status.ts` — superseded (FR6).

## Design

### Script behaviour (FR1-FR3, NFR1-NFR4)

Complete behaviour, in order:

1. If the number of positional arguments is not exactly 1, exit 0 with no output on either stream.
2. If the single argument is not one of `idle`, `working`, `blocked`, `done`, exit 0 with no output on either stream.
3. Otherwise write exactly one line to stdout: a JSON object whose only key is `terminalSequence` and whose value is the canonical sequence for that state (SPEC.md FR3 pins the bytes). Exit 0.

There is no subprocess, no file open, no timer, and no stderr output on any path.

Postcondition on the emitted value: after JSON decoding it MUST equal, byte for byte,

```
ESC ] 777 ; emterm ; agent-status ; v=1 ; state=<state> ; name=claude-code ESC \
```

with `ESC` = 0x1B and the sequence ending in `ESC` followed by a single backslash. The two control bytes and the trailing backslash must be escaped so the line is valid JSON.

### Shell constraints (NFR3)

POSIX only. `case` for the allow-list match, `[` for the argument-count test, `printf` for output. Do not use `echo` to emit the payload (backslash handling is implementation-defined). No `[[`, arrays, `local`, `echo -e`, or `$'...'`. The script must behave identically under `dash` and `bash`.

### Manifest (FR4, FR5)

All three hooks move to exec form: `command` names the script alone, `args` carries the state as its own element, `timeout` stays 3. No `SubagentStop` entry.

The `Notification` entry additionally gains a matcher restricted to notification types that mean a human is being waited on: `permission_prompt`, `elicitation_dialog`, `agent_needs_input`. It must NOT match `idle_prompt`, `auth_success`, `elicitation_complete`, or `elicitation_response`. The matcher is a regular expression over the type name and must be anchored so a listed name cannot match as a substring of a longer name.

### Test file (D3 in IMPLEMENTATION.md)

The test file stays TypeScript under `bun test` but executes the script as a child process. Invoke it via `sh <script> <args…>` so the assertions cover POSIX-shell behaviour rather than the developer's login shell.

## Acceptance Criteria

- [ ] AC-1: `notify-status.sh` exists with a `#!/bin/sh` shebang and is committed with the executable bit set (verifiable via `git ls-files -s`).
- [ ] AC-2: For each of `idle`, `working`, `blocked`, `done`, running the script prints one line that parses as JSON with exactly the single key `terminalSequence`, whose decoded value equals the canonical sequence for that state from SPEC.md FR3.
- [ ] AC-3: Running with an argument outside the allow-list (covering at least `""`, `"invalid"`, and `"WORKING"`) produces empty stdout, empty stderr, and exit 0.
- [ ] AC-4: Running with zero positional arguments produces empty stdout, empty stderr, and exit 0.
- [ ] AC-5: Running with two or more positional arguments (e.g. `working extra`) produces empty stdout, empty stderr, and exit 0.
- [ ] AC-6: Running with an argument containing shell metacharacters (at least `"working; touch PWNED"` and `"$(id)"`) produces empty stdout, exit 0, and creates no file.
- [ ] AC-7: `hooks.json` parses as JSON; all three hooks are exec form (`command` is the script path with no state appended, `args` holds the state); every `command` is `${CLAUDE_PLUGIN_ROOT}`-prefixed with no absolute path and no `..`; `timeout` is 3 on each; there is no `SubagentStop` entry.
- [ ] AC-8: The `Notification` matcher matches `permission_prompt`, `elicitation_dialog`, and `agent_needs_input`, and does not match `idle_prompt`, `auth_success`, `elicitation_complete`, or `elicitation_response`.
- [ ] AC-9: `notify-status.ts` no longer exists, and `notify-status.sh` contains no reference to `/dev/tty`, `emterm`, `bun`, `eval`, or backticks.
- [ ] AC-10: `bun test` passes and `bun run typecheck` passes.
- [ ] AC-11: No file outside the four listed in Scope is created, modified, or deleted.

## Test Notes

- AC-2's assertion is the important one: parse the JSON, decode the string, and compare against the literal canonical sequence. Comparing the raw JSON text instead would let an escaping bug pass.
- AC-8 is a pure-function test over the matcher string — extract the matcher from `hooks.json` and evaluate it against the seven notification-type names. No hook execution needed.
- For AC-6, assert both the absence of output and the absence of the side-effect file, so a future refactor that starts evaluating the argument fails loudly.
- Invoke via `sh` explicitly (not by relying on the shebang alone) so the tests exercise POSIX-shell semantics.
