# Task Plan: task0001 — Strip device queries in scrollback filter

## Goal

`strip_replayable_rich_content` removes every CSI sequence that term_core answers with a device response, so mux snapshots replay without the GUI synthesizing stale replies, while all other bytes replay unchanged.

## Requirements

### Files to Modify

## Design

### Strip predicate (normative, mirrors `crates/term_core/src/csi_dispatch.rs`)

A complete CSI sequence is removed if and only if it matches one of:

| final | private prefix | intermediates | first param | query kind |
|-------|----------------|---------------|-------------|------------|
| `n` | none | none | 5 or 6 | DSR / CPR |
| `c` | none, `?`, or `>` | none | any | DA1 / DA2 |
| `t` | none | none | 14, 16, or 18 | XTWINOPS size report |
| `p` | `?` | `$` | any | DECRPM |

Everything else is preserved byte-for-byte. "First param" is the leading decimal run of the parameter section; an empty run counts as 0 (matching term_core's first-or-zero parameter read).

### CSI recognition (raw bytes)

- Candidate starts at ESC `[`. Body: parameter bytes (0x30–0x3F, which includes the private markers `<=>?`), then intermediate bytes (0x20–0x2F), then a final byte (0x40–0x7E).
- C0 controls other than ESC (0x00–0x1A, 0x1C–0x1F) inside the body do not abort the candidate; when the candidate is stripped, these bytes are re-emitted to the output in order (IMPLEMENTATION.md D2).
- A bare ESC inside the body aborts the candidate: the scanned prefix is preserved as-is and scanning resumes at that ESC.
- A candidate with no final byte before end of buffer is preserved (existing "unterminated → keep" convention).
- The pass remains single O(n), integrated with the existing ESC-dispatch loop in the same function.

### Behavior flow

1. Filter walks the buffer as today; the ESC-dispatch gains a CSI branch (`[`).
2. On a complete CSI, apply the strip predicate: match → emit only embedded C0 bytes and continue past the final byte; no match → emit the sequence unchanged.
3. All existing OSC / APC / DCS handling is untouched.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: DA1 forms (`ESC[c`, `ESC[0c`, `ESC[?…c`) and DA2 forms (`ESC[>c`, `ESC[>0c`) are removed; surrounding bytes preserved (FR1)
- [ ] AC-2: `ESC[5n` and `ESC[6n` are removed; `ESC[0n` and `ESC[?6n` are preserved (FR1, FR2)
- [ ] AC-3: `ESC[14t`, `ESC[16t`, `ESC[18t` are removed; `ESC[22t`, `ESC[23t`, `ESC[8;24;80t` are preserved (FR1, FR2)
- [ ] AC-4: `ESC[?Ps$p` (known and unknown modes) is removed; `ESC[!p` and `ESC["p` are preserved (FR1, FR2)
- [ ] AC-5: `ESC[=c` is preserved (FR2)
- [ ] AC-6: an unterminated CSI at end of buffer is preserved (FR3)
- [ ] AC-7: a stripped query containing an embedded C0 byte re-emits that byte (e.g. BEL survives, query bytes do not) (FR4)
- [ ] AC-8: a bare ESC inside a CSI body aborts the candidate — the prefix is preserved and a following complete query is still stripped (FR2/FR1 interplay)
- [ ] AC-9: a mixed payload of plain text, SGR, viewer OSC, and device queries removes only viewer OSC + queries (FR1, FR2)
- [ ] AC-10: a full `build_snapshot_bytes` product from a DA1-bearing scrollback contains no removable device query (funnel regression, SPEC TS-12)
