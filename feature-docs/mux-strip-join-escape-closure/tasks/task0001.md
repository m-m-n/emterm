## Design

### Notation

- ESC = 0x1B, DEL = 0x7F, BEL = 0x07, ST = ESC followed by a backslash.
- Spaces inside a byte string are separators only (REQUIREMENTS.md A3). `ESC ESC ESC[6n[6n[5n` is 12 bytes; `ESC ESC DEL [6n[5n` is 9 bytes.
- "The predecessor closure" means mux-strip-concat-query-closure D1 (`Written::close_before_removal`). Name it by its feature every time, so it is never confused with this feature's own decision numbering.

### Pipeline and oracle

Both tests drive the pipeline and the oracle described in IMPLEMENTATION.md (Layer Structure, Conventions):

- **Replay view**: a fresh term_core instance is fed the whole snapshot output. The test then reads its rows, cursor and pending responses.
- **Reference view**: a fresh term_core instance is fed the raw stream, excluding the removed construct's own effect. Use the exclusion the sibling modules already apply: feed the raw ESC + construct, discard what that part produced (for example the answer to a removed query), then feed the continuation and observe.

### Test A — two-stage strip gives zero responses (FR1)

1. Create one write filter and feed `ESC ESC ESC[6n[6n[5n` in a single cut-free call.
2. Assert that the ring holds exactly `ESC ESC DEL [6n[5n`.
3. Pass that ring through the snapshot assembly entry point (`build_snapshot_bytes`, which re-strips with `strip_rich_content_and_remap`). Assert that the stripped scrollback part equals the ring byte for byte.
4. Replay the whole snapshot output in a fresh term_core. Assert that the response buffer is empty.

The existing reattach helper in `strip_concat_query` replays through the snapshot but never asserts an empty replay response, so step 4 must be asserted directly. Using that helper alone does not satisfy FR1.

### Test B — no RIS and no G0 designation across a removal (FR2)

- **Construct kinds** (eight): OSC 777 launch with a BEL terminator, OSC 777 launch with an ST terminator, OSC 9999 emterm-md, agent-status report, Kitty APC, SIXEL DCS, answered CSI query, and CSI query with an embedded C0 byte. When the existing removed-construct table used by the DoD-1 test is reachable, reuse it so the kind list cannot drift. Otherwise build a local table of the same eight kinds.
- **Continuations** (two):
  - (a) the single byte `c`
  - (b) `(0` followed by probe text. Every character of the probe text is one that the DEC Special Graphics set maps to a line-drawing glyph.
- **Per case** (8 × 2 = 16 cases):
  1. The input is visible prefix text, then ESC, then the construct, then the continuation. Feed the whole input in one cut-free call. The prefix makes a reset observable.
  2. Snapshot-strip the ring and replay it as in Test A.
  3. Build the reference view from the same raw input, with the construct's own effect excluded.
  4. Assert that rows, cursor and responses are equal. Also assert that the prefix text is still on screen, that the probe text is displayed as typed, and that the replay produced no response.
  5. A failing case names its construct kind and its continuation.

### Sensitivity controls (FR1, FR2)

The predecessor closure already exists, so Tests A and B pass from their first run and no red stage can be observed (REQUIREMENTS.md A6). Instead, the new module carries controls showing that each assertion can detect the attack it guards against:

- **Control for Test A**: the term_core setup used for replay answers `ESC[5n` with a non-empty response. `ESC[5n` is the joined query a closure-less two-stage strip would leave.
- **Control for Test B (a)**: prefix text followed by `ESC c` replays with the prefix gone, so a reset occurred. This is the closure-less join of continuation (a).
- **Control for Test B (b)**: `ESC(0` followed by the probe text displays characters that differ from the typed probe text. This is the closure-less join of continuation (b).

### DECISIONS.md content (FR4, FR5)

The document has two parts: decisions and residuals. Its content is fixed by SPEC.md FR4 and FR5. Cite those requirement IDs and include every listed point.

**Decisions:**

- **Scenario mapping.** For each of scenarios 1 to 3, give the bytes the write strip writes under the predecessor closure, and the test that pins the scenario:
  - Scenario 1: `ESC[6 DEL n`, pinned by the existing DoD-1 test.
  - Scenario 2: `ESC ESC DEL [6n[5n`. The snapshot strip leaves it unchanged, and term_core shows `[6n[5n` as text. Pinned by Test A.
  - Scenario 3: `ESC DEL c` and `ESC DEL (0`. Pinned by Test B.
- **Why DEL is inert in term_core.** DEL cancels an open CSI. Right after a lone ESC, DEL is an unknown escape final, which term_core ignores.
- **Superseded mitigation.** The mitigation the task proposed (CAN after ESC, and moving `closure_for` into `scrollback_filter`) is superseded by the predecessor closure. `closure_for` stays the cut-only closure.
- **Scope.** This feature makes no production change.

**Residuals:**

- **The kept-string-body join**, recorded as out of scope. The entry gives the mechanism, the `ESC]11;` reproduction, the impact, the wrap dump-block condition at `snapshot_bytes.rs:490`, and the two pinned expectations that stay unchanged, all as SPEC.md FR5 lists them.

## Test Notes

- AC-1, AC-2 and AC-7 are unit tests in the new module. AC-3 is the existing test, rerun unchanged.
- **Red stage.** AC-1 and AC-2 pass on their first run because the predecessor closure already exists (REQUIREMENTS.md A6). Record them with `red_confirmed: false` and state that reason. The AC-7 controls are the evidence that those assertions discriminate. For AC-3, the record cites the existing test.
- **Non-test criteria.** AC-4, AC-5 and AC-6 have no test of their own. Record them with `tests: []` and give the reason: document content for AC-4 and AC-5, build and diff outcome for AC-6.
- **Excluding the construct's own effect.** Follow the sibling modules' existing convention. A construct's own effect may change rows or cursor in the raw reference, for example an embedded C0 byte or an image construct. Exclude that effect the same way the existing references do. Never weaken the comparison to fewer fields.
- **Test budget.** Keep each case small (fresh term_core instances, short inputs) so the 16 cases stay inside the budget.
- **Known unrelated flakiness in the `--lib` suite.**
  - The tabs replay tests can fail nondeterministically under parallel runs; they are stable with one test thread.
  - The tmux socket discovery tests rarely fail under parallel runs.
