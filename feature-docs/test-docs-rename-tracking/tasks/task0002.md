# Task Plan: task0002 — Project rule: test-docs records follow cross-feature test renames

## Goal

A new project rule under `.claude/rules/` makes "follow current names" the policy for
test-docs records when a later feature renames a test that an earlier feature's record
lists, so later features apply it without deciding again.

## Requirements

FR6, NFR1, NFR3

## Scope

### Files to Create
- `.claude/rules/test-docs-records.md` — project rule stating the follow-current-names policy for test-docs records (FR6)

### Files to Modify

None.

## Design

### Placement and form (NFR3)

- Location: this repository's `.claude/rules/`. The file name `test-docs-records.md` is a
  noun naming its content and carries neither a `project-` nor a `core-` prefix. Nothing
  is written to the em-workflow plugin repository (its templates / references).
- Form: English Markdown in the style of the existing `.claude/rules/` files — a title, a
  short statement of purpose, then the rules as short sections or bullets. Each rule is
  phrased affirmatively: it states what to do.
- Content is limited to the policy, its scope and the four elements below. The
  background of the incident that prompted the rule (PR numbers, review finding ids, the
  specific renamed tests) is not included.

### Content: policy and scope

- Policy: when a later feature renames a test listed in a test-docs record, the record
  follows the current name. Records are not frozen as point-in-time snapshots.
- Target: the `acceptance_tests[].tests` lists of `test-docs/{feature}/taskNNNN.tests.yaml`
  records (SPEC A-6).
- Applies to renames that have a successor test. Deleting a test without a successor is
  outside the rule (SPEC A-7). Old-name mentions in predecessor features' feature-docs
  prose (SPEC / tasks / VERIFICATION) are outside the rule (SPEC A-6).

### Content: the four elements (FR6)

1. Update duty: a feature that renames a test listed in a predecessor feature's
   `test-docs/*/taskNNNN.tests.yaml` updates those `acceptance_tests[].tests` entries to
   the current names itself.
2. Supersede note: when the rename comes with a behavior change that inverts a
   predecessor AC's expectation, that AC's block gets a supersede note as a YAML comment.
   The note names the superseding SPEC and its FR IDs. `red_reason` is not changed.
3. The renaming feature's own records stay as written: its documents that record the
   rename — its SPEC, its `reviews/roundN.yaml`, and its own tests.yaml — are kept
   verbatim.
4. Resolution check: each updated name matches at least one test in the project's cargo
   test listing. The rule names the listing command — the `--lib` unit-test command of
   core-commands.md / core-build-location.md (quick-check target directory, manifest path
   `src-tauri/Cargo.toml`, run from the project root) with the libtest `--list` flag — and
   states that each updated name appears in its output as a test.

- [ ] AC-2 (FR6): The rule states the follow-current-names policy (records are updated to current names, not frozen as snapshots) and its scope: the `acceptance_tests[].tests` lists of test-docs records and renames that have a successor test, with test deletion without a successor and predecessor feature-docs prose outside it.
- [ ] AC-3 (FR6): The rule states that a feature that renames a test listed in a predecessor feature's `test-docs/*/taskNNNN.tests.yaml` updates those `acceptance_tests[].tests` entries to the current names.

- [ ] AC-5 (FR6): The rule states that the renaming feature's own SPEC, `reviews/roundN.yaml` and own tests.yaml are kept as written.
- [ ] AC-6 (FR6): The rule states that each updated name must match at least one test in the project's cargo test listing and names the `--lib` listing command.
- [ ] AC-7 (NFR1, NFR3): The task's diff contains only the new rule file; no file outside this repository (the em-workflow plugin's templates / references) and no file under `src-tauri/`, `crates/` or build configuration is written.
