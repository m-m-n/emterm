# selection-anchor-pivot - 要件定義書

## 1. 概要

### 1.1 背景

ダブルクリックのワード選択後にドラッグして上の行に触れると、上の行のワード位置が選択の開始位置になり、最初に選択したワードが選択範囲から外れる。トリプルクリックの行選択にも同じ構造の問題がある。

原因は `Selection::extend`（`src-tauri/src/selection.rs`）が Word / Line モードで呼び出しのたびに anchor / extent を境界スナップ結果で破壊的に上書きすることにある。ドラッグ中は motion イベントごとに extend が連続して呼ばれるため、2 回目以降の extend で元のワード / 行の位置情報が失われる。既存ユニットテストは extend を 1 回しか呼んでいないため検出できていなかった。

### 1.2 目的

ダブルクリック / トリプルクリック後のドラッグ選択で、最初に選択したワード / 行を常に選択範囲に含み続ける（ピボット挙動）。

### 1.3 スコープ

- Word モード（ダブルクリック）のドラッグ拡張
- Line モード（トリプルクリック）のドラッグ拡張
- Character モード（シングルクリック + ドラッグ）は変更しない

## 2. ビジネス要件

### 2.1 ビジネス目標

マウス選択が常に予測どおりに動作すること。

### 2.2 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| eMterm 利用者 | ターミナル上でマウス選択・コピーを行う全ユーザー |

### 2.3 期待される効果

- ダブルクリック / トリプルクリック起点のドラッグ選択で、選択開始位置がズレない

## 3. ユースケース

### 3.1 ユースケース一覧

| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | ワード選択のピボット拡張 | 利用者 | 高 |
| UC02 | 行選択のピボット拡張 | 利用者 | 高 |

### 3.2 ユースケース詳細

#### UC01: ワード選択のピボット拡張

**アクター**: 利用者

**事前条件**:
- ターミナルにテキストが表示されている

**基本フロー**:
1. ワードをダブルクリックする → そのワード全体が選択される
2. ボタンを押したまま上の行のワードへドラッグする → 「ドラッグ位置のワード先頭〜元ワードの末尾」が選択される
3. 元のワードの位置へドラッグで戻る → 元のワードのみの選択に戻る
4. 下の行のワードへドラッグする → 「元ワードの先頭〜ドラッグ位置のワード末尾」が選択される
5. ボタンを離してコピーする → 表示されていた選択範囲のテキストが得られる

**代替フロー**:
- ドラッグ先が空白セルの場合: そのセル位置を端点として扱う（ワード境界は収縮する）

**事後条件**:
- 最初に選択したワードが選択範囲に含まれている

#### UC02: 行選択のピボット拡張

**アクター**: 利用者

**事前条件**:
- ターミナルにテキストが表示されている

**基本フロー**:
1. 行をトリプルクリックする → その行全体が選択される
2. ボタンを押したまま上下の行へドラッグする → 「ドラッグ位置の行〜元の行」の全行が選択される
3. 元の行へドラッグで戻る → 元の行のみの選択に戻る

**事後条件**:
- 最初に選択した行が選択範囲に含まれている

## 4. 機能要件

### 4.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | ワード選択のピボット拡張 | ダブルクリックしたワードを固定端としてワード単位で拡張する | 高 |
| F02 | 行選択のピボット拡張 | トリプルクリックした行を固定端として行単位で拡張する | 高 |
| F03 | スクロール追従との整合 | ピボット位置も絶対行モデルに従い、eviction 補正の対象とする | 高 |

### 4.2 機能詳細

#### F01: ワード選択のピボット拡張

**説明**: ダブルクリック時のクリック位置（origin）を保持し、ドラッグ中の extend では origin のワード境界とドラッグ位置のワード境界から選択範囲を毎回再計算する。

**入力**:
- origin: Pos - ダブルクリックしたセル（絶対行 + 列）
- pos: Pos - 現在のドラッグ位置（絶対行 + 列）

**出力**:
- 選択範囲: 読み順で pos が origin より前なら「pos のワード先頭〜origin のワード末尾」、後なら「origin のワード先頭〜pos のワード末尾」、origin のワード内なら「origin のワードのみ」

**ビジネスルール**:
- ドラッグ中の extend を何回繰り返しても、origin のワードが選択範囲に含まれ続けること
- 上下方向・左右方向（同一行内の別ワード）のいずれでも同じピボット規則を適用すること

#### F02: 行選択のピボット拡張

**説明**: トリプルクリックした行（origin 行）を保持し、ドラッグ中の extend では「origin 行〜ドラッグ位置の行」の全行を毎回再計算する。

**入力**:
- origin: Pos - トリプルクリックしたセル
- pos: Pos - 現在のドラッグ位置

**出力**:
- 選択範囲: min(origin 行, pos 行) の行頭〜 max(origin 行, pos 行) の行末

**ビジネスルール**:
- ドラッグ中の extend を何回繰り返しても、origin 行が選択範囲に含まれ続けること

#### F03: スクロール追従との整合

**説明**: origin は anchor / extent と同じ絶対行モデル（`Pos.row` = 絶対バッファ行）で保持し、scrollback eviction 時の補正（`shift_rows_down`）を適用する。

**ビジネスルール**:
- origin 行が evict された場合の扱いは既存の anchor / extent と同じ規則に従うこと（選択の clamp / drop）
- reflow・alt-screen 切替・タブ切替での選択全クリアは現状維持とすること
