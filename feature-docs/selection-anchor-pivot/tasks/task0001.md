# Task Plan: task0001 — Pivot-anchored word / line drag selection

## Goal

Double-click (word) and triple-click (line) drag selections always keep the
originally clicked word / line inside the selection: every extension
recomputes both endpoints from the immutable origin position and the current
pointer position.

## Requirements

FR1, FR2, FR3, NFR1

## Scope

### Files to Create

- None.

### Files to Modify

- `src-tauri/src/selection.rs` — retain the origin position in the selection
  type; rework Word / Line extension to recompute endpoints from
  (origin, pointer); apply eviction compensation to the origin; add
  multi-extension unit tests.
- `src-tauri/src/window_host.rs` — verify the press / drag call sites still
  satisfy the construction contract (origin = press cell); adjust only if the
  constructor contract requires it.

## Design

- **Origin retention**: the selection type captures the press position
  (absolute row + column) at construction. Invariant: the origin is never
  mutated by extension; it changes only under eviction compensation (below).
- **Word-mode extension contract** (FR1): precondition — pointer position in
  absolute coordinates. Postcondition — with word boundaries computed against
  the live core for both the origin and the pointer position:
  - pointer before the origin word in reading order → range spans from the
    pointer word's start to the origin word's end;
  - pointer after the origin word → range spans from the origin word's start
    to the pointer word's end;
  - pointer inside the origin word → range is exactly the origin word.
- **Line-mode extension contract** (FR2): postcondition — range covers full
  rows from the lower of (origin row, pointer row) to the higher, column 0
  through the last column.
- **Eviction compensation** (FR3): the scrollback-eviction shift applies the
  same row delta and clamp rules to the origin as to the endpoints; the
  existing drop rule for fully evicted selections is unchanged.
- **Character mode** (NFR1): extension behavior untouched; rendering,
  ordering, and copy resolution keep reading only the two endpoints.
- Boundary lookups run against the live core on every extension — no caching
  of the origin word's column span beyond the origin position itself.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Word mode — after two or more consecutive extensions onto a word
  on the row above, the ordered range spans from that upper word's start to
  the origin word's end.
- [ ] AC-2: Word mode — extending away and then back to a position inside
  the origin word yields exactly the origin word.
- [ ] AC-3: Word mode — extending above and then below past the origin word
  yields the origin word's start through the lower word's end.
- [ ] AC-4: Word mode — extending to an earlier word on the same row yields
  that word's start through the origin word's end.
- [ ] AC-5: Line mode — repeated extensions up / down / back always cover
  full rows including the origin row; returning to the origin row yields the
  origin row only.
- [ ] AC-6: Eviction compensation shifts the origin together with the
  endpoints; a fully evicted selection is dropped as today.
- [ ] AC-7: All existing selection unit tests (character mode, single-extend
  word / line, resolve / copy, eviction) pass unmodified.

## Test Notes

- All criteria are unit tests in the selection module's existing test
  section, using the existing core-builder test helpers (plain and wide
  grids, scrollback builder).
- The crux is multi-extension sequences: existing tests call extension once,
  which is exactly why the bug escaped. AC-1, AC-2, AC-3, AC-5 each require
  at least two extension calls in sequence.
- Edge cases worth covering: extension onto a whitespace / empty cell
  (endpoint collapses to that cell while the origin word edge is kept);
  origin in scrollback with pointer in the viewport.
- AC-7 is enforced by running the full library test suite — do not edit
  existing test expectations.
