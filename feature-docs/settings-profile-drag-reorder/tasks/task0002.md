# Task Plan: task0002 — SSH connection list dragstart sets drag data, with regression tests

## Goal

Dragging an item in the settings panel's SSH connection list starts a drag on
Linux (WebKitGTK) and reorders the connections, because the SSH connection
list dragstart handler puts the item's index on the DataTransfer under the
list's custom MIME type. A bun regression test file detects a dragstart
handler that sets no drag data.

## Requirements

FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create
- `src-tauri/web-shared/settings/sections/ssh-section.test.ts` — regression tests for the SSH connection list drag reorder

### Files to Modify
- `src-tauri/web-shared/settings/sections/ssh-section.ts` — the dragstart handler of the SSH connection list drag-reorder setup also sets the drag data

## Design

### Component

The module-private SSH connection list drag-reorder setup in `ssh-section.ts`
(currently `setupSshDragReorder`). It registers dragstart / dragover / dragend
/ drop listeners on the connection list container through `SectionContext`
and keeps the dragged item's index in an in-memory `dragIndex`. The read-only
`.ssh/config` host list in the same section is not draggable and is not part
of this task.

### dragstart flow after the change

1. Resolve the list item from the event target; return when none is found
   (unchanged).
2. Store the item's index in `dragIndex` and add the `dragging` class
   (unchanged).
3. When the event carries a DataTransfer: set effectAllowed to `"move"`
   (unchanged) and add one entry of type `application/x-emterm-ssh-index`
   whose value is the item's `data-index` as a decimal string (new).

### Contract

- Postcondition of dragstart on the connection item whose `data-index` is i:
  the DataTransfer holds exactly one entry, of type
  `application/x-emterm-ssh-index`, with value i as a decimal string, and
  effectAllowed is `"move"` (IMPLEMENTATION.md, list drag-payload convention).
- dragover, dragend and drop behave exactly as before this task (FR4,
  IMPLEMENTATION.md D1).

### Constraints

- The change stays inside the existing setup function. No helper is extracted
  and no new export is added (FR5, IMPLEMENTATION.md D2).
- Only the two files listed under Scope change. `test-setup.ts` and the
  Rust/wry side stay unchanged (NFR1).

## Test Notes

- AC-1 to AC-5 are unit tests in `ssh-section.test.ts`. AC-6 is the red-first
  run of the AC-1 test before the fix. AC-7 is a command run.
- Every test renders the section with `ssh_command_path` set to an empty
  string, so the section does not request the `.ssh/config` host list over
  Tauri IPC (SPEC.md A6).
- The stub `SectionContext` follows IMPLEMENTATION.md Shared Components: its
  listener registration attaches the handler to the element (the drag
  listeners live on the list container, and the section's other inputs also
  register through it), and `saveSetting` / `reRender` record calls.
- Build the settings fixture inside the test file, following the style of the
  existing section tests in the same directory. Connections need
  distinguishable names so the reordered array can be compared by identity or
  name.
- Select the items of the eMterm SSH connection list (the draggable items
  carrying `data-index`), and dispatch every drag event on such an item with
  bubbling enabled, so the delegated listener resolves the item.
- DataTransfer: use the happy-dom Window class, or a minimal stub that records
  entries in insertion order and exposes the type list, the value per type and
  effectAllowed (IMPLEMENTATION.md Conventions). AC-2 asserts on the full type
  list, not only on the absence of `text/plain`.
- For AC-4, the drop event carries a DataTransfer pre-filled with the list's
  custom MIME type, which proves the drop handler does not read it.
- Render a fresh section for every test so `dragIndex` does not leak between
  tests.
