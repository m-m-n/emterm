# Task Plan: task0002 — Remove mux statusbar settings from the TypeScript mirror

## Goal

Remove the mux statusbar settings types and fixtures from the TypeScript
settings mirror so the TS schema matches the post-removal Rust schema (no
`statusbar` member on the mux settings object).

## Requirements

FR4 (TypeScript mirror only), NFR2 (TypeScript suites). The Rust mirrors of
FR4 are a sibling task's scope — see IMPLEMENTATION.md Shared Components,
"Settings mirror shape".

## Scope

### Files to Create

- (none)

### Files to Modify

- `src-tauri/web-shared/settings/types.ts` — remove the
  `MuxStatusbarSettings` / `MuxStatusbarCommand` interfaces and the
  `statusbar` field on the mux settings interface (~129-147).
- `src-tauri/web-shared/settings/sections/mux-section.test.ts` — remove the
  statusbar fixture data (~52) so fixtures conform to the updated types.

## Design

- The change is schema-only: mux-section.ts renders no statusbar fields, so
  no settings-UI control is removed — only type declarations and test
  fixtures (SPEC FR4 note).
- Target shape is fixed by the Shared Components contract "Settings mirror
  shape": after this task, the TS mux settings object has no statusbar
  member and no `MuxStatusbarSettings` / `MuxStatusbarCommand` type. No
  tolerance logic is needed on the TS side — it receives already-normalized
  settings from the backend.
- Preservation boundary (IMPLEMENTATION.md D4): `status-bar-section.ts`
  (general status bar settings UI) and the rendering logic of
  `mux-section.ts` are untouched.
- If the type removal surfaces additional references in web-shared /
  settings code (caught by typecheck), that is a reportable plan deviation —
  report it rather than silently expanding scope.

## Test Notes

  removed types anywhere in the checked TS scope fails it.
- The mux-section test suite keeps its existing assertions; only the
  fixture object loses its statusbar member. No new test cases are
  required — green suites with the removed shape are the verification.

## Out of Scope

- Any settings-UI rendering change (no statusbar controls exist in

- The general status bar settings section (status-bar-section.ts).
