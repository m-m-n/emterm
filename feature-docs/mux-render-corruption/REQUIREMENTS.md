# mux 描画崩れ（window/tab 切替後の行内容混在）の修正 - 要件定義書

## 1. 概要

### 1.1 背景

mux 上で動作している Claude Code の画面で、描画が壊れる事象が報告された。
スクリーンショットでは、別々の行の内容が 1 行に合成されて表示されている
（例: 入力中のテキストと過去の出力行が混ざった「medium 8件も起票しておいて
ってたようで、それは期待した描画になってる」という行）。

他の mux ウィンドウへ出力が漏れているのではなく、同一ウィンドウ内の
Claude Code 画面自体が壊れる。

### 1.2 目的

mux の window/tab 切替後に発生する描画崩れの原因を特定し、修正する。

### 1.3 スコープ

- 描画崩れの原因調査と修正
- 既知の未修正バグ「resize 時に新旧行数のバイトが scrollback に混在し、
  固定行数 replay で座標がズレる」（`tmp/apt-progress-bar-regression-2026-07-09.md`、
  PROBE D で実証済み）との関係調査を含む。同一真因ならまとめて修正する

## 2. 発生状況（確認済み事実）

| 項目 | 内容 |
|------|------|
| 発生環境 | eMterm mux 上の Claude Code |
| 発生タイミング | window/tab 切替後。ただし切替を行えば確実に発生するわけではない（間欠的） |
| mux 外での発生 | 未確認 |
| 発生時期 | 最近気づいた |
| 症状 | 別々の行の内容が同一行に混在して表示される |

## 3. 機能要件

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | 原因調査 | window/tab 切替後の描画崩れの真因を特定する。既知の replay 座標ズレバグとの関係（同一真因か別か）を切り分ける | 高 |
| F02 | 修正 | 特定した真因を修正し、window/tab 切替後に行内容が混在しないようにする | 高 |
| F03 | 再発防止テスト | 真因を再現するユニット/統合テストを追加する | 高 |

## 4. 非機能要件

- 修正により mux の window 切替・reattach の体感性能を悪化させない
- 既存のテストがすべてパスする

## 5. 制約条件

- 状態の権威は daemon 側（scrollback / snapshot 組み立て）と GUI 側
  （replay 適用）にまたがるため、修正はどちらの層かを調査で確定してから行う
- Linux / Windows 両対応を維持する

## 6. 成功基準

### 6.1 受け入れ基準

- [ ] 真因が特定され、既知の replay 座標ズレバグとの関係が明確になっている
- [ ] 真因を再現するテストが追加され、修正後にパスする
- [ ] 既存テストにリグレッションがない
- [ ] 最終的な実機確認（mux で window 切替を繰り返して崩れないこと）はユーザーが行う

## 7. テストシナリオ

- [ ] 正常系: window/tab 切替後の snapshot replay で行内容が混在しない
- [ ] 境界値: resize を挟んだ scrollback を持つ window の切替 replay
- [ ] 異常系: 崩れた状態を再現する入力列に対して修正後は正しく描画される
