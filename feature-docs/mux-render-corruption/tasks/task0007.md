## Design

### D1'''' — Keep the evicted head's dimensions (bb3353636b0206cb)

`enforce_dim_marker_cap` pops the front entry, which is the one describing the
retained window's leading span. `read_segments` then finds no head and falls
back to the oldest *surviving* marker's dimensions, so content produced before
that marker replays under a later size.

Measured by the reviewer, deterministically: an apt-style phase followed by 26
resize markers (28 total) replayed at 120x47 yields 0 mixed rows with full
attribution, 3 with no segments at all (the pre-feature behaviour), and 7 with
the current capped attribution. The fix is therefore not optional — the
feature currently makes this case worse than shipping nothing.

Retain the dimensions of the most recently evicted entry and use them for
position 0 when no head marker survives. The most recently evicted entry
describes the span immediately preceding the oldest survivor, which is exactly
what the leading retained span needs. An equivalent alternative is to evict an
interior entry instead of the front one, so the entry describing the window's
head is never the one dropped. Either keeps the cap's bound intact; neither
rewrites a recorded entry's attributes.

### D2'''' — Make the cap test discriminate (4254f3a66c1c3f5e)

The test added for this exact regression passes with no segments at all and
also passes against round 5's buggy implementation — its fixture is too small
to wrap the ring, so both implementations produce identical segment lists, and
its mixing detector finds nothing to detect.

Rebuild it so that removing the fix makes it fail:

- Put detectable content (a scroll-region + bottom-bar phase, like the working
  apt fixture) before the storm, and keep the storm's own bytes small enough
  that the earlier phase remains on the replayed grid.
- Assert the discrimination premise inside the test: replay the same bytes
  with no segments and with full uncapped attribution, and require that the
  no-segment case mixes rows while the full case does not. If that premise
  ever stops holding, the test fails instead of passing vacuously.
- Size the ring so it actually wraps, exercising cap eviction and retained-
  window pruning together, and assert the head segment's dimensions.

This is the sixth consecutive round in which a test that could not fail was
found. Treat "demonstrate it fails without the fix" as a hard gate on every
test written here, and record the demonstration in each test's comment.

### D3'''' — Oversize resume must not freeze a pane (46c29c2c65970d26)

Reviewers disagree on reachability: one holds that the visibility flag is
already latched so the pane stays detached indefinitely, the other that a
hide→show cycle retries and that the trigger needs an encoded snapshot larger
than the ring can produce. Settle reachability first — determine whether the
visibility controller can re-drive a resume after an oversize refusal — then
either fix the state machine so an oversize refusal is recoverable, or record
why it cannot occur, with the reasoning in the code rather than in a review
file.

### D4'''' — Prompt marks across the split (0bed3c30e41e2389, d139e51d1c8d03c8)

Command text for OSC 133 B marks is captured only while the bypass is active,
so marks landing in the split's non-bypass prefix lose their text, and the
prefix's real scrollback is released before anything can recover it. Fold
labels then come out empty or show an unrelated line. Capture the text for the
whole snapshot replay, not only for its bypassed portion.

The split's only test cannot see this, nor can it see the bookkeeping the
split introduced: its prefix is shorter than the viewport, so the scrollback
fold-in path never runs, and it compares only the viewport and cursor.
Strengthen it to scroll the prefix and to compare eviction totals and mark
lists, matching the granularity the equivalent whole-drain test already uses.

### D5'''' — Split gate considers the prefix (e519916efd5fdc42)

The split engages on suffix size alone, so a payload that is almost entirely
prefix still pays a full first pass, discards it, and triggers a second full
replay in the background — roughly doubling the work. Gate on the prefix being
cheap (or the suffix dominating), and add a bench arm for the large-prefix
shape so the regression is visible.

### D6'''' — Cost budget and domain alignment (02bb52aaff9638e5, 6cefb1dd16c126b6)

Per-segment limits bound one segment but not their sum; add a cumulative
budget at decode. Separately, the daemon accepts dimension products the client
rejects as malformed, so a legitimate pane can produce snapshots its own peer
discards — apply the same product constraint where dimensions are accepted.

### D7'''' — Verification honesty (004fe3021b5d0c15)

VERIFICATION.md currently claims TS-7 covers FR2/FR3 (it does not, per D2'''')
and judges NFR1 against a one-second ceiling that SPEC does not state. Correct
the coverage claim, and present the measured numbers as the NFR1 evidence
without inventing a threshold. The storm-shape figure (roughly 235-332 ms
against a pre-feature ~8 ms) is a real remaining cost: record it plainly and
leave the accept-or-not decision to the verify phase rather than resolving it
by rewriting the criterion.
