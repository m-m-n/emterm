# Task Plan: task0001 — Confirm and fix replay coordinate drift behind post-switch render corruption

window/tab switch is root-caused (explicitly confirming or refuting that it

## Design

### Phase 1 — Investigation (gate)

1. Reproduce the reported symptom class in a test: synthesize a recording of
   a full-screen TUI-style application (cursor-addressed line rewrites, like
   Claude Code's status/input area) interleaved with a row-count change, then
   snapshot-replay it into a fixed-size core (reuse the synthesis approach in
   `tmp/apt-progress-bar-regression-2026-07-09.md`, PROBE D — the report
   contains ready-to-adapt test code; note the report lives in the main
   working tree and is gitignored).
2. Verdict: if the mixed-line symptom reproduces via the resize-interleaving
   mechanism and no alternative mechanism is found in the switch path, record
   "same root cause" in the completion report. Otherwise investigate the
   actual cause (candidate areas: snapshot assembly, off-thread replay swap,
   scrollback filter) and record the divergence as a plan deviation before
   fixing that instead.

### Phase 2 — Fix (per IMPLEMENTATION.md D1/D2)

- Daemon side: on pane resize, append an in-band resize marker (encoding per
  D2 constraints) carrying the new dimensions into the scrollback recording.
- Replay side: when the replay consumer encounters a marker, resize the
  replay core to the marker's dimensions before feeding subsequent bytes, so
  every byte is interpreted under the row count it was produced for. After
  replay, the core ends at the current pane size (final resize to current
  dimensions if the last marker differs).
- Compatibility: a replay consumer that does not understand markers must not
  render them (degrade to current behavior); a marker-free recording must
  replay exactly as today.

- [ ] AC-1: A test synthesizing a resize-interleaved recording (apt-style

- [ ] AC-2: A test synthesizing a TUI-style cursor-addressed redraw recording

- [ ] AC-3: A resize-free recording replays to a grid identical with and
      without the fix (byte-path regression guard: markers absent → behavior
      unchanged).
- [ ] AC-4: A recording containing markers replayed through the full snapshot
      pipeline (write filter → snapshot assembly → replay) never renders
      marker bytes as visible cells.
- [ ] AC-5: All existing Rust `--lib` tests pass single-threaded, and the
      CLI-only feature check passes.
- [ ] AC-6: The completion report states the investigation verdict: whether
      the reported Claude Code symptom shares the PROBE D root cause, with

## Test Notes

- AC-1/AC-2/AC-3/AC-4 are unit tests in the mux test modules
  (`pty_spawn.rs` tests hosted the prior probes); AC-2's synthesis mimics a
  cursor-addressed TUI (fixed-row rewrites via cursor positioning) rather
  than apt's scroll-region pattern, covering the reported symptom shape.
- Replay tests are order-sensitive under parallelism — run with
  `--test-threads=1` (already the approved test command).
- TDD awkwardness: the intermittent on-device symptom itself cannot be
  reproduced deterministically; the tests target the mechanism, and final
  on-device confirmation is the user's manual step (VERIFICATION.md).
