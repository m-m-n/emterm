# Task Plan: task0006 — Make intermediate segment resizes cheap (round 5 rework)

## Goal

Replaying a segment-bearing snapshot costs about what a segment-free one
costs, so neither a tight marker cap nor a bypass downgrade is needed — which
removes both regressions round 5 introduced (whole-window drift from cap
merging, and the ~25x slower ordinary window switch) at their shared source.

## Requirements

FR2, FR3, NFR1, NFR2, NFR3

## Scope

- `crates/term_core/src/reflow.rs` — a resize path that sets the coordinate
  system without re-wrapping retained scrollback, if that is where it belongs
- `crates/term_core/src/bench.rs` — bench the axis that actually costs

## Design

### D1''' — The shared root: per-segment full reflow (986a3881b2b97a16, abb36fa1ad4c89ea)

Measured at the shipping scrollback default with a 0.95 MiB payload: a
segment-free replay takes ~7 ms; a single segment whose dimensions differ from
the target takes ~220 ms; 16 segments take ~239 ms. The dominant cost is not
the number of segments but the fact that any dimension change triggers a
content-preserving reflow of the whole retained scrollback.

Everything round 5 did to contain that cost caused a regression:

- Capping recorded markers at 16 made the cap's merge chain the oldest
  boundary back to offset 0, so after a drag of more than 16 steps the entire
  retained window replays at one mid-drag size — the original PROBE D drift,
  reintroduced.
- Downgrading the snapshot bypass whenever a segment resizes moved a ~137 ms
  rebuild from a background second pass to in front of the swap, and it fires
  on ordinary switches because the daemon's spawn-size head marker differs
  from the GUI grid until roughly 2 MiB of output has evicted it.

Attack the cost instead. An intermediate segment's resize only needs to
establish the coordinate system for the bytes that follow it; re-wrapping
retained scrollback at that moment is wasted work because the next resize —
and ultimately the restore to the caller's target size — re-wraps it again.
Only the final state must be fully consistent. Introduce a resize path for
mid-replay use that updates the coordinate system without re-wrapping retained
scrollback, and let the final restore-to-target do the one real reflow.

Verify equivalence, do not assume it: the grid and cursor after a
cheap-intermediate replay must match the current full-reflow-per-segment
result for the same input. Where they cannot match, prefer correctness and
state the exception.

Once intermediate resizes are cheap:

- The marker cap no longer needs to be tight, so raise or remove it and
  correspondingly retire the merge rule that damages attribution (FR2
  regression closed). If a cap remains, its merge must never move a boundary
  across bytes already recorded.
- The bypass downgrade no longer needs to fire on every dimension change
  (NFR1 regression closed). Keep whatever downgrade is genuinely required for
  correctness — round 4 established that a reflow against the intentionally
  empty bypass scrollback diverges from the synchronous path — but scope it to
  the cases that actually reflow scrollback.

### D2''' — Validate segment offsets at the wire boundary (58db33c799bedf87)

Dimensions are clamped on decode but offsets are not, so a frame whose first
offset is non-zero silently drops the payload prefix and a non-monotonic table
silently drops ranges. Validate offsets where the dimensions are already
validated: first offset zero, non-decreasing, within the content. A violation
is malformed, not content.

### D3''' — Wire the typed decode result (b45fb09344067621)

`DecodedSnapshotPayload::Malformed` exists and the protocol docs state the GUI
uses it to skip a corrupt frame, but the GUI still calls the tuple wrapper,
which maps malformed to empty content — blanking the pane. Use the typed
result and skip the frame, leaving the current display intact.

### D4''' — Bound the decoder to the producer (bfebad60b3862d3e)

The decoder accepts far more segments than any legitimate producer emits.
Align the limit with the producer's bound so a compact hostile frame cannot
buy a large amount of replay work.

### D5''' — Dimension budget (1227fc04fb9368d0)

Clamping to 4096x4096 still admits a single segment that allocates on the
order of half a gigabyte. Enforce a total-cell or byte budget for a snapshot
and reject frames exceeding it, rather than clamping hostile values to another
dangerous size.

### D6''' — Oversize snapshots (89b58cd82d7aa713, c1605e6978ee5e48)

The visibility-resume path detects an oversize encoded snapshot, logs, and
enqueues it anyway; the codec then rejects it and the connection loop ends.
The reattach path instead discards segments and degrades to dimension-blind
output framing. Neither is acceptable: make the size policy enforceable at
every producer, and on oversize either preserve segments across frames or fail
recoverably without changing replay semantics.

### D7''' — Pending-run attribution (fd379025e1900e9f)

The write filter's carried-over dimensions are cleared only when the pending
buffer empties, so after a partial drain the bytes that remain (which came
from the current read) stay attributed to an older read's dimensions. Track
the dimensions of the run actually held.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Replay of a snapshot containing dimension changes costs
      approximately what a segment-free replay of the same payload costs — a
      bench asserts a stated bound on the ratio, and it runs in the normal
      verification flow (not `#[ignore]`d, or explicitly invoked from
      VERIFICATION.md).
- [ ] AC-2: The bench measures the axis that actually costs: segment-free vs
      one dimension-differing segment, in addition to segment count.
- [ ] AC-3: A resize sequence longer than any recorded-marker cap replays with
      zero cross-line mixing — driven end to end through the ring, snapshot
      assembly, and replay, using the same mixing detector the existing TUI
      test uses.
- [ ] AC-4: An ordinary window switch (daemon spawn-size head marker differing
      from the GUI grid, no resize storm) is not measurably slower than a
      segment-free replay.
- [ ] AC-5: Grid and cursor after replay with cheap intermediate resizes match
      the full-reflow-per-segment result for the same input, across the
      existing resize-spanning fixtures.
- [ ] AC-6: A frame whose segment offsets are non-zero-leading, non-monotonic,
      or out of range is rejected as malformed rather than silently dropping
      payload.
- [ ] AC-7: A malformed frame leaves the displayed pane unchanged (no blanking)
      and is logged.
- [ ] AC-8: The decoder rejects segment counts above the producer's legitimate
      bound.
- [ ] AC-9: A snapshot whose segments would exceed the dimension budget is
      rejected before any allocation.
- [ ] AC-10: No producer enqueues a snapshot the codec will reject; the
      oversize path either preserves segments or fails without changing replay
      semantics.
- [ ] AC-11: Bytes remaining in the write filter after a partial drain are
      attributed to the dimensions of the read that produced them.
- [ ] AC-12: Existing Rust `--lib` tests pass single-threaded apart from the 7
      failures already present on base commit
      a8d4bed2df5e2f41f524bd0c1ff59fb07f76f025; CLI-only check passes.
- [ ] AC-13: VERIFICATION.md records the measured switch-latency numbers so
      NFR1 is judged on measurement rather than on a bench whose bound is never
      approached.
