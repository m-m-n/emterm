# Task Plan: task0004 — Carry replay dimensions out-of-band (round 3 rework)

## Goal

Replay learns which dimensions applied to which bytes from a structured field
delivered alongside the snapshot payload, never by pattern-matching the
payload itself. The forgery class disappears because no byte sequence is
interpreted as control; the attribution bugs the byte representation forced
(coalescing, correction markers, consumer pollution) disappear with it.

## Requirements

FR2, FR3, NFR1, NFR2, NFR3

## Scope

### Files to Modify

- `crates/term_core/src/terminal_core.rs` — replay accepts segments as a

- `src-tauri/src/mux/scrollback_filter.rs` — no marker stripping needed on the

- `src-tauri/src/tabs.rs` — pass segments into replay; honor the replay

## Design

### D1' — Dimensions travel beside the payload, not inside it

`dim_markers` already records `(offset, cols, rows)` structurally. Today that
structure is flattened into marker bytes at `read_all()` and re-parsed by
scanning at replay. Every forgery path found across rounds 1-3 exists because
the replay side cannot distinguish daemon-authored bytes from child-authored
ones (round 3: 95fb7c115b0b64da, 4a22bd439fcdaf56, d4a83d5403bf1d7c).

Carry the segment list as a separate field on the snapshot message and have
replay take it as a parameter: for each segment, resize to its dimensions,
then feed that byte range. Consequences that fall out for free:

- No byte sequence in the payload can affect dimensions — the forgery class is
  closed structurally, not by filtering (rounds 1-3 spent three attempts on
  filtering and each left a reconstruction path).
- The write-path marker strip becomes unnecessary; PTY bytes are just bytes.
- `read_all()` returns raw bytes again, so `mux-read` stops receiving injected
  protocol remnants (ef69658e6e4d0b05) and the double copy goes away
  (c84c751810cbd8cb).

Wire compatibility: a daemon and GUI of differing versions may be paired.
Decide and document the behavior when the segment field is absent (an older
daemon): replay must degrade to today's single-dimension behavior rather than
misinterpreting anything.

### D2' — Fix the attribution rules the byte representation distorted

- **Coalescing (ab54fae335086db3, 981230284d7d3273)**: merging must never move
  a dimension boundary across bytes that were already recorded. Either merge
  only at an identical offset, or advance the merged entry's offset so
  intervening content stays under the dimensions it was produced with. Bound
  marker growth by a mechanism that does not depend on how many redraw bytes a
  TUI emits per resize step.
- **Correction entries (9d4f7176af1b264e)**: an entry written to correct
  attribution must not be merged into or overwritten by an authoritative
  entry; the two roles need distinct semantics.
- **Publication order (5ac1a5171a1e6a58)**: dimensions must be visible to the
  reader before the child can produce output at the new size.
- **Atomicity (ae43417cee647afa)**: a reader must never observe a dimension
  pair that never existed.
- **Domain (b546481e9c2fcc85)**: pane creation validates dimensions against
  the same domain every other producer uses.

### D3' — Replay result contract (b235e4dbc61cc4ba)

The snapshot-bypass downgrade makes the populated-scrollback contract
payload-dependent while its only consumer assumes it unconditionally, so a
history that grew rows gets prepended twice. Make the result state which mode
ran and have the consumer branch on it, or preserve the invariant.

### D4' — Frame threshold (ea222e74bb0a046c)

Derive the single-frame threshold from the protocol's actual payload limit so
snapshots that fit in one frame are not routed through the chunked path.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: No child-process output can change replay dimensions. Tests cover:
      a bare marker-shaped byte sequence, one split across two filter batches,
      one split at a lone-trailing-ESC boundary, one nested in a non-SIXEL DCS,
      and one formed by concatenation after a strip pass. With D1' these should
      all pass trivially — assert that dimensions come only from the segment
      field.
- [ ] AC-2: Content recorded under one set of dimensions is always replayed
      under those dimensions, including when a resize follows within the
      coalescing window — a test with resize → under-threshold output → resize
      asserts the intervening output keeps its original dimensions.
- [ ] AC-3: A correction entry for bytes read before a resize survives
      subsequent recording — the three-step sequence (resize, stale chunk,
      fresh chunk) leaves the stale chunk attributed to the old dimensions.
- [ ] AC-4: Dimensions are observable to the reader before any output produced
      at the new size can be read.
- [ ] AC-5: A concurrent reader never observes a dimension pair that was never
      set.
- [ ] AC-6: Pane creation with out-of-domain dimensions is rejected or clamped
      through the same path a resize uses.
- [ ] AC-7: A row-growing payload above the off-thread threshold does not
      duplicate scrollback history after the swap — asserted at the consumer,
      not only inside term_core.
- [ ] AC-8: A resize storm whose per-step redraw exceeds the old 8 KiB
      threshold does not leave one full reflow per step in later replays.
- [ ] AC-9: `mux-read` output never contains protocol remnants, including when
      its tail cut falls where a marker used to be synthesized.
- [ ] AC-10: A snapshot that fits within the protocol's single-frame payload
      limit is delivered in one frame.
- [ ] AC-11: Replay against a snapshot with no segment field behaves as
      single-dimension replay (older-daemon compatibility), documented.
- [ ] AC-12: Existing Rust `--lib` tests pass single-threaded apart from the 7
      failures already present on base commit
      a8d4bed2df5e2f41f524bd0c1ff59fb07f76f025; CLI-only check passes.
