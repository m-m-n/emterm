# Task Plan: task0008 — Leave the capped gap unattributed; negotiate pane dimensions (round 7 rework)

## Goal

A resize sequence of any length replays with no more cross-line mixing than an
uncapped one, and the dimensions the daemon accepts are the dimensions the
client renders at.

## Design

### D1''''' — Do not attribute what was evicted (01f91fe698ceb287)

Round 7 kept the dimensions of the *most recently* evicted marker and applied
them at position 0. That is right only when exactly one entry was evicted;
with N evictions the gap spans everything those N markers described, and
applying the last one's dimensions to the whole gap misattributes its largest
(oldest) part.

The round-7 reviewer measured the alternative and it was clean: when two or
more entries have been evicted, **do not synthesize a head segment at all** —
leave the gap unattributed so it replays at the core's current (target)
dimensions, and keep every surviving marker at its true position. Across every
shape tested (25/28/32/52 markers, two storm patterns) this produced zero
mixed rows, matching full uncapped attribution. Keep the existing
single-eviction behaviour, which measured exactly equal to full attribution.

The reviewer also measured the other obvious variant — using the *oldest*
evicted marker's dimensions — and it was worse (3 and 8 mixed rows). Do not
choose it without re-measuring.

This requires relaxing the assumption that a segment list starts at offset 0:
snapshot assembly must shift a non-zero-leading list by the clear prefix
rather than asserting the leading offset away.

### D2''''' — Make the cap test cover the failure region (part of 01f91fe698ceb287)

The current test pins eviction to exactly one, so it cannot reach the shapes
that break. Parameterize it over eviction counts (one, a few, many) and, at
each, assert both that the capped result matches full uncapped attribution
*and* that it is no worse than replaying with no segments at all. The second
assertion is what catches "worse than not fixing"; the first alone is
vacuously true once they agree.

Round 7 satisfied the "test must fail without its fix" gate for the first
time. Keep that discipline: every test here must be shown to fail with its fix
reverted, noted in the test's comment.

### D3''''' — One dimension SSOT end to end (1d1b6b6297e3b6a0)

The daemon now clamps a pane's dimensions into the wire domain, but the client
already resized its own core to the unclamped value and nothing tells it
otherwise. Live output then comes from a PTY of one size and is interpreted by
a grid of another — the drift this whole feature exists to remove.

Make the accepted dimensions authoritative in one place: either clamp before
both the client's core resize and the daemon's PTY creation, or have the
daemon report the dimensions it accepted so the client adopts them. Pane
creation must resize the PTY it was given to the value it records, rather than
recording a value the PTY does not have.

### D4''''' — Producer and decoder budgets agree (4bc6ab813edd6d22)

Per-segment clamping alone lets the daemon assemble a snapshot whose segments
sum past the decoder's cumulative budget; the client then drops every such
frame as malformed and the pane keeps showing stale content. Derive one bound
from the other so a snapshot the daemon can build is always one the decoder
accepts, and extend the round-trip test to the largest segment list the daemon
can actually produce, not a single segment.

### D5''''' — Guard the split gate in the normal test run (7c70216c5a5d5c24, a4f4e36fef377d05)

The prefix gate's only check lives in an ignored bench, so deleting the gate
leaves the suite green. Move the deterministic assertion into the normal test
module and pin both sides of the boundary. Separately, the gate is byte-only,
so a payload that is 94% prefix still splits and pays the work twice; require
the suffix to actually dominate, and bound the prefix's segment count, then
add a bench arm at the daemon's marker cap with a just-over-threshold prefix.

### D6''''' — Snapshot chunk contract (426db84173e6b792)

`ResumeWithSnapshot` now carries a wire-encoded envelope, but its
documentation still describes it as bytes to send, with no statement that it
must go as a snapshot-kind chunk. A future caller following the doc would
render the envelope as terminal text. Encode the requirement in the type if
practical, otherwise state it in the variant's documentation and cross-
reference the sibling path that already learned this lesson.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: For eviction counts of one, several, and many, a capped replay
      mixes no more rows than full uncapped attribution, and never more than
      replaying with no segments at all.
- [ ] AC-2: The cap test is parameterized over those eviction counts and fails
      when D1''''' is reverted.
- [ ] AC-3: Snapshot assembly handles a segment list whose first entry is not
      at offset 0.
- [ ] AC-4: The dimensions the daemon accepts are the dimensions the client
      renders at — a test drives a resize the wire domain must clamp and
      asserts both ends agree afterwards.
- [ ] AC-5: Pane creation records only dimensions the underlying PTY actually
      has.
- [ ] AC-6: Any snapshot the daemon can assemble decodes successfully — a
      round-trip test uses the largest segment list the daemon can produce.
- [ ] AC-7: Deleting the split's prefix gate makes a normal (non-ignored) test
      fail; both sides of the boundary are pinned.
- [ ] AC-8: A payload that is overwhelmingly prefix does not split; a bench arm
      covers the daemon-cap-with-just-over-threshold-prefix shape.

      by the type or stated in its documentation.
