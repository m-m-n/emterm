## G2 — the continuous-traffic test can hang the whole suite (high, `bc0e5ae9c626fb31`)

`connection.rs:2355-2356`: `let _ = flood_task.await;` sits **before**
`conn_task.abort();`, and `client_writer` was moved into the flood task so the main
body cannot drop it. The flood task only checks its stop flag after an in-flight
`send()` completes; under the test's steady state that send is parked, and the read
loop stops draining once it sees one snapshot — so the server blocks in
`framed.flush().await`, never reads again, and the send never completes. `cargo test`
has no per-test timeout, so this hangs CI. The sibling test avoids it with
`drop(client)` → `abort()` → timeout-wrapped join. Fix the ordering and wrap the join
in a timeout.

## G3 — same-pane coalescing contradicts FR3's "ONLY permitted exception" (high, `329f746349f592e8`)

FR3 now says eviction of the oldest distinct-pane chunk when 8 distinct panes are
pending is the **ONLY** permitted exception, and that it "never applies to fewer than
`MAX_DEFERRED_ITEMS` DISTINCT panes". But `defer_chunk` replaces a queued same-pane
snapshot with a newer one at any queue length, discarding the earlier reply.

The behaviour is reasonable (a snapshot is self-contained; only the newest matters).
The text is what is wrong. Amend FR3 to describe the guarantee as "one snapshot per
pane, reflecting the newest request, is delivered" rather than a 1:1
request/reply correspondence, and list coalescing alongside eviction. Keep
`defer_chunk`'s doc consistent with it.

## G4 — the starvation guard stops at queue admission, not at delivery (high, `e6ac2a334424ebd7`)

`has_deferred_work` observes only the deferred queue and the reservation. Once a
snapshot is accepted into `pane_output_tx` — either immediately on a near-full
channel, or when a deferred item is flushed into it — both indicators go false while
the snapshot is still waiting for the drain arm to forward it. With continuously ready
client messages the biased first arm can then win indefinitely, starving both that
snapshot and all queued PTY output. The quota protects admission, not delivery.

Extend the signal to cover queued-but-unforwarded output (including the receiver
backlog is the obvious route), and add deterministic coverage for the
deferred-queue → channel → client transition under continuous client input.
