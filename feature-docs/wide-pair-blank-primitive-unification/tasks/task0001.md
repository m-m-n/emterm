# Task Plan: task0001 — Unify wide-pair partner blanking and the range-erase edge repair

## Goal

`term_core` has exactly one wide-pair partner-blanking primitive (self-guarding,
on the grid-cell mutation base layer) and exactly one range-erase edge-repair
chokepoint, with the print path, ICH/DCH, and the five range-erase handlers all
converged on them — with zero observable behavior change.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2, NFR3

## Design

Both component contracts are pinned in IMPLEMENTATION.md "Shared Components" —
implement against them; do not restate or reinterpret them here.

**Primitive behavior flow (FR1/FR2)**:

1. Resolve `(col, row)` to a cell; unresolvable → return with no mutation.
2. Read the cell's current width; width not 0 and not 2 → return with no
   mutation.
3. Rewrite the cell to a width-1 space, preserving fg/bg/flags/hyperlink.
4. Remove the overflow-table entry for that position and, when one was
   removed, the matching reverse-index entry.
5. Mark the row dirty.

The two prior implementations are output-equivalent (SPEC "Assumptions"); the
unified primitive adopts `blank_wide_pair_split`'s self-guarding contract.
Whether to keep `blank_wide_pair_partner`'s empty-overflow-table fast check is
an implementation detail — outcomes must match the contract either way.

**Migration map (FR3)** — every current call target moves to the primitive:

| Current call site | Count | Migrates to |
|-------------------|-------|-------------|
| `print_handler.rs` `blank_orphaned_neighbor_before_overwrite` → `blank_wide_pair_partner` | 2 | primitive (direct) |
| `print_handler.rs` `blank_orphaned_base_before_placeholder` → `blank_wide_pair_partner` | 1 | primitive (direct) |
| `csi_edit.rs` ICH repairs → `blank_wide_pair_split` | 3 | primitive (direct) |
| `csi_edit.rs` DCH repairs → `blank_wide_pair_split` | 3 | primitive (direct) |
| `csi_screen.rs` ECH / EL 0 / EL 1 / ED 0 / ED 1 inline capture-then-repair | 5 copies | chokepoint (which calls the primitive) |

`blank_wide_pair_partner`'s callers currently pre-check the neighbor's width
themselves; after migration, caller-side width checks may remain only as
call-avoidance optimizations — correctness must not depend on them (FR2).

**Chokepoint call-site shape (FR4)**: each of the five handlers computes its
`(row, start, end)` exactly as today, then makes a single chokepoint call in
place of the current capture + range clear + two conditional blanks. Handler
structure around the range stays as-is: ED 0 still clears the rows below the
cursor row afterwards, ED 1 still clears the rows above first (those full rows
go through `clear_line`, unchanged). ECH's `end <= start` early-return case is
absorbed by the chokepoint's empty-range branch.

**Full-row paths (FR5)**: `clear_line`, `clear_line_range` and their full-row
callers (EL 2, ED 2, ED 0/1's whole-row loops) are not modified and gain no
partner behavior. The constraint comment currently at
`handle_erase_characters` (`csi_screen.rs:140-146`) is preserved by restating
it at the chokepoint: partner repair is never folded into `clear_line_range`
because its full-row callers must not gain partner behavior.

**ASCII fast path (NFR1)**: the `old_width != 1` gates at
`handle_print_ascii`, `write_grapheme_to_grid`, and
`relocate_widened_base_via_wrap` stay exactly where they are; the width-1
common case performs no call into the new primitive and gains no new memory
access or branch.

**Public surface (NFR3)**: no `lib.rs` change; every new item is `pub(crate)`
or narrower.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A self-guarding partner-blanking primitive exists in
      `terminal_cells.rs`: applied to a width-0 or width-2 cell, it produces a
      width-1 space with fg/bg/flags/hyperlink preserved, removes the
      overflow-table entry and its reverse-index entry, and marks the row
      dirty (TS-2).
- [ ] AC-2: The primitive is a strict no-op (no mutation, no panic) on a
      width-1 cell and on an out-of-bounds / unresolvable position (TS-3).
- [ ] AC-3: `print_handler.rs` no longer defines `blank_wide_pair_partner`;
      `blank_orphaned_neighbor_before_overwrite` and
      `blank_orphaned_base_before_placeholder` call the primitive, and all
      existing print-path wide-pair tests pass unchanged (TS-1).
- [ ] AC-4: `csi_edit.rs` no longer defines `blank_wide_pair_split`; all six
      ICH/DCH repair call sites call the primitive directly, and all existing
      ICH/DCH wide-pair tests pass unchanged (TS-1).
- [ ] AC-5: The five range-erase call sites in `csi_screen.rs` (ECH, EL 0/1,
      ED 0/1) each make a single call to the shared chokepoint; no inline
      capture-then-repair copy remains; the FR5 constraint comment survives at
      the chokepoint (TS-1).
- [ ] AC-6: `clear_line`, `clear_line_range`, EL 2 and ED 2 are
      behavior-unchanged: a full-row erase over a row containing wide pairs
      still produces plain BCE fill with no attribute-preserving blank (TS-4).
- [ ] AC-7: The three `old_width != 1` gates remain at their print-path call
      sites; the full term_core `--lib` suite passes with zero assertion
      changes to existing tests; the workspace build check passes; `lib.rs`
      is untouched (TS-1; NFR1/NFR2/NFR3).

## Test Notes

- TDD order: write the primitive's direct unit tests first (AC-1/AC-2 → TS-2,
  TS-3) covering width-2 blanking, width-0 blanking, attribute preservation,
  overflow + reverse-index removal, dirty marking, width-1 no-op, and
  out-of-bounds no-op. Then implement the primitive, then migrate callers one
  module at a time, running the term_core suite after each migration.
- TS-1 (AC-3..AC-5, AC-7) is carried by the existing regression net: the
  wide-pair cleanup tests already in `csi_edit.rs`, `csi_screen.rs`, and
  `print_handler/tests.rs`. Their assertions must not be edited; comment-only
  updates are permitted.
- TS-4 (AC-6): check whether an existing EL 2 / ED 2 test already pins the
  wide-pair full-row case; add one only if none does.
- NFR1 has no automated assertion: AC-7's gate check is verified by diff
  inspection; the opt-in bench `snapshot_replay_bench_2mib_seq` remains
  available as a manual spot-check (TS-5, feature-level manual verification —
  not part of this task's test suite).
- Edge cases worth pinning if not already covered: chokepoint repair at
  `end == column count` (relies on the primitive's out-of-bounds self-guard),
  and the empty-range ECH case (count clamped to zero).

## Out of Scope

- Public API or `lib.rs` changes; any visibility wider than `pub(crate)`.
- Performance work beyond retaining the existing gates; no new benches, no
  automated perf assertions.
- Refactoring the ICH/DCH edge-condition logic itself — only the blank-call
  target changes.
- Modifying existing test assertions (NFR2 forbids it).
