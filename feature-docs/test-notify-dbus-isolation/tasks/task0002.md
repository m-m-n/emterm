# Task Plan: task0002 — NotifyRustSink with injected worker functions; worker_thread tests on fakes for both OSes

## Goal

`NotifyRustSink` can be constructed with injected worker functions (unix:
capability query and send; Windows: send), the Windows worker gains a send
injection point, and the three `worker_thread` tests build the sink with
recording fakes on both OSes and verify the fake receives what was sent.
`NotifyRustSink::new()` keeps the production behavior.

## Requirements

FR3, FR4, FR5, FR6, FR7, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify
- `src-tauri/src/callbacks.rs` — injection constructor, NotifyRustSink::new delegating to it, the Windows notify_worker send injection point, the worker start taking injected functions, and the related documentation comments
- `src-tauri/src/callbacks/tests.rs` — worker_thread module: the three sink tests switch to the injection constructor with fakes and gain reach assertions; fakes and a bounded-wait helper available on both OSes
- `test-docs/notification-worker-thread/task0001.tests.yaml` — only if a worker_thread test is renamed (FR7); otherwise untouched

## Design

Cross-task contracts used here: `NotificationSink` trait, `NotifyRustSink::new()`
and `NotifyRustSink` type identity (IMPLEMENTATION.md Shared Components);
decision D2 (IMPLEMENTATION.md Cross-task Design Decisions).

### Injection constructor (private to the callbacks module)

- **Inputs, per platform**:
  - unix — a capability-query function (returns a capability list or an error
    with displayable text) and a send function (summary and body in, success or
    an error with displayable text out). Same shape as the existing unix
    `notify_worker` injection points.
  - Windows — a send function of the same shape.
- **Preconditions**: the functions can be moved to the worker thread and own
  everything they capture, since they run there for the worker's whole life.
- **Postconditions**: identical to `NotifyRustSink::new()` except for the
  injected functions — queue capacity `NOTIFY_QUEUE_CAPACITY`, worker started
  at construction (never lazily), the same worker thread name, send that only
  enqueues, and the same bounded drop (`NOTIFY_WORKER_JOIN_TIMEOUT`).
- **Visibility**: not exported beyond the callbacks module (its child test
  module can reach it).

### `NotifyRustSink::new()`

- Delegates to the injection constructor with notify-rust's capability query
  and send on unix, and notify-rust's send on Windows.
- The production notify-rust function values appear in exactly one place per
  platform. Signature, visibility and the `Default` delegation are unchanged.

### Windows worker (`notify_worker`, non-unix)

- Gains a send injection point; its body no longer calls notify-rust
  directly.
- Per received notification:
  1. compute the redacted rendering from the received title and body;
  2. call the injected send with the received title and body, unchanged;
  3. on success, emit the debug-level record "notify-rust dispatched:
     {redacted}"; on failure, the warn-level record "notify-rust failed: {e}".
- No capability query and no escape are added (FR4).

### Worker start (`spawn_notify_worker`)

- Takes the per-platform injected functions and starts the worker with them.
  Thread name and the panic on thread-spawn failure are unchanged.

### Unix worker (`notify_worker`, unix)

- Signature and body unchanged. The existing `worker_injection_points` tests
  keep driving it directly.

### worker_thread test support (both OSes)

- **Recording fake send**: thread-safe, shared between the test body and the
  worker, records each (summary, body) pair in call order, always reports
  success. The existing recorder inside `worker_injection_points` is
  unix-only, so the `worker_thread` module needs one that compiles on both
  OSes.
- **Fake capability query (unix only)**: never touches D-Bus. Its result does
  not affect these tests, because their titles and bodies carry no markup
  metacharacter.
- **Bounded wait**: polls the recorder until a condition holds or a generous
  deadline (at least 2 s) passes.
- **Per-platform construction helper**: builds the sink through the
  injection constructor with the fakes, so each test body stays
  platform-neutral.

### worker_thread tests

The three tests keep their names, so
`test-docs/notification-worker-thread/task0001.tests.yaml` needs no update.
The FR7 record update (AC-7) applies only if a rename turns out to be
unavoidable.

| Test | Flow | Expected |
|------|------|----------|
| `sink_send_never_blocks_the_caller_even_past_queue_capacity` (TS-3) | Build with fakes → send `NOTIFY_QUEUE_CAPACITY` × 4 times, timing only the send loop → bounded wait on the recorder | Send loop under 100 ms; recorder holds at least one notification |
| `dropping_the_sink_after_sending_returns_within_the_shutdown_deadline` (TS-4) | Build with fakes → send three → time the drop → bounded wait on the recorder | Drop under 2 s; recorder holds exactly the three sent pairs in send order |
| `dropping_a_freshly_constructed_sink_with_no_notifications_returns_within_the_shutdown_deadline` (TS-5) | Build with fakes → time the drop | Drop under 2 s; recorder holds nothing |

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR3, FR5, FR6, TM-4; TS-3): `sink_send_never_blocks_the_caller_even_past_queue_capacity` builds the sink through the injection constructor with a recording fake send (and, on unix, a fake capability query); `NOTIFY_QUEUE_CAPACITY` × 4 sends complete in under 100 ms, and the recording fake receives at least one notification within the bounded wait.
- [ ] AC-2 (FR3, FR5, FR6; TS-4): `dropping_the_sink_after_sending_returns_within_the_shutdown_deadline` builds the sink the same way and sends three notifications; the drop returns in under 2 s, and the recording fake then receives exactly the three sent (title, body) pairs, in send order, within the bounded wait.
- [ ] AC-3 (FR3, FR5; TS-5): `dropping_a_freshly_constructed_sink_with_no_notifications_returns_within_the_shutdown_deadline` builds the sink the same way and drops it without sending; the drop returns in under 2 s and the recording fake has received nothing.
- [ ] AC-4 (FR3, NFR2, TM-1): `NotifyRustSink::new()` keeps its signature and visibility and delegates to the injection constructor with notify-rust's capability query and send on unix and notify-rust's send on Windows; queue capacity, join timeout and worker thread name are unchanged; the unix worker's order (redact → on-demand capability gate → escape → send) is unchanged (code review); the existing `worker_injection_points`, `notification_redaction`, `body_markup_escape` and `summary_markup_escape` tests pass without modification.
- [ ] AC-5 (FR4, NFR2, TM-2): The Windows `notify_worker` takes a send injection point and its body contains no direct notify-rust call; its success record is "notify-rust dispatched: {redacted}" with the redacted rendering computed from the received title and body, its failure record is "notify-rust failed: {e}", and it adds no capability query and no escape (code review plus the Windows-target check).
- [ ] AC-6 (NFR1, NFR3, NFR4, TM-4; TS-6): No test in `src-tauri/src/callbacks/tests.rs` constructs a `NotifyRustSink` through `new()` or `Default`; the full `--lib` test command passes; the default-features and `--no-default-features` cargo checks and the Windows-target check including tests pass.
- [ ] AC-7 (FR7; TS-8): If any `worker_thread` test is renamed, the matching `acceptance_tests[].tests` entries in `test-docs/notification-worker-thread/task0001.tests.yaml` carry the new names and each appears as a `<name>: test` line in the `--lib -- --list` output; if no test is renamed, the record is unchanged.

## Test Notes

- AC-1 to AC-3: switch each test to the injection constructor first — this is
  red (the constructor does not exist yet), then implement until green. The
  reach assertions in AC-1 and AC-2 also fail if the fake is not actually
  wired into the worker.
- TS-3: the worker drains the queue concurrently with the send burst, so the
  number of notifications the fake receives is not fixed; assert at least
  one (SPEC edge case).
- TS-4: measure the drop first, then wait on the recorder. The worker keeps
  draining items that were already queued after the sending side closes, so
  the three pairs arrive even if the drop's own bounded wait ends first; do
  not rely on drop timing (SPEC edge case).
- Windows tests are not executed on the Linux host; the Windows-target check
  including tests proves they compile (SPEC A7).
- No log capture; the Windows log records in AC-5 are confirmed by code
  review.
- Fakes hold no process-global state, so the tests stay safe under the
  default parallel test runner.

## Out of Scope

- A capability query or escape on Windows (FR4).
- Changing the unix `notify_worker` signature or logic.
- The App's sink selection.
- New tests that drive the Windows `notify_worker` directly.
- Changes to the bounded queue, the rate limiter or the log constants.
- Any crate-wide detection mechanism (FR6).
