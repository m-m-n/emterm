# GUI レンダリング CPU 使用率削減 - 要件定義書

## 1. 概要

### 1.1 背景

emterm GUI プロセスの CPU 使用率が高い（アイドル時 10〜15% / PTY 出力中 約80%）。
調査（`tmp/cpu-usage-investigation-2026-07-05.md`、2026-07-05 JST 実施）により、
以下の 3 つの確証原因が特定された。

1. ダーティ行スキップがデッド — `app.rs` の `dirty_rows_this_frame` がカーソル行を
   無条件 push するため、`window_host.rs` の「dirty 0 なら描画スキップ」早期リターンが
   一度も発火せず、あらゆる再描画トリガがフル描画になる
2. フル描画 = 全セル再処理 — 非空セルごと・毎フレームの swash シェイピング
   （shaped-run キャッシュ無し）、毎フレームの Vec/String ヒープ確保、毎フレームの
   `device.create_buffer` による instance バッファ新規生成
3. 60Hz 常時ポーリング — `ControlFlow::WaitUntil(now + 16ms)` を毎回再武装し、
   真の `ControlFlow::Wait` になる経路が無い。アイドルでも約 155 回/秒の起床

### 1.2 目的

上記 3 原因をすべて解消し、アイドル時・PTY 出力時の CPU 使用率を修正前より低減する。

### 1.3 スコープ

調査レポート 4 章の修正方針の全系統を対象とする。

- (a) Stage 1: ダーティ集合の正直化（ブロックカーソルのオーバーレイ化 + 無条件 push 削除）
- (a) Stage 2: render のダーティ行駆動化（行キャッシュ + 持続 instance バッファ）
- (c) `ControlFlow::Wait` + wakeup 駆動化（アイドル時ポーリング解消）
- 性能カウンタ（`EMTERM_RENDER_PERF=1` の env ゲート）の実装

対象外: mux daemon / attach クライアント、GPU 描画パス、グリフアトラス転送、
PTY 入力コアレス（いずれも調査でシロと判定済み）。

## 2. ビジネス要件

### 2.1 目標

ターミナルエミュレータとしての省電力・低負荷動作。アイドル時に CPU を消費しない
「行儀のよい」デスクトップアプリケーションであること。

### 2.2 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| emterm GUI 利用者 | Linux / Windows で emterm をターミナルとして常用するユーザー |

### 2.3 期待される効果

- アイドル時 CPU 使用率の大幅低減（描画フレームほぼゼロ + ポーリング起床解消）
- PTY 大量出力時の CPU 使用率低減（ダーティ行のみ再構築）
- ノート PC でのバッテリー消費低減

## 3. 機能要件

### 3.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | ダーティ集合の正直化 (Stage 1) | カーソル行の無条件 push を除去し、無変化フレームでダーティ集合が空になるようにする | 高 |
| F02 | ブロックカーソルのオーバーレイ化 | ブロックカーソルの描画をグリッドインスタンス焼き込みから egui オーバーレイ側へ移す | 高 |
| F03 | render のダーティ行駆動化 (Stage 2) | 行ごとの `Vec<CellInstance>` を CPU 側キャッシュとし、ダーティ行のみ再シェイプ・再構築する | 高 |
| F04 | 持続 instance バッファ | instance バッファを毎フレーム新規作成から持続バッファ + `write_buffer` 更新に変更する | 高 |
| F05 | `ControlFlow::Wait` + wakeup 駆動化 | アイドル時に真の `Wait` へ移行し、イベント駆動で起床する | 高 |
| F06 | 性能カウンタ | `EMTERM_RENDER_PERF=1` で描画フレーム数・再構築行数を warn レベル出力する | 中 |

### 3.2 機能詳細

#### F01: ダーティ集合の正直化 (Stage 1)

**説明**: `app.rs:3749` 付近の「カーソル行を無条件 `push_unique`」を削除する。
カーソル移動時（旧行 + 新行）・blink 位相反転時の条件付き push は残す。
これにより無変化フレームでダーティ集合が空になり、`window_host.rs:1391` の
描画スキップ早期リターンが機能する。

**ビジネスルール**:
- 無変化フレームではダーティ集合が空集合になること
- カーソル移動では旧行と新行がダーティになること
- blink 有効時は位相反転フレームのみカーソル行がダーティになること
- blink 無効時は位相由来の push が発生しないこと
- PTY 出力では出力行のみがダーティになること

#### F02: ブロックカーソルのオーバーレイ化

**説明**: ブロックカーソルは現在グリッドインスタンスに fg/bg 反転で焼き込まれている
（`render/mod.rs:659,713`）。これが「カーソル行常時ダーティ」の理由であるため、
アンダーライン/バーカーソルと同じ egui オーバーレイ側（`render/mod.rs:275`
`draw_cursor`）へ移す。セル矩形塗り + グリフ 1 個の反転色上描きで実現する。

**ビジネスルール**:
- 通常セル・wide 文字（2 セル幅）・絵文字・空セルで矩形が正しいこと
- スクロールバック表示中でカーソルが画面外なら描かないこと
- fold 行・画面端で矩形が壊れないこと

#### F03: render のダーティ行駆動化 (Stage 2)

**説明**: 行ごとの `Vec<CellInstance>` を CPU 側キャッシュとして持ち、ダーティ行だけ
再シェイプ・再構築する。クリーンな行はキャッシュを連結して使う。

**無効化規約**:
- スクロール → 全行ダーティ
- リサイズ・フォント変更 → キャッシュ全破棄
- 選択・ホバー・検索ハイライト変化 → 該当行ダーティ

**ビジネスルール**:
- 行キャッシュ経由の `CellInstance` 列は、フル再構築の列と完全一致すること（等価性）

#### F04: 持続 instance バッファ

**説明**: `terminal_grid_pass.rs:962-977` の毎フレーム `device.create_buffer` を、
持続バッファ + 必要時拡張 + `write_buffer` 更新に変更する。

**ビジネスルール**:
- バッファ成長ポリシーは純関数に切り出してテスト可能にすること

#### F05: `ControlFlow::Wait` + wakeup 駆動化

**説明**: `window_host.rs:2321,3229` の `about_to_wait` 末尾での
`ControlFlow::WaitUntil(now + 16ms)` 常時再武装をやめ、待つべきイベントが無い時は
真の `ControlFlow::Wait` に移行する。PTY 出力・入力イベント・blink タイマ等の
必要時のみ起床する。

**ビジネスルール**:
- カーソル blink 有効時は blink 周期での起床は許容する
- IME・PTY 出力・ユーザー入力への応答性を損なわないこと

#### F06: 性能カウンタ

**説明**: `EMTERM_RENDER_PERF=1`（`EMTERM_FONT_PERF` と同じ流儀の env ゲート）で
「描画フレーム数」「再構築行数」を warn レベルでログ出力する。

**ビジネスルール**:
- env 未設定時は計測・出力のオーバーヘッドが無いこと（リリースログは warn 以上のみ永続）

## 4. 非機能要件

### 4.1 パフォーマンス要件

- アイドル時・PTY 出力時の CPU 使用率が修正前より低減していること
  （測定: `/proc` サンプリング。調査レポート 6 章の再計測手順で前後比較）
- 数値の絶対目標は置かない（修正前比での低減を合格基準とする）

### 4.2 保守性要件

- ログ出力: 性能カウンタは warn レベル（リリースビルドで永続されるレベル）
- wgpu デバイス依存部分を除く CPU 側ロジックは `--lib` のユニットテストで固めること

### 4.3 互換性要件

- Linux / Windows 両対応（`#[cfg]` ゲートの規約に従う)
- CLI-only ビルド（`--no-default-features`）を壊さないこと

## 5. 制約条件

### 5.1 技術的制約

- ベンチマーク参照方針: 実装前に Alacritty（ダメージトラッキング）/ WezTerm
  （shaped line キャッシュ）の公式ドキュメント・issue で設計を裏取りする。
  コード転用は禁止、参照は公式ドキュメント・設定・issue/changelog に限定する
- wgpu デバイスが必要な部分はユニットテスト対象外とし、GPU 側は最終 verify の
  E2E・目視で確認する
- テスト実行: `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path
  src-tauri/Cargo.toml --lib`（`--bin emterm` は 0 件）。`tabs.rs` replay テスト
  混在時は `--test-threads=1`
- E2E・目視確認は TDD ループに入れず最終 verify でまとめて実行する

### 5.2 既知の制約

- TUI の行書き換えで選択ハイライトが残る既知の制約（対応保留中）を悪化させないこと

## 6. 想定される課題とリスク

| 課題 | 影響度 | 対応策 |
|------|--------|--------|
| カーソルオーバーレイ化による描画見た目の変化（反転色の再現） | 中 | カーソル座標・矩形のユニットテスト + 最終 verify での 3 形状 × blink 目視確認 |
| 行キャッシュの無効化漏れによる表示残像 | 高 | 等価性テスト + 無効化トリガーのマトリクステストで担保 |
| `ControlFlow::Wait` 化による入力・IME 応答性の劣化 | 中 | wakeup 経路を明示的に設計し、最終 verify で操作感を確認 |

## 7. 成功基準

### 7.1 受け入れ基準

- [ ] 無変化フレームでダーティ集合が空になり、描画スキップが機能する
- [ ] 行キャッシュ経由の `CellInstance` 列がフル再構築と完全一致する
- [ ] instance バッファの毎フレーム新規作成が解消される
- [ ] アイドル時に 60Hz ポーリング起床が発生しない（blink 起床は許容）
- [ ] `EMTERM_RENDER_PERF=1` で描画フレーム数・再構築行数が warn 出力される
- [ ] アイドル時・出力時の CPU 使用率が修正前より低減している
- [ ] カーソル 3 形状 × blink on/off、CJK・絵文字、選択・検索・ホバー、TUI で表示退行が無い

### 7.2 KPI

| 指標 | 目標値 | 測定方法 |
|------|--------|----------|
| アイドル時 CPU% | 修正前（10〜15%）より低減 | `/proc` サンプリング（レポート 6 章の手順） |
| PTY 出力中 CPU% | 修正前（約80%）より低減 | 同上（`seq` 大量出力シナリオ） |
| アイドル 10 秒の描画フレーム数 | blink 回数程度 | `EMTERM_RENDER_PERF=1` カウンタ |
| 出力中の再構築行数 | 出力行数オーダー | 同上 |

## 8. テストシナリオ

### 8.1 テスト観点

- [ ] 正常系: ダーティ集合の性質（無変化 / カーソル移動 / blink / PTY 出力）
- [ ] 正常系: カーソルオーバーレイ座標（通常 / wide / 絵文字 / 空セル / fold 行 / 画面端 / スクロールバック中）
- [ ] 正常系: 描画スキップ判定の純関数テスト（dirty 0 かつステータスバー不変 → skip）
- [ ] 等価性: 変異シナリオ（文字書き込み・スクロール・選択変更・リサイズ）で行キャッシュとフル再構築が一致
- [ ] 境界値: 無効化トリガーのマトリクス（選択・ホバー・検索・スクロール・リサイズ・フォント/テーマ変更・フォーカス得失）
- [ ] 正常系: 持続バッファの成長ポリシー純関数テスト
- [ ] パフォーマンス: アイドル 10 秒フレーム数 / 出力中再構築行数 / 前後 CPU% 比較
- [ ] E2E・目視（最終 verify のみ）: カーソル 3 形状 × blink、CJK・絵文字上のカーソル、選択・検索・ホバー、TUI（vim / Claude Code）残像、mux タブ切替後の表示
