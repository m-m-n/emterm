# Task Plan: task0002 — Honest dirty set + draw-skip decision + frames counter

## Goal

On a frame where nothing changed, `dirty_rows_this_frame` returns an empty
set and the render skip path actually fires, so unchanged frames cost no
grid rebuild; a frames-drawn perf counter makes this observable.

## Requirements

FR1, FR6 (frames-drawn half), NFR1.

## Scope

### Files to Create

- (none)

### Files to Modify

- `src-tauri/src/app.rs` — in `dirty_rows_this_frame`: remove the
  unconditional pushes of the current cursor row and the previous cursor row;
  replace with conditional pushes — push previous + current cursor rows only
  when the cursor cell moved since the previous frame, and push the current
  cursor row on a blink phase flip only while blink is enabled. Selection and
  fold fallback logic unchanged. Add/extend the dirty-set unit tests.
- `src-tauri/src/window_host.rs` — extract the skip decision ("dirty count is
  zero AND status bar unchanged → skip") into a pure function with unit
  tests; count drawn (non-skipped) frames behind `EMTERM_RENDER_PERF=1`
  (warn-level, `[EMTERM_RENDER_PERF]` prefix, env read once — see
  IMPLEMENTATION.md Conventions).

## Design

- Precondition (established by task0001): grid instances no longer encode the
  cursor, so a stationary cursor with stable blink phase requires no repaint
  of its row. The remaining reasons to dirty a cursor row are (a) the cursor
  moved (erase old cell overlay / draw new), and (b) the blink phase flipped
  (overlay must be repainted or erased) — both still flow through the dirty
  set because the skip decision would otherwise suppress the frame entirely.
- Soundness rule (IMPLEMENTATION.md D2): the dirty set may over-approximate
  but must never omit a changed row. When in doubt keep the conservative
  branch (e.g. the fold + selection full-repaint fallback stays).
- The skip decision function takes plain values (dirty row count as an
  option, status-bar-changed flag) and returns a skip verdict — no window,
  app, or egui types, so it is directly unit-testable.
- Frames-drawn counter: incremented on every frame that proceeds past the
  skip decision; periodically logged (e.g. once per second of activity or on
  a counter threshold — pick the simplest scheme that lets TS-8 count frames
  over a 10 s idle window).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A frame with no content change, no cursor move, no blink flip, no
  selection change, and no scroll returns an **empty** dirty set (write this
  test first, red, against the current behavior).
- [ ] AC-2: Moving the cursor dirties exactly the old row and the new row (on
  top of any content-dirty rows).
- [ ] AC-3: With blink enabled, the cursor row is dirtied only on frames
  where the blink phase flips; with blink disabled, no blink-driven push ever
  occurs.
- [ ] AC-4: PTY output dirties the output rows only (no cursor-row stowaway
  when the cursor did not move).
- [ ] AC-5: The skip decision is a pure function; "Some(0) dirty AND status
  bar unchanged → skip" and all three non-skip combinations are unit-tested.
- [ ] AC-6: With `EMTERM_RENDER_PERF=1`, drawn frames are counted and logged
  at warn level; with the variable unset, no counting side effects occur.

## Test Notes

- AC-1..AC-4 live next to `dirty_rows_this_frame`'s existing tests in
  `app.rs`; drive the terminal core through real writes (existing test
  helpers) rather than mocking.
- AC-3 needs control over blink phase timing; reuse whatever clock/phase
  hooks the existing blink tests use — if none exist, expose the phase
  comparison as a testable helper rather than sleeping in tests.
- AC-5/AC-6 in `window_host.rs`'s test module (pure logic only; no winit).

## Out of Scope

- Event-loop control flow (task0004).
- Cursor drawing (done in task0001).
