# Task Plan: task0004 — Wait-driven event loop

## Goal

The winit event loop stops rearming a 16 ms `WaitUntil` on every turn: with no
timed work pending it enters true `ControlFlow::Wait`, and every producer that
previously relied on the 60 Hz pump wakes the loop explicitly. Idle wakeups
drop from ~155/s to (at most) blink cadence.

## Requirements

FR5, NFR1.

## Scope

### Files to Create

- (none)

### Files to Modify

- `src-tauri/src/window_host.rs` — `about_to_wait`: compute the next control
  flow from pending timed work instead of unconditionally rearming 16 ms.
  Timed work with a deadline (cursor blink while enabled + focused, visual
  bell decay, active toasts) → `WaitUntil(nearest deadline)`; otherwise →
  `Wait`. The `resumed` handler's initial control flow follows the same rule.
- `src-tauri/src/app.rs` — expose "when is my next deadline" for the timed
  concerns the loop consults (blink half-cycle, bell decay, toast expiry), so
  the loop can compute the nearest deadline without duplicating timing
  logic. Provide the wake hook that PTY-owning tabs use.
- `src-tauri/src/tabs.rs` — PTY reader threads (and the mux bridge output
  path) signal the event-loop proxy when new output arrives, replacing the
  16 ms polling of `pump_all` as the discovery mechanism for PTY data.

## Design

- Inventory of `about_to_wait` responsibilities (every one must keep a wake
  source — IMPLEMENTATION.md D4):
  - PTY output (`pump_all`) → event: reader thread wakes via the existing
    `EventLoopProxy::send_event` user-event channel (same chain the
    status-bar providers already use).
  - IME pump → winit delivers IME/keyboard events natively; the pump runs on
    those wakeups (and on any other wake) rather than needing its own timer.
  - Settings-save watcher, child-window IPC → these already raise flags that
    a wake observes; route them through the proxy wake if they do not
    already.
  - Cursor blink / visual bell / toast expiry → deadline-based `WaitUntil`.
  - Drag-drop batch aggregation, search re-run, hover refresh → run on wakes
    triggered by the events that change their inputs (drop events, PTY wake,
    pointer events); none needs a free-running timer.
- Semantics: a wake (user event, window event, or deadline) runs the same
  pump sequence `about_to_wait` runs today; the change is *when the loop
  wakes*, not *what a turn does*. Coalescing: multiple PTY chunks between
  wakes still land in one turn (the existing coalescing budget in the pump
  is unchanged).
- Focus/visibility: blink deadline is armed only while blink is enabled and
  the window is focused (SPEC edge case: blink disabled → no periodic
  wakeups at all when idle).
- Platform note: behavior must hold on both Linux and Windows winit backends
  (no Unix-only wake API — the proxy channel is cross-platform).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The next-control-flow decision is a pure function of the pending
  timed-work states (blink enabled+focused with next flip time, bell decay
  deadline, toast expiry): returns Wait when none pending, otherwise
  WaitUntil of the nearest deadline — unit-tested for each combination.
- [ ] AC-2: With blink disabled, no window focus loss required: the decision
  function yields Wait on an idle terminal (no periodic wakeups).
- [ ] AC-3: The PTY output path signals the event-loop proxy on data arrival
  (observable via a test hook or by unit-testing the wake-registration
  contract on the reader side).
- [ ] AC-4: All existing `--lib` tests pass; no regression in tabs.rs replay
  tests (run single-threaded if flaky, per test/README.md).

## Test Notes

- AC-1/AC-2: extract the decision into a pure function over plain deadline
  values (like task0002's skip decision) — no winit types in tests.
- AC-3: the wake plumbing crosses threads; test the contract at the seam
  (e.g. the callback/channel invoked on output arrival) rather than driving
  a real event loop. Full interactive latency (typing, IME, TUI apps) is
  covered at final verify (TS-9) and by the idle-wakeup measurement (TS-8,
  `voluntary_ctxt_switches` per report §6).
- Watch for regressions in responsiveness-sensitive paths: nothing in this
  task may *remove* a pump — only change when it is scheduled.

## Out of Scope

- Dirty-set semantics and skip decision (task0002).
- Row cache / buffers (task0003).
- Blink inactivity timeout (Alacritty-style auto-stop) — future refinement,
  not in SPEC.
- mux daemon-side changes (daemon is not a CPU hotspot).
