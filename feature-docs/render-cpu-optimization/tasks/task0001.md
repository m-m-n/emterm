# Task Plan: task0001 — Block cursor as egui overlay

## Goal

The filled block cursor is drawn by the egui overlay layer instead of being
baked into the wgpu grid instances, so grid instance data no longer depends on
cursor position, blink phase, or window focus (IMPLEMENTATION.md invariant).

## Requirements

FR2 (partially enables FR1; NFR2 visual fidelity for cursor rendering).

## Scope

### Files to Create

- (none)

### Files to Modify

- `src-tauri/src/render/mod.rs` — remove the `block_cursor_cell` parameter and
  its fg/bg swap from `collect_cell_inputs` (both the scrollback branch and
  the live branch); update the affected `collect_cell_inputs` unit tests; the
  focused block-cursor case routes through the overlay drawing path.
- `src-tauri/src/render/cursor.rs` — add the filled-block overlay drawing:

- `src-tauri/src/window_host.rs` — delete the `block_cursor_cell` computation
  feeding `collect_cell_inputs` (the visibility conditions — focused, visible,
  block style, blink phase on, not scrolled back — move to the overlay side).

## Design

- Current state: `collect_cell_inputs` swaps fg/bg for the cursor cell when
  `block_cursor_cell` matches, which couples grid content to cursor state.
  Underline / bar shapes and the unfocused hollow outline are already drawn by
  the overlay (`draw_cursor` path); this task makes the focused filled block
  the overlay's job too, unifying all cursor shapes on one layer.
- Overlay contract: given cursor cell (col, row), cell metrics, and the cell's
  resolved style, paint (1) the cell rectangle filled with the cell's
  foreground color (i.e. inverted background) and (2) the covered glyph in the
  cell's background color (inverted foreground). A wide (2-cell) glyph under
  the cursor inverts its full 2-cell footprint.
- Visibility conditions preserved exactly from the current bake-in logic:
  window focused AND terminal cursor visible AND block style AND blink phase
  on AND not scrolled back (scroll offset zero). Unfocused windows keep the
  existing hollow-outline behavior, unchanged.
- Glyph access: the overlay needs the character under the cursor and its
  style; it may read them from the terminal core the same way existing
  overlay passes read state. No new shaping machinery — the overlay draws one
  glyph via the existing egui text/painting facilities already used for the
  preedit and summary overlays.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `collect_cell_inputs` has no cursor parameter; its output for a
  given (content, theme, selection, hover, scroll, fold) state is identical
  whether or not a cursor is present anywhere.
- [ ] AC-2: Overlay geometry: the block-cursor rectangle is correct for a
  normal 1-cell glyph, a wide 2-cell glyph (covers both cells), an emoji, and
  an empty cell (rect only, no glyph artifact).
- [ ] AC-3: When scrolled back (scroll offset non-zero), no block cursor is
  drawn.
- [ ] AC-4: At the last column and last row the cursor rect stays within the
  grid bounds (no out-of-range rect).
- [ ] AC-5: With a fold layout active, the cursor rect lands on the correct
  screen row (or is suppressed if the cursor row is hidden by a fold).
- [ ] AC-6: All pre-existing `collect_cell_inputs` and cursor tests pass
  (updated only where the removed parameter forces a signature change).
