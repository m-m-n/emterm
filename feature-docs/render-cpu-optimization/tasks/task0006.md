# Task Plan: task0006 — Row cache scroll tracking (rotate on scroll_event)

## Goal

The per-row instance cache correctly tracks term_core's full-screen
single-line scroll optimization: the frame after a live-tail scroll shows
every row's post-scroll content, with the cache rotated (not fully rebuilt)
so the output-time CPU benefit of dirty-row rendering is preserved while
scrolling.

## Requirements

FR3, NFR2 (fixes review round-2 critical finding 779c9130c103c55b).

## Scope

### Files to Create

- (none)

### Files to Modify

- `src-tauri/src/render/terminal_grid_pass.rs` — a rotate operation on the
  row cache: shift entries by N rows in the scroll direction, vacated
  entries become empty (must-rebuild) slots. Pure, unit-testable.
- `src-tauri/src/window_host.rs` — consume the terminal core's scroll event
  (direction + accumulated count) once per frame in the cached-render path:
  rotate the row cache by that amount before the dirty-row rebuild, then
  clear the event. Rotation by ≥ row-count degenerates to a full drop.
- `src-tauri/src/app.rs` — only if the consumption point naturally belongs in
  the App-side frame bookkeeping (e.g. alongside `dirty_rows_this_frame` /
  `record_render_state`); otherwise untouched.

## Design

- Contract being honored (term_core `ring_buffer::scroll_up_internal`,
  full-screen `count == 1` path): the core shifts its dirty bits up by one,
  marks the new bottom row dirty, and records/accumulates a scroll event
  (direction Up, count += 1) — on the promise that the renderer shifts its
  own representation by the same amount. This task makes the row cache that
  renderer-side representation.
- Consumption semantics: read the scroll event exactly once per rendered
  frame, before computing which cached rows to reuse; clear it after
  consumption so the next frame starts clean. Multiple scrolls between
  frames accumulate in `count` — rotate by the accumulated amount.
- Direction mismatch / count ≥ viewport rows / any uncertainty → degenerate
  to full cache invalidation (correctness first; these cases already imply
  most rows changed).
- Interaction rules:
  - `needs_full_redraw` frames: full rebuild already; just clear the event.
  - Skipped frames: a frame with a pending scroll event must NOT be
    skippable (a scroll changes every row's content; the dirty set from the
    core will be non-empty anyway — assert/keep this property).
  - Scrolled-back viewports (scroll offset non-zero) and fold layouts
    already fall back to full-row dirty sets; the rotation must not corrupt
    the cache in those modes (full invalidation acceptable there).
  - IME-preedit shadow rebuild path must apply the same rotation before its
    shadow rebuild (it shares the cache).
- The equivalence property (cache path output == full rebuild, byte-exact)
  remains the safety net and gains a scroll regression scenario.

- [ ] AC-1: Regression test for the bug: fill the viewport, clear dirty

- [ ] AC-5: Existing equivalence / invalidation-matrix / dirty-set tests
  keep passing; preedit shadow-rebuild path stays equivalence-correct when
  a scroll happens during composition (test or conservative full
  invalidation in that combination).

## Test Notes

- AC-1/AC-3 drive a real terminal core (existing test helpers write bytes /
  newlines); compare instance sequences structurally like the existing TS-4
  equivalence suite.
- AC-2 tests the rotate operation as pure data manipulation (no core, no
  wgpu).
- Watch the dirty-bit shift interplay: after rotation, the rows the core
  reports dirty (shifted + bottom) are rebuilt; rows the rotation vacated
  must also count as must-rebuild even if the core's dirty set misses them
  (empty slot ⇒ rebuild, by cache construction).
