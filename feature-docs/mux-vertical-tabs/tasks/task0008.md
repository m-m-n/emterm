## Design

Observed defect (real build screenshot): inside the card, rows reach the
card's right edge (no 8 px right padding); the bottom region of the card
also renders with wrong padding. The design spec (DESIGN.md floating
card) requires the 12 px vertical / 8 px horizontal panel padding
between the card edge and the list on every side.

Suspected mechanism (verify during implementation): the frame that
paints the card background derives its painted rect from its CONTENT's
actual bounds instead of the intended card rect. The minimum-size hint
is applied to the outer area, not to the frame's content, so the painted
background and the content constraint can disagree on the right/bottom
edges — the same "accidental gap / edge-touching" defect class the
flush panel showed. The fix must make one rect authoritative: the
computed card rect determines the painted background, and the content
region is that rect shrunk by the panel padding on all four sides.

Constraints carried over unchanged from task0007:

- Card rect = width from the shared width function, inset 16 px from the
  terminal area's top/right/bottom edges.
- 12 px corner radius, 92%-alpha `surface-container-high` fill,
  elevation-3 shadow, no separator, no scrim, no animation.
- Zero grid inset; toggle semantics and click routing unchanged.
- Persistent variant untouched.

Test-hook hardening: the existing overlay test hook records the
PRE-COMPUTED rect, which is why the mismatch escaped the unit tests.
Extend the hook (or add one) so the assertion covers the rect the
background is actually painted with, and pin the row-to-card-edge
insets (right edge included) numerically.
