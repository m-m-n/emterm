# Task Plan: task0001 — Rust settings layer: `mux.window_sidebar_overlay`

## Goal

The boolean placement-mode setting exists across all Rust settings layers,
persists round-trip, and defaults to `false` (persistent mode).

## Requirements

FR6

## Scope

### Files to Create
- (none)

### Files to Modify
- `crates/app_settings/src/settings.rs` — add the boolean to the `MuxSettings`
  serde shape with a `false` default, and to its `Default` impl
- `src-tauri/src/settings.rs` — add the field to the resolved runtime
  `MuxSettings`, its default, the deserialize-side optional overlay struct,
  and the loader copy step

## Design

Mirror the existing `tab_always_expand` boolean end-to-end (same file set,
same serde-default and Option-overlay pattern — see IMPLEMENTATION.md
Conventions). Field name is pinned in IMPLEMENTATION.md Shared Components:
`window_sidebar_overlay` under the mux settings group.

Semantics: `false` = persistent sidebar (default), `true` = overlay mode.
This task only makes the value exist, default, deserialize (including
null/missing), and reach the resolved runtime settings — consumers are other
tasks.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A settings JSON without the field resolves to `false`
- [ ] AC-2: A settings JSON with the field `null` resolves to `false`
- [ ] AC-3: A settings JSON with the field `true` resolves to `true` in the
      runtime settings the GUI reads
- [ ] AC-4: Serializing default settings then re-loading them round-trips the
      field without loss

## Test Notes

Unit tests beside the existing MuxSettings serde tests in both crates; follow
the existing null/missing-handling test style for sibling booleans. All four
criteria are plain serde/loader unit tests.

## Out of Scope

- TS mirror, settings UI, i18n (task0002)
- Any consumer behavior (prefix action, rendering)
