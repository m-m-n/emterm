# Task Plan: task0004 — Vertical tab sidebar widget (`ui::mux_sidebar`)

## Goal

A reusable egui component draws the mux window list (number + name + active
mark) in either placement variant, reports clicks, and exposes the shared
width formula — styled per the feature's design decisions on MD3 tokens.

## Requirements

FR2, FR3 (click reporting), NFR3

## Scope

### Files to Create
- `src-tauri/src/ui/mux_sidebar.rs` — the widget module (view-model, width
  function, draw function for both placement variants)

### Files to Modify
- `src-tauri/src/ui/mod.rs` (or the module roster in `src-tauri/src/lib.rs`,
  whichever declares `ui` submodules) — register the new module under the
  gui feature

## Design

Component contract is pinned in IMPLEMENTATION.md Shared Components: entry
list in (window index, display name, active flag) order → optional clicked
window index; the widget never talks to the daemon. Follow `ui/tab_bar.rs`
module style (small view-model structs + draw function, md3 accessors only).

Visual decisions (from the design step, restated as the implementable spec):
- Width: clamp(180 px, 22% of window inner width, 320 px) — exposed as the
  shared pure function.
- Row: 40 px high full-radius pill, 12 px horizontal padding, 8 px gap
  between number and name, 4 px gap between rows; panel padding 12 px
  vertical / 8 px horizontal.
- Number: small label (12 px, medium weight), right-aligned in a fixed
  narrow column, secondary text color (`on_surface_variant`).
- Name: 14 px body text, single line, ellipsis truncation.
- Active row: `secondary_container` background with `on_secondary_container`
  text — the only active mark. Inactive hover: 8% `on_surface` state layer.
- Persistent variant surface: `surface_container_low` background, 1 px
  `outline_variant` separator on the terminal-facing edge.
- Overlay variant surface: `surface_container_high` background, 1 px
  `outline_variant` separator on its left edge, elevation-3-like shadow.
  No scrim, no open/close animation.
- Overflow: vertical scrolling; rows never shrink. Empty list: bare panel,
  no placeholder text.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The width function returns 22% of the input width, clamped to
      [180, 320] (boundary cases: very narrow and very wide windows)
- [ ] AC-2: The view-model maps a window group's entries preserving order,
      numbering, names, and the single active flag; 0-entry and 1-entry
      lists are valid
- [ ] AC-3: Clicking an entry's interactive area reports that entry's window
      index; clicking elsewhere reports nothing
- [ ] AC-4: Long names truncate (galley/laid-out text does not exceed the
      row's available width); the widget requests vertical scrolling when
      entries exceed the available height
- [ ] AC-5: Colors used by the widget come exclusively from the md3 accessor
      set (no hardcoded color literals in the module)

## Test Notes

Width function and view-model mapping are plain unit tests (AC-1, AC-2).
Interaction/truncation (AC-3, AC-4) via egui's test harness pattern if
present in the repo; otherwise structure the module so hit-testing and
layout decisions are pure functions testable without a live egui context,
and cover those — document any part verifiable only manually. AC-5 is a
source-level assertion (review/grep-style test or discipline note).

## Out of Scope

- Wiring into the frame (render/mod.rs), grid geometry, visibility rules,
  PTY resize behavior (task0005)
- Top tab title change (task0005)
