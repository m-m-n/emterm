# Task Plan: task0002 — Settings UI (TS): overlay toggle + i18n

## Goal

The settings panel's mux section offers the 「オーバーレイで表示」 toggle
(default off), the TS settings mirror carries the new field, and ja/en locale
strings exist for both the toggle and the new keybind action label.

## Design

Field name and action id are pinned in IMPLEMENTATION.md Shared Components
(`window_sidebar_overlay`, `toggle-window-sidebar`). The toggle row follows
the MD3 switch pattern already used by other sections (settings-row-toggle);
no new visual design. Label ja: 「オーバーレイで表示」; en: "Display as
overlay". Description states that the window sidebar overlays the right edge
and is toggled with the mux prefix keybind.

The mux keybind grid is populated from the `get_mux_action_defaults` IPC, so
the new action appears once the Rust side (task0003) lands; this task only
supplies its display label keys so the grid shows a translated name.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The mux section renders a toggle for the field, initial state
      reflecting the current settings value (off by default)
- [ ] AC-2: Flipping the toggle saves the mux settings object with the field
      set accordingly (spread-save preserves sibling mux fields)
- [ ] AC-3: ja and en locale files both contain the toggle label/description
      keys and the `toggle-window-sidebar` action label key, and `bun run
      typecheck` passes with the new `MuxSettings` field

## Test Notes

`bun test` component tests with the existing happy-dom setup: render the
section with settings fixtures, assert toggle presence/state, simulate change
and assert the save callback payload. Locale-key presence can be asserted in
the same test file. Follow bun test-isolation conventions used by sibling
section tests.
