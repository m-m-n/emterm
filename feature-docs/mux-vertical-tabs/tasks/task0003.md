# Task Plan: task0003 — Prefix action `toggle-window-sidebar` + App overlay state

## Goal

`Ctrl+Z Ctrl+W` dispatches a new mux prefix action that toggles the App-level
overlay-open flag in overlay mode and does nothing in persistent mode; the
action participates in the existing keybind SSOT (defaults IPC, user
rebinding).

## Requirements

FR5, FR4 (no-op rule), NFR2

## Scope

### Files to Create
- (none)

### Files to Modify
- `src-tauri/src/mux/prefix.rs` — new `PrefixAction` variant
  `ToggleWindowSidebar`; new `ActionBindings` field wired into its default
  construction, the settings-map overlay, and the input-to-action dispatch;
  new `DEFAULT_ACTION_BINDINGS` row `toggle-window-sidebar` = Ctrl+W
- `src-tauri/src/app.rs` — App runtime flag `mux_sidebar_overlay_open`
  (initial false); handle the new action in the mux action dispatch (toggle
  only when the overlay-mode setting is true, per the Shared Components
  contract); reset the flag when the focused tab's mux group is torn down
  (detach / session end)

## Design

Follow the existing add-an-action recipe visible in prefix.rs: every existing
action touches the same four sites (variant, bindings field, defaults table
row, dispatch match). The defaults IPC (`get_mux_action_defaults`) and
`settings.mux.keybinds` overlay pick the new row up automatically from the
table — no changes to the settings window commands.

Toggle semantics (contract in IMPLEMENTATION.md Shared Components):
- Overlay-mode setting true → flip `mux_sidebar_overlay_open`.
- Overlay-mode setting false (persistent) → strict no-op: no state change,
  no dialog, no PTY interaction (FR4).
- Flag reset postcondition on mux teardown so a later attach starts closed.

The flag is rendering input only; this task does not render anything.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `toggle-window-sidebar` appears in the default action bindings
      with chord Ctrl+W, and the defaults-as-strings export includes it
- [ ] AC-2: With overlay mode enabled, dispatching the action twice returns
      the flag to its initial value (toggle round-trip)
- [ ] AC-3: With overlay mode disabled, dispatching the action leaves the
      flag false and produces no other observable state change
- [ ] AC-4: A user keybind override from the settings map rebinds the action
      (existing overlay mechanism) without affecting the other six actions
- [ ] AC-5: Existing default chords (detach / new / next / prev / rename /
      move) are unchanged by the addition (non-regression)

## Test Notes

Unit tests in prefix.rs beside the existing bindings tests (AC-1, AC-4,
AC-5). App-level toggle/no-op/reset (AC-2, AC-3) as app-layer unit tests
following the existing mux dispatch test style; if App construction is too
heavy there, test the toggle decision through the smallest existing testable
seam and document it.
