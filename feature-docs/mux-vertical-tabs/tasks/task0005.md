# Task Plan: task0005 — Frame integration: single mux tab, sidebar placement, grid geometry

## Goal

The mux window group renders as one top tab titled `mux: <active window
name>`, the sidebar appears in the correct placement per settings + runtime
state, sidebar clicks switch windows, and the terminal grid geometry honors
the resize discipline (no PTY resize on toggle/switch; exactly one on mode
change).

## Requirements

FR1, FR3, FR4, FR5 (overlay rendering), NFR1, NFR2

## Design

Cross-task decisions 1–3 in IMPLEMENTATION.md govern this task: reuse the
existing `MuxSwitch` tab-event application path for clicks; geometry inset
mirrors the `effective_tab_bar_height` gating pattern; overlay contributes
zero inset. The sidebar widget and width function come from the
`ui::mux_sidebar` contract (Shared Components) — implement against the
contract, not the sibling task's code.

Visibility rule (FR2/FR4/FR5): persistent variant visible iff overlay-mode
setting is false AND the active tab is mux-attached. Overlay variant visible
iff overlay-mode setting is true AND the runtime overlay flag is set AND the
active tab is mux-attached. Local tabs never show either variant.

Resize discipline (NFR1): overlay open/close and window switching leave the
grid columns/rows untouched. Only these change the inset and thus reshape
the PTY: entering/leaving a mux-attached tab in persistent mode (existing
tab-switch resize semantics apply) and flipping the placement setting
(exactly one reshape via the pending-resize flag).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A mux-attached tab yields exactly one top-tab cell; its label is
      `mux: <active window name>` and follows a rename of the active window
- [ ] AC-2: The sidebar's reported click results in the same window-switch
      behavior as the previous inline sub-tab click (event application path
      unchanged)
- [ ] AC-3: Grid geometry: with persistent mode on a mux tab, usable columns
      shrink by the shared width function's value; on local tabs and in
      overlay mode the inset is zero
- [ ] AC-4: Toggling the overlay does not change the computed grid size;
      flipping the placement setting triggers exactly one pending-resize
      cycle
- [ ] AC-5: Cursor and search-highlight x-origins match the grid origin when
      the persistent sidebar is visible
- [ ] AC-6: Visibility matrix holds (persistent/overlay × mux/local tab ×
      flag state) — local tabs never render a sidebar
- [ ] AC-7: Existing non-mux tab bar behavior (plain tab click, activity
      dot, fixed-area buttons) is unchanged

## Test Notes

Grid-size/inset math and visibility predicate as unit tests (AC-3, AC-4,
AC-6) — structure the inset decision as a pure function over (mode, flag,
tab-mux-state, window width). Label formatting incl. rename follow-up as a
tab-bar unit test beside existing label tests (AC-1). Event-path equivalence
(AC-2) via the existing tab-event application tests. AC-5 and pixel-level
alignment are manual (VERIFICATION M-1); note that `tabs.rs` replay tests
flake in parallel — use single-threaded runs when touched.
