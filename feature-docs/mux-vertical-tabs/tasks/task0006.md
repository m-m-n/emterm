# Task Plan: task0006 — Move the persistent sidebar to the right edge

## Goal

The persistent (default) sidebar renders on the RIGHT edge of the terminal
area — the same side as the overlay — and the terminal grid's x-origin no
longer shifts when the sidebar is visible (only the usable width shrinks).

## Requirements

FR4, NFR3

## Scope

### Files to Create
- (none)

### Files to Modify
- `src-tauri/src/render/mod.rs` — draw the persistent variant as a RIGHT
  side panel instead of a left one; remove any sidebar x-origin term from
  the cursor/search overlay origin math it hosts
- `src-tauri/src/ui/mux_sidebar.rs` — persistent variant: terminal-facing
  separator moves to the panel's LEFT edge; update the variant's panel
  construction and its unit tests accordingly
- `src-tauri/src/render/cursor.rs` — remove the sidebar x-origin inset (the
  cursor origin is identical with and without the sidebar)
- `src-tauri/src/window_host.rs` — grid geometry: the sidebar inset reduces
  only the usable width; the grid x-origin term reverts to its pre-sidebar
  form. `pending_resize` semantics stay unchanged
- `src-tauri/src/app.rs` — update any helper docs/tests that state the
  left-side placement (include for safety; behavior of
  `mux_sidebar_visibility` / `mux_sidebar_grid_inset` values is unchanged)

## Design

Cross-task decision 2 in IMPLEMENTATION.md (2026-07-20 update) governs this
task: right-edge placement means a width-only inset — no x-origin term
anywhere (grid, cursor, search overlays). The overlay variant is already on
the right and must not change. Visuals per DESIGN.md: persistent surface
stays `surface_container_low` with a 1 px `outline_variant` separator on the
terminal-facing (left) edge; overlay keeps `surface_container_high` +
elevation shadow. The shared width formula and the widget's list rendering
are untouched.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The persistent sidebar panel occupies the right edge of the
      terminal area; its separator line sits on the panel's left edge
- [ ] AC-2: With the persistent sidebar visible, the grid x-origin equals
      the origin without a sidebar; usable columns shrink by the shared
      width function's value (width-only inset)
- [ ] AC-3: Cursor and search-highlight x-origin computations contain no
      sidebar term and match the grid origin in both placement modes
- [ ] AC-4: Overlay-mode geometry and behavior are unchanged (zero inset,
      right-edge overlay, no PTY resize on toggle)
- [ ] AC-5: Existing sidebar/geometry unit tests updated to the right-edge
      expectations; full lib suite has no new failures beyond the documented
      pre-existing tabs.rs flaky set

## Test Notes

AC-2/AC-3 are pure-function geometry tests (inset/origin math) — extend the
existing `mux_sidebar_grid_inset` / origin tests. AC-1's panel-side choice is
verifiable via the render path's panel construction (side enum/API) plus the
widget's own tests; pixel-level confirmation stays manual (M-1 mockup
comparison). AC-4 reuses the existing overlay tests unchanged.

## Out of Scope

- Any change to the overlay variant, width formula, list content, click
  routing, settings, keybinds, or i18n
- Sidebar-related medium findings from review round 1 (recorded separately)
