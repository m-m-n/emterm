# Task Plan: task0007 — Overlay as a floating card (right side)

## Goal

The overlay-mode sidebar renders as a FLOATING CARD over the terminal's
right side instead of a flush edge panel: uniform margin from the terminal
area's top / right / bottom edges, rounded corners, slight translucency,
and no separator line. The persistent variant and all behavior (toggle,
click routing, zero grid inset) are unchanged.

## Requirements

FR5, NFR3

## Scope

### Files to Create
- (none)

### Files to Modify
- `src-tauri/src/ui/mux_sidebar.rs` — overlay variant only: card
  geometry (margins, radius), translucent fill, drop the separator line;
  update the variant's unit tests accordingly

## Design

Visual intent (design step, 2026-07-20 floating-card reshape):

- The card keeps the shared width function's value as its width. Its rect
  is inset by a uniform 16 px (`spacing-md`) from the terminal area's top,
  right, and bottom edges (the terminal area = the central region
  remaining after the top/bottom bars, i.e. the same region the flush
  panel used).
- Corner radius 12 px (`corner-medium`) on all four corners.
- Background `surface-container-high` at 92% opacity (slight
  translucency; list text must stay readable).
- NO separator line on any edge — the card's rounded edge is the only
  boundary.
- Elevation-3 shadow kept (the shared dialog elevation token). No scrim.
  No open/close animation. Appears/disappears in one frame.
- Inner list padding (12 px vertical / 8 px horizontal) and all row
  styling are unchanged.

Colors and the shadow come from the `ui::md3` accessors / shared dialog
tokens only (no hardcoded hex); the 92% opacity is applied to the token
color's alpha channel.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The overlay card's rect is inset exactly 16 px from the
      terminal area's top, right, and bottom edges; its width equals the
      shared width function's value
- [ ] AC-2: The card is drawn with a 12 px corner radius and a background
      equal to `surface_container_high` with alpha scaled to 92%
- [ ] AC-3: No separator line is painted by the overlay variant (the
      persistent variant's left-edge separator is unchanged)
- [ ] AC-4: Overlay behavior is unchanged: zero grid inset, toggle
      semantics, click routing, elevation shadow present, no scrim
- [ ] AC-5: Existing overlay-geometry unit tests updated to the
      floating-card expectations (including the persistent/overlay
      right-edge relation: overlay rows now sit 16 px further left);
      full lib suite has no new failures beyond the documented
      pre-existing tabs.rs flaky set

## Test Notes

AC-1 is a rect-geometry assertion against the overlay's card rect
(derivable the same way the existing overlay tests obtain row rects /
area geometry). AC-2/AC-3 are verifiable via the frame construction
(fill color alpha, absence of the separator paint) — use test hooks in
the same style the module already uses for row rects; pixel-perfect
appearance stays manual (M-1 mockup comparison). AC-4 reuses the
existing zero-inset / toggle tests unchanged.

## Out of Scope

- Any change to the persistent variant, width formula, list content, row
  styling, click routing, settings, keybinds, or i18n
- Grid geometry (`render/`, `window_host.rs`, `app.rs`) — the overlay
  contributes no inset before or after this task
