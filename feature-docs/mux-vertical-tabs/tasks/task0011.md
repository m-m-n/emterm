# Task Plan: task0011 — Suppress terminal selection under the overlay card

## Goal

A left-button press (and the drag that follows) on the overlay floating
card never starts or extends a terminal selection — clicks on the card
belong to the sidebar only (2026-07-20 実機バグ報告: オーバーレイ上の
ドラッグでターミナル選択が発生する).

## Requirements

FR5, NFR2

## Scope

### Files to Create
- (none)

### Files to Modify
- `src-tauri/src/window_host.rs` — the winit MouseInput handler's
  press-suppression guard, plus its regression tests

## Design

Observed defect: the MouseInput Pressed-edge guard that suppresses
terminal-selection starts already covers the bottom status-bar strip,
the right-edge scrollbar, and the PERSISTENT sidebar (via the
`mux_sidebar_inset_logical > 0` width test) — but the overlay card
contributes zero grid inset, so a press on the card falls through and
starts a selection on the terminal cells underneath; the subsequent
drag extends it.

Fix shape: the guard must use the shared sidebar hit-region helper
introduced by task0010 (`point_in_sidebar` and the visibility
resolution the MouseWheel guard already uses), which covers BOTH
placements, instead of (or in addition to) the persistent-only width
test. This keeps one geometry derivation for paint, wheel routing, and
press suppression (IMPLEMENTATION.md decision 3.5).

Constraints:

- Suppression applies to the press EDGE only, mirroring the existing
  strip/scrollbar rule: a drag that STARTED inside the terminal must
  still get its Released event processed when the button is lifted
  over the sidebar (selection commit / `dragging` reset unchanged).
- The egui forward of PointerButton events stays as-is (sidebar row
  clicks must keep working — FR3 path untouched).
- Existing suppression behaviors (top strip, bottom strip, scrollbar,
  persistent sidebar, profile-selector, CSD edge-resize) are unchanged
  (NFR2).
- No PTY resize, no grid geometry change, no new settings.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: With overlay mode on and the overlay open, a left press at
      a point inside the overlay card rect does not start a terminal
      selection (the guard returns before the selection-start arm)
- [ ] AC-2: The same press point with the overlay CLOSED (or on a local
      tab) behaves exactly as before — selection starts on the
      terminal cell
- [ ] AC-3: A selection started inside the terminal area and released
      over the visible sidebar still commits/clears normally (the
      guard stays Pressed-edge-only)
- [ ] AC-4: The press guard and the wheel guard resolve the sidebar
      region through the same shared helper (no second geometry
      derivation) — guarded by a structural/source-scan test in the
      established window_host convention
- [ ] AC-5: Full lib suite has no new failures beyond the documented
      pre-existing tabs.rs flaky set

## Test Notes

AC-1/AC-2 follow the existing MouseInput guard test conventions in
`window_host.rs` (synthetic event state + assert which arm consumed
it); AC-4 mirrors the source-scan regression test style task0010 added
for the wheel guard. Real-build feel is manual (M-4 extension).
