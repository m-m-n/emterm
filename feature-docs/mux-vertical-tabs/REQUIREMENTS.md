# muxタブ表示の縦タブ（左サイドメニュー）化 - 要件定義書

## 1. 概要

### 1.1 背景

現状、mux にアタッチすると mux の window が GUI 上部タブバーに展開される。横タブは window 数が増えるとタイトルが潰れてスケールしない。

### 1.2 目的

上部タブバーは維持しつつ、mux 全体を上部タブの1枠に集約し、mux の window 一覧を縦タブ（サイドメニュー）で表示する。

### 1.3 スコープ

- 上部タブバーにおける mux の集約表示
- 縦タブ（サイドメニュー）コンポーネントの新規実装（常時表示 / 右オーバーレイの2方式）
- 表示方式を切り替える設定項目の追加
- オーバーレイ開閉用の mux キーバインドアクションの追加

スコープ外:
- アクティビティ / ベルインジケータ（daemon 側検知＋プロトコル拡張が必要なため今回は含めない）
- mux の window 管理操作（rename / close 等）を縦タブ上から行う UI
- サイドバー幅のユーザー設定・ドラッグリサイズ

## 2. ビジネス要件

### 2.1 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| mux 利用者 | eMterm の mux 機能で複数 window を運用するユーザー |

### 2.2 期待される効果

- 多 window 時のスケーラビリティ向上（縦は伸ばせる）
- window タイトルの可読性向上（横幅を確保できる）
- ローカルタブと mux window が上部バーの同じ名前空間に混在しなくなり、階層が明確になる

## 3. ユースケース

### 3.1 ユースケース一覧

| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | 縦タブから window を切り替える | mux 利用者 | 高 |
| UC02 | オーバーレイをキーバインドで開閉する | mux 利用者 | 高 |
| UC03 | 表示方式を設定画面で切り替える | mux 利用者 | 中 |

### 3.2 ユースケース詳細

#### UC01: 縦タブから window を切り替える

**アクター**: mux 利用者

**事前条件**:
- mux にアタッチ済みで、mux タブがアクティブである
- 縦タブが表示されている（常時表示モード、またはオーバーレイ表示中）

**基本フロー**:
1. ユーザーが縦タブ上の window 項目をクリックする
2. その window に切り替わる（現在の上部タブクリックによる window 切替と同等の挙動）
3. 縦タブのアクティブマークが切替先 window に移る

**事後条件**:
- 切替先 window の画面が表示される

#### UC02: オーバーレイをキーバインドで開閉する

**アクター**: mux 利用者

**事前条件**:
- オーバーレイモード（設定「オーバーレイで表示」= on）である
- mux タブがアクティブである

**基本フロー**:
1. ユーザーが `Ctrl+Z Ctrl+W` を押す
2. 縦タブオーバーレイがターミナル面の右側に被さって表示される
3. もう一度 `Ctrl+Z Ctrl+W` を押すと閉じる

**代替フロー**:
- 常時表示モードで `Ctrl+Z Ctrl+W` を押した場合は何もしない（no-op）

**事後条件**:
- オーバーレイの開閉状態が反転している。PTY resize は発生しない

#### UC03: 表示方式を設定画面で切り替える

**アクター**: mux 利用者

**基本フロー**:
1. ユーザーが設定画面の「オーバーレイで表示」項目（boolean、デフォルト off）を切り替える
2. 縦タブの配置方法が常時表示 ⇔ 右オーバーレイで切り替わる

**事後条件**:
- 切替時に PTY resize が1回走るのは許容する

## 4. 機能要件

### 4.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | mux 上部タブ集約 | mux 全体を上部タブ1枠に集約する | 高 |
| F02 | 縦タブ表示 | mux の window 一覧を縦タブで表示する | 高 |
| F03 | クリックによる window 切替 | 縦タブの項目クリックで window を切り替える | 高 |
| F04 | 常時表示モード | サイドバーを固定配置する（デフォルト） | 高 |
| F05 | オーバーレイモード | サイドバーを右オーバーレイで開閉する | 高 |
| F06 | 表示方式設定 | 設定画面で表示方式を切り替える | 中 |

### 4.2 機能詳細

#### F01: mux 上部タブ集約

- 上部タブバーは維持する。mux の window は上部タブに展開せず、mux 全体で上部タブ1枠とする
- mux タブの表示名は「mux: <現在のアクティブ window 名>」形式とする。window 名は OSC タイトル書き換え（Claude Code 等によるタイトル変更）を反映する

#### F02: 縦タブ表示

- 縦タブは window のフラットな一覧とする（mux に tab 階層は無く、1 window = 1 pane 運用のため入れ子構造は不要）
- 各項目の表示内容: window 番号＋window 名＋アクティブマーク（現在の window の強調表示）
- アクティビティ / ベル等のインジケータは今回のスコープに含めない
- サイドバーの横幅はアプリ幅の 20〜25% 程度を動的に決定する固定値とする。設定項目・ドラッグリサイズは設けない
- 縦タブは mux 接続タブがアクティブなときのみ表示する。ローカルタブでは表示しない

#### F03: クリックによる window 切替

- 縦タブ上の window 項目をクリックしたら、その window に切り替える
- 挙動は現在の上部タブクリックによる window 切替と同等とする
- 表示方式（常時 / オーバーレイ）のどちらでも本仕様は変わらない

#### F04: 常時表示モード

- デフォルトの表示方式
- サイドバーを固定配置し、開閉は行わない（PTY resize が発生しない）
- このモードで `Ctrl+Z Ctrl+W` を押しても何もしない（no-op）

#### F05: オーバーレイモード

- サイドバーをターミナル面の右側に被せて表示する（表示中は右端が隠れる）
- 開閉はキーバインドで行う。デフォルトは `Ctrl+Z Ctrl+W`（`Ctrl+Z` は既存の mux プレフィックスキー）
- 同キーをもう一度押すと閉じる（トグル）。それ以外の閉じ方は設けない
- 開閉で PTY resize は発生しない
- 既存の `DEFAULT_ACTION_BINDINGS` テーブル（SSOT）に新アクションとして追加し、`settings.mux.keybinds` でのユーザー変更・設定パネル公開（`get_mux_action_defaults` IPC）まで既存パイプラインに乗せる

#### F06: 表示方式設定

- 設定画面に「オーバーレイで表示」項目（boolean、デフォルト off）を設ける
- 既存の Settings パターン（`app_settings` + TS ミラー + settings UI）に乗せる
- 設定切替時に常時表示 ⇔ オーバーレイで PTY resize が1回走るのは許容する

## 5. 非機能要件

### 5.1 パフォーマンス要件

- オーバーレイの開閉および window 切替で PTY resize を発生させない（resize 起因の既知バグとの相性を考慮）

### 5.2 互換性要件

- ローカルタブ（mux 非接続）の挙動は変更しない
- 既存の mux キーバインド（Ctrl+D / Ctrl+C / Ctrl+N / Ctrl+P / Ctrl+R / Ctrl+T）は変更しない。`Ctrl+W` は未使用であり競合しない

### 5.3 保守性要件

- 縦タブ本体のコンポーネントは共通化し、配置方法（push / overlay）のみ切り替える設計とする

## 6. UI/UX要件

### 6.1 画面設計要件

- 縦タブは egui ネイティブ描画で実装する
- 外観（配色・余白・アクティブマーク表現）は design ステップで DESIGN.md に固める。既存の MD3 トークン（`doc/UI-DESIGN-GUIDELINES.yaml`）に整合させる
- オーバーレイは右側に表示する（シェルのプロンプトや出力は左寄せが基本のため、左端を隠さない）
- オーバーレイ非表示中のアクティブ window 名の専用表示は設けない（確認したければオーバーレイを開く）

## 7. 制約条件

### 7.1 技術的制約

- mux の実階層は Session > Window > Pane の2段で、mux 内部に tab の概念は無い（`src-tauri/src/mux/session/window.rs`）
- 画面分割（SplitPane 0x11）はプロトコルから削除済みで、現運用は 1 window = 1 pane
- 現行プロトコルで GUI に届く window 情報は番号・名前・アクティブ状態のみ（ベル / アクティビティは存在しない）
- 開閉トグル式（push 型）は開閉のたびに PTY resize が走り TUI アプリが全面リフローするため採用しない

## 8. 成功基準

### 8.1 受け入れ基準

- [ ] mux アタッチ時、上部タブバーに mux が1枠として表示され、window が個別タブに展開されない
- [ ] mux タブの表示名が「mux: <アクティブ window 名>」となり、OSC タイトル変更に追従する
- [ ] 縦タブに window の番号・名前・アクティブマークが一覧表示される
- [ ] 縦タブの項目クリックで window が切り替わる
- [ ] デフォルト（常時表示）でサイドバーが mux タブアクティブ時のみ固定表示される
- [ ] 設定「オーバーレイで表示」を on にすると `Ctrl+Z Ctrl+W` で右オーバーレイが開閉する
- [ ] 常時表示モードで `Ctrl+Z Ctrl+W` を押しても何も起きない
- [ ] オーバーレイの開閉・window 切替で PTY resize が発生しない
- [ ] ローカルタブの挙動が変わらない

## 9. テストシナリオ

### 9.1 テスト観点

- [ ] 正常系: 縦タブ一覧表示・クリック切替・オーバーレイ開閉・設定切替
- [ ] 異常系: window が0個 / 1個のときの縦タブ表示、mux 非接続時に縦タブが出ないこと
- [ ] 境界値: window 数が多く縦タブが画面高さを超える場合のスクロール、長い window 名の表示
- [ ] 互換性: 既存 mux キーバインド・ローカルタブ挙動の非回帰

## 10. 用語定義

| 用語 | 定義 |
|------|------|
| mux | eMterm 内蔵の tmux 風多重化機構（daemon + GUI クライアント） |
| window | mux の Session 配下の作業単位。現運用では 1 window = 1 pane |
| 縦タブ | mux の window 一覧を縦に並べるサイドメニュー UI |
| 常時表示モード | 縦タブを固定配置する表示方式（デフォルト） |
| オーバーレイモード | 縦タブをターミナル面の右側に被せて開閉する表示方式 |
