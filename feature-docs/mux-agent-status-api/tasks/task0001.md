# Task Plan: task0001 — agent-status core module + `emterm agent-status` CLI

## Goal

A build-agnostic core module for agent-status types / wire grammar /
parsing / name sanitization, and a stateless `emterm agent-status`
subcommand that emits the OSC to stdout (tmux passthrough included) in
both GUI and CLI-only builds.

## Requirements

FR1, FR2, NFR1 (name sanitization), NFR2 (CLI-only build)

## Scope

### Files to Create
- `src-tauri/src/agent_status.rs` — core types, parse, build, sanitize
  (see IMPLEMENTATION.md Shared Components for the exact contract)
- `src-tauri/src/cli/agent_status.rs` — subcommand: argument handling,
  sequence emission via the core builder, tmux wrapping

### Files to Modify
- `src-tauri/src/lib.rs` — register both modules; `agent_status` core must
  NOT be `gui`-gated
- `src-tauri/src/main.rs` — dispatch the new subcommand (both builds)
- `src-tauri/src/cli/mod.rs` — wire the subcommand alongside
  markdown/json/yaml/image
- `src-tauri/tests/cli_subcommands.rs` — integration coverage for the new
  subcommand

## Design

- Wire grammar is fixed by SPEC FR1: set
  `OSC 777;emterm;agent-status;v=1;state=<s>[;name=<pct-encoded>]`, clear
  `OSC 777;emterm;agent-status;clear`.
- Parsing is whole-or-nothing: any invalid part rejects the entire
  sequence and reports "no event".
- CLI mirrors existing subcommands: stateless, writes to stdout, wraps in
  tmux DCS passthrough when inside tmux (reuse the existing tmux detection
  /wrapping used by markdown/json/yaml/image).
- `emterm agent-status <idle|working|blocked|done> [--name <n>]` and
  `emterm agent-status clear`. Invalid state value → usage error exit 2.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Parser accepts all four states, with and without `name`, and
      returns the matching Set event; `clear` returns the Clear event.
- [ ] AC-2: Parser rejects (returns no event, leaving nothing mutated):
      missing state, unknown state value, duplicate keys, invalid
      percent-encoding.
- [ ] AC-3: Unknown keys are ignored (sequence still accepted).
- [ ] AC-4: Names are percent-decoded, control characters stripped, and
      truncated to 80 characters.
- [ ] AC-5: Builder output round-trips through the parser for every state
      and for clear.
- [ ] AC-6: `emterm agent-status working --name claude` emits exactly the
      built sequence to stdout; inside tmux it is DCS-passthrough wrapped.
- [ ] AC-7: `cargo check --no-default-features` (cli component command)
      passes — the subcommand exists in the CLI-only build.
- [ ] AC-8: Invalid CLI state argument exits with the usage exit code.

## Test Notes

AC-1..AC-5 are pure unit tests in the core module. AC-6/AC-8 via the
existing `cli_subcommands.rs` integration-test style. AC-7 is a build
check (also part of verify). tmux wrapping test follows the existing
subcommands' test approach.

## Out of Scope

- Claude Code hooks integration (non-goal, SPEC A1).
- Documentation file (task0008).
