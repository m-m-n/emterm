# Task Plan: task0007 — agent notifications + settings toggle

## Goal

blocked/done transitions on panes the user is not looking at fire OS
notifications, gated by a new agent-notification setting (default on),
the existing global notification switch, and a per-pane rate limit.

## Requirements

FR9, NFR1 (sanitized names in notification bodies), NFR4 (settings UI i18n)

## Scope

### Files to Modify
- `src-tauri/src/notifications.rs` — agent-notification emission path
  (title/body format per IMPLEMENTATION.md), reusing the existing OS
  notification plumbing
- `src-tauri/src/app.rs` — drain the model's transition queue each frame /
  event tick; visibility check (foreground window + displayed tab);
  per-pane rate limiting
- `crates/app_settings/src/settings.rs` — `agent_status_notifications`
  field, serde default true
- `crates/app_settings/src/types.rs` — type surface if split there
- `src-tauri/src/settings.rs` — GUI runtime plumbing for the new field
- `src-tauri/web-shared/settings/types.ts` — mirror field in the
  AppSettings interface
- `src-tauri/web-shared/settings/settings-sections.ts` — toggle row in the
  appropriate settings section (existing toggle-row pattern)
- `src-tauri/web-shared/i18n/locales/en.json` — label/description strings
- `src-tauri/web-shared/i18n/locales/ja.json` — label/description strings

## Design

- Gating rules are pinned in IMPLEMENTATION.md (transition-only, non-
  visible pane, both settings on, rate limit). This task consumes the
  model's transition queue — it never inspects raw OSC.
- Rate limit: minimum interval per pane between fired notifications;
  suppressed notifications are dropped (not queued).
- Notification body uses the model's name (already sanitized by the core
  module) or a neutral fallback, plus the tab title.
- Settings default: on. Reading the setting happens at fire time so a
  settings change applies without restart.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A transition to blocked or done on a non-visible pane fires
      exactly one notification; transitions to working/idle never fire.
- [ ] AC-2: Transitions on the visible (foreground + displayed) pane do
      not fire.
- [ ] AC-3: No notification when the agent setting or the global
      notification switch is off.
- [ ] AC-4: Two qualifying transitions on one pane inside the rate-limit
      interval fire only the first; a transition after the interval fires.
- [ ] AC-5: Settings round-trip: field defaults to true, deserializes
      null/missing to true, and the TS interface mirrors the field
      (bun typecheck passes).
- [ ] AC-6: Settings panel shows the toggle with ja/en labels from the
      locale files.

## Test Notes

Gating logic extracted into a pure decision helper (inputs: transition,
visibility, settings, rate-limit state → fire/skip) and unit tested for
AC-1..AC-4. Serde default tests follow the existing app_settings
patterns. TS side covered by typecheck + existing settings tests style.

## Out of Scope

- Badge/status-bar visuals (task0006).
