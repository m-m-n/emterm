# Task Plan: task0006 — tab/window badges, status-bar summary, pane-ID copy UI

## Goal

Agent states become visible: aggregated badges on tab/window entries, a
per-state count summary in the status bar's app row, and a click-to-copy
public pane ID in the mux window/pane UI.

## Requirements

FR7, FR8, FR13 (copy affordance), NFR4

## Scope

### Files to Modify
- `src-tauri/src/ui/tab_bar.rs` — badge dot before the tab title
- `src-tauri/src/ui/mux_sidebar.rs` — window-entry badge (same aggregation
  over the window's panes) + pane public-ID click-to-copy row
- `src-tauri/src/ui/mux_dialogs.rs` — ID copy in the window/pane dialog if
  the sidebar is not the natural host (implementer picks ONE host and
  keeps the other unchanged; sidebar preferred)
- `src-tauri/src/ui/status_bar.rs` — right-aligned agent summary segment
  in the app row
- `src-tauri/src/app.rs` — pass model queries (aggregate/counts) to the UI
  layer
- `src-tauri/src/i18n.rs` — new inline t(ja,en) strings if a central list
  exists there (otherwise strings live inline at use sites per the
  existing pattern)

## Design

- Read-only against the AgentStatusModel contract (IMPLEMENTATION.md);
  visual constants (dot size, gap, ring, colors, typography, ordering,
  hide-when-empty) are pinned in IMPLEMENTATION.md Conventions.
- Tabs without any reported state render exactly as today (no reserved
  space, no layout shift).
- The summary renders by semantic-state counts and omits zero-count
  groups; the whole segment disappears when no pane reports a state.
- Copy affordance writes the public pane ID to the system clipboard using
  the app's existing clipboard path; label via t(ja,en) 「pane ID をコピー」
  / "Copy pane ID".
- No animation anywhere.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Tab badge shows the aggregated state per the priority order;
      unseen blocked/done render filled, seen render as ring; working /
      idle have a single (filled / muted) form.
- [ ] AC-2: Tabs and windows with no reported state render without any
      badge and without layout change.
- [ ] AC-3: Status-bar summary shows dot+count groups in the fixed order,
      omits zero counts, and is absent when no state is reported.
- [ ] AC-4: Badge and summary colors come from the md3 role accessors
      (blocked=on_error_container, working=primary,
      done=on_secondary_container, idle=on_surface_variant) — no hex
      literals in the diff.
- [ ] AC-5: The copy affordance places the pane's public ID on the
      clipboard and is labeled via inline t(ja,en).

## Test Notes

Aggregation/formatting logic (which groups appear, in what order, which
color role, filled vs ring) is extracted into pure helpers and unit
tested; egui paint calls stay thin. Clipboard interaction asserted at the
helper boundary. Visual confirmation happens in verify's manual section
(mockup comparison).

## Out of Scope

- Model semantics (task0005 owns them).
- Notifications (task0007).
- Any settings UI (task0007).
