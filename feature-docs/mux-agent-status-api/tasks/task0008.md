# Task Plan: task0008 — user documentation for agent status & API

## Goal

A single documentation page describing the agent-status report surface
(OSC + CLI), the read/send/wait API, pane IDs, and the trust boundary /
privilege notes required by the spec.

## Requirements

NFR1 (trust-boundary and privilege documentation)

## Scope

### Files to Create
- `doc/AGENT-STATUS.md` — the documentation page

## Design

Content requirements (English, matching the repo's existing doc style):

- State model: the four states + no-state, semantic meaning of each,
  clear, last-report-wins.
- Reporting: `emterm agent-status` usage, the OSC wire format, tmux
  passthrough note, SSH transparency.
- A note that integrations must ensure the emitted sequence reaches the
  terminal's PTY (e.g. hook systems that capture stdout will not work
  without a TTY-reaching configuration — unverified territory, phrased as
  a requirement, not a recipe).
- API: read/send/wait usage, `--pane current` / `EMTERM_PANE_ID`, exit
  codes table (from IMPLEMENTATION.md Conventions), wait `--after`
  linearization with the send watermark.
- Trust boundary: any PTY output (including remote/SSH) can forge status
  reports; forgery affects display and notifications only; reported state
  is never an authorization input. read/send are terminal-equivalent
  privilege; the socket is same-user only.
- Notifications: when they fire and the settings that gate them.
