# Task Plan: task0004 — agent API (read/send/wait) daemon handlers + `emterm mux` CLI

## Goal

The daemon answers ReadPane / SendText / WaitAgentState requests; mux
panes get `EMTERM_PANE_ID` injected at spawn; a new `emterm mux
read|send|wait` CLI talks to the daemon socket and maps results to the
conventional exit codes.

## Requirements

FR10, FR11, FR12, FR13 (injection + `current`), NFR1, NFR3

## Scope

### Files to Modify
- `src-tauri/src/mux/ipc/handlers.rs` — request dispatch for the three new
  requests; waiter registry (register / re-evaluate on state change /
  discard on disconnect or pane destroy)
- `src-tauri/src/mux/ipc/pty_spawn.rs` — inject `EMTERM_PANE_ID` (public
  pane ID) into the environment of newly spawned mux panes
- `src-tauri/src/mux/daemon.rs` — waiter re-evaluation hook on accepted
  state changes; timeout scheduling
- `src-tauri/src/mux/cli.rs` — client-side: connect as control client,
  send one request, print the result / map errors to exit codes
- `src-tauri/src/main.rs` — dispatch `emterm mux read|send|wait` (GUI
  build binary)

## Design

- Message shapes / error kinds / exit codes / wait semantics are pinned in
  IMPLEMENTATION.md — implement exactly those.
- read: resolve pane, take the tail N rendered rows (current screen +
  scrollback tail), strip ANSI, clamp N and total bytes to fixed caps,
  return UTF-8 text.
- send: validate (no NUL, size cap), capture revision watermark, then
  write the bytes to the pane PTY as one atomic request; reply with the
  watermark.
- wait: level-triggered per the shared contract; a pane with no state
  blocks until a state is set; `after_revision` filters; timeout via
  deadline; disconnect discards the waiter; pane destruction fails
  pending waiters with pane_gone.
- `--pane current` is resolved CLIENT-side from `EMTERM_PANE_ID`; a
  missing variable is a usage error.
- Requests targeting an unknown ID (including a stale incarnation) →
  unknown_pane. (not_mux_pane is the CLI-facing error name for targets
  outside the daemon's pane set, e.g. plain tabs, which never received an
  EMTERM_PANE_ID — wire-wise identical handling to unknown_pane per the
  shared error contract.)

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: read returns the tail N rows ANSI-stripped; N and byte caps
      are enforced; unknown pane errors.
- [ ] AC-2: send writes exactly the given bytes (no trailing newline
      added), rejects NUL / oversize without writing, and returns the
      pre-write revision watermark.
- [ ] AC-3: wait succeeds immediately when the current state is in the set
      (and revision > after_revision when given); otherwise blocks until a
      qualifying accepted report.
- [ ] AC-4: wait with after_revision does NOT succeed on a state whose
      revision ≤ after_revision (send-then-wait linearization).
- [ ] AC-5: wait timeout resolves with the timeout error; pane destruction
      during wait resolves with pane_gone; client disconnect removes the
      waiter registration.
- [ ] AC-6: Newly spawned mux panes have `EMTERM_PANE_ID` set to their
      public pane ID.
- [ ] AC-7: CLI exit codes match the convention (0 / 2 usage / 3 timeout /
      4 unknown or gone / 5 not_mux_pane / 1 other).
- [ ] AC-8: `--pane current` resolves from `EMTERM_PANE_ID`; missing env →
      usage exit.

## Test Notes

Handler-level unit tests with an in-memory session (existing handlers
test style) cover AC-1..AC-5. AC-6 via pty_spawn env assembly test.
AC-7/AC-8 as CLI arg-mapping unit tests (no live daemon needed —
exit-code mapping is testable from the error kind).
