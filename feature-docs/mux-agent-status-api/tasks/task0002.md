# Task Plan: task0002 — mux_ipc protocol extension

## Goal

The mux_ipc crate carries the new agent-status and agent-API messages with
explicit protocol versioning, without changing any existing message byte
encoding.

## Requirements

FR5, FR10, FR11, FR12, FR13 (message/ID shapes), NFR2

## Scope

### Files to Modify
- `crates/mux_ipc/src/protocol.rs` — new MessageType values, payload
  structs, error payload, public-pane-ID helpers, PROTOCOL_VERSION bump
- `crates/mux_ipc/src/lib.rs` — exports

## Design

- Message shapes, error kinds, and the public pane ID format are pinned in
  IMPLEMENTATION.md Shared Components — implement exactly those.
- New MessageType discriminants continue the existing numbering without
  colliding with any current value.
- Payloads use the same serde-JSON payload style as existing structured
  messages.
- Provide a helper to compose a public pane ID from (incarnation token,
  wire u32) and to parse one back; parsing a malformed ID yields an error,
  never a panic.
- PROTOCOL_VERSION handling: bump the constant; document (in the module's
  doc comment) that handshake mismatch is a clean rejection per existing
  handshake behavior. No silent compatibility shims.
- AgentState serialization shared with the core module's enum via a
  local mirror in mux_ipc (mux_ipc must not depend on the binary crate);
  the string values (`idle|working|blocked|done`) are the contract.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: All new message types round-trip encode → decode with full
      payload equality (each request, each response, the update, the error).
- [ ] AC-2: Every pre-existing MessageType's encoded bytes are unchanged
      (existing codec tests still pass untouched).
- [ ] AC-3: `from_u8` maps every new discriminant and still rejects
      unknown values.
- [ ] AC-4: Public pane ID: compose → parse round-trips; parsing malformed
      strings (empty, no separator, non-hex incarnation, overflow pane
      number) returns an error.
- [ ] AC-5: PROTOCOL_VERSION is bumped exactly once and referenced by the
      handshake path (compile-time constant use, no duplicated literal).
- [ ] AC-6: mux-ipc component test command passes.

## Test Notes

Pure unit tests inside the crate (existing test style). AC-2 relies on the
existing round-trip/codec tests remaining green without edits.

## Out of Scope

- Daemon/GUI handlers for these messages (task0003/0004/0005).
- Incarnation token GENERATION (daemon side, task0003) — this crate only
  composes/parses.
