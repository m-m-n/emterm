# Task Plan: task0001 — Per-region SC-8 rejection dispatch and disposition-pinning tests

## Goal

Replace the uniform rejection answer the grid-ownership guard gives today with an
explicit per-region decision that names the pre-regression local behaviour where
one existed, and pin every region's decided disposition in the unit suite so
reverting any arm fails the tests.

## Design

All cross-cutting contracts — the region-boundary contract, the grid-ownership
predicate's preserved truth table, the wheel-consumer helper's reuse contract, the
rejected-position disposition table, the record-update invariance, and the perform
step's unchanged behaviour — are pinned in IMPLEMENTATION.md ("Shared Components"
and "Cross-task Design Decisions" D1-D7). They are referenced here, not restated.

### Responsibilities inside this task

| Element | Responsibility in this task |
|---|---|
| Grid-ownership input record | Carry two independent top-area region flags in place of the single combined flag. No other field changes meaning. |
| Region-flag population (routing layer) | Fill the two new flags from the geometry already computed for the event, using the boundary the tab-bar wheel guard already uses. |
| Grid-ownership predicate | Keep answering the same question with the same truth table over the decomposed inputs. |
| Wheel rejection branch | Decide per region: arm-bearing regions take the arm the wheel-consumer helper names with tracking-active fixed false; suppressing regions decide nothing. |
| Press rejection branch | Decide per region and per button identity: a middle press with paste enabled takes the paste arm in the four press-reachable regions; every other combination decides nothing. Left and right presses decide nothing everywhere. |
| Motion rejection branch | Unchanged. |
| Inline test module | Hold every automated scenario, built from the existing base-input helpers, runnable with nothing windowed constructed. |

### Decision flow for a guard-rejected position

1. The routing layer's early guards run first, in their existing order; anything
   they consume never reaches the decision.
2. The routing layer builds the grid-ownership input record, including the two new
   region flags.
3. The grid-ownership predicate answers false.
4. The per-region dispatch resolves the answer using IMPLEMENTATION.md's overlap
   precedence (suppressing regions first), then the disposition table for the
   surviving region and the event's kind and button identity.
5. On the wheel path, an arm-bearing region consults the wheel-consumer helper with
   tracking-active fixed false and maps its answer onto the matching local arm.
6. The record updates stay at their default bundle in every case.
7. The perform step runs the named arm, or nothing.

### Test-strengthening obligation

The existing guarded-region test that sweeps every region, button identity and
event kind currently asserts only that no bytes were produced. It is strengthened
so each cell is additionally checked against an expected disposition table, while
keeping its byte-absence assertion. This is the single intended change to a
currently-green assertion (NFR6); every other existing assertion in the module
must still pass unmodified.

## Test Notes

- **Type**: all automated coverage is unit-level, in the inline test module beside
  the decision units. The repository has no E2E harness and none is introduced.
  Inputs are built from the existing base wheel / button / motion input helpers.
- **SPEC scenario mapping**: TS1 → AC-1 and AC-3; TS2 → AC-7 and AC-12; TS3 →
  AC-2; TS4 → AC-4; TS5 → AC-4; TS6 → AC-5; TS7 → AC-6; TS8 → AC-8; TS9 → AC-10;
  TS10 → AC-9; TS11 → AC-8.
- **Test-first order**: the region matrices (TS1, TS4) and the predicate truth
  table (TS8) are the cheapest failing tests to write before any production change,
  because they fail today with the uniform "nothing" answer. Write those first,
  then the decomposition, then the dispatch, then the remaining matrices.
- **Matrix shape**: express the region matrices as a table of (region input,
  expected disposition) cases iterated in one test rather than as one test per
  cell, so adding a region later forces a decision rather than silently passing.
- **Edge cases worth covering explicitly**: tab bar hidden (the tab-bar band
  collapses to zero height); each overlapping region pair named in AC-9; a left
  press inside the resize hot zone with no cached resize direction, which reaches
  the press decision and must answer "nothing" (assumption A1); middle-click paste
  disabled.
- **TDD-awkward areas**: two constraints are not expressible as a unit assertion —
  the guard order being unchanged (NFR3) and the absence of added hot-path cost or
  logging (NFR4). Both are handled by leaving the relevant code untouched and by
  code inspection in the review phase; neither is faked with a test that would pass
  regardless.
- **Wiring confirmation**: the path from a real pointer event through the early
  guards into the decision call cannot be unit-tested, because the handlers take
  mutable host and application state that a test cannot construct. It is covered by
  the manual scenarios in VERIFICATION.md (MS1-MS4), not by this task's automated
  suite.

- Introducing an E2E harness, a test framework crate, or any new dependency.
