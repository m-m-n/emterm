# Task Plan: task0001 — Rust: イベント種別トグルの設定キー追加と通知ゲート拡張

## Goal

エージェント通知のイベント種別トグル 2 キー（`agent_notify_on_done` / `agent_notify_on_blocked`）を設定スキーマに後方互換で追加し、通知発火判定に「対象状態に対応する種別トグル」の段を加える。既存の可視抑止・レート制限・working/idle 非発火のセマンティクスは変更しない。

## Requirements

FR2, FR3, FR4, FR6, FR7, NFR1, NFR2

## Scope

### Files to Create

なし

### Files to Modify

- `crates/app_settings/src/settings.rs` — `AppSettings` に新キー 2 つを追加（既存 `agent_status_notifications` と同一の宣言パターン: 既定 ON・null は既定値へ解決）。Default 実装、全フィールドを列挙する既存 round-trip テストのフィクスチャ、serde 解決テスト（missing / null / 明示 false）を追加・更新
- `src-tauri/src/settings.rs` — GUI ランタイム `Settings` 構造体・フラットキーのローダーミラー・適用処理・既定値に新キー 2 つを追加し、既存 `agent_status_notifications` のローダーテスト群（flat key 適用 / null は既定維持）と同パターンのテストを追加
- `src-tauri/src/notifications.rs` — 発火判定の純粋関数に種別トグルの段を追加し、判定テスト群を拡張
- `src-tauri/src/app.rs` — `App::maybe_notify_agent_transition` が設定から種別トグルを読んで判定関数へ渡すように更新し、App レベルテスト（capturing sink 使用の既存パターン）を追加

## Design

### 設定スキーマ（両 settings ファイル）

- キー名・型・既定値は IMPLEMENTATION.md「Shared Components」の契約に従う（`agent_notify_on_done` / `agent_notify_on_blocked`、bool、既定 ON）。
- 事前条件: 既存 `settings.json` に新キーが無い、または null。事後条件: 既定値 ON に解決され、デシリアライズは失敗しない（AC-6 of SPEC / NFR2）。
- `app_settings` クレートは CLI ビルド（GUI feature 無効）にも含まれるため、追加は GUI 専用機能に依存しない。

### 発火判定（notifications.rs）

- 契約: 発火 = 対象状態が blocked または done ∧ pane 非可視 ∧ 全体通知設定 ON ∧ エージェント通知マスター ON ∧ **対象状態に対応する種別トグル ON** ∧ レート制限外。
- done 遷移には `agent_notify_on_done`、blocked 遷移には `agent_notify_on_blocked` が対応する（IMPLEMENTATION.md 決定 1）。
- 関数は引き続き純粋・無変異。種別トグルの受け渡し形（呼び出し側で状態に応じた 1 値を選んで渡すか、両トグルを渡して関数内で選択するか）は実装者の判断とするが、状態→トグルの対応付けロジックは一箇所に閉じ、テストで独立性を検証できる形にする。
- レート制限の record は実際に発火した場合のみ行う既存契約を維持する（抑止された試行は窓を消費しない）。

### 呼び出し箇所（app.rs）

- `App::maybe_notify_agent_transition` は判定に必要な設定値の読み出しを担う唯一の統合点。`pane_key` は不透明な文字列キーであり、plain タブ / mux ペインのどちら由来でも判定経路は同一（FR7）。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `agent_notify_on_done` / `agent_notify_on_blocked` が両 settings 構造体（`app_settings::AppSettings` と GUI ランタイム `Settings`）に既定 ON で存在し、キー欠落・null・明示 false の各ケースが期待どおり解決される（各ケースにテストがある）
- [ ] AC-2: done 遷移は `agent_notify_on_done` が OFF のとき、他の全段（全体・マスター・非可視・レート制限外）が満たされていても発火しない。blocked 遷移と `agent_notify_on_blocked` についても同様
- [ ] AC-3: 種別トグルは相互独立である: `agent_notify_on_done` OFF でも blocked 遷移は発火し、`agent_notify_on_blocked` OFF でも done 遷移は発火する（テストで両方向を確認）
- [ ] AC-4: `notification_enabled` OFF または `agent_status_notifications` OFF のとき、種別トグルの値に関わらず発火しない（階層ゲート）
- [ ] AC-5: 既存挙動の回帰なし: working/idle 非発火・可視ペイン抑止・30 秒/ペインのレート制限・抑止時にレート制限窓を消費しない挙動がすべて維持される（既存テスト群がグリーンのまま、かつ種別ゲート追加後の状態での回帰テストがある）
- [ ] AC-6: `App::maybe_notify_agent_transition` 経由の判定が `pane_key` の形式（plain タブ形式のキー / mux ペイン形式のキー）に依存せず、同一入力に対して同一の判定を返すことをテストで確認する
- [ ] AC-7: rust の build / test コマンドに加え、CLI ビルド確認（`--no-default-features` の check）が通る（`app_settings` の変更が CLI ビルドを壊さない）
