# Task Plan: task0002 — TS: 設定パネル「エージェント」カテゴリと種別トグル UI

## Goal

設定パネルに「エージェント」カテゴリを新設し、エージェント通知マスターを通知カテゴリから移設したうえで、その配下にイベント種別トグル（ターン終了・質問待ち）を配置する。TS 側の `AppSettings` ミラーと en/ja の i18n ラベルを揃える。

## Requirements

FR1, FR2, FR3, FR5, FR6, NFR3

- `src-tauri/web-shared/settings/sections/agent-section.test.ts` — セクションレンダラーのテスト

### Files to Modify

- `src-tauri/web-shared/settings/settings-panel.ts` — categories ゲッターへのカテゴリ追加（id: `agent`）、`CATEGORY_ICONS` へのアイコン追加、コンテンツ描画分岐へのケース追加、レンダラー import

- `src-tauri/web-shared/settings/sections/terminal-behavior-section.test.ts` — 同上
- `src-tauri/web-shared/i18n/locales/en.json` — カテゴリラベル・セクション文言の追加、マスタートグル文言の移設
- `src-tauri/web-shared/i18n/locales/ja.json` — 同上

## Design

### カテゴリ（settings-panel.ts）

- categories ゲッターの `notification` カテゴリの直後に id `agent` のカテゴリを追加する（enabled: 常に有効）。ラベルは i18n キー `settings.categories.agent` を参照する。
- `CATEGORY_ICONS` に既存アイコン群と同スタイル（24px viewBox・currentColor 塗りのモノクロ単色）のアイコンを追加する。図案はエージェントを表すもの（例: ロボット/スマートトイ系の意匠）。MD3 トークン体系上、色はアイコン側に持たせず currentColor に従う（既存アイコンと同じ扱い）。
- コンテンツ描画分岐に `agent` ケースを追加し、新セクションレンダラーを呼び出す。

### セクションレンダラー（agent-section.ts）

- 既存セクションと同じ契約: 引数は描画先パネル要素と SectionContext。既存共通コンポーネント（セクション見出し・トグル）を用いる。
- 構成（上から順に）:
  1. セクション見出し（`settings.agent.title`）
  2. エージェント通知マスター — 既存キー `agent_status_notifications` に紐付くトグル
  3. ターン終了通知トグル — キー `agent_notify_on_done`
  4. 質問待ち通知トグル — キー `agent_notify_on_blocked`
- 各トグルは現在値を settings の対応キーから読み、変更時に SectionContext の保存関数で当該キーを保存する。
- 設定キー名は IMPLEMENTATION.md「Shared Components」の契約に従う（本タスクはキー名を発明しない）。
- 説明文はゲート挙動（IMPLEMENTATION.md 決定 2）と一致させる: 種別トグルはマスター・全体設定が ON のときに効く個別スイッチであり、「ターン終了」= done 遷移、「質問待ち」= blocked 遷移。

### 移設（notification-section.ts）

- 既存の `agent_status_notifications` トグルのブロックを通知セクションから除去する。他のトグル（全体設定・タブアクティビティ・Triggers 群）はそのまま。

### i18n（en.json / ja.json）

- 追加: `settings.categories.agent`、`settings.agent.*` 名前空間（セクションタイトル、マスターと種別 2 トグルの label / description）。
- 移設: マスタートグルの label / description は `settings.notification.agentStatusNotifications*` から `settings.agent.*` 配下の対応キーへ移し、旧キーは削除する（参照元が無くなるため）。
- en / ja の両方でキー集合を一致させる（NFR3）。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: 設定パネルのカテゴリ一覧に「エージェント」（id: `agent`）が追加され、アイコンが登録されており、選択（描画分岐）で agent セクションが描画される
- [ ] AC-2: agent セクションにマスタートグルと種別トグル 2 つが上から「マスター → ターン終了 → 質問待ち」の順で描画され、各トグルの表示状態が currentSettings の対応キー値を反映する
- [ ] AC-3: 各トグルの操作で対応する設定キー（`agent_status_notifications` / `agent_notify_on_done` / `agent_notify_on_blocked`）の保存が呼ばれる
- [ ] AC-4: notification セクションに `agent_status_notifications` トグルが表示されない（重複表示なし）
- [ ] AC-5: TS の `AppSettings` に新キー 2 つが boolean で存在し、名前が IMPLEMENTATION.md Shared Components の契約と一致する
- [ ] AC-6: en / ja 両ロケールにカテゴリラベルとセクション内全トグルの label / description キーが存在し、レンダラーテストで訳文が解決される（i18n キー名の素通り表示にならない）。旧 `settings.notification.agentStatusNotifications*` キーはどこからも参照されない
- [ ] AC-7: `bun test` と `bun run typecheck` が通る（既存セクションテストのフィクスチャ更新を含む）

## Test Notes

- テストは既存 `mux-section.test.ts` のパターンを踏襲する（bun:test + happy-dom + i18n 初期化、AppSettings 全体を構築するフィクスチャ、レンダラーを直接呼んで DOM を検証、保存呼び出しはコンテキストのスタブで捕捉）。
- AC-1 はカテゴリ定義とアイコン登録の検証を含む。ナビゲーションのクリック操作そのものの E2E は不要（描画分岐の単体検証で足りる）。
- AC-4 は notification セクションのレンダラーを呼び、agent 用トグルが描画されないことを確認する。
- AC-6 のロケール検証は、テスト内で ja / en を切り替えて主要ラベルが翻訳文字列に解決されることを確認する（既存テストの AC-3 パターン）。
- 必須キー追加により全フィールド構築フィクスチャを持つ既存テスト 2 ファイルが型エラーになるため、フィクスチャ更新を先に行うと typecheck が安定する。
