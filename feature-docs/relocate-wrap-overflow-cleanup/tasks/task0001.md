# Task Plan: task0001 — Close the relocation overflow-deletion gap and document the invariant

## Goal

Make the wrap-relocation path delete the overflow-table entries of the cells
whose overflow marker it clears, so the invariant both ASCII writers' marker
gate depends on holds in code, and state that invariant plus the deletion
obligation at both gates. No observable behavior change.

## Design

Cross-task decisions D1-D4, the overflow-entry lifecycle contract, and the
removal-shape convention are in IMPLEMENTATION.md; this section adds only what
is specific to this task.

### 1. Relocated base write (column 0 of the new row) — FR1, FR3

Precondition: the relocation has vacated the old cell, wrapped to the next row
and resolved that row's absolute index; the relocated content has just been
written into column 0.

Behavior, in order:

1. Write the relocated content into the cell (unchanged).
2. If the cell is now overflow-bound, insert the content into the table and
   into the reverse index — the existing branch, unchanged.
3. Otherwise, attempt to remove the entry at (column 0, new absolute row).
4. Only if that attempt reports an entry was actually removed, remove the same
   (row, column) pair from the reverse index.

Postcondition: no entry exists at that key unless the cell reports
overflow-bound; the reverse index agrees with the table.

### 2. Relocated spacer write (column 1 of the new row) — FR2, FR3

Precondition: column 1 exists on the new row and has just been rewritten as
the relocated pair's spacer, which always clears the overflow marker.

Behavior: attempt to remove the entry at (column 1, new absolute row) with no
branch on the cell's state, then update the reverse index only if the attempt
actually removed an entry. When column 1 does not exist, the whole spacer write
— including this removal — is skipped, as it already is today.

Postcondition: the spacer cell has no table entry and no reverse-index entry.

### 3. Invariant documentation at both ASCII writers — FR4, FR5, NFR1, NFR5

At each ASCII writer's marker-gated cleanup block (the slow writer in
`print_handler.rs` and the fast path in `terminal_dispatch.rs`), the existing
comment is extended to state two things in the writer's own words:

- the invariant it depends on: an overflow-table entry exists at a
  (column, absolute row) key only while that cell reports overflow-bound;
- the obligation the invariant creates: any write that clears a cell's overflow
  marker owns removing that cell's own table entry, because the ASCII overwrite
  no longer sweeps entries whose marker it did not observe.

Neither gate's condition changes, and the pre-write marker read stays where it
is. Reverting either gate to the ring-wide "table is non-empty anywhere" form
is prohibited (D1).

### 4. Robustness — NFR3

| Condition | Required behavior |
|---|---|
| The relocation's line feed scrolls (the widened base sat on the last row) | Removals proceed against the resolved new absolute row; no panic, no out-of-range access, eviction path undisturbed |
| Column 1 does not exist on the new row | The spacer-side removal is skipped without panic |
| No entry is present at a removal key | The removal attempt reports nothing removed and the reverse-index update is skipped |

### 5. Fallback branch — AC5 / D3

Approach (a) above is the plan. If it is shown infeasible during
implementation, take approach (b) instead (both ASCII gates return to the
self-healing form) and report the infeasibility evidence together with the
argument for how the per-byte cost budget is then covered. Do not switch
silently: taking (b) is a reportable plan deviation.
