# Task Plan: task0001 — Pin the ghost-drag latch mechanisms and the focus-loss semantics with seam-level regression tests

## Goal

Deliver five regression tests in the existing window-host test module that
fail whenever any of the four named mechanisms regresses, while leaving
production behaviour untouched.

## Requirements

## Scope

### Files to Modify

## Design

Read this together with IMPLEMENTATION.md, whose Shared Components table

restated here.

### The four guarded mechanisms

| Label | What it guarantees | The regression it guards against |
|---|---|---|
| reset-clears-held-gesture-slot | a tracking-inactive reset clears only the gesture slots of buttons that are NOT reported held | a reset that clears every slot, dropping the gesture of a button the user is still holding |
| held-unaware-apply-entry-point | both the button path and the wheel path hand the live held-button value to the held-aware apply entry point | either path applying with a default (nothing held) value, which degrades the rule above to clearing everything |
| ungated-no-owner-left-release | a left release with no recorded gesture owner still completes the selection while a drag is in flight | a release that unconditionally decides "nothing", stranding the drag flag as true forever |
| focus-loss-gate-inversion | focus loss terminates a drag exactly when the left button is NOT physically held | either arm being flipped: terminating a still-held drag, or failing to terminate an unheld one |

### Test 1 — wheel notch during a live left drag (TS-1, FR1)

Guards reset-clears-held-gesture-slot and held-unaware-apply-entry-point on
the wheel path.

1. Seed a fresh mouse-report record set whose left gesture slot records a
   local owner, standing for the press that started the selection drag.
2. Decide one wheel notch with tracking inactive and the position on the
   grid, then apply it through the wheel path's apply-and-fold unit, passing
   a held-button value that reports left as held.
3. Read the left gesture slot back: it must still report the local owner.
   This is the assertion that fails when the reset clears held slots, or when
   the held value stops reaching the apply entry point.
4. Decide a left release from those records with the drag-in-flight signal
   true: the disposition must name the selection-completion arm.
5. Drive the termination seam with the drag flag set, a pending anchor
   present and resolved selection text, then hand the returned destinations
   to the publish seam with a recording sink: the drag flag must read false
   and the sink must record a PRIMARY write.

### Test 2 — second button press during a live left drag (TS-2, FR2)

Guards the same two mechanisms on the BUTTON path. Identical to test 1 except
for step 2, which decides a press of a second button (middle or right) and
applies it through the held-aware apply entry point with the same
left-is-held value. Steps 3 to 5 assert the same observations.

### Test 3 — no-owner left release matrix (TS-3, FR1, FR2)

Guards ungated-no-owner-left-release directly, with no apply step.

1. From an empty record set, decide a left release with the drag-in-flight
   signal true: the disposition must name the selection-completion arm.
2. Decide the same release with the signal false: the disposition must be
   nothing.
3. Decide a middle release and a right release with the signal true: both
   must be nothing, so the fallback stays left-only.

### Test 4 — focus loss with left still held (TS-4, FR3(a), FR5)

Guards focus-loss-gate-inversion on the preserved arm.

1. Assert the focus-loss predicate answers "do not terminate" for in-flight
   and held. The doc comment must state that this arm is deliberate (A1,
   IMPLEMENTATION.md D4), not a defect awaiting repair.
2. Empty the records the way the focus-loss site does, then decide the later
   left release from those emptied records with the drag-in-flight signal
   true: it must still name the selection-completion arm, because that
   release is the drag's only remaining terminator.
3. Drive the termination seam and the publish seam as in test 1: the drag
   flag must read false and PRIMARY must be recorded.

### Test 5 — focus loss with left not held (TS-5, FR3(b))

Guards focus-loss-gate-inversion on the terminating arm.

1. Assert the focus-loss predicate answers "terminate" for in-flight and not
   held.
2. Drive the termination seam exactly as the focus-loss arm's publish half
   does: the drag flag must read false, the pending anchor must come back as
   consumed, and the recording sink must record a PRIMARY write.

### Shared authoring rules

- Each test builds its own records and state inline; nothing is shared
  between tests (NFR4).
- Each test names exactly one mechanism label in its doc comment (FR6) and
  states which requirement and which acceptance criterion it serves.
- Assertions target observable contracts only — disposition values, the
  gesture-slot read, the drag flag, the pending anchor, recorded sink calls —
  and carry messages that name the mechanism (NFR5).
- No window-host, winit, GPU-surface, PTY or terminal-mode type is named
  anywhere in the new tests (NFR1).

## Test Notes

- **The tests ARE the deliverable.** There is no production code to drive, so
  the usual red-green ordering is replaced by a mutation probe: for each of
  AC-1 to AC-5, apply the named mutation to the production seam LOCALLY,
  observe the new test fail, then REVERT the mutation and observe it pass.
  The revert is mandatory — AC-7 and the change-set check in VERIFICATION.md
  fail if any probe survives into the diff. Record each probe's observed
  failure in the task's test record. The revert is also gated inside this
  task rather than being left to a later phase: after the last probe has been
  restored and BEFORE anything is committed, compare the whole working tree
  against the task's base revision. Any byte-level difference in a file other
  than the single file named in Files to Modify means a probe (or an
  incidental edit) survived, and the task FAILS in that state — it is neither
  committed nor advanced to a later phase until the difference is removed and
  the comparison is repeated cleanly. Record the outcome of that comparison —
  that it ran, and what it reported — in the task's test record alongside the
  per-probe failures (AC-8).
- **Do not weaken existing coverage.** The apply layer's reset rule already
  has unit coverage inside the mouse-report module's own test module, and the
  focus-loss gate already has a truth-table test and a source-scan test. The
  new tests add the full press → interruption → release → terminate → publish
  sequence on top of them; none of the existing tests may be edited, renamed,
  merged or deleted (FR5).
- **Reuse the existing recording selection sink** already present in the test
  module rather than introducing a second double.
- **Determinism**: the new tests must pass with and without a single-thread
  constraint; verify by running them by name filter without that option
  several times (NFR4, NFR6).
- **Edge cases worth an explicit assertion**: the no-owner release with the
  drag-in-flight signal false (must stay nothing), and middle and right
  releases with the signal true (must stay nothing) — both inside TS-3.
- **Cite symbols, not line numbers**, in every comment (A6).
