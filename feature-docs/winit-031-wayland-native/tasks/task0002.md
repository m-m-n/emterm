# Task Plan: task0002 — synthetic key press gate

## Goal

Synthetic keyboard events (X11 FocusIn replays) never reach key handling:
no PTY write, no keybinding dispatch.

## Requirements

FR4

## Scope

### Files to Create

- (none)

### Files to Modify

- `src-tauri/src/window_host.rs` — keyboard-input arm: honor the winit
  `is_synthetic` flag per the IMPLEMENTATION.md Synthetic key press gate
  contract

## Design

Per the IMPLEMENTATION.md Shared Components contract: at the top of the
keyboard-input path, before any state mutation, keybinding matching, IME
forwarding decisions, or PTY write, a synthetic press is dropped (optionally
logged at warn level with key identity for post-mortem diagnosis of the
stray-`q` class of bugs). Non-synthetic events proceed unchanged. The
`Released` arm keeps its current behavior for non-synthetic events; synthetic
releases are dropped by the same gate.

Extract the drop decision into a small pure helper so it is unit-testable
without a winit event loop. This task must compile against the winit version
currently on the integration branch (0.30 or 0.31 — the flag exists in
both); do not use any 0.31-only API.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A keyboard event flagged synthetic produces no PTY bytes and no
      keybinding dispatch — unit test on the extracted decision helper
- [ ] AC-2: A non-synthetic keyboard event is processed exactly as before —
      unit test on the helper (both press and release cases)
- [ ] AC-3: `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path
      src-tauri/Cargo.toml --lib` passes

## Test Notes

- The winit event structs are hard to construct in tests; test the extracted
  decision helper (inputs: synthetic flag, press/release state) rather than
  driving the full event handler.
- Edge case: key repeat events are never synthetic in winit — no special
  handling needed, but do not gate on repeat.

## Out of Scope

- Any winit version migration work (task0001 owns it)
- Changes to IME handling beyond the gate placement
- Wayland-side behavior changes (winit generates no synthetic events there)
