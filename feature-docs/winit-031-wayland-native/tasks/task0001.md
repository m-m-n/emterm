## Design

### Backend selection (FR2)

Implement the Backend selection decision contract from IMPLEMENTATION.md as
a pure, unit-testable function in `main.rs` (or an adjacent private module).
`build_event_loop()` consumes its result: Auto builds the event loop without
forcing; ForceWayland / ForceX11 apply the respective backend via the 0.31
platform-extension mechanism. The startup log line explaining X11 forcing is
replaced by a factual line naming the selected decision.

### Migration order (within this task)

1. Bump the dependency; enumerate compile errors as the migration worklist.
2. Migrate the event-loop construction, application handler, and window
   creation surfaces first (everything else depends on their types).
3. Migrate per-event arms (keyboard / IME / drag / focus / resize etc.),
   preserving existing behavior for every arm except the drag set (D3).
4. Keep the `is_synthetic` information available at the keyboard arm — do
   not discard fields task0002 depends on.
5. Green the three build variants (default GUI check, `--no-default-features`
   check, Windows xwin check) and the lib test suite.

### D&D (FR3)

Per IMPLEMENTATION.md D3: `DragDropped` delivers a path list; feed each path
in order into the existing SFTP upload entry point; empty list is a no-op.
`DragEntered` / `DragMoved` / `DragLeft` map to the existing hover
visual-state handling that `HoveredFile` / `HoveredFileCancelled` drove.
Remove or simplify the manual batching in `sftp/ui.rs` that compensated for
the missing completion signal, keeping its externally observable behavior
(one upload flow per drop batch).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `Cargo.toml` pins winit to exactly 0.31.0-beta.2 with a comment
      marking it beta and to be bumped at 0.31 stable (NFR3)
- [ ] AC-2: Backend decision function returns ForceWayland for
      `EMTERM_BACKEND=wayland`; ForceX11 for `EMTERM_BACKEND=x11` with X11
      present; Auto for `x11` without X11 present, for empty, and for
      unknown values — each case covered by a unit test (FR2)
- [ ] AC-3: `build_event_loop()` contains no environment-based X11 forcing:
      the Auto decision never calls a force-X11 API (verified by unit tests
      on the decision function + code path review) (FR2)
- [ ] AC-4: Drop-path handling maps a non-empty path list to the existing
      upload entry point in list order and ignores an empty list — covered
      by unit tests on the extracted handling logic (FR3)
- [ ] AC-5: `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path
      src-tauri/Cargo.toml` exits 0 (FR1)
- [ ] AC-6: `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path

## Test Notes

- AC-2/AC-3/AC-4 are unit tests on pure logic (decision function, drop-path
  mapping) — write them first.
- AC-5–AC-8 are build/test gates run via the approved command strings.
- Windowing behavior itself (actual Wayland startup, real drags) is manual
  verification in the verify phase, not TDD-covered — do not attempt to
  spawn event loops in tests.

- Version bumps of wgpu / egui / wry beyond what compilation strictly forces
- Windows behavior changes beyond keeping the target compiling
- Removing the X11 backend or `EMTERM_BACKEND` support
