# Task Plan: task0001 — tmux socket discovery + chooser integration + attach

## Goal

The new-tab chooser lists live tmux sockets (rescanned on every open) and confirming a tmux row opens a new tab attached to that socket.

## Requirements

FR1, FR2, FR3, NFR1, NFR2, NFR3

## Scope

### Files to Create
- `src-tauri/src/tmux_sockets.rs` — tmux socket discovery: resolve the socket directory (`TMUX_TMPDIR` env var, fallback to the tmp dir named after the real UID), enumerate entries, keep only socket-type files that accept a Unix-domain connection, return name + absolute path pairs

### Files to Modify
- `src-tauri/src/lib.rs` — declare the new module (Unix + `gui` feature gated)
- `src-tauri/src/ui/profile_selector.rs` — add a tmux row kind to the chooser state, row rendering, and selection decode (`Choice` gains a tmux-socket variant; `row_to_choice` handles the extended ordering: Global → profiles → tmux sockets)
- `src-tauri/src/app.rs` — `open_new_tab_chooser`: run discovery, pass the socket list to the chooser, and open the chooser when profiles are empty but sockets exist (fast-path change per IMPLEMENTATION.md); `confirm_profile_selection`: on the tmux variant, spawn a new tab via the existing overrides path with executable `tmux` and argv `-S {socket_path} attach` (path as a discrete argv element)

## Design

- Discovery contract: input = environment (socket dir); output = list of (socket name, absolute path), possibly empty; never returns an error to the caller. Missing directory → empty list; unreadable or non-socket or connect-refused entries → skipped. No external process is spawned. Probe is a plain Unix-domain connect that must not hang (non-blocking connect or short timeout).
- Chooser ordering: existing rows keep their positions; tmux rows are appended after profiles. Row label makes the socket name identifiable (e.g. prefix `tmux:`). Zero sockets → no tmux rows, chooser identical to today.
- Attach tab: an ordinary tab whose PTY runs the tmux client; no interaction with the built-in mux subsystem (IMPLEMENTATION.md decision).
- Platform gating: discovery module and tmux row plumbing are Unix-only; Windows code paths compile without them and chooser behavior on Windows is unchanged.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Discovery over a directory containing a live listening socket, a stale (non-listening) socket file, and a regular file returns exactly the live socket with its name and absolute path
- [ ] AC-2: Discovery with a missing socket directory returns an empty list without error
- [ ] AC-3: Selection decode maps every row index correctly for the combined ordering Global → N profiles → M tmux sockets (including M=0 giving today's behavior)
- [ ] AC-4: Confirming a tmux row produces spawn overrides with executable `tmux` and argv exactly `-S {socket_path} attach`
- [ ] AC-5: With profiles empty and at least one live socket, "+" opens the chooser (does not silently spawn a plain tab); with profiles empty and no sockets, the existing immediate-spawn fast path is preserved
- [ ] AC-6: Rust GUI check, `--lib` tests, CLI-only check, and Windows cross-check all pass (commands in workflow.yaml `project.components`)

## Test Notes

- AC-1/AC-2: unit tests in the discovery module using a temp directory with a real bound Unix listener, a socket file whose listener was closed, and a plain file. TDD-friendly.
- AC-3/AC-4/AC-5: unit tests at the chooser/App decision layer — test the pure decode/override-construction logic rather than driving egui rendering. If the current decode helpers are not directly testable, structure the new logic so its decision core is a pure function.
- AC-6: build/test commands, run as-approved from the project root.
- Known base-tree flakiness: `tabs.rs` replay tests can fail nondeterministically in parallel; `--test-threads=1` stabilizes (project test notes).

## Out of Scope

- Per-session breakdown inside a socket, session previews, status badges
- Background/continuous socket watching
- Sockets at arbitrary `-S` paths outside the standard socket directory
- Any change to the built-in mux subsystem or its UI
- Windows-side tmux support
