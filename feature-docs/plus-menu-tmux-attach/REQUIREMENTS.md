# +メニューからの tmux セッションアタッチ - 要件定義書

## 1. 概要

### 1.1 背景
Notion を起点に tmux 上で Claude Code を起動する仕組みを構築した。起動された tmux セッションの現在の状況を簡単にモニタリングできる導線が eMterm 側に必要になった。

### 1.2 目的
eMterm の右上「+」メニュー（新規タブ chooser）から、稼働中の tmux ソケットを選んで新規タブでアタッチできるようにする。

### 1.3 スコープ
- tmux ソケットの検出（標準ソケットディレクトリの走査）
- +メニューの一覧への tmux ソケット項目の表示
- 項目クリックで対応ソケットへ `tmux attach` する新規タブの起動

## 2. ビジネス要件

### 2.1 ビジネス目標
外部システム（Notion Webhook）が起動した tmux 上の Claude Code セッションを、eMterm からワンクリックで開いてモニタリングできるようにする。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| eMterm 利用者 | tmux セッションで走る Claude Code 等の状況を確認したい開発者 |

### 2.3 期待される効果
- tmux セッションへのアタッチ操作（ターミナルを開いて `tmux attach` を打つ）が +メニューのクリック 1 回になる
- 稼働中の tmux ソケットの有無が +メニューを開くだけで分かる

## 3. ユースケース

### 3.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | tmux ソケットへアタッチする | 利用者 | 高 |
| UC02 | 稼働中 tmux ソケットの有無を確認する | 利用者 | 中 |

### 3.2 ユースケース詳細

#### UC01: tmux ソケットへアタッチする

**アクター**: 利用者

**事前条件**:
- tmux サーバーが 1 つ以上のソケットで稼働している

**基本フロー**:
1. 利用者がタブバー右上の「+」ボタンをクリックする
2. chooser に既存項目（Global Settings / プロファイル）に加えて稼働中の tmux ソケットが一覧表示される
3. 利用者が tmux ソケット項目をクリックする
4. 新規タブが開き、対応するソケットへ `tmux attach` した状態になる

**代替フロー**:
- 稼働中のソケットが 1 つも無い場合、tmux 項目は表示されない（既存の chooser 挙動のまま）

**事後条件**:
- 新規タブ内で tmux クライアントが対象セッションにアタッチされている

## 4. 機能要件

### 4.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | tmux ソケット検出 | tmux 標準ソケットディレクトリを走査し、生存ソケットを列挙する | 高 |
| F02 | +メニューへの表示 | chooser を開くたびに検出結果を一覧へ表示する | 高 |
| F03 | クリックでアタッチ | 項目クリックで新規タブを開き対応ソケットへアタッチする | 高 |

### 4.2 機能詳細

#### F01: tmux ソケット検出

**説明**: `$TMUX_TMPDIR`（未設定時は `/tmp/tmux-{uid}/`）配下のソケットファイルを列挙し、接続可能なもののみを生存ソケットとして扱う。

**入力**:
- なし（環境変数 `TMUX_TMPDIR` と実 UID から探索ディレクトリを決定）

**出力**:
- ソケット名（ファイル名。例: `default`, `notion`）とソケットの絶対パスのリスト

**ビジネスルール**:
- ソケット種別（S_IFSOCK）でないファイルは無視する
- 接続不能な stale ソケットは表示しない
- 列挙時に外部プロセス（tmux コマンド）を起動しない

**エラーケース**:
| エラー | 条件 | 対応 |
|--------|------|------|
| ディレクトリ不在 | tmux 未使用環境 | 空リストを返す（エラーにしない） |
| 権限エラー | ディレクトリ/ソケットへアクセス不可 | 該当エントリをスキップする |

#### F02: +メニューへの表示

**説明**: 既存の new-tab chooser（Global Settings + プロファイル一覧のモーダル）の一覧に、検出した tmux ソケットを項目として追加表示する。

**ビジネスルール**:
- chooser を開くたびに再走査する（常駐監視はしない）
- 検出 0 件なら tmux 項目・見出しを表示しない
- 表示ラベルはソケット名が識別できる形式にする（例: `tmux: default`）

#### F03: クリックでアタッチ

**説明**: tmux ソケット項目の選択確定で新規タブを起動し、そのタブの PTY で `tmux -S {socket_path} attach` を実行する。

**エラーケース**:
| エラー | 条件 | 対応 |
|--------|------|------|
| tmux コマンド不在 | PATH に tmux が無い | タブ内にシェル/PTY のエラーがそのまま表示される（専用ハンドリングはしない） |
| アタッチ失敗 | 選択後にサーバーが終了していた | tmux 自身のエラー出力がタブ内に表示される |

## 5. 非機能要件

### 5.1 パフォーマンス要件
- ソケット走査は chooser 表示を体感で遅延させない（外部プロセス起動なし、接続確認は非ブロッキング/短時間で完了）

### 5.2 セキュリティ要件
- 走査対象は自 UID のソケットディレクトリのみ
- ソケットパスはコマンド引数として直接 PTY 起動 API に渡す（シェル文字列連結をしない）

### 5.4 保守性要件
- ログ出力: 走査失敗等は既存の logging 機構（env_logger）に従う

### 5.5 互換性要件
- Unix（Linux）専用機能とし、Windows ビルド・CLI-only ビルド（`--no-default-features`）を壊さない

## 6. UI/UX要件

### 6.1 画面設計要件
既存の new-tab chooser モーダルの一覧に項目を追加する。新規画面・新規コンポーネントは作らない。

## 9. 制約条件

### 9.1 技術的制約
- 実装は既存の chooser（`profile_selector`）と PTY 起動 API（`SpawnOverrides` / `spawn_new_tab_with_overrides`）を利用する
- `-S` で任意パスに作られたソケットは検出対象外（標準ソケットディレクトリのみ）

## 11. 成功基準

### 11.1 受け入れ基準
- [ ] tmux のソケットを検出できる
- [ ] tmux のソケットがある場合に +メニューのリストに表示される
- [ ] +メニューで tmux のソケットをクリックすると対応する内容にアタッチされる

## 12. テストシナリオ

### 12.1 テスト観点
- [ ] 正常系: 稼働中ソケットが列挙され、選択でアタッチコマンドの新規タブが起動する
- [ ] 異常系: ソケットディレクトリ不在・stale ソケット・権限エラーで chooser が壊れない
- [ ] 境界値: ソケット 0 件（項目非表示）・複数ソケット（全件表示）
- [ ] 互換性: Windows ビルド・CLI-only ビルドがコンパイルできる

## 13. 用語定義

| 用語 | 定義 |
|------|------|
| tmux ソケット | tmux サーバーとクライアントが通信する Unix ドメインソケット。`tmux -L {name}` で `$TMUX_TMPDIR`（既定 `/tmp/tmux-{uid}/`）配下に作られる |
| chooser | eMterm の「+」ボタンで開く新規タブ選択モーダル（Global Settings + プロファイル一覧） |
