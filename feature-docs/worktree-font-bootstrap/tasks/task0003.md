# Task Plan: task0003 — CI job that runs the bootstrap verification

## Goal

Every push and pull request runs the bootstrap verification, so the regression
that produced this feature cannot return unnoticed — closing the gap that the
repository's CI has no Rust job at all today.

## Requirements

FR7

## Scope

### Files to Create

None.

### Files to Modify

- `.github/workflows/ci.yml` — gains one job that prepares a Rust build
  environment and invokes the bootstrap-verification entry point, alongside the
  existing bun job.

## Design

Read IMPLEMENTATION.md first. D7 pins this job's shape, D6 pins the isolation
property the job must not defeat, and the Shared Components table pins the
verification entry point's invocation contract — its path, its argument-free
invocation from the repository root, its exit-code meaning, and the host
facilities it needs.

**The verification script is created by a different task and is therefore
absent from this task's own worktree.** Wire the job against the pinned
contract, not against an inspection of the file. The job's correctness here is
verified structurally (the job exists with the right triggers, runner,
preparation steps, invocation and cache policy); its green run against the real
script belongs to the feature-wide verification.

### Job responsibilities

| Element | Requirement |
|---------|-------------|
| Triggers | The same push and pull-request triggers as the existing bun job. The workflow already declares them at workflow level, so the new job inherits them without any trigger edit. |
| Runner | The same Linux runner family the existing bun job uses. |
| Independence | A separate job, not a step appended to the bun job, so neither can delay or mask the other. |
| Rust toolchain | Installed by the job itself, since the workflow has no Rust job today. |
| System libraries | The desktop libraries the GUI-featured build links against must be installed before the verification runs, mirroring the set the release workflow's Linux job already installs. |
| Build caching | Caching the Rust build is permitted and expected, since the verification performs real builds. |
| Font cache | **Forbidden.** No step may restore, save or otherwise pre-populate bundled fonts, because the un-fetched scenario's whole value depends on starting empty. |
| Opt-out | Left unset, so the job exercises the automatic path rather than the stop path. |
| Invocation | Invokes the verification entry point per its pinned contract, from the repository root, with no arguments, and lets its exit status decide the job's result. |
| Timeout | A job-level time limit generous enough for real builds plus one real download, so a hang fails the job instead of consuming the runner budget. |

### Why the system libraries matter

The reported command builds with the GUI feature enabled, so it links the
desktop stack. On a bare runner that link step fails for reasons unrelated to
fonts, which would make the job fail for the wrong reason and eventually get
muted. The release workflow's Linux job already establishes the required
package set; reuse it rather than deriving a new one.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `.github/workflows/ci.yml` contains a new job, separate from the
      existing bun job, that runs on the same push and pull-request triggers
      and on the same Linux runner family, and that invokes the
      bootstrap-verification entry point at its contracted path, from the
      repository root, with no arguments — with the job's success determined by
      that invocation's exit status.
- [ ] AC-2: Before that invocation the job installs a Rust toolchain and the
      desktop system libraries the GUI-featured build links against, and it
      declares a job-level time limit sufficient for real builds plus one real
      download.
- [ ] AC-3: The job contains no step that restores, saves or otherwise
      pre-populates bundled fonts, and does not set the opt-out switch.
- [ ] AC-4: The existing bun job is unchanged, the workflow's trigger block is
      unchanged, and `.github/workflows/release.yml` — including its explicit
      acquisition step and its font cache — is not modified.

## Test Notes

- These criteria are structural properties of a workflow file, so verify them
  by parsing the changed workflow and asserting on its structure — the job's
  presence, its runner, the absence of any font-cache step, the invoked command
  and its arguments, the declared timeout, and the byte-level invariance of the
  bun job and of the release workflow. Write those assertions before editing
  the workflow.
- Validate that the edited file still parses as a workflow document; a
  syntactically broken workflow silently stops running rather than failing
  loudly, which is the exact failure mode FR7 exists to prevent.
- A green run of the new job against the real verification script is a
  feature-wide verification item (TS7), not a criterion this task can close on
  its own, because the script it invokes is created by another task.
- Do not weaken the job to make it pass in isolation — for example by making
  the invocation tolerate a missing script. The job must fail when the entry
  point is absent.

## Out of Scope

- `scripts/verify-font-bootstrap.sh` — task0002 owns it. Do not create it,
  stub it, or inline any part of its behavior into the workflow.
- `src-tauri/build.rs` — task0001 owns it.
- `.github/workflows/release.yml` — unchanged (NFR7).
- The existing bun job's steps, the workflow's trigger block, and any other
  workflow file in the repository.
- Reporting, notification, badge or branch-protection configuration around the
  new job.
