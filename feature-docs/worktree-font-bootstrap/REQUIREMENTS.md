# worktree-font-bootstrap - 要件定義書

## 1. 概要

### 1.1 背景

`git worktree add` で作成した新しいチェックアウトには、バンドルフォントのバイナリが存在しない。この状態で報告されたコマンド

```
CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib
```

を実行すると、`src-tauri/build.rs` がフォントの不在を検出してビルドを中断し、テストが 1 件も実行されない。

現状の確認結果として、`build.rs` の `check_bundled_fonts()` は既に対処方法を示すメッセージを出力している。したがって報告のうち「案内を出して止まる」側は既に満たされており、実際に残っている不具合は「新規 worktree でテストが 0 件しか走らない」ことのみである。

### 1.2 目的

- 新規 worktree のチェックアウトが、そのままライブラリテストスイートを実行できる状態になること。
- バンドルフォントの前提条件を、既に検証済みの唯一の取得経路（`scripts/fetch-fonts.sh`）で満たすこと。
- この退行が自動的に検出されること。

### 1.3 スコープ

対象は `src-tauri/assets/fonts/` のブートストラップと、それを検証するための CI 配線（FR7）に限る。

対象外は `viewer/dist`、`settings/dist`、`src-tauri/icons/` である。前 2 者については `build.rs` が既に緩やかに劣化する（debug プロファイルでは `cargo:warning`、`PROFILE == "release"` のときのみ panic）挙動を持ち、いずれも `cargo test --lib` を妨げない（FR8）。

## 2. ビジネス要件

### 2.1 ビジネス目標

| ID | ビジネス目標 |
|----|--------------|
| BO1 | 新規に作成した `git worktree add` のチェックアウトが即座にテスト可能であること。`CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib` が、テスト 0 件で `build.rs` 内で中断するのではなく、ライブラリテストスイートを実行すること。 |
| BO2 | バンドルフォントの前提条件が、2 つ目の分岐した仕組みではなく、既に検証済みの唯一の正規取得経路（`scripts/fetch-fonts.sh`）で満たされること。 |
| BO3 | 退行が自動検出されること。報告されたコマンドを未取得状態から実行するチェックが、すべての push と pull request で走ること（現状、CI には Rust ジョブが 1 つも無い）。 |

### 2.2 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| 新規 worktree で作業する開発者 | `git worktree add` 直後のツリーで `cargo test --lib` を実行する |
| CI | push / pull request 時にブートストラップ検証スクリプトを実行する（FR6、FR7） |
| パッケージング・オフライン環境のビルド実行者 | ネットワークに出ないビルドを行う（FR3、NFR7） |

### 2.3 期待される効果

- 報告された再現手順が再現しなくなる（AC1）。
- フォント取得の仕組みが 1 つに保たれる（FR5）。
- 同じ退行が再び入った場合、CI が失敗して検出する（AC7、AC8）。

### 3.2 ユースケース詳細

#### UC01: 新規 worktree でライブラリテストを実行する

**アクター**: 開発者

**事前条件**:
- `git worktree add` 直後で、`src-tauri/assets/fonts/` にフォントバイナリが存在しない。
- ネットワークが利用できる。

**基本フロー**:
1. 開発者が `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib` を実行する。
2. `CARGO_FEATURE_GUI` が設定されているため、`build.rs` が 7 つのバンドルフォントの存在を確認する（FR1）。
3. 1 つ以上欠けており、FR3 のオプトアウトが有効でないため、`build.rs` が `scripts/fetch-fonts.sh` を 1 回だけ呼び出す。取得先は、ビルド中の worktree 自身の `src-tauri/assets/fonts` に固定される（FR2）。
4. 7 つすべてが揃った時点でビルドが続行し、ライブラリテストスイートが実行される。

**代替フロー**:
- フェッチが非ゼロ終了した場合、または取得後もいずれかのフォントが欠けている場合は、FR4 のメッセージを出してビルドを停止する。
- FR3 のオプトアウトが有効な場合は、フェッチを一切試みずに FR4 のメッセージを出して停止する。

**事後条件**:
- ライブラリテストスイートが実行され、実行テスト数が 0 でない（AC1）。
- 7 つのバンドルフォントがその worktree の `src-tauri/assets/fonts` に存在し、その worktree の外にはフォントファイルが書かれていない（AC2）。

#### UC02: フェッチを禁止した状態でビルドする

**アクター**: パッケージング・オフライン環境のビルド実行者

**事前条件**:
- FR3 のオプトアウトが有効である。
- フォントが欠けている。

**基本フロー**:
1. ビルド実行者が GUI ビルドを実行する。
2. `build.rs` はフェッチを一切試みない。
3. `build.rs` が FR4 の対処方法つきメッセージを出して停止する。

**事後条件**:
- ネットワークアクセスが発生していない（AC3）。

#### UC03: ブートストラップ退行を CI で検出する

**アクター**: CI

**事前条件**:
- push または pull request が発生している。

**基本フロー**:
1. `.github/workflows/ci.yml` の新しいジョブが、FR6 のブートストラップ検証スクリプトを実行する。
2. スクリプトが、キャッシュ復元を伴わない隔離された未取得状態から報告コマンドを実行する。
3. ライブラリテストスイートが実行されなければ失敗する。

**事後条件**:
- 修正済みのツリーでは成功し、修正を取り消したツリーでは失敗する（AC7、AC8）。

## 4. 機能要件

### 4.1 機能一覧

| ID | 機能名 | 説明 | 状態 |
|----|--------|------|------|
| FR1 | GUI ゲート付きバンドルフォント存在確認の維持 | `CARGO_FEATURE_GUI` 設定時のみ 7 パスを確認する | resolved |
| FR2 | 不在検出時の自動フェッチ | 欠けていて、かつオプトアウト無効なら `scripts/fetch-fonts.sh` を 1 回呼ぶ | resolved |
| FR3 | フェッチを禁止する明示的オプトアウト | オプトアウト有効時はフェッチせず即停止する | resolved |
| FR4 | 失敗時は既存の対処方法つきメッセージで停止 | 現行実装のメッセージをそのまま使う | resolved |
| FR5 | `scripts/fetch-fonts.sh` を唯一の取得経路とする | 2 つ目の取得手段を導入しない | resolved |
| FR6 | ブートストラップ検証スクリプト | 未取得・フェッチ失敗・取得済みの 3 経路を検証する | resolved |
| FR7 | ブートストラップ検証スクリプトの CI 配線 | `ci.yml` に新ジョブを追加する | resolved |
| FR8 | スコープ境界 | フォントのブートストラップと CI 配線に限定する | resolved |

### 4.2 機能詳細

#### FR1: GUI ゲート付きバンドルフォント存在確認の維持

**説明**: `src-tauri/build.rs` は、`CARGO_FEATURE_GUI` が設定されているときに限り、バンドルフォントの欠落を検出し続ける。対象は以下の同一の 7 つの相対パスである。

- `assets/fonts/Noto-COLRv1.ttf`
- `assets/fonts/NotoSansCJKjp-Regular.otf`
- `assets/fonts/NotoSansCJKjp-Bold.otf`
- `assets/fonts/NotoEmoji-Regular.ttf`
- `assets/fonts/Inconsolata-Regular.otf`
- `assets/fonts/Inconsolata-Bold.otf`
- `assets/fonts/NotoSansSymbols2-Regular.ttf`

`--no-default-features` の CLI ビルドは、この確認に到達する前に従来どおり return する。

**ビジネスルール**:
- 対象パスの集合を変更しない。
- GUI ゲートの位置を変更しない。

#### FR2: 不在検出時の自動フェッチ

**説明**: FR1 の確認で 1 つ以上のバンドルフォントが欠けていると判明し、かつ FR3 のオプトアウトが有効でないとき、`build.rs` は `scripts/fetch-fonts.sh` を、ビルドスクリプトの 1 回の実行につき正確に 1 回だけ呼び出す。

**入力**:
- FR1 の確認結果（欠落しているフォントの有無）
- FR3 のオプトアウトの状態

**出力**:
- `scripts/fetch-fonts.sh` の実行と、その終了コード

**ビジネスルール**:
- 取得先は、ビルド中の worktree 自身の `src-tauri/assets/fonts` ディレクトリに固定する。
- 取得先はビルドスクリプトの manifest の位置から導出する。プロセスの cwd からは導出しない。
- 共有の場所や他 worktree の場所を取得先にしない。

#### FR3: フェッチを禁止する明示的オプトアウト

**説明**: 自動フェッチを明確に禁止するオプトアウトを設ける。これにより、オフライン・サンドボックス・パッケージングのビルドがネットワークに到達することがなくなる。オプトアウトが有効かつフォントが欠けているとき、`build.rs` はフェッチを一切試みず、FR4 の対処方法つきメッセージを出して即座に停止する。

**ビジネスルール**:
- オプトアウトは「フェッチを試みない」ことを意味する。「失敗を許容する」ことではない。

**備考**: 具体的な機構と名称は SPEC.md で 1 つに固定する（想定事項 a5）。

#### FR4: 失敗時は既存の対処方法つきメッセージで停止

**説明**: 以下のいずれかの場合、`build.rs` はビルドを停止する。

- フェッチの試行が非ゼロ終了した
- 試行後も 7 つのフォントのいずれかが欠けている
- FR3 のオプトアウトが有効である

**エラーケース**:

| エラー | 条件 | 対応 |
|--------|------|------|
| フォント欠落 | 上記 3 条件のいずれか | 現行実装と同一のメッセージでビルドを停止 |

停止時のメッセージは、現在すでに実装されているものをそのまま使う。

```
build_rs.font_missing: bundled font missing at {path}
Run `make fetch-fonts` (or `bash scripts/fetch-fonts.sh`) to download bundled fonts.
```

#### FR5: `scripts/fetch-fonts.sh` を唯一の取得経路とする

**説明**: `scripts/fetch-fonts.sh` がフォント取得の唯一の仕組みである。FR2 の自動試行にも、FR4 の人間向けメッセージで案内するコマンドにも、同じスクリプトを使う。

**ビジネスルール**:
- 2 つ目の取得手段を導入しない。
- スクリプトの HTTPS のみ・ファイル単位の SHA256 固定・冪等・アトミック移動という挙動を、変更せずそのまま使う。

#### FR6: ブートストラップ検証スクリプト

**説明**: 報告された状況を、キャッシュ復元の無い隔離された未取得状態から再現するブートストラップ検証スクリプトを追加する。スクリプトは報告コマンド

```
CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib
```

を実行し、ライブラリテストスイートが実行されない場合に失敗する。

**カバーする経路**:
- 未取得状態
- フェッチ失敗（FR4 のメッセージを伴う明確な停止）
- 取得済み状態（ネットワークアクセスが発生しないこと）

#### FR7: ブートストラップ検証スクリプトの CI 配線

**説明**: `.github/workflows/ci.yml` に、FR6 のスクリプトを実行する新しいジョブを追加する。トリガーは既存の bun ジョブと同じ push / pull_request とし、チェックが実際に走るようにする。

**ビジネスルール**:
- 未取得状態のシナリオでは、フォントキャッシュを復元しない。

#### FR8: スコープ境界

**説明**: 変更は `src-tauri/assets/fonts/` のブートストラップと、FR7 が必要とする CI 配線に限る。`viewer/dist`、`settings/dist`、`src-tauri/icons/` は対象外とする。前 2 者は `build.rs` が既に緩やかに劣化する挙動を持ち（debug プロファイルでは `cargo:warning`、`PROFILE == "release"` のときのみ panic）、`cargo test --lib` を妨げない。

## 5. 非機能要件

### 5.1 非機能要件一覧

| ID | 名称 |
|----|------|
| NFR1 | 非ヘルメティック性の受容と明示 |
| NFR2 | フォントが揃っているときはネットワークに出ない |
| NFR3 | サプライチェーン完全性の維持 |
| NFR4 | 書き込みの封じ込め |
| NFR5 | CLI 専用ビルドは無変更 |
| NFR6 | 再ビルドの churn を起こさない |
| NFR7 | パッケージング・リリースビルドの決定性 |

### 5.2 非機能要件詳細

#### NFR1: 非ヘルメティック性の受容と明示

ネットワークに到達し `OUT_DIR` の外に書き込むビルドスクリプトは非ヘルメティックであり、Cargo 自身のガイダンスに反する。このトレードオフは、完了条件が「報告された再現コマンドが再現しなくなること」である以上、受け入れる。ただし隠さず、SPEC に明示的に記述する。

#### NFR2: フォントが揃っているときはネットワークに出ない

7 つのフォントが存在し SHA256 が一致しているビルドは、ネットワークアクセスを一切行わない。`scripts/fetch-fonts.sh` の冪等なスキップが、定常状態のビルドをオフラインで安全にしている。

#### NFR3: サプライチェーン完全性の維持

自動化の経路は `scripts/fetch-fonts.sh` を弱めない。HTTPS のみ（`--insecure` を使わない）、アトミック移動の前にファイル単位の SHA256 検証を行い、未検証・部分的なファイルを `src-tauri/assets/fonts` に残さない。

#### NFR4: 書き込みの封じ込め

ビルドスクリプトは、ビルド中の worktree 自身の `src-tauri/assets/fonts` ディレクトリと、その一時的なステージング先にのみ書き込む。並行してビルドされる兄弟 worktree が互いのツリーに書き込むことはなく、共有の場所や cwd 依存の取得先を使わない。

#### NFR5: CLI 専用ビルドは無変更

```
CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path src-tauri/Cargo.toml --no-default-features
```

はフォント確認もフェッチもネットワークアクセスも行わない。現状どおりである。

#### NFR6: 再ビルドの churn を起こさない

ビルド中のフォント取得によって cargo が再ビルドループに入ったり、以降の呼び出しのたびに再ビルドが強制されたりしてはならない。フォントが揃った後は、ビルドスクリプトの再実行条件が安定していること。

#### NFR7: パッケージング・リリースビルドの決定性

配布・リリースビルドは決定的であり続ける。`.github/workflows/release.yml` は明示的な `bash scripts/fetch-fonts.sh` ステップとキャッシュを維持するため、そこでは自動経路が no-op になる。パッケージングビルドは FR3 のオプトアウトを有効にして、暗黙のフェッチを禁止できる。

### 5.3 本要件で定義しない項目

パフォーマンス目標値、可用性目標値、ブラウザサポート、API バージョンについては、本フィーチャーでは定義しない。

## 9. 制約条件

### 9.1 技術的制約

- ビルドスクリプトがネットワークに到達し `OUT_DIR` の外に書き込むことは非ヘルメティックであり、Cargo のガイダンスに反する（NFR1）。
- `scripts/fetch-fonts.sh` は bash スクリプトであるため、FR2 の自動フェッチはビルドスクリプトのホストに bash が存在することに依存する（想定事項 a4）。
- `src-tauri/build.rs` は `check_bundled_fonts()` の中で 7 つのフォントパスそれぞれに `cargo:rerun-if-changed={path}` を出力している（存在確認を通過した直後に出力するため、フォントが欠けている場合は 1 つも出力しないまま panic する）。ビルドスクリプトからこれらのファイルを書くことは cargo の変更追跡と相互作用するため、NFR6 は前提として仮定するのではなく意図的に満たす必要がある（想定事項 a7）。

### 9.2 ビジネス上の制約

- 取得経路を 2 つに増やさない（FR5）。
- 変更範囲をフォントのブートストラップと CI 配線に限る（FR8）。

### 9.3 スケジュール制約

該当なし。

### 9.4 宣言された変更集合

このフィーチャー固有のパスは手動で列挙せず、create-plan で `workflow.yaml` の各タスクの `files` から導出する（`references/phases/create-plan-phase.md`）。

**デフォルトメンバー**（SPEC作成者が明示的に除外しない限り、常に宣言に含まれる）:
- `feature-docs/worktree-font-bootstrap/**`
- `test-docs/worktree-font-bootstrap/**`

**意味論**:
- デフォルトのメンバーは、SPEC作成者が明示的に除外しない限り宣言に含まれる。除外は意図的な絞り込みであり、記載漏れによる省略ではない。
- この宣言はスーパーセット（superset）の主張であり、実際の変更集合は宣言に含まれる（CONTAINED IN）必要がある。実際には生成されないパスが宣言されていても違反にはならない。

- [x] スコープは `src-tauri/assets/fonts/` のブートストラップと CI 配線に限り、`viewer/dist` / `settings/dist` / `icons/` は対象外とする（FR8）。
