# Task Plan: task0001 — EL/ED cursor-row wide-pair partner cleanup

## Goal

EL (CSI K) and ED (CSI J) cursor-row erases no longer leave orphaned wide-pair halves at the erase-range edges: the surviving base or spacer outside the range is blanked to a width-1 space with its attributes preserved, matching ECH's existing behavior and the reference implementations (xterm / Alacritty / WezTerm), guarded by inline regression tests.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

- (none)

### Files to Modify

- `crates/term_core/src/csi_screen.rs` — add wide-pair partner cleanup around the four EL/ED cursor-row `clear_line_range` call sites; refresh the ECH scope comment; add inline regression tests.

## Design

Follow IMPLEMENTATION.md D1 (approach (a): local pre-capture, nothing folded into `clear_line_range`), D2 (uniform symmetric boundary pattern), and D3 (full-line clears unchanged). Contracts of the two primitives used — `blank_wide_pair_split` and `clear_line_range`, both unchanged — are pinned in IMPLEMENTATION.md Shared Components.

The four cursor-row call sites and their erase ranges:

| Call site | Sequence | Erase range on cursor row | Materially relevant edge |
|-----------|----------|---------------------------|--------------------------|
| `handle_erase_in_display` mode 0 (`csi_screen.rs:14`) | ED 0 | `[cursor.col, cols)` | left: spacer at range start → blank base at col−1 (FR3 → FR1 rule) |
| `handle_erase_in_display` mode 1 (`csi_screen.rs:25`) | ED 1 | `[0, cursor.col+1)` | right: base at range end−1 → blank spacer at col+1 (FR3 → FR2 rule) |
| `handle_erase_in_line` mode 0 (`csi_screen.rs:49`) | EL 0 | `[cursor.col, cols)` | left, same rule as ED 0 (FR1) |
| `handle_erase_in_line` mode 1 (`csi_screen.rs:53`) | EL 1 | `[0, cursor.col+1)` | right, same rule as ED 1 (FR2) |

Per-site flow — identical at all four sites, mirroring ECH (`csi_screen.rs:74-93`):

1. Determine the range start/end for the site (table above).
2. Before the clear, record from the pre-erase grid: (p1) the cell at the range start has width 0 (spacer); (p2) the cell at range end − 1 has width 2 (base). Capture must precede the clear — the BCE fill destroys the width information.
3. Call the existing range clear exactly as today (NFR2: BCE fill, overflow clearing, dirty-row marking unchanged).
4. If p1 holds and the range start > 0: blank the partner base at start − 1 via `blank_wide_pair_split`.
5. If p2 holds: blank the partner spacer at the range end via `blank_wide_pair_split` (an out-of-bounds range end is a safe no-op, NFR4).

Partner blanking changes only character content and width; fg/bg/flags/hyperlink are preserved (FR5) — this is what distinguishes the partner cell from the BCE-filled cells inside the range.

Non-cursor-row work inside ED 0/1 (the full-row `clear_line` loops), EL 2, ED 2, and ED 3 (scrollback sentinel) stay untouched (FR4 / D3).

**Comment refresh**: the comment above ECH's pre-capture (`csi_screen.rs:74-78`) currently justifies keeping the cleanup local with "shared with ED/EL (out of scope for this cleanup)". Update it so it still states the cleanup is never folded into `clear_line_range` itself, and now reflects that the ED/EL cursor-row call sites perform the same local cleanup — the durable reason being that `clear_line_range` is a shared primitive whose full-row callers must not gain partner behavior (IMPLEMENTATION.md D1).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TS-1; FR1, FR5): with a wide character whose base is at col−1 and spacer at col, and the cursor on the spacer, EL 0 (`ESC[K`) leaves the base at col−1 as a width-1 space with its original fg/bg preserved (distinct from the erase's current BCE bg), and `[col, cols)` is BCE-filled.
- [ ] AC-2 (TS-2; FR2, FR5): with the cursor on a wide character's base at col (spacer at col+1), EL 1 (`ESC[1K`) leaves the spacer at col+1 as a width-1 space, and `[0, col+1)` is BCE-filled.
- [ ] AC-3 (TS-3; FR3, FR5): repeating AC-1/AC-2 through ED 0 (`ESC[J`) and ED 1 (`ESC[1J`) produces identical cursor-row results, and the rows below (ED 0) / above (ED 1) are fully cleared.
- [ ] AC-4 (TS-4; FR1, FR2): cursor on the base with EL 0 (both halves inside the range) triggers no extra blanking outside the range; cursor on the spacer with EL 1 (base also inside the range) likewise.
- [ ] AC-5 (TS-5; NFR4): cursor at col 0 with EL 0 (full-row range, no left partner) and cursor positioned so col+1 == cols with EL 1 (right partner check out of bounds) are safe no-ops for the cleanup step.
- [ ] AC-6 (TS-6; FR4): EL 2 and ED 2 over a row containing wide pairs produce a fully BCE-cleared row with no behavioral change attributable to partner cleanup.
- [ ] AC-7 (FR6, NFR1, NFR2): the full term_core `--lib` suite passes with every pre-existing test unmodified; the change touches only `crates/term_core/src/csi_screen.rs` (no dependency or primitive changes); the ECH scope comment (`csi_screen.rs:74-78`) is refreshed per the Design section.

## Test Notes

- Every criterion is unit-testable as an inline `#[cfg(test)]` test in `csi_screen.rs`. Mirror the construction style of the existing wide-pair ECH tests (`test_erase_characters_spacer_start_blanks_left_base`, `test_erase_characters_base_at_range_end_blanks_right_spacer`): drive content through print handling, set distinct cursor attributes on the wide character, position the cursor, invoke the erase handler, assert per-cell character / width / color, include an unrelated wide pair elsewhere on the row to prove no over-reach, and assert row dirtiness.
- Test names follow the crate convention `<subject>_<scenario>_<expected>` (see `test/README.md`).
- Attribute preservation (FR5): give the wide character distinct fg/bg, switch the active bg before erasing so the BCE color differs, then assert the blanked partner keeps its original colors — this distinguishes partner blanking from BCE fill.
- TDD order: the AC-1/AC-2/AC-3 tests fail against the current code (proven failure paths); AC-4/AC-5/AC-6 are regression guards expected to pass before and after the fix and must keep passing.
- Run the suite with the project's verbatim test command: `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path crates/term_core/Cargo.toml --lib`
