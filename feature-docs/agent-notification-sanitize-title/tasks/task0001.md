# Task Plan: task0001 — Sanitize the tab title inside `agent_notification_body`

## Goal

Agent-status notification bodies never carry unsanitized OSC 0/2-derived tab
titles: `agent_notification_body` passes the embedded title through the
existing `sanitize_title`, and unit tests pin that CSI / control-character
titles cannot survive into the body (review finding 7dd413bdd9289905).

## Requirements

FR1, FR2, NFR1, NFR2

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/notifications.rs` — pass the embedded tab title through the
  existing `sanitize_title` inside `agent_notification_body`; add pinning
  unit tests to the file's inline test module.

## Design

### Verified current state (integration worktree)

- `sanitize_title` exists in `src-tauri/src/notifications.rs` (strips CSI
  sequences, drops C0 / DEL / C1 control characters, caps raw input, then
  truncates to 100 characters) and is already used by the tab-activity
  notification path.
- `agent_notification_body(transition, tab title, locale) -> body string`
  exists in the same file and currently embeds the tab title verbatim in the
  format "{agent name}: {tab title} ({state message})". The agent name is
  sanitized upstream (guaranteed by the core agent-status module); the tab
  title is not sanitized anywhere on this path.

### Change

1. Inside `agent_notification_body`, pass the incoming tab title through the
   existing `sanitize_title` before embedding it into the body string.
   Sanitizing inside the function makes it the choke point: both existing
   call sites are closed in one place, and any future call site is closed by
   construction.
2. Add unit tests to the file's inline test module pinning the postcondition
   below.

### Contract (postcondition of `agent_notification_body`)

- The returned body contains no escape / CSI byte sequences and no C0 / DEL /
  C1 control characters originating from the tab title.
- The body format "{agent name}: {sanitized tab title} ({state message})" is
  otherwise unchanged: a normal title is embedded exactly as before.
- Accepted parity side effect: `sanitize_title`'s raw-input cap and
  100-character truncation now also apply to the embedded title — identical
  to the tab-activity path's behavior (NFR1); intended, not a regression.

### Explicit non-changes

- `sanitize_title` itself is not modified (NFR1 — no new sanitization
  implementation, no behavior change to the shared sanitizer).
- The tab-activity notification path (`notification_body` and its callers)
  is not modified (NFR2).
- No call-site change: callers keep passing the raw tab title; the function
  sanitizes internally.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `agent_notification_body` passes the embedded tab title through
      the existing `sanitize_title` internally, so both call sites are
      closed at this single choke point (FR1, NFR1).
- [ ] AC-2: given a tab title containing a CSI sequence (e.g. ESC [ ... m),
      the returned body contains no escape or CSI bytes (TS1).
- [ ] AC-3: given a tab title containing C0 control characters, no control
      character survives into the returned body (TS2).
- [ ] AC-4: a normal tab title is embedded into the body exactly as before —
      the existing `agent_notification_body` tests (name fallback, body
      format) stay green unmodified (TS3, NFR2).
- [ ] AC-5: no new sanitization implementation is added, and neither
      `sanitize_title` nor the tab-activity notification path is modified
      (NFR1, NFR2).
- [ ] AC-6: the full default-feature `--lib` test suite passes (TS4).

## Test Notes

- Every criterion is unit-testable in `notifications::tests` (the file's
  inline `#[cfg(test)] mod tests`), which runs under default features —
  `agent_notification_body` is a pure function, so no GUI event loop is
  involved.
- Test naming follows the project convention
  `<subject>_<scenario>_<expected>`.
- AC-2 / AC-3: assert on the absence of the byte classes (no escape byte, no
  character in the C0 / DEL / C1 ranges) in the returned body, not on one
  exact fixture string — the tests pin the property, not a formatting
  accident.
- AC-4 doubles as the regression guard: the existing
  `agent_notification_body` tests must pass without modification.
- AC-6 (TS4): run the whole `--lib` suite; if the known `tabs.rs` replay
  flake appears, re-run with a single test thread (see VERIFICATION.md).

## Out of Scope

- Any change to the tab-activity notification path or to `sanitize_title`'s
  own behavior (input cap / truncation / stripped character classes).
- Making the notification path asynchronous.
- Changes to notification gating, settings, rate limiting, or dispatch
  (`notify-rust` usage).
- New sanitization implementations or new dependencies.
