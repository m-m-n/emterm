# Task Plan: task0001 — Remove the profile Launch action and its locale key

## Goal

The settings panel's Profiles section renders only the default toggle, Edit,
Duplicate and Delete actions for each profile; the production sources contain
no `profile:launch` event; and the `settings.profiles.launch` key is gone from
both locale files.

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2

## Scope

### Files to Create

None.

### Files to Modify
- `src-tauri/web-shared/settings/sections/profiles-section.ts` — delete the Launch action block
- `src-tauri/web-shared/settings/sections/profiles-section.test.ts` — add the tests for AC-1, AC-2 and AC-3
- `src-tauri/web-shared/i18n/locales/en.json` — remove the launch entry of the settings.profiles object
- `src-tauri/web-shared/i18n/locales/ja.json` — remove the launch entry of the settings.profiles object

## Design

### Profiles section (profiles-section.ts)

- Delete the Launch block: the "Launch (open new tab with this profile)"
  comment, the action-button creation labelled with the
  `settings.profiles.launch` text, and its click handler that dispatches the
  `profile:launch` custom event on the document.
- Postcondition: for every rendered profile, the `.profile-item-actions`
  container holds exactly four buttons, in this order: the default toggle
  (Unset Default when the profile is the default, Set as Default otherwise),
  Edit, Duplicate, Delete.
- The Add Profile button, the empty state, the info area, the drag handle and
  the drag reorder setup are unchanged.
- The module-private action-button helper stays, because the four remaining
  buttons still use it. The `.profile-action-btn` / `.profile-item-actions`
  CSS rules stay.

### Locale files (en.json, ja.json)

- Remove the `launch` entry ("Launch" / "起動") from the `settings.profiles`
  object in both files.
- Every other entry is unchanged, including unrelated wording that contains
  "launch" / "起動" (en.json `shellPathDesc` and `sshNotConfigured`, ja.json
  `sshNotConfigured`).
- Both files remain valid JSON and keep identical key sets (IMPLEMENTATION.md
  Conventions).

### Tests (profiles-section.test.ts)

- The new tests go in new describe block(s) named for the Launch removal,
  separate from the existing drag reorder blocks.
- The existing drag reorder test cases keep their names and bodies
  (IMPLEMENTATION.md Conventions). The file's render helper may be extended
  backward-compatibly, for example to render a profile marked as the default.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR4; SPEC.md TS-1): Rendering the Profiles section with profiles [A (default), B], each `.profile-list-item`'s `.profile-item-actions` holds exactly four buttons whose texts are, in order, the i18n text of `settings.profiles.unsetDefault` (for A) or `settings.profiles.setDefault` (for B), then `settings.profiles.edit`, `settings.profiles.duplicate` and `settings.profiles.delete`; no button's text equals "Launch" or "起動".
- [ ] AC-2 (FR2; SPEC.md TS-2): With a listener for the `profile:launch` event registered on the document and the section rendered with one non-default profile, clicking every action button of that profile's item never invokes the listener.
- [ ] AC-3 (FR3; SPEC.md TS-3): Read as parsed data, en.json and ja.json each have a `settings.profiles` object with no `launch` property.
- [ ] AC-4 (FR2, FR3; SPEC.md TS-4): No git-tracked file under `src-tauri/` other than `*.test.ts` files contains the string `profile:launch` or `settings.profiles.launch` (IMPLEMENTATION.md D3).
- [ ] AC-5 (FR4, NFR1; SPEC.md TS-5): The existing drag reorder test cases in `profiles-section.test.ts` keep their names and bodies and pass; `bun test` and `bun run typecheck` both exit with code 0.
- [ ] AC-6 (NFR2; VERIFICATION.md TS-6): Every source file this task changes is under `src-tauri/web-shared/`; no file under `src-tauri/src/` changes.

## Test Notes

- Red first: before the deletion, the AC-1 test fails (five buttons), the
  AC-2 test fails (clicking Launch invokes the listener) and the AC-3 test
  fails (the `launch` entry is present).
- AC-1: compute the expected button texts with the same i18n lookup the
  section uses, so the test holds in either UI language; the check against the
  literal "Launch" / "起動" texts is in addition to that.
- AC-2: clicking Edit opens the profile editor in the test document; remove
  whatever that click adds so that later tests start from a clean document.
  Clicking the default toggle, Duplicate and Delete reaches only the test's
  stub context (its save and re-render recorders).
- AC-3: check the locale files as data, not through the i18n lookup — a
  lookup of a missing key may fall back to returning the key itself, which
  would hide a leftover entry. The way the files are loaded keeps
  `bun run typecheck` passing.
- AC-4: verified by the search command of VERIFICATION.md TS-4, not by a unit
  test. Test files are excluded because the AC-2 test names the event.
- AC-5: run the full `bun test` and `bun run typecheck`.
- AC-6: verified from the task's changed-file list (VERIFICATION.md TS-6).

## Out of Scope

- Removing or changing the action-button helper or the `.profile-action-btn` /
  `.profile-item-actions` CSS rules.
- Changing locale wording outside the `settings.profiles` launch entry (for
  example `sshNotConfigured` or `shellPathDesc`).
- Any native (Rust) change, and any replacement way to open a tab with a
  profile.
- Renaming or rewriting the existing tests in `profiles-section.test.ts`.
- Tests for the Add Profile, default toggle, Edit, Duplicate or Delete
  behaviors beyond AC-1 and AC-2.
