# Task Plan: task0001 — Region-scroll transcription in the terminal core

## Goal

Lines that leave a scroll region whose top margin is the topmost screen row
are written to scrollback instead of being discarded, under exactly the five
conditions the specification fixes; in every other situation the terminal
behaves byte-for-byte as it does today.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, FR13, FR14, NFR1, NFR2, NFR4, NFR5

## Scope

### Files to Create

(none)

### Files to Modify

- `crates/term_core/src/ring_buffer.rs` — the region (non-full-screen) branch
  of the scroll-up routine gains the transcription condition, the
  transcription itself via the existing blank-push eviction routine, the
  restoration of rows below the bottom margin, and the region-path render
  bookkeeping. The full-screen branch, the downward-scroll helper and the
  eviction routine itself are not modified.
- `crates/term_core/src/terminal_core.rs` — the per-core transcription gate
  member and its public setter, per IMPLEMENTATION.md Shared Components.
- `crates/term_core/src/csi_scroll.rs` — new region-scroll tests placed beside
  the existing region-scroll tests, if that is where they belong; the scroll-up
  and scroll-down handlers themselves are unchanged.

## Design

### Where the decision lives

The condition is evaluated once, inside the shared scroll-up routine, on the
branch that is taken when the scroll region is not the whole screen
(IMPLEMENTATION.md D1). Every caller of that routine — the line-feed path
(reached from the control-character handler, the print-wrap path and the ASCII
fast path), the index and next-line escape handlers, and the scroll-up control
sequence — therefore inherits identical behaviour without any per-caller
change.

### The condition

All five clauses must hold for the outgoing lines to be transcribed; any one
of them failing selects today's in-place region shift instead.

1. The region's top margin is the topmost screen row.
2. No left or right margin is set. The terminal does not implement horizontal
   margins today, so this clause is trivially true; it is written into the
   condition anyway, as a forward constraint on any future horizontal-margin
   support (FR6).
3. The alternate screen is not active. This is an explicit mode check: the
   alternate screen shares one ring and one scrollback with the main screen,
   so nothing else would exclude it.
4. The core has scrollback capacity greater than zero.
5. The transcription gate is enabled.

The bottom margin is deliberately unconstrained: a region that ends above the
last screen row still transcribes.

### The transcribing path

1. The number of lines transcribed equals the already-clamped scroll count
   (the count is clamped to the region height before this point), so a
   scroll-up request larger than the region transcribes exactly the region
   height and no more.
2. Outgoing lines are pushed oldest-first through the existing blank-push
   eviction routine, so the scrollback order matches the on-screen order and
   the existing compressed row format, interning, reference counting and
   wrap-flag propagation are reused unchanged (NFR1).
3. That routine rotates the ring and blanks what becomes the new bottom
   viewport row. When the region's bottom margin is above the last screen row,
   the rows below the bottom margin must be restored to their original screen
   positions as part of the same operation, and the bottom-margin row must end
   up blank, filled the way the current implementation fills it.
4. Render bookkeeping on this path marks only the region's rows as changed and
   emits no full-screen scroll event: the canvas-shift optimization the
   full-screen branch uses for a single-line scroll is valid only when the
   entire screen scrolled (FR13).

### The non-transcribing path

Unchanged: the in-place region shift with delete-line semantics, producing no
scrollback line, no eviction, and the same screen result as before this
feature (FR2). This is also the required behaviour when the gate is disabled,
when the alternate screen is active, and when there is no scrollback capacity.

### Paths that must not change

The full-screen branch; the downward-scroll helper and its callers (the
scroll-down control sequence and the reverse-index escape); the line-insert
and line-delete handlers, which reach the grid helpers directly and must keep
producing no scrollback lines (FR7); the ASCII fast path and the bulk-scroll
skip-ahead, which require a full-screen region and therefore never interact
with this branch.

### Accounting

A transcribed line is an ordinary scrollback line for every existing consumer:
the scrollback length accessors, the eviction counter when capacity is
reached, and the per-pump scrollback delta the application layer feeds into
the parked-view follow correction. No new accounting is introduced and the
follow rules are not changed (FR14).

### The gate member

Defined per IMPLEMENTATION.md Shared Components: enabled at construction, one
public setter taking one boolean, reading it is allocation free. Do not give
the core any knowledge of the settings layer. Honouring the gate here is what
makes the feature user-reversible (NFR4); the setting's own plumbing belongs
to another task.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: On a full-width core with scrollback capacity greater than zero,
      setting a region whose top margin is the topmost screen row and whose
      bottom margin is above the last row, then feeding line feeds at the
      region's bottom row until the region scrolls N times, produces exactly N
      new scrollback lines whose contents equal the successive former top rows
      in chronological order.
- [ ] AC-2: In the AC-1 scenario, every screen row below the bottom margin
      holds the same characters at the same screen position before and after
      the scroll, and the bottom-margin row is blank.
- [ ] AC-3: A scroll-up control sequence inside a region whose top margin is
      the topmost row transcribes, and a count larger than the region height
      transcribes exactly the region height.
- [ ] AC-4: Each of these adds zero scrollback lines and reproduces the
      pre-change screen state — a region whose top margin is not the topmost
      row; the alternate screen being active; line insert and line delete; the
      scroll-down control sequence and reverse index at the region top; the
      gate disabled; zero scrollback capacity — and after leaving the
      alternate screen the same byte sequence transcribes again.
- [ ] AC-5: The full-screen scroll path is unchanged in scrollback contents,
      eviction count and its single-line scroll-event / dirty-row optimization;
      the transcribing region path marks only the region's rows changed and
      emits no full-screen scroll event.
- [ ] AC-6: Transcribed lines are counted as ordinary scrollback lines by the
      scrollback length accessors, and transcription at full capacity evicts
      the oldest line and increments the eviction counter exactly once per
      evicted line.
- [ ] AC-7: A newly constructed core has the gate enabled, the public setter
      changes only the behaviour of subsequent scrolls (no scrollback
      mutation, no dirty marking, no scroll event); the terminal-core library
      tests pass and every file this task touched is rustfmt-clean.

## Test Notes

- All behavioural criteria are unit tests in the terminal-core library, driven
  by feeding byte sequences through the core's PTY-data entry point — never by
  calling the internal scroll helpers directly. That is what makes them
  evidence against real TUI regressions (AC-1 to AC-6 map to TS-1, TS-2 and
  TS-3 in VERIFICATION.md).
- Write the negative cases first: they pin today's behaviour before the
  transcribing path exists, so they fail loudly if the condition is too wide.
- Assert screen state positionally, not just scrollback contents — AC-2 is the
  criterion most likely to be silently broken by the ring rotation.
- Edge cases worth explicit coverage: a region whose bottom margin is the last
  row (this is the full-screen branch, not the region branch, and must stay
  unchanged); scroll counts larger than the region height; transcription at
  exactly full scrollback capacity; a region active across a resize (the
  transcribed rows are ordinary scrollback rows there).
- TDD-awkward: the "no per-byte work added to the hot path" part of NFR2 is not
  expressible as a unit assertion. It is handled structurally — the condition
  is evaluated only on the region branch that is already taken, and the
  non-transcribing path allocates nothing — and is reviewed rather than tested.
