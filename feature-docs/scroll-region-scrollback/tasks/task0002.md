# Task Plan: task0002 — Settings key, native mirrors, tab seeding and live apply

## Goal

The transcription setting exists as a persisted boolean with a default of
enabled, reaches every newly spawned tab's terminal core at construction, and
reaches every already-open tab's core the moment settings are saved — without
restarting tabs, re-spawning PTYs, or dropping scrollback.

## Design

### The persisted key

One boolean under the key string pinned in IMPLEMENTATION.md Shared
Components. Wiring follows the existing alternate-scroll setting end to end,
including the existing null-tolerant deserialization helper listing, so that an
absent key and an explicit null both resolve to enabled and an explicit false
is honoured. The settings crate is compiled into the CLI-only configuration as
well, so the addition must not introduce anything that configuration lacks
(NFR3).

### The native mirror and overlay merge

The runtime mirror carries the same key name and type, defaults to enabled,
and its optional overlay member merges the same way the neighbouring boolean
terminal-behaviour settings merge: a value present in the overlay wins, an
absent one leaves the default in place.

### Seeding at tab construction

Immediately after a terminal core is constructed for a new tab, the settings
value is pushed into it through the core's public setter — at the same place
and in the same style as the existing cursor-behaviour seeding. Because the
core defaults to enabled, seeding only ever matters for the disabled case.

### Live apply on settings save

Inside the per-tab loop of the application-wide settings application, in the
same locked block that already applies other live terminal settings, the new
value is pushed into every existing tab's core. Nothing else happens: no tab
restart, no PTY re-spawn, no scrollback discard, no forced reflow. This follows
the live-apply precedent of the cursor-blink and fold settings, and explicitly
does not follow the create-time-only precedent of the scrollback-size setting
(which is create-time-only precisely because it discards existing scrollback).

### The gate member

Defined per IMPLEMENTATION.md Shared Components: enabled at construction, one
public setter taking one boolean, no side effects beyond the value itself. This
task owns the call sites; task0001 owns the consumption inside the scroll
decision. Do not add any scroll-behaviour logic here.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A settings document omitting the key deserializes to enabled; an
      explicit false round-trips as false; an explicit null resolves to
      enabled.
- [ ] AC-2: The native runtime mirror defaults to enabled, and merging an
      overlay that carries the key applies that value while an overlay without
      it leaves the default untouched.
- [ ] AC-3: A tab built from a settings value of disabled yields a terminal
      core whose transcription gate is disabled, and one built from enabled
      yields an enabled core.
- [ ] AC-4: Applying settings updates the transcription gate on the core of
      every already-open tab, not only on tabs created afterwards, verified in
      the style of the existing per-tab cursor settings test.
- [ ] AC-5: Applying settings performs no tab restart, no PTY re-spawn and no
      scrollback discard — an open tab's scrollback length is unchanged across
      the application of the new value.
- [ ] AC-6: The CLI-only build configuration still compiles with the new
      settings key present.
- [ ] AC-7: The settings-crate library tests and the application library tests
      pass, and every file this task touched is rustfmt-clean.

## Test Notes

- AC-1 is a serde round-trip unit test in the settings crate, in the style of
  the existing tests there (TS-4).
- AC-2 is a unit test of the overlay merge in the application crate's settings
  module; assert both directions (key present, key absent).
- AC-3 to AC-5 are application-library unit tests (TS-5). Model AC-4 directly
  on the existing test that asserts cursor style and blink reach every tab —
  build more than one tab, change the value, assert on each tab's core.
- AC-6 is the feature-gate check command rather than a test (TS-7); run it
  before declaring the task done, since the settings crate is the one piece of
  this task that the CLI-only configuration also compiles.
- Edge case worth covering: an overlay carrying an explicit null, which must
  land on enabled rather than on a deserialization error.
- TDD-awkward: the gate member and setter are shared with task0001 and may
  already exist in the merged parent. Write the call sites against the pinned
  contract; if the member is absent in this worktree, create it exactly as
  specified rather than inventing a variant signature.
