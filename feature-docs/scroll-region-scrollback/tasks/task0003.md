terminal behaviour subsection, beside the alternate-scroll toggle, with a
localized label and description in both shipped locales and a typed mirror
that matches the persisted schema.

## Design

### The mirror

The settings interface member uses the key string pinned in IMPLEMENTATION.md
Shared Components verbatim, typed as a boolean, positioned beside the
alternate-scroll member. This is a cross-language contract: a mismatch in the
key string or in optionality is a silent drift between the panel and the
persisted schema, which is why the type check is an acceptance criterion.

### The toggle

One toggle entry in the terminal behaviour subsection, rendered by the same
mechanism as the neighbouring alternate-scroll toggle, immediately adjacent to
it (the specification places the opt-out next to the nearest existing opt-out
on purpose). Its change handler saves under the pinned key string. No new
visual element, layout or design token is introduced — the design step was
skipped precisely because this is a duplicate of an existing toggle call.

### Labels

A label key and a description key under the terminal settings namespace,
defined in both locale files at identical key paths. The description should
say what the behaviour does in user terms — that lines scrolled out of an
application's scroll region are kept in the terminal's scrollback — rather
than naming internal control sequences.

### Default

The mirror's default is enabled, matching every other layer
(IMPLEMENTATION.md D3), so the toggle shows as on for a user who has never
touched it.

## Test Notes

- AC-2 and AC-3 are covered by the section test (TS-6); AC-1 by the type check
  and AC-4 partly by it as well, depending on how locale keys are typed
  (TS-7).
- Expect the new interface member to force updates to settings fixtures in
  other settings-section tests, since those fixtures construct a whole
  settings object. Those files are not enumerated in the file set above
  because the planner could not resolve them; touching them to keep the suite
  green is expected, and should be reported as a plan deviation with the list
  of files.
- A useful assertion for AC-4 is a direct comparison of the two locale files'
  key sets for the new keys, rather than eyeballing both files.
- TDD-awkward: nothing here is behaviourally deep; write the section test
  first against the pinned key string so that a typo in the key fails the test
  rather than silently producing a dead toggle.
