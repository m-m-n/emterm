# Task Plan: task0001 — Rust setting enum, migration, and key rewrite

## Goal

The Rust side stores the Shift+Enter behavior as the three-value enum
setting `shift_enter_behavior`, migrates the legacy boolean, and delivers
the selected byte sequence when a bare Shift+Enter is pressed.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1

## Scope

### Files to Create

- (none)

### Files to Modify

- `src-tauri/src/settings.rs` — replace the boolean field with the enum
  (serde values per the IMPLEMENTATION.md wire contract), default,
  partial-merge entry, and legacy-key migration.
- `src-tauri/src/window_host.rs` — replace the boolean rewrite branch with
  the three-way behavior branch (decision D1).
- `src-tauri/src/settings_store.rs` — update persistence tests referencing
  the old field; add round-trip coverage for the new key.

## Design

- **Setting type**: a three-variant enum implementing the wire contract in
  IMPLEMENTATION.md (Shared Components). Unknown or null JSON values
  resolve to the default `alt_enter` following the existing null-tolerant
  deserialization pattern.
- **Migration (FR5)**: during settings deserialization, when the new key
  is absent and the legacy key `shift_enter_as_alt_enter` is present, map
  true → `alt_enter` and false → `none`. When the new key is present it
  wins. The legacy key is never written back.
- **Rewrite decision**: applies only when the pressed key is Enter and the
  modifier state is exactly Shift (no Ctrl, no Alt) and the input is bound
  for the PTY (the existing branch location already guarantees the
  UI-layer handlers such as the search bar ran first).
  - `none` → drop the Shift modifier and encode normally (plain Enter).
  - `alt_enter` → drop Shift, set Alt, encode normally (current behavior).
  - `kitty_csi_u` → send the literal 7-byte sequence ESC `[` `1` `3` `;`
    `2` `u` through the same output path as encoder-produced bytes, for
    both host-PTY and mux targets (decision D1).
- **Testability**: express the rewrite decision as a small pure function
  (modifier state + behavior value in, rewrite action out) so the decision
  table is unit-testable without a window host instance.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The settings struct exposes `shift_enter_behavior` with the
      three wire values; the boolean field is gone; the default is
      `alt_enter`.
- [ ] AC-2: Deserialization resolves: new key present (each value) → that
      value; new key null or unknown string → default; legacy key only →
      true maps to `alt_enter`, false maps to `none`; both keys → new key
      wins; neither → default.
- [ ] AC-3: Bare Shift+Enter yields, per value: `none` = the plain Enter
      encoding, `alt_enter` = the Alt+Enter encoding, `kitty_csi_u` = the
      exact bytes 0x1B 0x5B 0x31 0x33 0x3B 0x32 0x75 for both host-PTY
      and mux encode targets.
- [ ] AC-4: Enter with Ctrl, with Alt, or with Ctrl+Shift is not rewritten
      under any of the three values.
- [ ] AC-5: settings_store round-trip persists `shift_enter_behavior`;
      existing tests referencing the old field are updated and pass.
- [ ] AC-6: `CARGO_TARGET_DIR=src-tauri/target cargo check
      --manifest-path src-tauri/Cargo.toml` and the `--lib` test command
      pass.
