# Task Plan: task0004 — Align app_settings migration precedence with FR5 (rework)

## Goal

The app_settings migration path applies the legacy boolean only when the
new key is truly absent, matching the native loader's FR5 semantics.

## Requirements

FR5

## Scope

### Files to Create

- (none)

### Files to Modify

- `crates/app_settings/src/settings.rs` — replace the default-value
  sentinel in the migration with a real present-vs-absent distinction for
  `shift_enter_behavior`; add the two regression fixtures.
- `crates/app_settings/src/types.rs` — only if the presence-tracking
  representation requires a type-level change.
- `src-tauri/src/settings_window/commands.rs` — only if the boundary
  tests need corresponding fixtures.

## Design

Review round 2 finding driving this task (reviews/round2.yaml):
`rd2-apply-migrations-precedence` (high) /
`rd2-migration-divergence-comprehensive` (medium).

- The migration currently treats "resolved value equals the default" as
  "key absent", which conflates: key absent / key present null / key
  present `alt_enter`. Track whether the key was present in the raw input
  (the native loader's present-vs-absent approach is the reference
  pattern) and fold the legacy boolean only when truly absent.
- Behavior contract to pin with tests: input with the new key explicitly
  `alt_enter` and legacy `false` resolves to `alt_enter`; input with the
  new key explicitly null and legacy `false` resolves to `alt_enter`;
  legacy-only input still maps per FR5.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `{"shift_enter_behavior": "alt_enter",
      "shift_enter_as_alt_enter": false}` resolves to `alt_enter` through
      the app_settings migration (and is persisted as such).
- [ ] AC-2: `{"shift_enter_behavior": null,
      "shift_enter_as_alt_enter": false}` resolves to `alt_enter` through
      the app_settings migration.
- [ ] AC-3: Legacy-only input still maps true → `alt_enter`,
      false → `none`; new-key-only and neither-key behavior unchanged.
- [ ] AC-4: Build and `--lib` test commands pass; app_settings crate
      tests pass.

## Test Notes

  place them beside the existing apply_migrations tests.
- No behavior change for any input where the new key is absent — the
  existing migration tests must keep passing unmodified.

## Out of Scope
