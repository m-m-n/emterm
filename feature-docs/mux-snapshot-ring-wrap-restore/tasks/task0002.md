# Task Plan: task0002 — apt resize / region-active and continuation coverage, pending-wrap and probe-history fixes

## Goal

The post-wrap dump block restores the full replay-established cursor state, including a pending wrap. Its replay-state probe reaches the same state as the client when a segment resize grows the screen. The apt-style stream is exercised with a real mid-run resize, with a snapshot while apt's scroll region is active and with one after apt's stop sequence, and with continued output under the region compared against a whole-stream reference.

## Design

Cross-task contracts are in IMPLEMENTATION.md (Shared Components, Conventions, D3, D4, D7, D8). This section covers task-specific points only.

### Pending wrap (D7)

1. The probe reads the pending-wrap flag with the rest of the replay-established state.
2. When the flag is clear, the composer's output is unchanged from task0001.
3. When the flag is set, the composer re-establishes it after the restore CUP. It places the cursor on the cell (or wide-cell pair) that ends at the last column of the cursor row, re-prints that cell's character with the cell's attributes as drawn by the dump, and then applies the SGR restore. The cell's character and attributes are the ones the dump draws at that position, so the re-print does not change any visible cell.
4. Under origin mode, the placement is region-relative, as in the D4 cursor restore.

### Probe history depth (D8)

The probe's scratch terminal gets a history depth large enough that a grow resize (rows, columns, or both) during segment replay pulls back the same rows the client pulls back. The depth is a bounded constant, and its doc comment states why that depth suffices. The probe still runs only for wrapped main-buffer panes and at the task0001 sites (D5). Nothing new runs under the scrollback lock or the shadow-parser lock.

### apt fixtures

- Mid-run resize: rows_a != rows_b, in both directions. At the segment boundary, the ring records a resize marker at rows_b and the shadow parser is resized to rows_b. Filler bytes in front force the ring past capacity before apt starts.
- Region-active variant: the stream ends before apt's stop sequence, so apt's scroll region is still set when the snapshot is assembled.
- Continuation fixture: an apt-like region stream (scroll region set, log lines scrolling inside it, bar redraws at the pinned row below it) with no cursor-up short-line pattern. It is held at one dims. vt100 and term_core render cursor-up short-line output differently, and they resize differently (term_core reflows, vt100 does not). Either difference would confound the reference comparison. Resize coverage is AC-1's.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR2, FR7, FR8, FR9; TS-3): Push the apt-style stream with a real mid-run resize past ring capacity, for (rows_a, rows_b) = (47, 48) and (48, 47) at 120 columns. Each case is snapshotted twice through `build_snapshot_bytes_for_ring`: once while apt's scroll region is active (the stream stops before the stop sequence), and once after the stop sequence. The ring and the shadow parser are resized at the segment boundary. For each of the four snapshots:
  - the ring reports wrapped;
  - the decoded segments end with (dump block start, current_dims) at rows_b;
  - replayed with `reset_and_replay_segments` at current_dims into a terminal with 10,000 history lines, every visible row's trimmed text equals the shadow parser's row;
  - the client's mixed-row count equals the shadow parser's own mixed-row count;
  - the client's scroll region, origin mode, cursor position and pending-wrap flag equal those of a terminal with 10,000 history lines that replayed the same payload truncated at the dump block start.
- [ ] AC-2 (FR9; TS-4): Build the apt-like region stream (Design) past ring capacity and snapshot it while its region is active. Before the snapshot, assert as a precondition that every shadow row equals the row of a `term_core` terminal fed the same bytes. Replay the snapshot. Then feed further log lines and bar redraws to the client, and feed the entire stream to a fresh reference `term_core` terminal at the same dims. The client's visible rows, scroll region, origin mode and cursor position equal the reference's.
- [ ] AC-3 (FR9; TS-16): Take a wrapped main-buffer stream whose last output exactly fills a row, leaving the cursor with a pending wrap. After a snapshot replay, the client's pending-wrap flag and cursor position equal the probe's, and its visible rows equal the shadow parser's. Appending one printable character to both the client and a whole-stream reference `term_core` terminal gives equal visible rows and cursor positions: the character goes to the next row's first column, and the last column keeps its character.
- [ ] AC-4 (FR9; TS-16): Variants of AC-3, each compared with a whole-stream reference after one more printable character:
  - (a) the pending-wrap row lies inside a narrowed scroll region with origin mode on;
  - (b) the row ends with a double-width character in its last two columns;
  - (c) a control case: the cursor sits at the last column with no pending wrap (placed there by absolute positioning). The client's pending-wrap flag is clear, and the next character overwrites the last column, as on the reference.
- [ ] AC-5 (FR9; TS-17): Take a multi-segment pre-dump payload that accumulates more history than the screen height and then grows. Cases: rows only at the same width; rows and columns together; current_dims larger than the last segment. The probe's scroll region, origin mode, cursor position, SGR attributes and pending-wrap flag equal those of an oracle terminal with 10,000 history lines replayed through `reset_and_replay_segments` on the same payload, segments and current_dims.
- [ ] AC-6 (FR10): The dump block still contains no DECSC, DECRC, ED 3, alt-screen toggle or autowrap mode change, including in the pending-wrap cases. The pre-existing `dump_block`, `wrap_restore_tests` and `pty_spawn` tests pass unmodified, and the lib test command (`--test-threads=1`) passes. The `--no-default-features` check compiles.
