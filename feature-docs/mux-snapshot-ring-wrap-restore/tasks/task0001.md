# Task Plan: task0001 — Post-wrap main-buffer snapshot restore (reproduction test first)

## Goal

Consider a mux main-buffer pane whose scrollback ring has evicted bytes. After a tab switch, reattach, on-demand snapshot or visibility resume, it shows the daemon shadow parser's visible screen, including once-written rows such as top's column header. Every other snapshot stays byte-identical. A reproduction test pins the loss by failing before the fix.

## Design

The contracts and cross-cutting rules are in IMPLEMENTATION.md (Shared Components, Conventions, D1–D6). This section covers task-specific points only.

### Reproduction first (FR1)

- Write and commit the reproduction test before any production-code change. It targets an assembly entry whose signature the fix does not change: `collect_reattach_data` with `visible == true`, or `handle_request_pane_snapshot`. That entry runs the production path read_segments → build_snapshot_bytes / build_shadow_parser_snapshot. The identical test body then fails before the fix and passes after it. Record the failing run (visible rows without the header) in the task's test record.
- Stream shape: the header row is drawn once by absolute cursor positioning. Frames that update only the process rows (absolute positioning, no header) then repeat until the cumulative bytes written exceed the fixture ring's capacity.
- Precondition assertions: the shadow parser's screen contains the header, and the cumulative bytes exceed capacity.

### Ring (D1)

- Add the combined read. The wrap state derives from the existing cumulative write counter and the capacity. `read_segments` stays as it is for its other callers.

### Wrap-aware builders (D2, D4, D6)

- For the non-wrapped and alt cases, both wrap-aware builders delegate to the existing builders.
- For a wrapped main-buffer pane with a non-empty dump, they:
  1. probe the delegated (pre-fix) payload and its segments;
  2. compose the block and append it;
  3. append the trailing (block start, `current_dims`) segment under the existing rule: only when the delegated segments are non-empty.
- Split the probe and the assembly by an internal seam: assembly receives the probe outcome. A failed outcome then yields the delegated non-wrapped output and one warn-level log line, and it can be tested without provoking a real `term_core` panic.
- Leave the existing inline tests module of `snapshot_bytes` unchanged. Declare the block module, and declare the new test module for test builds only.

### Probe and composer (D3, D4)

- Probe:
  1. Create a fresh `term_core` terminal at `current_dims`.
  2. Replay the pre-dump payload with its segments through the replay entry point that the client uses for Snapshot frames.
  3. Apply the transition to `current_dims`.
  4. Read back the scroll region, origin mode, cursor position and current SGR attributes.

  The scratch terminal's history capacity may be minimal because only mode state is read. The probe-equality test asserts that this choice does not change that state.
- Composer: follows the D4 flow. Sanitization removes exactly the two-byte DECSC (ESC 7) and DECRC (ESC 8) sequences and nothing else. To restore SGR, the composer resets it and then re-applies the probe's current attributes.

### Assembly sites (FR5, D5)

| Site | Change |
|---|---|
| `collect_reattach_data` (visible) | Replace `read_segments` with the combined read and call the wrap-aware reattach builder. The dump computation is unchanged (it is already unconditional). Hidden reattach is unchanged. |
| `handle_request_pane_snapshot` | Do the combined read inside the existing copy-only block, and pass the flag to the wrap-aware on-demand wrapper. |
| `resume_pane_with_permit` | Do the combined read first. The shadow-parser read then computes the dump only when the pane is on the alt screen or the ring has wrapped, and the snapshot goes through the wrap-aware resume builder. The permit, the size policy and the Connected swap are unchanged. |
| `evaluate_output_target` resume branch | Same as `resume_pane_with_permit`. |

### Documentation (NFR6, NFR7)

Update the layout SSOT docs and the site docs per the IMPLEMENTATION.md Conventions. They describe the wrapped-ring exception, the trailing segment and the NFR6 / NFR7 known limits. Also update the `MAX_DIM_MARKERS` and `MAX_DAEMON_SNAPSHOT_SEGMENTS` docs: the trailing dump segment now also applies to wrapped main-buffer panes, and both values stay the same.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR10; TS-1): A reproduction test drives a MuxPane fixture. The pane's scrollback is replaced by a small-capacity ring with a recorded resize marker, and the pane's shadow parser receives the same bytes. The test feeds the top-like stream from the Design section until the cumulative bytes exceed capacity. It then assembles the snapshot through a production assembly entry whose signature the fix does not change, replays it with `reset_and_replay_segments` at the pane dims, and asserts that the header row text is in the visible region. The test is committed before any production-code change. Its failing run against the pre-fix code (header absent) is recorded in the task's test record. Its code is identical in the failing and passing runs.
- [ ] AC-2 (FR6, NFR7; TS-7, TS-15(a)): The combined read reports the following:
  - wrapped when cumulative writes exceed capacity, or when a single write is strictly larger than capacity;
  - not wrapped when the total written is exactly capacity;
  - not wrapped after `clear` following a wrap;
  - not wrapped for a ring rebuilt from a wrapped ring's handoff capture.

  Its bytes and segments equal `read_segments` for the same ring state, and when the flag is set the bytes length equals capacity.
- [ ] AC-3 (FR2, FR5, FR6, FR7; TS-2): Run the AC-1 stream on a MuxPane fixture through each of the four paths: `collect_reattach_data` (visible), `handle_request_pane_snapshot`, `resume_pane_with_permit`, and the `evaluate_output_target` resume branch. Each path yields decoded segments that end with (dump block start, `current_dims`). Its replay with `reset_and_replay_segments` makes every visible row's text equal the shadow parser's row, header included. A variant in which the shadow parser's dims differ from the last recorded ring segment's dims gives the same result at `current_dims`.
- [ ] AC-4 (FR3, FR4, NFR1; TS-6, TS-9): Take rings whose total written is below capacity and exactly at capacity. Both wrap-aware builders and all four sites produce bytes and segments identical to the pre-fix layout, with no dump: clear prefix + stripped scrollback, plus the trailing main-buffer normalization on the reattach / on-demand layout. An alt-screen pane, with a wrapped ring and with a non-wrapped ring, produces bytes and segments identical to the pre-fix alt layouts. Pre-existing snapshot layout and omission tests pass without modification.
- [ ] AC-5 (FR2, FR7, FR8, FR9; TS-3, TS-5):
  - (a) An apt-style stream with a mid-run resize is pushed past ring capacity, with the ring and the shadow parser resized at the resize point. It is snapshotted while apt's scroll region is active, and again after apt's stop sequence. Each replayed visible region equals the shadow parser's screen row by row, and the mixed-row count is zero whenever the shadow parser's own screen has none.
  - (b) For a wrapped stream that ends with origin mode on and a narrowed region, each dumped row lands at the shadow parser's row index. After the snapshot, the scroll region, origin mode, cursor position and current SGR equal the probe's replay-established values.
  - (c) For a variant that ends with a pending saved cursor, the snapshot neither consumes nor replaces the saved-cursor slot. A subsequent DECRC plus further output matches a reference terminal that received the whole stream.
  - (d) No dump block contains DECSC or DECRC, including in a case whose shadow cursor is parked past the end of a row.
- [ ] AC-6 (FR9, FR2; TS-4, TS-8): After a post-wrap snapshot replay, the next chunk of the same stream is fed to the client: more top frames, or more apt log lines plus bar redraws under the region. The client's visible region then equals a fresh reference `term_core` terminal that received the entire stream at the same dims, and the scroll region, origin mode and cursor position match. The client's scrollback history after a post-wrap snapshot matches, in length and content, a replay of the same payload truncated at the dump block start.
- [ ] AC-7 (NFR2–NFR7; TS-10, TS-12, TS-13, TS-14, TS-15):
  - (a) A wrapped main-buffer ring with `MAX_DIM_MARKERS` surviving markers plus one cap eviction encodes to at most `MAX_SEGMENTS` segments and decodes as Structured. The existing oversize refusal and stay-detached tests pass.
  - (b) A unit test pins the default scrollback capacity at 2 MiB.
  - (c) The visibility-resume sites compute the dump only for alt-screen or wrapped panes, and the scrollback critical section of `handle_request_pane_snapshot` contains only the copy.
  - (d) The layout SSOT docs and the site docs state the wrapped-ring exception and the NFR6 / NFR7 known limits.
  - (e) A failed probe outcome yields exactly the non-wrapped output, tested through the internal seam.
  - (f) The lib test command passes, the `--no-default-features` check compiles, and no platform-specific code is added.

## Test Notes

- **Mapping**: AC-1 → TS-1; AC-2 → TS-7, TS-15(a); AC-3 → TS-2; AC-4 → TS-6, TS-9; AC-5 → TS-3, TS-5; AC-6 → TS-4, TS-8; AC-7 → TS-10, TS-12 (inspection), TS-13, TS-14, TS-15(b) (inspection).
- **Fixtures**: `MuxPane::new_test` panes carry a default-capacity ring without resize markers. Set each fixture up as follows:
  - Replace the pane's ring with a small-capacity ring (a few KiB).
  - Record a resize marker at the pane dims before writing.
  - Feed every byte to both the ring (through the attributing write) and the pane's shadow parser.

  Without the marker the snapshot carries no segments, and therefore no trailing segment.
- **Screen comparison**: compare the trimmed row text of the replayed `term_core` terminal with the shadow parser's rows at the same dims.
- **Reference terminal** (TS-4, TS-5): a fresh `term_core` terminal fed the whole stream, and resized at the same stream offset as the ring's resize marker.
- **apt scenarios** (TS-3, apt half of TS-4): reuse the apt synthesizer with mid-run resize and the mixed-row counter that already exist in `pty_spawn/tests.rs`. Add filler bytes in front so the ring exceeds capacity before apt starts. Resize the ring and the shadow parser at the resize point.
- **Origin mode / saved cursor** (TS-5): synthesize a stream that ends with a narrowed region and origin mode on, and a variant that ends right after a DECSC with no DECRC yet. Then feed a DECRC and further output to both the client and the reference.
- **Probe equality**: compare the probe state with the state read from a terminal replayed with `reset_and_replay_segments` on the same pre-dump payload.
- **History** (TS-8): compare the scrollback line count and content between the full payload and the payload truncated at the dump block start. If this fails because an erase pushes rows into history, adjust the composer (IMPLEMENTATION.md Risk Assessment); do not weaken the test.
- **Wire budget** (TS-10): follow the shape of the existing largest-real-producer round-trip test, with a wrapped ring on a main-buffer pane.
- **Test runs**: do not edit pre-existing tests. Run with `--test-threads=1`.
