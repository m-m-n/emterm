# Task Plan: task0002 — Ordered multi-response drain: deliver every device-query response in a multi-query chunk exactly once

## Goal

Replace term_core's single-slot device-response holding with an ordered
pending-response store so that a single parse pass carrying multiple
device queries delivers every synthesized response to the querying
application exactly once and in query order, and retire the contradictory
`on_device_response` callback channel so term_core has exactly one
response delivery route.

## Requirements

FR2, FR3, FR4, FR5

## Provenance

- source: review (round 1)
- source_ids: 9ef6b54302b083b3 (critical), c6092a0fdcb3b4a5 (critical),
  49bc2b33fa3b053c (high), 1133c5337fb5458c (medium),
  b3b78df745f37e0d (medium), fc006b4380d032ae (medium)

All six findings share one root cause: task0001 promoted the single-slot,
overwrite-on-write response buffer to the SOLE delivery route while
removing the per-event callback channel, so when one chunk carries N
queries, only the last response survives (`take_response` returns one
response; N−1 are lost). Orchestrator-verified evidence: five in-scope
queries in ONE `process_pty_data_fully` chunk yield only the final
XTWINOPS 18 reply; the same five queries in five chunks with interleaved
drains yield all five responses. The three medium findings are the same
family: the buffer's overwrite contract (b3b78df745f37e0d) and the
now-dead-but-documented-as-live callback channel (1133c5337fb5458c,
fc006b4380d032ae).

## Design

### Drain contract (binding; pinned in IMPLEMENTATION.md Shared Components)

- Writing a synthesized response APPENDS it to an ordered pending store —
  never overwrites.
- `take_response` returns every response synthesized since the previous
  drain, concatenated in synthesis order, and leaves the store empty; a
  second call returns empty. A drain whose result is discarded removes
  every pending response.
- The store's capacity must accommodate all responses synthesizable from
  one maximal coalesced input chunk (the existing 1 MiB / 12 ms coalesce
  bound); growth is bounded by the input that produced it, and no in-scope
  response is ever silently dropped. Document the bound.
- Callers in the Tab layer (the three existing write-back sites) remain the
  ONLY delivery route to a PTY. No write-back site changes its call shape —
  each already does "drain, then deliver what was drained", which is correct
  under the new contract without modification.

### Callback disposition (binding decision)

Adopt the reviewers' recommended option (a): remove the
`on_device_response` extension point entirely — the trait method, the fire
helper, and the five dispatch fire sites — so exactly one response channel
exists and the trait documentation cannot contradict the delivery
invariant (findings 1133c5337fb5458c, fc006b4380d032ae). The only
production implementor is the native callbacks struct; the remaining
implementors are test doubles, updated in the same change. If removal
proves infeasible inside this file set, the fallback is a default no-op
with the trait documentation rewritten to "observation only; must never be
written back to a PTY" — taking the fallback is a reportable deviation,
not a silent choice.

### Response-peek accessors

After the callback removal, audit remaining callers of the response-peek
accessors (pointer / length / bytes forms). If unreferenced, remove them;
if referenced, document explicitly what they expose under queue semantics
(the pending drain content, not "the most recent single response").

### What this task does NOT change

Routing/visibility invariants I1–I5 from task0001 stay in force. The
coalescing gates (`payload_has_device_query` / batch-eligibility) are
unchanged — they limit cross-frame coalescing and are orthogonal to the
in-chunk multi-query fix. Strip predicates are untouched.

- [ ] AC-1: A term_core `--lib` test feeds at least five distinct in-scope
      queries (covering DA1, DA2, and XTWINOPS 14/16/18 at minimum) in ONE

      hold on the mux-pane output path.
- [ ] AC-4: All pre-existing single-query-per-chunk tests (task0001's TS4
      per-type tests, both contexts) stay green unmodified, or any modified
      assertion carries a justification comment.
- [ ] AC-5: term_core exposes exactly one response delivery channel: no
      device-response callback fire sites remain (or the fallback no-op is
      in place with observe-only documentation and a reported deviation);
      the production callbacks contain no device-response delivery; trait
      docs and csi_device docs agree with the drain contract.
- [ ] AC-6: A snapshot-rebuilt core starts with an empty pending store, and
