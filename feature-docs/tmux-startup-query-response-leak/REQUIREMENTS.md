# tmux-startup-query-response-leak - 要件定義書

## 1. 概要

### 1.1 背景
eMterm 内で tmux を起動すると、端末のデバイスクエリ応答がターミナル表示内容へ
漏れ出す。報告された症状は、シェル出力の前に
`\x1b[>65;1;0c\x1b[8;51;207t\x1b[4;816;1656t` の文字列が 2 回繰り返して表示される
というもの（DA2 応答、XTWINOPS のテキストエリア文字数応答、XTWINOPS の
テキストエリアピクセル数応答）。

### 1.2 目的
eMterm 内で tmux を起動したとき、端末のデバイスクエリ応答が可視のターミナル
内容として漏れないようにする。同時に、tmux は能力ネゴシエーションに必要な応答を
引き続き受け取れる状態を保つ。

### 1.3 スコープ
- 対象: tmux 起動時のデバイスクエリ応答の経路（応答をクエリ発行元アプリケーション
  へルーティングする仕組み）と、その自動回帰テスト。
- 未確定: 対象ランタイムコンテキスト（FR4）と対象クエリ応答の集合（FR5）は
  `status: tbd`。create-plan の `create-plan.tbd-resolution` assume ゲートで解決する。
- design ステップ: skipped。理由は「可視・デザイントークンの表面を持たない
  Rust 内部のエスケープ応答ルーティング修正であり、per-tab-grid-size の先例と
  同じ判断」。

## 2. ビジネス要件

### 2.1 ビジネス目標

  内容へ漏れてはならない。同時に tmux は能力ネゴシエーションに必要な応答を
  引き続き受け取る。

### 4.2 機能詳細

#### FR1: 起動時クエリ応答の可視漏れを無くす

**ステータス**: resolved

**説明**: eMterm で tmux を起動しても、デバイスクエリ応答のバイト列がペイン内の
可視テキストとして描画されない。tmux 起動後のプロンプトはクリーンである。
報告された症状は、シェル出力の前に表示される
`\x1b[>65;1;0c\x1b[8;51;207t\x1b[4;816;1656t` の 2 回繰り返し
（DA2 応答、XTWINOPS のテキストエリア文字数応答、XTWINOPS のテキストエリア
ピクセル数応答）。

#### FR2: クエリ発行元アプリケーションへの応答配送を維持する

**ステータス**: resolved

**説明**: 本修正は応答を抑止するのではなく、クエリを発行したアプリケーション
（tmux）へルーティングする。各応答は引き続きちょうど 1 回配送される。tmux の
能力ネゴシエーションは従来どおり機能する。

#### FR3: 自動回帰テストの整備

**ステータス**: resolved

**説明**: 漏れの発生機構を Rust のユニットテスト（対象コードの隣に置くインライン
`#[cfg(test)]`、`--lib` スイート）でカバーし、手動再現なしで回帰を検出できるように
する。

#### FR4: 対象ランタイムコンテキスト

**ステータス**: tbd

**説明**: 本修正がカバーすべきランタイムコンテキスト — tmux を動かす素の eMterm
タブか、mux ペイン内の tmux か、その両方か。

**未確定の理由 (tbd_reason)**: バッチポリシー `unresolved: record_tbd`
（Codex 相談は利用不可 — usage limit）。暫定見解は `both`（素の eMterm タブで動く
tmux と mux ペイン内の tmux の両方をカバーする）。create-plan の
`create-plan.tbd-resolution` assume ゲートで解決する。

#### FR5: 対象クエリ応答の集合

**ステータス**: tbd

**説明**: スコープに含めるデバイスクエリ応答 — 報告された漏れで観測された
シーケンス（DA2、XTWINOPS 8 および 4）のみか、一般化した集合か。

**未確定の理由 (tbd_reason)**: バッチポリシー `unresolved: record_tbd`
（Codex 利用不可）。暫定見解は `generalize` — mux-snapshot-device-query-strip が
定義する応答集合（DA1 / DA2 / DSR / CPR / XTWINOPS 14,16,18 / DECRPM）を対象と
する。create-plan の assume ゲートで解決する。

#### FR6: タブ切替漏れ修正の非回帰

**ステータス**: resolved

**説明**: feature `per-tab-grid-size` が解決したタブ切替時のエスケープ文字列漏れが
再発しない。当該 feature の既存テストはグリーンのまま維持される。

## 12. テストシナリオ

### 12.1 テスト観点
- [ ] **TS1**（手動 / FR1, FR4）素のタブ: リリースビルドの eMterm を起動し、新規タブで `tmux` を実行、起動中および起動後のペインを観察する。プロンプトに `^[[>65;1;0c` / `^[[8;R;Ct` / `^[[4;H;Wt` などの余計なシーケンスが出ないこと。本プロジェクトに E2E インフラが無いため手動。
- [ ] **TS2**（手動 / FR1, FR4）mux ペイン（FR4 が `both` に解決した場合）: mux セッションへ attach し、mux ペイン内で `tmux` を実行して同じくクリーンな起動を確認。その後 detach/reattach し、リプレイによる漏れが無いことを確認する。
- [ ] **TS3**（手動 / FR2）修正後の tmux 健全性: 起動した tmux 内でペインを分割し、ウィンドウをリサイズし、色とステータスラインが正しく描画されることを確認する。応答が抑止ではなくルーティングされたことの証明。
- [ ] **TS4**（自動 / FR1, FR2, FR3, FR5）応答ルーティング機構の Rust ユニットテスト: スコープ内のクエリシーケンス（FR5 に従う）をコア経路へ流し、応答がクエリ元 PTY writer へ配送され、可視グリッドおよび scrollback には決して入らないことをアサートする。実行は `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib`（tabs.rs の replay テストは `-- --test-threads=1` が必要な場合がある）。
- [ ] **TS5**（自動 / NFR3）ネガティブテスト: 通常のアプリケーション出力中に含まれる、応答に似ているだけのバイト列が改変されないこと。
- [ ] **TS6**（自動 / NFR2）フィーチャーゲート確認: `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path src-tauri/Cargo.toml --no-default-features` が成功すること。
- [ ] **TS7**（自動 / FR6, NFR4）既存の per-tab-grid-size および mux-snapshot-device-query-strip のテストスイートが `--lib` 実行でグリーンのままであること。
