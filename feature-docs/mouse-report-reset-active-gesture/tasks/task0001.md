# Task Plan: task0001 — Bound the local drag: reset preserves held gestures, left release and focus loss always terminate

## Goal

A reset raised because mouse tracking is inactive no longer erases the
gesture-ownership slot of a physically-held button; a left release that is not
report-owned always terminates a live local selection drag; and a focus loss
terminates one too — so the drag flag can never be stranded and the
pointer-state-gated features can never be permanently disabled.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4, NFR5

## Design

Read IMPLEMENTATION.md first: D1 (reset trigger distinction), D2 (the
exclusion lives in the application step), D3 (the no-owner release gate), D4
(focus loss shares the publish half, not the fold toggle), D5 (the lifecycle
invariant), D6 (the invariance perimeter), the three Shared Components
contracts, and the Conventions section's two name/structural-test rules. This
section adds only what is specific to the work.

### 1. Reset narrowing (FR1, FR6)

The application step currently answers one reset flag by resetting the
cell-change cache and clearing every gesture slot. It becomes:

1. Reset the cell-change cache whenever either reset trigger fired —
   unconditional, unchanged from today.
2. When the tab-change trigger fired, clear every gesture slot, held or not.
3. Otherwise, when the tracking-inactive trigger fired, clear only the slots
   of buttons the supplied held-button value reports as NOT held.
4. The "no button" identity never occupies a slot, so the exclusion must not
   give it one.

The pre-existing entry point delegates with an all-released held-button value,
which reduces step 3 to "clear every slot" — its present behaviour for its
existing inline test call sites.

### 2. The drag-in-flight signal and the release broadening (FR2, FR5)

Define the signal once in the pointer-routing layer per the Shared Components
contract. The button-decision input bundle gains one plain boolean field
carrying it; only the release half reads it, and only in its no-owner branch.
The press half ignores it entirely.

Release decision table after the change:

| Recorded owner | Button | Drag in flight | Disposition | Record updates |
|---|---|---|---|---|
| report-owned | any | — | unchanged from today (a report when some tracking mode is active, otherwise nothing) | clear this button's slot (unchanged) |
| locally owned | left | — | the selection-completion arm (unchanged) | clear this button's slot (unchanged) |
| locally owned | middle / right | — | nothing (unchanged) | clear this button's slot (unchanged) |
| none | left | true | the selection-completion arm (**new**) | today's reset observations, unchanged |
| none | left | false | nothing (unchanged) | today's reset observations, unchanged |
| none | middle / right | — | nothing (unchanged) | today's reset observations, unchanged |

### 3. The terminator split and the focus-loss arm (FR3)

The release path's local arm today performs, in order: clear the drag flag;
consume the pending selection anchor; if the consumed anchor was present, no
selection exists and the control modifier is not held, attempt a fold toggle
and, when it succeeds, stop without publishing; otherwise publish any existing
selection to PRIMARY and, when the copy-on-select setting is on and the text
is non-empty, to CLIPBOARD.

Split this into:

- the **publish half** — clear the drag flag, consume the pending anchor,
  publish an existing selection — made module-visible;
- the **fold-toggle branch** — unchanged, still reached only from the release
  path and still short-circuiting the publish exactly as today.

The release path composes the two so its externally observable behaviour
(which destinations are written, under which conditions, and when the fold
toggle wins) is what it is today. The focus-loss arm calls the publish half
only, guarded by the drag-in-flight signal, and keeps everything it already
does — dropping modifiers, zeroing the button-down count, clearing the
gesture-ownership and held-button records, refreshing the link cursor, forcing
a full redraw. Order the terminator call so it runs while the drag state it
inspects is still intact. With the guard false, the arm's behaviour is
unchanged in every respect.

### 4. The structural test (mandatory, see IMPLEMENTATION.md Conventions)

The delegate list in the structural routing test asserts the routing source
contains the literal needle for the OLD application entry point, trailing open
parenthesis included. Moving the three production call sites makes that needle
absent. **Replace** that list entry with the companion's needle; do not add a
second entry beside it, which would leave a guaranteed-red assertion.

### 5. What must not change (FR4, NFR5, D6)

Button-code composition, byte encoding, the release targeting the tab its
press recorded, the motion gate, the cell-change filter, the wheel-consumer
matrix, the guard-rejected press and wheel dispositions, and the bounded
wheel-report duplication cap with its constant. The reset narrowing changes
only which gesture slots survive an already-raised reset; it must never cause
a reset to be raised where one is not raised today, and never cause a report
to be emitted where none is emitted today.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: An outcome carrying a tracking-inactive reset, applied through the
      companion entry point with left held, resets the cell-change cache and
      leaves the left slot recorded; the same outcome applied with a middle
      slot recorded but middle not held clears the middle slot.
- [ ] AC-2: An outcome carrying a tab-change reset clears every gesture slot,
      including the slot of a currently-held button; the pre-existing
      application entry point, called with no held buttons, still clears every
      slot exactly as today.
- [ ] AC-3: With no tracking mode active, a left press over the grid followed
      by a wheel notch over the grid leaves the left gesture slot recorded as
      locally owned and the following left release names the
      selection-completion arm; the same holds with a middle press, and again
      with a right press, in place of the notch, and the middle or right slot
      is recorded and cleared independently of the left slot.
- [ ] AC-4: A left release whose left slot is empty names the
      selection-completion arm when the drag-in-flight input is true and names
      "nothing" when it is false; a chrome-position press followed by its
      release therefore causes no PRIMARY write, no CLIPBOARD write and no
      fold toggle.
- [ ] AC-5: With a live drag and a materialized selection, the focus-loss path
      leaves the drag flag false, the pending anchor consumed and the
      selection published to PRIMARY (and to CLIPBOARD when copy-on-select is
      on); with no drag in flight it writes neither destination and leaves
      selection state untouched; it never runs the fold-click toggle; and the
      existing gesture and held-button record clear still runs in both cases.
      After it has run, no subsequent pointer motion extends the selection.
- [ ] AC-6: The structural routing test's delegate list names the companion
      application entry point INSTEAD OF the old one (not in addition to it)
      and the test passes; the existing focus-loss test's full input-bundle
      literal compiles with the new field and that test still passes.
- [ ] AC-7: Every pre-existing test in the decision layer's inline test module
      and in the `window_host` module test file passes; no report byte
      sequence, release tab target, guard-rejected disposition or wheel-matrix
      outcome changes; the bounded wheel-report duplication cap and its
      constant are untouched.
- [ ] AC-8: No signature in the decision layer takes or returns a winit type,
      an egui handle, a GPU surface, a PTY or a `term_core` mode type; every
      new decision-layer test is a bare test constructing no window; each
      decision function leaves the records value it was handed unmodified; the
      crate still compiles with default features off; no dependency is added.

## Test Notes

- **Regression evidence**: the tests behind AC-3, AC-4 and AC-5 must fail
  against the revision this task starts from and pass afterwards. Confirm the
  failure before implementing — they are this task's TDD contract.
- **Compile-order trap worth knowing up front**: the button-decision input
  bundle derives only debug / clone / copy — it has **no** default
  implementation — so adding the drag-in-flight field breaks the one full
  struct literal that constructs it, at `src-tauri/src/window_host/tests.rs:1844-1863`.
  That literal sits inside the focus-loss test at `tests.rs:1809-1872`, which
  this task extends anyway. Expect to touch it; it is not a plan deviation.
- **Fixture defaults**: the existing input-builder helpers in the decision
  layer's inline test module default to mouse tracking ON. Every repro test
  here needs tracking explicitly off, otherwise the press records report
  ownership and the scenario does not reproduce.
- **Threading a sequence**: AC-3 needs one records value threaded through the
  whole press → interleaved event → release sequence via the application step,
  not three independent decisions against fresh records — the bug only appears
  in the threaded form.
- **AC-1/AC-2 are application-step tests**, not decision tests: construct the
  outcome directly, apply it with a chosen held-button value, then inspect the
  slots and the cell-change cache.
- **AC-5 at the record level**: the focus-loss arm cannot be driven without a
  winit window. Follow the precedent of the existing focus-loss test — pin the
  properties the call is required to have (which state ends up cleared, which
  destination is written, which branch is never taken) at the level that is
  reachable, keep the guard a pure function of plain booleans so its truth
  table is covered exhaustively by bare tests, and keep the arm's body a
  straight-line composition of the guard and the terminator so nothing
  untestable hides inside it.
- **AC-8's purity check**: copy the records value before the decision and
  compare after; the records type is a plain copyable value, so this needs no
  fixture.
- **AC-7** is satisfied by running the whole suite, not by new assertions. Run
  the library tests single-threaded, as the project's test conventions
  require.
- **Edge cases worth a test**: tracking turning on mid-drag (the left slot
  says locally owned while tracking is active — the release must still
  complete the drag, not emit a report); tracking off with a report-owned
  button held (the release must stay "nothing", not become a spurious report);
  the "no button" identity never gaining a slot through the exclusion; a press
  over the grid whose release arrives over chrome (the release stays
  position-independent); a side button with no report identity (its release
  returns early and can never terminate a left drag).
