### Guard test (FR3)

Placement: one new test function in `src-tauri/src/mux/upgrade/tests.rs`
(module `mux::upgrade::tests`). It inherits that module's existing Unix-only
build and adds no build condition of its own. Private helper functions used
only by this test may sit next to it in the same file.

Inputs:
- The record text, read at test time from the repository root, located as the
  parent of the crate's manifest directory — the same approach the existing
  repository-file helper in
  `src-tauri/src/mux/ipc/pty_spawn/tests/strip_open_string_body_closure.rs`
  uses. That helper is not imported or modified; the approach is replicated
  locally.
- The current source text of `src-tauri/src/mux/upgrade/tests.rs` itself.

Processing flow:
1. Collect the record's `tests` list entries: lines that start with six
   spaces followed by a hyphen and one space. The entry is the rest of the
   line. Free text inside `red_reason` and comments is never treated as an
   entry.
2. Isolate the AC-2 block: from the first occurrence of a newline, two
   spaces, `AC-2:` and a newline, up to the next newline followed by two
   spaces and `AC-`. If the AC-2 start marker is absent, the test fails with
   a message naming the missing marker; it never passes with an empty block.
3. Check (a): AC-2's entries contain the current name.
4. Check (b): no entry anywhere in the record equals the old name.
5. Check (c): for every entry anywhere in the record that starts with
   `mux::upgrade::tests::`, the remainder (the function name) appears in the
   test-module source as the text `fn ` + name + `(`. A string literal that
   merely contains a name (including this test's own old-name literal) is
   not a definition, because the check requires the `fn ` prefix and the
   opening parenthesis directly around the name.
6. Each failed check names the offending entry (or the missing name) in its
   assertion message.

Postconditions:
- With the corrected record: (a), (b) and (c) all hold and the test passes.
- With line 51 reverted to the old name: (a), (b) and (c) all fail.
- With any `mux::upgrade::tests::` entry renamed to an undefined function:
  (c) fails and names that entry.

No YAML parser is introduced; the checks are plain string operations. No new
dependency is added.
