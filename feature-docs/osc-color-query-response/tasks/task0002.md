# Task Plan: task0002 — Theme: answer OSC 4 / 10 / 11 / 12 color queries

## Goal

The live GUI theme answers OSC 4 / 10 / 11 / 12 color queries with the values
the renderer is currently using, formatted by the single existing formatter,
and those answers reach the PTY through the existing device-response route —
wired end to end, with no placeholder left behind.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR10, NFR1, NFR4

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/render/theme.rs` — the query side of the theme's OSC entry:
  recognize query tokens, resolve values, produce response byte sequences;
  the two existing "query responses are handled elsewhere" discard points
  become the query path, and their stale comments are removed.
- `src-tauri/src/tabs/output_pipeline.rs` — **predicted** production wiring
  site: register the theme-backed responder into the seam for the core that

- `src-tauri/src/tabs/mod.rs` — **predicted** alternative wiring site (core
  construction / per-pane setup).
- `src-tauri/src/callbacks.rs` — **predicted** alternative wiring site (where
  core callbacks are installed today).
- `crates/term_core/src/osc_handler.rs` — **only if** the SC-2 seam and the
  SC-1 terminator kind are absent in this worktree: implement them exactly to

- `crates/term_core/src/lib.rs` — **only if** the SC-2 seam and the SC-1

The wiring site is a prediction made without filesystem discovery: exactly
one of the predicted sites is the real one. Register the responder in the one
place where the core that owns the live theme is set up, and report which
site that turned out to be.

## Design

Implements SC-4 (query side) and SC-6 of IMPLEMENTATION.md; those contracts
are normative and are not restated here. The reset codes are task0003's; this
task does not change them.

**Value resolution** follows SC-6 for palette indices, and the live
foreground / background / cursor color for the default-color codes. Nothing
is cached: every answer is resolved at the moment of the query.

**OSC 10 / 11 / 12 payload walk**: the payload is split into elements; the
code advances element by element exactly as the existing set path advances it
(10 → 11 → 12, stopping once the target passes 12). For each element:

- a query token produces one response for the code the element resolves to;
- anything else keeps the existing set behavior;
- either way the code advances by exactly one, so a query element never
  consumes the next element and never shifts the chain.

**OSC 4 payload walk**: the payload is walked as index/value pairs in payload
order. A pair whose value is the query token produces one response carrying
that index and its resolved color. A pair whose index is not a decimal
integer, or is 256 or greater, produces nothing at all — neither a response
nor a state change — matching the existing skip behavior of the set path.
Every other pair keeps the existing set behavior, including writing both the
overlay and the 16-color array for indices below 16.

**Response shape**: an OSC introducer, the code, the payload part (the index
too, for OSC 4), the color text from the one existing formatter, and the
terminator form named by the SC-1 terminator kind — never a hardcoded
terminator.

**Inertness**: a query token under an OSC code the theme does not own, an
out-of-range or unparseable index, a malformed pair, and an element that is
neither a query token nor a parseable color spec all produce no bytes and no
state change. Answering a query never reports a visible change, so it can
never trigger a full-grid dirty mark.

**Wiring**: the responder is registered once, for the core that owns the live
theme, so that a query arriving on the live output path is answered without
any further call site. This task owns that wiring end to end
(IMPLEMENTATION.md D7); it must not be left to a later task or to review.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A single OSC 10, 11 or 12 query answers with the live foreground,
      background or cursor color respectively; a payload that is a color spec
      rather than a query token produces no response and keeps its existing
      set behavior (TS-2).
- [ ] AC-2: A chained default-color payload of three query tokens produces
      three responses carrying codes 10, 11 and 12 in that order; a
      four-element chain produces no fourth response; a query element neither
      consumes the following element nor shifts the code progression (TS-3).
- [ ] AC-3: An OSC 4 query answers with the value SC-6 resolves for that
      index, covering all three cases: overlay set, overlay unset with index
      below 16, and overlay unset with index in 16..=255 (TS-4).
- [ ] AC-4: A payload mixing sets and queries applies each set and answers
      each query in payload order (TS-5).
- [ ] AC-5: The response terminator equals the request terminator for both
      forms, for OSC 4 and for OSC 10 / 11 / 12 (TS-15).
- [ ] AC-6: Index 256 or greater, a non-decimal index, a query token under an
      OSC code the theme does not own, and an unparseable spec element each
      produce no response bytes and no theme state change, and answering any
      query reports no visible change (TS-16).
- [ ] AC-7: With the production wiring in place, a query arriving on the live
      output path results in exactly one device-response delivery carrying the
      expected bytes — no placeholder, no second registration, and no new PTY
      write path (TS-11 supports this end to end).

## Test Notes

- AC-1 through AC-6 are theme-level unit tests: build a theme in a known
  state, hand the entry point a code, a payload and a terminator kind, and
  assert both the produced response sequences and the absence of state
  change. They need no term_core seam and no pipeline.
- AC-3's three resolution cases must be asserted separately, including an
  index whose overlay slot is unset — an unset slot is never reported as
  missing.
- AC-7 is the one test that crosses layers. Keep it as small as possible:
  drive bytes through the live output path and assert a single delivery.
- Edge cases worth covering: an empty payload; a payload of only separators;
  a query token in a chain position past code 12; a pair whose index parses
  but whose value is neither a query token nor a color spec.
- TDD-awkward: the wiring test depends on the SC-2 seam existing. If the seam
  is absent in this worktree, implement it to the contract first (it is in
  this task's file list for exactly that reason) and expect the merge to
  adopt the parent side.
