# Task Plan: task0004 — Response delivery: drain, coalescing gate, replay isolation

## Goal

Every color-query response reaches the PTY exactly once through the existing
device-response route — never lost to frame coalescing, never duplicated
across the mux bridge, and never replayed into a running shell's input.

## Requirements

FR6, NFR2, NFR3, NFR6

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/tabs/input.rs` — the payload classifier that decides whether
  a frame carries a device query: make sure an OSC 4 / 10 / 11 / 12 query
  counts as one (or pin the already-correct behavior with a test).
- `src-tauri/src/tabs/output_pipeline.rs` — the two drain sites and the
  coalescing eligibility check: confirm color-query responses flow through the
  existing drain unchanged and add the regression coverage.
- `src-tauri/src/tabs/replay.rs` — the third drain site plus the two points
  that discard pending responses; extend the existing discard regression to
  cover an OSC color query.
- `src-tauri/src/tabs/mod.rs` — **predicted** location of the shared test
  scaffolding / the device-response write helper these tests drive.

## Design

Relies on SC-2, SC-3 and SC-7 of IMPLEMENTATION.md, and on decisions D5, D6
and D9; those are normative and are not restated here.

**Drain, unchanged.** The three existing drain sites already forward pending
responses to the device-response write. This task adds no fourth site and no
second live consumer — it proves the existing three carry the new responses
and locks that in with tests. A change that introduces a new PTY write path
fails this task.

**Coalescing.** The response buffer holds one pending content at a time, so a
frame carrying a query must be parsed alone: otherwise a later query in the
same batch can overwrite an answer that has not been drained. The existing
eligibility gate already refuses to coalesce frames carrying a device query.
This task settles SPEC assumption A7 by inspection and by test: either the
classifier already recognizes color queries — in which case a test pins it —
or it is extended to do so. The classifier only inspects; it never consumes
or rewrites bytes, and a frame with no query keeps today's behavior.

**Replay isolation.** The replay path and the off-thread swap path discard
pending responses, so a color query baked into snapshot bytes by a
long-dead program can never be answered into a live shell's input. This
invariant is not relaxed: the existing regression tests must pass with no
modification, and are extended with an OSC color query payload alongside the
identification / status-report payloads they already cover.

**Mux.** For a remote pane, PTY output is parsed on more than one side of the
bridge. This task determines which side owns the answer (the side holding the
live theme), pins it with a test so a second answering side would fail, and
confirms the answer is framed back to the originating pane by the same route
the existing cursor-position response uses.

**Portability.** Nothing on this path may use a Unix-only API; the response
route must behave identically on both supported platforms.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A response produced while a chunk is being parsed is drained once
      and forwarded through the existing device-response write, at each of the
      three existing drain sites; no new PTY write path and no second live
      drain consumer exists in the diff (TS-11).
- [ ] AC-2: Two separately parsed frames, each carrying a query, each receive
      their own response; no response is lost or overwritten (TS-11).
- [ ] AC-3: A frame whose payload carries an OSC 4 / 10 / 11 / 12 query is
      classified as a device query and is therefore parsed alone; a frame
      without one keeps its current coalescing behavior (TS-13). The report
      states whether the classifier already recognized color queries (SPEC
      assumption A7) or was extended here.
- [ ] AC-4: A color query embedded in replayed snapshot bytes produces no PTY
      write; the pre-existing discard regression tests pass unmodified and are
      extended to cover a color-query payload (TS-12).
- [ ] AC-5: For a remote pane over the mux bridge, exactly one side answers a
      query — a second answering side is detectable and fails the test — and
      the answer is framed back to the originating pane by the existing
      device-response route.
- [ ] AC-6: No Unix-only API is introduced on the response path, and the
      platform-conditional compilation of the touched files is unchanged
      (TS-19).

## Test Notes

- Use a test-local responder that conforms to SC-2 and returns fixed bytes
  rather than depending on the real theme responder; that keeps every test in
  this task runnable on its own and keeps the assertions about the route,
  not about color values.
- AC-1 and AC-2 are integration-level tests inside the tabs module: feed
  bytes through the live output path and assert the number and content of
  device-response deliveries.
- AC-3 has two shapes depending on what is found: a pinning test if the
  classifier already recognizes color queries, an extension plus test if not.
  Either way the test must fail if the classification is later removed.
- AC-4 must extend the existing regression rather than replace it — a
  rewritten assertion that no longer fails on the original leak is a
  regression in itself.
- The app crate's test command pins single-threaded execution; keep these
  tests free of cross-test shared state anyway, since replay tests in this
  module have a history of order sensitivity.
- Edge cases worth covering: a frame carrying a query plus ordinary output; a
  query split across two frame boundaries (classification must not depend on
  a query being wholly inside one frame — document the behavior found);
  a drain when nothing is pending.

## Out of Scope
