# Task Plan: task0001 — Deferred IME request queue + anomaly diagnostics

## Goal

Windows で CorvusSKK 変換モード中の `l` 入力がアプリケーションの応答なしを
引き起こす同期ブロッキング経路（winit イベント配送中の Imm* 到達）を排除
する。IME 要求を bridge 内に記録し、`about_to_wait` からフラッシュする方式に
置き換え、Linux の観測可能な振る舞いは変えない。

## Design

背景・根拠は SPEC.md「Background Analysis」を正とする。設計要点:

1. **記録**: `WinitImeBridge` は `BridgeWindow::set_ime_allowed` /
   `set_ime_cursor_area` を直接呼ぶ代わりに、意図を内部状態として記録する。
   - allow 状態: 最後に要求された値のみ保持（last-writer-wins）
   - cursor rect: 最後に要求された rect のみ保持。既存の
     `last_cursor_area` dedup（同一 rect は記録もしない）は維持する
2. **フラッシュ**: flush 入り口が記録済み要求を実行する。順序は
   allow 状態 → cursor rect（現行の enable→seed 順を保存）。1 回の flush で
   各種別につき最大 1 コール。何も記録が無ければコールもアロケーションも
   しない。
3. **構築時 enable**: `with_handle` / `init` の `set_ime_allowed(true)` も
   記録経由にする（構築は `can_create_surfaces`＝イベント配送中に起こる
   ため）。最初の `about_to_wait` で発行される。
4. **Drop**: 記録済み要求を破棄し、デタッチ（allow=false）だけは直接呼ぶ
   （SPEC FR3。Drop はイベント配送の一部ではない）。
5. **異常ログ (FR4)**: `on_winit_ime` で「`Enabled` 受信時に既に
   `ime_enabled == true`」「`Disabled` 受信時に既に `ime_enabled == false`」を
   warn で記録。各異常種別につき latched（初回のみログ）。通常遷移は debug
   以下。
6. **ゲート述語・イベント変換は不変 (FR5)**: `should_suppress_key`、
   `ImeEvent` への変換、プラットフォーム選択（`cfg!(windows)`）には
   一切手を入れない。
7. **配線**: `window_host` の `about_to_wait` から App 経由で flush を呼ぶ。
   既存の `notify_cursor_rect_if_changed`（redraw 経路）と
   `notify_ime_focus`（Focused 経路）の呼び出し箇所は変更しない —
   それらの先で記録されるだけになる。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: イベント配送経路（`window_event` から到達するコード）から
  `BridgeWindow` の副作用メソッドへ同期到達する経路が存在しない。
  `BridgeWindow::set_ime_allowed` / `set_ime_cursor_area` の呼び出し元は
  flush 実装と `Drop` のみである（grep で確認可能）
- [ ] AC-2: `notify_focus(true)` 記録後、flush まで mock window にコールが
  発生せず、flush 後に `set_ime_allowed(true)` がちょうど 1 回発生する
  （SPEC TS-1）
- [ ] AC-3: flush 前の複数 `notify_cursor_rect` は最後の rect 1 コールに
  合体し、同一 rect の dedup は従来どおり機能する（SPEC TS-2）
- [ ] AC-4: 同一ターンに記録された allow 状態と cursor rect は
  allow → cursor の順で flush される（SPEC TS-3）
- [ ] AC-5: 記録なしの flush は mock コールを発生させない（SPEC TS-4）
- [ ] AC-6: pending 要求を残した Drop は要求を破棄し、
  `set_ime_allowed(false)` をちょうど 1 回呼ぶ（SPEC TS-5）
- [ ] AC-7: 構築時 enable は記録され、初回 flush で発行される
  （flush 前 `[]` / flush 後 `[true]`）（SPEC TS-6）
- [ ] AC-8: 既存のゲート述語・イベント変換テストが意味論無変更でパスする
  （mock コールを観測するテストへの明示 flush 追加のみ許容）（SPEC TS-7）
- [ ] AC-9: 二重 Enabled / 二重 Disabled で warn 経路が発火し、同一種別の
  2 回目は latch されて再発火しない（SPEC TS-8）
- [ ] AC-10: `cargo check`（default features）と `cargo test --lib` が通る
