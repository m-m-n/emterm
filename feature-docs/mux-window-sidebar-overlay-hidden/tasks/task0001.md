# Task Plan: task0001 — Open overlay sidebar on mux attach transition

## Goal

The overlay-mode mux window sidebar is open immediately after emterm
attaches to a mux session (startup and reattach alike), restoring the AC-7
"default open" guarantee without a manual prefix + Ctrl+S toggle.

## Requirements

FR1, FR2, FR3, NFR1, NFR2

## Scope

### Files to Create

- None.

### Files to Modify

- `src-tauri/src/app.rs` — one attach-transition assignment in the
  `pump_all` bookkeeping block, doc-comment updates on the two related
  fields, and new inline unit tests.

## Design

### Verified anchors (see IMPLEMENTATION.md D1)

All positions verified at planning time (2026-08-03); anchor by code shape,
since SPEC.md's `3922-3929` claim had already drifted:

- Runtime flag `mux_sidebar_overlay_open`: declared near `app.rs:414`,
  initialized open at construction near `app.rs:921` (NFR2 — leave both
  unchanged except for the doc comment).
- User toggle: inside `dispatch_mux_action` near `app.rs:3100` (unchanged).
- Detach-guard block inside `pump_all`, near `app.rs:3979-3986`, in three
  steps: (1) compute whether the active tab is mux-attached now; (2) if the
  bookkeeping field `active_mux_attached_prev_pump` recorded the same tab as
  attached last pump and it is no longer attached, reset the flag to closed;
  (3) update the bookkeeping field for the next pump.

### Change

Insert the attach-transition rule between steps (2) and (3) — immediately
after the existing detach guard, before the bookkeeping update:

- **Precondition**: the bookkeeping field holds no value (end of previous
  pump: the then-active tab was not mux-attached, or this is the first
  pump) AND the active tab is mux-attached in the current pump.
- **Postcondition**: the overlay-open runtime flag is open.
- The predicate MUST read the bookkeeping field's pre-update value, i.e.
  the rule sits before step (3)'s reassignment — mirroring how the detach
  guard reads it.
- The rule is unconditional: no gate on the `window_sidebar_overlay`
  setting, matching the detach guard's ungated shape (the flag drives no
  rendering in persistent mode, so the assignment is inert there).
- Update the doc comments on `mux_sidebar_overlay_open` and
  `active_mux_attached_prev_pump` so they describe the open-on-attach rule
  alongside the existing teardown reset.

### Intended consequences (accepted — do not add discrimination logic)

1. Reattach after an explicit close re-opens the sidebar (FR3, accepted).
2. Switching the active tab from a non-mux tab to a mux-attached tab also
   fires the rule and re-opens the sidebar. Accepted per IMPLEMENTATION.md
   D2 — the single-slot bookkeeping cannot distinguish the two cases, and
   extending it would exceed NFR1's confinement.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1/FR2, TS1): New inline unit test — an app with one plain
      (non-mux) tab, overlay mode forced on, flag forced closed, pumped once
      to establish the not-attached baseline; after delivering a mux attach
      (the Welcome route the existing mux test fixture uses) and pumping
      again, the overlay-open flag reads open.
- [ ] AC-2 (FR3, TS1): New inline unit test — a mux-attached app pumped
      once; sidebar explicitly closed via the toggle action; a Detached
      message delivered and pumped (flag remains closed); a second attach
      delivered and pumped; the flag reads open again.
- [ ] AC-3 (FR1 negative, TS1): New inline unit test — while continuously
      attached (bookkeeping already recording the attached tab), an explicit
      close followed by further pumps leaves the flag closed: the rule fires
      only on the not-attached→attached transition, never on a steady
      attached state.
- [ ] AC-4 (NFR1 regression, TS2/TS3): The existing overlay test group
      passes unmodified — `ac7_mux_sidebar_overlay_open_on_a_freshly_constructed_app`,
      `mux_sidebar_overlay_resets_when_focused_tabs_mux_group_tears_down`,
      `mux_sidebar_overlay_survives_switching_away_from_the_mux_tab`,

## Test Notes

- AC-1..AC-3 are unit tests inline in `src-tauri/src/app.rs`'s existing
  `#[cfg(test)]` module, placed near the task0003 toggle/overlay test group.
  Reuse the existing helpers: the mux-window app fixture (builds an attached
  app via a real Welcome message), the overlay-mode settings helper, the
  pump entry point, and the message-delivery entry point the teardown test
  already uses for Detached.
- AC-1 needs a fixture variant that starts WITHOUT a mux group (plain app +
  initial tab, as several visibility-matrix tests already construct), then
  attaches via Welcome after the baseline pump. Forcing the flag closed via
  direct field assignment inside tests follows existing test precedent.
- AC-4 is pure regression: run the listed tests plus the full `--lib` suite.
  Pre-existing, unrelated flakiness in `tabs.rs` replay tests may require a
  single-threaded rerun (project convention); that flakiness is not a
  failure of this task.
- TDD order: write AC-1..AC-3 tests first (they fail against current code
  except where the flag's default-open masks the behavior — forcing the flag
  closed in the fixtures is what exposes the missing assignment), then add
  the assignment.

## Out of Scope

- Root-causing why the detach guard fires during the startup sequence
  (spurious Detached delivery vs. initialization ordering) — a separate
  future task.
- Any change to `src-tauri/src/tabs.rs`, the mux daemon, or the bridge
  (NFR1).
- Persisting the flag or touching the settings schema / the
  `window_sidebar_overlay` setting's semantics (NFR2).
- Any change to the overlay sidebar's appearance, opacity, or dimming
  behavior.
- Extending the attach bookkeeping (e.g. per-tab attach history) to
  suppress the switch-to-mux-tab reopen — accepted behavior per
  IMPLEMENTATION.md D2.
