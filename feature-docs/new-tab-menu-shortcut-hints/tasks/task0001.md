# Task Plan: task0001 — Shortcut labels on new-tab chooser rows

## Goal

The new-tab chooser (tab bar + button) shows, right-aligned on the "Global
Settings" row and on the row of the profile the `new_tab` keybind opens, the
canonical text of the shortcut that opens that row's target, derived from
the current resolved keybind table. Every other row, and the Ctrl+Shift+P
profile selector, is drawn as today.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify
- `src-tauri/src/ui/keybinds.rs` — add the chord label formatter and the reachable-label query (FR5, FR6)
- `src-tauri/src/ui/keybinds/tests.rs` — tests for the formatter (TS-1, TS-2, TS-3) and for the reachable-label query
- `src-tauri/src/ui/profile_selector.rs` — row-label assignment on the selector state; row display data gains an optional shortcut label; the row painter draws it and bounds the shell path, name and badge; unit tests for the assignment and the row geometry
- `src-tauri/src/app/chooser.rs` — App-level label query that feeds the assignment with the current App state
- `src-tauri/src/app/tests/chooser.rs` — App-level tests (TS-7, TS-8, and TS-4 to TS-6 if placed here)
- `src-tauri/src/render/overlays.rs` — attach each row's label when building the rows handed to the draw call

## Design

Cross-task context (layers, token reuse, no label caching, test-name
preservation) is in IMPLEMENTATION.md and is not restated here.

### Components

| Component | Location | Responsibility | Contract |
|-----------|----------|----------------|----------|
| Chord label formatter (NFR4 b) | `src-tauri/src/ui/keybinds.rs` | Turn one resolved chord into its canonical label text | See "Formatter contract" below |
| Reachable-label query (FR6) | `src-tauri/src/ui/keybinds.rs` | For `new_tab_global` or `new_tab`, return the formatted label of the action's resolved chord, or no label when a higher-priority action owns the same chord | See "Reachability contract" below |
| Row-label assignment (NFR4 a) | `src-tauri/src/ui/profile_selector.rs`, on `ProfileSelectorState` | Decide which row carries which label | See "Assignment contract" below |
| App-level label query (FR4) | `src-tauri/src/app/chooser.rs` | Run the assignment against the current App state | Reads `App.keybinds`, the `is_default` flags of `settings.profiles` and the selector state at call time; stores nothing, so the call after a settings apply reflects the new table; takes no locale |
| Overlay wiring | `src-tauri/src/render/overlays.rs` | Hand labels to the painter | When building the Global row and the profile rows for the draw call, attach each row's label from the App-level query by row index; tmux rows built inside the draw path carry no label, which matches the assignment |
| Row painter (FR7, NFR1) | `src-tauri/src/ui/profile_selector.rs`, draw path | Paint the label and keep the other row content out of its way | See "Row painting contract" below |

### Formatter contract

- Input: any chord. Output: a non-empty label; never panics.
- Enabled modifiers come first in the fixed order Ctrl, Shift, Alt (each
  only when set), then the main-key name; parts are joined with `+` and no
  spaces.
- Main-key names: letters as the uppercase letter, digits as the digit,
  function keys as F1 to F20, every other key as the word token
  `parse_chord` accepts for it in CamelCase (for example PageDown, ArrowUp,
  Plus, Minus, Comma, Backslash). A symbol alias (such as `+` or `,`) is never
  emitted; for `+` the symbol cannot round-trip because specs are split on
  `+`.
- For every main key `parse_chord` can produce, parsing the label returns
  the original chord. A key outside that set cannot appear in a resolved
  table; for it the formatter still returns a non-empty name, without a
  round-trip guarantee.
- No locale and no platform input (NFR2). No logging.

### Reachability contract

- Applies to the two actions `new_tab_global` and `new_tab`.
- Returns no label exactly when an action that comes earlier in the runtime
  match priority has the same resolved chord. The priority is the order
  `KeybindTable::collisions` reports as (winner, loser); the query is derived
  from that same ordering rather than from a second hand-written list
  (SPEC.md FR6). In effect: `new_tab_global` is hidden by copy, paste and
  profile_selector; `new_tab` by those three and `new_tab_global`.
- A collision with a lower-priority action (for example `new_tab` equal to
  `close_tab`) does not hide the label.
- The existing warn-level collision logging in table construction is not
  changed and the query itself does not log.

### Assignment contract

- Inputs: the selector state (its mode and its tmux rows), the ordered
  `is_default` flags of `settings.profiles`, and the resolved keybind table.
- Output: one optional label per row, as many entries as the dialog shows
  rows in the current mode (Global + profiles + tmux rows in chooser mode;
  profiles only in selector mode), in row order.
- Row identity is decoded through the existing row-to-choice mapping, the
  single site that knows the Global / profile / tmux offsets.
- Chooser mode: the Global row gets the reachable label of `new_tab_global`;
  the row of the first profile whose flag is set gets the reachable label of
  `new_tab`; every other row (other profiles, later flagged profiles, tmux
  rows) gets none. With no flagged profile only the Global row can carry a
  label. "First flagged" is the same rule the `new_tab` keybind uses to pick
  its profile (`crate::profiles::default_profile`, first flagged wins).
- Selector mode (`include_global` off): every entry is none (FR8).
- Pure: no egui context, no App, no I/O.

### Row painting contract

- A row without a label is laid out and painted exactly as today.
- A row with a label:
  - The label uses the shell path's font size (label-small 12px, the
    existing shell font constant) and the shell path's color for the row's
    state: md3 on-surface-variant on a normal or hovered row, and the
    on-secondary-container-derived shell color on the highlighted row. Both
    the shell path and the label take their color from one shared
    resolution.
  - The label is vertically centered like the shell path, and its right edge
    sits at the row's right edge minus the row's horizontal padding
    (ROW_PAD_X).
  - The shell path's available width runs from its start position to
    ROW_INNER_GAP before the label's left edge. When no width remains, the
    shell path is not drawn (the existing zero-width rule).
  - Name and Default badge painting is bounded by the same boundary
    (ROW_INNER_GAP before the label's left edge); anything past it is
    clipped, so a long name or the badge never paints under the label.
    Batch-mode planning assumption: SPEC.md FR7 requires no overlap but does
    not say how a long name yields; clipping was chosen over hiding the
    label so FR1/FR2 always hold.
- Separate the horizontal geometry (label rectangle, shell path range,
  content boundary) into a pure computation from the row's edges, the
  position after the name and badge, and the measured label width, so it is
  testable without an egui context; painting reads its results.
- No new constant or token in the four token files named in IMPLEMENTATION.md
  Conventions; reuse the constants already in the profile selector module.
- No field is added to `ProfileSelectorState`.

### Flow

1. Each frame while the selector is visible, the overlay pass asks App for
   the per-row labels.
2. App passes its current keybind table, the profile flags and the selector
   state to the row-label assignment.
3. The assignment decodes each row through the row-to-choice mapping and
   asks the reachable-label query for the Global row and the default-profile
   row.
4. The overlay pass attaches the labels to the row display data and calls
   the draw path.
5. For each labeled row the painter measures the label, computes the row
   geometry, paints the label, then paints the name, badge and shell path
   within the boundary.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR5, NFR4; TS-1, TS-3): The formatter, called with no egui context, returns: for the default table, `Ctrl+Shift+G` for `new_tab_global` and `Ctrl+Shift+T` for `new_tab`; for a table built from the `new_tab_global` spec `ctrl+shift+g`, `Ctrl+Shift+G`; for a chord with Ctrl, Shift, Alt and T, `Ctrl+Shift+Alt+T`; for a table built from an unparseable `new_tab` spec, `Ctrl+Shift+T` for `new_tab`.
- [ ] AC-2 (FR5; TS-2): Parsing the formatter's output with `parse_chord` returns the original chord for every chord of the default table, for PageDown, ArrowUp, Plus, F11, a digit and Comma, and for every main key `parse_chord` can produce (A to Z, 0 to 9, F1 to F20 and each named-key token).
- [ ] AC-3 (FR1, FR2, FR3, NFR4; TS-4, TS-5): In chooser mode with the default table, the assignment, called with no egui context, returns one entry per row in Global, profiles, tmux order, and: with profiles [A (default), B] and one tmux row, Global is `Ctrl+Shift+G`, A is `Ctrl+Shift+T`, B is none and the tmux row is none; with no default profile, only the Global row has a label (`Ctrl+Shift+G`); with profiles [A (default), B (default)], only A has `Ctrl+Shift+T`.
- [ ] AC-4 (FR6, NFR4; TS-6): When `new_tab_global` equals the copy, paste or profile_selector chord, the Global row has no label. When `new_tab` equals the copy, paste, profile_selector or `new_tab_global` chord, the default-profile row has no label. When `new_tab` equals `new_tab_global`, the default-profile row has no label and the Global row keeps its label. When `new_tab` equals a lower-priority action's chord (`close_tab`), the default-profile row keeps its label.
- [ ] AC-5 (FR8; TS-7): After App opens the profile selector through `open_profile_selector` (include_global off) with a default profile configured, the App-level query returns no label for any row.
- [ ] AC-6 (FR4, NFR2; TS-8): After `apply_settings` with `keybinds.new_tab_global` = `Ctrl+Alt+G` and `keybinds.new_tab` = `Ctrl+Alt+N`, reopening the chooser makes the App-level query return `Ctrl+Alt+G` for the Global row and `Ctrl+Alt+N` for the default-profile row; the query returns the same labels with the App locale set to Ja and to En.
- [ ] AC-7 (FR7, NFR1; TS-10, TS-9): The row geometry computation, called with no egui context, places a labeled row's label right edge at the row's right edge minus ROW_PAD_X, ends the shell path range ROW_INNER_GAP before the label's left edge (an empty range when no width remains), bounds name and badge at that same boundary, and gives an unlabeled row the same geometry as today. The label is painted with the shell font size and the shell path's state color (checked in TS-9).
- [ ] AC-8 (NFR1, NFR3; TS-11, TS-12): The CLI-only check (`--no-default-features`) compiles; the change modifies none of the four token files named in IMPLEMENTATION.md Conventions; every modified Rust source file is in the GUI-gated ui, app or render modules.

## Test Notes

- AC-1, AC-2 and the reachable-label query tests go in `src-tauri/src/ui/keybinds/tests.rs` (SPEC.md test placement). Tables with modified specs are built from modified keybind settings, the pattern the existing tests in that file use. For the exhaustive part of AC-2, enumerate the main-key tokens `parse_chord` accepts, parse each into a chord, format it and parse again.
- AC-3 and AC-4 call the assignment directly on a selector state (NFR4), either in the profile selector module's tests or in `src-tauri/src/app/tests/chooser.rs`. Cover every hide case of AC-4, not only the three SPEC.md TS-6 examples, so each priority branch is exercised.
- AC-5 and AC-6 are App-level tests in `src-tauri/src/app/tests/chooser.rs`, using the settings-based App constructor, `open_profile_selector`, the entry-injecting chooser-open variant and `apply_settings`. The public chooser-open path runs real tmux discovery; tests avoid it so they stay deterministic.
- AC-7: unit-test the pure geometry computation with synthetic row edges, start positions and label widths (labeled, unlabeled, and no-room cases). Colors and the actual painting are covered by the manual TS-9.
- AC-8: run the CLI-only check from `.claude/rules/core-build-location.md` and inspect the diff's file list.
- Existing tests keep their names. The existing test that builds a selector state field by field stays valid because no field is added.
- The full `--lib` run has known nondeterministic tests unrelated to this task (`tabs.rs` replay tests under parallel execution; the `tmux_sockets` discovery fork race). When one of them fails, rerun it alone or with `--test-threads=1` before treating it as a regression.

## Out of Scope

- Labels on the Ctrl+Shift+P profile selector, on profiles other than the first default profile, and on tmux rows.
- Changes to keybind parsing, resolution, dispatch order, fallback defaults or collision logging.
- New tokens or constants in the token files; changes to row height, name font, badge styling or the dialog size.
- Ellipsizing the profile name (it is only clipped at the label boundary).
- Caching labels, or adding fields to the selector state or App.
- Settings WebView or TypeScript changes.
- Crate-wide reformatting.
