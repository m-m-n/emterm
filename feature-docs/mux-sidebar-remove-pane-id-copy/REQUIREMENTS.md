# mux サイドバーの pane ID コピーボタン削除 - 要件定義書

## 1. 概要

### 1.1 背景

mux サイドバーの pane 行には、その pane の public pane ID をクリップボードへ
コピーするアイコンボタンが表示される（task0006 AC-5 で追加）。このボタンは
不要である。

### 1.2 目的

mux サイドバーの pane 行から pane ID コピーボタンを削除し、そのボタンのため
だけに存在するクリック判定・クリップボードコピー経路も併せて除去する。

### 1.3 スコープ

**対象**:

- `src-tauri/src/ui/mux_sidebar.rs` のコピーアイコン描画・ヒット判定・
  ホバーテキスト、およびそれ専用の定数・ヘルパー・構造体フィールド
- `src-tauri/src/render/mod.rs` のコピー要求の収集と `FrameEvents` への配線
- `src-tauri/src/window_host.rs` のコピー要求適用（`set_clipboard` 呼び出し）
- 上記に対応する単体テスト

**対象外**:

- エージェント状態バッジ（task0006 AC-1/AC-2）を含む、コピーボタン以外の
  サイドバー表示
- `App::mux_public_pane_ids` マップ本体と `App::mux_public_pane_id()`
  アクセサ（通知のレート制限キーで引き続き使用される）
- `WindowHost::set_clipboard`（選択コピーのキーバインドが使用する）

## 2. ビジネス要件

### 2.1 ビジネス目標

不要な UI 要素を除去し、サイドバーの表示と操作を pane 切り替えという
本来の役割に絞る。

### 2.2 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| eMterm 利用者 | mux サイドバーで pane を切り替えて使う |

### 2.3 期待される効果

- サイドバー行に不要な操作対象が無くなる
- コピーボタンのためだけに存在していたコードが無くなる

## 3. ユースケース

### 3.1 ユースケース一覧

| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | サイドバーで pane を切り替える | eMterm 利用者 | 高 |

### 3.2 ユースケース詳細

#### UC01: サイドバーで pane を切り替える

**アクター**: eMterm 利用者

**事前条件**:

- mux サイドバーが表示されている（persistent または overlay）
- エージェントが起動中で、pane の public pane ID が daemon から通知済み

**基本フロー**:

1. 利用者がサイドバーの pane 行を見る
2. 行には番号・エージェント状態バッジ・pane 名のみが表示され、
   コピーアイコンは表示されない
3. 利用者が行のどこをクリックしても、その pane への切り替えが発生する

**事後条件**:

- クリックした pane がアクティブになる
- クリップボードは変更されない

## 4. 機能要件

### 4.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | コピーアイコン非表示 | pane 行にコピーアイコンを描画しない | 高 |
| F02 | クリック判定除去 | 行内のコピー用ヒット領域を無くす | 高 |
| F03 | コピー経路除去 | サイドバー由来のクリップボード書き込み経路を除去 | 高 |
| F04 | 専用コード除去 | コピーボタン専用の定数・ヘルパー・フィールド・引数を除去 | 中 |

### 4.2 機能詳細

#### F01: コピーアイコン非表示

**説明**: `draw_rows` のコピーアイコン描画（`paint_copy_icon`）と
ホバーテキスト表示を削除する。行の名前表示幅が予約していたアイコン領域も
解放し、名前は行の右パディングまで使える。

#### F02: クリック判定除去

**説明**: `ui.interact(copy_icon_rect(rect), ...)` によるコピー用ヒット
ターゲットを削除する。行全体のクリックは従来どおり pane 切り替えとして
扱われ、`icon_clicked` による抑制も不要になる。

#### F03: コピー経路除去

**説明**: `SidebarOutcome.copy_pane_id` を削除し、`render::draw_terminal`
の `clipboard_copy_request` 収集と `FrameEvents::clipboard_copy` フィールド
（`FrameEvents::any()` の項目を含む）、`window_host` 側の
`set_clipboard` 適用ブロックを削除する。

#### F04: 専用コード除去

**説明**: `COPY_ICON_SIZE` / `COPY_ICON_GAP` / `copy_icon_rect` /
`paint_copy_icon` / `SidebarEntry::public_pane_id` を削除し、コピー
アイコンのホバーテキストのためだけに渡されていた `locale` 引数を
`draw` / `draw_persistent` / `draw_overlay` / `draw_rows` から削除する。
`render/mod.rs` の `public_pane_id` 添付処理も削除する。

**エラーケース**: なし（UI 要素とその専用経路の削除のみ）

## 5. 非機能要件

### 5.1 パフォーマンス要件

- 描画コストは削除により減るか同等。増加させない

### 5.2 セキュリティ要件

- クリップボードへの書き込み経路が 1 つ減る。残る書き込み経路
  （選択コピーのキーバインド）は変更しない

### 5.4 保守性要件

- 未使用コード（dead code）を残さない
- `cargo check` が警告を増やさない

### 5.5 互換性要件

- CLI ビルド（`--no-default-features`）に影響しない（対象は gui feature
  配下のみ）

## 6. UI/UX要件

### 6.1 画面設計要件

- pane 行の構成は `[番号] [バッジ] 名前` となり、右端の操作アイコンは無い
- 行の高さ・角丸・色（アクティブ / ホバー / 通常）は変更しない
- persistent / overlay の両バリアントで同じ結果になる

## 9. 制約条件

### 9.1 技術的制約

- 該当箇所: `src-tauri/src/ui/mux_sidebar.rs`（task0006 AC-5 で追加された
  copy-to-clipboard アイコン。`copy_icon_rect` / `paint_copy_icon` /
  `SidebarOutcome.copy_pane_id` など）
- `App::mux_public_pane_ids` は通知のレート制限キー生成で使われており
  削除できない

## 10. 想定される課題とリスク

### 10.1 技術的課題

| 課題 | 影響度 | 対応策 |
|------|--------|--------|
| `locale` 引数削除がテスト呼び出し箇所に広く波及する | 低 | 呼び出し箇所を機械的に更新し、テストで担保する |
| 行レイアウトの幅計算に副作用が出る | 中 | 既存のレイアウトテストで番号・バッジ・名前の位置を確認する |

## 12. テストシナリオ

### 12.1 テスト観点

- [ ] 正常系: public pane ID が既知の行でもコピーアイコンが描画されない
- [ ] 正常系: 行の右端（旧アイコン領域）をクリックすると pane 切り替えが
      発生する
- [ ] 回帰: バッジ有無での行レイアウト（番号・バッジ・名前の位置）が不変
- [ ] 回帰: persistent / overlay 双方で同じ挙動

## 13. 用語定義

| 用語 | 定義 |
|------|------|
| public pane ID | daemon が払い出す pane の外部公開 ID 文字列 |
| pane 行 | mux サイドバーに 1 pane ごとに描画される行 |
