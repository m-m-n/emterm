# Task Plan: task0001 — エージェント状態バッジの 4 状態絵文字統一

## Goal

エージェント状態バッジを 4 状態すべて絵文字表示に統一する。blocked は unseen=❓ / seen=❔、done は unseen=✅ / seen=💤（idle と同一クラスタ）とし、絵文字テクスチャ不在時の円フォールバックは既存の unseen=塗り / seen=リングの形を保つ。

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3

## Scope

### Files to Create

なし

### Files to Modify

- `src-tauri/src/ui/tab_bar.rs` — 新規絵文字クラスタ定数の追加、`badge_presentation()` の blocked/done 解決の絵文字化、Emoji 表示解決へのフォールバック形の伝搬、`resolve_badge_render_mode()` のフォールバック解決の更新、陳腐化する doc コメント（「フォールバックは常に塗り」「blocked/done は円」等）の追随、インラインテストの更新・追加
- `src-tauri/src/ui/mux_sidebar.rs` — 共有 painter の消費側。機能変更は想定しないが、blocked/done を円前提で記述した doc コメントやテスト表現があれば追随させる（変更不要ならそのままでよい）

## Design

### 表示テーブル（SPEC 4.2 のとおり）

| 状態 | unseen | seen |
|------|--------|------|
| working | ⚡ (U+26A1) | ⚡ (U+26A1) |
| idle | 💤 (U+1F4A4) | 💤 (U+1F4A4) |
| blocked | ❓ (U+2753) | ❔ (U+2754) |
| done | ✅ (U+2705) | 💤 (U+1F4A4、`IDLE_BADGE_EMOJI` と同一クラスタ) |

### D1: 新規クラスタ定数（FR6）

blocked unseen（U+2753）、blocked seen（U+2754）、done unseen（U+2705）の 3 定数を、既存の `WORKING_BADGE_EMOJI` / `IDLE_BADGE_EMOJI` と同形式（`tab_bar.rs` 内の公開文字列定数・単一コードポイント・VS-16 なし）で追加する。done+seen は新定数を作らず `IDLE_BADGE_EMOJI` をそのまま参照する。

### D2: `badge_presentation()` の解決変更（FR1 / FR2 / FR3 / FR5）

- 事前条件: 引数は既存どおり Aggregated（state + unseen）。シグネチャは変更しない。
- 事後条件: 4 状態 × unseen/seen の 8 組み合わせすべてが Emoji 表示解決になり、クラスタは上表のとおり。円の表示解決を直接返す状態はなくなる（円はテクスチャ不在時のフォールバック専用になる）。
- working / idle の解決結果は現状と同一（unseen/seen 非依存）を維持する。

### D3: フォールバック形の伝搬（FR4、SPEC A1）

現行の Emoji フォールバックは「working/idle は常に塗り」という前提で常に塗り円へ解決している。blocked/done が絵文字化されるとこの前提が崩れ、seen=リングを保てない。そこで契約を次のとおり変更する。

- Emoji 表示解決は、テクスチャ不在時に使うフォールバック円の形（塗り / リング）を併せて保持する。形の導出元は既存の `agent_badge_filled()` のセマンティクス（blocked/done は unseen=塗り / seen=リング、working/idle は常に塗り）。`agent_badge_filled()` 自体は変更しない。
- `resolve_badge_render_mode()` の事後条件: テクスチャ利用可なら絵文字テクスチャの blit、不在なら保持されたフォールバック形の円へ解決する。空白バッジ・toolkit 既定テキスト経路には決してならない。
- 表示解決の値はモジュール内（`paint_agent_badge` とインラインテスト）でのみ構築されるため、この契約変更に伴う呼び出し側の更新は `tab_bar.rs` 内で完結する。`paint_agent_badge` のシグネチャは変えず、mux サイドバーの消費経路（`mux_sidebar.rs` の `paint_agent_badge` 呼び出し）は無変更で成立させる。

### D4: 変更しないもの（NFR1 / NFR2、SPEC A2）

- `agent_badge_filled()` の判定内容
- `agent_state_color()`（`ui::status_bar` と共有。色役割はフォールバック円の描画にのみ効く）
- 集約優先度・unseen フラグの set/clear（`agent_status_model.rs` / `app.rs`）
- `AGENT_BADGE_SLOT_WIDTH` と統一バッジスロットのレイアウト
- 絵文字テクスチャの untinted blit・ラスタライズ経路

### D5: 既存テストの追随

blocked/done が円の表示解決であることを前提にした既存インラインテスト（blocked/done の円解決テスト、フォールバック解決テストなど）を新テーブルの期待値に更新する。working/idle の既存期待値は変えない。

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `badge_presentation()` が 4 状態 × unseen/seen の 8 組み合わせすべてを表示テーブルどおりのクラスタ（working=⚡/⚡、idle=💤/💤、blocked=❓/❔、done=✅/💤）の Emoji 表示解決にする
- [ ] AC-2: done+seen のクラスタが `IDLE_BADGE_EMOJI` と同一定数（同一文字列）である
- [ ] AC-3: 新規クラスタ定数が既存定数と同形式（`tab_bar.rs` 内の公開文字列定数・単一コードポイント・VS-16 なし）で定義されている
- [ ] AC-4: テクスチャ不在時、blocked/done は円フォールバックに解決され、unseen=塗り / seen=リングの形を保つ。空白バッジ・toolkit 既定テキスト経路には決してならない
- [ ] AC-5: テクスチャ不在時、working / idle のフォールバックは従来どおり塗り円のまま
- [ ] AC-6: 表示判定は `badge_presentation()` の 1 箇所のまま（`tab_bar.rs` の外に新たな判定ロジックを作らない）。mux サイドバーは共有 painter 経由の既存経路を維持する
- [ ] AC-7: 集約優先度・unseen set/clear・`agent_state_color()`・done の内部状態に変更がなく、`--lib` スイート全体がグリーン（main 基線比）

## Test Notes

- AC-1〜AC-5 はユニットテスト。`tab_bar.rs` の既存インラインテストモジュールに置き、`--lib` で走る形にする（NFR3、`test/README.md` の規約）。
- AC-1 は 8 組み合わせのテーブルテスト 1 本にまとめる（VERIFICATION.md TS-1）。
- AC-2 は定数の同一文字列検証（TS-3）。AC-3 はコードポイント・VS-16 なしの検証を TS-1/TS-3 に含める。
- AC-4 / AC-5 は「テクスチャ不在」を表す引数でのフォールバック解決検証（TS-2）。UI コンテキスト無しで呼べる既存テストの形を踏襲する。
- AC-6 / AC-7 は既存スイートの回帰（TS-4）とレビューでの確認。
- 既知の基線: `tabs.rs` の replay テストは並列実行で非決定的に落ちることがある（main 基線の既知事象）。失敗が出た場合は main 基線との差分で判定する。
