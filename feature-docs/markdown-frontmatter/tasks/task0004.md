# Task Plan: task0004 — Collapsible block view + styles + i18n

## Goal

Deliver the front matter block UI: a collapsed-by-default, MD3-token-styled
DOM component with a "Front Matter" label and format badge in the header,
an always-fully-expanded tree when opened, and the parse-error fallback
state (error notice + raw text).

## Requirements

FR4, FR5 (visual half), FR6, NFR1, NFR2, NFR3

## Scope

### Files to Create
- `src-tauri/web-shared/markdown/frontmatter/view.ts` — block DOM builder
  (header, toggle behavior, tree rows, error state)
- `src-tauri/web-shared/markdown/frontmatter/view.test.ts` — DOM tests
  (happy-dom)
- `src-tauri/web-shared/markdown/frontmatter/frontmatter.css` — block +
  tree styles on `--md-sys-*` tokens

### Files to Modify
- `src-tauri/web-shared/i18n/locales/en.json` — parse-error notice string(s)
- `src-tauri/web-shared/i18n/locales/ja.json` — same keys, Japanese

## Design

- Input: the shared extraction + parse result contracts from
  `frontmatter/types.ts` (task0001) and the node list from
  `tree-builder.ts` (task0003) — both wave 1, already merged.
- Output: one detached DOM element the integration layer mounts above the
  rendered body (IMPLEMENTATION.md D3). The component manages its own
  open/closed state; default closed.
- Header row: "Front Matter" label + format badge (YAML / TOML / JSON,
  derived from the extraction format). Clicking the header toggles the
  content area. In the error state the header additionally shows the
  parse-failure indication (i18n string).
- Content area (success): tree rows from the flat node list — indentation
  by depth, key styling distinct from value styling, always fully expanded,
  no per-node toggles.
- Content area (failure): the i18n parse-error notice with the parser's
  message, plus the raw front matter text preformatted.
- XSS (NFR1): every key / value / error / raw string enters the DOM via
  text nodes; the subtree is built element-by-element — no HTML-string
  assembly anywhere in this module.
- Styling (NFR2): `--md-sys-*` tokens only; tree look modeled on the native
  data viewer (key/value coloring, indentation); works in light and dark
  themes.
- i18n (NFR3): notice strings via the shared i18n mechanism; "Front
  Matter" and format names stay untranslated.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Building the block for a successful parse yields a collapsed
      element showing only the header with label and the correct format
      badge for each of yaml / toml / json.
- [ ] AC-2: Activating the header expands the content (tree visible);
      activating again collapses it.
- [ ] AC-3: The expanded tree shows one row per node with depth-based
      indentation and both keys and scalar values visible.
- [ ] AC-4: For a parse failure, the header indicates the failure, and the
      expanded content shows the error notice (localized string present in
      both en and ja locales) and the raw text.
- [ ] AC-5: Keys/values/raw text containing HTML markup (`<script>`,
      `<img onerror>`) appear as literal text in the DOM — no element is
      created from front-matter-derived strings.
- [ ] AC-6: An empty parse tree renders the expanded state without rows and
      without errors.
- [ ] AC-7: The stylesheet references only `--md-sys-*` custom properties
      for colors.

## Test Notes

DOM tests under happy-dom (`test-setup.ts` initializes i18n); covers
SPEC.md TS-8, TS-9, TS-10 (view half). AC-7 can be asserted by scanning
the CSS text for hard-coded color literals. Visual fidelity in real
WebViews is manual (VERIFICATION.md MT-1/MT-2), not unit-tested.
