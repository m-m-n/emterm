# Task Plan: task0003 — Tree builder (legacy port)

## Goal

Deliver the DOM-free tree-building stage: convert a parsed JS value tree
into the flat, display-ordered node list that drives the always-fully-
expanded tree view — a TS port of the legacy WebView implementation.

## Requirements

FR5 (logic half; the visual half is task0004)

## Scope

### Files to Create
- `src-tauri/web-shared/markdown/frontmatter/tree-builder.ts` — flat node
  list builder; defines and exports its own node type (IMPLEMENTATION.md D4)
- `src-tauri/web-shared/markdown/frontmatter/tree-builder.test.ts` — unit
  tests

### Files to Modify
- (none)

## Design

Port from the `legacy/webview` branch, `src/data-viewer/tree-builder.ts`
(and its test file), adapted to this feature's needs:

- Input: any parsed JS value.
- Output: a flat array of nodes in display order. Each node carries: key
  (object key, or `[i]` for array elements), depth (0 for top level, +1 per
  nesting level), path (dot-joined keys / bracketed indexes), value, and a
  has-children flag (true for non-null objects/arrays).
- Containers contribute their children recursively; recursion stops at
  depth 128 (MAX_DEPTH) to bound adversarial input.
- A non-container root (scalar front matter, e.g. a YAML document that is
  just a string) yields a defined result the view can render (single
  value row or empty list — decide and test it).
- The node type is defined locally in this module, not in
  `frontmatter/types.ts` (keeps this task file-independent from task0001).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A nested object produces one node per key at every level, in
      source order, with correct depth and path values.
- [ ] AC-2: Arrays produce `[i]`-keyed nodes; nested containers inside
      arrays recurse with incremented depth.
- [ ] AC-3: Leaf nodes report has-children false; container nodes true.
- [ ] AC-4: Input nested deeper than 128 levels is truncated at the cap
      without error or stack overflow.
- [ ] AC-5: Scalar / null / empty-object roots yield the documented result
      without throwing.

## Test Notes

Pure-function unit tests (no DOM); covers SPEC.md TS-7. The legacy test
file is a porting reference for expected shapes — extend it with the
scalar-root and depth-cap cases if the legacy suite lacks them.

## Out of Scope

- Any DOM/rendering (task0004).
- Selection, keyboard navigation, detail panes — the legacy data viewer
  features not needed by the always-expanded front matter tree.
