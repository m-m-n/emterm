# Task Plan: task0010 — Rework 5: clamp error-state raw display

## Goal

Resolve the round-5 finding (see `reviews/round5.yaml`, 51c277a7): the
error-state raw text must never reach the DOM unbounded — clamp it to a
display bound with a truncation marker so oversized front matter cannot
freeze the WebView via layout instead of parsing.

## Requirements

NFR1 (bounded work on hostile input; SPEC Security Considerations now
mandates the display clamp)

## Scope

### Files to Create

### Files to Modify
- `src-tauri/web-shared/markdown/frontmatter/limits.ts` — add the display
  bound for error-state raw text (order of 64 KiB; document that it is a
  UI/display bound, distinct from the parse bound)
- `src-tauri/web-shared/markdown/frontmatter/view.ts` — clamp the raw

- `src-tauri/web-shared/markdown/frontmatter/view.test.ts` — over-bound

  rendered verbatim (no marker)

## Design

`buildErrorView` currently assigns `extraction.raw` to the `<pre>` text
node without any bound, while the raw can be as large as the Rust-side
session cap (100 MiB). Clamp at the view boundary: slice the raw to the
display bound and append a marker (reuse the existing localized
truncated-notice string if it fits naturally, or a simple ellipsis marker
— the marker itself is not front-matter-derived so a literal is fine).
The clamp applies to the error path only; the success path renders tree
rows already bounded by MAX_NODES. Constant lives in `limits.ts` with the
other bounds. No change to parser/extractor behavior.
