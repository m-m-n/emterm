## Design

Three sub-goals, one worktree (their files interlock, so they cannot be
separate same-wave tasks):

### 1. Theme-following tokens (NFR2)

Outcome: with an effective light theme the block renders with light token
values; with dark, dark values; switching is driven by the viewer's
existing effective-theme input (the payload appearance). Constraints:

- Do not add another hand-maintained copy of `--md-sys-*` values. First
  candidate: reuse the token definitions that already exist in
  `web-shared/styles.css` (the token SSOT mirror) — e.g. import them into
  the viewer bundle and activate the right set via the mechanism that
  stylesheet already uses for theme switching. Investigate that mechanism
  before choosing.
- If a value copy genuinely cannot be avoided, keep it in ONE place and add
  an automated drift test that fails when it diverges from
  `web-shared/styles.css`.
- Replace the static-grep AC-7 style test with one that asserts the
  resolved/active token values actually differ between light and dark
  application (kills the false-assurance gap flagged in 95a9b4db).

### 2. Single extraction at the boundary (architecture a150c434)

Outcome: `extractFrontMatter` runs once per document. The viewer entry
extracts, hands the stripped body to the renderer, and reuses the same
extraction for the block. The shared renderer goes back to rendering
exactly the string it is given (no hidden stripping). The reviewer
confirmed the renderer has a single consumer (the viewer entry), so no
other caller loses behavior. FR7's passthrough guarantee moves with the
extraction point: no front matter → the entry hands the renderer the
original source unchanged.

### 3. Resource caps (security 8cab75d1, architecture c04fd0d7)

Outcome: hostile front matter cannot drive unbounded work.

- Normalization: guard against cyclic parse results (seen-set) so a
  self-referential YAML alias yields a captured parse failure or a safe
  placeholder — never a hang/uncaught stack exhaustion.
- Tree building: enforce a total node budget (documented constant) on top
  of MAX_DEPTH; traversal stops at the budget.
- View: when the budget was hit, show a localized truncated notice so the
  user knows the tree is partial.

- [ ] AC-2: No new hand-maintained `--md-sys-*` value copy exists; either
      the viewer reuses the styles.css definitions, or a drift test pins
      the single remaining copy to them.
- [ ] AC-3: `extractFrontMatter` executes exactly once per rendered
      document (observable via the module seam in tests), and
      `MarkdownRenderer.render()` no longer strips anything: rendering a
      string starting with `---` through render() directly renders it as
      markdown.
- [ ] AC-4: The full front-matter pipeline still satisfies the round-1
      contracts: body free of delimiter artifacts, block mounted above the
      body, error state for broken content, no block and unchanged output
      for front-matter-less documents.
- [ ] AC-5: A YAML front matter with a self-referential alias completes
      parsing with a defined result (parse failure or safe value) with no
      hang or uncaught exception.
- [ ] AC-6: Front matter whose parsed tree exceeds the node budget renders
      a truncated tree plus a localized notice (en/ja), with DOM row count
      bounded by the budget.
- [ ] AC-7: The full `bun test` suite passes with no new failures beyond
      the 2 known pre-existing entry.test.ts cases; typecheck and the
      viewer/settings builds succeed.
