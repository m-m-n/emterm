# Task Plan: task0001 — Front matter extractor + shared types

## Goal

Deliver the DOM-free detection/extraction stage: given a Markdown source
string, decide whether it starts with a YAML / TOML / JSON front matter
block, and if so return the raw block content, its format, and the body with
the block stripped. Also establish the shared type contracts used by every
other task.

## Requirements

FR1, FR2 (and the fast-path half of NFR4)

- `src-tauri/web-shared/markdown/frontmatter/extractor.ts` — detection +

### Files to Modify
- (none)

## Design

Detection rules (SPEC.md FR1, exclusive branch on the leading delimiter):

1. Tolerate a UTF-8 BOM before the first character.
2. YAML: first line is exactly `---` (trailing whitespace allowed). Block
   ends at the next line that is exactly `---` (same tolerance). Content is
   the lines between the delimiters.
3. TOML: identical shape with `+++` delimiters.
4. JSON: first non-BOM character is `{`. Block ends at the matching closing
   brace, found by balancing braces while skipping JSON string literals
   (double-quoted, backslash escapes honored). Content includes both braces.
5. Anything else — including a blank or whitespace first line — means "no
   front matter".
6. Missing closing delimiter / unbalanced brace → "no front matter" (the
   whole source is body; FR6 does NOT apply here).
7. CRLF line endings must be handled (delimiter match tolerates a trailing
   carriage return).

Stripping rule (FR2): the returned body is the source minus the block and
the newline immediately following it. In the "no front matter" case the
body MUST be the original string, reference-identical where possible (this
is the FR7 / NFR4 fast path).

The extractor performs no parsing of the block content (IMPLEMENTATION.md
D5) — delimiter integrity only.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A document starting with a `---` line and containing a later
      `---` line yields a YAML extraction whose raw content is the text
      between the delimiters and whose body no longer contains the block.
- [ ] AC-2: The same shape with `+++` delimiters yields a TOML extraction.
- [ ] AC-3: A document starting with `{` yields a JSON extraction ending at
      the balanced closing brace, including when `{`, `}`, `"` (escaped)
      appear inside string literals; the body starts after the block.
- [ ] AC-4: Documents with no front matter — body text first, blank first
      line, `---` appearing only mid-document, `***` first — return "no
      front matter" with the source unmodified.
- [ ] AC-5: Unterminated blocks (`---` never closed, unbalanced `{`) return
      "no front matter" with the source unmodified.
- [ ] AC-6: A UTF-8 BOM before the delimiter does not defeat detection;
      CRLF sources are detected and stripped correctly.
- [ ] AC-7: An empty block (`---` immediately followed by `---`) yields an
      extraction with empty raw content and a correctly stripped body.
- [ ] AC-8: A document that is only a front matter block (no body after)
      yields an extraction with an empty body.

## Test Notes

All criteria are pure-function unit tests (no DOM). Cover the SPEC.md
scenarios TS-1 (extraction half), TS-3, TS-4, TS-5, and the edge cases
(BOM / CRLF / empty block / front-matter-only file). The JSON
brace-balancing cases (AC-3, AC-5) are the highest-risk area per
IMPLEMENTATION.md Risk Assessment — give them the densest coverage.
