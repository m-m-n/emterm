## Design

### 1. Depth-cap truncation notice (FR5, high)

`addChildren` currently returns at `depth >= MAX_DEPTH` without setting the
truncation flag, so depth-based truncation never triggers the localized
partial-tree notice that node-budget truncation shows. Outcome: exceeding
EITHER cap reports truncation through the same flag, and the existing view
notice fires. Tests pin both cap kinds.

### 2. Neutral limits module (architecture)

`MAX_NODES` (and `MAX_DEPTH`) move to `frontmatter/limits.ts`; parser and
tree-builder both import from it. The parser no longer imports anything
from the view-layer tree-builder module. No behavioral change; constants
keep their values (2000 / 128) — the SPEC names them.

### 3. Themed error accent (NFR2, medium)

The parse-error accent currently uses hardcoded hex literals gated on
`:root[data-theme="dark"]`. Outcome: the accent is drawn from the viewer's
theme-aware palette path (the same mechanism that supplies the other
`--markdown-*` colors, which updates on live OS theme flips), and
`frontmatter.css` contains no color literals. If this removes the last
consumer of the `data-theme` attribute gate introduced by task0007, do not
leave the now-unused mechanism behind — remove it (attribute write flag,
CSS gate) and its tests, or report why it must stay. The accent must still
differ appropriately between light and dark themes.
