# Task Plan: task0009 — Rework 4: pre-parse raw size guard

## Goal

Resolve the round-4 finding (see `reviews/round4.yaml`, 9827537c): bound
the work the YAML/TOML/JSON parser libraries can be forced to do by
rejecting oversized raw front matter before it is handed to any parser.

## Requirements

mandates `MAX_RAW_BYTES`)

### Files to Modify

- `src-tauri/web-shared/markdown/frontmatter/parser.test.ts` — over-limit
  and at-limit cases

## Design

The guard lives at the top of the parse entry point: measure the raw
content (byte-oriented measure preferred over UTF-16 length; document the
choice), and if it exceeds `MAX_RAW_BYTES` return the standard parse
failure carrying a message that states the size limit. The failure flows
through the existing FR6 fallback (error notice + raw text). Note the raw
text is also rendered via textContent in the error view — rendering a
just-over-limit raw is acceptable (DOM text insert is cheap relative to
parsing); no view change is needed. No behavior change for content at or
below the bound.
