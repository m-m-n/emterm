# Task Plan: task0002 — Format parsers + library selection

## Goal

Deliver the DOM-free parsing stage: given raw front matter content and its
format, produce a plain JS value tree or a captured parse failure. Includes
selecting and adding the YAML and TOML parser libraries.

## Requirements

FR3

## Scope

### Files to Create
- `src-tauri/web-shared/markdown/frontmatter/parser.ts` — format dispatch
  to the three concrete parsers
- `src-tauri/web-shared/markdown/frontmatter/parser.test.ts` — unit tests

### Files to Modify
- `package.json` — add the selected YAML and TOML parser dependencies
- `bun.lock` — lockfile update from the dependency addition

## Design

- Input: raw content string + format value; both come from the shared
  extraction contract in `frontmatter/types.ts` (task0001, wave 1 — already
  merged when this task starts).
- Dispatch: JSON → built-in JSON parsing; YAML / TOML → the selected
  libraries.
- Output: the shared parse-result contract — success with a value tree of
  plain object / array / string / number / boolean / null, or failure with
  the underlying parser's error message. Any exception from a parser
  library is caught and converted to a failure; the function never throws
  (IMPLEMENTATION.md D5).
- Normalization: library-specific value types (e.g. TOML date/time values)
  are converted to plain strings/numbers so the tree builder and view only
  ever see plain JS values.

**Library selection (in-task decision, record the outcome in the task
report):** evaluate the SPEC.md candidates (`js-yaml` / `yaml`;
`smol-toml` / `@iarna/toml`) on: bundle size impact, bun-bundler
compatibility (the viewer bundle is built with `bun build`), maintenance
state, and error-message quality (messages surface in the FR6 UI). Prefer
the smallest adequate option.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Valid YAML content (nested maps, lists, scalars incl. numbers,
      booleans, null) parses to the corresponding plain JS value tree.
- [ ] AC-2: Valid TOML content (tables, arrays, key-values; a date value)
      parses to a plain JS value tree containing only plain types.
- [ ] AC-3: Valid JSON content parses to the corresponding value tree.
- [ ] AC-4: Broken content in each of the three formats yields a failure
      result carrying a non-empty error message — no exception escapes.
- [ ] AC-5: Empty content yields a defined, non-throwing result (empty/null
      tree treated as success so FR4's empty-tree display works).
- [ ] AC-6: `bun run build:viewer` succeeds with the new dependencies
      (bundler compatibility).

## Test Notes

Pure-function unit tests (no DOM); covers SPEC.md TS-1/TS-2/TS-3 (parsing
half), TS-6 (failure capture), TS-10 (empty block). AC-6 is verified by
running the build once in-task, not by a unit test.

## Out of Scope

- Detection/stripping (task0001).
- Tree building and UI (task0003 / task0004).
- Where error messages are displayed (task0004).
