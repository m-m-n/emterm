# Task Plan: task0002 — Plain-tab half of the SC-1z parity corpus

## Goal

The plain tab processes every SC-1z row (K58-K64) in one bulk call from the
S-W seed and ends in the row's final OSC 7501 table, OSC 777 state and, where
given, table-change count. This pins the reference outcome that the mux half
is asserted against (FR4).

## Requirements

FR4, FR5, FR8, NFR5

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/tabs/tests/output_pipeline.rs` — a K58-K64 list of its own, with the same row shape as the existing K38-K57 list, and the tests that run it; the existing lists and tests stay unchanged.

## Design

- The rows, their notation, their streams, their lengths and their expected
  outcomes are SC-1z in IMPLEMENTATION.md (Shared Components). Build each
  stream from that notation exactly, and assert each stream's length and its
  byte string against the table.
- Delivery follows IMPLEMENTATION.md D3. Each row starts on a plain tab
  seeded with S-W and is processed in one `process_combined` call. The plain
  side ignores the "Mux deliveries" column.
- What is asserted per row, in the same way as the existing K38-K57 list:
  - the final OSC 7501 table
  - the final OSC 777 state
  - where the row gives one, the number of pending summary changes, which is
    the plain side's measure of table changes
  - no OSC 7501 answer written
- The plain tab is the oracle (IMPLEMENTATION.md D1). No production file
  changes. If a row's outcome differs from SC-1z, report the row as a plan
  deviation. Do not change term_core, the plain-tab path or the expectation.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR4, FR5; TM-1): each of K58-K64, processed in one
  `process_combined` call on a plain tab seeded with S-W, ends in the row's
  final OSC 7501 table and final OSC 777 state, with no OSC 7501 answer
  written. Where the row gives a table-change count, the number of pending
  summary changes equals it.
- [ ] AC-2 (FR5): the rows form a list of their own that holds exactly
  K58-K64 in order.
  - Each stream is built from the SC-1z notation, has the length the table
    lists, and equals the byte string the notation spells out.
  - Each row has seed S-W and the one-call delivery.
  - The K1-K15, K16-K37 and K38-K57 lists, and the tests that pin their
    names, are unchanged.
- [ ] AC-3 (FR8, NFR5): no production file and no file under
  `crates/term_core/` changes. Every existing test in `output_pipeline.rs`
  passes unchanged, and the src-tauri `--lib` suite passes.

## Test Notes

- These are integration-style tests on the plain tab (GUI build, default
  features). They pass on the unmodified code base, because the plain tab
  is the reference. TDD here means writing the rows and confirming they hold
  the SC-1z outcomes. The rows never need a red phase.
- Rows that matter most as oracle checks:
  - K58 (reproduction 1) and K59: the second compound leaves term_core on
    the alternate screen, so the mark is not counted and the root `working`
    record stays with 0 table changes.
  - K60 and K61: the second compound returns term_core to the main screen,
    so the mark removes the record and the table ends empty.
  - K62 (reproduction 2): term_core takes the `ESC` after `ESC (` as the
    designator, so the following `c` is text and no RIS happens.
  - K63: the `ESC c` after the compound is a RIS, and the mark after W
    removes the re-reported record.
  - K64: the ?1047h after C1l takes term_core back to the alternate screen.
- Name the new tests with the `altdetect_` prefix and the AC labels above
  (IMPLEMENTATION.md Conventions).

## Out of Scope

- The mux half of SC-1z and any change to the mux reader or the tracker.
- Any change to term_core, to the plain-tab callbacks or to existing rows.
