# Task Plan: task0001 — Recognize the remaining use-line forms in the ac8 allowlist checker

## Goal

The ac8 allowlist checker (test-only) recognizes four more use-line forms:
several leading attributes on one line, `use` directly followed by `::` or `{`,
`[` / `]` inside a string literal in an attribute, and a multi-line attribute
that closes on the use line. A non-allowlisted use root written in any of these
forms is reported as a violation, and every existing ac8 expectation keeps
holding.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/program_status/tests.rs` — extend the use-line recognition of the ac8 allowlist checker (FR1-FR4) and add the new ac8 self-tests (FR5)

## Design

### Responsibilities

Every component below lives in the test-only module above. Nothing outside it
changes (NFR1).

| Component | Responsibility | Change in this task |
|---|---|---|
| `ac8_check_allowlist` | Scans a source text line by line and returns the violations | Carries an open-attribute state from one line to the next (FR4) |
| Use-line recognition (inside the checker) | Decides whether a line, or the rest of a line after a closing attribute, is a use line, and isolates its use path | Skips any number of leading attributes (FR1); tracks attribute brackets with string-literal awareness (FR3); accepts `use` directly followed by `::` or `{` (FR2) |
| Root extraction | Takes the first `::`-separated segment of the use path | Unchanged |
| `ac8_violation` | Builds the violation text | Unchanged (NFR2) |
| `AC8_ALLOWED_PROJECT_PATH`, `AC8_ALLOWED_USE_ROOTS` | The allowlist | Unchanged (FR6) |

### Attribute scanning rules (FR1, FR3)

An attribute starts at `#[` and ends at the `]` that brings its bracket depth
back to zero.

- Outside a string literal: `[` raises the depth by one, `]` lowers it by one,
  and `"` opens a plain string literal.
- Inside a string literal: `[` and `]` leave the depth unchanged. A backslash
  makes the next character on the same line part of the literal, so `\"` does
  not close it and `\\` is one literal backslash. An unescaped `"` closes it.
- Raw strings and char literals get no special treatment (A2).

### State carried across lines (FR4)

The checker holds one piece of state between lines: whether a leading attribute
is still open, and if so its bracket depth and whether it is inside a string
literal.

- Initial state: no open attribute.
- A line that opens a leading attribute and reaches its end with the depth
  still above zero is not a use line. The attribute's depth and string state
  carry to the next line.
- A line read while an attribute is open continues that attribute from its
  first character, under the rules above. If the attribute stays open through
  the end of the line, the line is not a use line. If it closes, the
  open-attribute state is cleared and the text after the closing `]` goes
  through the per-line flow below from step 2.

### Per-line flow

1. If an attribute is open, continue it as described above.
2. Drop leading whitespace. While the text starts with `#[`, consume one
   attribute; after it closes, drop any whitespace (possibly none) and repeat.
   If an attribute is still open at the end of the line, stop: the line is not
   a use line.
3. Accept the optional visibility (`pub` / `pub(..)`), keeping every form the
   checker already accepts.
4. Accept the `use` keyword when it is followed by whitespace, by `::` or by
   `{`, keeping every form the checker already accepts (such as a line that
   holds only `use`).
5. Pass the use path to root extraction, compare the root with the allowlist,
   and report a mismatch through `ac8_violation`. The offending line is the
   physical line on which the `use` keyword appears.

Postconditions:

- A `::`-led or `{`-led use path is a violation whether or not whitespace
  follows `use` (FR2, A1). Root extraction is unchanged and yields no
  allowlisted name for such a path.
- `#!` inner attributes and block comments between an attribute and `use` are
  not handled (A5).
- Every source the existing ac8 tests feed, and `program_status.rs`, give the
  same result as before (FR6).

### Self-tests to add (FR5, A4)

- Every new test name starts with `ac8_`, so the `program_status::tests::ac8`
  filter selects it. No existing test is renamed or edited (FR6).
- Each new test feeds a synthetic source to `ac8_check_allowlist`.
- Forms 1, 3 and 4 get rejection tests and allowed-root tests. Form 2 gets
  rejection tests only (A1, A4).
- How the cases are grouped into test functions is the implementer's choice.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR5): Each of `#[cfg(a)] #[allow(b)] use winit::event::Event;`,
  `#[cfg(a)]#[allow(b)] pub use winit::event::Event;` and
  `#[cfg(a)] #[allow(b)] pub(crate) use winit::event::Event;` is rejected by
  `ac8_check_allowlist` with a violation reporting use root `winit`.
  `#[cfg(test)] #[allow(unused)] use std::fmt;` yields no violation.
- [ ] AC-2 (FR2, FR5): Each of `use::winit::event::Event;`,
  `use{winit::event::Event};`, `pub use::winit::event::Event;`,
  `pub(crate)use{winit::event::Event};`, `use ::std::fmt;` and
  `use {std::fmt};` is rejected with at least one violation. These tests
  assert rejection only, not the reported root.
- [ ] AC-3 (FR3, FR5): Each of `#[cfg(feature = "]")] use winit::event::Event;`,
  `#[cfg(feature = "[")] use winit::event::Event;` and
  `#[doc = "\"]"] use winit::event::Event;` is rejected with a violation
  reporting use root `winit`. `#[cfg(feature = "]")] use std::fmt;` yields no
  violation.
- [ ] AC-4 (FR4, FR5): The source whose four lines are `#[cfg(all(`, `unix,`,
  `feature = "gui"` and `))] use winit::event::Event;` is rejected, and the
  violation's offending line is the fourth line, the one carrying
  `))] use winit::event::Event;`. Each of the following yields no violation:
  the same source with its last line `))] use std::fmt;` instead; the source
  whose four lines are `#[derive(`, `Debug,`, `)]` and `pub struct X;`; a
  multi-line attribute that closes on its own line, followed by a line holding
  `use std::fmt;`.
- [ ] AC-5 (NFR2): Every violation produced for the rejected sources of AC-1,
  AC-3 and AC-4 contains the offending line, `super::agent_status` and
  ``without the `gui` feature``.
- [ ] AC-6 (FR6): `AC8_ALLOWED_PROJECT_PATH`, `AC8_ALLOWED_USE_ROOTS`, the
  existing self-test constants and assertions, and the existing test names are
  unchanged. Every existing `ac8_*` test passes, including
  `ac8_the_module_uses_only_always_built_crates` on the current
  `program_status.rs`.
- [ ] AC-7 (NFR1): Apart from the workflow-generated test record under
  `test-docs/program-status-ac8-use-line-forms/`, the task's diff changes only
  `src-tauri/src/program_status/tests.rs`: no production code, no `Cargo.toml`,
  no `lib.rs` and no new crate.

## Test Notes

- Every criterion is a unit test in `src-tauri/src/program_status/tests.rs`,
  run with the project's `--lib` test command.
- Red phase: the rejection cases of AC-1, AC-3 and AC-4 and the no-space cases
  of AC-2 are expected to fail before the change. The with-space AC-2 cases
  (`use ::std::fmt;`, `use {std::fmt};`) and the allowed-root cases may
  already hold before the change. They pin the chosen semantics and guard
  against regressions rather than drive the change.
- AC-4's offending-line check asserts that the violation names the closing
  line and that no earlier line of the attribute is reported.
- AC-6 is met by running the existing ac8 tests as they are. Editing an
  existing test is not part of this task.
- Edge cases covered by the criteria: no whitespace between attributes (AC-1),
  an escaped quote inside an attribute string (AC-3), an attribute closing on
  its own line before the use line (AC-4), a multi-line attribute followed by
  a non-use item (AC-4).

## Out of Scope

- Raw strings (`r".."`, `r#".."#`) and char literals inside attributes (FR3,
  A2).
- `#!` inner attributes and block comments between an attribute and `use`
  (A5).
- Changing root extraction, the allowlist or the `ac8_violation` text.
- Renaming or editing existing ac8 tests. The predecessor record
  `test-docs/program-status-ac8-allowlist-gaps/task0001.tests.yaml` therefore
  needs no update.
- Production code, `Cargo.toml`, `lib.rs` and new crates (NFR1).
