## Design

Field contract: see IMPLEMENTATION.md Shared Components — the persisted JSON
key is exactly `agent_notify_visible_pane`, and decision D3 requires every
fixture that builds a full settings object to carry the field (value `true`,
matching the default).

### Toggle

- Position: appended after the existing three, preserving the section order
  master → turn complete (done) → waiting for input (blocked) → visible pane.
- Component key: `agent-notify-visible-pane` (yielding the element id
  `settings-agent-notify-visible-pane` via the existing `renderToggle` id
  convention).
- Reads its initial value from the current settings; saving persists the key
  `agent_notify_visible_pane` with the flipped boolean through the existing
  `saveSetting` channel (persistence to `settings.json` is the existing
  channel's responsibility — no new plumbing).

### i18n

New keys in the `settings.agent` namespace, sibling pattern of
`notifyOnBlocked` / `notifyOnBlockedDesc`:

- `settings.agent.notifyVisiblePane` — ja label 「表示中のペインでも通知する」
  (fixed by REQUIREMENTS.md 6.1); en label "Notify Even for the Visible Pane".
- `settings.agent.notifyVisiblePaneDesc` — description conveying decision D2's
  semantics in both languages: notifications also fire for the pane currently
  visible in the focused window; requires Agent Status Notifications to be on
  (wording follows the existing `*Desc` style).

No new markup path, component, styling, or category is introduced (NFR1 /
SPEC XSS note).
