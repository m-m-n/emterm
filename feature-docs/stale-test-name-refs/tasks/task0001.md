## Design

### What a correct edit looks like

Each substitution replaces one complete `OLD_ID` occurrence with `NEW_ID`. The
resulting diff hunk for that line differs from the base only in that identifier
segment.

Three properties of the occurrence set determine how the substitution must be
performed. All three are stated in IMPLEMENTATION.md Conventions; they are
repeated here as operating constraints because they are what makes a naive bulk
edit wrong:

1. **Match the full identifier, never its prefix.** The leading segment
   `test_relocate_widened_base_via_wrap_` is shared with several unrelated test
   identifiers in this repository — it occurs several times more often than
   `OLD_ID` does, including inside `crates/term_core` source, which this task
   must not touch at all. A prefix-scoped replacement corrupts unrelated
   identifiers and breaks NFR1.
2. **Keep module qualification intact.** Some occurrences are preceded
   immediately by a module path (`print_handler::tests::`). That qualifier is
   not part of `OLD_ID`; only the trailing identifier segment changes, and the
   qualifier stays exactly as written.
3. **Replace per occurrence, not per line.** At least one target line carries a
   second, unrelated test identifier that shares the same prefix and must
   survive untouched. Rewriting that whole line is a defect even if the
   resulting `OLD_ID` count is right.

### What must not change

Surrounding YAML structure and indentation, Markdown prose, table column
alignment, line ordering, line wrapping, whitespace, trailing newlines, and
every other identifier — all stay byte-identical (FR4). No file under
`crates/`, `src-tauri/src/`, `src-tauri/tests/`, or any build configuration is
modified (NFR1). No schema validator for `test-docs/*/taskNNNN.tests.yaml` is
built and no test logic is changed (NFR3).

### Why no source change is needed

`NEW_ID` already exists in the `crates/term_core` test source at the base
revision (the relocate-wrap-cursor-clamp rename is merged — assumption A-3), so
the identifier-filtered cargo run of AC-3 resolves to a real test purely as a
consequence of the documentation edits. If that run reports zero tests
executed, the identifier you wrote is wrong — do not respond by editing the
test source.
