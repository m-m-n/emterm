# Task Plan: task0001 — Extend the ring_push_blank survivor test to observe the clear's row scope

## Goal

The existing `ring_push_blank` survivor test in `crates/term_core` observes which row's
overflow entries were cleared: a second, non-recycled viewport row's entries are shown to
survive the scroll while the recycled row's entries are shown to disappear, so a regression
that replaced the row-scoped clear with a whole-table clear fails the suite instead of
passing silently.

## Design

### Fixture

The test extends the existing fixture rather than replacing it. The current fixture is a
narrow viewport, two rows tall, with scrollback capacity zero, so a line feed issued from
the last row takes the scrollback-disabled eviction branch of `ring_push_blank` and recycles
exactly one ring slot. The extension adds:

1. **A survivor row** — the viewport row that the scroll does *not* recycle, carrying
   overflow-bound content in at least one column. Its content is produced through the same
   print path and by the same technique the existing row's cells use (a base character
   followed by the same run of combining marks, which is what pushes a cell past the inline
   storage cap). Consistency of technique matters: a survivor cell built a different way
   could land in inline storage and never reach the overflow table at all.
2. **A captured survivor absolute row key** — resolved from the survivor's viewport position
   *before* the scroll, through the same viewport-to-absolute-row mapping the existing test
   already uses for the recycled row. Capturing it afterwards would defeat the purpose: the
   point is that the key is stable across the scroll even though the row's viewport position
   shifts.

Per IMPLEMENTATION.md D5, widening the fixture's row or column count is permitted if the
one-recycled/one-survivor assumption does not hold in practice, as long as the
scrollback-disabled eviction branch remains the branch exercised.

### Observation flow

1. Populate the to-be-recycled row's cells with overflow-bound content (existing behavior,
   unchanged).
2. Populate the survivor row's cell(s) with overflow-bound content.
3. Capture both absolute row keys — the recycled one (existing) and the survivor one (new).
4. Pre-scroll anti-vacuity assertions: both rows genuinely have entries in the overflow
   table, and both rows appear in the reverse index with the expected columns.
5. Move to the last row and emit a plain line feed, driving the full-screen scroll path
   through `ring_push_blank` (existing behavior, unchanged).
6. Post-scroll assertions, in two groups:
   - **Removal** (existing, preserved verbatim): neither of the recycled row's columns
     remains in the overflow table, and the recycled row's key is gone from the reverse index.
   - **Survival** (new): the survivor row's overflow entry is still present, and the reverse
     index still holds the survivor row key carrying the expected column set.

Group ordering is not significant, but both groups must be present: removal alone is the
pre-feature state, and survival alone would not show the clear happened at all.

### Comments the test must carry

- **The leading explanatory block** (above the test) is updated so its claim matches what the
  test now proves — row-scoped clearing pinned to the evicted absolute row, not merely
  "clearing happened at eviction time". Leaving the block describing the narrower claim is a
  correctness defect in its own right (NFR2).
- **The redundancy comment** (in the test body) records that removing only ONE of the two
  clearing sites leaves this test green, because within a single push the new bottom absolute
  row equals the evicted absolute row, making the two sites mutually redundant for this
  fixture. It must state both the fact and the reason — see IMPLEMENTATION.md D3.

Both comments are written in English, matching the surrounding module's style.

### Transient production mutation (AC-6)

Governed by IMPLEMENTATION.md D2. In outline: replace the row-scoped clearing pair inside
`ring_push_blank` with an unconditional clear of the whole overflow table and the whole
reverse index; run the component test command; confirm the extended test fails on a
*survivor-row* assertion (a failure on a recycled-row assertion would not demonstrate what
this feature adds); record the verbatim failure message; restore the production file; confirm
byte-identity and re-run the suite green.

A single-site removal that leaves the test green is the documented, expected outcome of D3
and is not a substitute for — nor a contradiction of — this whole-table mutation.

**TDD shape — read this before starting.** The behavior being pinned is already correct in
production, so the new assertions pass the moment they are written. Writing them first and
seeing green therefore proves nothing. The red step for this task is the AC-6 mutation
(IMPLEMENTATION.md D4): the new assertions must be demonstrated to fail against deliberately
broken production behavior. Sequence the work as:

1. Write the survivor-row fixture and the pre-scroll anti-vacuity assertions. If a
   pre-assertion fails at this point, the survivor content is not reaching the overflow table
   — fix the fixture (technique or geometry), never the assertion.
2. Add the survivor-row post-scroll assertions and confirm green.
3. Perform the AC-6 mutation, capture the failure verbatim, revert, re-confirm green and
   byte-identity.
4. Add/refresh the comments, then run the format check.

**Scenario mapping**: AC-1/AC-3/AC-4/AC-5 are observed by TS1; AC-2 by TS2; AC-6 by TS3;
AC-7 by TS4 (see VERIFICATION.md).

**Edge cases worth covering**

- Survivor content that does not exceed the inline cap: caught by the AC-2 pre-assertions,
  which must fail loudly rather than letting the AC-4 assertions pass vacuously.
- The survivor and recycled rows resolving to the same absolute row key: this would make the
  removal and survival assertions contradict each other, so the test fails rather than
  silently self-cancelling. If observed, the fixture geometry is wrong (D5).
- Under the AC-6 mutation, a failure on a recycled-row assertion instead of a survivor-row
  assertion: not acceptable evidence — the recycled-row assertions were already green before
  this feature, so only a survivor-row failure demonstrates the added observation.

**Determinism**: the test uses no timing, no ordering across tests, and no shared mutable
state, so it must pass under the default parallel harness. A result that needs a serialized
harness indicates a fixture defect, not an acceptable configuration.
