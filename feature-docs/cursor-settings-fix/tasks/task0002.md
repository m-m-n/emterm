# Task Plan: task0002 — seed cursor style/blink defaults from settings (GUI)

## Goal

The `cursor_style` and `cursor_blink` settings reach every tab's
`TerminalCore` — at tab spawn and immediately on settings apply — using the
canonical numeric shape mapping.

## Requirements

FR1, FR5

## Scope

### Files to Create
- (none)

### Files to Modify
- `src-tauri/src/settings.rs` — settings `CursorStyle` → canonical numeric
  shape value conversion (0 = block, 1 = underline, 2 = bar; mapping pinned
  in IMPLEMENTATION.md Shared Components)
- `src-tauri/src/tabs.rs` — at tab spawn, seed the core's shape default from
  `settings.cursor_style` next to the existing `set_cursor_blink` seeding
- `src-tauri/src/app.rs` — in the settings-apply per-tab loop, push the shape
  default via `set_cursor_style` next to the existing `set_cursor_blink` call

## Design

- Conversion lives with the settings `CursorStyle` type (same home as the
  existing theme-enum projection) so both consumers share one mapping.
- Seeding calls use the EXISTING `TerminalCore::set_cursor_style` /
  `set_cursor_blink` API — no new core API is required (see
  IMPLEMENTATION.md Shared Components note on semantics landing via
  task0001).
- Newly spawned tabs and the settings-apply loop must end up with identical
  effective values for a given settings object (FR5: apply reaches all
  existing tabs; new tabs inherit current values).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The settings-to-numeric conversion maps block → 0,
      underline → 1, bar → 2.
- [ ] AC-2: A tab spawned with `cursor_style: bar` reports
      `get_cursor_style()` = 2 on its core (spawn-path seeding).
- [ ] AC-3: Applying new settings with `cursor_style: underline` /
      `cursor_blink: false` updates EVERY existing tab's core so
      `get_cursor_style()` = 1 and `get_cursor_blink()` = false.
- [ ] AC-4: Existing spawn-path blink seeding behavior is preserved
      (`cursor_blink: false` in settings → core reports blink false at
      spawn).

## Test Notes

- AC-1 is a pure-function unit test in `settings.rs`.
- AC-2/AC-4 follow the existing tab-spawn test pattern in `tabs.rs`; AC-3
  follows the existing settings-apply tests in `app.rs` (GUI-gated tests,
  same cfg gating as the surrounding file).
- Note: in this task's worktree the core still has pre-task0001 semantics;
  the assertions above hold under both old and new getter semantics by
  construction (no active overrides in these tests).

## Out of Scope

- term_core state model, DECSCUSR, OSC 22 — task0001.
- Renderer color / theme changes — task0003.
- New settings fields or settings-panel (WebView) changes.
