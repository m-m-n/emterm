# Task Plan: task0003 — cursor color from theme (scheme / OSC 12 / OSC 112)

## Goal

The cursor overlay is painted with the theme's effective cursor color
(`Theme.cursor_fg`: scheme color, OSC 12 override, OSC 112 reset) instead of
the SGR pen foreground, for all three shapes.

## Requirements

FR3, FR4, NFR1

## Scope

### Files to Create
- (none)

### Files to Modify
- `src-tauri/src/render/mod.rs` — `draw_cursor`: underline / bar stroke color
  and unfocused hollow-block outline color switch from
  `core.get_cursor_fg()` (SGR pen) to `Theme.cursor_fg`
- `src-tauri/src/render/cursor.rs` — `draw_block_cursor`: fill =
  `Theme.cursor_fg`; covered glyph repainted in the cell's resolved
  background color (D3 in IMPLEMENTATION.md)
- `src-tauri/src/render/theme.rs` — theme remembers the scheme's base cursor
  color; OSC 112 restores that base instead of the hard-coded default preset
- `src-tauri/src/callbacks.rs` — existing OSC 112 test updated to assert
  reset-to-scheme-color behavior

## Design

- The theme is constructed from settings + active color scheme; it must
  retain the scheme's cursor color as the reset target so OSC 112 restores
  the SCHEME color even when the scheme is not the default preset.
- Precedence for the effective cursor color (FR4): OSC 12 override while
  active → scheme cursor color otherwise. Theme reconstruction on settings
  apply already resets OSC-driven palette mutations (existing documented
  behavior for OSC 10/11); cursor color follows the same rule — this is the
  existing full-remap semantics, not a new exception.
- Block cursor legibility: the glyph under the cursor is repainted in the
  covered cell's resolved BACKGROUND color (the fill is the cursor color, so
  the glyph must contrast with it the way inverted text did).
- NFR1: color resolution is a field read on already-available references —
  no added locks, no per-frame allocation.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The cursor color used by the overlay resolves to
      `Theme.cursor_fg`, not `TerminalCore::get_cursor_fg()`, for underline,
      bar, and both block variants (focused fill / unfocused outline).
- [ ] AC-2: With a non-default color scheme active, the resolved cursor
      color equals that scheme's cursor color (not the theme foreground and
      not the default preset's cursor color).
- [ ] AC-3: After OSC 12 sets a color, the resolved cursor color is the OSC
      value; after OSC 112, it is the ACTIVE SCHEME's cursor color again.
- [ ] AC-4: The focused block cursor paints the covered glyph in the cell's
      resolved background color.
- [ ] AC-5: SGR pen color changes (e.g. printing colored text) do not change
      the resolved cursor color.

## Test Notes

- Extract the color resolution into a pure helper so AC-1/AC-2/AC-3/AC-5 are
  unit-testable without an egui context (same pattern as
  `block_cursor_rect` / `cursor_screen_row` in `render/cursor.rs`).
- AC-3 extends the existing OSC 12/112 tests in `callbacks.rs` /
  `render/theme.rs`.
- AC-4 is verifiable by asserting the glyph paint color input in the helper;
  final visual confirmation is a manual item in VERIFICATION.md.

## Out of Scope

- Cursor shape / blink state (task0001) and settings seeding (task0002).
- Any new settings field for a custom cursor color.
- `theme.cursor_style` consumers (D2: left as-is).
