# Task Plan: task0001 — Block-comment carry discriminating tests and predecessor AC-3 record

## Goal

The ac8 allowlist checker self-tests gain two tests that pass on the current
attribute scanner and fail when the scanner drops the block-comment level it
carries to the next line, and AC-3 of the predecessor test record names those
two tests as the regression guard against that defect.

## Requirements

## Design

### Scanner contract the tests pin

An attribute still open at the end of a physical line carries three pieces of
state to the next line: bracket depth, the string-literal flag and the
block-comment nesting level (`ac8_scan_attribute` and its callers in
`src-tauri/src/program_status/tests.rs`). The defect to detect is the
carry-dropping mutant named in SPEC.md AC-1: the scanner's end-of-text return
keeps depth and the string flag but reports a block-comment level of zero.

### FR1 source (bracket form) — expected behavior

Input: exactly the two-line source given in SPEC.md FR1, lines joined by a
newline.

- Current scanner: line 1 ends inside a block comment at level one. On line 2
  the leading `]` is comment content, `*/` ends the comment, and the later `]`
  brings the depth to zero and closes the attribute; the remaining text is a
  use line with root `winit`. Result: a winit violation that quotes line 2.
- Mutant: line 2's leading `]` closes the attribute; the remaining text begins
  with `*/`, which is not a use line. Result: no violation at all.

### FR2 source (quote form) — expected behavior

Input: exactly the three-line source given in SPEC.md FR2, lines joined by a
newline.

- Current scanner: line 1 ends inside a block comment at level one. On line 2
  the `"` is comment content, `*/` ends the comment, and `)]` closes the
  attribute with nothing after it. Line 3 is an ordinary use line. Result: a
  winit violation that quotes line 3 and no end-of-source violation.
- Mutant: line 2's `"` opens a string literal that never closes, so line 3 is
  string content and the attribute is still open when the source ends.
  Result: only the end-of-source violation, quoting line 1; no winit
  violation.

### Mutant check procedure (temporary, never committed)

1. Run the two new tests on the current scanner: both pass.
2. Temporarily change only the scanner's end-of-text return so the reported
   block-comment level is zero (SPEC.md AC-1 mutant).
3. Run the two new tests: both fail (FR1: no violation returned; FR2: only the
   end-of-source violation). Keep the failure messages for the records. In the
   same mutant state also run
   `ac8_comments_ac3_a_bracket_in_a_block_comment_spanning_lines_does_not_hide_a_use_line`
   and confirm it passes; that observation backs the predecessor red_reason
   update below.
4. Revert the mutant and confirm the scanner has no diff against the base
   revision before any commit.
