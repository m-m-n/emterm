# Task Plan: task0002 — ScrollbackWriteFilter boundary rules aligned with term_core

## Goal

After this task, the scrollback write filter holds only a genuinely incomplete trailing sequence in pending. That means an unfinished OSC/DCS/APC string, or a lone trailing ESC. ESC-aborted strings count as closed. A suppressed chunk therefore never re-sends queries, text or complete sequences the client already received.

## Design

### Boundary scan

The filter's safe-boundary scan decides how much of (pending plus chunk) can be flushed through the existing strip. It follows the SPEC FR2 table (a) to (e) and the IMPLEMENTATION.md "Incomplete vs aborted string" contract.

**OSC, DCS and APC.** All three string kinds follow the same rules:
- BEL (OSC only) or ESC followed by backslash completes the string.
- ESC followed by any other byte closes the string as aborted. Scanning continues at that ESC as a new escape sequence, so a later incomplete string there is held from its own start.
- An ESC that is the last available byte leaves the string incomplete: it is held from the string's start.

The current DCS and APC scans ignore a mid-body ESC; that changes. The current OSC scan treats a mid-body ESC as unterminated; that changes too.

**Other escapes.**
- ESC ESC: the second ESC is the introducer that gets evaluated.
- ESC ( and ESC ): the next byte, even an ESC, is consumed as the designator. It never introduces anything.
- ESC X and ESC ^: complete two-byte sequences, not strings.
- A lone ESC as the last byte is held, since it may introduce a string.

**CSI and UTF-8 partials.** These are not held. The ring is a byte stream, so they rejoin naturally, and they are not strip targets.

**Scan cost.** The scan stays linear: each string scan stops at the next ESC or terminator, so no byte is rescanned per introducer.

**Unchanged.**
- The 512 KiB pending cap.
- The overflow flush, which still goes through the strip.
- The dims attribution of pending runs.
- The read-only pending accessor.
- The strip itself (NFR1).

### Postcondition

This is the IMPLEMENTATION.md "Write-filter pending" contract. After every feed, pending is either empty or starts at the ESC opening the single incomplete string (or lone ESC) at the end of the fed stream, and holds only that sequence's bytes. The only exception is right after an overflow flush, when pending is empty.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1; TS-1): A main-buffer OSC 11;? whose body ends in ESC at the end of a feed is held whole in pending. When the next feed supplies the backslash, the complete OSC is released in one flush and the ring holds it unsplit (test write_filter_holds_string_ending_in_trailing_esc_until_completed).
- [ ] AC-2 (FR5): OSC, DCS and APC bodies followed by ESC plus a non-backslash byte count as closed at that ESC. Nothing after them is held because of them. A string that begins at that ESC and is still incomplete at the end is held from its own start (test write_filter_closes_esc_aborted_strings_and_holds_only_incomplete_tail).
- [ ] AC-3 (FR5): The escape rules hold:
  - ESC ESC followed by an OSC introducer: the second ESC is treated as the introducer.
  - ESC ( followed by ESC ] …: the ESC is consumed as the designator, so no OSC is held.
  - ESC X and ESC ^ followed by text: nothing is held.
  - A lone trailing ESC: held, then released once the next byte shows what it is.
- [ ] AC-4 (FR5; TS-5): At reader level, a forwarded read containing an ESC-aborted OSC and an ESC-aborted DCS, followed by ESC [ 6 n and text, leaves pending empty. When the next chunk is suppressed, its replacement contains neither that 6n nor that text. The ring content equals the strip of the whole concatenated main-buffer stream (test suppressed_chunk_after_aborted_strings_does_not_resend_delivered_query_or_text).
- [ ] AC-5 (FR5, postcondition): Over a corpus of the AC-1 to AC-4 inputs, fed at every split position, pending after each feed satisfies the IMPLEMENTATION.md write-filter pending contract. It is either empty or exactly the incomplete trailing sequence from its opening ESC, and its string boundaries match term_core's for the same bytes.
- [ ] AC-6 (TM-2, NFR5): The existing pending-cap and overflow-flush tests pass unmodified, so the 512 KiB cap and the strip-on-flush are unchanged. A hostile 64 KiB feed made of repeated string introducers, each aborted by ESC, completes with scan work proportional to its length and holds at most the final incomplete sequence.
- [ ] AC-7 (NFR6, AC-8 of SPEC): `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib` and `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path src-tauri/Cargo.toml --no-default-features` both pass. Every existing test whose expectation changed is listed with its reason, and all other existing tests pass unmodified.
