# Task Plan: task0001 — Client-parity replacement builder with cross-chunk start state

## Goal

A suppressed chunk's replacement carries every query and viewer launch the client would have acted on, in order, exactly once, plus an incomplete tail. Everything is classified the way the client's term_core parser and GUI theme do, including sequences that started in the previous read.

## Design

### 1. Client-parity classifier (new module)

**Responsibility.** Walk bytes in one forward pass and track the client parser's state at sequence granularity. The states are:
- ground
- UTF-8 partial (lead byte seen, continuations pending)
- escape
- escape-charset (after ESC ( or ESC ), awaiting the designator)
- CSI
- OSC string
- DCS string
- APC string
- string-escape: an ESC seen inside one of the three string kinds

The transitions follow the SPEC FR2 table (a) to (g) and the IMPLEMENTATION.md "Incomplete vs aborted string" contract. The term_core details this plan depends on are listed below; confirm each one against `crates/term_core/src/parser/` while implementing.
- Only ESC introduces a sequence. Bytes 0x80-0xBF in ground, and any 8-bit C1 byte, are printable data and never introducers.
- An invalid UTF-8 continuation clears the partial character and is reprocessed from ground, so an ESC there starts an escape.
- Inside CSI:
  - C0 bytes are executed and the CSI continues.
  - ESC aborts the CSI into escape.
  - A final byte completes it.
  - An invalid byte cancels it to ground, exactly as term_core does.
- ESC ESC stays in escape.
- ESC X and ESC ^ are complete two-byte sequences.
- ESC ( and ESC ) consume the next byte, even an ESC, as the designator.
- Every other intermediate (0x20-0x2F) ends the escape at that byte.

**Per completed sequence**, report:
- its kind
- its start and end positions
- for strings, its terminator: BEL, ST, or aborted

**Start-state derivation (FR6).**
- **Stream shorter than N (D2):** the retained window holds the whole stream so far, so walk it from ground.
- **Full window:** start the walk at the first ESC whose designator context the window itself decides. That excludes an ESC at window offset 0. It also excludes an ESC at offset 1 when offset 0 is ( or ). Bytes before that ESC count as ground data.
- **Fallback:** if the full window has no such ESC, the state is ground, or UTF-8 partial as decided by the trailing bytes. This can only miss an item, never fabricate one (as-05, TM-1).

**Color-query predicate (FR2 (g), (h), as-04).** An OSC counts as a query when the client would produce at least one response to it:
- Reconstruct the OSC number and data exactly as term_core's OSC string state does. Digits before the first semicolon accumulate into the number, even with non-digits interleaved; those non-digits go to the data. The first semicolon is dropped, and every later byte is data. The data is then decoded lossily as the client does.
- Apply the theme's rules:
  - OSC 4: index/spec pairs. The index is parsed with the client's numeric parsing and must be below 256; the spec is a query when it is a question mark after the client's trimming.
  - OSC 10/11/12: items map to consecutive targets and stop past 12; an item is a query when it is a question mark after trimming.
- An aborted OSC is never a query.
- Establish the route from the parsed OSC number to the theme's handler, including any narrowing conversion, from the client code. Treat any OSC whose route cannot be established, and any number whose accumulation would overflow in term_core (as-06), as not-a-query.
- The arithmetic never panics.

**Viewer-launch predicate (FR7, D3).**
- A complete (BEL- or ST-terminated) OSC 777 emterm OSC counts when its kind is one of the viewer kinds in the existing viewer-kind SSOT. The agent-status kind never counts.
- A complete OSC 9999 emterm-md counts.
- Confirm that the image kind opens a viewer window. If it does not, exclude it and report the change (D3).

**CSI query classification** reuses the existing device-query predicate in `mux/scrollback_filter.rs` unchanged. That module is the SSOT of which CSI queries the client answers.

**Contract.**
- Pre: any byte slices.
- Post: work proportional to the retained-window length plus the chunk length; no panic on any input.

### 2. Replacement builder (suppressed_output.rs)

**Inputs:**
- the chunk bytes
- the chunk's ring-written spans (the existing input)
- the write filter's pending after this chunk
- the retained window, i.e. the stream bytes before this chunk (new input)

**Output:** the replacement bytes, possibly empty.

**Rules:**
1. **Items.** These are the sequences whose completing byte lies in the chunk; the start may lie in the window. They are emitted in stream order:
   - **CSI device queries**, from any region: the bytes from start to final with the CSI's C0 bytes removed (FR3, FR6). Their effect is already in the snapshot.
   - **Color queries**, only when the completing byte lies outside the ring-written spans: the whole OSC, with its original terminator, set parts included (as-04). Color queries in ring-written spans are answered when the snapshot replays.
   - **Viewer launches**, from any region: the whole sequence with its terminator. The write path strips them from the ring.
2. **Tail.** Per IMPLEMENTATION.md D4. A CSI tail has its C0 bytes removed (FR3), including the part carried over from the window. A string tail that ends in ESC stays incomplete (FR1).
3. **Pending exclusion (FR4).** When the tail comes from pending, nothing is extracted from the chunk bytes pending re-delivers. No other range is excluded because of pending.
4. **Assembly.** The replacement is the items in stream order followed by the tail.

### 3. Reader wiring (mod.rs)

- **Retained window.** The window is reader-thread-local, with no lock. After every non-empty read's handling, on every path (forwarded, suppressed, detached, closed), the window is advanced by copying: it becomes the last up to N bytes of the previous window followed by the chunk (NFR3).
- **Pipeline input.** The suppressed pipeline receives the window as it was before the current read.
- **Normal path.** Nothing else is added to it: no scan, no allocation beyond the bounded copy.
- **Unchanged.** Lock order, the covered check, the fixed destination S, and the rule that an empty replacement is not sent (NFR2, TM-2, TM-3).

### 4. Behavior-changing existing tests (AC-8)

## Test Notes

- **Unit level (classifier, builder).** Drive the classifier and builder directly, with explicit pending and window inputs. This covers the corpus, the split sweeps, the start-state derivation (full and partial window, undecidable designator context) and hostile inputs.
- **Reader level (pty_spawn/tests.rs).** Use the existing scripted-reader helpers with P2 pauses and production snapshot paths, and compare against the reference with the established client model. Place new tests next to the existing suppressed-chunk tests.
- **Pending in reader-level tests.** Give pending only content that is a genuinely incomplete string at the end of the main buffer. Do not rely on how the write filter treats ESC-aborted strings (IMPLEMENTATION.md, write-filter pending contract).
- **Oracles.** Color-response oracle tests that use the GUI theme are gated on the gui feature. Keep OSC numbers that overflow in term_core out of oracle comparisons (as-06): term_core may panic on them in test builds. Test the classifier alone for those.
- **FR9.** The timing difference of the cursor-position response is accepted (FR9). AC-6 asserts order and count only.

## Out of Scope

- Changing term_core, the GUI theme, the strip predicate module, or the viewer-kind SSOT.
- Write-filter boundary rules and the pending cap (handled under the write-filter contract).
- Delivering inline images. Reconstructing sequences that started more than N bytes back (known gaps, D6).
- Color SET sequences without a query in alternate-screen regions.
