- `decisions_md_contains_every_d7_registry_test_name` checks only that each registry name appears in DECISIONS.md, not that a test with that name exists.

### Restored FR8 tests (pane level)

Both tests use the production resume path and the existing test-side client model (IMPLEMENTATION.md "Test-side client model", including the buffer-switch routing task0003 added). Reader inputs stay within the IMPLEMENTATION.md "Suppressed-chunk delivery contract". The tests assert no alternate-screen resume payload bytes, only the client model's resulting state.

- **Hidden alternate-screen exit (TS-9).** The pane is on the alternate screen, and the client model mirrors that. The pane is hidden, then receives ESC [ ? 1 0 4 9 l while hidden, and is then resumed. After the client model applies the resume Snapshot-kind chunk, it is on the main screen. Its main history and visible rows equal a reference that was fed the raw stream once.
- **apt-style progress bar (TS-10).** A main-screen pane draws a progress bar with a scroll region (DECSTBM) and cursor save and restore (DECSC/DECRC). The cursor position, scroll region and visible rows are recorded before the hide. After the hide and resume, the client model shows the same values. If the client model does not expose the scroll region directly, it is observed through behavior: one line feed at the region's bottom margin scrolls only the rows inside the region, in both the resumed model and the pre-hide reference.

### Contingency: a restored test fails on the current code

A failing restored test is a real FR8 divergence. Fix it in the visibility-resume layout (`snapshot_bytes.rs`), or in the resume path's captured inputs (`output_target.rs`). The rules are those in IMPLEMENTATION.md "Resume snapshot builder" and D5:
- everything travels in the single Snapshot-kind chunk;
- the main-pane resume payload stays unchanged;
- reattach and on-demand layouts do not change;
- no wire change;
- the client code is not changed.

If no such fix exists, stop and report a plan deviation. Never weaken a restored test's assertions to make it pass.

### Registry test-existence check (FR13)

A new structural test sits next to `decisions_md_contains_every_d7_registry_test_name`. It checks that every test name on the registry list is defined as a test function in the crate's source tree (`src-tauri/src`, found from the crate manifest directory, with platform-neutral path handling).
- **Name list.** It uses the same name list as the existing structural test, never a second copy. Moving that list into a shared constant is allowed. Report the move in the completion report as a behavior-preserving change to the existing test.
- **Names the table cites.** Any regression-test name DECISIONS.md cites is added to the list, including `viewer_launch_image_kind_is_not_redelivered_d3`.
- **Lookup check.** The lookup the check uses is itself tested: it reports a deliberately undefined name as missing.
