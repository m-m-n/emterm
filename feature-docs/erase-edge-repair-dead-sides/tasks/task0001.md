# Task Plan: task0001 — Per-site edge repair in range erases and ED 0/1 cursor-row delegation

## Goal

The range-erase chokepoint in `csi_screen.rs` captures and repairs only the
edge(s) each call site can actually orphan (EL 0: left, EL 1: right, ECH:
both), and ED 0 / ED 1 erase their cursor row through EL 0 / EL 1. The
externally observable behavior of ED / EL / ECH stays identical.

## Design

### Edge selection (resolution of SPEC A-5)

Keep the single private chokepoint `erase_range_with_edge_repair` (same name)
and give it an edge-selection input naming which edge(s) of the range may be
orphaned. The selection has exactly three cases: left edge only, right edge
only, both edges. Its representation is the implementer's choice, provided it
stays private to `csi_screen.rs` and no other module gains a new item.

Per-side helpers that each perform their own range clear are not used: the
capture of every selected edge must happen before the one range clear, and
ECH needs both captures before that clear.

### Chokepoint contract

- **Inputs**: viewport row; half-open column range [start, end); edge selection.
- **Precondition**: none (unchanged; the primitives self-guard).
- **Flow**:
  1. If end ≤ start: run the plain range clear on [start, end) only — no
     capture, no repair — for every selection.
  2. Before clearing, capture only the selected edges:
     - left selected: whether the cell at start is a width-0 spacer;
     - right selected: whether the cell at end − 1 is a width-2 base.
     The cell of an unselected edge is not read.
  3. Plain range clear of [start, end).
  4. Left selected, start was a spacer, and start > 0: blank the partner half
     at column start − 1.
  5. Right selected and end − 1 was a base: blank the partner half at column
     end. end equal to the column count is absorbed by the blanking
     primitive's out-of-bounds self-guard (no extra check is added).
- **Postcondition**: for every call site, grid content, cell widths,
  attributes, overflow entries and dirty flags equal the pre-change result.

### Call-site mapping

| Site | Range | Selection | Structural fact about the unselected side |
|------|-------|-----------|-------------------------------------------|
| EL 0 | [cursor column, column count) | left only | end is always the column count, so the right partner position is outside the row and its repair is always a no-op |
| EL 1 | [0, cursor column + 1) | right only | start is always 0, so the left repair's start > 0 guard never holds |
| ECH | [cursor column, min(cursor column + count, column count)) — unchanged | both | — |

### ED delegation

- ED mode 0: erase the cursor row via EL mode 0, then full-row clear every
  row from cursor row + 1 to the last row; return 0.
- ED mode 1: full-row clear every row from row 0 up to (not including) the
  cursor row, then erase the cursor row via EL mode 1; return 0.
- ED mode 2, mode 3 and invalid modes: unchanged.
- ED no longer calls the chokepoint directly. The chokepoint's only callers
  are EL mode 0, EL mode 1 and ECH.

### Unchanged code

- EL mode 2, ED mode 2, `clear_line`, `clear_line_range`: code unchanged;
  none of them reaches the chokepoint.
- Public signatures of the three handlers; signatures and behavior of
  `clear_line_range`, `blank_wide_pair_half`, `get_cell_width`.

### Doc comments

- Chokepoint doc comment: list the three selections and which site uses
  which (ECH: both; EL 0, and ED 0 through delegation: left only; EL 1, and
  ED 1 through delegation: right only), with the structural fact from the
  table above for each one-sided site. Keep the empty-range statement and the
  statement that the step is never folded into `clear_line_range`. The
  current mention of ED 0 / 1 as direct callers is replaced by the delegation.
- `blank_wide_pair_half` caller list: its entry "the range-erase edge-repair
  chokepoint" must remain true. Edit the text only if it no longer matches.
