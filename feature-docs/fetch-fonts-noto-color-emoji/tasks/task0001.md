# Task Plan: task0001 — Retire the swash_emoji probe and add the asset-manifest consistency check

## Goal

Make the documented test command compile on a clean checkout by deleting the
retired color-emoji probe and the two Cargo-manifest declarations that exist
only for it, and add an integration check that fails whenever a font embedded
at compile time is not declared in both the fetch script and the font inventory
table.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR9, NFR1, NFR2, NFR3, NFR5

## Scope

### Files to Create

- `src-tauri/tests/asset_manifest.rs` — the asset-manifest consistency check: an
  auto-discovered, feature-agnostic integration test binary that derives the
  embedded-font set and the two declaration sets from repository text and
  reports every font missing from either declaration.

### Files to Modify

- `src-tauri/examples/swash_emoji.rs` — delete this file entirely; it is the
  retired probe whose compile-time embed of an unfetched font breaks the
  documented test command.
- `src-tauri/Cargo.toml` — remove the example-target declaration for the
  retired probe, and remove the dev-dependency on the png encoder crate
  together with the comment stating that it exists solely for that probe; leave
  the other three example-target declarations, and the png feature of the image
  dependency, untouched.
- `src-tauri/Cargo.lock` — expected to change as a consequence of the
  dev-dependency removal; commit whatever the build tool regenerates rather
  than hand-editing it.

## Design

### A. Removal

1. Delete the retired probe source.
2. Remove its example-target declaration from the manifest. The three other
   example targets keep their current declarations, including their feature
   requirement.
3. Remove the dev-dependency that exists solely for that probe (the png encoder
   crate, version 0.17), together with the comment stating that it exists
   solely for it. The similarly-named feature of the image dependency is a
   different thing and stays.
4. Confirm by compiling that nothing else consumed the removed dev-dependency
   (see Test Notes).

### B. The consistency check

Responsibilities, per IMPLEMENTATION.md decision D5, are split so that the
comparison is independent of file access:

| Responsibility | Input | Output |
|---|---|---|
| Embedded-font collection | the text of the crate's source files, each with its own path | the set of font file names embedded at compile time |
| Fetch-script declaration set | the text of the font fetch script | the set of font file names it declares as fetched |
| Inventory declaration set | the text of the font inventory document | the set of font file names listed in its inventory table |
| Comparison | the three sets above | per offending font, which of the two declarations is missing |
| Repository binding | the crate manifest directory supplied by the build environment | the text handed to the four responsibilities above |

Contract of the comparison responsibility:

- Precondition: three sets of font file names; no file access, no environment
  access.
- Postcondition: a report listing, for every embedded font name absent from one
  or both declaration sets, that name and the identity of each missing
  declaration. An embedded font present in both sets contributes nothing to the
  report. An entry present in a declaration set but not embedded contributes
  nothing either — the assertion is one-directional (FR6).

Contract of the embedded-font collection responsibility:

- Precondition: source text plus the path it came from.
- Postcondition: the file-name component of every compile-time embed literal
  whose path ends in one of the two font extensions used by this project (the
  OpenType and TrueType extensions, i.e. the extensions of the files under the
  crate's bundled-font directory). Embed literals whose paths end otherwise are
  ignored (FR6). Source excluded by scan scope contributes nothing.

Scan scope (IMPLEMENTATION.md, Conventions), restated here as behavior this
task must implement:

1. Walk the crate's directory tree starting from the crate manifest directory.
2. Skip every build output directory — the quick-check, release-host and
   cross-build output directories, and any sibling directory whose name starts
   with the same build-output prefix — so that a populated build directory
   cannot change the result (NFR5).
3. Skip the checking test's own source, or otherwise ensure its own literal
   tokens cannot be collected as a finding (TS5).
4. Read only text; never require a font binary to exist (NFR3).

Failure reporting (IMPLEMENTATION.md, Conventions): the assertion message names
each offending font file and states, for each, whether the fetch-script
declaration is missing, the inventory row is missing, or both. A reader of a
terminal or CI log must be able to act on the message without opening the test
source.

Expected current state: the check passes unmodified on the present tree. The
seven fonts embedded by the font resolver today are NotoSansCJKjp-Regular.otf,
NotoSansCJKjp-Bold.otf, Noto-COLRv1.ttf, NotoEmoji-Regular.ttf,
Inconsolata-Regular.otf, Inconsolata-Bold.otf and NotoSansSymbols2-Regular.ttf;
each is declared by the fetch script and listed in the inventory table.

### C. Interaction between A and B

Part B's check cannot pass while part A is undone: the retired probe embeds a
font that appears in neither declaration, which is exactly the violation the
check is built to report. Implement A first, then B, inside this one task.

## Test Notes

- **TDD order**: write the comparison responsibility's tests first against
  synthetic sets and synthetic text (AC-4, AC-6), then the repository-facing
  test that asserts the real tree's invariant (AC-3, AC-5). The removal in part
  A lands before the check can go green.
- **Negative scenarios without mutating tracked files**: AC-4 corresponds to
  scenarios TS2 and TS3. Exercise them by handing synthetic declaration text to
  the comparison responsibility; do not edit the real fetch script or inventory
  document in an automated test. The end-to-end confirmation on the real files
  is a manual verification item recorded in VERIFICATION.md.
- **Self-match guard** (TS5): the checking test's own source necessarily
  contains the token it scans for. Either exclude its own path from the walk or
  construct the token so that it cannot match itself; assert the guard rather
  than relying on it implicitly.
- **Build-directory determinism** (TS6): assert the exclusion rule directly — a
  path under a build output directory contributes nothing — rather than by
  populating a real build directory in the test.
- **Feature-off run** (NFR2): the documented features-off command is a compile
  check, not a test run, so it does not build test targets. Run the test
  command with features off explicitly to confirm the check builds and passes
  there.
- **Known pre-existing flakiness** (TS8): in this project the terminal-tab
  replay tests are non-deterministic under parallel execution (stable with a
  single test thread) and one socket-discovery test is rarely flaky. Both are
  pre-existing and unrelated; do not attribute them to this task, and do not
  fix them here.
- **Dev-dependency removal check** (AC-2): after removing it, compile with
  default features and with features off. A surviving consumer surfaces as a
  compile error; report it rather than restoring the dependency silently.
