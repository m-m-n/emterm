# Task Plan: task0002 — DCH / ECH 経路の overflow 相方掃除テスト（TS3 / TS4）

## Goal

DCH / ECH 経路が共有する wide ペア相方掃除（`blank_wide_pair_split`、
`crates/term_core/src/csi_edit.rs:161`）について、overflow 分岐
（`char_len == 0xFF`）を実際に通るユニットテスト 2 本（TS3 / TS4）を追加し、
overflow テーブルと `overflow_ridx` の同期崩れを CI で検知可能にする。

## Requirements

FR2, FR3, FR4, NFR1, NFR2

## Scope

### Files to Create

なし。

### Files to Modify

- `crates/term_core/src/csi_edit.rs` — `mod tests` に TS3（DCH）のテストを追加。
- `crates/term_core/src/csi_screen.rs` — `mod tests` に TS4（ECH）のテストを追加。

（両ファイルとも変更はファイル末尾の `#[cfg(test)] mod tests` 内に限定する。
非テスト部分への変更は NFR2 違反。）

## Design

前提状態の構築は IMPLEMENTATION.md D1（ZWJ 家族絵文字レシピ）、overflow 同期の
assert は D2、空白/空文字の区別は D4 に従う。本タスク固有の設計は以下。

### TS3: spacer 位置で DCH → base（col0）が掃除される（`csi_edit.rs`）

1. 家族絵文字を row 0 の col0 に書き、グリッドへの書き出しを完了させる
   （D1 注意点 1）。
2. 事前 assert（D2 + FR3）: base セル（col0）の overflow フラグが真、
   overflow テーブルと `overflow_ridx` に col0 のエントリが存在、
   col0 の幅が 2、col1 の幅が 0（spacer）。
3. カーソルを spacer 位置（col1）に置き、DCH を count=1 で実行する
   （`handle_delete_characters`）。
4. 事後 assert: col0 の `get_cell_char` が `" "`・幅 1（D4: 空文字 `""` では
   ないことをスペース 1 文字との等値で検証）。overflow テーブルと
   `overflow_ridx` の双方から col0 のエントリが除去済み（FR3）。

**経路の注記**: DCH は自前の overflow 範囲掃除をカーソル位置以降
（col1 以降）にしか行わないため、col0 の overflow エントリはシフト処理後も
残っており、その除去は `blank_wide_pair_split` の overflow 分岐だけが担う。
つまり TS3 の事後 assert はプリミティブ内の `char_len == 0xFF` 分岐を通った
ことの直接証明になる（FR3）。

### TS4: spacer 位置で ECH → base（col0）が掃除される（`csi_screen.rs`）

1. TS3 と同じ前提状態を構築する（事前 assert は最低限、col0 が overflow
   状態の base・col1 が spacer であることを確認）。
2. カーソルを spacer 位置（col1）に置き、ECH を count=1 で実行する
   （`handle_erase_characters`）。消去範囲の先頭が spacer のため、
   `csi_screen.rs:155` の `blank_wide_pair_split` 呼び出し（範囲先頭の
   左隣 = col0 の掃除）を通る。
3. 事後 assert: col0（start-1）の `get_cell_char` が `" "` を返す（FR2。
   D4 の空文字との区別を含む）・幅 1。

### 共通事項

- 2 本のテストは別ファイルの別 `mod tests` に入り、互いに独立している。
  それぞれのモジュールの既存 wide-pair 掃除テスト群（DCH は `csi_edit.rs`、
  ECH は `csi_screen.rs` の各 AC 系テスト）の構築スタイルを踏襲する。
- テスト名・コメントは隣接テストの流儀に合わせ、TS 番号と FR 番号を
  コメントに付記する（NFR1）。

## Test Notes

- 本タスクの成果物自体がユニットテスト（TS3 / TS4）。AC-1 → TS3、AC-2 → TS4
  に 1:1 対応する。
- TDD 上の注意: 対象のプロダクションコードは実装済みなので、追加テストは
  最初から green になるのが正しい。red の確認は assert の期待値を意図的に
  崩して行い、プロダクションコードを触らないこと（NFR2）。
- D1 の事前 assert が落ちる場合は D1 のフォールバック基準（1 クラスタ merge・
  幅 2・16 バイト超）で別クラスタに差し替える。
- overflow / `overflow_ridx` への直接 assert は test/README.md の推奨に対する
  意図的な例外（IMPLEMENTATION.md D2 で合意済み）。
- TS4 は FR3 の必須対象ではない（workflow.yaml の FR3 tests は TS1–TS3）が、
  overflow 同期の assert を任意で加えることは妨げない。加える場合も D2 の
  スコープ（overflow / `overflow_ridx` / overflow フラグ）を超えないこと。
