# Task Plan: task0001 — print 経路の overflow 相方掃除テスト（TS1 / TS2）

## Goal

print 上書き経路の wide ペア相方掃除（`blank_wide_pair_partner`、
`crates/term_core/src/print_handler.rs:74`）について、overflow 分岐
（`char_len == 0xFF`）を実際に通るユニットテスト 2 本（TS1 / TS2）を追加し、
overflow テーブルと `overflow_ridx` の同期崩れを CI で検知可能にする。

## Requirements

FR1, FR3, FR4, NFR1, NFR2

## Scope

### Files to Create

なし。

### Files to Modify

- `crates/term_core/src/print_handler/tests.rs` — TS1 / TS2 のテストを追加
  （既存の wide-pair-overwrite-cleanup 節の末尾に本 feature の節を設ける）。

## Design

前提状態の構築は IMPLEMENTATION.md D1（ZWJ 家族絵文字レシピ）、overflow 同期の
assert は D2、空白/空文字の区別は D4 に従う。本タスク固有の設計は以下。

### TS1: base（col0）を ASCII で上書き → spacer（col1）が掃除される

1. 家族絵文字を row 0 の col0 に書き、グリッドへの書き出しを完了させる
   （D1 注意点 1: grapheme バッファの flush）。
2. 事前 assert（D2 + FR3）: base セル（col0）の overflow フラグが真、
   overflow テーブルと `overflow_ridx` に col0 のエントリが存在、
   col0 の幅が 2、col1 の幅が 0（spacer）。
3. カーソルを col0 に戻し、ASCII 1 文字を print する（base の上書き）。
4. 事後 assert: col0 は上書きした ASCII 文字・幅 1。col1 の `get_cell_char`
   が `" "`・幅 1（FR1 の出力仕様）。overflow テーブルと `overflow_ridx` の
   双方から col0 のエントリが除去済み（FR3）。

**経路の注記**: TS1 では overflow エントリの除去は上書き書き込み側の overflow
掃除で起き、相方掃除プリミティブが空白化するのは非 overflow の spacer 側で
ある。overflow 状態の base 自体をプリミティブが掃除する経路は TS2 が担う —
2 本で両方の除去サイトをカバーする設計であり、TS1 に「プリミティブ内の
overflow 分岐」の実行を求めない（FR3 の証明は事前/事後 assert の組で行う）。

### TS2: spacer（col1）を ASCII で上書き → base（col0）が掃除される

1. TS1 と同じ前提状態を構築し、同じ事前 assert を行う。
2. カーソルを col1 に置き、ASCII 1 文字を print する（spacer の上書き）。
   これにより上書き前の相方掃除ルール R2 が発火し、overflow 状態の base
   （col0）が `blank_wide_pair_partner` で空白化される — プリミティブ内の
   overflow 分岐（`char_len == 0xFF`）を通る本命経路。
3. 事後 assert: col0 の `get_cell_char` が `" "`・幅 1（D4: 空文字 `""` では
   ないことをスペース 1 文字との等値で検証）。col1 は上書きした ASCII 文字・
   幅 1。overflow テーブルと `overflow_ridx` の双方から col0 のエントリが
   除去済み（FR3）。

### 共通事項

- グリッドは既存テスト同様に小さめの固定サイズで各テストが独立に構築する。
- カーソル移動は既存テストが使う公開操作（カーソル設定 / 復帰改行入力）を
  踏襲する。
- テスト名・コメントは同ファイル内の既存 wide-pair 掃除テスト群の流儀に
  合わせ、TS 番号と FR 番号をコメントに付記する（NFR1）。

## Test Notes

- 本タスクの成果物自体がユニットテスト（TS1 / TS2）。AC-1 → TS1、AC-2 → TS2
  に 1:1 対応する。
- TDD 上の注意: 対象のプロダクションコードは実装済みなので、追加テストは
  最初から green になるのが正しい。red を確認したい場合は assert の期待値を
  意図的に崩して落ちることを確認してから戻す、で足りる（プロダクション
  コードを触って red を作らないこと — NFR2）。
- D1 の事前 assert が落ちる場合はテストのバグではなくクラスタ選定の問題。
  D1 のフォールバック基準（1 クラスタ merge・幅 2・16 バイト超）で別クラスタ
  に差し替える。
- overflow / `overflow_ridx` への直接 assert は test/README.md の「内部状態
  への assert を避ける」推奨に対する意図的な例外（IMPLEMENTATION.md D2 で
  合意済み。スコープはこの 2 構造 + overflow フラグに限定）。
