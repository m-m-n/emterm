# mux-suppressed-output-round4-fixes - 要件定義書

## 1. 概要

### 1.1 背景
mux-suppressed-output-round3-fixes（PR #112）のレビュー round 1 で、medium 指摘 3 件（3e2024dce619ed9f、989ec5c588abce06、48caec6f5b0b5810）が `unresolved` のまま残った。いずれも、スナップショット再生後に、クライアントが開始していない問い合わせ（OSC 11 色照会など）が成立しうる。

### 1.2 目的
- 重なったスナップショット取得（タブ切替 / 再アタッチ）で抑止されたチャンクと、そのチャンクについてスクロールバックリングに書き込むバイトが、ライブのクライアントと同じ解析状態を保つ。再生や抽出で、クライアントが開始していない照会（OSC 11 色照会、CSI DSR など）を完成させない。
- 上記 3 件の各指摘について、解決済みか変更不要かを判定し、根拠と対応する回帰テストを記録する。
- 2 つの隣接経路（カット時に進行中の CSI、抽出が取り除く `ESC (` / `ESC )` の直後の切替シーケンス）を term_core ベースの回帰テストで確認し、再現したものを修正し、結果を 3 件の stable_id の判定とは別に記録する。

### 1.3 スコープ
- 対象: FR1〜FR6（mux デーモン内の書き込みフィルター、クライアント同等走査（client-parity scan）、メイン範囲の抽出、抑止チャンクの置換出力）。
- 対象外: `mux_ipc` のワイヤー形式、Snapshot / SnapshotRestore フレームの形（NFR1）。
- 対象外: `feature-docs/mux-suppressed-output-round3-fixes/reviews/round1.yaml` の変更（FR6）。
- 対象外: `feature-docs/mux-suppressed-output-round3-fixes/SPEC.md` の編集（as-04）。

### 4.2 機能詳細

#### FR1: カットで連鎖を考慮して閉じる（3e2024dce619ed9f）

**説明**:
書き込みフィルターの境界走査は、投入した範囲の末尾について 2 つの位置を記録する。

- 最後の未完の構成要素（OSC/DCS/APC 文字列、または単独 ESC）の開始位置
- そこへつながる連鎖の先頭

連鎖の先頭は、連続する構成要素のうち最も早い開始 ESC とする。連鎖を成す各構成要素は、次の構成要素を開始する ESC によって閉じられる。該当するのは次の 2 種類とする。

- `ESC <\ 以外のバイト>` で中断された文字列のうち、中断した ESC が次の構成要素を開始するもの
- `ESC ESC` の、置き換えられた最初の ESC

**ビジネスルール**:
- `pending` は連鎖の先頭以降のバイトを保持する。
- これはカット時だけでなく、通常の drain 経路（write_filter.rs の 355 行付近）でも成り立つ。そのため、読み取りをまたぐ連鎖は保持されたままになる。連鎖を開始した読み取りでは、連鎖の先頭を書き込まない。
- カット時、および round3 の FR4 のフォールバック（pty_spawn/mod.rs）が `pending` を閉じるとき、連鎖の先頭以降のバイトはリングに書き込まない。
- 連鎖の先頭より前の確定済みバイトは、既存の strip を通す。
- 終端は付加しない。
- pending の事後条件（`feed_with_cuts` / `pending()` のドキュメント）を次のように改める: 各呼び出しの後、`pending` は空であるか、投入したストリームのうち最後のカットより後ろの末尾にある、ただ 1 つの未完の構成要素で終わる連鎖をちょうど保持する。
- 持ち越し分の完了（`CarriedCompletion`）は、連鎖の先頭ではなく、構成要素の開始位置から定める。
- 保持中の未完の構成要素が、呼び出しの中でどのカットよりも前に完了した場合は、それを報告し、保持していた範囲全体を確定させる。
- 抑止チャンクの末尾の再配送（suppressed_output.rs の `pending_after` の末尾と、その長さから導く除外部分）を、新しい `pending` の内容に合わせる。どのバイトも、項目として抽出され、かつ再配送されることはない。
- 512 KiB のオーバーフローのフラッシュをまたいでフィルターが持ち越す状態（`pending`、連鎖の先頭、構成要素の開始位置、指示子待ちフラグ）を定義し、テストする。
- オーバーフローのフラッシュは、引き続き実行範囲を strip に通す。
- 帰結: 次の 3 形式は、再生時に色照会を生じない。切替より前のバイトが 1 回の読み取りで届いても、複数の読み取りに分かれて届いても成り立つ。
    - `ESC]11;? ESC]0;x` + 切替 + BEL
    - `ESC]11;? ESC ESC` + 切替 + `\`
    - `X ESC ESC` + 切替 + `]11;? BEL`
- 根拠: 回答 requirement.fr1.cross-call-chain（hold-chain）。

#### FR2: as-05 フォールバックで、指示子の不確定性をチャンク全体に及ぼす（989ec5c588abce06）

**説明**:
`first_chunk_byte_may_be_designator` が成り立つとき、クライアント同等走査はチャンクを 2 通りに読む。

- (a) チャンクの先頭バイトを指示子として消費する読み方
- (b) 先頭バイトを ground から解析する読み方

**ビジネスルール**:
- 項目は、両方の読み方が同じ範囲で報告する場合にだけ報告する。
- 末尾（tail）は、両方の読み方が同じ末尾開始位置を与える場合にだけ報告する。末尾の C0 strip フラグは、その末尾から取る。
- それ以外は捨てる。
- この規則は、チャンクの先頭バイトから始まるものだけを捨てる現在の規則を置き換える。
- as-05 フォールバックの条件の外では何も変えない。
- この規則は取りこぼしを生むだけで、項目を追加することはない。
- 帰結: フォールバックで、`ESC ( ESC ( ESC ]11;? BEL` は色照会を配送しない。`ESC ( ESC ( ESC [` は、後続の `6n` が DSR に完成させうる末尾を再配送しない。

#### FR3: カット時の指示子待ちで、指示子として消費された ESC を書く（48caec6f5b0b5810）

**説明**:
書き込みフィルターがカット、または round3 の FR4 のフォールバックの閉じ処理（pty_spawn/mod.rs）で閉じるとき、クライアントが文字集合の指示子を待っていることがある。これは、実行範囲が文字列の外の `ESC (` / `ESC )` で終わる場合、またはフラグが空の `pending` とともに持ち越された場合に起きる。この場合、フィルターは書き込み済みのバイトの後ろに ESC を 1 バイト（0x1B）リングへ書き込み、フラグをクリアする。この ESC は、クライアントが指示子として消費した切替シーケンスの ESC を表す。

**ビジネスルール**:
- 同じ規則を次のすべての経路に適用する。
    - 同じ呼び出し内のカット
    - 先の読み取りが空の `pending` とともに残した待ち
    - 512 KiB のオーバーフローのフラッシュに続くカット
    - mod.rs のフォールバック
- クライアントが指示子を待っていないときは何も書かない。
- round3 SPEC の as-02 と EC-2（待ち状態の `ESC (` を、後ろに何も付けずに書いていた）を、この要件で置き換える。
- 旧挙動を固定している既存のテストは期待値を変える（AC-7 参照）。
- 帰結: `X ESC ( ESC[?1049h ESC[?1049l ESC ( ESC ]11;? BEL` は、再生時に OSC 11 照会を生じない。
- 検証は末尾の確認だけでなく、後続バイトに対する term_core の解析とその応答を、生のストリームの基準と比べる。
- 根拠: 回答 requirement.fr3.awaiting-designator-at-cut（append-esc）。

#### FR4: 条件付き: カット時に進行中の CSI（隣接経路）

**説明**:
create-plan はまず、カット直前で進行中の CSI について、term_core ベースの回帰テストを追加する。例: `ESC[6`、次に 47/1047/1049 h/l の切替、次に後の読み取りで `n`。その間に可視性復元スナップショットを挟む。1 回の読み取りと、読み取りをまたぐ分割の両方を扱う。

write_filter.rs の 556 行付近は `ESC [` を完了したエスケープとして読み飛ばす。そのため、ライブのクライアントのパーサーが切替の ESC でその CSI を中断した一方で、`ESC[6` がリングに書き込まれる可能性がある。

**ビジネスルール**:
- テストが、生のストリームでは生じない照会またはパース状態の違いを再現した場合は、このフィーチャーで修正する。リングを再生しても、ライブのパーサーがカットで閉じた CSI の内部にクライアントを残さない。
- 再現しない場合は、テストを残し、この経路を「再現しない」と記録する。
- 結果は、3 件の stable_id の判定とは別に記録する。
- 根拠: 回答 requirement.scope.adjacent-gaps（include-adjacent）。

#### FR5: 条件付き: 指示子スロットに置かれた切替シーケンスを抽出が誤読する（隣接経路）

**説明**:
create-plan はまず、`ESC (` / `ESC )` の直後に 47/1047/1049 h/l シーケンスが続く場合について、term_core ベースの回帰テストを追加する。1 回の読み取りの中の場合と、`ESC (` が前の読み取りの末尾にある場合の両方を扱う。

term_core はその ESC を指示子として消費し、残りをテキストとして表示する。`extract_main_buffer_bytes` はそれを画面切替として取り除き、この結果がカットの導出とライブ範囲（live spans）も決める。

**ビジネスルール**:
- テストは、スナップショット + 置換 + 後続チャンクを、生のストリームの基準と比べる（画面、カーソル、応答、表示文字）。
- 違いを再現した場合は、このフィーチャーで修正し、メイン範囲の抽出とカットの導出が、指示子スロットの ESC について term_core と一致するようにする。
- 再現しない場合は、テストを残し、この経路を「再現しない」と記録する。
- 結果は、3 件の stable_id の判定とは別に記録する。
- 根拠: 回答 requirement.scope.adjacent-gaps（include-adjacent）。

## 5. 非機能要件

### 5.1 パフォーマンス要件

**NFR3: リーダーのホットパスの負荷**
- リーダーの通常経路に、バイトを走査する新しいパスを追加しない。
- 連鎖の先頭と構成要素の開始位置の追跡は、既存の `scan_boundary` のパスの中で行う。
- 指示子待ちの ESC の書き込みは O(1) とする。
- FR2 の 2 つ目の読み方は、as-05 フォールバックの条件下にある抑止チャンクに対してだけ動き、有界の線形走査にとどまる。

### 5.2 セキュリティ要件

**NFR4: セキュリティ（TM-1）**
- リング再生・置換の項目・再配送される末尾のいずれを通じても、クライアントのパーサーが制御シーケンスを開始しない位置から、照会やビューア起動を捏造しない。
- FR1・FR2・FR3（再現した場合は FR4・FR5 も）は、この規則への違反を修正する。

**NFR5: セキュリティ（TM-2）**
- 書き込みフィルターの境界走査、strip、クライアント同等走査（FR2 の 2 通りの読み方を含む）、メイン範囲の抽出は、いずれも有界で、panic しない。
- 512 KiB の `pending` 上限と、strip を通すオーバーフローのフラッシュは維持する。保持中の連鎖も上限に数える。
- 空の置換を、空の `PtyOutput` チャンクとして送らない。

### 5.3 可用性要件
該当なし。

### 5.4 保守性要件

**NFR2: ロックの規律**
- ロック順序は `output_target` -> キャプチャ排他 -> リング / シャドウパーサー、および `output_target` -> 境界排他のままとする。
- `output_target` または境界排他を保持している間は、ブロックする待機を行わない。
- 置換の走査（FR2 の 2 つ目の読み方を含む）は、キャプチャ排他と境界排他の外で行う。

### 5.5 互換性要件

**NFR1: 互換性**
- `mux_ipc` のワイヤー形式、Snapshot / SnapshotRestore フレームの形、スナップショットのバイト組み立て配置、置換を通常の `PtyOutput` チャンクとして配送することは変えない。
- リングの内容は、次の点でだけ変わる。
    - (a) カット、または round3 の FR4 のフォールバックでの閉じ処理で閉じられた連鎖は、その先頭以降を書き込まない。連鎖は、確定するか閉じられるまで、読み取りをまたいで保持する（FR1）。
    - (b) カットまたはフォールバックでの閉じ処理の時点で待ち状態にある `ESC (` / `ESC )` の後ろに、ESC を 1 つ書き込む（FR3）。
    - (c) FR4・FR5 の経路が再現した場合に、それらが加える変更。

**NFR6: ビルドとプラットフォーム**
- `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path src-tauri/Cargo.toml --no-default-features` が通る。
- Linux と Windows で動作が同じ。
