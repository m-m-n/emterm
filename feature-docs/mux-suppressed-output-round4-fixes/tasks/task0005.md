# Task Plan: task0005 — Conditional: switch sequence in the designator slot

## Goal

Check with a term_core-based regression test whether a 47 / 1047 / 1049
switch right after `ESC (` / `ESC )` is mishandled by main-span extraction.
Term_core consumes that ESC as the designator and prints the rest as text,
while extraction removes it as a screen switch. If the test reproduces a
difference, make extraction and cut derivation agree with term_core on a
designator-slot ESC. Record the outcome either way (adjacent path FR5).

## Requirements

FR5, FR6, NFR1, NFR2, NFR3, NFR4, NFR5, NFR6

### Files to Modify

## Design

Follow IMPLEMENTATION.md D4 (test first, bounded fix) and the capture-step
and main-span extraction contracts.

### Step 1: the test

Write the registry test before any production change and run it on the
parent's code. Its cases:

- `ESC (` or `ESC )` directly followed by `ESC[?1049h`, `ESC[?1047h` or
  `ESC[?47h`, and by the matching `l` forms;
- each within one read, and with `ESC (` ending the previous read;
- each followed by text and later chunks;
- each through snapshot + replacement + following chunks.

The test compares with the raw-stream reference: screen, cursor, responses
and displayed characters. Record in the task's test record whether it
failed and which aspect differed.

### Step 2a: it reproduces

The fix boundary is extraction, cut derivation and the capture step:

- Extraction treats a toggle whose ESC sits in the designator slot as
  term_core does. The ESC after an `ESC (` / `ESC )` outside any string is
  consumed as the designator, and the rest is not a toggle.
- When `ESC (` / `ESC )` ended the previous read, the reader carries that
  fact as O(1) state into the next extraction. The state is maintained
  inside the existing extraction pass (NFR3).
- Cut derivation and the live spans follow from the corrected span list.
- Ordinary toggles keep today's handling, and so does the borrowed result
  for chunks without toggles.

The capture step cross-checks extraction's final alternate-screen state
against the shadow parser. The shadow parser may still switch on a
designator-slot toggle, because it treats ESC as an abort. Keep the
cross-check and its fallback coherent with the corrected extraction. If
reference parity needs a change outside the boundary, stop at the boundary
(D4): record the residual difference and its cause in DECISIONS.md and
report a plan deviation. Changes outside the boundary include the shadow
parser's own state, the snapshot assembly or its alternate-screen layout,
and the wire format.

### Step 2b: it does not reproduce

Keep the test as regression coverage and make no production change.

### Locks

The capture step already runs under the capture exclusion with the ring and
the shadow parser. The new state is reader-local. The task adds no lock and
no blocking wait, and the lock order stays `output_target`, then the
capture exclusion, then the ring / shadow parser (NFR2).

### Records

Fill the FR5 regions of DECISIONS.md per D5: "reproduced and fixed", or
"not reproducing", plus any residual per D4, with the registry test path.
Add the module line where IMPLEMENTATION.md's region table assigns it, and
make the harness widening edit.
