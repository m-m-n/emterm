# Task Plan: task0004 — Conditional: in-progress CSI at a cut

## Goal

Check with a term_core-based regression test whether a CSI still in
progress right before a cut leaves the ring in a state the live client never
had. If it does, close that CSI at the cut so that replaying the ring never
leaves the client inside a CSI the live parser closed. Record the outcome
either way (adjacent path FR4).

## Requirements

FR4, FR6, NFR1, NFR3, NFR4, NFR5, NFR6

## Scope

### Files to Create
- `src-tauri/src/mux/ipc/pty_spawn/tests/round4_cut_csi.rs` — the FR4 registry test, plus CSI-corpus filter tests and budget tests

### Files to Modify

- `feature-docs/mux-suppressed-output-round4-fixes/DECISIONS.md` — the FR4 adjacent-path section and the FR4 behavior-changing tests subsection

## Design

Follow IMPLEMENTATION.md D4 (test first, bounded fix), D3 (closing
conditions) and D2 (this task owns the CSI closing in step 2 and clearing
the CSI state in step 3).

### Step 1: the test

Write the registry test before any production change and run it on the
parent's code. Its cases:

- `ESC[6` in one read, followed in the same read by a 47 / 1047 / 1049
  `h`/`l` pair, then `n` in a later read;
- the same split across reads (for example `ESC[` | `6` + pair | `n`);
- a visibility-restore snapshot covering the read with the switch;
- a variant where the snapshot comes after the switch read and before `n`.

The test compares against the raw-stream reference: responses, screen,
cursor and displayed characters. Record in the task's test record whether
it failed. Reading the code, it is expected to reproduce: today's boundary
scan steps over `ESC [` as a complete escape, so the ring can hold `ESC[6`
directly followed by the later `n`.

### Step 2a: it reproduces

- Track CSI state inside the existing boundary scan pass. After `ESC [`,
  follow term_core's CSI transitions:
  - parameter, intermediate and final bytes;
  - C0 controls, which execute inside the CSI without ending it;
  - bytes term_core treats as invalid, which cancel the CSI silently;
  - an ESC, which aborts the CSI and starts a new escape.
- Report whether the run ends inside a CSI. Carry the O(1) CSI sub-state
  across feeds the way the awaiting-designator flag is carried. CSI bytes
  are never held in `pending` (D3).
- At a cut, write the CSI closing after the emitted bytes when the emitted
  stream ends inside a CSI, then clear the state. This covers a cut inside
  a call, a cut at an empty segment, an overflow flush followed by a cut,
  and the reader's fallback closing (an empty fed range with a cut at 0).
  The closing never coincides with the FR3 designator ESC or with a dropped
  chain (D2).
- Choose closing bytes that meet D3, and confirm them with term_core: the
  CSI is cancelled without dispatch, the parser is back in ground, and no
  character, cursor move or response results. Check that neither strip
  treats the closing bytes as the start of a strip target.

### Step 2b: it does not reproduce

Keep the test as regression coverage and make no production change.

### Records

Fill the FR4 regions of DECISIONS.md per D5: "reproduced and fixed" or
"not reproducing", with the registry test path. Add the module line where
IMPLEMENTATION.md's region table assigns it, and make the harness widening
edit.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: (FR4, SPEC AC-6, registry) The test at the registry path exists. It covers `ESC[6`, each 47 / 1047 / 1049 `h`/`l` pair and a later `n`: in one read and split across reads, with a visibility-restore snapshot covering the switch read, and with the snapshot between the switch read and `n`. It compares responses, screen, cursor and displayed characters with the raw-stream reference. The task's test record states whether it failed on the pre-change code.
- [ ] AC-2: (FR4, TM-1) If it reproduced, the test passes after the fix. No DSR or other response occurs that the reference does not produce, and replaying the ring never leaves the client inside a CSI that the live parser closed at a cut. This also holds when the cut comes from the reader's fallback closing, and when an overflow flush is followed by a cut. If it did not reproduce, no production file changes.
- [ ] AC-3: (FR4) Filter level, if reproduced. The CSI corpus covers parameters, intermediates, C0 bytes inside the CSI, bytes that cancel it, and an ESC that aborts it.
  - For every split position and for byte-at-a-time feeding, the emitted bytes and the carried state equal the single-call result.
  - Closing bytes are written only when the emitted stream ends inside a CSI at a cut, at most once per cut, and never together with the FR3 designator ESC.
  - A CSI completed or cancelled before the cut gets no closing.
  - Feeding the closing bytes to term_core after the CSI leaves it in ground with no response and no displayed change.
- [ ] AC-4: (TM-2, NFR3, NFR5) CSI tracking adds no pass over the chunk; it runs inside the existing boundary scan and carries O(1) state across feeds. Long CSI parameter runs, and many CSIs straddling reads with cuts, finish within the test time budget and never panic.
- [ ] AC-5: (FR6, SPEC AC-6) DECISIONS.md's FR4 section states "reproduced and fixed" or "not reproducing", with the registry test path. The FR4 behavior-changing tests subsection lists any existing test whose expectation changed (each also reported as a plan deviation) or reads None.
- [ ] AC-6: (NFR1, NFR6) Ring content changes only as NFR1 (c) allows, and only when FR4 reproduced. The diff changes nothing under `crates/mux_ipc/` and no snapshot assembly code. `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib` and `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path src-tauri/Cargo.toml --no-default-features` pass.

## Test Notes

- AC-1 and AC-2 are reader-level and use the widened harness, with the full
  comparison (IMPLEMENTATION.md oracle convention).
- AC-3 runs the filter against a term_core oracle on the same bytes: feed
  the emitted bytes, then a probe, and compare the parser state with the
  reference.
- If the test does not reproduce, AC-2 and AC-3 reduce to "no production
  change". State this in the task's test record.
