# Task Plan: task0003 — As-05 fallback: two-reading intersection

## Goal

In the as-05 fallback, the client-parity scan reads a suppressed chunk two
ways: once with its first byte consumed as a designator, and once with that
byte parsed from ground. It keeps only the items and the tail both readings
report identically. An `ESC (` chain inside the chunk can then no longer
produce a fabricated query (finding 989ec5c588abce06).

## Design

Follow the client-parity scan contract in IMPLEMENTATION.md Shared
Components. The scan's signature, its result shape and its behavior outside
the fallback condition do not change.

### Fallback condition

The fallback condition is the existing one: the "chunk's first byte may be
a designator" check holds. That needs a full retained window, no decidable
ESC in it, and a trailing `(` / `)` that is the window's first byte or
follows an ESC. Under it, the walk starts at the chunk, so the window
contributes nothing to the walked view.

### Two readings

Under that condition, the scan reads the same view two ways:

- Reading (b) is today's walk from ground at the chunk's first byte.
- Reading (a) treats that byte as the consumed designator, and starts the
  same ground-state walk one byte later.

Both readings report in the same coordinates.

- **Items.** An item is kept only when both readings report an item with
  the same range and the same kind.
- **Tail.** A tail is kept only when both readings report the same tail
  start. Its C0-strip flag is the one that tail carries.
- **End-of-view checks.** Checks that inspect the view's trailing bytes
  without depending on where the walk started are evaluated once on the
  shared view. One example is the incomplete-UTF-8-character check. Such a
  tail is then reported identically by both readings, which keeps round3's
  result for a UTF-8 partial at the chunk start.

Anything else is dropped.

This replaces the current rule, which only drops what starts at the chunk's
first byte. The intersection can only remove results; it never adds an
item or a tail.

### Costs

The second reading runs only under the fallback condition, so it is not on
the reader's normal path (NFR3). It is one more bounded linear pass over
the same view and never panics (NFR5). It runs inside the existing scan
call, which the suppressed pipeline makes outside the capture and boundary
exclusions. The task adds no lock (NFR2).

### Records

Update the scan's doc and the fallback-rule doc to the intersection rule.
Fill the FR2 regions of DECISIONS.md per D5. Add the module line where
IMPLEMENTATION.md's region table assigns it.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: (FR2, TM-1, registry) The test at the registry path exists and fails on the pre-fix code. It uses an as-05 fallback window: a full retained window with no decidable ESC and a trailing `ESC (`. In that window:
  - a suppressed chunk `ESC ( ESC ( ESC ]11;? BEL` yields no item, no replacement query and no response;
  - a suppressed chunk `ESC ( ESC ( ESC [` yields no tail, and a following read `6n` produces no DSR response;
  - the same holds behind a trailing `ESC )`.
- [ ] AC-2: (FR2, SPEC AC-5) Items and tails that both readings report identically are still delivered. Cases:
  - a chunk whose first byte is plain text, followed by a complete color query, still delivers that query;
  - a construct that both readings parse alike after a short prefix is kept;
  - an incomplete UTF-8 character at the end of the view is still reported as the tail.

  The control is the same chunk behind a ground window.
- [ ] AC-3: (FR2) A corpus of windows outside the fallback condition gives results identical, item by item and tail by tail, to the pre-change scan. The corpus has windows below the retention size, windows with a decidable ESC, and a trailing `(` not preceded by ESC. Every existing `round3_as05_*` test and every existing client-parity-scan test passes unchanged.
- [ ] AC-4: (TM-2, NFR3, NFR5) Long `ESC (` chains in the fallback window and in the chunk, odd and even, with both readings, finish within the test time budget and never panic. A window outside the fallback condition runs exactly one reading.
- [ ] AC-5: (NFR2) `client_parity_scan.rs` takes no lock and adds no blocking wait, and the scan's call sites in the suppressed pipeline are unchanged (diff inspection).
- [ ] AC-6: (FR6) DECISIONS.md holds the FR2 row (verdict, rationale, the registry test path) and the FR2 behavior-changing tests subsection, which lists any existing test whose expectation changed or reads None.
