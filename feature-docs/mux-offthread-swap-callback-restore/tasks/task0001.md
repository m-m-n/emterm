# Task Plan: task0001 — Transplant callbacks and OSC registration across the off-thread core swap

## Goal

After an off-thread snapshot replay swap, the tab's live `TerminalCore`
retains the pre-swap callbacks and the app-layer OSC 9999
(`MUX_OSC_PARAM` → `OSC_MUX_INBAND`) registration, so pre-mux mux transport
frames and callback-driven inner content keep working exactly as on a
never-swapped tab.

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2

## Design

### Transplant contract (`apply_offthread_swap`)

- Precondition: the tab holds an old live core (callbacks installed at
  construction; OSC 9999 registered) and a worker-built replacement core
  (no callbacks, no app-param registrations).
- Postcondition, while still holding the core lock in step 1 of the swap:
  1. the old core's callbacks value is moved onto the swapped-in core
     (an old core with no callbacks results in no callbacks — no panic);
  2. the swapped-in core has the `MUX_OSC_PARAM` → `OSC_MUX_INBAND`
     app-param registration in effect, behaviorally identical to a freshly
     constructed tab core. Either re-register the known mapping or move the
     old core's registration map — pick whichever is cleaner against the
     current `term_core` API surface.
- The worker-side snapshot build contract (core built with no callbacks) is
  unchanged; no transplant logic runs off the main thread.

### Invariant audits (report, do not expand scope silently)

- Confirm the 2nd-pass scrollback restore path (`spawn_scrollback_restore` →
  `apply_scrollback_restore`) merges into the live core and never replaces
  it; if it does replace, apply the same transplant there and note the
  deviation in the completion report.
- Audit `Tab::new`'s core setup for any other wiring lost by a whole-core
  assignment (beyond callbacks and the OSC app-param registration). Record
  findings in the completion report; fixing anything beyond the two named
  items is out of scope.

### Comment update

Update the rationale comment at the `Tab::new` OSC registration site to
state that off-thread replay cores become the live core at swap time and
receive the wiring by transplant in `apply_offthread_swap`.

## Test Notes

- AC-1/AC-2/AC-5/AC-7 are unit tests at the Tab level, following the
  existing off-thread replay tests (payload sized ≥
  `OFFTHREAD_REPLAY_THRESHOLD_BYTES` to force the off-thread path, worker
  completion pumped the way existing tests do). A recording
  `TerminalCallbacks` double similar to `term_core`'s `Recorder` pattern
  serves as the observable.
- AC-3/AC-4 drive the outer-stream processing entry (the pre-mux
  `process_outer_via_core` path) with bridge-formatted Welcome bytes and
  assert the mux-message side effect (e.g. mux session becoming
  established / attach bootstrap observable used by existing mux tests).
- AC-6 can extend an existing 2nd-pass restore test with post-restore
  assertions instead of a new scenario.
- Known flake: `tabs.rs` replay tests are order-sensitive; always run with
  `--test-threads=1` (project convention).
- TDD: write the AC-1..AC-7 tests first; they must fail on the unfixed swap
  (except AC-6/AC-7 which may pass pre-fix — note observed pre-fix status in
  the report).
