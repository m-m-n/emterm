# Task Plan: task0001 — Post-strip CSI state for the cut closing and the carry

## Goal

The scrollback write filter writes the DEL closing at a cut, and carries the
CSI state into the next call, according to the CSI state of the bytes it
actually wrote after the strip. An open CSI followed by a construct the strip
removes can no longer leave the ring open for a later byte to complete into a
query on replay. Regression tests pin the three reported forms on every path.

## Design

### Where the defect is

At a cut, the cut-aware feed writes the DEL when the boundary scan's CSI state
at the boundary is open. The boundary scan clears that state at every `ESC` it
steps past, but the strip then removes some of those constructs together with
their opening `ESC`: the OSC 777 viewer launch, OSC 9999 emterm-md,
agent-status reports, Kitty APC, SIXEL DCS and answered CSI device queries
such as `ESC[6n`. The written bytes then end inside the CSI that the removed
`ESC` would have aborted, and no DEL follows. The cut-free path carries the
same pre-strip state, so a later fallback closing writes nothing either. The
overflow flush has the same gap.

### State-reporting strip form (shared strip module)

- Inputs: the bytes; whether the first byte is a pending charset designator;
  the CSI sub-state of the written stream before these bytes. Precondition:
  the designator flag and an open CSI sub-state are never given together.
- Outputs: the stripped bytes, identical to what the existing write-path form
  returns for the same bytes and designator flag; and the CSI sub-state of the
  stream formed by the given state followed by those stripped bytes.
- The state is advanced inside the strip's existing single pass by every byte
  the pass writes: copied bytes, designator bytes, and the C0 bytes
  re-emitted from a removed CSI query (EC-3: they leave an open CSI open).
  Bytes the pass removes never advance it. Extra state is O(1); there is no
  second pass.
- Transitions are term_core's, as the boundary scan and its CSI walk already
  follow them. In ground only `ESC` matters. After `ESC`: `[` enters the CSI
  entry state; `(` or `)` makes the next byte a designator, consumed whatever
  it is; another `ESC` stays in the escape state; any other byte completes
  the escape. Inside a CSI: the entry and parameter sub-states accept and
  cancel bytes exactly as the existing CSI walk does; a C0 byte other than
  `ESC` leaves the state; a final byte completes the CSI; `ESC` aborts it and
  starts an escape. An OSC / DCS / APC body needs no state of its own for this
  question: only an `ESC` leaves it, and that `ESC` behaves as it does from
  ground.
- The per-byte CSI transitions are defined once and used by both the boundary
  scan's CSI walk and this form; no second copy exists.
- The CSI sub-state value is defined in the shared strip module, so that
  module never depends on the IPC layer. The write filter keeps it nameable
  under its current name (`CsiPhase`), so the existing tests compile
  unchanged.
- The existing forms (the snapshot form, the write-path form, the remap forms
  and the designator form) keep their signatures and outputs.

### Write filter (the cut-aware feed)

1. A segment followed by a cut, no overflow: strip the run up to the boundary
   with the new form, starting from the carried state. Write one DEL after the
   written bytes when the reported state is inside a CSI, then clear the
   state. The designator `ESC` decision still comes from the boundary scan.
2. The last segment, no overflow: when bytes before the boundary drain, the
   carried state becomes the reported state of their stripped output, started
   from the state carried in. When nothing drains (boundary 0), the carried
   state is unchanged. A held strip target that completes in a later call and
   strips to nothing therefore keeps the open CSI carried in (EC-1).
3. An empty segment with a cut, including the reader's fallback closing:
   unchanged; it now closes the post-strip state.
4. The overflow flush: strip the whole run with the new form, starting from
   the carried state. In the last segment the reported state is carried;
   before a cut, one DEL is written when it is inside a CSI. The
   awaiting-designator state at the end of the flushed run still comes from
   the bounded scan.
5. The boundary scan keeps its structural role (IMPLEMENTATION.md D3). It no
   longer decides the closing or the carried CSI state. Whether it keeps
   walking CSI bytes for any other purpose is an implementation choice, as
   long as only one CSI transition definition exists.
6. Unchanged invariants: at most one DEL per cut; never a DEL and the
   designator `ESC` at the same cut (EC-6); no CSI byte held in `pending`; the
   512 KiB cap and the strip-filtered overflow flush; lock order and wire
   format untouched; no log output added on the per-call path.

### Test design (identifiers in IMPLEMENTATION.md)

- R1: three new CLOSING_CASES rows, each with kept `ESC[6` and inside true:
  `ESC[6` with a complete OSC 777 emterm markdown launch ended by BEL; `ESC[6`
  with a complete Kitty APC (`ESC _ G`, a payload, `ESC \`); `ESC[6` with
  `ESC[6n`. Fed byte by byte, the CSI-query row's query is written across
  calls and is not stripped by the write path (D2, FR6 item 3), so the test
  states that row's byte-by-byte expectation explicitly: the fed bytes, with
  no DEL. Every existing row keeps its expectation.
- R2: for each form, each switch pair from the round3 helper and continuations
  that include `n`, with the cut in the same call and with the fallback
  closing, compare term_core fed the written ring and the continuation with
  term_core fed the raw stream with the switch inline. Keep the removed
  construct's own effect out of the comparison (EC-5): compare the responses
  provoked after the cut only (the convention of the after-cut view in the
  round4 chain tests), and choose a Kitty payload that neither answers nor
  places an image.
- R3: the carried state after cut-free calls (including EC-1), and split
  invariance over a corpus mixing open CSIs, held strip targets (OSC 777,
  OSC 9999, agent-status, Kitty APC, SIXEL DCS) and text. CSI-query strip
  targets stay out of the split corpus (D2).
- R4: reuse the "OSC held at the cap" construction of the round4 cut tests,
  with a run that ends in `ESC[6` and a complete strip target.
- R5: the production reader with the visibility-restore harness of
  round3_write_path (restore at a given read) and its raw-stream comparison.
  For the CSI-query form the raw-stream reference answers the stripped query
  itself; exclude that answer, and keep the full comparison for the other two
  forms.
- R6: the edge cases EC-2, EC-3, EC-4 and EC-6 at the filter level.
- R7: long inputs, within the 10-second budget the round4 cut tests use.
- R9: output identity of the new form against the existing write-path form
  over the scrollback_filter corpora.
