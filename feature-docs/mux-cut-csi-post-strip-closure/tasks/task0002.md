## Design

### Facts the record states

- Source of the finding: the medium architecture finding `4c0ad9058a983648`,
  left unresolved in review round 1 of the predecessor feature
  mux-suppressed-output-round4-fixes.
- Cause: the cut closing (one DEL when the written stream ends inside a CSI)
  and the CSI state carried to the next call used the boundary scan's state.
  The boundary scan clears that state at an `ESC` it steps past, but the strip
  removes some constructs together with that `ESC`: the OSC 777 viewer launch,
  OSC 9999 emterm-md, agent-status reports, Kitty APC, SIXEL DCS and answered
  CSI device queries such as `ESC[6n`. With `ESC[6`, such a construct and a
  cut, the ring ended in `ESC[6` with no DEL, and a later `n` completed a
  cursor-position query on replay. The cut-free path carried the same state,
  so a later fallback closing wrote nothing either; the overflow flush had the
  same gap.
- Fix (IMPLEMENTATION.md D1): the CSI state of the strip-applied output,
  obtained inside the strip's existing pass, decides the closing on the cut
  inside a call, on the empty-segment and fallback closing, and on the
  overflow flush, and it is the state carried after a cut-free call. The
  shared strip's output is unchanged (D2).
- Regression tests: R1-R7 of IMPLEMENTATION.md, cited by their full test
  paths exactly as listed there.
- Behavior-changing tests: none, per IMPLEMENTATION.md Shared Components
  (R1 gained three table rows, with a row-specific byte-by-byte expectation
  for the CSI-query row; no existing row changed). No predecessor test-docs
  record was updated.
- Residuals (SPEC FR6), each with its occurrence condition:
  1. `ESC[6`, a complete viewer launch and `n` fed in one cut-free call are
     written to the ring as `ESC[6n`.
  2. The ring ends in an `ESC[6` whose following construct the strip removed,
     a snapshot is taken in that state with no cut to close it, and the next
     live `n` can complete a cursor-position query.
  3. A CSI device query written across calls reaches the ring as written;
     only the snapshot-time strip removes it.
  Out-of-scope reason, for each: the fix is limited to the cut and the
  carried state (SPEC as-04, IMPLEMENTATION.md D2); these cases come from the
  shared strip joining the bytes around a removed construct without a cut;
  changing the shared strip's output changes the snapshot path, which NFR1
  excludes; a separate task handles them.
- Predecessor records: `feature-docs/mux-suppressed-output-round4-fixes/reviews/round1.yaml`
  and `feature-docs/mux-suppressed-output-round4-fixes/DECISIONS.md` are not
  modified by this feature (SPEC as-02).
