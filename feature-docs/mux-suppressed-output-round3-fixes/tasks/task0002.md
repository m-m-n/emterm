# Task Plan: task0002 — Write-path client parity: closed constructs, designators, straddling switches

## Goal

The scrollback ring never holds a construct the client closed at a removed
or straddling screen switch, and the shared strip and the write filter
treat the byte after `ESC (` / `ESC )` as a designator in every path, so
ring and snapshot content no longer depend on read split positions (review
findings 973af79f520bdaa5, 195916fd94088018, 76342d8d941e6416,
2a9d929f4fafb7cb).

## Design

Cross-task contracts used here (IMPLEMENTATION.md Shared Components):
"Shared strip with an initial state", "Write filter feed", "Capture-step
results", "Replayable-OSC decision" and "Reader-level test oracle". Region
ownership and anchors: IMPLEMENTATION.md Conventions.

### 1. Shared strip (FR2, FR3)

- The single pass in `strip_rich_content_and_remap` gains the
  designator transition: at top level, `ESC (` or `ESC )` followed by any
  byte copies those three bytes verbatim and resumes after them. The third
  byte is consumed even when it is ESC, so it never starts an OSC, APC,
  DCS or CSI candidate. This is the same transition as term_core's escape
  handling and as the write filter's boundary scan.
- `ESC (` / `ESC )` at the very end of the input is copied verbatim; the
  caller carries the state.
- A state-taking form accepts one flag, "byte 0 is a pending designator".
  With the flag set, byte 0 is copied verbatim and scanning resumes after
  it. The existing three entry points keep their signatures and mean "flag
  clear". The snapshot side keeps calling them unchanged.
- Remapped watch offsets map each copied byte one-to-one, the designator
  byte included. The pass stays single and bounded, with no backtracking.
- The OSC branch keeps calling the replayable-OSC decision exactly where it
  does today. Its body belongs to another task's region.

### 2. Write filter (FR1, FR2)

- Every strip call receives, as its initial flag, whether the run it strips
  starts with a pending designator byte. That is the existing "skip" value
  for the segment: a designator wait carried in with an empty `pending`.
  This applies to the normal drain, the cut path and the overflow flush.
- Cut path (FR1): the boundary scan already computed for the run gives the
  start of the single incomplete construct at the run's end: an OSC, DCS or
  APC string, or a held lone ESC, whether carried in `pending` or opened in
  this segment. Emit only the bytes before that start, through the strip
  with the initial flag. Drop the bytes from that start on. Append no
  terminator. Clear the designator flag as today. When the run ends in an
  awaiting-designator `ESC (` / `ESC )`, nothing is held and the whole run
  is emitted, which is the round2 as-08 handling (SPEC as-02).
- Carried-over completion: reported under exactly the existing condition.
  Its sequence bytes and fed end are unchanged. A completion always ends
  before the dropped construct, so it stays readable from the recorded run.
- Overflow flush: unchanged, except that the strip receives the initial
  flag. The flag after the flush still equals the client-parity state at
  the end of the flushed run.
- The documentation of `feed_with_cuts` and of `pending` changes from
  "closed and emitted through the strip" to "closed and not written".
  The `pending` postcondition is unchanged.

### 3. Reader capture step (FR4)

On the fallback path, when the main-span scan's final alternate-screen
state disagrees with the shadow parser's post-chunk state:

- `alt_before` or `alt_after` true: feed an empty range with one cut at
  fed position 0, with empty live spans. The existing feed gate already
  runs the filter when a cut exists. The filter closes `pending` under the
  FR1 rule, and clears the designator flag. No carried-over completion can
  arise, and nothing is written for the chunk (SPEC as-05).
- `!alt_before && !alt_after`: unchanged whole-chunk feed.

### 4. Existing tests

Update the tests this task owns in IMPLEMENTATION.md's changed-expectation
registry. Expected emitted or ring bytes lose the closed construct. Doc
comments that say the construct is released or emitted are corrected. Test
names are kept, except for the one rename listed there. No predecessor
test-docs record changes, because no renamed test of this task is listed
in one.

## Test Notes

- AC-1 strip cases go in `scrollback_filter/tests.rs`. The registry tests
  and every reader-level test go in the new child module, which sees the
  top-level helpers of `pty_spawn/tests.rs` through its parent.
- AC-4 needs the visibility-restore snapshot layout without a dump block.
  The on-demand stand-in snapshot appends a screen dump whose ESC aborts
  the open OSC and hides the bug. Write a small driver in the new module:
  pause the reader at P2 of the chosen read, run the production visibility
  restore for the pane, release, collect the channel, and apply the
  snapshot to a client core with `reset_and_replay_segments` with its
  responses discarded. The driver in the inline `fr8_snapshot_tail` module
  is private; do not edit that module (IMPLEMENTATION.md Shared
  Components, "Reader-level test oracle").
- FR1 cases compare screen, cursor and displayed characters
  unconditionally; the prefix-reproduction guard is not used for them
  (IMPLEMENTATION.md Conventions, "Reader-level oracle convention").
- Red phase: on the pre-fix code, AC-4's BEL completes the OSC and the
  client answers. AC-5 reports a carried-over completion and delivers the
  query. AC-1 strips the leading-zero launch. AC-2 differs between split
  and one-call output.
