# Task Plan: task0003 — Designator-aware as-05 fallback in the client-parity scan

## Goal

When the retention window is full, holds no decidable ESC, and ends in a
possible charset-designator introducer, the client-parity scan extracts
nothing from a construct that starts at the chunk's first byte. A
suppressed chunk can then no longer fabricate a query or launch there
(review finding eaf83fe08869d5e6).

## Design

Cross-task contracts used here (IMPLEMENTATION.md Shared Components):
"Client-parity scan" (owned here; signature, result shape and the meaning
of the combined buffer and boundary stay as they are), "Replacement
builders" (called unchanged by this task's tests) and "Reader-level test
oracle".

### The rule (SPEC FR5, as-03)

The rule applies only in the as-05 fallback: the window is at the
retention size and holds no ESC that the existing designator-slot
exclusion accepts as a restart position. Trigger: the window's last byte
is `(` or `)`, and that byte is either the window's first byte or preceded
by ESC. (At the retention size the first alternative cannot occur; it is
kept so the rule reads the same as the existing designator-slot
exclusion.) In that case:

- The chunk's first byte may have been consumed by the client as a
  designator. Whether it was depends on the parity of a designator chain
  that started before the window, which the window cannot decide.
- No item is extracted, and no tail is produced, from a construct whose
  first byte is the chunk's first byte.
- Constructs that start later in the chunk are classified by the existing
  rules. The walk continues from where the construct starting at the
  chunk's first byte ends under the existing transitions.
- The rule never adds an item. It can only cause misses (SPEC FR5).

Outside the trigger, the fallback is unchanged: it starts at the window's
end, or at the window's trailing UTF-8 partial. A trailing `(` preceded by
anything other than ESC is a designator byte or text, never an introducer,
so it does not trigger. The designator-slot-excluding restart selection
for windows that do hold a decidable ESC is unchanged, and so is the
short-window case (walk from the window's start).

### Implementation latitude

How the start state is represented is the implementer's choice (for
example, an extra "first chunk byte may be consumed" outcome of the
start-state derivation, honored by the scan). The scan's external contract
must not change. Call-site rewrites inside this file's tests, forced by an
internal signature change, are allowed and are not behavior changes.

### Single pass

The check reads at most the window's last two bytes. Item and tail
filtering stays inside the existing walk. No new pass over the window or
the chunk is added (NFR5).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: (FR5, TM-1) For a full window with no decidable ESC whose last two bytes are `ESC (` or `ESC )`, no item and no tail are extracted from a construct starting at the chunk's first byte. Chunks tested: `ESC ]11;? BEL`, `ESC [6n`, a complete OSC 777 markdown launch, an incomplete `ESC [`, and an incomplete OSC. Windows tested: an `ESC (` chain filling the window, an `ESC )` chain, a mixed `ESC (` / `ESC )` chain, and a chain preceded by a `(` at window offset 0. A query that starts later in the same chunk, after a construct that ends inside the chunk, is still extracted exactly as the existing rules extract it.
- [ ] AC-2: (FR5, unaffected cases) A full window with no decidable ESC whose trailing `(` is not preceded by ESC (for example, a window of `(` bytes only) still scans from the chunk start: a chunk `ESC [6n` yields that query. Windows below the retention size, windows with a decidable ESC, the trailing-UTF-8-partial fallback, and the existing start-state tests in `client_parity_scan.rs` and `suppressed_output.rs` keep their results. Existing tests pass unchanged, apart from call-site rewrites.
- [ ] AC-3: (FR5, TM-1, TS-5; registry test `mux::ipc::pty_spawn::tests::round3_as05::round3_eaf83fe0_as05_fallback_never_fabricates_after_a_trailing_esc_paren`) Through the reader: 129 consecutive `ESC (` in earlier reads, then a suppressed chunk `ESC ]11;? BEL`. No replacement chunk is sent for it, and the client produces no response. The client's responses equal the raw-stream reference's (none). - [ ] AC-4: (TM-2, NFR5, TS-9) Degenerate full windows (all `(`, all ESC, alternating `ESC (` and `ESC )` chains, `(` at offset 0 followed by non-ESC bytes) combined with adversarial chunks (long CSI, long OSC, a 64 KiB `ESC (` chain) finish within the test time budget and never panic. `ac1_degenerate_full_windows_complete_without_panicking` passes unchanged.

## Test Notes

- AC-1, AC-2 and AC-4 are unit tests in `client_parity_scan.rs`'s tests
  module, calling the scan or the replacement builder with hand-built
  windows. Use the retention-size constant, never a literal size.
- AC-3 runs in the new child module with the existing top-level reader
  helpers (suppressed reads, client view, reference core, response
  comparison). The stream must be split into reads so that the suppressed
  chunk is exactly `ESC ]11;? BEL`.
- Red phase: on the pre-fix code, the fallback scans from the chunk start,
  so AC-3 delivers `ESC ]11;? BEL` and the client answers.
