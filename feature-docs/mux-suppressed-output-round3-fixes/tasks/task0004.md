# Task Plan: task0004 — Generation-checked tail omission at send time; later record wins

## Goal

The suppressed pipeline decides tail omission from the destination's
boundary record as it stands when the replacement is actually sent, and an
equal-boundary re-record keeps the later snapshot's construct instead of
collapsing to none (review findings 6230e66b979e312e, 240031761bfdf695).

## Design

Cross-task contracts used here (IMPLEMENTATION.md Shared Components):
"Boundary record" and "Replacement builders" (owned here), "Write filter
feed", "Capture-step results" and "Client-parity scan" (consumed
unchanged), and "Reader-level test oracle". Region ownership in `mod.rs`
and `tests.rs`: IMPLEMENTATION.md Conventions.

### 1. Boundary record (FR6, FR7)

- Each destination entry carries a generation. Values come from a counter
  owned by the pane's capture state, so a value is never reused, even
  across destinations.
- Record rules for one destination:

| Case | Boundary | Construct | Generation |
|------|----------|-----------|------------|
| no entry yet | inserted | the recorded one | new value |
| higher boundary | replaced | the recorded one, none included | new value |
| equal boundary | kept | the recorded one, none included (the later record wins) | new value |
| lower boundary | kept | kept | kept |

- Closed destinations are still pruned on every record, as today.
- The covered query, both the free-standing form and the form on a held
  boundary guard, returns the existing construct value (present only when
  the chunk number equals the recorded boundary) together with the entry's
  current generation. Existing callers that read only the construct are
  unaffected.
- The record entry points keep their signatures, so the snapshot paths'
  call sites stay untouched (IMPLEMENTATION.md, "Boundary record").
- A test-only pause hook P4 joins P1–P3. Like them, it costs nothing in
  non-test builds.

### 2. Replacement assembly split (FR6)

- **Prepare.** Inputs: the request without the snapshot trailing
  construct. Work: everything today's builder does before the tail-omission
  rule: scan, item assembly (carried-over completion included), and tail
  selection. Output: an owned value with the assembled items, the tail
  bytes, and whether the tail may be omitted. Only a tail found by the
  client-parity scan may be omitted; the write filter's pending-run tail
  never may. Runs outside every exclusion.
- **Finalize.** Inputs: a prepared value and a construct (possibly none).
  Applies today's rule unchanged: an omittable, non-empty tail equal to the
  construct is treated as already carried, which gives nothing when there
  are no items, and filler-if-designator plus items plus tail otherwise.
  Any other case gives items followed by the tail. It performs no scan, no
  identification and no decider call; it only compares and concatenates.
- The two existing builders become "finalize of prepare" and keep their
  signatures and results for every input.

### 3. Reader send sequence (FR6, NFR2)

Both suppressed call sites, the direct Suppressed arm and the NeedsSlot
re-check arm, run the same pipeline:

1. The covered decision, under `output_target` and the boundary exclusion,
   captures the construct and the generation for destination S.
2. Outside every exclusion: passthrough capture and notification
   processing, partial-sequence discard, carried-over completion mapping,
   then prepare.
3. If the prepared value has neither items nor a tail, stop: no construct
   can make the result non-empty.
4. Secure a send slot for S outside every exclusion: a non-blocking
   reservation first, a blocking reservation when the channel is full, and
   stop when it is closed. In the NeedsSlot arm, reusing the slot already
   reserved or releasing it first is the implementer's choice.
5. P4 (test builds only).
6. Re-take `output_target`, then the boundary exclusion, and re-run the
   covered query for S and the chunk number. If the generation equals the
   captured one, the captured construct stands. Otherwise, use the current
   record's construct; with no entry for S, use none.
7. Finalize. If the result is non-empty, send it into the secured slot
   while still holding both. Otherwise release the slot and send nothing.
8. Release both.

The replacement goes only to S; no other destination's record is
consulted (NFR4). No blocking wait runs under either lock, and a
non-blocking send under the hold is the only channel operation there
(NFR2). The added work under the locks is O(1) apart from the comparison
of the construct with the tail and the final concatenation (NFR3).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: (FR7, TM-3, TS-7; registry test `mux::session::pane::tests::round3_24003176_equal_boundary_takes_the_later_record`) Record rules hold for one destination. An equal-boundary record with a different construct leaves the later one, in both directions (none then `ESC (`, and `ESC (` then none), and between two different constructs. An identical construct is kept. A higher boundary replaces both values. A lower boundary leaves boundary, construct and generation unchanged. Insert, higher and equal records each give a strictly greater generation. A record for one destination never changes another destination's construct or generation. The renamed test `ac2_equal_boundary_with_a_different_construct_takes_the_later_record` asserts the later-record rule.
- [ ] AC-2: (FR6) The covered query, both free-standing and on a held guard, returns the construct with unchanged semantics and the destination's current generation. The generation is the same across repeated queries with no record in between. All existing `ac2_*` record tests other than the renamed one, and the existing snapshot-path tests that read the recorded construct, pass unchanged.
- [ ] AC-3: (FR6, TM-2, NFR5) For a corpus of requests with and without a construct, finalize applied to prepare equals the existing builder's output, and every existing `suppressed_output.rs` test passes unchanged. Both suppressed call sites use the send sequence. A suppressed chunk whose final replacement is empty sends no `PtyOutput` chunk and releases its slot. The only empty `PtyOutput` the reader sends is the EOF marker.
- [ ] AC-4: (FR6, TM-3, TS-6; registry test `mux::ipc::pty_spawn::tests::round3_send_recheck::round3_6230e66b_tail_omission_uses_the_record_current_at_send_time`) With the reader paused at P4 after the covered decision, a second snapshot is recorded for the same destination before the send, and the decision follows the current record. (a) The stale record is `ESC (` and the current one, at the same boundary, is none: the tail `ESC (` is sent, although the stale decision gave an empty replacement. (b) The stale record is none and the current one is `ESC (`: the tail is omitted, so nothing is sent without items, and the filler form is sent with items. (c) The current record has a higher boundary: the tail is sent. (d) The stale record is none and the current one is a UTF-8 lead byte: the tail is omitted, and no replacement character appears when the next read completes the character. Where a real second snapshot reaches the client, the client equals the raw-stream reference in screen, cursor, responses and displayed characters, with no stray `(`. A record for another destination made at P4 does not change S's decision, and S's replacement never reaches the other destination.
- [ ] AC-5: (FR7, TS-7) Through the reader, two snapshots for one destination at the same boundary, both before the covered decision. On-demand (none) then visibility restore (`ESC (`): no `(` is re-sent, and the next chunk's first byte is consumed as the designator, as in the reference. Visibility restore then on-demand: the tail `ESC (` is re-sent. In both orders the client equals the raw-stream reference, with no stray `(` displayed.
- [ ] AC-6: (NFR2, TS-13) While the reader is blocked securing a slot on a full channel inside the suppressed pipeline, another thread can take `output_target` and then the boundary exclusion within a short timeout. While the reader is paused at P4, both the capture exclusion and the boundary exclusion are free. `snapshot_paths_run_concurrently_with_reader_and_resize_without_deadlock` and the existing pause-hook tests pass unchanged.
- [ ] AC-7: (SPEC AC-8, NFR1, NFR6) `test-docs/mux-suppressed-output-round2-fixes/task0004.tests.yaml` AC-2 lists `mux::session::pane::tests::ac2_equal_boundary_with_a_different_construct_takes_the_later_record` in place of the old name. The block carries a supersede comment naming this feature's SPEC.md FR7, `red_reason` is unchanged, and the new name resolves in the libtest listing. No file under `crates/mux_ipc/` changes. ## Test Notes

- AC-1 and AC-2 are unit tests in `session/pane/tests.rs`, next to the
  existing `ac2_*` record tests and using their helpers.
- AC-3 equivalence tests go in `suppressed_output.rs`'s tests module. The
  call-site and empty-replacement checks are reader-level.
- AC-4, AC-5 and AC-6 go in the new child module. The visibility-restore
  driver inside the inline `fr8_snapshot_tail` module is private; write an
  equivalent driver in the new module and leave that module untouched
  (IMPLEMENTATION.md, "Reader-level test oracle").
- For a second snapshot, use a production snapshot path where one exists
  for the pane's state. Otherwise, record through the boundary-record API
  and insert production-assembled snapshot bytes under the same boundary
  hold, as a snapshot path does. State which in the test record. Case (c),
  the higher boundary, cannot arise from a real reader and is recorded
  through the API; parity is not asserted for it.
- The parity check in AC-4 and AC-5 follows the reader-level oracle
  convention.
- Red phase: on the pre-fix code, (a) sends nothing and the client
  consumes the next byte wrongly, (d) re-sends the lead byte and shows a
  replacement character, and AC-1's equal-boundary case yields none.
