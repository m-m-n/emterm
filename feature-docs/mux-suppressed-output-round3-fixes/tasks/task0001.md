# Task Plan: task0001 — Allocation-free OSC identification on the write path

## Goal

The strip's replayable-OSC decision identifies an OSC body without copying
it or validating it as UTF-8, with results identical to the existing
recover-then-identify reference (review finding b3e644c5e2d31809).

## Requirements

FR8, NFR3, NFR5, NFR6

## Scope

### Files to Create

No new files.

### Files to Modify
- `src-tauri/src/mux/osc_identify.rs` — add the allocation-free identification entry and its tests, including the test-only allocation counter
- `src-tauri/src/mux/scrollback_filter.rs` — only the replayable-OSC decision and the osc_identify import line (region ownership in IMPLEMENTATION.md)

## Design

### Allocation-free identification (new entry in `osc_identify`)

Contract (pinned in IMPLEMENTATION.md Shared Components):

- Input: an OSC body as bytes, any values, possibly empty.
- Output: the identity value the reference pair (`recover_osc`, then
  `identify_osc`) returns for the same body.
- Postconditions: no heap allocation; one forward pass bounded by the
  input; never panics.

Processing flow:

1. Walk the bytes before the first `;`. Digits accumulate in base 10 into
   the OSC number with overflow detection. Non-digit bytes are part of the
   data view. On accumulation above the u16 range, return "not identified"
   at once; this matches the reference, which yields no number.
2. If the number is neither 777 nor 9999, return "not identified" at once.
3. Build a borrowed data view, without copying: the non-digit bytes before
   the first `;`, in order (they may be non-contiguous when digits are
   interleaved), followed by the bytes after the first `;`. The first `;`
   itself is dropped. A body with no `;` has only the first part.
4. For 777: the view must begin with `emterm;`. The kind is the bytes up to
   the next `;`, or to the end. `agent-status` gives the agent-status
   identity; a member of the replayable viewer kinds gives the
   viewer-launch identity; anything else is not identified.
5. For 9999: the view must equal `emterm-md`, or begin with `emterm-md;`,
   to give the markdown-launch identity.

Equivalence with the reference for invalid UTF-8: every token compared is
ASCII. Lossy decoding never turns invalid bytes into ASCII and never
absorbs a valid ASCII byte, so a byte-level comparison on the borrowed view
gives the same answers as the reference's string comparison. A kind or
token containing invalid bytes matches nothing on either side.

### Wiring

`is_replayable_osc_body` keeps its name, signature and meaning
(IMPLEMENTATION.md Shared Components) and answers through the new entry.
`scrollback_filter.rs` stops calling `recover_osc` and `identify_osc`. The
reference pair stays in `osc_identify` with unchanged behavior for
delivery-side callers (SPEC as-04) and as the test oracle.

### Test-only allocation counter

A global allocator wrapper exists only in test builds (`cfg(test)`), inside
`osc_identify`'s test code. It forwards every request to the system
allocator. It counts a request only while a thread-local "armed" flag is
set on the calling thread. The thread-local state is constant-initialized
and needs no destructor, and the counting path itself never allocates.
The test arms the flag immediately before calling the new entry and
disarms it immediately after, so only those calls are measured (SPEC
AC-7). Cross-task constraint: IMPLEMENTATION.md Conventions, "Test-only
allocation counting".

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: (FR8 equivalence) For every body in a corpus, the new identification returns exactly the reference pair's result. The corpus holds: canonical OSC 777 bodies for every replayable viewer kind, the image kind and agent-status; OSC 9999 bodies equal to `emterm-md`, starting with `emterm-md;`, and near misses (`emterm-mdx`, `emterm-m`); leading-zero numbers (`0777`, `09999`); non-digit bytes before the first `;`, including interleaved digits and `777emterm;;markdown;…`; bodies with no `;`; the empty body; other numbers (0, 2, 11, 52, 133); numbers above the u16 range; invalid UTF-8 before and after the first `;`; and a long body. The corpus also includes every body up to 4 bytes long over an alphabet of the significant bytes (digits, `;`, `e`, `m`, one invalid byte).
- [ ] AC-2: (FR8, NFR3; registry test `mux::osc_identify::tests::round3_b3e644c5_osc_identification_is_allocation_free_and_matches_the_reference`) The test-only counter, armed only around the new identification calls, records zero heap allocations over the AC-1 corpus, and the results equal the reference. As a control, the same counter records at least one allocation around a reference recovery call on the same thread. The test fails on the pre-fix code: before the entry exists, a stub that delegates to the reference pair makes the zero-allocation assertion fail.
- [ ] AC-3: (FR8 wiring) `is_replayable_osc_body` answers through the new identification, and `src-tauri/src/mux/scrollback_filter.rs` no longer references `recover_osc` or `identify_osc`. The existing `scrollback_filter` tests and the existing `osc_identify` tests pass unchanged: leading-zero launches, non-digit forms, overflow, agent-status stripped, fold and emterm-mux kept, image handling.
- [ ] AC-4: (TM-2, NFR5) A 1 MiB body and a body whose number has one million digits each finish within 2 seconds in the test profile, do not panic, and return the reference's result.
- [ ] AC-5: (NFR6) `osc_identify` gains no dependency on `mux::ipc` or on a `gui`-gated item. The allocation counter and its allocator wrapper are compiled only under `cfg(test)`. `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path src-tauri/Cargo.toml --no-default-features` passes, and the full `--lib` test suite passes with the counter installed.

## Test Notes

- All new tests are unit tests in `osc_identify`'s tests module. The
  reference pair is the oracle, so no expected values are hand-written for
  the equivalence corpus.
- The allocation counter is process-wide but counts only on the armed
  thread. Arm it after the corpus is built, and avoid assertion-message
  formatting while it is armed, so that only the identification call
  contributes.
- AC-3's reference condition is checked by review of the diff. The
  behavioral half is covered by the existing strip tests passing unchanged.

## Out of Scope

- Delivery-side callers (`client_parity_scan`, `suppressed_output`) keep
  the reference pair (SPEC as-04).
- The strip's designator handling and every other part of
  `scrollback_filter.rs`, which belong to the strip owner.
- Any change to what is identified. The identity rules are the round2 rules.
