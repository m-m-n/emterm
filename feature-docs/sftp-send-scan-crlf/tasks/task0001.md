# Task Plan: task0001 — Line-ending independent send-site scan with CRLF regression cases

## Goal

The send-site detection routine in the test-only module of
`src-tauri/src/sftp/service.rs` finds the `mod tests` boundary and reports the
same bare-send result for LF, CRLF, and mixed-line-ending input, and the
red-case test pins this with CRLF cases.

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2

## Scope

### Files to Create

None.

### Files to Modify
- `src-tauri/src/sftp/service.rs` — inside the test-only mod tests item only: line-ending normalization at the entry of the detection routine, doc comments updated to match, and new CRLF and mixed-line-ending red cases.

## Design

Follows IMPLEMENTATION.md decision D1 and its Conventions (NFR1 scope,
NFR2 forbidden-shape assembly, A-1 line-ending scope).

### Detection routine (`scan_for_bare_send_sites`) contract

- **Input**: any module text; line breaks may be LF, CRLF, or a mixture.
- **Precondition**: none beyond valid UTF-8 text.
- **Postcondition**:
  - The result equals the result the routine returns for the same text with
    every CR LF pair replaced by LF.
  - `MissingBoundary` is returned exactly when the normalized text contains
    no `#[cfg(test)]` line immediately followed by a `mod tests` line.
  - Otherwise `Found` is returned, with each flag telling whether the
    corresponding assembled forbidden shape occurs in the normalized text
    before the boundary.
  - Boundary offset and region extraction are both taken on the normalized
    text; no offset computed on one string is applied to another.
- A lone CR is left untouched (A-1).

### Processing flow

1. Receive the input text.
2. Derive the normalized copy: each CR LF pair becomes a single LF.
3. Ask the boundary locator for the boundary in the normalized copy; if
   absent, report `MissingBoundary`.
4. Take the region of the normalized copy that precedes the boundary.
5. Check the region for each assembled forbidden shape and report `Found`
   with the two flags.

### Boundary locator (`find_mod_tests_boundary`)

Signature and anchor condition unchanged (A-2). Its doc comment states that
the returned offset refers to the text it was given; the detection routine's
doc comment states that normalization happens before the boundary search, so
the real-source check and the red-case test both get line-ending
independence through the routine.

### Real-source structural test

`every_progress_and_result_send_site_routes_through_the_wake_helpers` keeps
passing the file content as read to the detection routine; no change to its
logic is needed.

### New red cases

Added to `send_site_scan_detection_routine_red_cases` (FR3 requires the CRLF
case to live there; the other new cases may live there or in a sibling test
inside the same `mod tests` item):

- **CRLF case (FR3)**: the case (i) shape — a `#[cfg(test)]` seam impl block
  holding a bare send, a blank line, then the `#[cfg(test)]` / `mod tests`
  boundary — with every line break written as CRLF.
- **Offset-sensitive CRLF cases (FR2)**: (a) CRLF text whose bare send sits on
  the line directly above the boundary line, preceded by enough CRLF line
  breaks that slicing the original text at the normalized boundary offset
  would cut the send off; (b) CRLF text whose sends appear only inside the
  `mod tests` body.
- **Mixed / full-CRLF parity (FR1)**: for each existing LF text of cases (i),
  (ii) and (iii), a full-CRLF variant and a mixed variant (some line breaks
  CRLF, others LF, including the break between the `#[cfg(test)]` line and
  the `mod tests` line being CRLF in at least one variant).

All new cases reuse the existing assembled bare-send parts; new literals add
only line-break escapes and scaffolding text, never a joined forbidden shape
(NFR2).

## Test Notes

- AC-1 to AC-4 are unit tests inside the module's `mod tests` item. TDD order:
  add the CRLF case (AC-1) first and observe it fail with `MissingBoundary`,
  then add the normalization and see it pass; then add AC-2 / AC-3 cases.
- AC-2 (a) is the case that distinguishes "offsets taken on one string" from
  "offsets mixed across strings"; choose the number of preceding CRLF lines so
  the CR count exceeds the distance between the end of the bare send and the
  boundary.
- AC-5 runs the real-source structural test only on the LF checkout; the real
  CRLF working copy is exercised by the verify phase's manual scenario, not by
  this task.
- AC-6 and AC-7 are static checks (text search, diff review), run after the
  unit tests pass.
- Unrelated flaky tests may appear in the full `--lib` run (tab replay tests
  under parallel execution, tmux socket discovery); re-run such a test with a
  single test thread before treating it as a regression of this task.

## Out of Scope

- Adding `.gitattributes` or any other repository-side line-ending pinning
  (A-3).
- Treating a lone CR as a line break (A-1).
- Any change to production code, the `#[cfg(test)] impl SftpService` seam
  block, or public API (NFR1).
- Changing the boundary locator's signature or anchor condition (A-2).
- Changing the send helpers or the set of forbidden shapes.
- Running a Windows test binary; the Windows cross-check in the verify phase
  covers compilation only.
