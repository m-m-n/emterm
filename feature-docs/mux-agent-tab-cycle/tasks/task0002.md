# Task Plan: task0002 — settings UI row for the next-agent-window keybind

## Goal

The settings panel's mux keybind section shows and edits the binding of the
new `next-agent-window` action exactly like existing mux actions, with
Japanese and English labels.

## Requirements

FR1, NFR3

## Scope

### Files to Create

- (none)

### Files to Modify

- `src-tauri/web-shared/settings/sections/mux-section.ts` — add the
  `next-agent-window` action to the mux keybind rows, following the pattern
  of the existing action rows.
- `src-tauri/web-shared/i18n/locales/en.json` — English label (and
  description, if existing rows carry one) for the new action.
- `src-tauri/web-shared/i18n/locales/ja.json` — Japanese label (same keys
  as the English file).
- `src-tauri/web-shared/settings/types.ts` — only if the mux keybind action
  list is typed here; no shape change is expected (the keybinds value stays
  an action-name → key map).

## Design

The action identifier, default binding (Ctrl+A) and settings key are pinned
in IMPLEMENTATION.md (Shared Components) — implement against that contract.

- The row reads and writes `settings.mux.keybinds["next-agent-window"]`
  with the same edit/reset behavior as the existing mux action rows.
- Labels come from the web-shared i18n locale files (NFR3); no hard-coded
  user-visible strings.
- No new styling: the row reuses the section's existing markup and CSS
  patterns (the project design system is unchanged; no new tokens).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: The mux settings section renders a row for `next-agent-window`,
      labeled via the ja/en locale files, and the label resolves in both
      languages (no raw-key fallback) (NFR3).
- [ ] AC-2: Editing the row reads and writes
      `settings.mux.keybinds["next-agent-window"]` identically to existing
      mux action rows (FR1 configurability).
- [ ] AC-3: `bun run typecheck` and `bun test` pass; `bunx biome check` is
      clean on the touched files.

## Test Notes

- If the mux section has existing bun tests covering its row list, extend
  them to include the new action; otherwise AC-1/AC-2 rest on typecheck
  plus the manual check (VERIFICATION.md MT-3), stated in the completion
  notes.
- Locale files: both languages must gain the key — a missing-key fallback
  that shows the raw key path counts as a failure of AC-1.

## Out of Scope

- Rust-side action registration, dispatch, and keybind validation
  (separate task; contract in IMPLEMENTATION.md).
- Any new visual design, styling tokens, or section layout changes.
