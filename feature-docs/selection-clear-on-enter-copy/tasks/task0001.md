# Task Plan: task0001 — Clear the mouse selection on Enter forwarding and on copy

## Goal

Pressing Enter (in any Shift+Enter mode) or copying through `keybinds.copy`
drops the mouse selection and its pending anchor together, so a highlight left
stranded by a TUI line rewrite disappears on the next frame, while every other
key keeps the selection alive.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4, NFR5, NFR6

## Scope

### Files to Create

None — every file this task needs already exists.

### Files to Modify

- `src-tauri/src/window_host/input_translate.rs` — add the side-effect-free
  clear-decision predicate described in IMPLEMENTATION.md Shared Components.
- `src-tauri/src/app/mod.rs` — add the selection-clear helper described in
  IMPLEMENTATION.md Shared Components. The six existing clear conditions in
  this file are not rewritten.
- `src-tauri/src/window_host/event_loop.rs` — inside the forwarded branch at
  line 497, call the helper when the predicate says to, using the existing
  `is_enter` local already computed at line 448 of the same file.
- `src-tauri/src/window_host/key_routing.rs` — inside the copy branch at line
  101, call the helper immediately after the clipboard write, within the
  branch that only runs when a selection is present.
- `src-tauri/src/window_host/tests.rs` — predicate truth-table tests, the
  Shift+Enter-mode tests, and the source-text scan assertions.
- `src-tauri/src/app/tests.rs` — application-state tests for the helper and for
  the dirty rows of the frame following a clear, built with the existing test
  builder in this file.

## Design

### Components this task adds

Both are specified by contract in IMPLEMENTATION.md Shared Components — the
predicate in the input-translation layer and the clear helper on the
application state. Implement against those contracts; they are not restated
here.

### Enter flow

1. A key press arrives in the event loop; the existing local at
   `event_loop.rs:448` records whether the logical key is the named Enter key.
   This is evaluated *before* the Shift+Enter rewrite is applied, so it holds in
   every `shift_enter_behavior` mode, including the raw-bytes path.
2. The existing translation and rewrite steps run unchanged and the bytes, if
   any, go to the PTY; the existing forwarded flag records whether that
   happened.
3. Inside the forwarded branch at `event_loop.rs:497` — the same branch whose
   existing live-tail snap already runs there — consult the predicate with the
   forwarded flag and the Enter flag, and call the clear helper when it answers
   true.
4. On the next frame the existing dirty-row computation unions the current and
   previous selection, so the rows the old highlight occupied are repainted.

Three paths never reach step 3 and need no extra guard: a configured key
binding (including `keybinds.copy`) returns earlier, an IME composition commit
is consumed earlier, and a modifier key pressed alone produces no bytes so the
forwarded flag stays false.

### Copy flow

1. The copy binding is resolved in `key_routing.rs` and the chord is consumed
   whether or not a selection exists.
2. Only when a selection is present (the branch at `key_routing.rs:101`) is the
   text resolved and written to the clipboard.
3. Immediately after that write, still inside the same branch, call the clear
   helper.
4. When no selection is present, nothing changes: the chord is consumed and
   neither the clipboard nor the selection state is touched.

### Invariants to preserve

- The six existing clear conditions (left-button press, tab switch,
  column-count-changing resize, alt-screen enter/exit, frame reset, scrollback
  eviction) keep their current behaviour and their current inline form.
- Nothing is written to the clipboard or to PRIMARY beyond the copy that
  already happens; the PRIMARY-set path on pointer release and the middle-click
  paste path are untouched.
- No redraw request or full-redraw flag is added — the existing dirty-row
  machinery is relied on, so the render-skip optimizations are not bypassed.
- Everything changed stays inside the `gui` feature; the CLI-only build keeps
  compiling.

## Test Notes

- **Unit (pure)**: AC-1 and AC-2 are plain truth-table tests placed next to the
  existing `shift_enter_rewrite` tests at `window_host/tests.rs:1748-1907` and
  written in the same shape. These are the natural TDD entry point — write them
  before the predicate exists.
- **Unit (state transition)**: AC-3 and AC-6 use the existing application test
  builder in `src-tauri/src/app/tests.rs`. AC-3 needs two cases (both fields set
  → both unset; nothing selected → unchanged). AC-6 asserts on the dirty rows of
  the frame following the transition, not on pixels.
- **TDD-awkward — the two call sites**: neither can be driven from a test. The
  Enter site is inside the winit event loop, and the copy site's handler takes a
  concrete window host and needs a real window. Planned handling: source-text
  scan assertions (AC-4, AC-5) in the same shape as the existing pointer-routing
  scans at `window_host/tests.rs:1488 / 1536 / 1581 / 1629`. Keep each assertion
  to one claim and to the smallest stable landmark that still proves placement,
  so unrelated edits nearby do not break it.
- **Edge cases worth covering in the truth table**: a printable key or a cursor
  key with the forwarded flag true must answer false (this is the guard that
  keeps "select, read, and keep typing" working); a non-forwarded Enter must
  also answer false.
- **Edge cases deliberately not tested**: the numpad / Ctrl / Alt Enter variants
  all report the same named logical key and therefore behave as Enter by
  construction; a mux-connected tab reaches the same forwarded branch; a
  newline inside a paste never passes through this branch. None of these needs
  a dedicated test.
- **Known accepted regression**: pressing Enter while the left button is held
  drops the pending anchor, so the fold-click decision on release
  (`window_host/pointer_routing.rs:355`) does not hold and the fold toggle
  misfires once. Accepted (ASM5) — do not add a guard for it and do not write a
  test asserting the old behaviour.
- **Manual only**: confirming the highlight visibly disappears on a release
  build is TS9 in VERIFICATION.md and is run only on the user's explicit
  instruction — it is not part of this task's completion.

- Clearing on input-field wrapping, or detecting rewrites of lines inside the

- Any change to PRIMARY, to middle-click paste, or to the bracketed-paste
  sanitization path.
- Any change to redraw scheduling, to the frame-skip decision, or to the fold
  layout's full-row dirty behaviour.
- Any design-token, styling, or layout change.
