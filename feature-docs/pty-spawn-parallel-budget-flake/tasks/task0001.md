# Task Plan: task0001 — Load-independent budget and arm-order verdicts with a source-scan guard

## Goal

The three budget tests judge their production calls by thread CPU time, the two
reattach tests arm the second P2 stop before the first release, and a source-scan
guard fails on a return to the wall-clock budget or to the release-before-arm order.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create
- `src-tauri/src/mux/ipc/pty_spawn/tests/budget_and_arm_order_guard.rs` — the guard
  module: the pure judging functions, their negative-example unit tests and the
  real-source guard test (FR6).

### Files to Modify
- `src-tauri/src/mux/ipc/pty_spawn/tests/escape_state_carry.rs` — FR1: the budget of
  `escape_carry_alternating_written_escapes_and_strip_targets_finish_within_the_budget`

- `src-tauri/src/mux/ipc/pty_spawn/tests/post_strip_cut_csi.rs` — FR2: the budget of
  `post_strip_alternating_strip_targets_and_open_csis_finish_within_the_budget`
  becomes a `CpuMeter` budget.
- `src-tauri/src/mux/ipc/pty_spawn/tests/strip_open_string_body_closure.rs` — FR3: the

  `open_body_closure_a_dcs_or_apc_body_left_open_by_an_overflow_flush_is_closed_at_the_next_removal`

## Design

Follow IMPLEMENTATION.md C1 (measurement convention), C2 (guard token contract), C3
(no intentional CPU load) and D2-D4. This section states only what each file needs.

### FR1 — `escape_state_carry.rs`

- The test body creates one meter where it now takes its start instant.
- Every call of `feed_pieces` in the body runs inside one measure call of that
  meter. Where a helper call is now written inside an assertion, its result is
  bound first and then asserted, with the same comparison and message.
- Inputs (the alternating inputs, the byte-at-a-time piece list, the split pairs)
  and expected values are built outside the measured calls.
- At the end the body judges the meter against `BUDGET`, asserts the verdict is
  within (message shows the verdict) and asserts the measured total is greater than
  zero. The final wall-clock check is removed.
- `feed_pieces`, its other callers, the repetition counts, the split positions and
  every output assertion stay as they are.

### FR2 — `post_strip_cut_csi.rs`

- Same shape as FR1. The measured calls are each call of `run_pieces` (oracle check
  off, as now) and the one `emitted_through` call of the query case.
- `run_pieces`, `emitted_through`, `BUDGET`, the workloads and the assertions stay as
  they are.

### FR3 — `strip_open_string_body_closure.rs`

- `check_a_flushed_open_body_is_closed_at_the_next_removal` gains one parameter: a
  runner supplied by the caller. Contract — precondition: the runner executes the
  production call it receives exactly once, on the calling thread; postcondition:
  the helper performs the same production calls, assertions and oracle replay in the
  same order as today.
- Inside the helper, exactly two production calls per target go through the runner:
  the overflow setup (`overflow`) and the next-call feed. Building the next call's
  input, every assertion and `assert_replays_like_raw` run outside the runner.
- The DCS / APC test creates one meter, supplies a runner that passes each call
  through that meter's measure, and at the end judges against `BUDGET`, asserts
  within and asserts a total greater than zero. Its start instant and wall-clock
  check are removed.
- The OSC sibling
  (`open_body_closure_an_osc_body_left_open_by_an_overflow_flush_is_closed_at_the_next_removal`)
  supplies a runner that executes the call directly and keeps its own start instant,
  its wall-clock check, its inputs and its assertions.
- The helper's doc comment states the runner's role.

### FR4 / FR5 — `tests.rs`

- In `visible_reattach_redelivers_alt_screen_and_main_screen_color_queries_once`, the
  second `output_capture.p2.arm()` moves to immediately before the first
  `release_tx.send`, after the first `collect_reattach_data`.
- In `on_demand_snapshot_redelivers_alt_screen_and_main_screen_color_queries_once`,
  the same move, after the first `handle_request_pane_snapshot`.
- The comment next to each moved arm explains, in words, why the arm comes before the
  release (the pattern at `tests.rs:1893-1894`). It does not need the literal tokens:
  the guard ignores whole-line comments (C2).
- Every `recv_timeout` value stays 5 s; nothing else in either test moves.
- The guard module is declared next to the other test modules near the end of
  `tests.rs`, with a one-line comment naming this feature and FR6, in the style of
  the neighboring declarations.

### FR6 — `budget_and_arm_order_guard.rs`

Components:

| Component | Responsibility | Contract |
|-----------|----------------|----------|
| Body finder | Locates the body of one named function in a source string | Input: source text, function name. Output: the body text, or "missing". Matches only the exact text `fn` + space + name + `(`; a name that is a prefix of another name never matches. The body ends at the end of that function (the line holding only its closing brace, at the indentation of a top-level item); text of any later function is never included. CR LF and LF line ends give the same result |
| Budget judgment | Judges one budget test body (C2, first bullet) | Pure: input source text and name; output accepted, missing (naming the function) or rejected (stating which token is forbidden or absent). Whole-line `//` comments are ignored |
| Arm-order judgment | Judges one arm-order test body (C2, second bullet) | Pure: input source text and name; output accepted, missing (naming the function) or rejected. Rejected when fewer than two `p2.arm()` exist, when no `release_tx.send(` exists, or when the first `release_tx.send(` comes before the second `p2.arm()`. `release_tx_2.send(` is not a first release. Whole-line `//` comments are ignored |
| Real-source guard test | Applies both judgments to the real files | Embeds the four target files at compile time (D3); judges the three budget names in their files and the two arm-order names in `tests.rs`; fails on any missing or rejected result, and its message names the test and the reason |

Target names and files: FR1 test in `escape_state_carry.rs`, FR2 test in
`post_strip_cut_csi.rs`, FR3 test in `strip_open_string_body_closure.rs`, FR4 and FR5
tests in `tests.rs`. The guard never scans its own file.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: (FR1, FR2, NFR1, NFR3) The bodies of
  `escape_carry_alternating_written_escapes_and_strip_targets_finish_within_the_budget`
  and `post_strip_alternating_strip_targets_and_open_csis_finish_within_the_budget`
  contain no `Instant::now` and no `.elapsed()`; every `feed_pieces`, `run_pieces`
  and `emitted_through` call in them runs inside a measure call of one `CpuMeter`
  created in the body; each body asserts that the verdict of `.judge(BUDGET)` is
  within and that the measured total is greater than zero; their inputs and output
  assertions are unchanged; both tests pass.
- [ ] AC-2: (FR3, NFR1, NFR3) In
  `open_body_closure_a_dcs_or_apc_body_left_open_by_an_overflow_flush_is_closed_at_the_next_removal`
  there is no `Instant::now` and no `.elapsed()`; for every body and target, the
  overflow setup and the next-call feed run inside a measure call of the test's
  `CpuMeter`, and `assert_replays_like_raw` and the helper's assertions run outside
  every measure call; the test asserts a within verdict against `BUDGET` and a
  measured total greater than zero, and passes. The OSC sibling keeps its wall-clock
  budget, its inputs and its assertions, and passes.
- [ ] AC-3: (FR4, FR5) In both
  `visible_reattach_redelivers_alt_screen_and_main_screen_color_queries_once` and
  `on_demand_snapshot_redelivers_alt_screen_and_main_screen_color_queries_once`, the
  second `output_capture.p2.arm()` comes after the first reattach or snapshot request
  and before the first `release_tx.send`; every `recv_timeout` value is still 5 s;
  the assertions are unchanged; both tests pass.
- [ ] AC-4: (FR6) Unit tests of the budget judgment show: a body with
  `Instant::now` and `.elapsed()` and no meter is rejected; a body with
  `CpuMeter::new` and `.judge(BUDGET)` but no `.measure(` is rejected; a body with
  all three meter tokens and no wall-clock token is accepted; a source without the
  named function is reported as missing, and the report names that function.
- [ ] AC-5: (FR6) Unit tests of the arm-order judgment show: a body whose first
  `release_tx.send(` comes before its second `p2.arm()` is rejected; a body with one
  `p2.arm()` is rejected; a body with no `release_tx.send(` is rejected; a body with
  the second `p2.arm()` before the first `release_tx.send(` is accepted; a source
  without the named function is reported as missing, and the report names that
  function.
- [ ] AC-6: (FR6, NFR4) Unit tests of the body finder and both judgments show: a
  forbidden or required token that appears only in the following function neither
  rejects nor satisfies the named function; a token on a whole-line `//` comment
  inside the body neither rejects nor satisfies it; a name that is a prefix of
  another function's name is not matched to that function; a source with CR LF line
  ends gets the same verdict as the same source with LF line ends.
- [ ] AC-7: (FR6, NFR3) The real-source guard test, run on the changed source, finds
  all five target tests and accepts each. Within `src-tauri/`, only the five files
  of this plan change; no test is renamed; `BUDGET`, `TARGETS`, `Target` and every
  wall-clock check other than the three FR1-FR3 budgets are unchanged.

## Test Notes

- Red first: write the guard's unit tests (AC-4 to AC-6) and the real-source guard
  test before converting anything. On the current source the real-source test fails,
  reporting the wall-clock forms of the three budget bodies and the release-first
  order of the two reattach bodies; record that failure as the red evidence for
  FR1-FR6. Then convert the five tests until the real-source test and the five tests
  pass.
- AC-1 to AC-3 are checked by the real-source guard test plus the five tests
  passing; the "outside every measure call" parts of AC-2 and the "unchanged" parts
  of AC-1, AC-3 and AC-7 are checked by reading the diff.
- Run tests one ordinary run at a time with a name or module filter (for example the
  guard module `mux::ipc::pty_spawn::tests::budget_and_arm_order_guard`). Never
  repeat a run to catch the old failure, never run tests in a loop, never raise
  thread counts or add load (C3, NFR2). The parallel failure is not reproduced.
- One ordinary run of the serial command of SPEC.md AC-5 is a useful final check;
  the verify phase runs the TS-5 and TS-6 runs of VERIFICATION.md.
- No test is renamed, so no test-docs record of another feature changes (SPEC.md A6).

## Out of Scope

- Wall-clock checks other than the three FR1-FR3 budgets, including the OSC sibling,
  the other `open_body_closure_*` tests and the deadlock-detection deadlines at
  `tests.rs:2406` and `tests.rs:2735`.
- Production code, `CpuMeter` and its module, `BUDGET` (stays 10 s), `TARGETS`,
  `Target`, the helpers `feed_pieces`, `run_pieces`, `emitted_through` and `overflow`.
- Renaming tests, changing workloads or output assertions, and changing the
  `recv_timeout` values.
- Guarding any test other than the five named ones.
- Reproducing the parallel failure, under load or by repetition.
