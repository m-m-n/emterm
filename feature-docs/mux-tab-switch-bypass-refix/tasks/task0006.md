# Task Plan: task0006 — Make the inset-change predicate's tolerance pin representable

actually exercises a reachable tolerance — or the predicate is made an
explicit exact comparison — so the pinned behavior and the doc's claimed

## Design

### Defect — the tolerance pin is vacuously true

`status_bar_insets_changed_false_within_epsilon` passes `40.0` and
`40.0 + f32::EPSILON / 2.0`, but at magnitude 40 one ULP (~3.81e-6) is
far larger than `f32::EPSILON / 2` (~5.96e-8), so the addition rounds
back to exactly `40.0` — the test duplicates the
`..._false_when_identical` case and pins nothing: rewriting the predicate
as a plain inequality would keep it green. More broadly, at real inset
magnitudes (tens of logical px) an absolute-epsilon threshold is
equivalent to an exact comparison, so the doc's claimed
float-noise-churn avoidance does not occur.

### Resolution routes (implementer's choice)

- **Representable-tolerance route**: exercise the tolerance where it is
  representable — e.g. compare around 0.5, whose ULP is exactly
  `f32::EPSILON / 2`, with a within-tolerance nonzero perturbation
  asserted "unchanged" and a past-tolerance perturbation asserted
  "changed". The tolerance claim in the predicate's doc is then scoped
  honestly (state at which magnitudes it is effective).
- **Exact-comparison route**: accept that the tolerance is unreachable in
  this domain, switch the predicate to a plain inequality comparison,
  drop the epsilon claim from the doc, and pin the exact-comparison
  semantics (identical → unchanged; any differing value → changed).

Either way the vacuous test case is removed or replaced — no test may
remain whose perturbation rounds back to its baseline.

### Boundary with task0005 (IMPLEMENTATION.md D-E)

This task owns the predicate's tolerance semantics and its tests, and
modifies nothing else in `window_host.rs`. The predicate's shape — stored
and candidate inset values in, bool out — is the stable seam; task0005
consumes it unchanged. FR4's application behavior (which actions follow a
"changed" verdict) is task0005/merged-task0002 territory and is untouched
here.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: no test remains whose perturbation is absorbed by float
  rounding: every non-identical test input differs from its baseline
  after rounding (demonstrable by the test's own construction, e.g. an
  assertion that the two compared values are not bit-identical when the
  case intends a real perturbation).
- [ ] AC-2: the pinned semantics are non-vacuous: if the epsilon
  tolerance is kept, at least one test passes a representable
  within-tolerance nonzero perturbation and asserts "unchanged" — a case
  a plain-inequality predicate would fail — plus a past-tolerance case
  asserting "changed"; if the exact-comparison route is taken, tests pin
  that any representable difference reports "changed" and identical
  values report "unchanged".
- [ ] AC-3: the predicate's doc comment matches the chosen semantics at
  real inset magnitudes — either the tolerance's effective magnitude
  range is stated, or the float-noise-churn claim is removed for the
  exact comparison; the doc cites `869ddd643c123a44` per
  IMPLEMENTATION.md D-C.
- [ ] AC-4 (NFR3): the remaining `window_host.rs` inset and settler unit
  tests stay green with no assertion changes outside the rewritten
  tolerance test(s); the `..._false_when_identical` case remains exactly
  once (no duplicate pin).
