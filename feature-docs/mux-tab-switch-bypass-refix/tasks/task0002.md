# Task Plan: task0002 — Rate-limited settler self-wake and settler-independent inset application

## Goal

During the resize-settle window the render loop's self-wake is rate-limited
to a modest cadence (instead of spinning at full frame rate for up to
`RESIZE_SETTLE_MAX_DURATION`), and a status-bar height change applies the
new drawing insets even when the derived grid size does not change —
without reintroducing the PTY reshape storm the prior feature fixed.

## Requirements

FR3, FR4, FR6, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/window_host.rs` — `refresh_status_bar_insets` (the inset
  assignment and the awaiting-decision self-wake), a new pure self-wake
  predicate plus any state it needs on the host, doc comments, and new
  unit tests in the file's test module.

## Design

### Current behavior (two defects, one function)

`refresh_status_bar_insets` currently (a) assigns
`status_bar_top_inset_logical` / `status_bar_bot_inset_logical` and sets
`pending_resize` ONLY when `resize_settler.observe(candidate)` forwards a
grid-size decision, and (b) otherwise, while
`ResizeSettler::awaiting_decision()` is true, requests a redraw
unconditionally on every frame.

- Defect (a): a status-bar height change whose derived `(cols, rows)`
  candidate is unchanged (cell height above `ROW_HEIGHT` 22.0 at larger
  font sizes, or row clamping) never applies the new insets — permanently
  stale drawing origin and mis-routed mux-sidebar pointer input, which
  reads the same fields (findings `a82206113b8160fd` / `aba5ebbdf9a9addb`,
  one mechanism, one fix).
- Defect (b): the unconditional wake re-enters the redraw cycle with no
  brake — the exact anti-pattern the file already rate-limits for toasts —
  spinning the loop for up to `RESIZE_SETTLE_MAX_DURATION` (1 s) at
  startup and on every mux attach/reattach/tab-switch, competing with the
  off-thread snapshot replay worker for CPU (finding `81507f39e384b34e`).

### Change 1 — rate-limited self-wake (FR3, NFR2)

Extract a pure predicate — plain values in, plain bool out, directly
unit-testable, mirroring `toast_redraw_due`'s form — that decides whether
an awaiting-decision frame requests another redraw: the first wake of a
settle window fires immediately; subsequent wakes fire only after a
minimum interval has elapsed since the last self-wake-driven request.

Cadence constraint: the interval must be short enough that the settler can
still detect quiescence and reach its decision on an otherwise idle window
within `RESIZE_SETTLE_MAX_DURATION` — an interval at or below
`RESIZE_SETTLE_QUIET_DURATION` (64 ms) satisfies this by construction,
while still bounding the wake rate far below a display's full frame rate
(NFR2). The exact constant is the implementer's decision, recorded with
rationale in its doc comment.

Regression guard: the wake must keep arriving until the settler decides —
round-1 findings `02546e5e10deb500` / `5b1878c41d3e02d6-perf-P2` (idle
window strands a pending settle forever) were what the unconditional wake
was added to fix, and must not return.

### Change 2 — settler-independent inset application (FR4)

Apply the drawing insets when the inset VALUES themselves change (an
epsilon-style change predicate on the inset values, as
`refresh_mux_sidebar_inset` already does for its own inset), independent of
the settler's outcome and of `awaiting_decision` state. Per
IMPLEMENTATION.md D-D, `pending_resize` (PTY reshape + group-wide `Resize`
broadcast) remains tied to the settler's forwarded grid-size decision only
— an inset-only change must not flip it. Whether an inset-only change
requests a one-shot repaint so the new origin takes effect promptly is the
implementer's decision; it must not create a sustained wake loop.

The two changes interact: the rate limit applies to the awaiting-decision
self-wake only and must never delay or gate inset application.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TS4): unit tests for the pure self-wake predicate: not
  awaiting → no wake; awaiting, no prior wake → wake; awaiting, within the
  interval → no wake; awaiting, past the interval → wake.
- [ ] AC-2 (TS4): a simulated idle-window sequence test (mirroring
  `resize_settler_self_drives_to_settlement_without_any_external_wake`)
  drives observes only at the rate-limited cadence and asserts the settler
  still reaches its decision within `RESIZE_SETTLE_MAX_DURATION`.
- [ ] AC-3 (NFR2): the predicate enforces a minimum interval between
  self-wake-driven redraw requests, asserted by unit test (bounded wake
  rate, not full frame rate).
- [ ] AC-4 (TS5): a status-bar height change with an unchanged derived
  grid-size candidate applies the new
  `status_bar_top_inset_logical` / `status_bar_bot_inset_logical` values
  (unit test on the inset-application predicate/path).
- [ ] AC-5 (TS5 / FR6): a frame where neither the insets nor the derived
  grid size change leaves the insets untouched and does NOT set
  `pending_resize` (no reshape storm; prior FR6 guard intact); an
  inset-only change also does not set `pending_resize`.
- [ ] AC-6 (NFR3): all existing `ResizeSettler` and `toast_redraw_due`
  unit tests stay green with no assertion changes.
- [ ] AC-7: doc comments on the changed sites cite `81507f39e384b34e` and
  `a82206113b8160fd` / `aba5ebbdf9a9addb`, and state the D-D boundary
  (insets on value change; reshape on settler decision).

## Test Notes

- All ACs are deterministic unit tests in `window_host.rs`'s test module,
  driven by injected time values (the existing settler tests' style) —
  no real clock, no GUI required. Run via the `rust_app` component's test
  command (single-threaded per the configured command string).
- `tabs.rs` off-thread tests are chronically flaky on this host even on
  main (prior retrospect); judge any failure against the main baseline.
- TDD order: predicate tests (AC-1/AC-3) first, then the idle-settlement
  sequence (AC-2), then the inset predicate tests (AC-4/AC-5).
