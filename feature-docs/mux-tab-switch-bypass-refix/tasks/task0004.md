# Task Plan: task0004 — Segment-bound gate: h == 0 cost justification, top-end alignment, and pin purpose

## Goal

The raised bypass segment bound (24 → 62) is justified on every path that
actually reaches the gate — including the `h == 0` fold-degradation path,
where column-changing MIDDLE segments take full reflows — the gate's
documented invariants state what the code does, and the loop-2 cross-crate
pin distinguishes daemon-cap drift from a deliberate cost-policy change
instead of welding the cost-policy constant to the wire cap.

## Design

### Defect A — the same-width rationale fails on `h == 0` (`a1a06ed541045dd5` / `77da6aceb73b1a72`)

The sole stated justification for raising `BYPASS_PREFIX_MAX_SEGMENTS`
24 → 62 is the doc claim that every MIDDLE segment transition is a
same-width resize by construction — because `middle_is_row_bounded`
requires matching columns, and a column change supposedly degrades the
HEAD fold instead of reaching this gate. The last clause is the opposite
of what the code does: `middle_is_row_bounded` is evaluated only inside
`candidate_safe`, and when it fails, `h` degrades to 0, at which point the
MIDDLE is the entire pre-suffix region — column-changing segments included
— and reaches the gate unchecked. Those segments take the full-reflow
resize path (cost proportional to accumulated content), not the
row-delta-bounded same-width path, so the cited round-10 evidence does not
apply, and the worst case loosened from 24 to 62 full reflows over a
byte-bounded MIDDLE. No existing fixture covers the column-changing shape:
both the pre-existing daemon-cap bench and this feature's 26-segment
fixtures hold columns fixed.

Resolution routes (implementer's choice; all stay inside SPEC NFR1 and the
Optimization Constraint):

- **(a) Two-tier bound** — the raised bound applies only when the fold
  succeeded (`h > 0`, where `middle_is_row_bounded` has verified
  same-width); the `h == 0` degradation path keeps the old 24 (or another
  value justified by its own cost argument).
- **(b) Column-uniformity check** — the split itself verifies the MIDDLE
  is column-uniform, so column-changing MIDDLEs never engage. FR6
  non-regression is mandatory here: D9 deliberately rescues that shape
  today, and its existing tests must stay green.
- **(c) Keep 62 everywhere, add the missing evidence** — a release bench
  reproduces the `h == 0` column-changing worst case (the admitted segment
  count, MIDDLE packed to the `BYPASS_PREFIX_MAX_BYTES` limit, dominating
  suffix) and asserts a ceiling relative to bypass-engaged cost in the
  file's precedent relative-bound style; the same-width-by-construction
  rationale is replaced with the measured numbers.

In every route: the false doc sentence is corrected, and
`BYPASS_PREFIX_MAX_BYTES`'s own doc comment gains a cross-reference noting
that it and the segment bound form one cost budget and must be re-measured
together.

### Defect B — top-end alignment (`474e01ad8c29e7f0`)

62 mirrors the daemon's dim-marker record cap, but a snapshot can carry
two more segments (the snapshot cap saturates the wire cap at 64), and a
split needs at least one suffix segment, so the largest reachable MIDDLE
is 63 — a legal shape the gate rejects, making the documented invariant
"this gate never rejects a shape the daemon itself could have produced"
false at the top end (the loop-2 slack rationale is off by one for the
MIDDLE bound, because a synthesized head segment lands in the MIDDLE when
`h == 0`). Either re-derive the bound from the snapshot cap (largest
reachable MIDDLE = wire cap minus the mandatory suffix) with the doc
re-derived from the snapshot-cap constant, or keep the value and weaken
the stated invariant, documenting that the top 1–2 slots are deliberately
out of scope. Boundary tests move with whatever bound is operative.

### Defect C — the pin welds cost policy to the wire cap (`96f7205be52fece8` / `1adb07864f11618f`)

The loop-2 lower-bound pin confines `BYPASS_PREFIX_MAX_SEGMENTS` to
[62, 64], but the constant is a cost-policy value (how many per-segment
reflows the fast path tolerates), independent of the transport cap. Two
consequences: a deliberate lowering (e.g. route a's `h == 0` tier) fails
the pin with a message asserting "this is exactly the round-7/round-8
regression" — misdiagnosing a design decision as drift — and, because a
split needs a non-empty suffix, pinning at 62 leaves the segment-count
gate able to reject only a single shape, fixing it as near-dead code. The
constant's purpose must be decided explicitly and made one coherent story
across the gate condition, the pin, and the docs:

- pin a dedicated daemon-cap mirror constant against the wire-cap
  constant, leaving the cost-policy constant free; or
- keep the assertion but rewrite bounds/message so it distinguishes a
  missed daemon-cap follow-up from a deliberate cost-driven reduction; or
- drop the segment-count condition in favour of the byte bound plus
  suffix-dominance (the rejection benches must demonstrably still hold);
  or
- re-derive the pin's boundary from the largest reachable MIDDLE with the
  slack term redefined as "total segments minus the mandatory suffix".

Whatever is chosen, drift detection survives: a silent revert of the gate
bound to 24 without a matching mirror/doc decision still fails a test.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TS8, FR1/NFR1): the `h == 0` column-changing MIDDLE shape is
  demonstrably cost-bounded: a unit test pins the tightened or conditional
  gate behavior at both sides of the `h == 0` bound (routes a/b), and/or a
  `#[ignore]`d release bench reproduces the `h == 0` worst case (admitted

## Test Notes

- AC-1 (unit route), AC-3, AC-4 are deterministic unit tests in
  `terminal_core.rs`'s test module, run via the `term_core` component's
  debug `--lib` command. AC-4's drift check is a test-time assertion
  (temporarily set the bound to 24 locally to confirm the failure mode and
  message, then restore — record the observation in the test's doc
  comment, matching how loop 2's pin was verified).
- AC-1 (bench route) and AC-5's benches run via the `term_core_bench`
  release command (`--ignored --nocapture`); bounds are relative to a
  same-run baseline to absorb host noise.
- TDD order: write the `h == 0` column-changing fixture first and record
  its behavior against the current gate (this is the missing-evidence
  reproduction), then apply the chosen route until AC-1–AC-4 pass.
