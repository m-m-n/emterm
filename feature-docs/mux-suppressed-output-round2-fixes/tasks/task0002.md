## Design

### FR1: restart-position selection

Applies only when the retained window is full (256 bytes); a shorter window
still holds the whole stream and is scanned from offset 0, as today.

- The ESC at window offset `i` is **excluded** when `i` is 0, or when the
  byte at `i-1` is `(` or `)` and either `i` is 1 or the byte at `i-2` is
  ESC.
- The rule is applied at every candidate, so a chain `ESC ( ESC ( …`
  excludes each of its ESCs in turn.
- The selection returns the first ESC that is not excluded. When none
  exists, the existing as-05 fallback applies unchanged (ground state at
  the window end, or the start of a trailing incomplete UTF-8 sequence).
- The rule may exclude an ESC the client would in fact have started a
  sequence at; that only loses a query or launch, never fabricates one
  (TM-1).
- Selection stays a single forward pass over the window with no panicking
  indexing (TM-2).

### FR2: color queries from every region

- Replacement assembly includes every color query the client-parity scan
  reports for the chunk, verbatim, whether its bytes lie inside a
  ring-written range, outside it, or across a range edge. This is the same
  treatment CSI queries already get.
- The ring-written overlap check for color queries, and its helper, are
  removed. Viewer-launch and CSI-query handling is unchanged.
- Rationale that fixes the defect: the snapshot is replayed with its
  responses discarded, so a color query surviving into the ring is never
  answered through the snapshot.
- A color query that completed inside the retained window is still not
  reported; the scan's existing chunk-end filter already guarantees that.

## Acceptance Criteria (MANDATORY)

      preceded by ESC. Every ESC of an `ESC ( ESC ( …` chain is excluded. A
      window with no qualifying ESC falls back exactly as before. Windows made

      pass without panicking.

## Test Notes

- AC-1 and AC-3 are unit tests. The window-restart rule can be tested
  directly in the client_parity_scan tests module; the registry test (AC-2)
  goes through the four-parameter replacement builder so it compiles and
  runs against the pre-fix sources. Use a term_core client to assert "no
  response" (take its response bytes after feeding the replacement and a
  BEL).
- AC-4 is a builder-level test using ring-written ranges that cover, miss and
  straddle the query.
- AC-5 reuses the existing reader harness and the three snapshot paths' test
  scaffolding (as in the two behavior-changing reader tests). The visibility
  restore case is new.
- The window must be exactly 256 bytes for the FR1 cases; build it
  programmatically and assert its length in the test.
- The retained window only grows through earlier reads. For reader-level
  variants, feed the window content as a preceding non-suppressed read.
