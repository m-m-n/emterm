# Task Plan: task0001 — Shared OSC number recovery and viewer-launch identification

## Goal

Scrollback stripping (ring write and snapshot assembly) and replacement-output
extraction recover OSC numbers and identify viewer launches through one shared
layer, so a viewer launch written with a leading-zero number or with non-digit
bytes before the first `;` is stripped from the ring and the snapshot and
reaches the client exactly once (finding `a93dffe30438a693`).

## Requirements

FR7, NFR1, NFR5, NFR6

## Scope

### Files to Create
- `src-tauri/src/mux/osc_identify.rs` — shared OSC number recovery and viewer-launch identification, independent of mux::ipc and of the gui feature

### Files to Modify
- `src-tauri/src/mux/mod.rs` — register the new shared module
- `src-tauri/src/mux/scrollback_filter.rs` — the strip-side OSC body decision uses the shared identification instead of string-prefix matching
- `src-tauri/src/mux/scrollback_filter/tests.rs` — strip-selection tests for the shared identification
- `src-tauri/src/mux/ipc/pty_spawn/client_parity_scan.rs` — delivery-side recovery and viewer-launch predicate rebuilt on the shared layer; FR7 registry test

## Design

### Shared layer responsibilities

1. **Recovery.** Given an OSC body (the bytes between the `ESC ]` introducer
   and the terminator, terminator excluded), produce the number and the data
   exactly as term_core's OSC string state reconstructs them — the same
   values the existing delivery-side recovery returns today:
   - digits before the first `;` accumulate in base 10 (leading zeros do not
     change the value);
   - the first `;` is dropped;
   - every other byte is data, including non-digit bytes before the first
     `;` and digits after it;
   - data is decoded lossily, as term_core's dispatch does;
   - a body without leading digits yields number zero, as today;
   - the number is absent when the accumulation exceeds u16 (as-06).
   Single pass over the body, no panicking arithmetic or indexing (TM-2).
2. **Identification.** From the recovered number and data, classify the OSC
   as exactly one of:
   - *viewer launch of kind K*: number 777, data `emterm;K` or `emterm;K;…`,
     K one of the replayable viewer kinds in `crate::viewer_kinds` (image
     included);
   - *Markdown launch*: number 9999, data `emterm-md` or `emterm-md;…`;
   - *agent-status report*: number 777, kind `agent-status`;
   - *not identified*: everything else (fold, emterm-mux, other kinds, other
     numbers, an absent number).
   The identification describes what the OSC is; it never decides whether
   to strip or deliver. The agent-status kind name used here has a single
   source; the strip side's existing constant either moves here or refers to
   it.

### Consumer selections

| Consumer | Selects |
|----------|---------|
| Strip side (the OSC-body decision behind every scrollback strip entry point: ring write, snapshot assembly, strip-and-remap) | viewer launch of every kind (image included), Markdown launch, agent-status report. Keeps not identified. |
| Delivery side (the existing viewer-launch predicate in the client-parity scan) | viewer launch of every kind except image, and Markdown launch. Never agent-status, never not identified. |

- The delivery-side entry points keep their names, visibility and contracts
  (IMPLEMENTATION.md Shared Components); they become thin adapters over the
  shared layer. Their truth tables do not change.
- The strip side moves from raw-byte prefix matching to recovered-number
  identification. For the canonical forms (`777;emterm;<kind>;…`,
  `9999;emterm-md…`) the outcome is identical to today; the only difference
  is the NFR1 exception: leading-zero numbers (`0777;…`, `09999;…`) and
  non-digit bytes before the first `;` (`777emterm;;markdown;…`) are now
  identified and stripped.
- OSC detection in the agent-status feed scanner and the passthrough scanner
  is not changed (as-09).

### Processing flow (strip side, per OSC found by the existing strip scan)

1. The existing strip scan finds a complete OSC and hands its body to the
   OSC-body decision.
2. The decision recovers number and data through the shared layer.
3. The decision identifies the OSC and returns "strip" exactly for the strip
   side's selection above.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TM-2): Recovery returns: `10;?;?` → number 10, data `?;?`;
      `010;?` → 10, `?`; `0777;emterm;markdown;x` → 777,
      `emterm;markdown;x`; `777emterm;;markdown;x` → 777,
      `emterm;markdown;x`; a body without leading digits → number zero; an
      accumulation above 65535 → number absent. Empty bodies, invalid UTF-8
      and a body of one million digits return in one pass without panicking.
- [ ] AC-2: Identification returns viewer launch of kind K for every
      replayable viewer kind (markdown, image, json, yaml, html) in the
      canonical, leading-zero and non-digit-prefixed forms; Markdown launch
      for `9999;emterm-md`, `9999;emterm-md;x` and `09999;emterm-md;x`;
      agent-status for `777;emterm;agent-status;x`; not identified for
      `777;emterm;fold;x`, `9999;emterm-mux;x`, `9999;emterm-mdx`,
      `777;other;x`, number 778, and an overflowed number.
- [ ] AC-3 (NFR1 exception): The scrollback strip used on ring write and on
      snapshot assembly removes `0777;emterm;markdown;…`,
      `09999;emterm-md;…`, `777emterm;;markdown;…`, `0777;emterm;image;…`
      and `0777;emterm;agent-status;…`, and keeps `777;emterm;fold;…`,
      `9999;emterm-mux;…`, other kinds and overflowed numbers. Every existing
      scrollback_filter test passes unchanged.
- [ ] AC-4: The delivery-side viewer-launch predicate is true for every
      viewer kind except image and for Markdown launches, in all three forms,
      and false for image, agent-status and not-identified OSCs. The existing
      client_parity_scan tests (including the gui-gated theme oracle) pass
      unchanged.
- [ ] AC-5 (TS-7, registry): `round2_a93dffe3_leading_zero_viewer_launch_reaches_the_client_once`
      in the client_parity_scan tests module: for a suppressed main-screen
      chunk holding `0777;emterm;markdown;…`, and one holding
      `09999;emterm-md;…`, the launch is absent from the strip-applied ring
      bytes and appears exactly once in the replacement output (once in
      total); placed in an alternate-screen range it appears once in the
      replacement output; `0777;emterm;image;…` is stripped and not
      delivered. The same test body fails on the pre-fix code (the
      leading-zero launch survives the strip and arrives twice).
- [ ] AC-6 (NFR6, as-09): The shared module imports nothing from mux::ipc and
      nothing gated on the gui feature; the agent-status feed scanner and the
      passthrough scanner are unchanged;
      `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path src-tauri/Cargo.toml --no-default-features`
      and the `--lib` test run pass.

## Test Notes

- AC-1 and AC-2 are table-driven unit tests in the new module's tests.
- AC-3 goes in `scrollback_filter/tests.rs`, exercising the public strip
  entry points (ring-write strip and snapshot strip), not the private
  decision.
- AC-4 and AC-5 go in the client_parity_scan tests module. AC-5 combines the
  ring-write strip over the chunk's ring-written bytes with the existing
  four-parameter replacement builder (ring-written range = the main-screen
  part, empty pending, empty window), counting the launch's occurrences.
  These entry points keep their parameters in this feature, so the same test
  body runs against the pre-fix sources.
- AC-6 is checked by the build command plus a review of the new module's
  imports.

## Out of Scope

- term_core's u16 overflow in OSC number accumulation (as-06).
- OSC detection in the agent-status feed scanner and the passthrough scanner
  (as-09).
- Replacement-output assembly rules (window restart, color-query inclusion,
  pending exclusion, carried-over completion, snapshot trailing construct).
- Inline images (Kitty APC, SIXEL DCS) and OSC 777 emterm image delivery
  (known loss).
