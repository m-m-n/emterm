# Task Plan: task0004 — Do not re-send a tail the snapshot already carried

## Goal

Every snapshot path records, with the destination's suppression boundary, the
incomplete construct its snapshot leaves the client parser in. Replacement
assembly uses that record so a tail the client already holds is not re-sent,
and so queries still arrive intact when they coexist with such a tail
(finding `3eccc254dd278b33`). Snapshot bytes and the wire format do not
change.

## Requirements

FR8, NFR1, NFR2, NFR3, NFR4, NFR5, NFR6

## Design

### 1. Trailing-construct decider (new leaf module)

- **Input**: the snapshot payload exactly as sent to the destination. That
  is the bytes of all segments, in order, walked with the same parser-state
  carry-over across segment edges that term_core's segment replay applies.
  AC-1 pins this against term_core.
- **Start state**: ground. The client resets its parser before replaying a
  snapshot.
- **Output**: exactly one of:
  - *none*;
  - *UTF-8 partial*: the lead byte plus the continuation bytes seen so far;
  - *awaiting designator*: `ESC (` or `ESC )`;
  - *incomplete CSI*: from its ESC to the payload end, with C0 bytes removed
    in the same way the replacement builder removes them from a CSI tail.
- Any other end state gives none: inside OSC/DCS/APC, lone ESC, or another
  escape state. A construct longer than 256 bytes also gives none.
- **Transitions**: client parity with term_core (as-01; IMPLEMENTATION.md
  D3):
  - strings swallow bytes until BEL (OSC only), ST or an ESC abort;
  - ESC aborts a CSI or a string;
  - ESC ESC stays in escape;
  - the byte after `ESC (` / `ESC )` is always the designator;
  - a non-continuation byte ends a UTF-8 partial silently.
- One forward pass over the payload, with no panicking arithmetic or
  indexing (TM-2). The decider depends on nothing in mux::ipc,
  mux::session or the gui feature.

### 2. Boundary record (per destination)

- Each destination's entry holds its boundary chunk number together with the
  construct (none, or bytes). Record rules for a new (boundary, construct):
  - **higher boundary**: replaces both values;
  - **equal boundary**: keeps the construct when identical, otherwise sets
    it to none, so conflicting information falls back to the pre-feature
    re-send;
  - **lower boundary**: leaves the entry unchanged.
- Pruning of closed destinations is unchanged.
- The existing boundary-only record form stays and means "construct none",
  so existing call sites in tests keep compiling. Production snapshot paths
  use the construct-carrying form.
- The covered query answers, under the same boundary hold as today, both:
  - whether the chunk number is covered;
  - the construct, only when the chunk number equals the recorded boundary
    (otherwise none).
- The destination identity is the one captured at the reader's suppression
  decision. The construct is never derived from the current output target or
  pane state (NFR4, TM-3).

### 3. Snapshot paths

| Path | Where the construct is decided | Where it is recorded |
|------|-------------------------------|----------------------|
| Visibility restore | after the snapshot payload is built, outside the capture exclusion | together with the boundary, at the existing record point |
| Visible reattach | after off-lock assembly | together with the boundary, only when the snapshot is deliverable (as today) |
| On-demand, immediate and deferred | in the handler, after the payload is built | passed with the boundary into the enqueue's deferred commit, and recorded when the deferred flush or the fair-permit front item records the boundary |

- The decider only reads the payload. Snapshot bytes, frames and the
  `mux_ipc` wire format stay byte-identical (NFR1).
- Lock order and the capture-exclusion rule follow IMPLEMENTATION.md
  Conventions (NFR2).

### 4. Reader

- Both covered-check sites (the non-blocking attempt and the retry after
  a slot reservation) obtain the construct with the covered decision.
- The suppression outcome carries it to the suppressed pipeline, which puts
  it into the replacement request's snapshot trailing construct field
  (IMPLEMENTATION.md Shared Components).

### 5. Builder tail rule (FR8)

- Applies only when the tail comes from the client-parity scan, never to a
  pending-run tail (IMPLEMENTATION.md D2).
- The rule triggers when the construct is present and byte-equal to the tail
  the builder would otherwise append (for a CSI tail, compared after the
  existing C0 removal). In that case:
  - with no query or launch items, the tail is omitted. The replacement may
    become empty and is then not sent;
  - with items and an awaiting-designator construct, the builder emits one
    filler designator byte (the ASCII designator `B`), then the items, then
    the tail. The client's pending designator slot absorbs the filler, the
    items parse intact, and the re-sent `ESC (` / `ESC )` restores the
    designator slot for the next chunk's first byte;
  - with items and a UTF-8 or CSI construct, the builder emits the items then
    the tail, as before. The items' leading ESC silently ends a UTF-8 partial
    and aborts a CSI (D3); the tail restores the state.
- In every other case (construct absent or different) the output is
  unchanged. This covers the as-03 shapes: reattach and on-demand
  snapshots ending in a screen-switch sequence, alternate-screen visibility
  restore, and snapshots with a dump block.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TM-2): The decider returns:
      - UTF-8 partial for payloads ending after 2-, 3- and 4-byte leads with
        fewer continuations than needed;
      - awaiting designator for `ESC (` and for `ESC )`;
      - incomplete CSI, with embedded C0 removed, for `ESC [1;` and for
        `ESC [1` CR `;`;
      - none for each of: ground, inside OSC/DCS/APC, a lone ESC,
        `ESC ( ESC` (designator consumed, then a lone ESC), `ESC (` inside an
        OSC, and a construct above 256 bytes.
      For a two-segment payload whose construct straddles the segment edge,
      the result agrees with the parse state term_core reaches through
      `reset_and_replay_segments`. Random and adversarial payloads of 2 MiB
      complete in one pass without panicking.
- [ ] AC-2 (TM-3, NFR2): For one destination, the record rules hold: a
      higher boundary replaces, an equal boundary with an identical construct
      keeps it, an equal boundary with a different construct yields none, and
      a lower boundary leaves the entry unchanged. A record for one
      destination never changes another's. The covered query returns the
      construct only when the chunk number equals the recorded boundary. The
      construct is read under the same boundary hold as the covered decision.
      The decider runs outside the capture exclusion, and the lock order is
      unchanged.
- [ ] AC-3 (NFR1): Visibility restore, visible reattach (when deliverable)
      and on-demand (immediate and deferred) each record the construct of the
      payload they sent. For the same ring and shadow state, the snapshot
      bytes and frames of all three are byte-identical to the pre-feature
      output, and the wire format is unchanged.
- [ ] AC-4 (TS-8, registry): `round2_3eccc254_visibility_restore_does_not_resend_a_tail_the_snapshot_carried`
      and its companions cover visibility restore of a main-screen pane. Two
      ring shapes are tested (ring not wrapped, and ring wrapped with an
      empty screen dump), each with three splits: mid UTF-8, right after
      `ESC (`, and inside an incomplete CSI. In each, the first half is
      suppressed and the client's display, cursor and parsing of the
      following chunks match the reference. No U+FFFD and no designator `(`
      is displayed. The registry test includes the `ESC (` split, and the
      same test body fails on the pre-fix code.
- [ ] AC-5 (coexistence): A suppressed chunk ends in each of the three tail
      kinds after a color query, and after a CSI query. Each query is
      answered exactly once, and parsing of the following chunks matches the
      reference, including the charset selected by the next chunk's first
      byte after an `ESC (` tail.
- [ ] AC-6 (as-03, TM-3): The following shapes record none and re-send the
      tail as before: reattach or on-demand snapshots ending in a switch
      sequence, alternate-screen visibility restore, and a snapshot with a
      dump block. The existing tests
      `visible_reattach_redelivers_a_cut_csi_tail_and_the_client_view_matches_the_reference`
      and
      `visible_reattach_redelivers_a_cut_utf8_tail_with_no_replacement_character_in_any_row`
      pass unchanged. A pending-run tail is never affected. With two
      snapshots sent back to back to one destination, the chunk uses the
      construct of the record that covers it. With two destinations, each
      uses only its own record.
- [ ] AC-7 (NFR6, SPEC AC-8, AC-9): Every existing test passes unchanged,
      apart from call-site rewrites for changed parameter lists. The new
      module has no gui-gated dependency. The `--lib` test run and
      `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path src-tauri/Cargo.toml --no-default-features`
      pass.

## Test Notes

- AC-1 is table-driven in the new module's tests. The segment-edge case
  compares the decider with a term_core instance fed the same segments
  through `reset_and_replay_segments`. term_core is already a dependency of
  the crate's tests.
- AC-2 goes in `session/pane/tests.rs` against the boundary record directly.
- AC-3 extends the existing record tests of each path (`ipc/reattach/tests.rs`
  and `ipc/handlers/tests.rs`, plus the visibility-restore tests in
  `session/pane/tests.rs`). Byte identity is asserted by comparing the sent
  payload with the assembly function's output for the same ring.
- AC-4 and AC-5 use the reader harness with the output-capture pause hooks,
  which place the visibility-restore snapshot between the chunk's capture
  step and its forward decision, as the existing visible-reattach tail tests
  do.
  - Client and reference are term_core instances.
  - The snapshot is applied with `reset_and_replay_segments` and its
    responses are discarded.
  - When the harness cannot produce a wrapped ring with an empty dump
    cheaply, drive that shape through the snapshot assembly function and the
    replacement builder directly, with the same client/reference comparison.
- D3 in IMPLEMENTATION.md explains why only the `ESC (` split fails on the
  pre-fix code. The UTF-8 and CSI splits are regression guards.

## Out of Scope

- Changing snapshot bytes or layouts, or the `mux_ipc` wire format.
- Interference between daemon-appended bytes (trailing switch sequences,
  dump blocks, the alternate-screen switch of visibility restore) and the
  tail (as-03).
- Pending-run tails, write-filter behavior, window restart selection and
  color-query inclusion.
- OSC number recovery and viewer-launch identification.
