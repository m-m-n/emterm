# Task Plan: task0001 — Hold the overflow flush's final live lone ESC

## Goal

When the scrollback write filter takes its overflow flush in the last segment of a call and the flushed run ends in a live lone ESC, that ESC is held in pending instead of written, so the next read strips it together with its continuation and the ring never stores a strip target split across that flush in executable form. Filter-level and production-reader-level regression tests pin the fix and the unchanged rest of the overflow path.

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4, NFR5

## Design

Read IMPLEMENTATION.md first. Its Shared Components row 1 (the held state after an overflow flush), D2 (hold mechanism) and D3 (what counts as a live lone ESC) are the contract this task implements.

### Change site

The overflow branch of the cut-aware feed, taken when the pending run (carried bytes plus this segment) exceeds the 512 KiB cap. Only one case changes: the segment is the last one of the call (no cut follows it in this call) and the run's last byte is ESC. A flush in a segment that a cut follows, and every run whose last byte is not ESC, keep their current bytes, state and closure (FR3, SPEC A4, AC-6).

### Flow of the changed case

1. Take the whole run out of pending, clear the held construct start and mark the call as overflowed, as today.
2. Compute the awaiting-designator flag at the end of the run with the existing bounded boundary scan, as today. For a run that ends in ESC it is always false.
3. Strip the run without its final byte, once, from the written state carried in and with the existing designator flag for the run's first byte. This replaces today's whole-run strip, so the number of passes does not grow (NFR1). Call the reported end state S.
4. Decide in O(1), from S and with the transitions the strip already follows, which written state the final ESC would leave. The strip module is not modified: use its existing state-reporting form on that single byte, or an equivalent O(1) step inside the write filter.
   - Escape (S is Ground, Escape or inside a CSI; a string body counts as Ground): the ESC is live; continue with step 5.
   - Anything else (S is the designator wait, so the ESC is the charset designator): write the stripped bytes followed by that ESC, carry the state after it and the flag from step 2, and stop. This is byte- and state-identical to today's whole-run strip.
5. Write the stripped bytes. Carry S as the written state and the flag from step 2 (false).
6. Put that one ESC back into pending, with the held construct start at 0 (a chain of one construct).
7. The end-of-call bookkeeping stays as it is and already yields the rest of the contract: the call reports no carried completion (the overflow rule), and because the call drained bytes, the held ESC's start dims become this call's current dims (the existing D7''' rule, FR5). The outcome's own dims stay as today (the carried run's start dims when the call began with a carried run).

### Later calls

No new code path. The held ESC is a carried run of one byte, so the next call resumes its boundary scan at it and the strip sees the ESC and its continuation together:
- a strip target is removed (FR1);
- a non-strip continuation is written after the ESC, whole (FR4);
- a string the ESC opens and the continuation completes is reported as a carried completion (FR4);
- a cut, or the reader's fallback closing, drops the ESC unwritten and writes the closure of S (FR4);
- a next call that itself overflows strips the ESC with its own bytes in its flushed run.

### Invariants to keep (NFR3)

- For a run whose last byte is ESC, the strip of the run without that byte, followed by that ESC, equals the strip of the whole run: a trailing ESC is always written verbatim and never changes an earlier strip decision. AC-6 pins it on the non-live and cut cases.
- No change to live forwarding, the snapshot-time strip, the non-overflow path, the strip functions, the reader loop or the suppressed-chunk replacement builder.

### Doc comments (NFR4)

Every doc comment in the write filter that states the overflow postcondition as "pending is empty" or "always empty" right after the overflow flush states the new one: empty, or exactly the one held live lone ESC when the flush was in the call's last segment. This covers at least the "Overflow." paragraph of the cut-aware feed's doc and the postcondition of the pending accessor's doc, plus any overflow paragraph of the struct or the plain feed that describes what remains after the flush. State the memory bound (the cap, then at most one byte after a flush) once.

- [ ] AC-1 (SPEC AC-1; FR1, FR6, TM-1): Reproduction at filter level.
