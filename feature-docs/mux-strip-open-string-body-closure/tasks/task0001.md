# Task Plan: task0001 — Close an open written string body at a removal

## Goal

A construct removed while the written stream is inside an open OSC body or an
open ST-terminated (DCS / APC) body is replaced by the string-body closure,
ESC then CAN, at every strip entry point and from every start state. The ring
then never completes an OSC color query (OSC 4/10/11/12) that the raw stream
never made: not on snapshot replay, and not for a later live continuation.

Supporting work in the same task:

- inverting the pinned predecessor expectations;
- the AC-11 rename and its test-docs record update;
- the decision record;
- the doc comments.

## Design

Cross-task contracts (the closure bytes, the closure before a removal, the
state-reporting strip, remap, the cut closure decision) and decisions D1 to D4
are in IMPLEMENTATION.md. This section adds only what is specific to this
task.

### Why one task

Every new test depends on the production fix, and every inverted predecessor
expectation fails until the fix lands. The rename, the test-docs record and
DECISIONS.md describe the same change. Split tasks would run in parallel
worktrees where the tests of one could not pass without the other. The
Acceptance Criteria are therefore more than the usual seven. Each one is
still one test group.

### Production change

1. In the shared strip module, the closure before a removal gains the open-OSC-body
   and open-ST-terminated-body cases. They write STRING_BODY_CLOSING through the
   per-byte writer, so the reported state ends in Ground. Every other state keeps
   its current behavior: CSI_CLOSING for a CSI and for a written lone `ESC`, and
   nothing for Ground and Designator.
2. STRING_BODY_CLOSING is defined in the shared strip module with the same
   visibility as CSI_CLOSING. Its value stays the two bytes 0x1B and 0x18.
   The write filter drops its own definition and re-exports the shared one
   under the same name.
3. Nothing else changes. Remap already maps a removed construct's offsets
   around whatever the removal writes, and the cut path already chooses from the
   written end state. The snapshot builders call the shared strip.

### Test inputs used below

- Removed constructs: the eight kinds of the existing target tables.
  - OSC 777 launch, BEL-terminated and ST-terminated.
  - OSC 9999 emterm-md.
  - Agent-status report.
  - Kitty APC.
  - SIXEL DCS.
  - The answered CSI query.
  - The CSI query with an embedded CR. Its re-emitted C0 byte is CR.

  "c0" below means the construct's re-emitted C0 bytes, which are empty for
  all but the last kind.
- Body heads: `ESC]0;t`, `ESC]11;`, `ESC Px`, `ESC _Xnot-kitty`.
- Color heads: `ESC]11;`, `ESC]10;`, `ESC]12;`, `ESC]4;1;`.
- DCS / APC heads whose abort answers nothing: `ESC Px`, `ESC _x`.
- Continuations: `n`, `?` BEL, plain text, `ESC \`.

### FR8 item 5 rows (state form, expected output / reported state)

| Start state + input | Before | After |
|---------------------|--------|-------|
| OscBody + `ESC[6 BEL n` | `BEL` / Ground | `ESC CAN BEL` / Ground |
| OscBody + `ESC[6 CR n` | `CR` / OscBody | `ESC CAN CR` / Ground |
| StBody + `ESC[6 BEL n` | `BEL` / StBody | `ESC CAN BEL` / Ground |
| Ground + `ESC]0;t ESC[6 BEL n` | `ESC]0;t BEL` / Ground | `ESC]0;t ESC CAN BEL` / Ground |
| Ground + `ESC]0;t ESC[6n` | `ESC]0;t` / OscBody | `ESC]0;t ESC CAN` / Ground |
| Ground + `ESC Px ESC[6n` | `ESC Px` / StBody | `ESC Px ESC CAN` / Ground |
| Ground + `ESC Px ESC[6n ab` | `ESC Px ab` / StBody | `ESC Px ESC CAN ab` / Ground |
| OscBody or StBody + each construct (loop) | empty / the body state | `ESC CAN` / Ground |
| Ground + `ESC]0;t` + each construct (loop) | `ESC]0;t` / OscBody | `ESC]0;t ESC CAN` / Ground |
| Ground + `ESC Px` + each construct (loop) | `ESC Px` / StBody | `ESC Px ESC CAN` / Ground |

### Rule for an unforeseen failing test

If an existing test outside FR8 items 1 to 6 fails, and it fails only because
a removal inside an open written body now writes ESC CAN, handle it in this
order:

1. Confirm with the end-state oracle and the raw-stream reference that the
   new bytes replay like the raw stream.
2. Update the expectation and keep the test name.
3. Record its before and after values in DECISIONS.md.
4. Report it as a plan deviation.

A failure with any other cause is a defect in the change, not an expectation
to update.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR3, NFR3; TM-1): strip level, every entry point. Feed each body head + each removed construct + each continuation to each of the six strip entry points:
  - the replay strip;
  - the write-path strip and its designator form;
  - remap and its designator form;
  - the written-state form, started in Ground.

  The output is exactly head + ESC CAN + c0 + continuation: one closure, before the C0 bytes. The written-state form reports Ground, and the end-state oracle observes Ground for the output. The output replays like the raw-stream reference with the construct's own effect excluded (rows, cursor, responses). With all eight constructs concatenated inside one body, the output is head + one ESC CAN + every construct's C0 bytes in order + continuation. TM-1: the joined bytes never complete a string the raw stream aborted.
- [ ] AC-2 (FR1, FR3, NFR3; TM-1): carried bodies and split reads.
  - (a) The written-state form, started in the open OSC body and in the open ST-terminated body, given each construct + each continuation, writes ESC CAN + c0 + continuation and reports Ground. The oracle agrees.
  - (b) The write filter after an overflow flush left a body open. Cover an OSC body held at the cap and each of the four DCS / APC bodies that overflow_open_string_cut holds at the cap; each is flushed past the cap. The next call, of each construct + `?` BEL + plain text, writes ESC CAN + c0 + `?` BEL + text, holds nothing and leaves Ground. The replay of everything written matches the raw-stream reference.
  - (c) After an overflow call that ends with body bytes and a held live lone `ESC`, a next call of the construct without its `ESC` + `?` BEL + text writes ESC CAN first and leaves Ground.
  - (d) Head + each string construct the filter holds across reads + `?` BEL, split into two calls at every position with no cut, writes the same bytes as one call. The CSI query constructs split at every position replay with no response through the themed client and match the reference. TM-1: no split position lets a later byte join the body.
- [ ] AC-3 (FR1, FR7 a/c/d, NFR3; TM-1): DoD snapshot replay.
  - For each color head × each construct, one cut-free write-filter call of head + construct + `?` BEL writes exactly head + ESC CAN + c0 + `?` BEL to the ring. Nothing is held and the state is Ground.
  - The stripped scrollback part of build_snapshot_bytes over that ring equals the ring.
  - Replaying the snapshot payload through the themed client produces no response. Its rows and cursor equal view_after_a_cut of head + construct then `?` BEL.
  - The same holds for the DCS and APC heads, comparing rows, cursor and responses with the raw-stream reference.
  - Controls: the themed client answers `ESC]11;?BEL` (the closure-less join) and answers each color head + `?` BEL.

  TM-1: no color response on snapshot replay.
- [ ] AC-4 (FR7 b/c; TM-1): live continuation.
  - For each color head × each construct, the ring is the write-filter output of head + construct.
  - build_resume_snapshot_bytes over that ring, with no segments, an empty screen, the main buffer and the shared test dimensions, gives the resume clear prefix followed by the ring, with nothing appended.
  - Replay it through the themed client and discard the replay's responses. A following live `?` BEL produces no response.
  - The same holds when the raw head + construct is given as the ring: the snapshot-time strip writes the closure.
  - Controls: with a ring of the head alone, the same path answers the live `?` BEL.

  TM-1: no color response for a live continuation.
- [ ] AC-5 (FR4): remap and segments. For a body head + each construct + continuation, use remap and its designator form with watch offsets at:
  - 0 and inside the head, which map unchanged;
  - the construct's first byte, which maps to the head length, before the closure;
  - a byte inside the construct, its last byte, and the offset right after it, which map to the head length + 2 + c0 length;
  - one past that and the input end, which shift by the same difference.

  Mapped offsets are non-decreasing and never exceed the output length, and both forms agree. In the snapshot-builder test module, build_snapshot_bytes segments placed at the same input positions follow the same mapping, shifted by the snapshot clear prefix.
- [ ] AC-6 (FR5, FR6; TM-2): no double closure, and the closure stays inert.
  - After a write-filter call of head + construct writes head + ESC CAN + c0, each of these writes nothing more and leaves Ground with no designator awaited:
    - one cut, and two cuts, at the end of that call;
    - a cut at fed offset 0 of the next call (the call writes its text only);
    - the reader's fallback closing (an empty fed range with a cut at 0).
  - The write-path strip and the snapshot-time strip turn body + ESC CAN + each construct into body + ESC CAN + c0, adding no closure. Body + ESC CAN alone is kept unchanged.
  - The vt100 replay copy of a ring holding the closure equals the ring.

  TM-2: the inserted closure never doubles, is never read as a target start or ST, and is never rewritten.
