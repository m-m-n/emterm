# Task Plan: task0002 — Plain-tab half of the cut parity corpus

## Goal

Tests pin that a plain tab, fed every row of the IMPLEMENTATION.md SC-1 cut
parity corpus through its live output path, ends in the row's final OSC 7501
table and final OSC 777 state. Together with the mux half (asserted against
the same corpus), this is the plain-tab / mux parity check of FR7. No
production file changes.

## Requirements

FR7, FR8, FR9, NFR4, NFR5

## Scope

### Files to Modify

## Design

### What is tested

The plain-tab path is the reference behavior (IMPLEMENTATION.md D1): term_core
cuts an OSC string at an in-body `ESC` followed by a byte other than `\`,
dispatches it as unterminated, and the plain-tab callbacks drop an
unterminated OSC 7501 and apply an unterminated OSC 777 / OSC 133. This task
adds tests only; it does not change term_core, the callbacks or the tab.

### Driving a row

1. Build a plain tab holding the row's seed: S-W through the existing seeded
   plain-tab helper, S-ALL through the existing one-record-per-state helper,
   S-0 as a fresh test tab. Drain the pending summary changes the seed made.
2. Deliver the row's stream through `process_combined`: one call for "one";
   two consecutive calls for each split the row's delivery names (IMPLEMENTATION.md D3).
3. Observe:
   - **Final OSC 7501 table**: the tab's record table (ids and states).
   - **Table changes**: the pending summary changes the stream recorded.
   - **Final OSC 777 state**: resolve the tab's pending agent-status events
     and pending latch inputs the way the app applies them — walk the latch
     inputs in order; a Set / Clear input first applies the tab's next
     unconsumed event and then records the latch set / clear; a Mark input
     records a live prompt mark; events left over are applied afterwards —
     through the agent-status model's public plain-tab operations, and read
     the tab's state from the model.

### Threat-model link

The rows this task asserts are the plain-tab reference for TM-1 (K1–K5) and
TM-2 (K10, K14, K15). The mitigations themselves are implemented on the mux
path by task0001.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR7, FR9; reference for TM-1): Through `process_combined`, corpus rows K1–K5 — with K3 and K4 delivered as two consecutive calls split between the two ESCs — end in the row's final OSC 7501 table. K1–K4 record no pending summary change and write no OSC 7501 answer; K5 records exactly one pending summary change, the empty table.
- [ ] AC-2 (FR7): Rows K6 and K7 each produce exactly one OSC 777 Set event with state working, and their final OSC 777 state is working.
- [ ] AC-3 (FR7; reference for TM-2): Rows K8–K10 end in the row's final OSC 777 state, resolved from the tab's agent-status events and latch inputs as the Design describes. Rows K11–K15 end in the row's final OSC 7501 table; K14 and K15 do so in one call and at each cut-point split the row names.
- [ ] AC-4 (FR8, NFR4, NFR5): Every existing test in the file — the SC-4 parity corpus tests and the OSC 7501 prompt-start / RIS tests included — passes with its assertions unchanged. The task changes no file other than its declared test file: nothing under `crates/term_core/`, nothing in `src-tauri/src/callbacks.rs`, and no other production file. The new tests use no platform-gated API.

## Test Notes

- The plain tab already behaves as SC-1 expects, so these tests are expected
  to pass on first run; there is no red phase for this task. Before relying on
  that, confirm each new test can fail: for one row per AC, temporarily assert
  a wrong expectation and see it fail, then restore it.
- If a row's plain-tab outcome differs from SC-1, do not change term_core, the
  callbacks or the tab, and do not change the row's expectation in the test to
  match: report the row as a plan deviation (IMPLEMENTATION.md D1).
- The existing latch tests (the end-to-end latch-feed tests in the tabs test
  modules) show how an uncut D→A pair appears as latch inputs; the K8–K10
  resolution goes one step further to the model's final state.
- A non-canonical prompt start's effect on the OSC 777 latch is not a corpus
  row (IMPLEMENTATION.md SC-1, last paragraph); do not add one.
- Name the rows in assertion messages so a failure identifies the row and the
  split offset.
- `tabs` replay tests can fail nondeterministically in parallel; rerun a
  failing one with a single test thread before treating it as a failure.
