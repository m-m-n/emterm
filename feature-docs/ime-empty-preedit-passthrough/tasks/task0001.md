# Task Plan: task0001 — Two-level IME state with a platform-conditional key gate

## Goal

The winit IME bridge stops suppressing keys once the input method's preedit
becomes empty on Unix, while continuing to suppress them for the whole
duration of a Windows composition, so that emptying an SKK conversion buffer
no longer makes the terminal unresponsive to keyboard input.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, FR9, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/ime/winit_bridge.rs` — replace the single composition flag
  with the two-state model, update the event-handling arms, make the key
  suppression predicate platform-conditional, correct the module and field
  documentation, and add the regression tests.

## Design

### State

The bridge holds two independent boolean states in place of the current single
flag:

| State | Meaning | Set by | Cleared by |
|-------|---------|--------|------------|
| Preedit-present | The most recently observed preedit text was non-empty | A preedit event carrying non-empty text | A preedit event carrying empty text; a commit event; a disable event |
| Lifecycle-open | The IME lifecycle has been opened and not yet closed | An enable event | A disable event |

Neither state is named "composing" (IMPLEMENTATION.md Conventions).

### Event handling contract

For each incoming winit IME event, the bridge updates state and enqueues
neutral events exactly as follows. Anything not named in a row is left
untouched.

| Incoming event | Preedit-present | Lifecycle-open | Enqueued |
|----------------|-----------------|----------------|----------|
| Enable | unchanged | true | nothing |
| Preedit with text T | true when T is non-empty, false otherwise | unchanged | a preedit event carrying T, including when T is empty |
| Commit with text T | false | unchanged | a commit event carrying T, only when T is non-empty |
| Disable | false | false | a focus-out event |
| Delete-surrounding | unchanged | unchanged | nothing |

Preconditions: none — every arm is total over its input and must not panic.
Postcondition: the queue is only ever appended to; no arm removes or reorders
previously queued events.

### Key suppression predicate

`dispatch_key_event` answers "consumed" or "passthrough" from one state,
selected by compile-time target:

- On Windows: consumed exactly when Lifecycle-open is true.
- On every other target: consumed exactly when Preedit-present is true.

The predicate reads the raw key event's contents not at all — it stays a
constant-time boolean read with no allocation and no locking (NFR1).

The branch selection is expressed once. Both arms must exist in the compiled
source on every target so that neither branch can rot unnoticed; only the
selection is conditional.

### Documentation to correct

The module-level and field-level documentation currently asserts that the
Wayland text-input protocol sends an empty preedit for cursor-only updates.
That assertion is false for the pinned winit version and is the reasoning error
behind the bug. Replace it with the verified behavior recorded in SPEC.md
"Rationale for the platform split", stated compactly: which winit sub-crate
emits the lifecycle events for which underlying platform event, and why that
forces the platform split. Do not merely soften the wrong claim — remove it.

### Existing tests

Every test currently in the module must be re-read and classified before the
change is made. For each, state whether its expected result is unchanged under
the new model. Only tests whose premise no longer holds may be adjusted, and
each adjustment must be justified in the commit message. In particular, the
existing test covering a bare empty preedit with no preceding enable event
still expects passthrough, but the reason differs per platform — its
documentation must say so rather than leaving the coincidence unexplained.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: After a non-empty preedit followed by an empty preedit, the next
      key dispatch is passthrough on non-Windows targets, and both preedit
      events are observable through the neutral event queue in order.
- [ ] AC-2: After a non-empty preedit, an empty preedit, and then another
      non-empty preedit, the next key dispatch is consumed again on non-Windows
      targets.
- [ ] AC-3: An enable event alone never causes a key dispatch to be consumed on
      non-Windows targets.
- [ ] AC-4: On Windows, a key dispatch between an enable event and a disable
      event is consumed even when the only preedit seen was empty, and is
      passthrough after the disable event.
- [ ] AC-5: On Windows, a commit event occurring between an enable and a
      disable event does not make the following key dispatch passthrough.
- [ ] AC-6: A delete-surrounding event leaves the key dispatch answer unchanged
      from whatever it was immediately before, in both the preedit-present and
      preedit-absent situations.
- [ ] AC-7: Every test that existed in the module before this change still
      passes, and the module contains no remaining claim that the Wayland
      protocol sends an empty preedit for cursor-only updates.

## Test Notes

All criteria are unit-testable inside the module's existing test harness, which
already provides a mock window handle and helpers for building raw key events.
No new test infrastructure is needed.

- AC-1, AC-2, AC-3 and the non-Windows halves of AC-6 are asserted under a
  non-Windows target condition.
- AC-4, AC-5 and the Windows half of AC-6 are asserted under a Windows target
  condition. Target-gated code is not compiled on the Linux development host at
  all, so the only local evidence available is the project's Windows
  cross-check command; run it and confirm it succeeds. Write these tests so
  that a test run on a Windows host executes them.
- AC-7 is verified by running the existing test set unmodified and by reading
  the resulting file.

Edge cases worth covering beyond the criteria: a commit arriving directly after
an empty preedit (the queue order must be preedit, empty preedit, commit), and
an empty preedit arriving with no preceding event at all.

TDD note: write each test against the intended state model first and watch it
fail for the right reason (a consumed answer where passthrough is expected)
before changing the state fields.
