## Design

### TS-5

Add a test that runs the full three-step sequence on non-Windows targets and
asserts the dispatch answer after each step: passthrough after the leading
empty preedit, consumed after the non-empty preedit, passthrough again after
the trailing empty preedit. Name it so the X11 start/end ambiguity it stands
for is evident from the name alone.

### TS-1

Reshape the existing TS-1 test so the parts that are platform-independent run
on every target and only the platform-dependent expectation is conditional:

- Send the enable event first, matching the real event order an input method
  produces.
- Assert the dispatch is consumed while the non-empty preedit is current. With
  the enable event present this expectation holds on every target — the Windows
  gate is satisfied by the lifecycle being open, the non-Windows gate by the
  preedit being non-empty — so this assertion needs no platform condition.
- Assert the queue receives both preedit events in order. This verifies FR2 and
  is platform-independent, so it must not sit behind a platform condition.
- Keep only the final expectation (what the dispatch answers after the preedit
  is emptied) platform-conditional, since that is the one answer the two gates
  genuinely disagree on.

Express the platform-dependent expectation as a value chosen at compile time
rather than by duplicating the test body, so that a single test carries the
whole scenario on both targets.
