## Goal

The scrollback write filter carries the full end state of the bytes it wrote after the strip
(Ground / Escape / Designator / Csi(Entry) / Csi(Param)) and writes at most one closure per
cut chosen from that state, so its output and state do not depend on where PTY reads are
split, and a ring replay never completes a query or reset the client did not start
(review finding `a879a02de382209f`).

## Design

Cross-task decisions are in IMPLEMENTATION.md: D1 (the carried state and the closure rule),
D2 (the Escape closure is CAN), D4 (the only behavior-changing rows), D6 (registry anchor),
and the regression test identifiers R1-R11 this task must define under exactly those names.

### Written end state (shared strip module)
- Five values: Ground, Escape, Designator, Csi(Entry), Csi(Param). The transitions are the
  ones the existing private written-state type already applies per written byte; they do not
  change.
- The type becomes nameable inside the mux module tree (the same visibility as the CSI phase
  type), so the write filter can store it. It offers a projection to the CSI sub-state:
  Csi(phase) gives that phase, every other state gives none.

### Stateful strip (successor of the CSI-state form)
- Inputs: the bytes; the verbatim flag (the first byte is a pending charset designator, as
  decided by the write filter's boundary scan); the carried written state.
- Precondition: when the verbatim flag is set, the carried state is Designator or Ground (the
  run before ended in a written `ESC (` / `ESC )`, which leaves the written stream in one of
  those two; Ground arises from a splice, EC-5). Checked by a debug assertion.
- Postconditions:
  - The stripped bytes are byte-identical to the designator form's output for the same bytes
    and flag, whatever the carried state is: the state never influences a removal decision.
  - The returned state is term_core's state after the carried state followed by the stripped
    bytes. Bytes the pass removes never advance it; written bytes, designator bytes and the
    C0 bytes re-emitted from a removed CSI query do.
  - Extra state is O(1) and is advanced inside the one existing pass.
- The verbatim copy of the first byte is driven by the flag alone. A carried Designator with
  the flag clear only affects transitions: the first written byte moves it to Ground, and the
  first input byte is examined as a possible strip-target start as usual.
- The narrowing form that returns only the CSI sub-state is removed; its callers (the write
  filter and the strip tests) move to the successor, whose name states that it reports the
  written state. The other strip forms keep their names, signatures and outputs (NFR1).

### Write filter
- The carried field holds the full written state and replaces the CSI-only field. Its doc
  states that it may stand together with the awaiting-designator flag (Designator or Ground
  while the flag is set) and with a non-empty `pending` (the state is that of the written
  bytes before the held chain's head).
- Every strip call passes the run's verbatim flag and the carried state and stores the
  returned state: the normal drain, the run before an in-call cut, and the overflow flush.
  A call that drains nothing leaves the state unchanged.
- One closure decision, used by every cut path: Csi(Entry) or Csi(Param) writes
  `CSI_CLOSING`; Escape writes the Escape closure; Designator writes one ESC (0x1B); Ground
  writes nothing. Exactly one decision per cut.
- Where the state at a cut comes from:
  1. In-call cut: the state returned by the strip of the run truncated at the boundary (the
     chain the cut drops is not written and does not affect it).
  2. Empty-segment cut, including the reader's fallback closing (empty range, cut at fed 0):
     the carried state.
  3. Cut after an overflow flush: the state returned by the strip of the flushed run.
- The boundary scan's awaiting flag no longer decides any closure. It still decides the next
  run's verbatim flag and is carried only when no cut follows.
- Escape closure constant: CAN (0x18), next to `CSI_CLOSING`, documented with the FR4
  properties and IMPLEMENTATION.md D2. `CSI_CLOSING` is unchanged.
- Test accessors: `csi_phase()` keeps returning the CSI sub-state (none for any other
  state, SPEC as-05); a new test-only accessor returns the full written state.

### Cut flow (every path)
1. Determine the written end state at the cut, as listed above.
2. Write the closure for that state (at most one byte).
3. Set the carried state to Ground and clear the awaiting-designator flag.
4. Continue from ground with the next fed byte.

### term_core end-state oracle (tests)
- Classifies the end state of a byte stream into the five values using only term_core's
  observable behavior (displayed text, cursor, responses), by feeding probe continuations
  whose interpretation differs per state. A probe must not provoke a response and must not
  designate a charset that changes the glyphs being compared.
- Validated on reference streams before it is used: `abc` is Ground; `ESC`, `abc ESC` and
  `ESC[6 ESC` are Escape; `ESC (` and `ESC[6 ESC (` are Designator; `ESC [` is Csi(Entry);
  `ESC[6` and `ESC[?25` are Csi(Param).
- Used by R1 (after every cut-free call), R2 (its confirm column) and the new module. One
  definition is preferred; if the two test module trees each keep their own, both are
  validated on the same reference streams.
