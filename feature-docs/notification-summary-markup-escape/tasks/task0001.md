# Task Plan: task0001 — Escape notification summary at the D-Bus egress

## Goal

When the notification server confirms body-markup capability, the summary
(title) leaving `NotifyRustSink::send` has markup meta characters neutralized
exactly as the body already does; when the capability is unconfirmed, the
title passes through byte-for-byte unchanged (fail-open parity with the body
path).

## Requirements

FR1, FR2, FR3, NFR1, NFR2

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/callbacks.rs` — inside `NotifyRustSink::send`
  (`:148-174`), extend the existing capability-gated escape decision to the
  summary. The fix site is the unescaped summary-setting call at `:166`. The
  single per-send gate evaluation is reused for both summary and body
  (IMPLEMENTATION.md D2); the change stays inside the existing Unix-only
  conditional-compilation scope (D5).
- `src-tauri/src/callbacks/tests.rs` — new summary-escape unit tests beside
  the PR #35 body-escape tests they mirror (`:695`, `:707`, `:751`).

## Design

Reused components and their fixed contracts are pinned in IMPLEMENTATION.md
Shared Components (`escape_body_markup`, `body_markup_confirmed`,
`sanitize_title`) — none of them changes in this task.

Processing flow of `NotifyRustSink::send` after the change:

1. `send` receives title and body (producers have already applied
   `sanitize_title` to titles where applicable; this task does not touch the
   producers).
2. Inside the existing Unix-only scope, the per-send capability gate is
   evaluated once (one fresh capability query per send — unchanged from
   today; no second query is added).
3. Gate resolves "confirmed": the escape transform is applied to BOTH title
   and body before they are set as summary and body.
4. Gate resolves "unconfirmed": title and body are used byte-for-byte
   unchanged (fail-open, matching the current body behavior).
5. The notification dispatch call and its success/failure logging are
   unchanged; the Windows path (no capability query) is unchanged.

Path coverage (FR2): titles from `parse_osc9` (`src-tauri/src/callbacks.rs:681-693`)
via `handle_notify` (`:451-462`) reach this egress, including the fallback
branch (empty title segment → current tab title from untrusted OSC 0/2, or
`"emterm"`). Because the escape sits at the single egress, the other summary
producers (tab activity, agent status, link-hover) are covered without
per-producer changes (NFR1). Internal copies (`pending_notifications` at
`:454-457`, rate-limiter keys) keep the raw title (IMPLEMENTATION.md D4).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: With a confirmed capability list (contains `body-markup`), a
      title containing `&`, `<`, `>` (e.g. a tag-bearing `<a href>` title) is
      converted to entity references with `&` processed first — the same
      output the body path produces for the same input; double-escape of
      pre-existing entities is accepted, mirroring the pinned body behavior.
- [ ] AC-2: With an unconfirmed capability result (successful list without
      `body-markup`, or a failed fetch), the same title is left byte-for-byte
      unchanged through the sink's escape decision.
- [ ] AC-3: A title truncated by `sanitize_title` to 100 characters ending in
      `<` escapes to a complete trailing entity reference (escape happens
      after truncation; the entity is never split).
- [ ] AC-4: The OSC 9 fallback-title branch (empty title segment → tab title
      or `"emterm"`) produces a title that flows through the same escaped
      summary decision as an explicit title.
- [ ] AC-5: Existing PR #35 body-escape tests in
      `src-tauri/src/callbacks/tests.rs` pass unchanged — body escape order,
      capability gating, and fail-open behavior are byte-for-byte identical.
- [ ] AC-6: The summary escape exists only inside `NotifyRustSink::send`,
      within the existing Unix-only conditional-compilation scope;
      `sanitize_title`, the notification producers, and the Windows toast
      path are unmodified (the diff touches only the two files in Scope).

## Test Notes

- All criteria map to unit tests run by the approved command
  `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib`.
- The escape lives in the production sink, which unit tests cannot invoke
  against a real D-Bus connection. Mirror the existing composed-decision
  technique (`src-tauri/src/callbacks/tests.rs:751`, `:768`): exercise the
  gate + escape decision as a composition of `body_markup_confirmed` and
  `escape_body_markup` with injected capability results. If the escape
  decision is factored into a small testable unit inside `callbacks.rs` to
  avoid duplicating the decision in tests, that unit stays private to the
  egress (AC-6 still holds).
- AC-1 ↔ TS1/TS2, AC-2 ↔ TS2, AC-3 ↔ TS3 (compose `sanitize_title` output
  with the escape, mirroring `:707`), AC-4 ↔ TS4 (feed `parse_osc9` fallback
  output through the composed decision), AC-5 ↔ TS5 (existing suite,
  unmodified), AC-6 ↔ TS6/TS7 (inspection; see VERIFICATION.md).
- Edge cases worth covering: title consisting only of meta characters;
  fallback title `"emterm"` (no meta characters — escape is an identity
  transform, must not corrupt).
