# Task Plan: task0001 — Revise the target SPEC.md Test Scenarios to the implementation test names

## Goal

`feature-docs/mouse-report-held-callsite-test/SPEC.md` names the 25 test
functions that actually exist in `src-tauri/src/window_host/tests.rs`, under its
own existing TS IDs, so its Unit Tests section grep-resolves against the
implementation file.

## Requirements

FR1, FR5, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify

- `feature-docs/mouse-report-held-callsite-test/SPEC.md` — the "Test Scenarios >
  Unit Tests" bullets: each scenario's stale test name is replaced by the
  canonical name(s) for that TS ID (IMPLEMENTATION.md, "Canonical test-name
  assignment"). Nothing else in the document changes.

## Design

### What the document looks like now

The "Test Scenarios > Unit Tests" section holds six bullets, `TS-1` … `TS-6`.
Each bullet opens with one backticked identifier — the scenario's test name —
then a Japanese description of what the test does, then a
`（要件: … / AC: …）` annotation. All six of those identifiers are names that
were never written into `tests.rs`; each appears exactly once in the document.
The `TS-M1` bullet under "E2E Tests", the "Integration Tests" / "Edge Cases"
sections, and the Traceability tables carry no test-function name.

### What changes

Per TS ID, the opening identifier is replaced by that scenario's canonical
name(s):

| Target-document TS | Names to carry |
|---|---|
| TS-1, TS-2, TS-3, TS-6 | the one canonical name of that scenario |
| TS-4 | all 18 canonical names, enumerated |
| TS-5 | all 3 canonical names, enumerated |

For TS-4 and TS-5 a single opening identifier cannot carry the whole set, so the
bullet gains a nested enumeration of its names beneath the existing description.
That nested list is the only structural addition this task makes; heading
levels, bullet order, TS IDs and the `（要件: … / AC: …）` annotations stay as
they are.

The TS-4 entry for `sanity_the_fake_callee_pattern_matches_a_real_unquoted_call`
carries the role note required by IMPLEMENTATION.md's scaffold role-note
contract, written in the document's Japanese (NFR3).

### What must not change

- Every existing Japanese description, every TS ID, every
  `（要件: … / AC: …）` annotation, and the "Integration Tests", "E2E Tests"
  (including the `TS-M1` bullet), "Edge Cases" and Traceability sections.
- The document's references to production identifiers and to the pre-existing
  test `pointer_routing_handlers_hold_no_decision_only_delegate_to_the_seam`
  (IMPLEMENTATION.md, Conventions) — those are already correct.
- Any file other than this one (IMPLEMENTATION.md, decision D3).
