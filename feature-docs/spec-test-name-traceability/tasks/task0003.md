## Design

### What the document looks like now

Section 12.2 holds a four-column table — TS ID / テスト名 / 対応要件 / 対応AC —
with one row per target-document TS ID (`TS-1` … `TS-6`, then `TS-M1`). Each
`TS-1` … `TS-6` row's テスト名 cell holds one backticked identifier that was
never written into `tests.rs`; each appears exactly once in the document. The
per-scenario supplementary notes that follow the table reference TS IDs only and
contain no test-function name.

### What changes

Only the テスト名 cells of the `TS-1` … `TS-6` rows, replaced by the canonical
name(s) of each scenario (IMPLEMENTATION.md, "Canonical test-name assignment"):

| Target-document TS | Names the row carries |
|---|---|
| TS-1, TS-2, TS-3, TS-6 | the one canonical name of that scenario |
| TS-4 | all 18 canonical names |
| TS-5 | all 3 canonical names |

**Row set stays as it is** — one row per TS ID, in the existing order, with the
existing four columns (NFR3). A row carrying several names enumerates them
inside the テスト名 cell, each in its own backtick span, one per rendered line
(the repository already uses HTML line breaks inside table cells for this). The
対応要件 and 対応AC columns are untouched, and so is the `TS-M1` row.

The TS-4 entry for `sanity_the_fake_callee_pattern_matches_a_real_unquoted_call`
carries the role note required by IMPLEMENTATION.md's scaffold role-note
contract, written in the document's Japanese (NFR3). Where the note does not fit
the table cell, it goes into that scenario's existing supplementary note below
the table — which is the only case in which this task touches those notes.

### What must not change

- Section 12.1, the 対応要件 / 対応AC columns, the `TS-M1` row, every other
  section of the document, and the document's Japanese prose (NFR3).
- The document's references to production identifiers and to the pre-existing
  test `pointer_routing_handlers_hold_no_decision_only_delegate_to_the_seam`
  (IMPLEMENTATION.md, Conventions) — those are already correct.
- Any file other than this one (IMPLEMENTATION.md, decision D3).
