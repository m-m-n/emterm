# keycap クラスタ合成（単独到着結合文字の遡り合成） - 要件定義書

## 1. 概要

### 1.1 背景

- keycap 絵文字クラスタ `5️⃣`（U+0035 U+FE0F U+20E3）および `5⃣`（VS16 なし）が
  eMterm 上で「5」+「□（空キーキャップ）」の2セルに分解表示される
- 調査（tmp/keycap-cluster-investigation-2026-07-25.md）により機構を確定済み:
  - term_core の `handle_print` はグラフェムバッファ開始条件が
    `EXT_PICTOGRAPHIC | REGIONAL_IND` のみで、数字 base の keycap クラスタを組み立てない
  - 単独到着した幅0文字（VARIATION_SEL / COMBINING）はカーソル位置のセルを上書きし、
    後続文字でさらに上書きされて消える
  - keycap 固有ではなく、単独到着する結合文字全般（例: `e` + U+0301）が壊れている
  - renderer 側の keycap クラスタ対応（fallback ルーティング / presentation 判定）は
    実装済みだが、term_core がクラスタを1セルに入れないため機能していない
  - swash のシェーピングでは VS16 が keycap の GSUB リガチャを阻害する
    （`base + 20E3` の2文字定義に VS16 が挟まるとマッチしない）

### 1.2 目的

- keycap クラスタ（`<digit> [VS16] U+20E3`）を1クラスタとして合成し、
  keycap 絵文字グリフで描画する
- 単独到着する結合文字全般（é 等）の遡り合成を成立させる

### 1.3 スコープ

**対象**:

1. term_core: 単独到着した幅0文字（VARIATION_SEL / COMBINING）の遡り合成
2. renderer: 絵文字フォントへのシェーピング前の VS16 除去

**対象外**:

- 既存の grapheme_buffer 経路（ExtPict base）の変更
- はみ出し描画（overflow）ノブ（WezTerm 型3値ノブは将来課題）
- unicode_version 相当の幅設定ノブ（将来課題）

## 2. ビジネス要件

### 2.1 ビジネス目標

- AI-first 方針: Claude Code 等の AI ツールが出力する絵文字（keycap 含む）を正しく表示する

### 2.2 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| eMterm 利用者 | keycap 絵文字・結合文字を含む出力を閲覧する全ユーザー |

### 2.3 期待される効果

- keycap 絵文字が1グリフで正しく描画される
- 結合文字（アクセント付きラテン文字等）の欠落が解消される

## 3. ユースケース

### 3.1 ユースケース一覧

| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | keycap 絵文字の表示 | PTY 上のアプリケーション | 高 |
| UC02 | 結合文字の表示 | PTY 上のアプリケーション | 高 |

### 3.2 ユースケース詳細

#### UC01: keycap 絵文字の表示

**アクター**: PTY 上のアプリケーション（Claude Code 等）

**事前条件**:
- カラー絵文字フォントがロードされている

**基本フロー**:
1. アプリケーションが `5 FE0F 20E3` を出力する
2. term_core が `5` をセルに書く
3. 後続の FE0F / 20E3 が直前セルに遡り合成される
4. VS16 ありのためセルが幅2に遡り拡張される（隣セル spacer 化・カーソル1前進）
5. renderer がクラスタから VS16 を除去して絵文字フォントでシェーピングする
6. keycap 絵文字グリフが1つ描画される

**代替フロー**:
- VS16 なし（`5 20E3`）: 幅1のまま合成し、モノクロ含むフォント解決に従い描画する
- 行頭などで base セルが無い: 幅0文字を捨てる（グリッドに書かず、カーソルも進めない）
- base が全角セルの spacer 位置: spacer を跨いで base セルに付加する
- VS16 遡り拡張が行末セルで発生: 行送り（wrap）処理を行う

**事後条件**:
- グリッド上でクラスタ全体が base セル1つ（+ spacer）に格納されている

#### UC02: 結合文字の表示

**アクター**: PTY 上のアプリケーション

**基本フロー**:
1. アプリケーションが `e` U+0301 を出力する
2. term_core が `e` をセルに書く
3. U+0301 が直前セルに遡り合成される（幅1のまま、カーソル前進なし）
4. é として描画される

## 4. 機能要件

### 4.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | 幅0文字の遡り合成 | 単独到着した VARIATION_SEL / COMBINING を直前に書いたセルに追記する | 高 |
| F02 | VS16 連動の幅2遡り拡張 | VS16 を含むクラスタになったセルを幅2に拡張し、隣セルを spacer 化してカーソルを1進める | 高 |
| F03 | 全角 spacer 跨ぎ | 直前セルが全角の spacer の場合、base セルへ付加する | 高 |
| F04 | base 不在時の破棄 | 行頭など base が無い場合、幅0文字をグリッドに書かず捨てる | 高 |
| F05 | シェーピング前 VS16 除去 | 絵文字フォントへのシェーピング前にクラスタから VS16 を除去する（presentation 判定は除去前のクラスタで行う） | 高 |

### 4.2 機能詳細

#### F01: 幅0文字の遡り合成

**説明**: `write_grapheme_to_grid` で幅0（`char_width` = 0 の VARIATION_SEL /
COMBINING）の文字が単独到着した場合、現状の「カーソル位置のセルへの上書き」を廃止し、
「直前に書いたセル」の内容へ追記する。カーソルは進めない（F02 の拡張時を除く）。

**ビジネスルール**:
- keycap（`5 [FE0F] 20E3`）も é（`e 0301`）も同一機構で処理する
- Alacritty / xterm の遡り合成モデルと同型

#### F02: VS16 連動の幅2遡り拡張

**説明**: 遡り合成の結果クラスタに VS16（U+FE0F）が含まれる場合、base セルを幅2に
拡張する。隣セルを spacer 化し、カーソルを1進める。行末では wrap 処理を行う。

**ビジネスルール**:
- VS16 あり（カラー絵文字表示）→ 幅2
- VS16 なし（テキスト表示）→ 幅1のまま
- `flush_grapheme_buffer` の既存規則（VS16 → 幅2）と一致させ、内部方針を統一する

#### F05: シェーピング前 VS16 除去

**説明**: swash は default-ignorable な VS をリガチャマッチ時にスキップしないため、
VS16 が挟まると keycap の GSUB リガチャ（`base + 20E3`）が成立しない。絵文字フォントへ
シェーピングする前にクラスタから VS16 を除去する。フォント選択（presentation 判定）には
除去前のクラスタを使う。

## 9. 制約条件

### 9.1 技術的制約

- wcwidth 系アプリ（zsh 行編集 / nvim 等）は keycap を幅1計算するため、幅2化により
  カーソル同期がズレる場合がある。本タスクでは幅2を採用し、設定ノブは将来課題とする
- swash 0.1.18 のシェーピング挙動（VS16 のリガチャ阻害）を前提とする

## 10. 想定される課題とリスク

## 13. 用語定義

| 用語 | 定義 |
|------|------|
| keycap クラスタ | `<base(0-9 * #)> [U+FE0F] U+20E3` のグラフェムクラスタ |
| VS16 | U+FE0F VARIATION SELECTOR-16。絵文字表示を要求する |
| 遡り合成 | 単独到着した幅0文字を直前に書いたセルへ追記すること |
| spacer | 全角（幅2）セルの右隣を占有するプレースホルダセル |
