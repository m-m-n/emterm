# Task Plan: task0002 — strip VS16 before emoji font shaping

## Goal

Clusters routed to the color emoji font are shaped without VS16 (U+FE0F), so
the keycap GSUB ligature (`base + 20E3`) matches and 5️⃣ renders as a single
composed glyph.

## Requirements

FR5, NFR1

## Scope

### Files to Create

(none)

### Files to Modify

- `src-tauri/src/render/terminal_grid_pass.rs` — the two shaping call sites
  (`glyph_instance` and the prewarm/secondary site) feed a VS16-stripped
  cluster to the shaper when the resolved font is the emoji font; unit tests
- `src-tauri/src/render/font/fallback.rs` — if the stripping helper is
  better placed next to the routing decision, it may live here; existing
  routing tests must keep passing unchanged
- `src-tauri/src/render/font/presentation.rs` — no behavioral change
  expected; touched only if the VS16-detection helper is shared from here

## Design

### Current behavior (defect)

The grid pass shapes `cell.glyph` verbatim and uses only the first shaped
glyph. With VS16 inside the cluster, swash fails the keycap ligature match
(it does not skip default-ignorable variation selectors), decomposing the
cluster; the first glyph is then wrong (e.g. the emoji font's "5").

### Target behavior

1. Font selection is UNCHANGED: presentation / fallback decisions operate on
   the full cluster including VS16 (contract in IMPLEMENTATION.md — task0001
   guarantees VS16 is preserved in the cell).
2. When the selected font is the color emoji font, the string passed to the
   shaper is the cluster with every U+FE0F removed.
3. When the selected font is not the emoji font, shaping input is unchanged
   (VS15/text-presentation flows are untouched).
4. Both shaping call sites in the grid pass go through the same stripping
   decision (single helper — no divergence between the main and secondary
   sites).

### Notes

- Rationale (from the 2026-07-25 investigation): with bundled fonts,
  `5 20E3` shapes to a single ligature glyph while `5 FE0F 20E3` decomposes;
  Noto-COLRv1 lacks a cmap entry for FE0F entirely (.notdef pollution).
- The existing accidental-correctness case (⚠️ = U+26A0 + FE0F working via
  `shaped.first()`) must keep rendering correctly after stripping.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: For an emoji-font-routed keycap cluster (`5 FE0F 20E3`), the
      string handed to the shaper contains no U+FE0F.
- [ ] AC-2: Shaping the stripped keycap cluster with the bundled emoji font
      yields a single glyph (ligature match), and that glyph is what the
      grid pass uses.
- [ ] AC-3: Font selection for the keycap cluster still resolves to the
      color emoji font using the cluster INCLUDING VS16 (existing
      presentation/fallback tests pass unchanged).
- [ ] AC-4: A non-emoji-routed cluster's shaping input is byte-identical to
      the cell content (no stripping outside the emoji path).
- [ ] AC-5: An ExtPict + VS16 cluster (e.g. U+26A0 U+FE0F) still renders its
      emoji glyph after stripping.
- [ ] AC-6: All pre-existing render/font tests pass unchanged.

## Test Notes

- AC-1/AC-4 are pure unit tests on the stripping decision (cluster in,
  shaper input out) using the existing mock-rasterizer test patterns in
  terminal_grid_pass.rs.
- AC-2/AC-5 shape against the real bundled fonts via the swash adapter,
  following existing font-loading test patterns in the render/font module.
- AC-3/AC-6 are the regression gates: run the main crate lib test suite.

## Out of Scope

- term_core grid content (task0001).
- Overflow/oversize glyph drawing knob.
- Any change to font fallback ordering or presentation semantics.
