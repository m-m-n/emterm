### 1. The EC1 scroll-path test (FR1, FR2, FR3)

Subject: the test currently named
`test_relocate_widened_base_via_wrap_scrolls_without_panic_or_stale_entries`
at `crates/term_core/src/print_handler/tests.rs:1559`, with its leading

What the test can actually observe: it writes only four ASCII letters and
performs one variation-selector merge, none of which exceeds the 16-byte
inline cap, so the overflow table is empty for the test's entire run. Its two
absence-of-overflow-entry assertions are therefore true independently of the
code under test.

Required end state:

| Leading comment | States (a) what the test proves — the relocation's own line feed may scroll the viewport, and the relocated base plus spacer must land on the resolved row without panicking or reading out of range; and (b) why it proves nothing about overflow cleanup, citing the mechanism of IMPLEMENTATION.md D2. ### 2. The new eviction-clearing test (FR4)

Subject: `ring_push_blank`'s clearing of the recycled slot's overflow table
and reverse index. Placed in `crates/term_core/src/ring_buffer/tests.rs`
beside `test_ring_push_blank_clears_ridx` (line 417) because the unit under
test is the ring buffer, not the print handler.

Name: `test_ring_push_blank_clears_recycled_row_overflow_entries`.

Fixture and flow — no relocation, no scroll region, no variation selector
anywhere in it:

1. Construct a 5-column, 2-row terminal with scrollback capacity zero, so the
   scroll takes the scrollback-disabled eviction branch.
2. Populate viewport row 0, columns 0 and 1, each with content that stays
   width 1 but exceeds the 16-byte inline cap — a base character followed by
   a long run of combining marks. Mirror the fixture shape already used at
   `print_handler/tests.rs:1457-1472`, driving the cells through the same
   printing/PTY path those tests use rather than by direct cell mutation.
3. Capture the absolute (ring slot) row key of viewport row 0.
4. **Pre-assert**: the overflow table holds an entry for column 0 and for
   column 1 on that row key, and the reverse index for that row key holds
   both column numbers. A fixture that fails here is not overflow-bound and
   would make the test vacuous — this pre-assertion is what prevents
   repeating the defect being fixed.
5. Place the cursor on the last row and emit a plain line feed, so the
   full-screen scroll path runs `ring_push_blank` and recycles the captured
   slot.
6. **Post-assert**: neither column's entry remains in the overflow table for
   that row key, and the reverse index no longer holds the row key at all.

Leading comment: names the AC / requirement IDs it covers and states that it
pins the eviction-time clearing directly, with no relocation involved.
Per IMPLEMENTATION.md D4 it must not claim the property was previously
unpinned.

## Test Notes

- **This task's product is tests.** The TDD cycle applies inverted: for AC-3
  the red state is produced by the mutation of step 3 (temporarily removing
  production behavior), not by writing a test before an implementation.
  Capture the failure message during that window — it is required record
  content and cannot be reconstructed afterwards.
- **Guard against repeating the defect.** The new test's pre-assertion is the
  anti-vacuity guard: if the fixture's content does not exceed the inline cap,
  the pre-assertion fails and the test cannot silently become vacuous. Do not
  weaken or delete that pre-assertion to make the test pass.
- **Two tests going red is expected** during the mutation window
  (IMPLEMENTATION.md D4). Do not "fix" `test_ring_push_blank_clears_ridx`,
  and do not treat its failure as a scope expansion.
- **Restore before finishing.** Verify the production freeze by inspecting the
  diff, not by memory: the mutation of step 3 touches a production file, and
  AC-5 is the check that it left nothing behind.
- **Module-level imports** in `ring_buffer/tests.rs` may need extending for
  the new test's fixture; that stays inside the file already in scope.
- **Determinism**: the new test builds its own terminal instance and touches
  no process-global state, so it stays parallel-safe under the default
  harness (NFR3).
- **Both documentary criteria** (AC-6, AC-7) are verified by review rather
  than by an automated test; record them in the new tests.yaml with an empty
  test list and a reason, matching the existing record's convention for
  criteria with no test projection.
