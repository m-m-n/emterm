# Task Plan: task0002 — Reword the upgrade test comment about the pane-level read check

## Goal

The comment in `src-tauri/src/mux/upgrade/tests.rs` that says the pane-level
test proves the read side "deterministically" is reworded. It now describes
the bounded read-until-marker check that the pane-level test performs.

## Requirements

## Design

### Current state (for orientation)

The comment sits inside
`snapshot_then_restore_round_trips_scrollback_and_the_restored_pane_is_writable`,
just before the restored pane is written `after-restore` plus a newline. It
says the restored pane is still writable through its adopted master. It also
says the pane-level test
`from_restored_pane_can_write_and_read_through_its_adopted_master`
"additionally proves the read side deterministically, without a background
reader thread in the way".

### Required content of the reworded comment

The comment describes the pane-level test as its Shared Components contract
in `IMPLEMENTATION.md` defines it ("Read-back check of the target test"),
together with decisions D1 and D2:

- It keeps the AC-5 statement that the restored pane is still writable
  through its adopted master.
- It still names `from_restored_pane_can_write_and_read_through_its_adopted_master`
  (the name is unchanged) as the test that additionally checks the read side.
- It describes that check as reading the echo back through a reader cloned
  from the master before hand-off, and accumulating until the marker arrives
  or a bounded deadline passes.
- It may say that no pane reader thread competes for the echo. It must not
  say that the pane-level test has no background reader thread at all,
  because that test now reads on a helper thread of its own (D1).
- It contains no form of the word "deterministic" and does not describe the
  check as a single read.

Only the comment changes. The test's code, assertions and the write call stay
as they are.
