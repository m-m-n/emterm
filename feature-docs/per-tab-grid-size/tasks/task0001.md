# Task Plan: task0001 — Active-tab-only resize routing and activation reconcile

## Goal

`App` routes every grid-size trigger to the active tab only and reconciles a
tab's size at the moment it becomes active, so inactive tabs' PTYs receive no
TIOCSWINSZ and their cores are never resized behind the user's back.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3

## Design

Cross-task contracts (the `Tab::resize` postconditions, the tab grid-dims
source of truth, the `App::cell_size` invariant, and the invalidation
ownership split) are pinned in IMPLEMENTATION.md — implement against them;
do not restate or re-derive them.

### 1. `App::set_grid_size` becomes active-tab-only (FR1, FR2, FR5)

Responsibility after this task:

1. Clamp the incoming dims with the wire-domain clamp BEFORE any comparison
   or recording (unchanged — IMPLEMENTATION.md D4).
2. Early-return when the clamped dims equal the current `cell_size`
   (display area unchanged — per-tab divergence is the reconcile's job, not
   this method's).
3. Record `cell_size`.
4. Detect a column-count change from the ACTIVE tab's pre-resize column
   count (post-fix invariant: active tab dims == old `cell_size`, so either
   source agrees; the active tab's core is the authoritative read).
5. Resize ONLY the active tab via `Tab::resize`.
6. On a column-count change, clear the app-level trackers (selection,
   pending selection anchor) only. Do NOT call the tab-level clear method —
   the tab clears its own prompt/fold trackers inside its resize
   (IMPLEMENTATION.md D3). Remove the all-tabs clearing loop.
7. Search-overlay buffer-dirty marking and the full-redraw request stay as
   they are (they concern the active, rendered tab).

Update the method's doc comment — it currently documents "propagate to all
PTYs", which becomes false.

### 2. Activation reconcile (FR3, FR4)

One reconcile responsibility, invoked from EVERY path that changes which tab
is active (IMPLEMENTATION.md D2):

- explicit tab switch (`switch_to_tab`),
- the close-tab active-index fix-up,
- the exited-tab reap active-index fix-up.

Behavior: compare the now-active tab's core dims against `cell_size`; if
they differ, resize that tab via `Tab::resize` with `cell_size` dims; if
equal, issue nothing at all. The reconcile runs AFTER the path's existing
activation bookkeeping (scroll restore, search close, selection clearing) so
it operates on the committed active tab. No-op guards in `switch_to_tab`
(same index / out of range) must stay before any reconcile.

Newly-spawned tabs (initial and additional) are already created at
`cell_size` dims — no reconcile call is added to spawn paths. `reorder_tab`
keeps the same logical tab active — no reconcile there either.

For mux tabs, no frame-specific handling is written here: restricting who
gets `Tab::resize` IS the FR4 rule (IMPLEMENTATION.md D1).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (TS1): with two or more tabs, a grid-size change alters only the
      active tab's core dims; an inactive tab's core reports its prior dims
      afterward. (FR1, FR2)
- [ ] AC-2 (TS2): activating a tab whose dims differ from the current
      display area resizes it exactly at activation time; activating a tab
      whose dims already match issues no resize (dims unchanged and no
      tracker invalidation occurs). (FR3)
- [ ] AC-3 (TS2): the close-tab and exited-tab-reap active-index fix-ups
      also reconcile the newly-active tab's size. (FR3)
- [ ] AC-4 (TS5): a width-changing resize of the active tab clears the App
      selection and pending selection anchor; a height-only change keeps
      them; an inactive tab retains its prompt/fold marks across another
      tab's width change. (FR6)
- [ ] AC-5 (TS4): with an inactive mux-flavored tab present (mux session
      name and pane group seeded), a grid-size change leaves that tab's core
      dims unchanged — no `Tab::resize` invocation, hence, per the pinned
      `Tab::resize` contract, no pane `Resize` frames for it. (FR4)
- [ ] AC-6 (TS3): an out-of-wire-domain request still records clamped dims
      in `cell_size`, agreeing exactly with the active tab's core
      (`set_grid_size_clamps_cell_size_to_agree_with_the_core` stays
      green). (FR5)
- [ ] AC-7 (TS6): the full `--lib` suite passes with the enumerated test
      updates justified in test comments (NFR2), and the CLI
      `--no-default-features` check compiles (NFR3).

## Test Notes

- AC-1..AC-6 are app.rs unit tests (inline `#[cfg(test)]`), driven through
  the public App surface (`spawn_initial_tab` / `spawn_new_tab`,
  `set_grid_size`, `switch_to_tab`, close/reap paths) and observed through
  tab core dims and tracker state — the same style as the existing
  `set_grid_size` tests.
- AC-5's mux-flavored tab can be seeded through the tab's public mux fields
  or by feeding a mux welcome control message through the tab's
  message-apply path, whichever is cheaper — the assertion is only "core
  dims unchanged".
- AC-4's "inactive tab retains prompt/fold marks" holds in this task's own
  worktree regardless of the sibling task (an inactive tab is never resized,
  so nothing can clear its trackers). The positive clearing assertion for
  the resized tab's own prompt/fold marks is deliberately NOT in this task —
  it is the tabs.rs task's responsibility (D3).
- Run tests with the project command:
  `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib -- --test-threads=1`.
