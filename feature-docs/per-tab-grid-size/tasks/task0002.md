# Task Plan: task0002 — Tab-owned reflow invalidation and pinned resize contract

## Goal

`Tab::resize` becomes fully self-contained per the shared contract: the tab
clears its OWN reflow-invalidated trackers when its column count changes,
while the wire-domain clamp and the mux pane `Resize` frame emission are
preserved exactly as pinned — making per-tab correctness independent of who
triggers the resize.

## Requirements

FR1, FR4, FR5, FR6, NFR2, NFR3

## Scope

### Files to Create

- (none)

### Files to Modify

- `src-tauri/src/tabs.rs` — `Tab::resize` (~3626-3712) gains the
  self-invalidation postcondition; new tests in the inline test module
  (existing clamp tests at ~6117 and ~6146 stay green).

## Design

Cross-task contracts (the full `Tab::resize` postcondition set (a)-(e), the
tab grid-dims source of truth, and the invalidation ownership split) are
pinned in IMPLEMENTATION.md — implement against them; do not restate or
re-derive them.

### 1. Self reflow-invalidation on width change (FR6 — contract (c))

Inside the resize flow:

1. Read the core's pre-resize column count before the core is resized.
2. Apply the wire-domain clamp and the core/PTY resize exactly as today
   (contracts (a), (b) — behavior-preserving).
3. If the post-clamp column count differs from the pre-resize column count,
   the tab invokes its own existing `clear_reflow_invalidated_state` after
   the core resize. A height-only change, or a raw request that clamps back
   to the same column count, clears nothing.

The comparison uses POST-CLAMP dims — a caller passing an out-of-domain
width that clamps back to the current width is not a width change.

### 2. Behavior explicitly preserved (contracts (a), (b), (d), (e))

- The clamp stays where it is, applied before any effect (FR5,
  IMPLEMENTATION.md D4 — do not move, remove, or "unify" it with the
  app-side clamp).
- The mux pane `Resize` frame block stays the ONLY emission site, emitting
  post-clamp dims for every pane in the tab's group, still positioned after
  the core/PTY resize. No new emission site, no duplication, no relocation
  (IMPLEMENTATION.md D1).
- The pending off-thread-switch deferred-resize logic and the pending
  scrollback-restore cancellation are untouched. Self-invalidation keys off
  the visible-core resize event happening in this method — the deferred
  application at swap time is core-internal and out of this task's reach.

## Test Notes

- AC-1..AC-3 are new tabs.rs unit tests built on the existing `test_tab`
  helper: seed a prompt mark and a fold region on the tab (both trackers are
  tab-owned and reachable from the tabs.rs test module, mirroring the
  seeding the app.rs tests do today), resize, assert tracker state.
- Direct capture of emitted pane `Resize` frames is impractical in unit
  tests (control frames are written into a live PTY session), so FR4's frame
  rule is verified compositionally: this task preserves the single emission
  site inside `Tab::resize` (review-verifiable, no functional change
  intended), the app-side task proves non-invocation for inactive tabs, and
  the manual TS7 scenario covers the end-to-end absence of leaked
  fragments. Do NOT add a PTY capture seam for this — not required.
- Run tests with the project command:
  `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib -- --test-threads=1`
  (the replay tests in this file flake under parallel execution).
