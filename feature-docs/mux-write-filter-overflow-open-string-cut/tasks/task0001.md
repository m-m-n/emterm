# Task Plan: task0001 — Open string body in the written state and its ESC + CAN closure at a cut

## Goal

The scrollback write filter's written end state distinguishes an open OSC body
and an open ST-terminated (DCS / APC) body from ground, and every cut that
finds the written stream in one of them writes `ESC` + CAN, so a ring replay
after an overflowed string matches what the client saw.

## Design

This task implements every Shared Component of IMPLEMENTATION.md and decisions
D1-D4; they are referenced here, not restated.

### State model (shared strip module)

- The per-byte advance gains the transitions of SPEC.md "Written-state
  transitions for string bodies": from Escape, `]` enters the open OSC body
  and `P` / `_` enter the open ST-terminated body; in the OSC body BEL returns
  to ground; in either body `ESC` moves to Escape; every other byte keeps the
  body. Escape followed by `\` already returns to ground (ST completed), and
  Escape followed by any other byte already behaves as from Escape, so the
  string-abort rule needs no state of its own.
- Unchanged: the Designator state consumes any byte (a designator never opens a
  body); the CSI transitions; `ESC X` / `ESC ^` complete an escape (term_core
  has no SOS / PM string, IMPLEMENTATION.md D1).
- Every written byte advances the state, including the C0 bytes re-emitted
  from a removed CSI device query (a re-emitted BEL ends an OSC body, as it does
  on replay of the ring); a removed byte advances nothing. The strip's removal
  decisions and output bytes do not read the state (NFR2).
- The CSI sub-state accessor reports nothing for a body state, as for every
  other non-CSI state.

### Closure at a cut (write filter)

- The closure decision maps both body states to the string-body closure
  (IMPLEMENTATION.md D2). No cut path needs its own logic: each path already
  consults the state SPEC.md "Closure at a cut" names, and that state now
  carries the body.

| Cut path | State consulted (already, today) |
|----------|----------------------------------|
| Cut inside the call | The strip-reported state of the run before the cut, the dropped chain excluded |
| Cut at an empty segment, reader's fallback closing | The carried state |
| Cut after an overflow flush in the same call | The strip-reported state of the flushed run |
| Cut / fallback closing dropping a held live lone `ESC` | The carried state stored with the held `ESC`, which is the state of the bytes written before it |

- Postcondition of every cut: the written state is Ground, no designator is
  awaited, and exactly one closure was written for that cut.

### Overflow branch

- The hold decision is unchanged (FR4): the run's final `ESC` is still advanced
  from the strip-reported state, and from either body state it leaves Escape,
  so it is held as a chain of one construct. The state stored with it is now
  the body state; this follows from the extended model and needs no extra
  path. The flushed run is still stripped once (NFR1).
- The overflow-branch comments that say a string body counts as ground are
  rewritten (FR7).

### End-state oracle (test support)

- The existing probes classify a body as Escape (both `m` and `[m` are
  absorbed). In that branch, a `\` + `m` probe separates them: after Escape the
  backslash completes an escape and `m` is displayed; inside a body both are
  data. A BEL + `m` probe then separates the bodies: BEL ends an OSC body and
  `m` is displayed; in a DCS / APC body both are data.
- The oracle still asserts that no probe provokes a response, so the streams
  given to it open string bodies whose completion or abort answers nothing (an
  OSC 0 title, a DCS / APC that term_core does not answer).
- The helper that produces the bytes entering a given state gains inputs for
  the two body states, under the same no-answer constraint.

### Regression module

- The new module reuses the existing helpers of its sibling modules (the OSC
  held at the cap, view_after_a_cut, view_of, text, switch_pairs,
  run_reader_without_owner, DIMS, and the strip-target constants) without
  modifying them. DCS and APC runs held at the cap are built in the new module.
- It is declared in the pty_spawn test module list right after the
  predecessor's module, with a one-line comment naming this feature and FRs.

### Rule for an unforeseen failing test (IMPLEMENTATION.md D3)

When an existing test outside this task's files fails only because a cut now
writes `ESC` + CAN after written bytes that end inside an open body, or because
a state assertion now sees a body state, confirm with the oracle or
view_after_a_cut that the new bytes replay like the client, update that
expectation, keep the test's name, and report the test and its file as a plan
deviation. Any other failure is a defect in the production change.

### Why one task

The ten criteria below exceed the usual size, but the production change and
its tests only pass together: a split would leave a task whose tests cannot
pass in its own worktree.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, NFR2; TS-9): The state-reporting strip reports the open OSC body after a written `ESC ]` and body bytes, the open ST-terminated body after a written `ESC P` or `ESC _` and body bytes, Ground after a BEL written in an OSC body, the ST-terminated body after a BEL written in a DCS / APC body, Escape after a body's written `ESC`, Ground after a written `ESC \`, and the carried-in body state unchanged across a construct it removes. For the same input its written bytes are identical whatever state is carried in, the body states included. Every new row is confirmed by the extended end-state oracle, and the oracle's existing reference streams keep their classification.
- [ ] AC-2 (FR2, FR4, FR5, TM-1; TS-2): With the OSC held at the cap and call 1 = body bytes + `ESC`, exactly one `ESC` is held and the written state is the open OSC body. The reader's fallback closing then writes exactly `ESC` + CAN, leaves `pending` empty, the written state Ground and no designator awaited, and a second fallback closing writes nothing. In a separate run, a call carrying a cut at fed 0 followed by plain text writes `ESC` + CAN then the text, with `pending` empty and the state Ground. For each 47 / 1047 / 1049 pair, the replay of each run's written bytes plus a later plain-text call equals view_after_a_cut of the raw stream, and the text is displayed.
- [ ] AC-3 (FR2, FR3, FR5, TM-1; TS-3): An overflow run that ends in plain OSC body bytes (no trailing `ESC`) holds nothing and leaves the open OSC body state. A cut at fed 0 of the next call and the fallback closing each write `ESC` + CAN, and the replay with later plain text equals view_after_a_cut for each switch pair. An overflow flush followed by a cut in the same call, the run ending inside the body (the input the round4_designator_cut open-OSC case used), writes the write-path strip of the run followed by `ESC` + CAN, holds nothing and leaves Ground.
- [ ] AC-4 (FR1, FR2, TM-1; TS-4): For a non-strip-target DCS, a non-strip-target APC, a Kitty APC and a SIXEL DCS, each held at the cap and flushed open past it, the written state is the open ST-terminated body; a cut writes `ESC` + CAN and the replay equals view_after_a_cut for each switch pair. A later call that writes a BEL (and plain bytes) inside such a body keeps the ST-terminated body state, and a following cut still writes `ESC` + CAN.
- [ ] AC-5 (FR3; TS-5): After an overflow leaves an open OSC body, a later call of plain bytes keeps the body state and a following cut writes `ESC` + CAN; a later call that writes a BEL, and one that writes `ESC \`, each return the state to Ground and a following cut writes nothing; a later call that writes an `ESC` followed by `[` leaves the CSI state and a following cut writes DEL.
- [ ] AC-6 (FR4, FR6, TM-2; TS-6): In overflow_lone_esc.rs the `endings()` entry 'inside an open string body' expects the open OSC body state and the `ESC` + CAN closing, and the fallback-closing test's doc comment states that closing. Every overflow_lone_esc test passes, including: exactly one `ESC` held after call 1 for that ending; every strip-target continuation after that ending removed, with the written totals equal to the reference feeding; a `\` continuation written as `ESC \`, leaving Ground. In round4_designator_cut.rs the open-OSC case leaves `round4_overflow_flush_then_a_cut_without_a_wait_writes_nothing_extra`, whose two other cases are unchanged. No existing test is renamed.
- [ ] AC-7 (FR2, FR6, TM-1; TS-1): Through the production reader (`run_reader_without_owner`), reads grow an `ESC ]0;` OSC past the cap, the read that crosses the cap ends in `ESC`, and the next read begins with a 47 / 1047 / 1049 `h` ... `l` pair followed by main-buffer plain text. The ring holds the string-body closure once, term_core replaying the ring displays that text, and its view (rows, cursor, responses) equals the reference (term_core fed the raw stream).
- [ ] AC-8 (FR5, TM-2; TS-10): The string-body closure is the two bytes `ESC`, CAN, distinct from the other three closures. For streams ending inside an open OSC, DCS or APC body, the stream followed by the closure ends in Ground per the oracle, and probe text after it (including `[6n`, `\` and BEL-terminated text) replays as view_after_a_cut of the stream closed by a switch pair, with no response. Neither the write-path strip nor the snapshot-time strip reads the closure as the start of a strip target or as ST, and a strip target written right after the closure is still removed.
- [ ] AC-9 (NFR1, NFR2, NFR3, NFR4, NFR5; TS-7, TS-11): The full `--lib` suite passes with no existing expectation changed beyond AC-6 (or one handled and reported under the Design rule for an unforeseen failing test). The `--no-default-features` cargo check succeeds. The diff leaves the cap value, the overflow warning log, live forwarding, the snapshot-time strip and the reader's cut derivation unchanged; the added state is O(1), the strip stays one pass, and the overflow branch strips each flushed run once.
- [ ] AC-10 (FR7; TS-8): The doc comments FR7 lists (the WrittenState doc, the escape-state comment in its advance, the closure_for and ESCAPE_CLOSING docs, the "Overflow" and "Closure at a cut" paragraphs of feed_with_cuts, the overflow-branch comments), the written-state field doc and the cut-branch comments that enumerate the closures state the open-body states and the `ESC` + CAN closure; none states that a string body counts as ground or that a cut writes at most one of two closures.
