# Task Plan: task0002 — D2-repair call-site documentation truthfulness

## Goal

Make the wide-pair blanking primitive's documentation in the cell layer
enumerate exactly the set of paths that perform the D2 repair after this
feature, so a reader cannot conclude that an uncovered print path is covered
or that a covered one is not.

## Requirements

FR5, NFR2

## Scope

### Files to Create

None.

### Files to Modify

- `crates/term_core/src/terminal_cells.rs` — the doc comment on the wide-pair
  blanking primitive: its enumeration of D2-repair call sites. Nothing else in
  this file changes — no executable code, no signature, no test.

## Design

The authoritative post-change call-site set is IMPLEMENTATION.md decision
D-2. This task transcribes that set into the primitive's doc comment; it does
not survey the code to derive its own set, and it does not need to read any
other task's plan. IMPLEMENTATION.md "Shared Components" carries the
primitive's contract, which the doc comment's existing behavioural
description (self-guarding, no-op on unresolvable positions or on widths
other than 0 and 2, preserves attributes, clears the overflow entry) already
matches and must keep matching.

Two properties the rewritten enumeration must have:

- **Complete and exclusive**: every path that reaches the primitive after this
  feature appears, and no path that does not reach it appears. The dispatch
  ASCII fast path is the entry this feature adds, and it must be named
  distinctly from the print path's own ASCII writer — the two are different
  code paths for the same byte, and conflating them is the exact confusion
  that let the gap survive.
- **Self-contained**: a reader determines the set from the comment itself. The
  current text defers to an external `IMPLEMENTATION.md` "Shared Components"
  section; that pointer is a feature-local document that will not stay
  adjacent to the crate, so the comment must not depend on it to convey which
  paths are covered. Keep such a pointer only if the comment is already
  complete without it.

The comment stays a prose enumeration. No fenced code block is introduced (a
code block in a doc comment invites doctest treatment and adds no value
here).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR5): The primitive's doc comment enumerates every D2-repair call
      site listed in IMPLEMENTATION.md D-2 — the print path's grapheme writer
      (pre-overwrite and pre-placeholder), the print path's ASCII writer, the
      widened-base relocation-by-wrap step, the PTY-dispatch ASCII fast path,
      the ICH/DCH edge repair, and the range-erase edge repair — with the
      dispatch fast path named distinctly from the print path's ASCII writer.
- [ ] AC-2 (FR5): The enumeration names no path that does not reach the
      primitive, and a reader can determine the complete set from the comment
      alone, without opening a file outside the crate.
- [ ] AC-3 (NFR2): The diff for this task touches comment text only — no
      executable statement, signature, visibility, test, or manifest is
      modified — and the term_core library suite plus the CLI-only check still
      pass.

## Test Notes

- FR5 has no automated scenario in SPEC.md; it is verified by inspection
  during review against IMPLEMENTATION.md D-2, and the verification plan
  records it as an inspection item. Do not invent a test that asserts on
  comment text.
- AC-3 is proven by running the term_core library suite and the CLI-only
  check unchanged-green, plus a read of the task's own diff confirming it is
  comment-only.
- No new test is added by this task; the existing behavioural tests for the
  primitive already cover its contract and must stay untouched.

## Out of Scope

- `crates/term_core/src/terminal_dispatch.rs` and
  `crates/term_core/src/print_handler.rs` — task0001 owns both.
- Changing the primitive's behaviour, signature, visibility, or its
  behavioural description (as opposed to its call-site enumeration).
- Updating doc comments on the ICH/DCH or range-erase call sites, or any other
  documentation in the crate.
- Rewording the enumeration in a way that changes the described contract of
  the primitive itself.
