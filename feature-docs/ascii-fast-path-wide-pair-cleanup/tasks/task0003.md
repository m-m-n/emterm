# Task Plan: task0003 — D2-repair call-site enumeration completeness (VS16 lazy-widening path)

## Goal

Make the wide-pair blanking primitive's call-site enumeration in the cell
layer true again: it currently claims to list every path that reaches the
primitive ("and no others") while omitting the print path's VS16
lazy-widening step, so a reader concludes that an actually-covered path is
not covered and that the listed set is complete when it is not.

## Requirements

FR5, NFR2

## Scope

### Files to Create

None.

### Files to Modify

- `crates/term_core/src/terminal_cells.rs` — the doc comment on the wide-pair
  blanking primitive (`blank_wide_pair_half`): its enumeration of D2-repair
  call sites only. No executable statement, no signature, no visibility, no
  test in this file changes.

## Design

### The defect

The enumeration in the primitive's doc comment has six items and asserts it
is exhaustive. Measured against the crate, one originating path is absent:
the print path's variation-selector-16 (VS16) lazy-widening step, which
retroactively widens an already-written width-1 base cell to width 2 and then
writes the pair's spacer at the next column, performing the rule-R3
pre-placeholder repair before that spacer write
(`print_handler.rs`, `widen_after_merge`, the pre-spacer repair call around
line 387).

The enumeration's third item — the widened-base relocation-by-wrap step —
covers only the last-column relocation branch (`relocate_widened_base_via_wrap`,
`print_handler.rs` from line 423), not its parent's ordinary branch. The two
are different steps: the relocation branch runs only when the widened base sits
in the row's last column with auto-wrap on; the ordinary branch runs in every
other VS16 widening, which is the common case.

### Authoritative post-rework call-site set

This is the enumeration this task makes true in the doc comment. It is stated
here in full so this task is implementable from this plan alone. It supersedes,
for the purposes of this task, the six-item enumeration in IMPLEMENTATION.md
decision D-2, which carries the same omission (D-2 is the drift source; see Out
of Scope).

The primitive is reached from exactly these originating paths:

1. the print path's grapheme writer — before an overwrite (rules R1/R2) and
   before writing a wide-pair placeholder (rule R3);
2. the print path's ASCII writer — before an overwrite (rules R1/R2);
3. the print path's VS16 lazy-widening step — before writing the spacer that
   a retroactively widened width-1 base requires (rule R3);
4. the print path's widened-base relocation-by-wrap step, taken when that
   widening happens in the row's last column — before the relocated base's
   overwrite at the next row's first column (rules R1/R2) and before the
   relocated spacer's write at the following column (rule R3);
5. the PTY-dispatch ASCII fast path's write step — before an overwrite
   (rules R1/R2); a distinct code path from item 2, for the same byte;
6. the ICH/DCH edit path's edge repair;
7. the range-erase edge-repair chokepoint.

Items 1-5 reach the primitive indirectly, through the two shared repair
entry points (the orphan-neighbour repair for rules R1/R2 and the
orphaned-base repair for rule R3); items 6 and 7 call it directly. The
enumeration is written in terms of the originating paths, not of the two
intermediate entry points, because a reader asking "is my write path
repaired?" is holding an originating path.

### Properties the rewritten enumeration must keep

- **Complete and exclusive**: every originating path that reaches the
  primitive appears; no path that does not reach it appears. If the code
  disagrees with the seven items above at implementation time, the code wins
  and the divergence is reported as a plan deviation rather than silently
  encoded.
- **Distinguishing**: the dispatch ASCII fast path stays named distinctly
  from the print path's ASCII writer, and the VS16 lazy-widening step stays
  named distinctly from the relocation-by-wrap step it can delegate to.
  Conflating either pair is what let the omission survive.
- **Self-contained**: the reader determines the set from the comment alone,
  without opening a file outside the crate.
- **Unchanged elsewhere**: the comment's behavioural description of the
  primitive (self-guarding, no-op on unresolvable positions and on widths
  other than 0 and 2, attribute preservation, overflow-entry removal, row
  dirtying) and the D2 invariant statement are not reworded by this task.

The comment stays prose. No fenced block is introduced.

  itself an AC-4 failure.
