# Task Plan: task0001 — SanitizedTitle newtype, builder signatures, call-site migration and doc rewrite

## Goal

Both notification body builders take the tab title only as `&SanitizedTitle`, which outside `crate::notifications` can come only from `sanitize_title`. Every caller and test is migrated to it. Notification text is byte-for-byte unchanged. The doc comments describe the type-enforced tab-title contract and the upstream agent-name contract.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/notifications.rs` — add the new sanitized-title type; change the return type of sanitize_title and the title parameter type of both builders; remove the internal sanitize call from the agent builder; rewrite the doc comments; migrate the unit tests and add the TS1 test
- `src-tauri/src/app/mod.rs` — pump_all's pending notification list stores the sanitized type, still captured at the existing capture point
- `src-tauri/src/app/agent_status.rs` — maybe_notify_agent_transition sanitizes its raw tab title on the fire branch before it builds the agent body; update its doc comment
- `src-tauri/src/app/tests/agent_status.rs` — add an App-level test that sends a CSI-bearing tab title through the agent notification path
- `src-tauri/src/callbacks/tests.rs` — the tests that depend on sanitize_title read through the accessor; the agent-body call passes a sanitized title

## Design

The contract for `SanitizedTitle`, `sanitize_title`, both builders and `AgentTransition::name` is pinned in IMPLEMENTATION.md, under Shared Components and D3/D4. Implement against it. The line numbers below are as of planning time.

### `src-tauri/src/notifications.rs`

1. **The type**: define `SanitizedTitle` next to `sanitize_title` (around lines 142-159), with one private text field. Its doc comment states three things:
   - the invariant (no CSI, no C0/DEL/C1 control character, at most 100 characters);
   - that `sanitize_title` is its only producer;
   - that no raw-text constructor or conversion exists, on purpose.

   The public surface is exactly what IMPLEMENTATION.md lists.
2. **`sanitize_title`**: keep the algorithm unchanged (4096-character input cap, CSI strip, C0/C1/DEL filter, 100-character cut). Only wrap the result in the new type.
3. **`notification_body`** (lines 161-174): change the title parameter to `&SanitizedTitle`. Keep the locale × kind message table and the `"{title}: {msg}"` shape unchanged.
4. **`agent_notification_body`** (lines 360-393):
   - change the title parameter to `&SanitizedTitle`;
   - delete the internal `sanitize_title` call;
   - leave the name / fallback and state-message logic untouched;
   - leave `transition.name` as-is, with no re-sanitization.
5. **Doc comments** (FR4, FR5):
   - **`notification_body` doc**: keep the WebView-parity sentence. Add that the builder requires a `SanitizedTitle`, that only `sanitize_title` produces one, and that the type therefore enforces the tab-title invariant at every call site.
   - **`agent_notification_body` doc**: replace the paragraph that ends "single choke point for both existing call sites and any future one" and the sentence that justifies sanitizing inside the function. The new text says four things:
     - the builder requires a `SanitizedTitle`;
     - only `sanitize_title` produces one;
     - the type enforces the tab-title invariant at every call site;
     - the agent name comes from `AgentTransition::name`, is trusted as already sanitized at parse time by `crate::agent_status`'s `sanitize_name`, and is not re-sanitized here.
   - **`AgentTransition::name` doc** (lines 213-215): name the upstream parse-time function (`agent_status`'s `sanitize_name`) explicitly, and state that the body builders do not re-sanitize the name.
   - `sanitize_name` is private. Write it as a plain code-formatted path, not an intra-doc link.
6. **Unit tests in this file**:
   - The five `sanitize_*` tests compare through the read accessor, with their expected literals unchanged.
   - `body_formats_match_webview_strings` and `body_formats_match_webview_ja_strings` build their input with `sanitize_title` on `"tab"`, with their expected strings unchanged.
   - Add the TS1 test: pass `sanitize_title` of `"\x1b[31mred\x1b[0m title"` to `notification_body`, for every `ActivityKind`.
   - The four `agent_notification_body_*` tests pass `sanitize_title` of their existing raw literal, with their expected bodies unchanged. They may keep their names.
   - Add one small test showing that the accessor text and the `Display` output of a sanitized value are identical.

### `src-tauri/src/app/mod.rs`

- `pending_notifications` (declared around lines 1016-1017) becomes a list of (sanitized title, activity kind) pairs.
- The push at the capture point (around lines 1286-1289) keeps the same gate (notifications enabled, window unfocused, per-tab throttle passed) and still sanitizes there. This keeps each stored title at 100 characters or fewer and avoids cloning a raw OSC title (NFR3).
- The dispatch loop (around lines 1391-1394) passes a reference to the stored value to `notification_body`.
- No other logic changes.

### `src-tauri/src/app/agent_status.rs`

The parameter list of `maybe_notify_agent_transition` stays unchanged, including the raw `tab_title: &str`. Its flow:

1. Read the rate limit and compute the gating decision (unchanged).
2. If the notification fires:
   1. record the fire in the rate limiter;
   2. sanitize `tab_title`;
   3. build the agent body from the sanitized value;
   4. dispatch it through the notification sink.
3. If it does not fire, do no sanitization and dispatch nothing.

Update the method's doc so that "`tab_title` feeds the notification body" says the title is raw and untrusted, and that it is sanitized here on the fire path before the body is built.

### `src-tauri/src/app/tests/agent_status.rs`

Add one test that uses the existing `app_with_test_sink` / `agent_transition` helpers. It sends a Blocked transition named `claude` for a pane that is not visible, with the raw tab title `"\x1b[31mred\x1b[0m title"`. It asserts three things:

- the transition fires;
- the sink records exactly one call;
- the call's summary is the notification title constant and its body is `"claude: red title (blocked)"`.

### `src-tauri/src/callbacks/tests.rs`

- `escape_body_markup_after_sanitize_title_truncation_keeps_entity_intact` (around lines 730-745) and `confirmed_capabilities_escape_a_sanitize_title_truncated_title_intact` (around lines 942-958) read the character count, the trailing `<` and the input to the escape functions through the accessor. All assertions stay unchanged: the 100-character boundary, the trailing `&lt;`, and the `escape_for_send` result.
- `tab_activity_and_agent_bodies_are_both_escaped_when_confirmed` (around lines 798-843): the agent-path call passes `sanitize_title` of `"my-tab"`. All assertions stay unchanged. The existing comment about the sink-side escape "single choke point" refers to the markup-escape choke point, not to title sanitization, so leave it as is.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, NFR4): `crate::notifications` defines `SanitizedTitle` with a private text field, and `sanitize_title` returns it. The type exposes a read-only borrowed-text accessor and `Display`, and a unit test shows they yield identical text for a sanitized sample. Inspection of the public surface confirms none of the following: a public field, a public constructor taking raw text, a conversion in either direction with `String` / `&str` (`From` / `Into` / `FromStr` / `Deref` / `AsRef` / `Borrow`), `Default`, or deserialization.
- [ ] AC-2 (FR1, FR6; TS4, TS5): these tests compare through the read accessor and pass with unchanged expected texts and assertions:
  - the five existing `sanitize_*` tests in `notifications.rs`;
  - the two truncation-boundary tests in `callbacks/tests.rs` that depend on `sanitize_title` (100-character boundary, trailing `&lt;`, `escape_for_send` result).
- [ ] AC-3 (FR2, FR6; TS1, TS2): `notification_body` takes `&SanitizedTitle`. A new unit test passes `sanitize_title` of `"\x1b[31mred\x1b[0m title"` and gets `"red title: <message>"` for every `ActivityKind`, with no ESC byte and no CSI remnant. `body_formats_match_webview_strings` and `body_formats_match_webview_ja_strings` pass with input `sanitize_title("tab")` and unchanged expected strings.
- [ ] AC-4 (FR2, FR4, FR6; TS3): `agent_notification_body` takes `&SanitizedTitle`. Its body contains no `sanitize_title` call and uses `transition.name` as-is. The four existing `agent_notification_body_*` tests pass after the test passes its raw literal through `sanitize_title`, with unchanged expected bodies.
- [ ] AC-5 (FR3, NFR3): in `App::pump_all`, `pending_notifications` holds (sanitized title, activity kind) pairs filled by `sanitize_title` at the existing capture point. `App::maybe_notify_agent_transition` keeps its raw `&str` tab-title parameter and sanitizes only on the fire branch. The new App-level test gets exactly one sink call, with body `"claude: red title (blocked)"`. All existing tests in `app/tests/agent_status.rs` pass unchanged.
- [ ] AC-6 (FR4, FR5; TS7): `notifications.rs` no longer contains the text "single choke point for both existing call sites and any future one". The `notification_body` and `agent_notification_body` docs each state three things: the builder requires `SanitizedTitle`, `sanitize_title` is its only producer, and the type enforces the tab-title invariant at every call site. The `AgentTransition::name` doc and the `agent_notification_body` doc both state that the name is sanitized upstream at parse time by `agent_status`'s `sanitize_name` and is not re-sanitized by the builders.
- [ ] AC-7 (NFR1, NFR2; TS6): `cargo check` passes with default features and with `--no-default-features`. `cargo test --lib -- --test-threads=1` passes. No dependency is added to `src-tauri/Cargo.toml`, and the `gui` gating of `notifications` in `lib.rs` is unchanged.
