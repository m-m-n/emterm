# Task Plan: task0001 — Strip-join closing, lone-ESC neutralization and split-query classification

## Goal

After this task, no join the shared strip produces completes an escape or a
CSI device query the raw stream never made. This holds within one read,
across reads and across a snapshot. A device query split across reads never
reaches the ring in answerable form. Every behavior change is recorded and
covered by regression tests.

## Design

Shared contracts and decisions D1-D6 are in IMPLEMENTATION.md. This section
covers only how this task applies them.

### Shared strip (D1, D2, D3)
- The written-stream state's CSI variant carries the open-CSI
  classification. Every written byte advances it. Removed bytes never do.
- Every removal arm (Kitty APC, SIXEL DCS, replayable OSC, answered CSI
  query) checks the written state before skipping the construct. If the
  state is inside a CSI or in the escape state, one CSI_CLOSING is written
  first. A removed query's embedded C0 bytes follow the closing.
- A byte about to be written as the final byte of an open CSI whose
  classification says "answered device query" is written as CSI_CLOSING
  instead (D2).
- The state-reporting form takes the carried classification as its start
  state and returns the end classification (D3). Its debug precondition (no
  designator wait together with an open CSI) stays.
- The first-parameter accumulation that `scan_csi_device_query` performs is
  factored into one definition used by both the scan and the classification.
  The scan's observable results do not change.

### Write filter (D4)
- The carried CSI field becomes the classification. Every call into the
  state-reporting form passes it and stores the returned value. This covers
  the drain path, the cut segment, the empty segment and the overflow flush.
- The cut, empty-segment and overflow-flush closing rules are unchanged:
  close when the carried classification is present, never together with the
  designator ESC, then clear.
- The `csi_phase` accessor returns the classification's sub-state.

### Records (FR8)
DECISIONS.md lists every existing test whose expectation changes under the
heading "Behavior-changing tests". Each entry gives the test's full `--lib`
path, the old and new expectation in one line each, and the FR that changes
it. Expected entries (not exhaustive; the implementer records what actually
changes):
- `round4_cut_csi.rs`: the CLOSING_CASES rows that follow `ESC[6` with a
  launch, a Kitty APC or a query. The strip now writes the closing, so the
  kept bytes end in DEL and the cut adds none (FR1). BYTE_BY_BYTE_EXPECTATIONS:
  the byte-by-byte ring of `ESC[6` + `ESC[6n` ends in DEL in place of `n` (FR3).
- `post_strip_cut_csi.rs`: the carried-state case (b), where the CSI carried
  in now ends at the completing call (EC-1), and the closing-path cases whose
  written bytes gain a strip-written closing (FR1).
- `scrollback_filter/tests.rs`:
  `strip_bare_esc_in_csi_body_aborts_then_strips_following_query` and the
  `post_strip_state_form_*` tests (FR1, D3).

Any residual found during implementation (for example the overflow-flush
lone ESC in IMPLEMENTATION.md Open Questions) goes in a "Residuals" section
of DECISIONS.md.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR5, NFR3, TM-1): The test crosses these inputs:
  - open heads `ESC[`, `ESC[6`, `ESC[?25`, `ESC[6 space` and `abc ESC[12;3`
  - removed construct kinds: OSC 777 viewer launch (BEL- and ST-terminated),
    OSC 9999 emterm-md, agent-status, Kitty APC, SIXEL DCS, and an answered
    CSI query with and without an embedded C0 byte
  - continuations `n`, `c`, `t`, `m` and plain text

  Each combination goes as one cut-free input to every strip entry point and
  to one cut-free write-filter call. In every output, exactly one
  CSI_CLOSING sits at the construct's position, before any re-emitted C0
  byte (EC-3). Several removed constructs inside one open CSI produce exactly
  one closing (EC-4). `ESC[` + launch + `c` forms no DA1 (EC-5). A construct
  removed in ground or inside a kept string body adds no byte. The
  state-reporting form reports no open CSI after the closing. Replaying each
  output through term_core gives no response, and the same rows and cursor as
  the raw-stream reference with the construct's own effect excluded.
- [ ] AC-2 (FR2, TM-1): This runs through the production reader and the
  visibility-restore harness, with no cut and no screen switch. For every
  removed construct kind, the chunks are [`ESC[6` + construct, `n`] and
  [`ESC[6` + construct, CR, `n`], with the restore taken after the first
  read. The held-construct variant splits the construct across reads, with
  the restore between them (EC-2). The same sequences are also run through
  the reattach layout. In each case, the client's responses, rows and cursor
  equal the raw-stream reference's. No CSI_CLOSING is appended at a snapshot
  end, and the existing layout tests pass unchanged: reattach trailing
  `ESC[?1049{h,l}`, resume layouts, and the wrapped-ring dump block.
- [ ] AC-3 (FR3, FR7, TM-2): Each answered form is split at every position,
  fed byte by byte, and fed with C0 bytes inside the continuation. The forms
  are `ESC[6n`, `ESC[5n`, `ESC[261n`, `ESC[c`, `ESC[0c`, `ESC[?c`, `ESC[>c`,
  `ESC[14t`, `ESC[16t`, `ESC[18t` and `ESC[?1$p`. In every case:
  - Replaying the ring through term_core gives no response.
  - Each C0 byte keeps its effect, once and in order.
  - The pending length is 0 after every call.

  `ESC[6` followed in the next call by `ESC[6n` gets the closing (EC-8).
  Non-query CSIs split the same way are written byte-identical to their
  input (`ESC[3` | `1m`, `ESC[=c`, `ESC[0n`, `ESC[15t`; EC-9). A cut clears
  the carried classification. Parity (TS-5) is tested over two sets:
  - open prefixes: with a private marker, with intermediates, with long
    parameters, with saturating parameters, and `ESC[261`
  - every possible next byte

  The filter writes CSI_CLOSING in place of that byte exactly when term_core
  answers the raw stream.
- [ ] AC-4 (FR4, NFR3, TM-1): The inputs are `ESC` + `ESC[6n` + `[c`, `ESC` +
  launch + `[6n`, `ESC` + Kitty APC + `[c`, and `ESC ESC` + each removed
  construct kind + `[c` / `[6n`. Each goes in one call to every strip entry
  point, and to the write filter split at every position, including a lone
  trailing ESC held across calls (EC-11). Replay gives no response and
  equals the raw-stream reference. The neutralizing CSI_CLOSING precedes any
  re-emitted C0 byte. After every call, the filter's carried state is either
  none or an open CSI that term_core agrees with. It is never an escape
  state.
- [ ] AC-5 (FR5, FR6): Four groups of checks.
  - For equal start states, every strip entry point returns byte-identical
    output over the AC-1 and AC-4 inputs.
  - Take the state-reporting form started from a head's carried
    classification. Its output equals the ground-started strip of head +
    input, minus the head's written bytes. The exception is input that
    completes the head's CSI as an answered query. There the two outputs
    are replay-equivalent in term_core and neither produces a response.
  - The existing tests for `scan_csi_device_query`, `csi_is_device_query`,
    `is_replayable_osc_body`, `dcs_is_sixel` and the kept-byte set pass
    unchanged.
  - Remap: watch offsets are placed at the first byte of, strictly inside,
    and right after a construct removed inside an open CSI and after a lone
    ESC. The remapped offsets are non-decreasing and within the output. The
    first-byte offset maps before the closing. The others map after the
    closing and the re-emitted C0 bytes. `build_snapshot_bytes` segment
    offsets point at the same content for such a ring.
- [ ] AC-6 (FR7, FR8): The predecessor suites pass, with expectations
  changed only where FR1, FR3 or FR4 change written bytes. The suites are
  `round4_cut_csi`, `post_strip_cut_csi`, `round4_chain`, `round3_write_path`,
  the `scrollback_filter` tests and the `snapshot_bytes` tests. The existing
  cut-rule tests still pass:
  - at most one closing per cut
  - never together with the designator ESC (EC-6)
  - the empty-segment, fallback and overflow-flush paths close an open CSI,
    and the overflow flush writes the strip's closing in place (EC-7)
  - after every cut-free call, the carried sub-state equals term_core's on
    the written bytes

  A cut that follows a strip-written closing writes no second closing. The
  `post_strip_cut_csi.rs` case (b) is inverted per EC-1. DECISIONS.md lists
  every changed test with its old and new expectation and the FR that causes
  the change. No test is renamed, and the predecessor DECISIONS.md and
  test-docs records are unchanged.
- [ ] AC-7 (NFR1, NFR2, NFR4, TM-3): Each of these inputs finishes within the
  10 s budget without panicking:
  - an open CSI + strip target alternation repeated 100k times
  - a lone ESC + strip target alternation repeated 100k times
  - long ESC ESC chains before removed constructs
  - a 300k-byte CSI parameter run, fed whole and fed byte by byte (the
    pending length stays 0)
  - the overflow-flush path

  Both `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib`
  and
  `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path src-tauri/Cargo.toml --no-default-features`
  succeed.

## Test Notes

- AC-1, AC-4 (strip part) and AC-5 are unit tests in the `scrollback_filter`
  test module. AC-1 and AC-4 (write-filter part), AC-3 and AC-7 are unit
  tests in the new `strip_concat_query` module. AC-2 is the reader-level
  integration test in the same module. It reuses the round3 harness:
  `run_visibility_restore_at`, the client and reference views, and the
  reattach-layout helpers.
- The oracle is term_core fed the raw stream with the removed construct's own
  effect excluded (SPEC A3). Follow the predecessor helpers that exclude a
  construct's own answer, for example the own-answer helper in
  `post_strip_cut_csi.rs`.
- Write the AC-1, AC-3 and AC-4 tests first and see them fail on the current
  code. The current strip writes `ESC[6n` for AC-1's first row. The current
  filter writes the split query whole for AC-3.
- Parity (AC-3) needs no hand-written truth table. Build the prefix corpus,
  feed each prefix plus each byte to term_core, and compare its responses
  with whether the filter wrote CSI_CLOSING in place of that byte.
- EC-2 depends on the `suppressed_output` re-delivery of the held head. If
  the AC-2 held-construct variant fails because of that path, stop and
  report a plan deviation. Do not edit `suppressed_output`.
- Run the tests with the `--lib` command above. The `tabs.rs` replay tests
  are known to be nondeterministic under parallel runs; they are unrelated to
  this task.
