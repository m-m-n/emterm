# Task Plan: task0001 — Align agent-notification docs with visible-pane behavior

## Goal

`doc/AGENT-STATUS.md`'s "## Notifications" section describes the agent-status
notification behavior that is in the code today: every pane notifies on a
real transition to blocked / done, a visible pane is controlled by the
visible-pane setting, and every gating setting is listed with its default.
`doc/SPECIFICATION.md` is confirmed to state the same behavior.

### 1. Behavior to document (confirmed against the code at the base revision)

Source of truth for every statement:

- `src-tauri/src/notifications.rs` — `should_fire_agent_notification`
  (lines 271-287) and the state-to-toggle mapping it consults
  (`event_type_notifications_enabled`, lines 241-251).
- `src-tauri/src/app/agent_status.rs` — `agent_status_pane_visible`
  (lines 45-57).
- `src-tauri/src/settings/mod.rs` — the defaults (lines 313-321).

A notification fires only when ALL of the following hold:

| Condition | Setting / rule | Default |
|---|---|---|
| The new state is blocked or done (a real transition) | — | — |
| The pane is not visible, OR the visible-pane setting is on | `agent_notify_visible_pane` | on |
| Agent-status notifications are enabled | `agent_status_notifications` | on |
| The global notification setting is enabled | global notification switch | on |
| The event toggle matching the new state is on — done uses `agent_notify_on_done`, blocked uses `agent_notify_on_blocked` | per-event toggles | on |
| The pane is within its per-pane rate limit | — | — |

"Visible" means: the OS window has focus AND the pane belongs to the active
tab. For a mux-attached tab, the whole window group of that tab counts as
visible while that tab is the active tab of the focused window. This is the
same definition `doc/SPECIFICATION.md` uses ("the focused window's active
tab").

Consequences the text must convey:

- With the visible-pane setting on (default), visible and non-visible panes
  notify alike.
- With it off, only visible panes are suppressed; non-visible panes are
  unaffected by this setting.
- Every other condition in the table applies regardless of visibility.

### 2. Edits to doc/AGENT-STATUS.md ("## Notifications", the file's last section)

Edit A — opening statement (currently lines 190-191, the sentence beginning
"An OS notification fires when a pane not visible in the foreground
window"). Replace it with a statement conveying:

1. An OS notification fires for any pane on a real transition to blocked or
   done.
2. For a visible pane (the focused window's active tab), this is controlled
   by the visible-pane setting (default on) and is suppressed only when that
   setting is off.
3. Panes that are not visible are unaffected by that setting.

The lead-in to the "never produce a notification" list and its three bullets
(same-state re-report, name-only change, snapshot/replay-derived update)
stay as they are.

Edit B — conditions paragraph (currently lines 199-203). Rewrite it so it:

1. Keeps the per-pane rate limit.
2. Lists every setting a notification requires, each stated as default on:
   the agent-status notification setting, the global notification setting,
   the per-event toggles (the done toggle for transitions to done, the
   blocked toggle for transitions to blocked), and the visible-pane setting
   (for visible panes).
3. Keeps the sentence stating that the name in a notification body is the
   sanitized (control-character-stripped) display name.

Writing rules for both edits (NFR3):

- State behavior only. No reasons, no references to PRs, review findings,
  or other features, and no history wording (for example "new", "now",
  "previously", "no longer", "existing", "restores").
- Settings are referred to by their settings key, matching the style of
  `doc/SPECIFICATION.md` and the current section.
- English, matching the rest of the document.
