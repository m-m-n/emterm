# Task Plan: task0002 — GUI ingest: route, accumulate, spawn

## Goal

The GUI terminal recognizes OSC 777 kind `html`, accumulates its chunks into the decoded document, writes the hand-off payload file, and spawns the `--html-viewer` child process; mux snapshot replay strips the sequence via the kind SSOT.

## Requirements

FR2

## Scope

### Files to Create
- `src-tauri/src/viewer/html.rs` — `html` session accumulator (begin/chunk/end), payload struct (HTML text + optional basedir) and temp-file writer

### Files to Modify
- `src-tauri/src/viewer_kinds.rs` — add `html` to `REPLAYABLE_VIEWER_KINDS`
- `src-tauri/src/viewer/mod.rs` — module roster; `html` arm in the route dispatch; drift-test kind list; sink method that writes the payload and spawns the child with the `--html-viewer` flag

## Design

- The accumulator mirrors the markdown session pattern (Decision D4): `begin` captures basedir, `chunk` stores base64 fragments keyed by seq, `end` joins in seq order, decodes once, and emits a render request through the sink.
- The payload hand-off follows the shared-component contract in IMPLEMENTATION.md: JSON temp file, mode 0600, create-new, unique name; fields are the HTML text and optional basedir only (no appearance data).
- The spawn path mirrors the markdown sink method but passes the `--html-viewer` flag (Decision D1). The child-side flag handling is task0004; this task only needs the spawner to pass the agreed flag string.
- Adding `html` to the SSOT automatically extends the mux scrollback stripper; its existing drift test and the route drift test must both stay green, which forces the route arm and kind list updates to stay in lockstep.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `REPLAYABLE_VIEWER_KINDS` contains `html`, and both existing drift tests (route kinds, scrollback stripper) pass with the new kind.
- [ ] AC-2: A begin → chunk(s) → end sequence for kind `html` yields exactly one emitted render request whose document equals the decoded concatenation of the chunks (in seq order) and whose basedir matches the begin parameter; out-of-order chunk delivery still decodes correctly.
- [ ] AC-3: Malformed input (chunk/end without begin, invalid base64) is dropped without panic and without emitting a render request, matching the markdown accumulator's tolerance behavior.
- [ ] AC-4: The payload writer produces a create-new 0600 JSON file containing the document text and basedir; a round-trip read restores both fields.
- [ ] AC-5: The sink spawns the child with the `--html-viewer` flag and the payload path as its argument (verifiable at the command-construction seam, same style as existing spawn tests if present).

## Test Notes

- AC-1 relies on the two existing drift tests plus a direct constant assertion.
- AC-2/AC-3 are unit tests on the accumulator following the markdown session test suite structure.
- AC-4 uses a temp-dir round trip.
- AC-5: test at whatever seam the markdown sink already exposes; if spawn construction is not directly testable today, assert the flag constant and payload path plumbing at module level and note it.

## Out of Scope

- The child process itself (window, rendering, security policy) — task0004.
- Resolver logic — task0003.
- CLI side — task0001.
