# Task Plan: task0001 — Query notification capabilities only when a markup metacharacter is present

## Goal

On Unix, the notification worker queries notify-rust capabilities only when the
title or the body contains `&`, `<` or `>` — at most once per notification,
never cached — while the summary and body handed to notify-rust stay
byte-for-byte identical to the current implementation for every input and
every query outcome. The doc comments in `src-tauri/src/callbacks.rs` describe
the new conditional behavior.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2, NFR3, NFR4, NFR5, NFR6

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/callbacks.rs` — new Unix-only metacharacter constant, predicate and on-demand escape gate; the worker's escape step switched to the gate; four doc comments rewritten.
- `src-tauri/src/callbacks/tests.rs` — new Unix-gated test module for the gate, the no-caching property and the escape identity property; existing tests untouched.

## Design

All component contracts are pinned in IMPLEMENTATION.md "Shared Components";
D1–D3 there give the rationale. This section covers only the task-level
detail.

### Normative decision table (SPEC 判定表; FR1 / FR2 / FR3)

| Metacharacter in title or body | Supplier calls | Supplier outcome | Returned (summary, body) |
|---|---|---|---|
| In neither | 0 | — | Inputs unchanged |
| In either or both | 1 | Error | Both escaped |
| In either or both | 1 | Success, list contains `body-markup` | Both escaped |
| In either or both | 1 | Success, list omits `body-markup` | Inputs unchanged |

"Metacharacter" means exactly `&`, `<`, `>`. Quotes (`"`, `'`) and every other
symbol are not metacharacters. Empty strings contain no metacharacter.

### Processing flow of the on-demand gate

1. Check the title with the metacharacter predicate; if it has none, check
   the body.
2. If neither field has a metacharacter: return owned copies of the two
   inputs. The supplier is dropped without being called.
3. Otherwise: call the supplier once, pass the title, the body and that one
   result to the existing `escape_for_send`, and return its pair unchanged.

The gate holds no state: two consecutive calls never share a query result.

### Worker wiring

In `notify_worker`, the Unix-only escape step currently evaluates the
capability query eagerly and passes its result to `escape_for_send`. Replace
it with a call to the on-demand gate that receives the notify-rust capability
query itself, un-invoked, as the supplier. Keep everything else in the loop
exactly as is:

- the redaction line stays first and keeps deriving from the raw values
  received off the queue (NFR4);
- the escape step stays a single Unix-gated binding that shadows the title
  and body (NFR3);
- dispatch and the two log records do not change.

### Existing helpers

`escape_for_send`, `escape_body_markup`, `body_markup_absence_confirmed`,
`sanitize_title` and `NotificationRateLimiter` keep their signatures and
behavior (NFR2). `escape_for_send` stays the fail-closed decision unit that
the gate delegates to; only its doc comment changes.

### Doc comment updates (FR5)

Rewrite these four so they describe the conditional query: zero queries when
neither field contains a metacharacter, exactly one query otherwise, never
cached, and both fields decided by that one result.

1. The doc comment of `notify_worker` (currently "... capability query,
   escape decision, dispatch, log, in that order, once per received
   notification").
2. The notification-worker-thread D3 comment above the escape step inside
   `notify_worker` (currently "capability query happens here, once per
   notification, never cached"). Keep the fail-closed and Windows-gating
   explanations it already carries.
3. The doc comment of `NotifyRustSink` (currently lists "capability query,
   dispatch" as round-trips the worker performs for every send).
4. The doc comment of `escape_for_send` (currently "the caller queries
   `get_capabilities()` exactly once per `send`" and "the only caller is
   `NotifyRustSink::send`"): the caller is now the on-demand gate, which
   invokes it only when a metacharacter is present.

The new constant, predicate and gate each get a doc comment stating their
contract from IMPLEMENTATION.md. After the change, no comment in
`src-tauri/src/callbacks.rs` may claim that the capability query runs
unconditionally or exactly once per notification or send, and none may claim
that a synchronous D-Bus round-trip happens on the PTY-processing thread or
the UI thread. Past-tense history comments (for example the section header
saying the sink "used to" perform the round-trip on the calling thread) are
accurate and stay.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR3, FR4; VERIFICATION TS-1, TS-5): for titles and bodies
      without `&`, `<`, `>` — ASCII, non-ASCII, empty title, empty body, the
      fallback title `emterm`, and text containing `"`, `'` and other symbols
      — the gate returns the inputs unchanged and a counting stub supplier
      records zero calls.
- [ ] AC-2 (FR2, FR3, FR4; TS-2, TS-3, TS-4): with a metacharacter in the
      title only (including the OSC 9 fallback title `<tab title>`), in the
      body only (including a lone `&` and a pre-existing `&amp;`), and in both
      fields, under each of the three stub outcomes (error, success containing
      `body-markup`, success omitting `body-markup`), the stub records exactly
      one call and the returned pair equals the existing `escape_for_send`
      result for the same title, body and outcome.
- [ ] AC-3 (NFR1; TS-7): two consecutive gate calls with metacharacter input,
      each given its own counting stub with a different outcome, each call its
      own stub exactly once and each follow its own outcome — no result is
      carried over between calls.
- [ ] AC-4 (FR3, NFR2; TS-8): a test pins the identity property the
      short-circuit relies on — `escape_body_markup` leaves every printable
      ASCII character outside the metacharacter set, and a sample of
      non-ASCII characters, unchanged, and changes each of `&`, `<`, `>`;
      the metacharacter constant contains exactly those three characters.
- [ ] AC-5 (FR1, NFR1, NFR3, NFR4; TS-10): in `src-tauri/src/callbacks.rs`,
      `notify_worker` hands the capability query to the gate un-invoked; no
      non-comment line invokes the capability query anywhere else; the
      redaction still precedes the gate and reads the raw values; the new
      items are Unix-only; no new cfg branch and no caching primitive is
      introduced.
- [ ] AC-6 (FR5; TS-9): the four doc comments listed in Design describe the
      conditional query, and a text search of `src-tauri/src/callbacks.rs`
      finds no comment stating that the capability query runs
      unconditionally, "exactly once per send", or "once per notification",
      and none claiming a synchronous D-Bus round-trip on the PTY-processing
      thread or the UI thread.
- [ ] AC-7 (NFR2, NFR3, NFR5, NFR6; TS-6): the existing
      `escape_for_send`, `body_markup_absence_confirmed` and
      `escape_body_markup` tests pass with their assertions unchanged;
      `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib`
      and
      `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path src-tauri/Cargo.toml --no-default-features`
      both succeed; no `Cargo.toml` or `Cargo.lock` file anywhere in the
      repository changes.

## Test Notes

- AC-1 to AC-4 are pure unit tests in a new Unix-gated module of
  `src-tauri/src/callbacks/tests.rs`; no D-Bus connection is involved. Place
  the module next to the existing escape-gate modules.
- The counting stub is a supplier that increments a counter owned by the test
  on each call and returns a preset outcome; the error type can be the unit
  type, as the existing escape tests already do.
- For AC-2, compute the expected pair by calling `escape_for_send` directly
  with an equal, independently built outcome value — this makes the
  byte-identity check against the current implementation explicit. Add at
  least one hard-coded spot check as well (for example `<tab title>` becoming
  `&lt;tab title&gt;` under the error outcome).
- For AC-1, also assert the result equals `escape_for_send` for each of the
  three outcomes, showing the short-circuit is output-equivalent to the
  previous always-query behavior.
- AC-5 and AC-6 are checked by reading the diff and by text search of
  `src-tauri/src/callbacks.rs`; unit tests cannot observe the real D-Bus
  query. The real-bus effect is covered by the manual D-Bus observation in
  VERIFICATION.md.
- AC-7: diff `src-tauri/src/callbacks/tests.rs` against the base — existing
  test functions must be byte-identical; only additions are allowed.
- Known unrelated flakiness in the `--lib` suite (the `tabs.rs` replay tests
  under parallel execution and the rare `tmux_sockets` discover race) is not
  caused by this task; re-run before treating such a failure as a regression.

  it no longer exists in `src-tauri/src/callbacks.rs`).
- Comments outside `src-tauri/src/callbacks.rs`, and comments inside it that
  make no claim about query frequency or thread blocking.
