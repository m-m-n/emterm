# Task Plan: task0001 — App Line 1 auto-hide in the status-bar widget

## Goal

App Line 1 no longer renders as an empty band: it is counted and drawn only when its resolved content is non-empty, and when no row at all is visible the status-bar panel is not inserted (height 0).

## Requirements

FR1, FR2, FR3, NFR1

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/ui/status_bar.rs` — replace the unconditional App Line 1 visibility (`app1_visible = true`, present in both the row-count helper and the draw function) with the resolved-content rule already used by App Line 2; update/extend the widget's unit tests.

## Design

- The row-count helper decides how many rows the panel reserves; the draw function decides which rows are painted. Both currently hard-code App Line 1 as visible with a comment referencing the original FR12 rule. Both must use the app row's existing "has content" predicate instead, and the stale comment must be updated to describe the new rule.
- No view-model, runtime, or settings changes: the predicate already exists on the app-row type and is used by App Line 2.
- Panel collapse falls out of existing behavior: when the count is 0 the draw function returns before inserting the panel, and the panel-height helper multiplies row height by the count. Do not add a separate code path for it — cover it with tests instead.
- Precondition/postcondition of the changed helper: given an enabled view model, the returned count equals the number of rows whose visibility predicate is true (OSC: its render rule; App Line 1 and 2: content non-empty); disabled view models still return 0.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: With the status bar enabled and OSC row, App Line 1, and App Line 2 all empty, the visible row count is 0 and the panel height is 0.
- [ ] AC-2: With App Line 1 empty and the OSC row having content (or forced visible), the visible row count is 1 and only the OSC row is drawn.
- [ ] AC-3: With App Line 1 having resolved content, it is counted and drawn (regression guard).
- [ ] AC-4: With App Line 1 empty and App Line 2 having content, App Line 1 is hidden while App Line 2 is shown.
- [ ] AC-5: A disabled view model still yields 0 rows regardless of content.
- [ ] AC-6: All pre-existing status-bar widget tests pass, updated only where they relied on App Line 1 rendering while empty.

## Test Notes

- All criteria are unit-testable in the widget's existing test module using hand-built view models (no font stack needed) — follow the surrounding test style.
- AC-1/AC-2 map to the row-count helper; drawing-side assertions can follow the existing pattern used by the App Line 2 auto-hide test.
- Edge case worth covering: a run list containing only empty-text runs (resolved-empty template) counts as no content — this is already the predicate's semantics; assert it from the widget side.

## Out of Scope

- Any change to the OSC row rules, App Line 2 rules, or the enabled/disabled short-circuit.
- Settings schema, settings UI, view-model, template-engine, or runtime changes.
- Debounce/hysteresis for providers that alternate between empty and non-empty output.
