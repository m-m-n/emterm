# Task Plan: task0001 — anchor_scan: close the callee / fn-name miscount paths in locate_call

## Goal

The test-only `anchor_scan::locate_call` stops under-counting callee calls and
depth-0 function definitions. Raw-identifier callees, callees swallowed by a
numeric literal (`0..x`, `0.method`), turbofish-form calls, and
raw-identifier function names are all counted, so every ambiguous input
returns `Err` instead of `Ok`. The module header comment's stale
design-document path is also corrected.

## Design

Protected invariant: `locate_call` never returns a wrong range as success
(anchor-scan-false-success SPEC FR4). Each change below closes one path where
a real occurrence was not counted, so that an ambiguous input looked unique.
Line numbers quoted in SPEC.md may have drifted. Locate code by structure
(the scanner's numeric-literal branch, `locate_call` step 1 / step 2), not by
line number.

### 1. Numeric-literal scan boundary (FR2)

Current behavior: a numeric literal starts at an ASCII digit and runs over
letters, digits, `_` and `.`. New behavior for a `.` met inside that run:

| Character right after the `.` | Behavior |
|---|---|
| a digit | the `.` stays in the literal and the run continues (`1.5`, `1.0f32`, the `0.1` of tuple index `x.0.1`) |
| `.` | the literal ends before this `.` (`0..x`, `0..=x`) |
| an identifier-start character (same predicate the scanner uses for identifiers) | the literal ends before this `.` (`0.method`) |
| anything else (whitespace, other punctuation, end of input) | unchanged from current behavior |

Letters, digits and `_` that do not follow a `.` continue the run as today
(`1e10`, `0x1F`, the `f32` suffix). A `.` left outside the literal goes
through the scanner's existing punctuation path. The identifier after it
goes through the existing identifier path, so it becomes its own identifier
token.

### 2. Bare-name comparison (FR1, FR4, FR5)

- **Bare name of an identifier token**: the token's identifier text with a
  leading `r#` removed. Text without that prefix is used as is.
- Step 1 compares the bare name of the token after `fn` against `fn_name`.
  Step 2 compares the bare name of each identifier token against
  `callee_last_segment`. The supplied `fn_name` / `callee_last_segment` are
  used as given. Callers pass bare names.
- The `fn` keyword check in step 1 keeps using the **raw** identifier text,
  so the token `r#fn` is never treated as the keyword (SPEC as-1).
- Only the comparison changes (FR5). The scanner's raw-identifier branch
  still emits one identifier token whose text and byte range include `r#`.
  Token offsets, `callee_end`, `open_paren_end`, `close_paren_start` and the
  argument range are computed exactly as today. So for
  `r#probe_call(a, b, c, d)`, `callee_end` falls right after `r#probe_call`.
- The implementer chooses whether to change the existing identifier-text
  accessor or add a separate bare-name accessor. The only constraint is that
  the keyword check still sees raw text.

### 3. Step 2 call-shape recognition (FR3)

Inside the located body, step 2 counts every occurrence of either shape:

| Shape | Token sequence |
|---|---|
| Plain | identifier whose bare name equals the callee, then `(` |
| Turbofish | identifier whose bare name equals the callee, then two consecutive `:` tokens, then `<`, then a generic-argument list, then the `>` that balances the opening `<`, then `(` |

- Generic-argument balancing: each `<` opens one level and each `>` closes
  one. The scanner emits each `>` as a separate punctuation token, so `>>`
  closes two levels (EC-3). Tokens other than `<` / `>` inside the list are
  skipped.
- The balancing walk never goes past the body end. If no balancing `>` is
  found, or the token after it is not `(`, the occurrence is not a call and
  is not counted. This covers a non-call reference such as
  `let f = probe_call::<u8>;` (EC-4).
- Comments between the pieces are already discarded by the scanner, so they
  do not affect recognition (EC-5).
- Uniqueness: the count across both shapes must be exactly 1. Otherwise
  `locate_call` returns `Err`, with the same meaning as today's
  "expected exactly one call" failure.

### 4. Anchoring only the plain shape (SPEC as-2)

Steps 3 and 4 (paren walk, argument count, returned offsets) still anchor
only the plain shape, starting from the `(` right after the callee token.
When the single counted occurrence is a turbofish call, `locate_call`
returns an explicit `Err`. It never starts the paren walk from a token other
than the callee's own `(`. This keeps today's `Err` result for a body whose
only call is `probe_call::<u8>(a, b, c, d)`.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, FR5; SPEC AC-1, AC-6; TS-1, TS-6):
  - A body with `r#probe_call(w, x, y, z); probe_call(a, b, c, d);` returns
    `Err`.
  - A body whose only call is `r#probe_call(a, b, c, d);` returns `Ok`. The
    argument text is `a, b, c, d`, and the source up to `callee_end` ends
    with `r#probe_call`.
- [ ] AC-2 (FR2; SPEC AC-2, AC-3; TS-2, TS-3, EC-1): each of these bodies
  returns `Err`. Each one pairs `probe_call(a, b, c, d);` with a second
  call written after a numeric literal:
  - `let r = 0..probe_call(k);`
  - `self.0.probe_call(x);`
  - `let r = 0..=probe_call(k);`
- [ ] AC-3 (FR2; SPEC AC-7; TS-7, EC-2): these single calls anchor as `Ok`:
  - `probe_call(1.5, 1.0f32, 1e10, 0x1F)`, with 4 arguments and argument
    text exactly `1.5, 1.0f32, 1e10, 0x1F`.
  - A call whose first argument is the tuple index `x.0.1`, followed by
    three plain arguments. It has 4 arguments and the argument text matches
    exactly.
- [ ] AC-4 (FR3; SPEC AC-4; TS-4, EC-3, EC-5): each of these bodies returns
  `Err`. Each one pairs `probe_call(a, b, c, d);` with one turbofish call:
  - `probe_call::<u8>(w, x, y, z);`
  - `probe_call::<Vec<u8>>(w, x, y, z);` (nested generics)
  - a turbofish call with block comments between the callee name and `::`,

- [ ] AC-5 (FR3; SPEC as-2, EC-4):
  - The body `let f = probe_call::<u8>; probe_call(a, b, c, d);` returns

## Test Notes

  in-memory sources. Run them with
  `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib anchor_locate_call`
  from the worktree root. The tests live in the library target (`--lib`).
- Tests that fail before the change (red first):
  - TS-1 and TS-6 (AC-1)
  - TS-2 and TS-3 (AC-2)
  - TS-4, the nested-generics case and the comment case (AC-4)
  - TS-5 and the single `fn r#probe_fn` case (AC-6)
- Tests that already pass before the change are guards against a wrong
  implementation. They are not red tests. Write them anyway:
  - EC-1 `0..=` (AC-2): today the literal ends at `=`, so the callee already
    survives.
  - TS-7 and EC-2 (AC-3): guard against a boundary rule that breaks floats,
    suffixes or tuple indices.
  - EC-4 and the turbofish-only case (AC-5): guard against counting non-call
    turbofish references and against anchoring from `::`.
  - The `r#fn` case (AC-6): guards against removing `r#` before the keyword
    check.
- AC-7 is the existing suite plus a diff-scope check. Run the
  `anchor_locate_call` filter above and the `button_path_` filter. Before
  finishing, run the full `--lib` suite once.
- AC-8 is a comment-only change and does not become a unit test. Verify it
  by searching the file text for both paths.
