# Task Plan: task0001 — Budget regression guards for repeated non-SIXEL DCS

## Goal

Every mux daemon path that scans PTY output has a test that runs the input
`(ESC P x)*N` + `ESC \` at a size where a quadratic scan would exceed the 10 s
budget by orders of magnitude, and each test finishes within the budget with
the input written unchanged. Production code changes only if one of these
tests shows non-linear behavior.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create
- `src-tauri/src/mux/ipc/pty_spawn/tests/strip_non_sixel_dcs_linear.rs` — the feature's test module: the input generator and the budget tests of FR1 to FR6
- `test-docs/mux-strip-non-sixel-dcs-linear/task0001.tests.yaml` — the per-task test record (FR8)

### Files to Modify
- `src-tauri/src/mux/ipc/pty_spawn/tests.rs` — register the new module after the existing feature modules, with a one-line comment naming the feature, the task and the FRs, as the existing registrations do

- `src-tauri/src/mux/ipc/pty_spawn/write_filter.rs` — only when FR7 applies: make the boundary scan or the overflow flush linear for the input
- `src-tauri/src/mux/ipc/pty_spawn/client_parity_scan.rs` — only when FR7 applies: make the client-parity scan linear for the input
- `src-tauri/src/mux/ipc/pty_spawn/suppressed_output.rs` — only when FR7 applies: make the suppressed replacement preparation linear for the input

## Design

Cross-task conventions (the input, the budget, the sizes, test identity, the
record) are in IMPLEMENTATION.md and are not restated here.

### The input generator

- One generator in the new module produces the input for a requested total
  length: N repetitions of the unit `ESC P x` followed by one `ESC \`.
- Every test builds its input from it, so every test exercises the same shape.

### Existing harnesses reused

| Harness | Location | Used by |
|---------|----------|---------|
| Shared 10 s budget constant | the `post_strip_cut_csi` test module (other modules import it) | every budget assertion |
| Detached production reader: chunks in, ring out | `run_reader_without_owner` in the `round3_write_path` test module | AC-4 |
| Production reader with suppressed reads: chunks and suppressed read indices in; received chunks, stand-in snapshots and ring out | `run_reader_with_suppressed_reads` in `tests.rs` | AC-5 (FR6 half) |
| Write filter dimensions constant | the `round3_write_path` test module | AC-2 |

### Paths and observations

| AC | Entry point | Feeding | Observations |
|----|-------------|---------|--------------|
| AC-1 | `strip_replayable_rich_content`, `strip_pty_output_for_scrollback_write`, `strip_rich_content_and_remap` with ascending watch offsets spread over the input, `strip_pty_output_for_scrollback_write_with_written_state` with no pending designator and a ground state | one call each on the 2 MiB input | output equals the input byte for byte; each call within the budget |
| AC-2 | `ScrollbackWriteFilter` | (a) the whole input with the chain just under the pending cap, in one call; (b) the same chain in pieces of at most 65,536 bytes; (c) a chain past the cap, so the overflow flush runs | concatenated emitted bytes equal the input; pending is empty after the trailing ST; each case within the budget |
| AC-3 | `build_snapshot_bytes`, `build_resume_snapshot_bytes` | a 2 MiB scrollback of the input, a main-buffer pane, several dimension segments whose offsets are spread over the input (some inside a unit) | the scrollback part of the payload (between the builder's fixed prefix and anything after the scrollback) equals the input; mapped segment offsets are non-decreasing and within the payload; each build within the budget |
| AC-4 | `run_reader_without_owner` | reads of at most 65,536 bytes; total length covering the pending-cap range and at most the 2 MiB ring capacity | the ring equals the input; the run within the budget |
| AC-5 (FR5) | `client_parity_scan::scan`, called directly with an empty window | the 2 MiB input as one chunk, (i) with no excluded pieces, (ii) with excluded pieces (ascending, non-overlapping, chunk coordinates, e.g. the suffix a held chain would occupy) | no item in either call; no tail in (i); each call within the budget |
| AC-5 (FR6) | `run_reader_with_suppressed_reads` | reads of at most 65,536 bytes; one suppressed read after which the write filter still holds the chain (non-empty pending, the scan with excluded pieces); one suppressed read that carries the trailing ST (empty pending after it, the scan with no excluded pieces) | the ring equals the input; the only empty PtyOutput chunk is the EOF marker; the run within the budget |

### Processing flow of one budget case

1. Build the input at the case's size.
2. Record the start time.
3. Run the entry point as the table states.
4. Assert the observations, then assert the elapsed time is below the budget,
   with the case name and the elapsed time in the message.

### FR7 branch (only on evidence)

1. A case exceeds the budget or its time grows faster than linearly with the
   input size.
2. Identify the scan that re-walks bytes for the input.
3. Make it linear without changing which constructs it removes or keeps
   (a non-SIXEL DCS byte for byte, a SIXEL DCS removed as before).
4. Every new case passes and the full `--lib` run stays green.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR1, NFR1, TM-1, TM-2): each of the four shared strip entry points, called once on the 2 MiB input, finishes within the 10 s budget and returns the input unchanged byte for byte.
- [ ] AC-2 (FR2, NFR1, TM-1): `ScrollbackWriteFilter` fed the input in one call with the chain just under the pending cap, in pieces of at most 65,536 bytes with the chain just under the cap, and past the cap (the overflow flush) finishes each case within the 10 s budget; the concatenated emitted bytes equal the input and pending is empty after the trailing ST.
- [ ] AC-3 (FR3, NFR1, TM-1): `build_snapshot_bytes` and `build_resume_snapshot_bytes` on a 2 MiB scrollback of the input with dimension segments each finish within the 10 s budget; the scrollback part of each payload equals the input, and the mapped segment offsets are non-decreasing and within the payload.
- [ ] AC-4 (FR4, NFR1, TM-1): the Detached production reader driven with the input in reads of at most 65,536 bytes over the pending-cap range finishes within the 10 s budget and its ring equals the input.
- [ ] AC-5 (FR5, FR6, NFR1, TM-1): `client_parity_scan::scan` called directly on the 2 MiB input finishes within the 10 s budget with and without excluded pieces and reports no item, and reports no tail without excluded pieces; the production reader with suppressed reads runs one suppressed read with non-empty pending and one with empty pending within the 10 s budget, its ring equals the input, and it sends no empty PtyOutput chunk other than the EOF marker.
- [ ] AC-6 (FR7, NFR4, TM-2): when AC-1 to AC-5 pass at HEAD, the task changes no production source file (only the new test module, the module registration and the test-docs record); when a production change is needed, AC-1 to AC-5 pass after it and every existing test stays green.
- [ ] AC-7 (FR8): `test-docs/mux-strip-non-sixel-dcs-linear/task0001.tests.yaml` lists every new test under the acceptance criterion it verifies, with `red_confirmed: false` and a `red_reason` stating that the quadratic scan was already resolved before this feature (`scan_body_end` and `find_st` stop at the first ESC), so the tests are regression guards that were green from the start.
- [ ] AC-8 (NFR2, NFR3): every new test is a plain `#[test]` without `#[ignore]`, no dependency is added, the full `--lib` test run passes and the `--no-default-features` cargo check succeeds.

## Test Notes

- AC-1 to AC-5 are tests in the new module; AC-1, AC-2, AC-3 and the FR5 half
  of AC-5 call the entry points directly, AC-4 and the FR6 half of AC-5 drive
  the production reader thread through the existing harnesses.
- AC-6 and AC-8 are verified by the full `--lib` run, the
  `--no-default-features` check and the task's diff; AC-7 by the record's
  content.
- Red phase: SPEC A1 and A3 expect every new test to pass at HEAD, so no red
  state is observable and the record says so (FR8). If a new test fails at
  HEAD, that is the FR7 branch: record the observed failure as it happened
  instead of the FR8 `red_reason`, and report the difference from SPEC A1 as a
  plan deviation.
- Stronger checks that follow from "nothing is removed" and may be asserted:
  each watch offset of `strip_rich_content_and_remap` maps to itself, and the
  state form reports ground after the trailing ST.
- FR6 branch selection is established by construction: where the read
  boundaries fall relative to the chain and the trailing ST decides which
  suppressed read sees non-empty pending. The test's doc comment states which
  read takes which branch.
- The suppressed-reads harness uses a capacity-16 channel with no consumer
  until join: keep the number of delivered chunks (PtyOutput chunks, stand-in
  snapshots, replacement output and the EOF marker) within that capacity, or
  the reader blocks and the join never returns.
- Keep the number of passes over each 2 MiB input small; the lib tests run as
  a debug build.
- During development run the new module alone with a test-name filter; run
  the full `--lib` suite once at the end.

## Out of Scope

- Any production change when AC-1 to AC-5 pass at HEAD.
- Other input shapes (SIXEL DCS, Kitty APC, OSC and CSI chains): earlier
  features' budget tests cover them.
- Renaming or removing any existing test or symbol (SPEC A6).
- Formatting files this task does not touch, release builds, E2E or manual
  checks.
