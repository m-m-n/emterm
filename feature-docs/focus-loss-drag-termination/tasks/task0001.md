# Task Plan: task0001 — Gate focus-loss drag termination on the left button

## Goal

Focus loss stops destroying a left selection drag the user is still physically
performing: the focus-loss arm terminates the live local left drag only when
the left button is not held, the decision is a pure window-free predicate with
a unit-tested truth table, and the arm's fidelity to that predicate is pinned
by the structural source-text assertion.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR7, FR8, NFR1, NFR2, NFR3, NFR4, NFR5, NFR6

## Scope

### Files to Create

None. This task modifies existing files only.

### Files to Modify

- `src-tauri/src/window_host/pointer_routing.rs` — add the new pure termination predicate as a sibling of the existing drag-state helpers, with module-internal visibility; the existing helpers keep their signatures and meaning
- `src-tauri/src/window_host/event_loop.rs` — in the focus-loss arm, read the left-held state before the decision layer's clear routine runs and gate the local-drag publish on the new predicate; everything else in the arm stays as it is
- `src-tauri/src/window_host/tests.rs` — replace the structural needle set with literals of the rewritten arm, keep the fold-click negative assertion, and add the predicate's truth-table and state-shape tests
- `src-tauri/src/window_host/mouse_report.rs` — comment only: tie the existing no-owner left-release test to this feature's delegation of the preserved drag's termination; no behaviour, signature or byte sequence changes here

## Design

Contracts for the new predicate, the existing helpers it composes with, the
clear routine and the no-owner release fallback are pinned in
IMPLEMENTATION.md's Shared Components table; the ordering invariant, the
predicate's home, the delegation decision and the no-state-shape-change rule
are decisions D2, D3, D4 and D5 there. This section states only what is
specific to carrying them out.

### Decision flow inside the focus-loss arm

1. The arm begins exactly as it does today: it records that the window is no
   longer focused and performs the existing IME-focus notifications.
2. Before anything clears the pointer bookkeeping, the arm reads the left slot
   of the host's event-derived held-button record into a plain bool. This read
   is the arm's only new state access.
3. The arm evaluates the termination predicate over the local drag-in-flight
   signal and that bool.
4. When the predicate says "terminate", the arm calls the local-drag publish
   routine exactly as today: the drag flag is cleared, the pending selection
   anchor is consumed, and any materialized selection is published to PRIMARY
   (and to CLIPBOARD when copy-on-select is on).
5. When the predicate says "do not terminate", the arm publishes nothing: no
   PRIMARY write, no CLIPBOARD write, no fold-click toggle. The drag flag stays
   set and the pending anchor stays in place, so the drag continues when focus
   returns.
6. The remainder of the arm runs unchanged and in its current order: the
   modifier reset, the pointer-buttons-down reset, the decision layer's clear
   routine, the link-cursor update, and the trailing redraw requests.

The preserved drag is terminated later by the release path: because the clear
routine has emptied the gesture-ownership record, the eventual left release is
a no-owner release and takes the existing local-completion fallback when the
drag-in-flight input is true. No new terminator is added.

### The predicate

A pure function over plain bools in the pointer-routing layer. It returns
"terminate" only for the combination "a local left drag is in flight AND the
left button is not held"; every other combination returns "do not terminate".
It mutates nothing, performs no I/O, and its signature mentions no windowing,
GPU, PTY or terminal-mode type. Whether it takes the composed drag-in-flight
signal or the two bools that signal is built from is the implementer's choice,
provided the inputs stay plain bools and the truth table below holds.

### The structural assertion

The existing assertion reads the event-loop module's source at compile time and
checks a set of literal needles plus the negative assertion that the arm never
reaches the fold-click toggle. The needle set is replaced — not extended — with
literals that actually occur in the rewritten arm and that together pin: the
call to the new predicate, and the held-button read. Each needle must be
specific enough that the pre-change composition could not have satisfied it,
so a needle that is merely a prefix of a longer stale expression is unusable.
The fold-click negative assertion is preserved verbatim.

## Test Notes

- **Write the tests first.** AC-1 and AC-2 are ordinary unit tests over the
  predicate and can be written before the predicate exists. AC-4's structural
  assertion can only be finalized once the arm's new wording is settled, so the
  workable order is: predicate tests, predicate, arm rewrite, needle
  replacement.
- **Placement and naming**: the predicate's tests belong next to the existing
  drag-state truth-table test in the window-host test module, as bare unit
  tests named subject-scenario-expected, each constructing its own inputs. No
  new test framework, no shared fixture.
- **The arm itself is not behaviourally testable.** Driving it end to end needs
  a window the test layer does not have. That is why AC-3 and AC-4 are
  discharged structurally: the unit tests prove the decision, the structural
  assertion proves the arm calls it in the composed form the decision expects,
  including the ordering of the held-button read.
- **Needle selection is the subtle part.** Choose literals that cannot occur in
  the pre-change arm. A needle that is a prefix of a longer stale expression
  passes vacuously and destroys the value of the assertion; the SPEC records
  this explicitly.
- **Existing coverage to leave alone**: the no-owner left-release test already
  proves the preserved drag's terminator, and the clear-routine tests already
  prove both records are emptied. They must pass unchanged; the only edit
  permitted to them is the explanatory comment naming this feature's delegation.
- **Run commands** are the project's declared ones, listed in VERIFICATION.md;
  the test run is single-threaded because some existing replay tests are
  non-deterministic under parallelism.

## Out of Scope

- Any additional terminator for a genuinely lost release: no focus-regained
  check, no first-motion-after-refocus check, no separate selection-side press
  record. The residual leak is accepted and self-healing (IMPLEMENTATION.md D4).
- Changing the prior feature's SPEC document, or any other feature's documents.
  The supersession is already recorded in this feature's own SPEC.
- Any state-shape change: no new field on the host or app state, no field type
  change, no change to the existing drag-state helper signatures.
- Any change to mouse-report byte sequences, to the wheel-report notch clamp,
  to target-tab selection, or to the fold-click path.
- Any UI, styling or design-token change, and any refactor of the release path
  beyond the explanatory comment.
- Adding a test framework, a benchmark harness or E2E automation.
