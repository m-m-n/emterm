# Task Plan: task0001 — Narrow the ring_push_blank redundancy NOTE to the overflow clear pair

## Goal

The redundancy NOTE on `test_ring_push_blank_clears_recycled_row_overflow_entries`
attributes "always a no-op" only to Step 3's overflow clear pair, and records
that Step 3's cell fill and `ring_wrapped` reset have no eviction-side
counterpart and are therefore required.

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2, NFR3

## Scope

### Files to Create

Nothing. This task creates no files.

### Files to Modify

- `crates/term_core/src/ring_buffer/tests.rs` — the NOTE attached to
  `test_ring_push_blank_clears_recycled_row_overflow_entries`: its concluding
  claim is narrowed, and one or two sentences recording the required (non-
  redundant) Step 3 actions are appended. Comment text only.

## Design

### Locating the target

Find the NOTE by the enclosing test's name
(`test_ring_push_blank_clears_recycled_row_overflow_entries`), not by line
number — the line numbers quoted in SPEC.md and REQUIREMENTS.md are a snapshot
and may have drifted. The NOTE is the comment block at the end of that test; its
final sentence is the conclusion being narrowed.

### What the corrected NOTE must assert

The factual model is pinned in IMPLEMENTATION.md, "D2: The attribution model the
corrected NOTE must express" — read it there rather than re-deriving it. In
summary, the revised text must leave a reader able to answer, for each of Step
3's three actions, whether it duplicates work the eviction side already did:

| Step 3 action | Eviction-side counterpart | How the NOTE must present it |
|---|---|---|
| Clearing the overflow / overflow-row-index pair for the new bottom row | Yes — Step 1 clears exactly this pair for the evicted row, in all three of its branches | Redundant within a single push; this is the only action the "always a no-op" statement covers |
| Filling the new bottom row's cells | None | Required, not redundant |
| Resetting the new bottom row's `ring_wrapped` flag | None — the eviction side only reads that flag, it never resets it | Required, not redundant |

### What must survive unchanged

The NOTE's existing reasoning stays as it is: the identification of the two
clearing sites, the evaluation order (the evicted absolute row is captured
before Step 1, the ring head rotates in Step 2, the new bottom absolute row is
derived in Step 3), and the resulting conclusion that the two are the same ring
slot whenever at least one row is pushed. That premise is correct. Only the
sentence that generalises from it is narrowed, and the new sentences are
appended after it.

### Editing constraints

Comment text only, inside the one file named above. No production source, no
assertion, no fixture, no test name, no test added or removed. New lines follow
the surrounding NOTE's wrap width and the English declarative register described
in IMPLEMENTATION.md, "Conventions".
