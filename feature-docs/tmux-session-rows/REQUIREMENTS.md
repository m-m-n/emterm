# 稼働している tmux の識別を session 名で行う - 要件定義書

## 1. 概要

### 1.1 背景
「+」ボタンで開く新規タブ chooser には、稼働中の tmux がソケット単位（ソケットファイル名）で表示される。tmux の既定サーバーを使っている場合、ソケット名は常に `default` になるため、そのサーバー内に複数のセッションがあっても chooser 上は `default` の 1 行しか出ず、どのセッションなのかを区別できない。

### 1.2 目的
chooser の tmux 行の識別子を、ソケット名ではなく tmux セッション名にする。複数セッションが稼働している状態で、どのセッションに入るのかを選べるようにする。

### 1.3 スコープ
- 生存ソケットごとの tmux セッション列挙
- chooser への「セッション 1 行」表示（ソケット 1 行から置き換え）
- 選択したセッションを指定してアタッチする新規タブの起動

## 2. ビジネス要件

### 2.1 ビジネス目標
複数の tmux セッション（例: Notion 起点で起動された複数の Claude Code 実行）が同一サーバー上に並んでいるとき、eMterm の +メニューから目的のセッションを直接選んでモニタリングできるようにする。

### 2.2 対象ユーザー
| ユーザータイプ | 説明 |
|----------------|------|
| eMterm 利用者 | 複数の tmux セッションを並行して走らせ、状況を確認したい開発者 |

### 2.3 期待される効果
- chooser 上で稼働中セッションの一覧と名前が分かる
- 目的のセッションへ直接アタッチできる（アタッチ後に `Ctrl-b s` で切り替える手間が消える）

## 3. ユースケース

### 3.1 ユースケース一覧
| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | セッションを選んでアタッチする | 利用者 | 高 |
| UC02 | 稼働中セッションの一覧を確認する | 利用者 | 高 |

### 3.2 ユースケース詳細

#### UC01: セッションを選んでアタッチする

**アクター**: 利用者

**事前条件**:
- tmux サーバーが稼働し、1 つ以上のセッションが存在する

**基本フロー**:
1. 利用者がタブバー右上の「+」ボタンをクリックする
2. chooser に既存項目（Global Settings / プロファイル）に加えて、稼働中の tmux セッションが 1 セッション 1 行で表示される
3. 利用者が目的のセッション行をクリックする
4. 新規タブが開き、そのセッションにアタッチされた状態になる

**代替フロー**:
- セッション列挙に失敗したソケットは、従来どおりソケット単位の 1 行として表示され、選択時はセッション指定なしでアタッチする
- 稼働中のソケットが 1 つも無い場合、tmux 行は表示されない（既存の chooser 挙動のまま）

**事後条件**:
- 新規タブ内の tmux クライアントが、選択したセッションにアタッチされている

#### UC02: 稼働中セッションの一覧を確認する

**アクター**: 利用者

**基本フロー**:
1. 利用者が「+」ボタンをクリックする
2. chooser に稼働中セッション名が一覧表示される
3. 利用者は一覧を確認して chooser を閉じる（アタッチしなくてもよい）

## 4. 機能要件

### 4.1 機能一覧
| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| F01 | セッション列挙 | 生存ソケットごとに tmux セッション名を列挙する | 高 |
| F02 | セッション行の表示 | chooser に 1 セッション 1 行で表示し、セッション名で識別できるようにする | 高 |
| F03 | セッション指定アタッチ | 行の選択でそのセッションを指定してアタッチする新規タブを開く | 高 |

### 4.2 機能詳細

#### F01: セッション列挙

**説明**: 既存のソケット検出（`$TMUX_TMPDIR`、未設定時は `/tmp/tmux-{uid}/` 配下の生存ソケット列挙）の結果を入力とし、各ソケットに対して tmux にセッション名を問い合わせる。

**入力**:
- 生存ソケットのリスト（ソケット名 + 絶対パス）

**出力**:
- (ソケット名, ソケットパス, セッション名) の組のリスト

**ビジネスルール**:
- ソケット検出そのもの（種別判定・接続確認・stale 除外）は既存の挙動を変えない
- 問い合わせは生存が確認できたソケットに対してのみ行う
- 表示順は決定的にする（ソケット名 → セッション名の順）

**エラーケース**:
| エラー | 条件 | 対応 |
|--------|------|------|
| tmux コマンド不在 | PATH に tmux が無い | 該当ソケットはソケット単位の 1 行にフォールバックする |
| 問い合わせ失敗・タイムアウト | サーバーが応答しない等 | 該当ソケットはソケット単位の 1 行にフォールバックする |
| セッション 0 件 | 応答はあるがセッションが無い | 該当ソケットはソケット単位の 1 行にフォールバックする |

#### F02: セッション行の表示

**説明**: chooser の tmux 行を、ソケット単位から セッション単位に置き換える。

**ビジネスルール**:
- chooser を開くたびに再列挙する（常駐監視はしない）
- 表示ラベルはセッション名で識別できる形式にする
- 既定ソケット以外のソケットのセッションは、ソケット名も併記して衝突しないようにする
- 検出 0 件なら tmux 行を表示しない（既存挙動のまま）
- 行の見た目・キーボード操作・選択位置の既存挙動は変えない

#### F03: セッション指定アタッチ

**説明**: セッション行の選択確定で新規タブを起動し、そのタブの PTY で対象セッションを指定した tmux アタッチを実行する。

**ビジネスルール**:
- セッション名はコマンド引数として直接渡す（シェル文字列連結をしない）
- セッション名の指定は完全一致で行う（部分一致で別セッションに入らない）

**エラーケース**:
| エラー | 条件 | 対応 |
|--------|------|------|
| 選択後にセッション消滅 | 列挙〜クリックの間に終了した | tmux 自身のエラー出力がタブ内に表示される（専用ハンドリングはしない） |

## 5. 非機能要件

### 5.1 パフォーマンス要件
- セッション列挙は chooser 表示を体感で遅延させない。ソケットごとに問い合わせのタイムアウトを設け、応答しないソケットが chooser を止めないようにする

### 5.2 セキュリティ要件
- 列挙・アタッチともに、パス・セッション名をコマンド引数（argv 要素）として渡す。シェル経由の文字列展開をしない
- 走査対象は自 UID のソケットディレクトリのみ（既存どおり）

### 5.4 保守性要件
- ログ出力: 列挙失敗等は既存の logging 機構（env_logger）に従う

### 5.5 互換性要件
- Unix（Linux）専用機能とし、Windows ビルド・CLI-only ビルド（`--no-default-features`）を壊さない

## 6. UI/UX要件

### 6.1 画面設計要件
既存の new-tab chooser モーダルの行の内容（ラベル文字列）と行数が変わるのみ。新規画面・新規コンポーネント・新規の視覚要素は作らない。

## 9. 制約条件

### 9.1 技術的制約
- 既存の chooser（`profile_selector`）、ソケット検出（`tmux_sockets`）、PTY 起動 API（`SpawnOverrides` / `spawn_new_tab_with_overrides`）を利用する
- 既存機能で「検出時に外部プロセスを起動しない」としていた制約は、セッション名を知る唯一の手段が tmux への問い合わせであるため、生存ソケットに限定した問い合わせに緩和する

## 11. 成功基準

### 11.1 受け入れ基準
- [ ] 複数の tmux セッションがある状態で区別が可能

### 11.2 詳細な受け入れ基準
- [ ] 同一サーバー上に複数セッションがあるとき、chooser にセッションごとの行が出る
- [ ] 行のラベルからどのセッションかが分かる
- [ ] 行を選ぶとそのセッションにアタッチされる
- [ ] セッション 0 件・列挙失敗時も chooser が壊れない

## 12. テストシナリオ

### 12.1 テスト観点
- [ ] 正常系: 複数セッションが列挙され、選択でそのセッションを指定したアタッチコマンドの新規タブが起動する
- [ ] 異常系: tmux 不在・問い合わせ失敗・タイムアウト・セッション 0 件でソケット行にフォールバックする
- [ ] 境界値: ソケット 0 件（行なし）・複数ソケット × 複数セッション（全件表示）・セッション名の重複
- [ ] 互換性: Windows ビルド・CLI-only ビルドがコンパイルできる
- [ ] 非退行: 既存 chooser の行順・キーボード操作・既定プロファイル選択が変わらない

## 13. 用語定義

| 用語 | 定義 |
|------|------|
| tmux ソケット | tmux サーバーとクライアントが通信する Unix ドメインソケット。既定サーバーのソケット名は `default` |
| tmux セッション | 1 つの tmux サーバー内で独立したウィンドウ集合を持つ単位。`tmux new -s {name}` で名前を付けられる |
| chooser | eMterm の「+」ボタンで開く新規タブ選択モーダル |
