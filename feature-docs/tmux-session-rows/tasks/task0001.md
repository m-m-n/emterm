# Task Plan: task0001 — tmux session enumeration, session rows, and session-targeted attach

## Goal

The new-tab chooser lists one row per live tmux session instead of one row per tmux socket, and confirming a row opens a new tab attached to exactly that session. A socket whose sessions cannot be listed still appears as today's single socket row with today's attach behavior.

## Requirements

FR1, FR2, FR3, FR4, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create
- None.

### Files to Modify
- `src-tauri/src/tmux_sockets.rs` — add session enumeration on top of the existing socket discovery: query each live socket's tmux server for its session names under a bounded wait, parse the response, degrade to a fallback entry on any failure, and expose the ordered entry list plus the label and attach-argument rules from IMPLEMENTATION.md Shared Components. Existing socket-discovery behavior stays as it is.
- `src-tauri/src/ui/profile_selector.rs` — hold the new entry list instead of the socket-name/path pair list, render each entry's label via the shared label rule, and keep the row-index decode (`row_to_choice` / `Choice::Tmux`) as the single authority for the `Global → profiles → tmux` ordering.
- `src-tauri/src/app.rs` — call enumeration when the chooser opens, hand the entry list to the selector, count rows from it, evaluate the skip-the-modal fast path against it, and build the spawn overrides for a confirmed entry via the shared attach-argument rule. Keep the non-Unix stub returning an empty list.

## Design

### Discovery: from live sockets to chooser entries

1. Run the existing socket discovery unchanged, yielding the live sockets (socket-type entries in the resolved socket directory that accept a Unix-domain connection).
2. For each live socket, in a deterministic order, ask that socket's tmux server for its session names by running the tmux binary with an argument vector consisting of the socket flag, the socket's absolute path, the list-sessions subcommand, and a format flag whose value selects only the session name. No shell is involved.
3. Wait for the child under a bound of at most 300 ms. If the child finishes in time and reports success, treat its standard output as the response; otherwise the socket is un-enumerable. On expiry, terminate the child and reap it so no zombie remains.
4. Parse a successful response as one session name per line, ignoring empty lines and trailing whitespace, preserving each name's characters verbatim otherwise. Zero usable names means the socket is un-enumerable.
5. Emit one entry per parsed session name for an enumerable socket; emit exactly one fallback entry (socket name and path, no session) for an un-enumerable socket.
6. Order the result by socket name, then by session name; a fallback entry occupies its socket's position.

Failure taxonomy — every one of these produces the fallback entry, never an error and never a panic: the tmux binary is absent from the search path, the spawn itself fails, the child exits non-zero, the child exceeds the bound, the output is empty, or the output contains no non-empty line.

### UI: rendering and decoding

The selector holds the entry list handed to it by the Application layer and renders each entry using the shared label rule. The list is appended after the Global Settings row and the profile rows, unchanged from today. The row-index decode continues to be the only place that knows the synthetic-row offsets, so the renderer and the confirm path cannot disagree about which entry a row index means.

### Application: opening and confirming

Opening the chooser runs discovery plus enumeration afresh; there is no caching and no background watcher. The skip-the-modal fast path applies only when there are no profiles and the entry list is empty. Confirming a tmux row resolves the row to an entry and spawns a new tab through the existing overrides path using the shared attach-argument rule; a missing entry index spawns nothing.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: For a socket whose server reports several session names, enumeration yields one entry per name, carrying the name verbatim, and the entry list is ordered by socket name then session name. Empty and whitespace-only lines in the response produce no entries.
- [ ] AC-2: Each failure mode — tmux binary absent, spawn failure, non-zero exit, empty or name-less output — yields exactly one fallback entry for that socket and no error or panic.
- [ ] AC-3: A socket whose server never answers is abandoned within the 300 ms bound and yields a fallback entry; the child process is terminated and reaped rather than left running or left as a zombie.
- [ ] AC-4: The label rule produces `tmux: {session}` for a session on the socket named `default`, `tmux: {socket}: {session}` for a session on any other socket, and `tmux: {socket}` for a fallback entry.
- [ ] AC-5: The attach-argument rule produces, for a session entry, the tmux executable with arguments naming the socket path, the attach-session subcommand, the target flag, and the session name carrying tmux's exact-match marker; and for a fallback entry, the socket path with the plain attach subcommand. Every value is a separate argument; no value is a shell string.
- [ ] AC-6: With tmux entries present, the row-index decode maps each row to the correct entry with the `Global → profiles → tmux` ordering intact; the row count equals profiles plus entries plus the Global row; and the skip-the-modal fast path fires only when profiles and entries are both empty.
- [ ] AC-7: Existing socket-discovery behavior and existing chooser behavior are unchanged: the socket-type filter, stale-socket rejection, missing-directory tolerance, socket-directory resolution, default-profile preselection, and keyboard wrap-around all keep their current semantics and their existing tests keep passing without being weakened.

## Test Notes

- AC-1, AC-2, AC-4, AC-5, AC-6 are unit-testable as pure functions once parsing, the label rule, and the argument rule are separated from the process spawn. Drive them from response text and entry values rather than from a real tmux server.
- AC-3 needs a child that does not answer. Prefer a stand-in command that sleeps over depending on a real tmux install, and assert both that the call returns within a margin of the bound and that no child survives it.
- AC-2's "tmux binary absent" case is best exercised by pointing the enumeration at a command name that cannot resolve, rather than by mutating the test process's search path globally.
- Edge cases worth explicit tests: a session name that is a prefix of another (the exact-match marker must be what distinguishes them), a name containing a space, a non-ASCII name, and the same session name existing on two different sockets.
- The existing tests in the touched modules are the regression net for AC-7; they must be updated only where the entry-list shape forces it, never relaxed in what they assert.

## Out of Scope

- Caching enumeration results or watching tmux in the background.
- Showing anything beyond the session name in a row (window counts, attached-client state, activity, creation time).
- Sockets created at arbitrary paths outside the standard socket directory.
- Any change to eMterm's own built-in mux subsystem — attaching stays a plain PTY spawn.
- Windows support for this path.
