## Findings to resolve (from reviews/round1.yaml)

### b8f4473ba546db63 / 1a56eee65f8b253c (high, comprehensive + security) — release.yml:49

**Title**: semver `case` グロブを通過する文字列で sed コマンド注入が成立する

**Description**: loop 2 で入れた `case "$VERSION" in [0-9]*.[0-9]*.[0-9]*)` は
プレフィックスグロブで、`1.2.3";echo${IFS}X/e;}#` 等が通過し GNU sed の `e`
コマンド経由の任意コマンド実行が PoC で再現済み。実行先は
`contents: write` + `git push origin HEAD:main` の特権ジョブ。

**Suggestion**: アンカー付き正規表現による全文一致検証に置き換える
（`[[ "$VERSION" =~ ^[0-9]+\.[0-9]+\.[0-9]+([-+][0-9A-Za-z.-]+)?$ ]]` /
`grep -Eq` 等。エラーメッセージに値そのものを含めない）。可能なら値を
sed/awk のプログラムテキストに埋め込まない形（awk `ENVIRON` 等）へ寄せる。

### 28af69c7ff93f357 (high, spec) — release.yml:20

**Title**: tag 無し dispatch は「skip」ではなく job 失敗 + continue-on-error
で、NFR2 と FR3 の順序保証のどちらかを必ず壊す

**Description**: SPEC NFR2 の許容挙動は (a) job を skip する / (b) tag input
から解決する、の 2 択。現実装の exit 1 + `continue-on-error: true` は、
本当の失敗（push 拒否・注入拒否）でもリリースが進んでしまい FR3 の順序保証
が silent に失われる。

**Suggestion**: sync-version に job-level
`if: ${{ github.event.inputs.tag != '' || startsWith(github.ref, 'refs/tags/') }}`
を付け、`continue-on-error: true` を外し、create-release に
`if: ${{ always() && needs.sync-version.result != 'failure' && needs.sync-version.result != 'cancelled' }}`
を付ける（skip は通し、real failure はブロックする）。step 内の fail-closed
`exit 1` ガードは保険として残してよい。
