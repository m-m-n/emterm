# Task Plan: task0005 — Status bar template variable {agent_status}

## Goal

The status bar template gains `{agent_status}`: the state word of the active
tab's composite aggregate (the tab itself plus, while mux-attached, every
pane of its window group), empty when there is none, re-rendered whenever
that value changes.

## Requirements

FR13, NFR5

## Scope

### Files to Create
- `src-tauri/src/status_bar/providers/agent_status.rs` — the agent_status variable provider: holds the current value, bumps its version and wakes the frame on change; unit tests in the same file, following the sibling providers.

### Files to Modify
- `src-tauri/src/status_bar/providers/mod.rs` — export the provider.
- `src-tauri/src/status_bar/runtime.rs` — register the provider with the template engine and expose a shared handle, the way the cwd provider is exposed.
- `src-tauri/src/app/mod.rs` — refresh the provider's value from the active tab before the status bar view model is built.
- `src-tauri/src/app/agent_status.rs` — the helper that computes the active tab's aggregate word with the same keys the tab badge uses.
- `src-tauri/src/app/tests/agent_status.rs` — integration tests for the value, mux aggregation and tab switching.

## Design

Contracts used: SC-4 (aggregate over pane keys) and SC-2 (the state's word
is its display form). FR13 / A11 fix the value set.

- Value: the display word of the composite aggregate over the active tab's
  agent-status keys — the same key set the tab badge aggregates (the tab's
  own key plus, while mux-attached, every pane of the window group). No
  aggregate → empty string.
- Provider: named `agent_status`; returns the stored value; its version
  advances, and the shared wake function fires, only when a newly set
  value differs from the stored one. The provider never reads terminal
  data itself; its only input is the value App sets.
- Refresh point: App sets the value each time it builds the status bar
  view model, so tab switches, tab closes, mux window switches and
  agent-status batches are all reflected without separate hooks; setting
  an unchanged value is free of side effects.
- Default templates are unchanged.
- The value comes from the state vocabulary only, never from names,
  titles or other terminal-supplied text (NFR5).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Registration (FR13): a template containing `{agent_status}` resolves through the runtime's engine to the provider's current value, and the default templates do not contain the variable.
- [ ] AC-2: Value (FR13, A11): the value is the word of the active tab's composite aggregate over the same keys the tab badge uses — including the panes of a mux-attached tab's window group — and the empty string when no key carries a state.
- [ ] AC-3: Change detection (FR13): setting a different value advances the provider's version and invokes the wake function once; setting the same value again changes neither.
- [ ] AC-4: Fixed vocabulary (NFR5, TM-4): for every reachable input the value is one of the state words or empty; agent names, 7501 titles and apps never appear in it.
- [ ] AC-5: Refresh (FR13): after an agent-status change in the active tab, after switching the active tab, and after closing the active tab, the next status bar build shows the new value.
