# Task Plan: task0007 — Hot-upgrade handoff of OSC 7501 records

## Goal

A mux daemon hot upgrade carries every pane's OSC 7501 records and their
update order across the handoff file, so the new daemon shows, aggregates
and evicts exactly as the old one would have.

## Requirements

FR17

## Design

Contracts used: SC-1 (export/import), SC-5 (where a pane's table lives).
Decision D8 applies.

- Schema: the handoff schema version advances by one. Each pane gains an
  ordered list (least recently updated first) of records with id, state
  word, optional kind word, optional progress, optional app, optional
  decoded title and optional decoded msg — plain values defined in the
  `mux_ipc` crate, which knows nothing of SC-1's types.
- Older documents: every previously supported version still decodes; the
  previous version gets its own decode shape, as the earlier versions
  already do, and yields panes with an empty list. An unknown future
  version is rejected as today.
- Capture: the pane snapshot and the live refresh performed just before
  the file is written both read the pane's current table through SC-1
  export, for live and exited panes alike.
- Restore: each pane's list goes through SC-1 import (which re-validates
  every record and applies the cap) and the result is installed in the
  restored pane's agent-status record together with the existing OSC 777
  state and revision.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Schema (FR17): the schema version is one above the previous version, a document whose panes carry records encodes and decodes with every record field and the order intact, and the supported-version range includes the new version.
- [ ] AC-2: Compatibility (FR17): documents of every previously supported version decode into panes with no records, and a version above the new one is rejected.
- [ ] AC-3: Capture (FR17): the pane snapshot and the refresh before writing record each pane's current records and order — a record added after the snapshot appears after the refresh — for live and exited panes.
- [ ] AC-4: Restore (FR17, TM-7): after restore each pane's table equals the captured one, including which record the next eviction removes, and the pane's OSC 777 state and revision are unchanged from today's behavior; a document carrying an invalid record (bad id, oversized or control-character title, out-of-range progress) or more than 256 records restores only the valid, most recent 256.
