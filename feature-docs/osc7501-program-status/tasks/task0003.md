# Task Plan: task0003 — Plain-tab OSC 7501 ingestion and query response

## Goal

A plain (non-mux) tab receives OSC 7501 with either terminator, keeps its own
record table under the protocol's lifecycle, and feeds the table's summary
into the GUI model so the tab badge, notifications and `{agent_status}` see
the composite state; every tab answers the `?` query with the same
terminator; a mux-attached tab drops 7501 state parsed from mux inner content
while still answering queries.

## Design

Contracts used: SC-1 (parse, table, lifecycle, summary), SC-2 (five-word
conversion), SC-4 (plain-tab summary operation). Decisions: D1 (where the
plain-tab table lives), D4 (plain-tab ingestion path and ordering), D6
(query routing).

### Mapping
Every term_core instance a tab uses — the one built with the tab and any
core installed in its place (off-thread swap or another replacement) —
maps OSC 7501 to a dedicated internal action code (103 is unused at
planning time) through the existing app-param mapping, so 7501 never
reaches the unknown-OSC warning path. The callback arm for that code does
nothing; all 7501 work happens in the responder, which sees the
terminator.

### Responder
The tab's registered OSC responder handles code 7501 in addition to the
existing color codes:
1. Terminator neither BEL nor ST → nothing (no answer, no feed item).
2. SC-1 parse returns Query → answer with ESC `]` `7501;?` followed by the
   query's own terminator. No feed item.
3. SC-1 parse returns Report → push a report item to the callback state's
   7501 feed. No answer.
4. Anything else → nothing.
Answers travel the existing device-response route (plain tab → its PTY;
mux-attached tab → the active pane's input through the existing route).

### Feed and table
- The 7501 feed is ordered: report items from the responder, prompt-mark
  candidates from the existing OSC 133 callback, a reset item from the
  existing RIS callback.
- Each pump, the output pipeline takes the feed, keeps only prompt-mark
  candidates that the same pump's live, main-screen marks confirm (the
  same forward walk the existing latch feed uses), and applies the items
  in order to the tab's table: report → apply; confirmed prompt start →
  prompt-start operation; reset → reset operation.
- After each item that changes the summary, the tab records the new
  summary (or its absence) on a pending list. App collects the list in
  the pump and, after that tab's OSC 777 inputs, converts each entry to the
  model's summary (SC-2 five-word conversion) and applies it with the
  SC-4 plain-tab operation.
- While the tab is mux-attached at pump start, the feed is discarded
  exactly where the existing OSC 777 candidates are discarded.
- The table belongs to the tab and is dropped with it; the model entry is
  discarded by the existing tab-close path.

### Coalesce gate
The existing device-query classifier treats a complete OSC 7501 whose body
is exactly `?` (BEL or ST) as a query, mirroring how it treats color
queries; a 7501 report is not a query.

### NFR4
All work is bounded by SC-1's caps and runs inside the existing pump;
nothing blocks on I/O.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Mapping (FR1): every core a tab uses — at tab creation and after the off-thread core swap — maps OSC 7501 to the dedicated internal action code, and an OSC 7501 never reaches the unknown-OSC callback path.
- [ ] AC-2: Query (FR8, TM-6): a body of exactly `?` with BEL is answered with ESC ] 7501;? BEL and with ST with ESC ] 7501;? ESC \; an unterminated sequence or any other body gets no answer; one query yields exactly one answer through the existing device-response route; a query leaves the tab's records and the model unchanged.
- [ ] AC-3: Reports (FR1, FR9): reports terminated by BEL and by ST both reach the tab's table in arrival order, and the model's status and the tab's badge aggregate show the composite of the tab's OSC 777 state and its OSC 7501 summary; a tab that receives only OSC 777 shows exactly what it showed before.
- [ ] AC-4: Lifecycle (FR7): a live main-screen OSC 133 A removes `working`, `blocked` and `idle` records and keeps `done` and `error`, honoring byte order against reports in the same pump; an A on the alternate screen removes nothing; RIS removes every record; DECSTR and switching the alternate screen on and off remove nothing.
- [ ] AC-5: Close (FR7, A1): closing a tab drops its records together with its model entry; a later tab never inherits them.
- [ ] AC-6: Mux-attached tab (FR14, TM-5): while a tab is mux-attached at pump start, 7501 reports and resets parsed from mux inner content change neither the tab's table nor the model, and a 7501 query in that content is still answered once through the existing route to the pane.
- [ ] AC-7: Coalesce gate (FR8, A3): the device-query classifier returns true for a complete OSC 7501 `?` query with either terminator and false for a 7501 report, an incomplete query, and plain text.
