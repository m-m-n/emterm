# Task Plan: task0004 — mux daemon OSC 7501 delivery and composite wait

## Goal

In a mux pane the daemon recognizes OSC 7501 and RIS in the same ordered
agent-status feed as OSC 777 and OSC 133, keeps the pane's record table
whether or not a GUI is attached, advances the pane revision and pushes the
OSC 7501 summary to the GUI, resyncs it silently after snapshots, and makes
WaitAgentState follow the composite state.

## Design

Contracts used: SC-1, SC-2, SC-3; contract owned: SC-5. Decisions: D1, D2,
D7.

### Scanner
- On a completed OSC whose body starts with the canonical `7501;` prefix
  (BEL or ST), the scanner emits one program-status item carrying the body
  after the prefix and the terminator kind, regardless of live spans
  (reports are unconditional, as OSC 777 reports already are).
- On RIS (ESC c) at any position where the terminal would execute it, the
  scanner emits one reset item, also regardless of live spans.
- Items keep exact byte order with OSC 777 reports and live OSC 133 marks,
  across read boundaries, through the one existing channel.
- 7501 bodies use the scanner's existing bounded carry; an over-long or
  unterminated body yields no item.

### Pane record (SC-5)
The pane's shared agent-status record gains the 7501 table (empty by
default) under the same lock as the OSC 777 state and the revision, and
yields the composite (SC-2 compose of the OSC 777 state and the table's
summary state through the five-word conversion).

### Apply rules (D7)
1. Program-status item: SC-1 parse. Report → apply to the table, bump the
   revision once. Query or anything else → nothing (the attached GUI
   answers queries, D6).
2. Live OSC 133 prompt start: in addition to the existing latch handling,
   apply the prompt-start operation; bump the revision when the table
   changed. If the latch also fired its inferred clear, one bump covering
   both is acceptable; the broadcast reflects the final state.
3. Reset item: apply the reset operation; bump when the table changed.
4. Every bump re-evaluates waiters and broadcasts one agent-status update
   (not replay-derived) carrying the OSC 777 part and the SC-3 summary item
   built from the table's summary (state, sanitized title, effective app;
   absent for an empty table). Nothing depends on attach state.

### Resync
Snapshot, reattach and window-switch resync messages (replay-derived) carry
the summary item too; their existing "revision above zero" condition
already covers panes whose only activity was OSC 7501.

### Wait
The immediate check, registered-waiter re-evaluation and the returned state
use the composite. An OSC 777-only pane behaves exactly as before.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Scanner (FR1, FR14): a complete OSC 7501 with BEL or ST yields one program-status item with its body and terminator kind, and ESC c yields one reset item; both are emitted in exact byte order with OSC 777 reports and live OSC 133 marks, including when a sequence is split across reads.
- [ ] AC-2: Scanner bound (TM-2): an OSC 7501 longer than the scanner's existing carry bound, or one that never terminates, yields no item, and the scanner's retained bytes never exceed the existing bound.
- [ ] AC-3: Apply and push (FR14, TM-3): an accepted report changes the pane's table and bumps its revision exactly once, a query or an ignored body changes nothing; each bump re-evaluates waiters and broadcasts one non-replay agent-status update whose summary item carries the aggregate state, the sanitized title and the effective app; this holds with no GUI attached.
- [ ] AC-4: Lifecycle (FR7, A1): a live main-screen prompt start removes the pane's `working`, `blocked` and `idle` records and keeps `done` and `error`; a mark not in a live main-screen span never reaches the table; a reset item removes every record; a bump and broadcast happen only when the table changed; the records go away with the pane.
- [ ] AC-5: Resync (FR14): resync messages after a snapshot, reattach or window switch are replay-derived and carry the summary item, including for a pane whose only activity was OSC 7501.
- [ ] AC-6: Wait (FR9, FR16): WaitAgentState matches and returns the composite — a wait for `error` is satisfied by a 7501 `error` record, a wait for `working` is satisfied while OSC 777 says `done` and a 7501 record says `working` — and every existing wait test for OSC 777-only panes passes unchanged.
