# Task Plan: task0006 — mux replay stripping and suppressed-output parity for OSC 7501

## Goal

OSC 7501 reports and queries never survive into the daemon's scrollback
ring or snapshots, so a reattach replays neither a record change nor a
query the GUI would answer again; and a 7501 query inside a suppressed
output chunk still reaches the attached GUI, the same way color queries do.

## Requirements

FR8, FR15

## Scope

### Files to Create

No new files.

### Files to Modify
- `src-tauri/src/mux/osc_identify.rs` — a program-status identity for OSC number 7501 in both the reference and the zero-allocation identification.
- `src-tauri/src/mux/scrollback_filter.rs` — the replayable-OSC selection includes the program-status identity.
- `src-tauri/src/mux/scrollback_filter/tests.rs` — strip tests for the write path and the snapshot path.
- `src-tauri/src/mux/snapshot_bytes.rs` — snapshot assembly test proving 7501 sequences are absent (no behavior change expected).
- `src-tauri/src/mux/ipc/pty_spawn/client_parity_scan.rs` — a complete 7501 query is a deliverable item; the viewer-launch selection stays exhaustive over the new identity.
- `src-tauri/src/mux/ipc/pty_spawn/suppressed_output.rs` — the replacement builder emits a delivered 7501 query verbatim.

## Design

Decision D6 applies (queries are answered only by the attached GUI; the
daemon never answers; replayed bytes carry no 7501).

### Identification
The identification layer reconstructs the OSC number exactly as the
client parser does (leading zeros, existing overflow rule). Number 7501
identifies as a program-status sequence regardless of its data — reports
and the `?` query alike. The zero-allocation identity and the reference
identity agree on every input, as the existing corpus test requires.

### Strip
The replayable-OSC selection used by both the scrollback write path and
the snapshot path strips program-status sequences, next to the existing
viewer, Markdown and OSC 777 agent-status selections. Everything the strip
keeps today stays kept.

### Suppressed-output parity
When a chunk is suppressed, the classifier already extracts the queries
the client's live parser would have answered. A complete OSC 7501 whose
reconstructed data is exactly `?` (BEL or ST) is such a query and is
delivered verbatim, like a color query. A 7501 report is never delivered
by this path (the daemon delivers state out of band, D7).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Identification (FR15): OSC bodies whose reconstructed number is 7501 — canonical and leading-zero forms, reports and the `?` query — identify as program-status; other numbers keep their current identity; the zero-allocation identity equals the reference identity over the corpus extended with 7501 cases.
- [ ] AC-2: Strip (FR15, TM-5): the scrollback write-path strip and the snapshot strip remove complete OSC 7501 reports and queries with either terminator, leave the surrounding bytes byte-for-byte intact, and leave every sequence they kept before (including fold marks and mux control) unchanged; replay bytes built from a ring that saw 7501 traffic contain no OSC 7501.
- [ ] AC-3: Suppressed-output parity (FR8, A3): a suppressed chunk containing a complete OSC 7501 `?` query yields a replacement that carries that query exactly once with its own terminator, a 7501 report in the chunk is not carried, and the viewer-launch selection is unchanged for every existing case.
