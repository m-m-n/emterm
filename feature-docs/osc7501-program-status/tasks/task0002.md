## Design

Contracts: SC-2, SC-3 and SC-4 in IMPLEMENTATION.md; rank and order: D2;
names: D5; wire compatibility: D3.

### Core and wire state
- `error` joins the core state with the word `error` (its display form is
  the word, which the status bar reuses).
- OSC 777 keeps accepting exactly `idle` / `working` / `blocked` / `done`;
  the existing four-state collection the OSC 777 tests iterate keeps
  exactly those four members. The `emterm agent-status` CLI subcommand is
  not touched.
- A separate five-word conversion maps each Program Status state word to
  the core state (SC-2); every other input maps to nothing.
- The wire state gains `error` after the existing values so the encoding of
  the existing four never changes. The daemon's and the model's core↔wire
  conversions become total.

### Composition (SC-2)
compose(OSC 777 state, OSC 7501 aggregate) returns the higher of the two by
the D2 in-pane rank; a missing side yields the other side; both missing
yields no state.

### GUI model (SC-4)
- Each entry holds the OSC 777 part (state, name) and the OSC 7501 summary
  (core state, title already sanitized, effective app) separately. The
  state the model reports for an entry — status, aggregate, counts,
  any-reported-state, unseen tracking and transitions — is the composite.
- Plain tab: a new operation sets the tab's summary (present or absent),
  advances the model-minted revision, recomputes the composite and applies
  the existing unseen / transition rules. The existing plain-tab OSC 777
  operation recomputes the composite with the stored summary.
- Mux pane: a new daemon-update operation takes the summary next to the
  existing arguments and stores both verbatim with the daemon revision;
  the existing daemon-update operation keeps its signature and means "no
  summary".
- An entry whose only input is OSC 777 behaves exactly as today.
- Transitions fire only when the composite changes and the update is not
  replay-derived; their name follows D5.
- Aggregation ranks blocked > unseen error > unseen done > working > seen
  error > seen done > idle; `error` uses the same unseen semantics as
  `done`. Counts gain an `error` bucket.

### Wire summary item (SC-3) and GUI apply
- The agent-status update message gains one trailing, optional item: the
  pane's OSC 7501 aggregate as a wire state, the sanitized title, the
  effective app. It is absent when the pane has no records.
- When the GUI applies a daemon update, it converts the item to the
  model's summary and uses the new daemon-update operation; replay-derived
  updates stay silent as today.
- Existing literal constructions of the message (daemon and test fixtures)
  gain the absent item; their assertions do not change.

### Display
- Badge for `error`: U+274C while unseen; IDLE_BADGE_EMOJI (U+1F4A4) once
  seen; fallback circle filled while unseen and a ring once seen (same as
  `done`); color = the md3 `error` role (A12).
- `md3` gains the `error` role, mirroring the `error` token of
  `src-tauri/web-shared/settings/ui-theme-presets.ts` for every preset in
  both brightnesses; the existing roles are untouched.

### Notifications
- `error` is a qualifying target, gated by `agent_notify_on_done` (not by
  `agent_notify_on_blocked`); every other gate is the existing one.
- Body state word: `error` (English) / `エラー` (Japanese) (A14). The name
  arrives already sanitized on the transition and goes through the existing
  body path unchanged (no markup interpretation; escaping happens in the
  existing send path, A9).

### `emterm mux wait`
`--state` accepts `error` alongside the existing four; the usage error
lists all five.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: Error state (FR11, FR18, A8): the core state has `error` with word `error`; OSC 777 parsing still rejects `state=error` and the four-state collection still has exactly four members; the five-word conversion maps `idle`/`working`/`blocked`/`done`/`error` and rejects other words; the wire state serializes `error` as `error`, the existing four states encode exactly as before, and the core↔wire conversions round-trip all five.
- [ ] AC-2: Composition (FR9): compose returns the higher of its two inputs by blocked > working > error > done > idle, returns the present side when one side is absent, and returns no state when both are absent.
- [ ] AC-3: Model composite (FR9, FR12): status, aggregate, counts, any-reported-state and transitions use the composite; a plain-tab summary update advances the tab's revision; a daemon update with a summary stores it with the daemon revision; a transition fires only on a composite change of a non-replay update; its name follows D5 (title, then app, then the OSC 777 name, then none); every pre-existing `agent_status_model` and `app` agent-status test passes with only fixture-literal additions.
- [ ] AC-4: Aggregation (FR11): across panes the order is blocked > unseen error > unseen done > working > seen error > seen done > idle; marking seen flips `error` from unseen to seen exactly as it does `done`; counts report `error` separately.
- [ ] AC-5: Wire summary (FR14): the agent-status update message carries the optional trailing summary item (wire state, sanitized title, effective app), absent for a pane without records, and round-trips through the control-message encoding; the GUI applies a daemon update's summary so the pane's composite and transition name follow it, and a replay-derived update with a summary applies silently.
- [ ] AC-6: Display (FR11, A12): an unseen `error` aggregate renders U+274C with a filled fallback circle, a seen one renders IDLE_BADGE_EMOJI with a ring fallback; its color is the md3 `error` role; the md3 `error` role equals the `error` token for every preset in dark and light; tab bar and mux sidebar resolve the same presentation.
- [ ] AC-7: Notifications (FR12, A14, TM-4): a transition to `error` fires only when `agent_notify_on_done` is on (independent of `agent_notify_on_blocked`) and every existing gate passes; the body uses `error` / `エラー`; the body carries the transition's name as plain text through the existing body and send path.
- [ ] AC-8: CLI (FR16): `emterm mux wait --state error` and lists including `error` parse into the wire `error` state, the error message names all five states, and the `emterm agent-status` subcommand still offers only its existing states.
