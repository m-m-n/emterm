# agent-badge-emoji-distinction - 要件定義書

## 1. 概要

### 1.1 背景

実機確認（M-1, emterm-plugin-runtime-fixes）で、タブバー／サイドバーのエージェント状態バッジにおいて working と idle の両状態が同系色の塗り円で判別しづらいことが判明した（POC-RESULTS.md に記録）。

### 1.2 目的

タブバー／サイドバーのエージェント状態バッジで、working と idle を色・形以外の手段（カラー絵文字など）でも一目で区別できるようにする。

### 1.3 スコープ

**対象**:

- タブバーのエージェント状態バッジ表示（`tab_bar.rs` の `paint_agent_badge`）
- サイドバーのミラー実装バッジ表示（`mux_sidebar.rs`）
- カラー絵文字描画のための既存 swash 経路（`emoji_cache.rs` の `EmojiTextureCache`）の流用

**対象外**:

- working / idle 以外のエージェント状態（blocked / done 等）の現行バッジ表示（現行を維持する）
- デスクトップ通知対応（別課題）

**design ステップに委ねる事項**:

- 各状態に割り当てる具体的な絵文字／グリフ
- 既存の円バッジとの置換か併置か
- サイズ・配置

## 2. ビジネス要件

### 2.1 ビジネス目標

タブバー／サイドバーのエージェント状態バッジで、working と idle を色・形以外の手段（カラー絵文字など）でも一目で区別できるようにする。

### 2.2 対象ユーザー

| ユーザータイプ | 説明 |
|----------------|------|
| eMterm 利用者 | タブバー／サイドバーのバッジでエージェント状態を確認する |

### 2.3 期待される効果

- working と idle を一目で区別できる
- タブバー・サイドバー双方で同じ区別が得られる

## 3. ユースケース

### 3.1 ユースケース一覧

| ID | ユースケース名 | アクター | 優先度 |
|----|----------------|----------|--------|
| UC01 | タブバーでエージェント状態を確認する | eMterm 利用者 | 高 |
| UC02 | サイドバーでエージェント状態を確認する | eMterm 利用者 | 高 |

### 3.2 ユースケース詳細

#### UC01: タブバーでエージェント状態を確認する

**アクター**: eMterm 利用者

**事前条件**:

- タブにエージェント状態（working または idle）が設定されている

**基本フロー**:

1. 利用者がタブバーを見る
2. タブバーのエージェント状態バッジが状態に応じた表示になっている
3. 利用者が working と idle を一目で区別する

**代替フロー**:

- working / idle 以外の状態（blocked / done 等）では現行のバッジ表示を維持する

**事後条件**:

- 利用者が working と idle を区別できている

#### UC02: サイドバーでエージェント状態を確認する

**アクター**: eMterm 利用者

**事前条件**:

- サイドバーに表示される対象にエージェント状態（working または idle）が設定されている

**基本フロー**:

1. 利用者がサイドバーを見る
2. サイドバーのエージェント状態バッジが UC01 と同じ区別で表示されている
3. 利用者が working と idle を一目で区別する

**代替フロー**:

- working / idle 以外の状態（blocked / done 等）では現行のバッジ表示を維持する

**事後条件**:

- タブバーとサイドバーで表示が食い違っていない

## 4. 機能要件

### 4.1 機能一覧

| ID | 機能名 | 説明 | 優先度 |
|----|--------|------|--------|
| FR1 | タブバーのバッジで working / idle を非色依存の手段で区別 | タブバーのエージェント状態バッジで working と idle を色・形以外の手段でも区別する | 高 |
| FR2 | サイドバーのバッジにも同じ区別を反映 | `mux_sidebar.rs` のミラー実装バッジにも FR1 と同じ視覚区別を反映する | 高 |
| FR3 | カラー絵文字描画は既存 swash 経路を流用 | `status_bar.rs` で確立済みの `EmojiTextureCache` + swash 経路をバッジ描画に流用する | 高 |

### 4.2 機能詳細

#### FR1: タブバーのバッジで working / idle を非色依存の手段で区別

**説明**: タブバーのエージェント状態バッジ（`tab_bar.rs` の `paint_agent_badge`、現状 `circle_filled` / `circle_stroke` のみ）で、working と idle を色・形以外の手段（カラー絵文字など）で一目で区別できる表示にする。

**入力**:

- エージェント状態: working / idle

**出力**:

- バッジ表示: 状態に応じた表示（具体的なグリフ・描画モードは design ステップで決定）

**ビジネスルール**:

- working と idle の区別は色・形以外の手段でも成立すること
- working / idle 以外の状態の現行バッジ表示は維持すること

**バリデーション**: 該当なし

**エラーケース**: 該当なし

#### FR2: サイドバーのバッジにも同じ区別を反映

**説明**: `mux_sidebar.rs` のミラー実装バッジにも FR1 と同じ working / idle の視覚区別を反映する。

**入力**:

- エージェント状態: working / idle

**出力**:

- サイドバーのバッジ表示: FR1 と同じ区別

**ビジネスルール**:

- タブバーとサイドバーで表示が食い違わないこと

**バリデーション**: 該当なし

**エラーケース**: 該当なし

#### FR3: カラー絵文字描画は既存 swash 経路を流用

**説明**: egui 標準（ab_glyph）はカラー絵文字を描画できないため、`status_bar.rs` で確立済みの `EmojiTextureCache`（`emoji_cache.rs`）+ swash ラスタライズ → `egui::Image` 貼付の経路をタブ／サイドバーのバッジに流用する。

**入力**:

- 表示対象のグリフ

**出力**:

- ラスタライズされたテクスチャを貼付したバッジ描画

**ビジネスルール**:

- カラー絵文字の描画に egui 標準（ab_glyph）を使わない

**バリデーション**: 該当なし

**エラーケース**: 該当なし

## 9. 制約条件

### 9.1 技術的制約

- egui 標準（ab_glyph）はカラー絵文字を描画できない。`status_bar.rs` で確立済みの `EmojiTextureCache`（`emoji_cache.rs`）+ swash ラスタライズ → `egui::Image` 貼付の経路を流用する（FR3）
- `tab_bar.rs` と `mux_sidebar.rs` は色ロジックを共有するが描画関数は独立実装であり、変更を両ファイルに適用する必要がある（NFR1）
- 変更対象は GUI 専用モジュール（`ui/` 配下）であり、CLI ビルドを壊さないこと（NFR2）
- E2E 基盤が存在しない（`test/README.md`: `docker-compose.e2e.yml` / `e2e-tests/` とも無し）ため自動 E2E は組まない
- DevTools は使用不可であり、調査は `emterm.log` 経由で行う
