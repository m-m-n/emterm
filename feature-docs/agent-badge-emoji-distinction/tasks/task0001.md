# Task Plan: task0001 — Emoji badge distinction for working/idle in tab bar and sidebar

## Goal

The agent-state badges in the tab bar and the mux sidebar render `working`
as ⚡ (U+26A1 HIGH VOLTAGE) and `idle` as 💤 (U+1F4A4 ZZZ) as color emoji via
the established swash texture-cache path, identically on both surfaces, with
the current filled-circle rendering as fallback; all other agent states keep
their current badge rendering.

## Requirements

FR1, FR2, FR3, NFR1, NFR2

## Scope

### Files to Create

- (none)

### Files to Modify

- `src-tauri/src/ui/tab_bar.rs` — shared state→presentation decision logic
  (next to the existing shared `agent_state_color` / `agent_badge_filled`
  helpers), emoji-capable badge painting in `paint_agent_badge`, unified
  badge slot width in the label layout, unit tests.
- `src-tauri/src/ui/mux_sidebar.rs` — same emoji-capable badge painting and
  unified slot width in the row layout, consuming the shared decision logic
  imported from the tab-bar module (existing import pattern), unit tests.
- `src-tauri/src/ui/emoji_cache.rs` — receives the relocated emoji-resource
  bundle type (see Design 3).
- `src-tauri/src/ui/status_bar.rs` — imports the emoji-resource bundle from
  its new location; no behavioral change.
- `src-tauri/src/render/mod.rs` — constructs the emoji-resource bundle
  before the tab bar draws and passes it into the tab-bar draw call and both
  sidebar draw calls.

## Design

### 1. Presentation selection (shared, pure — FR1/FR2/NFR1)

One pure function, placed beside the existing shared badge helpers in the
tab-bar module (the sidebar already imports shared badge logic from there),
consumed by BOTH painters so the decision exists exactly once.

- **Input**: the aggregated badge value (semantic agent state + unseen flag).
- **Output**: one of two presentation kinds:
  - *Emoji*, carrying the state's grapheme cluster — `working` → U+26A1,
    `idle` → U+1F4A4. Both are single-codepoint, default-emoji-presentation
    clusters (no VS-16), accepted by the existing emoji-cluster prefilter,
    and covered by the bundled Noto Color Emoji bitmap strikes.
  - *Circle*, carrying the existing filled-vs-ring choice — `blocked` /
    `done` keep the current semantics (filled when unseen, ring when seen),
    delegating to the existing shared fill helper.
- **Postcondition**: total over all four states; no side effects; callable
  from unit tests without any UI context (TS1).

### 2. Fallback resolution (pure — FR3, SPEC edge case)

A second pure decision resolves the final render mode from a selected
*Emoji* presentation plus texture availability (the cache produced a
texture, or not — including "no emoji resources supplied", the test-context
case):

- Texture available → blit the emoji texture.
- Otherwise → render the CURRENT filled-circle form for that state
  (working / idle are always filled per the existing fill helper), in the
  state's existing color. Never a blank slot; never the toolkit's default
  text path for these glyphs (the default rasterizer cannot render color
  emoji — FR3).

Keeping this a pure decision makes the fallback branch unit-testable
without standing up a font stack.

### 3. Emoji resource plumbing (FR3)

The resource bundle the emoji path needs (glyph-rasterizer handle + font
fallback chain + emoji texture cache handle) is currently defined in the
status-bar widget module and constructed in the frame-composition function
AFTER the tab bar draws. Changes:

- Relocate the bundle type to the emoji cache module — its natural home now
  that three widgets consume it; the status-bar widget imports it from
  there (no behavioral change to the status bar).
- The frame-composition function constructs the bundle once per frame
  BEFORE the tab-bar draw and passes it into the tab-bar draw call and both
  sidebar draw calls (persistent and overlay variants).
- The parameter is optional on every draw signature it is added to, so
  existing unit tests keep running without a font stack (the established
  status-bar pattern); absence of the bundle triggers the fallback rule of
  Design 2.

### 4. Rendering rules — identical in both surfaces (NFR1)

- **Replace, not combine**: for `working` / `idle` the emoji replaces the
  dot entirely — no circle underlay, no side-by-side pairing.
- **Size**: the emoji renders aspect-fit inside a 12×12 logical-px box
  (the design system's `label-small` 12px badge scale from
  `doc/UI-DESIGN-GUIDELINES.yaml`), centered in the badge slot at the
  row/label vertical center. Rasterization is requested at
  12 × the display's pixels-per-point, in physical px; the cache's existing
  supersample + downscale path handles small-size quality.
- **Untinted**: the emoji texture is blitted with its own color table — no
  tint from the shared state-color mapping. That mapping remains the SSOT
  for the blocked/done circles and for the fallback circles only.
- **Unified badge slot**: when a badge is present, the reserved slot width
  becomes 12 logical px for ALL states, in both surfaces; the unchanged 8px
  blocked/done dot is centered within the slot. The 6px gap after the badge
  and the "no slot reserved when no badge has ever been reported" behavior
  are unchanged. Consequence: a pane transitioning working → done causes no
  title/name shift.
- **No animation**: the badge is a static glyph; no blink/pulse.

### 5. Unchanged paths

The blocked/done circle painting (colors, filled/ring rule, 1.5px ring
width), the activity dot and its animation, the group-centering /
row-layout logic beyond the slot-width constant, and every agent state
other than `working` / `idle`.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: A shared pure state→presentation function exists beside the
      existing shared badge helpers and returns the emoji presentation
      (U+26A1 cluster for `working`, U+1F4A4 cluster for `idle`) and the
      circle presentation for `blocked` / `done` preserving the current
      filled-when-unseen / ring-when-seen semantics — verified by unit
      tests over all four states without any UI context (TS1).
- [ ] AC-2: The fallback decision is pure and unit-tested: an emoji
      presentation with no obtainable texture (including no emoji resources
      supplied) resolves to the state's current filled-circle rendering —
      never a blank slot, never the toolkit's default text path (FR3).
- [ ] AC-3: In the tab bar, a `working` / `idle` badge with emoji resources
      available renders as an untinted texture blit aspect-fit in a 12×12
      logical-px box, replacing the dot entirely (FR1).
- [ ] AC-4: The sidebar renders the identical glyph, box size, slot width,
      gap, and fallback rule as the tab bar, consuming the same shared
      decision function (FR2, NFR1).
- [ ] AC-5: When any badge is present the reserved slot width is 12 logical
      px in both surfaces (8px blocked/done dot centered within it), the
      6px gap and the no-badge/no-slot behavior are unchanged, and a
      working → done transition produces no title/name x-shift — verified
      by layout assertions in both widget test modules.
- [ ] AC-6: Agent states other than `working` / `idle` keep their current
      badge rendering code path; every pre-existing badge test in both
      widget test modules still passes (SPEC edge case).
- [ ] AC-7: The CLI build still compiles:
      `CARGO_TARGET_DIR=src-tauri/target cargo check --manifest-path src-tauri/Cargo.toml --no-default-features`
      exits 0 (NFR2, TS2).

## Test Notes

- AC-1 / AC-2 are plain pure-function unit tests (TS1): all four states ×
  both unseen values for selection; both availability values for fallback.
  Inline `#[cfg(test)] mod tests`, named `<subject>_<scenario>_<expected>`,
  run via
  `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib`.
- AC-3 / AC-5: both widget test modules already capture painted shapes /
  text positions through full-context runs (see the existing badge layout
  tests in each file) — extend that pattern to assert slot width, no-shift
  on state transition, and that an image shape (not a text shape) is
  emitted for working/idle when resources are present. If standing up real
  emoji resources in tests proves impractical, the fallback branch (AC-2)
  plus the pure-decision tests carry the automated weight and the blit
  itself is covered by the manual check (TS3) — note this in the
  implementation report if taken.
- AC-6: run the existing suites of both files unmodified.
- Actual rasterization quality and "at a glance" legibility are manual
  (TS3, feature-level VERIFICATION.md) — not unit-testable.

## Out of Scope

- Desktop notifications (explicitly excluded in REQUIREMENTS.md).

- Any settings/toggle for the badge style.
- Status-bar behavior changes (only the resource-bundle import location
  moves).
- Badge animation of any kind.
- Changes to the aggregation logic that produces the badge value.
