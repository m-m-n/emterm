## Test Notes

**This task adds no test, and that is a requirement, not an omission** (NFR1,
FR6). The usual test-first cycle does not apply: writing a test would change
the suite's counts, which AC-7 requires to stay identical, and adding an
automated name-drift check is explicitly out of scope. Do not resolve this
tension by inventing a test.

How each criterion is discharged instead:

| Criterion | Method |
|---|---|
| AC-1, AC-2 | Text search of the single repaired file (absence of the old name; absence of the removed field) plus a read-through of both repaired bodies |
| AC-3, AC-4 | Diff review of the repaired file against the base, checking that every hunk falls inside the enumerated locations |
| AC-5 | YAML parse of the repaired file plus comparison of its top-level key set against the pre-change file |
| AC-6 | Manual evidence: definition file+line per cited name, and one name-filtered test run |
| AC-7 | Change-set listing against the base, plus the `main` component's test suite run |

Edge cases worth attention:

- A removal inside a quoted compiler error can leave `/` or `and` stranded, or
  can unbalance the escaped-backtick / code-span pairing. Check the delimiter
  balance explicitly after each of repairs 2-4 (IMPLEMENTATION.md C3).
- Deeper indentation on an edited line changes folded-scalar semantics even
  though the file still parses (IMPLEMENTATION.md C2). Compare the edited
  lines' leading whitespace against their neighbours.
- The suite is known to be order-sensitive in places, so run the regression
  check single-threaded when comparing counts.
