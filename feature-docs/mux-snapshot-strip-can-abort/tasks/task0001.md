# Task Plan: task0001 — Abort-aware APC / DCS body end scan in the mux strip

## Goal

The shared mux strip pass ends a Kitty APC / DCS body at the first ESC in the body. It removes an aborted Kitty APC / SIXEL DCS body up to the aborting ESC and judges every byte from the aborting ESC on with the existing rules. A snapshot replay then shows the bytes written after a body that a cut closed with `ESC` + CAN. The tests and comments that stated the old behavior are updated to match.

## Design

Cross-task conventions (commands, test names, payload choice) are in IMPLEMENTATION.md.

### Body end scan (FR1, FR4)

Responsibility: given the input and the index right after an APC / DCS introducer, report how the body ends. This is a private part of the strip module.

- Precondition: the start index is within the input or at its end.
- Complete(end): the first ESC at or after the start is followed by `\`. `end` is the index just past that `\`.
- Aborted(at): the first ESC at or after the start is followed by any other byte, ESC and CAN (0x18) included. `at` is the index of that ESC, the aborting ESC.
- Unterminated: there is no ESC at or after the start, or the first one is the last byte of the input.
- BEL is body data. It neither ends nor aborts the body.
- Postcondition: past the first ESC at or after the start, the scan reads only the one byte right after it.

The write filter's own string scan has the same three outcomes. The strip keeps a scan of its own: the strip module must not depend on the IPC layer, and NFR2 keeps the write filter's scan unchanged.

### Strip pass decisions (FR2, FR3, FR5)

| Introducer | Complete | Aborted | Unterminated |
|---|---|---|---|
| Kitty APC (`ESC _ G`) | Removed through the ST (unchanged) | Removed from the introducer ESC up to, not including, the aborting ESC. The pass resumes AT the aborting ESC | Kept |
| Any other APC (`ESC _` not followed by `G`) | Kept (unchanged, no scan) | Kept | Kept |
| DCS (`ESC P`) | Removed through the ST when the body is SIXEL by the existing final-byte rule (unchanged) | Removed up to the aborting ESC when the pre-abort range (the bytes between `ESC P` and the aborting ESC) is SIXEL by the same rule. Otherwise kept | Kept |

Flow of an aborted-body removal:
1. Apply the existing pre-removal closing (D1 of mux-strip-concat-query-closure). One CSI_CLOSING is written when the written stream is inside a CSI or right after a written lone ESC. Nothing is written in ground or inside a string body.
2. Move the input position to the aborting ESC without consuming it.
3. The next iteration judges the aborting ESC with the existing rules. It may be a kept escape, a kept OSC, a charset designation, or a strip target, which is then removed as its own construct.

"Kept" means what it means today for a construct with no terminator: the introducer ESC is copied and scanning goes on byte by byte. The aborting ESC is then judged by the existing rules when the scan reaches it.

### Remap and written state (FR5, FR6)

No new rule. The existing per-iteration watch-offset rule already gives these mappings:
- An offset at the introducer maps to the output position before whatever the removal writes.
- Offsets strictly inside the removed body, or at the aborting ESC, map to the output position of the aborting ESC.

Removed bytes never advance the written state. Only the closing byte and the copied bytes do. The write path and the snapshot path stay the one shared pass.

### Linear bound (NFR1)

Each body scan stops at the next ESC, so the ranges scanned for distinct introducers never overlap. The pass stays one linear sweep even on input made only of aborted or unterminated introducers. The existing "no ST terminator from here on" cache no longer bounds the pass. Keeping or removing it is an implementation choice, but every comment about linearity must state the bound that actually holds.

## Test Notes

- Expected red before the change: AC-1, AC-2, AC-3 (the removal and keep rows that depend on the abort), the updated assertions of AC-7 and AC-8, and AC-9's comment checks. AC-4 and the identity half of AC-6 pin behavior that is already correct. They are green before and after, so record them that way rather than forcing a red.
- term_core replay and `client_written_state` need payloads that neither answer nor place an image. The oracle asserts that its probes provoke no response, so a wrong payload fails loudly. This matters for a kept body that ends in a lone ESC: a probe aborts that body and dispatches it.
- The bodies longer than 512 KiB are built once per test, with few passes over them (the predecessor's convention). The write-filter tests already have a 10-second `BUDGET` constant to reuse.
- Run cargo from the worktree root with the quick-check target directory and the manifest path. See VERIFICATION.md for the exact commands.
- Some full-suite failures have causes outside this task:
  - The `tabs.rs` replay tests are nondeterministic in parallel and stable with a single test thread.
  - A `tmux_sockets` discover test rarely fails in parallel runs.
  - A wall-clock budget test can fail under machine load. The predecessor record test-docs/mux-write-filter-overflow-open-string-cut/task0001.tests.yaml notes one in `overflow_lone_esc.rs`.

  None of these is touched here. Re-run such a failure alone before treating it as a regression.
- If any other existing test fails only because it pinned the old aborted-body behavior, update its expectation to FR1-FR4, keep its name, and report the file as a plan deviation.
