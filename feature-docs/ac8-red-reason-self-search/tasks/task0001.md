## Design

### What the rewritten scalar says

The scalar keeps three elements and drops one.

Kept:

1. **The no-observable-pre-state framing** (opening): this task's own commit
   does not exist before the task runs, so its change set cannot be enumerated
   beforehand; the enumeration was therefore verified after committing, against
   the merge base. This is the justification for AC-8's `red_confirmed: false`
   and `tests: []`, so it survives any shortening. The merge-base revision
   itself is neither re-derived nor restated.
2. **The two-path enumeration**: the change set consists of exactly two paths,
   `test-docs/ac2-red-reason-accuracy/task0001.tests.yaml` (the record the task
   edited) and `test-docs/ac7-red-reason-scope/task0001.tests.yaml` (that
   feature's own generated record). Both paths are named; "exactly two paths" is
   stated.
3. **The language determination**: the enumerated change set contains no Rust
   file and no TypeScript file.

Dropped:

4. **The trailing self-search clause** — the sentence reporting that a
   fixed-string search of the record's own text for a single-file phrasing
   returns no match, together with the two needles it quotes inline. Nothing
   replaces it: the replacement text makes no claim whatsoever about the result
   of searching the record's own text, and introduces no new claim the change
   set does not directly support.

### Constraints the rewrite works inside

- **Scalar form**: the value stays a folded block scalar introduced by the same
  introducer, at the same indentation as the file's other folded scalars, in
  English prose, with line width and style comparable to the file's other
  `red_reason` values and no trailing whitespace.
- **Sibling values**: AC-8's `tests` stays the empty list and `red_confirmed`
  stays the boolean `false`. They are not re-typed, re-quoted, or re-indented.
- **Containment**: the edit is addressed to the AC-8 `red_reason` scalar
  specifically. No file-wide search-and-replace is used — the two occurrences of
  `lists only` at lines 43 and 47 belong to the AC-4 `red_reason`, describe a
  different record, are correct as written, and must survive byte-identically.
- **Out-of-scope neighbours**: the trailing `notes` block contains a topically
  adjacent sentence about this task's own change set. It is not touched.

### Verifying the rewrite without repeating the defect

Per the re-runnable-claim rule and the assertion-scoping convention in
IMPLEMENTATION.md:

- The check loads the file with a plain YAML parser and asserts against the
  **loaded AC-8 `red_reason` string**, never against raw file bytes and never
  against the whole file. Whole-file assertions would collide with the surviving
  AC-4 occurrences, and byte-level assertions would miss folding artifacts.
- Every needle the check searches for lives in the check script (or in this
  task's own evidence record) — never inside the scalar being searched.
- The check script is not committed: it belongs in the project's gitignored
  `tmp/` directory or in the session scratchpad, both outside this feature's
  declared change set.

## Test Notes

- **AC-1, AC-2, AC-3, AC-4, AC-5 → scripted parse/assert check (unit-level,
  TS1)**. One script loads the record, asserts the top-level key order and the
  eight-entry `acceptance_tests` mapping, then asserts on the loaded AC-8
  `red_reason` string: both required paths present, the two-path statement
  present, the no-Rust / no-TypeScript wording present, the pre-state framing
  present, and no self-search report present. Scalar form and indentation are
  checked against the file's other folded scalars. Write this check before
  editing the scalar: on the base revision it fails on the self-search
  assertion, which is the red state the task closes.
- **AC-7 (re-runnability half) → re-execution of the described enumeration
  (integration-level, TS2)**. Re-run the change-set enumeration for the
  predecessor task's commit against its merge base and compare the result with
  the recorded wording: exactly the two named paths, no Rust file, no TypeScript
  file.
- **AC-6 → git inspection plus region-wise byte comparison (TS3)**. Confirm a
  single changed file, a single hunk, and byte identity of every region outside
  the AC-8 `red_reason` against the base revision. The `lists only` occurrences
  at lines 43 and 47 are an explicit check item, not an incidental one.
- **AC-7 (no-regression half) → project commands (TS4)**. Run the TypeScript
  commands (`bun run typecheck && bun test`) and the Rust `--lib` suite as a
  regression guard. Neither exercises the edited YAML, so both are expected to
  match the baseline the predecessor task recorded; a difference means something
  outside the declared change set moved.
- **TDD-awkward part**: the acceptance target is prose inside a data file, so
  the "test" is the parse/assert script rather than a suite test. Keep the
  script's needles on the script side — writing an assertion's needle into the
  scalar it searches is exactly the defect under repair.
- **Edge cases worth covering explicitly**: folded-scalar re-wrapping (assert on
  the loaded value); the AC-4 `lists only` survival; the `notes` block being
  untouched; this task's own evidence record stating a verified property rather
  than a search result.
