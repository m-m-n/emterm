# Task Plan: task0001 — Transition-only warn on capability-query failure in the unix notify_worker

## Goal

When the unix notification worker's capability query fails, emit one
warn-level emterm.log record per failure transition: the first failure, a
change of error text, or a failure after a success. The fail-closed escape
decision and all existing notification output stay unchanged.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2, NFR3, NFR4, NFR5, NFR6, NFR7

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/callbacks.rs` — add the marker constant and the warn decision helper (both unix-only); add the worker-local state and the bind-once supplier to the unix notify_worker; add a Display requirement to its fetch error type parameter; update doc comments
- `src-tauri/src/callbacks/tests.rs` — add unit tests for the helper and one worker test; switch the worker fake's error type to a text type without touching any assertion

## Design

This task implements the contracts pinned in IMPLEMENTATION.md:

- Shared Components: the helper contract and its transition table, the
  marker constant, the worker previous-failure state, and the warn record
  format.
- D2: bind the query result once through the gate's deferred supplier.
- Conventions.

These are not restated here.

### Worker flow (unix notify_worker, per received notification)

1. Before the receive loop starts, set the worker-local previous-failure
   state to none.
2. Build the redacted rendering from the title and body as received from the
   queue. This step is unchanged and still comes first (NFR7).
3. Call `escape_for_send_on_demand` with the received title and body and a
   deferred supplier. When invoked, the supplier:
   1. performs the capability query exactly once and binds the result;
   2. passes the current state and the bound result to the warn decision
      helper;
   3. replaces the state with the helper's next state;
   4. if the helper returns "warn", emits exactly one warn-level record in
      the format pinned in IMPLEMENTATION.md (marker constant, colon and
      space, then the next-state text);
   5. returns the same bound result, unmodified, to the gate.
4. When the gate does not invoke the supplier (no metacharacter), none of
   step 3 happens: no query, no state change, no log.
5. The send and the existing send-result records are unchanged.

### Signature change

The fetch error type parameter of the unix notify_worker requires a Display
representation, matching the send error type parameter. The unix
spawn_notify_worker needs no source change: the production capability-query
error type already satisfies the requirement.

### Doc comments (FR5)

- notify_worker's doc comment gains a paragraph stating the following:
  - a failed capability query emits a warn record carrying the marker
    constant;
  - the record is emitted only on a transition (first failure, changed
    error text, failure after a success);
  - recovery (a success after a failure) is silent;
  - the state is worker-local, is never used for the escape decision, and
    no capability result is cached.
- The comment block at the gate call states the same rule briefly.
- The helper's own doc comment summarizes the transition table.

### Test fakes

- In the worker_injection_points module, the fixed capability-fetch fake
  changes its error type from the unit type to a text type.
- The existing fetch-failure test builds its failure with a text value.
- No assertion changes.
- The body_markup_escape and capability_query_skip_gate modules need no
  change, because the functions they call keep error types without a
  Display requirement. Leave those modules untouched.

## Test Notes

- **AC-1 / AC-2**: unit tests in a new unix-only test module for the helper.
  - Use a text error type for the results.
  - For the chained case, feed each call's returned next state into the
    next call, as the worker does.
  - The success cases cover a list with body-markup and an empty list, to
    show that any success resets the state whatever the list contains.
- **AC-3**: add a test to the worker_injection_points module that reuses the
  fixed capability-fetch fake (text error) and the send recorder.
  - Assert on the fetch call counter (2) and on the recorded sends (3,
    in order, with the expected escaped or unchanged fields).
  - Do not assert the number of warn records here: log capture is not
    allowed (NFR5). AC-1 and AC-2 cover the warn count.
- **AC-4**: the marker-value assertion is a unit test. That the record
  carries no notification text is checked by review (TS-7). The design makes
  it structural: the emission site uses only the marker constant and the
  helper's next-state text.
- **AC-5**: run the callbacks tests before and after the change. In the diff
  of the test file, pre-existing tests may change only the fake's error type
  and the failure value construction.
- **AC-6 / AC-7**: review checks on the diff plus the two build commands.
- The helper is pure. Write its tests first (TDD), then wire the worker.
