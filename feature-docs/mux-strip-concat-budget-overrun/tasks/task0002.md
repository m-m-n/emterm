# Task Plan: task0002 — Scaling-ratio regression guard for the strip and the write filter

## Goal

Add, next to `CpuMeter`, a judgment of two thread CPU times measured at input
sizes N and 4N; show that it accepts a linear surrogate and rejects a quadratic
one; and add a guard that runs the real write-path strip and the real one-call
write-filter feed at N and 4N and fails when their cost stops being linear.

## Requirements

FR3, NFR1, NFR2, NFR4

## Scope

### Files to Create
- `src-tauri/src/mux/ipc/pty_spawn/tests/strip_scaling_ratio.rs` — the scaling-ratio tests on the real write-path strip and the real one-call write-filter feed

### Files to Modify
- `src-tauri/src/mux/ipc/pty_spawn/tests/thread_cpu_time.rs` — the scaling-ratio judgment next to the CPU meter, and its unit tests
- `src-tauri/src/mux/ipc/pty_spawn/tests.rs` — registers the new test module, with a comment naming the feature, the task and FR3

## Design

Cross-task rules that apply here: IMPLEMENTATION.md Shared Components
("Scaling-ratio judgment"), D1 (the linearity criterion), D2 (the measured
production entries keep their contract), D3 (file ownership) and Conventions.
This plan does not restate them.

### The scaling-ratio judgment (`thread_cpu_time.rs`)

- Takes the thread CPU time measured at N (the smaller) and at 4N (the larger)
  and returns a verdict with the contract of IMPLEMENTATION.md Shared
  Components: linear exactly when the smaller time is above zero and the ratio
  larger / smaller is strictly below 8.
- The verdict carries both times and the ratio, and its displayed message shows
  all three, as the existing budget verdict shows its total and budget.
- It reads no clock and holds no platform-specific code. It is visible to the
  sibling test modules the same way `CpuMeter` is.
- The module doc comment's statement about which tests read a wall clock stays
  true: the new tests read none.

Unit tests, in the module's own tests:

- Fixed-duration cases, with no measurement: a ratio just below 8 is linear; a
  ratio of exactly 8 is not; a ratio above 8 is not; a zero smaller time is not,
  and judging it does not panic; the message holds both times and the ratio.
- The surrogate case, in the manner of the module's existing TS-4 test: a linear
  surrogate and a quadratic surrogate (the module's existing ones, or ones of the
  same kind) are each measured through a `CpuMeter` at N and at 4N on the test
  thread. The linear one is judged linear and the quadratic one is judged not
  linear. Each smaller measurement is about 100 ms or more of thread CPU time on
  a debug build, and the quadratic's larger measurement stays within a few
  seconds.

### The real-path guard (`strip_scaling_ratio.rs`)

- The unit, built as the target test builds its alternation: a lead followed by
  a strip target. One unit holds, for every `TARGETS` entry, the open-CSI lead
  (ESC [ 6) followed by that target and the lone-ESC lead followed by that
  target. The expected output of each part is its lead, `CSI_CLOSING` and the
  target's re-emitted C0 bytes; the expected output of an input is the
  concatenation of its parts' expected outputs.
- The inputs are N and 4N repetitions of the unit. N makes each smaller
  measurement about 100 ms or more of thread CPU time on a debug build, and
  makes the N input longer than `SCROLLBACK_FILTER_PENDING_CAP`.
- Strip test: `strip_pty_output_for_scrollback_write` is measured once on the N
  input and once on the 4N input, each through a `CpuMeter`. Each output equals
  its expected bytes, and the judgment of the two times is linear.
- One-call feed test: a fresh `ScrollbackWriteFilter` per size, fed the whole
  input in one call measured through a `CpuMeter`. The test asserts that the N
  input is longer than the cap, so both sizes take the overflow flush. Each
  output equals its expected bytes, the filter ends with no open CSI, and the
  judgment of the two times is linear.
- Each test writes its two times and the ratio to the test output; a failure
  message shows the verdict.
- Inputs, expected outputs and comparisons are built outside the measured calls.
- When the ratio reaches 8 on the production code this task starts from, that is
  reported as a failure (IMPLEMENTATION.md D2); the production code, the
  threshold and the input stay as specified.

### Registration (`tests.rs`)

The new module is declared among the feature test modules, with a one-line
comment naming mux-strip-concat-budget-overrun task0002 and FR3.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1 (FR3, NFR4): The scaling-ratio judgment judges a ratio just below 8 as
      linear, and a ratio of exactly 8, a ratio above 8 and a zero smaller time as
      not linear, without panicking; its message shows both times and the ratio.
- [ ] AC-2 (FR3): Measured through `CpuMeter` at N and at 4N on the test thread,
      a linear surrogate is judged linear and a quadratic surrogate is judged not
      linear (the TS-4 manner of `thread_cpu_time.rs`).
- [ ] AC-3 (FR3, NFR1, TM-2): The strip test runs the real
      `strip_pty_output_for_scrollback_write` on the alternating input at N and
      at 4N, each measured through `CpuMeter`; both outputs equal the expected
      bytes and the 4N / N ratio is judged linear (below 8).
- [ ] AC-4 (FR3, NFR1, TM-2): The one-call feed test runs the real
      `ScrollbackWriteFilter::feed` in one call on a fresh filter at N and at 4N,
      each measured through `CpuMeter`; it asserts that the N input is longer than
      `SCROLLBACK_FILTER_PENDING_CAP`; both outputs equal the expected bytes and
      the 4N / N ratio is judged linear (below 8).
- [ ] AC-5 (NFR1, NFR2, NFR4): In a single-threaded debug run, each smaller
      measurement of AC-2, AC-3 and AC-4 is about 100 ms or more of thread CPU
      time, as the times the tests write to the test output show. The new tests
      read no wall clock, add no budget, spawn no thread and measure each size
      once per entry; the judgment holds no platform-specific code.
- [ ] AC-6 (FR3): `CARGO_TARGET_DIR=src-tauri/target cargo test --manifest-path src-tauri/Cargo.toml --lib mux::ipc::pty_spawn::tests -- --test-threads=1`
      passes, the new tests and the existing `thread_cpu_time.rs` tests included,
      and against the base commit `TARGETS`, `Target`, `BUDGET` and the existing
      behavior of `CpuMeter` are unchanged.

## Test Notes

- AC-1 and AC-2 have a red before the judgment exists. AC-2 is also the evidence
  that the judgment can fail: the quadratic surrogate is rejected.
- AC-3 and AC-4 guard behavior that is expected to hold already on the base
  production code (linear cost), so the guard may pass as soon as it is written.
  When no red can be observed for them, record that with the reason, and point at
  AC-2 as the proof that the same judgment rejects a quadratic cost.
- Size N by one single-threaded debug run, reading the times the tests write;
  do not average noise by repeated runs (NFR2).
- The Windows clock (about 15.6 ms resolution) is the reason for the 100 ms
  sizing; the judgment itself is platform-neutral, and the tests compile on both
  platforms through `CpuMeter`.

## Out of Scope

- Changing production code, the threshold 8, `CpuMeter`'s existing behavior,

- Ratio guards for `strip_replayable_rich_content`, for the unit-aligned and
  64 KiB reads and for the ESC chain (FR3 names only the write-path strip and the
  one-call feed).
- Any wall-clock check.
