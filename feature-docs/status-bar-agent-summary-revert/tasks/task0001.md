# Task Plan: task0001 — Remove the agent-status summary from the status bar

## Goal

The status bar renders no agent-state indicator and its visible-row logic and
public API return to their pre-`c0a20fa` shape, with every piece of code that
existed solely to feed the summary deleted and all call sites updated.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, FR8, NFR1, NFR3, NFR4

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/ui/status_bar.rs` — delete the summary's drawing routine,
  segment type, builder function, layout constants, and the imports that only
  they used; restore the App-row drawing path, the App Line 1 visibility rule,
  and the three public function signatures; delete the summary-specific tests
  and adjust the surviving tests' call sites.
- `src-tauri/src/render/mod.rs` — stop building a summary for the frame and call
  the status-bar draw entry point with the view model and emoji resources only.
- `src-tauri/src/window_host.rs` — stop deriving a "has summary" flag and call
  the panel-height helper with the view model only.
- `src-tauri/src/app.rs` — delete the aggregate-counts query method that existed
  only for the summary, together with its passthrough unit test; leave the badge
  and pane-ID projections used by the tab bar and the mux sidebar untouched.

## Design

### What is removed from the status-bar widget

| Element | Reason |
|---------|--------|
| The routine that paints dots and counts anchored to an App row's right edge | It is the summary itself (FR1) |
| The segment value type (color + count) and the pure function that builds an ordered, zero-omitting segment list from per-state counts | Only inputs to the removed painter (FR4) |
| The five layout constants prefixed for the summary (font size, dot diameter, dot gap, segment gap, edge gap) | Only used by the removed painter (FR4) |
| The imports introduced for the summary: the egui rectangle type, the agent-status counts type, and the tab bar's state-to-color helper | Unreferenced after the above (FR4); the color helper itself stays public for the tab bar's own badge |
| The `agent_summary` parameter threaded through the App-row drawing helper | No caller supplies it (FR3) |

### Restored behavior

1. Row visibility: the App Line 1 row is visible when, and only when, its own
   resolved template content is non-empty — the same rule App Line 2 already
   uses. The disjunction with the summary's presence is removed from both the
   row-count computation and the drawing entry point (FR2).
2. Public signatures (see IMPLEMENTATION.md Shared Components for the full
   contracts): the row-count helper, the panel-height helper, and the draw entry
   point each drop their trailing summary-related parameter (FR3).
3. App-row drawing: an App row paints its template-derived left and right
   sections and nothing else. The left/right half-width split, tail truncation,
   zero inter-widget spacing, and emoji segmentation behavior are unchanged —
   do not alter that layout math while removing the summary overlay.

### Call-site updates

- The frame's terminal-drawing path passes the status-bar view model and the
  emoji resources; it no longer reads aggregate agent-state counts (FR5).
- The window host's panel-height reservation passes the view model alone; it no
  longer compares aggregate counts against a default value (FR6).
- The application state type loses the aggregate-counts accessor and its
  dedicated test (FR7). Confirm before deleting that no caller other than the
  two above referenced it.

### Test removals and retentions

Delete exactly these status-bar tests, whose subject no longer exists (FR8):
the four covering the segment-list builder (empty counts, ordering with zero
omission, zero-count omission, color agreement), the one asserting that a
summary makes App Line 1 visible with no template, and the three covering
drawing with, without, and alone-with a summary. Also delete the application
state's counts-passthrough test (FR7).

Every other test in the file is retained. Where a retained test calls one of the
three restored functions, update the call to the restored signature only —
expected values and assertions stay as they are.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: No status-bar row paints any agent-state dot, count, or
      agent-state-derived color; no agent-status type or helper is referenced
      anywhere in the status-bar widget.
- [ ] AC-2: With the status bar enabled, an empty App Line 1 template, and any
      set of agent states present in the model, the reported visible row count
      and panel height are identical to those computed with no agent states
      present, and App Line 1 is not among the visible rows.
- [ ] AC-3: The row-count helper, the panel-height helper, and the draw entry
      point each take only the arguments listed in IMPLEMENTATION.md Shared
      Components, and every call site in the crate compiles against them.
- [ ] AC-4: The aggregate-counts accessor on the application state no longer
      exists, while the badge and pane-ID projections used by the tab bar and
      the mux sidebar still exist and behave as before.
- [ ] AC-5: The eight summary-specific status-bar tests and the counts
      passthrough test are gone; every other test in the two touched test
      modules is still present and passing.
- [ ] AC-6: The default-feature build and the CLI-only (`--no-default-features`)
      build both succeed with no new warnings, and the library test suite passes
      with no new failures relative to the task's base commit.

## Test Notes

- AC-2 is the regression's direct expression and belongs in a unit test written
  first: construct a view model with an empty App Line 1 template and assert the
  row count and panel height, since the restored functions no longer accept an
  agent-related argument at all. The stronger form of this criterion — that the
  result cannot depend on agent state — is now structural (the functions have no
  agent input), so the test documents the visibility rule rather than a
  data-dependency.
- AC-1 and AC-3 are largely compile-time properties; verify them by the absence
  of the removed identifiers and by a clean build in both feature
  configurations, not by adding new assertions.
- AC-5 is a test-inventory check: record which tests exist before the change and
  confirm the retained set afterwards.
- Run the library tests single-threaded when the suite proves flaky; the
  project's replay tests are known to be non-deterministic under parallelism,
  and such failures are pre-existing rather than caused by this task. Compare
  against a baseline run on the task's base commit before attributing any
  failure to this change.
- TDD is awkward for pure deletions: write or adapt the AC-2 test first against
  the restored signature (it will not compile until the signature is restored),
  then perform the removals until it compiles and passes.
