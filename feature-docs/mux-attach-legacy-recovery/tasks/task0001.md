# Task Plan: task0001 — attach path legacy daemon recovery

## Goal

`emterm mux attach` recovers from a stale legacy-protocol daemon (shutdown +
respawn with the current binary) instead of dying on a rejected handshake,
while daemon-absent attach still errors exactly as today.

## Requirements

FR1, FR2, FR3, NFR1

## Scope

### Files to Create

None.

### Files to Modify

- `src-tauri/src/mux/daemon.rs` — extract the daemon-spawn logic (the
  socket-parent-dir creation, detached process spawn, readiness wait) out of
  `ensure_daemon_running` into a dedicated spawn function; refactor
  `ensure_daemon_running` to call the recovery probe and then the spawn
  function as needed; widen the recovery probe's visibility so the cli
  module can call it; add attach-path recovery tests to the existing test
  module.
- `src-tauri/src/mux/cli.rs` — in `execute_attach`, after the
  socket-existence check and before the bridge starts, run the recovery
  probe; on the "recovered" outcome, call the spawn function; then proceed
  to the bridge as today. Extract the pre-bridge sequence (existence check →
  recovery → conditional spawn) into a helper the tests can drive without
  starting the bridge.

## Design

### Spawn function (extracted, daemon.rs)

- Responsibility: everything the current `!daemon_running` branch of
  `ensure_daemon_running` does — create the socket's parent directory with
  restricted permissions, spawn the daemon as a detached background process
  (keeping the platform-specific detach branches as-is), and wait for
  readiness with the existing backoff loop.
- Precondition: no compatible daemon currently owns the socket.
- Postcondition: a daemon answers on the socket, or an error string
  identical to the current failure messages ("Failed to spawn daemon: …",
  "Failed to start mux daemon").
- `ensure_daemon_running` after the refactor: stale-socket cleanup →
  presence check → recovery probe (when present) → spawn function (when
  absent or recovered). Externally observable behavior unchanged.

### Attach pre-bridge helper (cli.rs)

Numbered flow:

1. Resolve the daemon socket path.
2. If the socket does not exist, return the current error (message
   unchanged: "No mux sessions to attach to (daemon not running)…").
3. Run the recovery probe against the socket.
4. Probe says compatible → done (return the socket path).
5. Probe says recovered → call the spawn function, then return the socket
   path.
6. Any probe/spawn error propagates as the command's error.

`execute_attach` calls this helper, then starts the bridge with the
returned socket path. Logging and nesting checks stay where they are.

### Visibility

The recovery probe (and its outcome enum) become visible to the cli module
(crate-internal visibility; no public API surface added).

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: With a fake legacy (adjacent-older protocol) daemon listening on
      the socket, the attach pre-bridge helper succeeds: the fake daemon is
      shut down, a new daemon is spawned from the current binary, and a
      subsequent handshake on the socket is accepted.
- [ ] AC-2: With a fake current-protocol daemon listening, the attach
      pre-bridge helper succeeds without spawning anything; the fake daemon
      still owns the socket afterwards.
- [ ] AC-3: With no socket present, the attach pre-bridge helper fails with
      the existing "No mux sessions to attach to" message, byte-identical to
      today's error.
- [ ] AC-4: All pre-existing daemon and mux tests pass unchanged after the
      spawn-function extraction (`ensure_daemon_running` behavior parity).
- [ ] AC-5: The crate compiles on the CLI-only feature set and the Windows
      target gates are respected (no `cfg` regressions introduced by the
      extraction).

## Test Notes

- AC-1/AC-2 build on the existing fake-daemon test infrastructure in the
  daemon.rs test module (`FAKE_LEGACY_VERSION` fake legacy server and the
  compatible-daemon counterpart used by the `recover_from_legacy_daemon_*`
  tests). Mirror their construction style and socket-path isolation.
- AC-1 spawns a real daemon process; keep the assertion to "handshake
  accepted", then shut the daemon down in the test (send the shutdown
  request the recovery path itself uses) so no process outlives the test.
  If the test needs the current executable, note that cargo test binaries
  are not the emterm binary — follow whatever pattern the existing daemon
  lifecycle tests use for spawning; if no such pattern exists and a real
  spawn is impractical, split AC-1 into (a) probe-returns-recovered plus
  (b) a spawn-function test against a free socket path, and record the
  deviation in the completion report.
- AC-3 is a plain unit test (nonexistent path).
- AC-4 is the existing suite (`--lib`), no new tests.
- TDD order: write AC-1..AC-3 tests against the helper first, then extract
  and wire until green.

## Out of Scope

- Protocol-version policy changes (PROTOCOL_VERSION handling stays as-is).
- Attach session-selection arguments (`_session` stays unused).
- GUI-side mux code.
