# Task Plan: task0003 — Make task0001's recorded test evidence true

## Goal

task0001's test-evidence record claims a full-suite pass count from a command
that cannot compile in this worktree, and lists a statically vacuous test as
evidence for one of its acceptance criteria. This task removes both
overclaims: the no-selection focus-loss test asserts the destination decision

`test-docs/focus-loss-drag-cleanup-test/task0001.tests.yaml` is rewritten so
every command it quotes is one that actually runs here, its counts come from

## Design

Read IMPLEMENTATION.md first: decision D2 (observational neutrality is the
acceptance bar), decision D4 (a recorded sink call is evidence of a write
request only) and decision D6 (what this feature's records and rows may claim,
shared with task0004). This task changes no production code and no production

### Part A — the no-selection test asserts the decision

Today the no-selection case routes its publish call through a guard whose
condition is a compile-time-decidable literal, so the publish never happens and
the closing emptiness assertion holds no matter what the state core returns.
The destination decision the core returned is bound but never examined.

Contract after this task:

- The destination decision returned for a no-selection termination is
  asserted directly against the value the preserved write rule (FR6) requires
  for that case: neither destination selected.
- Any publish step the test still performs is driven by a value-carrying
  optional binding, not by a literal the compiler can fold away, so the
  sink-emptiness assertion constrains the publish path rather than restating a
  tautology.
- The test keeps its current name, its module and its position among the
  window-free tests; it constructs no window host (NFR1) and adds no
  production code (NFR3).

### Part B — the evidence record states what was run

The record's failure lists and every command it quotes must describe this
worktree as it is:

- The default-feature test command named by SPEC AC-5 and by the workflow's
  own component `test_command` does not reach a test binary here: the
  `gui`-gated `swash_emoji` example embeds a font asset that is absent from
  this tree, so the command fails at compile time. `task0002.tests.yaml`
  already records exactly this. task0001's record must record the same fact,
  in the same terms, in both `baseline_failures` and `final_failures`, so the
  two records in one feature stop contradicting each other.
- The AC-6 entry names the command that was actually run to completion — the
  library test target form, which is also the command NFR1 names — together
  with the pass / fail / ignored counts that command produced before and after
  the implementation, and the count of tests this feature added.
- The AC-6 entry states plainly that SPEC AC-5's unqualified full-suite
  framing is blocked by a pre-existing, unrelated missing asset, rather than
  leaving it recorded as satisfied.
- The AC-4 entry's `red_reason` describes what the corrected no-selection test
  now pins, not what the vacuous version appeared to pin.

The pre-existing compile blocker is not this feature's to fix: the asset is
absent from the main tree as well, the manifest entry that needs it is outside
this feature's declared change set, and adding a binary asset is a separate
decision. The required outcome is an accurate record of the blocker, not its
removal.
