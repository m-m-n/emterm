# Task Plan: task0005 — Give the no-selection focus-loss test's emptiness assertion force

## Goal

The no-selection focus-loss test asserts the destination decision directly, but
never reaches `publish_to_targets`, so its closing sink-emptiness assertion is a
tautology and the `if targets.primary` FALSE arm of the publish helper is
exercised by no test at all. This task makes that publish call unconditional so
the emptiness assertion constrains the publish path, proves by mutation that it
now fails when the PRIMARY guard is deleted, and corrects the three prose sites
that already claim the opposite.

## Design

Read IMPLEMENTATION.md first: D2 (observational neutrality is the acceptance
bar), D4 (a recorded sink call is evidence of a write REQUEST only) and D6 (the
shared claim-accuracy contract the rework tasks are bound by). This task adds no
seam, no production code and no new shared contract; it drives the seams
task0001 already built (`consume_drag_termination`, `selection_publish_targets`,
`publish_to_targets`, the `RecordingSelectionSink` double).

### Part A — the publish call becomes unconditional

Today the test binds a statically-known empty optional and guards its publish
step with an optional-match on that binding. The compiler can decide the guard,
so the publish helper is never entered, the sink is trivially empty, and the
helper's no-PRIMARY path has no test behind it anywhere in the suite.

Contract after this task:

- The existing direct destination assertion stays exactly as it is — the
  decision returned by the state core is compared against the value FR6's
  preserved write rule requires for a no-selection termination (neither
  destination selected).
- The publish step is performed unconditionally with the decision the state
  core returned and a placeholder payload; the optional-match wrapper is
  removed. No branch of any kind remains in the test body.
- The closing sink-emptiness assertion therefore constrains the publish
  helper's behaviour for a both-destinations-false decision, rather than
  restating a fact the compiler already established.
- The test keeps its name, its module and its position among the window-free
  tests; it constructs no window host (NFR1) and adds no production code
  (NFR3).

### Part B — two mutation proofs, not one

The site has already survived one partial rework, so the corrected test is
accepted only when BOTH mutations are demonstrated, in the same task, each
reverted and re-run:

1. **Publish-guard mutation (new).** Deleting the PRIMARY guard in the publish
   helper so a PRIMARY write always happens must make this test's EMPTINESS
   assertion fail. Before this task, that mutation leaves the whole suite green
   — that is precisely the gap TS-10 names.
2. **Decision-inversion mutation (existing, kept).** Altering the destination
   predicate's no-selection arm to select PRIMARY must make this test's DIRECT
   destination assertion fail, as task0003 already demonstrated.

Each mutation is applied alone, observed, reverted, and the identical command
re-run green. Neither is ever committed.

### Part C — the three prose sites say what the test does

Three records currently assert that moving the empty literal into a binding
removed the dead branch. That explanation is untrue and is the same defect class
this feature exists to eliminate (D6 item 1), so each is rewritten to describe
the unconditional publish call, the emptiness assertion that can now fail, and
the mutation evidence that backs it. None of them may keep the
binding-versus-literal explanation, and none may claim coverage the corrected
test does not provide.
