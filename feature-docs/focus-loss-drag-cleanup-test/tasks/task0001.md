# Task Plan: task0001 — Window-free seam and window-free tests for the focus-loss local-drag cleanup path

## Goal

Make the focus-loss local-drag cleanup path drivable from bare tests with no
winit window, by extracting a window-free state core, a pure destination
predicate and an injectable selection-write sink, and by adding the tests that
drive them — with the shipped binary's behaviour unchanged.

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, FR7, NFR1, NFR2, NFR3, NFR4

## Scope

### Files to Create

None. Every change lands in existing files.

### Files to Modify

- `src-tauri/src/window_host/pointer_routing.rs` — hosts the new window-free state core and the pure destination predicate, and turns the local-drag terminator into a thin adapter that routes its two selection writes through the sink
- `src-tauri/src/window_host/mod.rs` — hosts the production implementation of the selection-write sink, delegating to the host's existing primary and clipboard write primitives without changing them
- `src-tauri/src/window_host/tests.rs` — hosts the recording sink double and every new bare test (truth table, state core, recorded payloads, end-to-end cleanup, empty-selection edge)
- `src-tauri/src/window_host/event_loop.rs` — verification only: the focus-loss arm's guard and terminator call expressions must remain character-for-character as they are today, and no edit to this file is expected

## Design

Read IMPLEMENTATION.md first: the layer structure, the Shared Components
contracts (state core, destination predicate, selection-write sink, pinned
test identifiers), the naming convention for NFR4, and decisions D1-D5 govern
this task and are not restated here.

### Composition after the change

1. The focus-loss arm calls the drag-in-flight guard; when it reports true it
   calls the terminator. Both call expressions keep their current text.
2. The terminator (the adapter) gathers plain values from the host and the
   application state: the current drag flag, the pending selection anchor, the
   resolved selection text, and the copy-on-select setting.
3. The terminator hands those to the window-free state core, which clears the
   drag flag, takes the pending anchor, asks the destination predicate for the
   destination set, and returns the consumed anchor together with that
   decision.
4. The terminator issues one sink call per selected destination, PRIMARY
   first, each carrying the resolved selection text verbatim.
5. The terminator returns the consumed anchor — the same value, in the same
   shape, that it returns today.

### Preserved write rule (FR6, do not repair)

| selection present | copy-on-select | text empty | destinations written |
|---|---|---|---|
| false | false | — | none |
| false | true | — | none |
| true | false | false | PRIMARY |
| true | false | true | PRIMARY |
| true | true | false | PRIMARY then CLIPBOARD |
| true | true | true | PRIMARY |

Nothing is written when there is no selection or when the active-tab lookup
fails. The empty-text PRIMARY write is current behaviour and is pinned by the
new tests, not corrected.

### Invariants this task must not break

- The terminator keeps its name, its module-internal visibility, its parameter
  order, its parameter types and its return type. An existing test reads the
  focus-loss arm's source text and matches both call expressions literally.
- The fold-click toggle stays on the release-path composition only; the string
  naming it never appears in the focus-loss arm's file.
- The copy-chord clipboard write in the key-routing module is untouched: an
  existing test source-scans that file for its literal write call and for that
  call's adjacency to the selection-clearing call.
- No existing assertion is weakened, relaxed or deleted.

### Recording double

The recording double implements the same sink abstraction as the production
implementation and appends one record per call, holding the destination and
the payload text. A test can therefore distinguish "PRIMARY only" from
"PRIMARY and CLIPBOARD", read back the exact text written to each, and assert
the call count and the call order.

## Test Notes

- Write the tests first. Each acceptance criterion above maps to at least one
  bare test in `src-tauri/src/window_host/tests.rs`; all of them run under the
  library test target with no window.
- Follow the style of the existing truth-table test in the same module for the
  eight-combination coverage: the eight rows may be one test per row or one
  table-driven test, as long as every name starts with the pinned prefix and
  every row is individually asserted.
- Edge cases worth an explicit assertion: empty resolved text with
  copy-on-select on (PRIMARY recorded, CLIPBOARD not recorded); no selection
  at all (nothing recorded, empty anchor returned); a pending anchor present
  while the drag flag is already false.
- TDD-awkward part: AC-5 and AC-6 are regression conditions over existing
  tests and the CLI-only check rather than new tests. Run the existing suite
  before touching anything to record the baseline, and re-run it plus the
  CLI-only check after each structural step.
- A recorded sink call is evidence of a write request, not of an OS-level
  selection or clipboard update (IMPLEMENTATION.md D4). Do not name a test in
  a way that claims the stronger thing.
