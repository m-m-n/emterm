# Task Plan: task0001 — Comment-aware attribute scan and end-of-source rule in the ac8 allowlist checker

## Goal

The ac8 allowlist checker in the program_status test module ignores `[`, `]` and `"`
inside line comments and block comments within an attribute, and reports an attribute
still open at the end of the source as a violation, so use lines after an attribute that
holds a comment are checked against the use-root allowlist again.

## Requirements

FR1, FR2, FR3, FR4, FR5, NFR1, NFR2, NFR3

## Scope

### Files to Create

None.

### Files to Modify
- `src-tauri/src/program_status/tests.rs` — the attribute scanner and its carried open-attribute state gain comment handling, the allowlist check gains the end-of-source rule, the four doc comments named under Design / Doc comments are updated, and a new self-test section is added after the program-status-ac8-use-line-forms section.

## Design

### Items touched (all in the ac8 part of the program_status test module)

| Item | Responsibility after this task |
|---|---|
| `Ac8OpenAttribute` (the open-attribute state carried to the next line) | Holds the bracket depth, the string state and the block-comment nesting level (zero when not inside a block comment). The line-comment state is never part of it. |
| `ac8_scan_attribute` | Scans attribute text starting from a given carried state, applying the scanner rules below; reports either the text after the closing `]` or the state still open at the end of the text. |
| `ac8_after_leading_attributes` | Role unchanged. Every freshly opened attribute starts at depth one, outside a string literal and at block-comment level zero. |
| `ac8_check_allowlist` | Rules A and B unchanged. Additionally keeps the trimmed physical line holding the `#[` of the attribute currently carried, and after the last line applies the end-of-source rule below. |

### Scanner rules

Precedence is top to bottom. A two-character token (`//`, `/*`, `*/`) is consumed as a
unit, so its characters never start or end another token.

1. Inside a string literal: unchanged. A backslash makes the next character part of the
   literal, an unescaped `"` closes it, and everything else — `//`, `/*`, `[`, `]`
   included — is string content (Assumption A1).
2. Inside a block comment (level one or more): `/*` raises the level by one and `*/`
   lowers it by one; the block comment ends when the level returns to zero. Every other
   character — `[`, `]`, `"` and `//` included — is comment content (FR2, Assumption A5).
3. Otherwise (attribute code): `//` starts a line comment that runs to the end of the
   scanned text, which is the end of the physical line; the scan then reports the
   attribute still open with its current depth, outside a string literal and at
   block-comment level zero (FR1). `/*` opens a block comment at level one. `"` opens a
   string literal. `[` and `]` change the depth, and the `]` that brings the depth to zero
   closes the attribute.

Carry-over: when the text ends with the attribute still open, the depth, the string state
and the block-comment level carry to the next line (FR2). A line comment never carries
(FR1).

### End-of-source rule (FR3)

Postcondition of `ac8_check_allowlist`: when the source ends with an attribute still
open — in attribute code, inside a string literal of that attribute, or inside a block
comment of that attribute — the returned list ends with exactly one additional violation.
It is built with `ac8_violation` from the trimmed physical line holding the `#[` of that
attribute, its problem text contains the phrase "does not close before the end of the
source", and it is appended after every other violation (Assumption A6). The line named
is the one holding the still-open attribute's `#[`, also when that line first closes an
attribute carried from an earlier line and then opens a new one that stays open. When no
attribute is open at the end of the source, the returned list is exactly what the
per-line rules produce.

### Doc comments (NFR2)

The doc comments of `Ac8OpenAttribute`, `ac8_scan_attribute`,
`ac8_after_leading_attributes` and `ac8_check_allowlist` describe the comment handling
(FR1, FR2) and the end-of-source rule (FR3) consistently with the behavior above. A
statement that every `[`, `]` or `"` outside a string literal is syntax no longer appears
without the comment exception.

In the criteria below, `\n` inside a quoted source marks a line break.

## Out of Scope

- Comments outside an attribute's `#[..]`: before the first `#[` on a line or between
  attributes on the same line (Assumption A2).
- Char literals and raw strings inside attributes (Assumption A3).
- Any change to `src-tauri/src/program_status.rs`, to rules A and B, to the allowlist
  constants or to the text format of `ac8_violation`.
- Renaming or editing existing ac8 tests (FR5); consequently no predecessor feature's
  test-docs record needs updating.
- A source that ends while a bare use line is still waiting for its root line (behavior
  unchanged).
