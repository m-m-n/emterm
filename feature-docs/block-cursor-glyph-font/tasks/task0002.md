# Task Plan: task0002 — align overlay glyph with grid pass (rework)

## Goal

Close review round 1's HIGH findings by aligning the block-cursor overlay
glyph path with the grid pass on three axes: vertical baseline (add
`v_pad`), HiDPI scale (apply `pixels_per_point`), and per-frame allocation
budget (skip pixel extraction / ColorImage build on texture-cache hit).
Also apply the GlyphFit horizontal shrink so wide-advance fallback glyphs
stay inside the cursor rect.

## Requirements

Refines FR2, NFR1, NFR3 (HiDPI = cross-platform behavior consistency).

## Design

### Behaviors to achieve

- **Baseline parity**: overlay glyph's baseline equals
  `rect.min.y + v_pad + base_ascent` where `v_pad = ((cell_h -
  base_line_height) * 0.5).max(0.0)` — the same formula the grid pass
  uses at `terminal_grid_pass.rs:479-483`.
- **HiDPI parity**: overlay `font_px` equals
  `theme.font_size_px() * pixels_per_point.max(1.0)`, obtained from
  `painter.ctx().pixels_per_point()`. The destination rect passed to
  egui MUST be sized in logical pixels — divide the raster's physical
  dimensions by the same `pixels_per_point` factor when placing
  it, so the raster shows at its intended logical size.
- **GlyphFit parity**: apply the same `sx = (cell_w / advance).min(1.0)`
  horizontal shrink the grid pass uses when the fallback glyph's advance
  exceeds the cell width. `OverlayGlyph.advance` already carries the
  advance; use it.
- **Per-frame allocation**: on a texture-cache hit, no `Vec<u8>` for
  RGBA pixels and no `egui::ColorImage` are allocated. The meta lookup
  MUST return without touching `extract_region_rgba`; only the loader
  closure invoked on cache miss reaches into pixel extraction.

### Processing flow

1. `draw_block_cursor` resolves cell + rect (unchanged).
2. Compute `scale = painter.ctx().pixels_per_point().max(1.0)` and
   `font_px = runtime_font_size_pt * PT_TO_PX * scale`.
3. Compute `v_pad` and `base_ascent` via the shared helper — same
   inputs as the grid pass.
4. Ask the font module for the overlay glyph's **meta** (key, width,
   height, bearing, advance, glyph identity for later pixel
   extraction). No pixel extraction here.
5. Ask `get_or_create_overlay_texture` for the `TextureHandle`. On
   miss, the loader closure calls the pixel-extraction step and builds
   the `ColorImage`. On hit, neither runs.
6. Compute `sx = (cell_w_px / max(advance, width)).min(1.0)` (guard
   against zero) and scale the destination rect horizontally.
7. Paint the texture inside the destination rect, positioned so the
   raster's baseline aligns with `rect.min.y + v_pad + base_ascent`
   (divide bearing / raster dimensions by `scale` to convert from
   physical to logical pixels for egui).

### Preconditions / postconditions

- **Pre**: same as task0001.
- **Post**: for the same `(code_point, size, weight, style, scale)`,
  the overlay glyph's egui `TextureHandle` corresponds to the SAME
  `GlyphKey` the grid pass would produce; the overlay's on-screen
  position of that glyph is within sub-pixel tolerance of the grid's
  position for the same cell.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: `draw_block_cursor` reads `pixels_per_point` from the
      painter's egui context (or receives it via `App`) and multiplies
      it into `font_px` before computing the `GlyphKey`. Verified by a
      unit test running `resolve_overlay_glyph` at `scale = 2.0` and
      asserting the `GlyphKey` matches the grid-side computation for
      the same scale.
- [ ] AC-2: The overlay's baseline formula equals
      `rect.min.y + v_pad + base_ascent`, with `v_pad` computed from
      `(cell_h - line_height) * 0.5` (clamped at 0). Verified by a
      unit test asserting the computed baseline for known metrics
      matches the grid-pass formula.
- [ ] AC-3: The `v_pad` / `line_height` computation is exposed as a
      shared helper in `render::font` and is called from both the
      overlay path AND (if the file is touched) the grid pass. If the
      grid pass is not refactored, `IMPLEMENTATION.md` gains a note
      explaining the deliberate deferred de-duplication and the
      drift-risk it accepts.
- [ ] AC-4: On the second consecutive `paint_overlay_glyph` call for
      the same `(code_point, size, weight, style, scale)`,
      `extract_region_rgba` is NOT invoked, and no `egui::ColorImage`
      is constructed. Verified by a unit test counting invocations
      (mock rasterizer counter, plus a wrapper that flags
      `extract_region_rgba` calls per invocation).
- [ ] AC-5: When the covered glyph's advance exceeds the cell width,
      the overlay's destination rect is horizontally scaled by
      `sx = (cell_w_px / advance).min(1.0)`. Verified by a unit test on
      the fit-selection helper with a synthetic wide-advance glyph.
- [ ] AC-6: Existing task0001 acceptance tests remain green with no
      behavioral edits. Verified by running the crate test suite.
- [ ] AC-7: `CARGO_TARGET_DIR=src-tauri/target cargo check
      --manifest-path src-tauri/Cargo.toml` and the same with
      `--no-default-features` both pass.
