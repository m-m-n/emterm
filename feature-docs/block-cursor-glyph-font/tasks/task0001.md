# Task Plan: task0001 — block cursor overlay glyph via swash

## Goal

Rewire the focused block cursor's covered-glyph re-draw in
`render::cursor::draw_block_cursor` to source its raster from the same
font resolver / rasterizer / cache the wgpu grid pass uses, so the
glyph shape matches the grid pixel-for-pixel (Inconsolata "0" stays
slashed, etc.).

## Requirements

FR1, FR2, FR3, FR4, FR5, FR6, NFR1, NFR2, NFR3, NFR4.

## Design

### Responsibilities

- `draw_block_cursor` (`render::cursor`):
  1. Compute rect + covered cell (unchanged).
  2. Paint the rect in cursor color (unchanged).
  3. When `cursor_glyph_paintable(&ch)` is true (unchanged gate):
     resolve the glyph via the shared font module contract and paint
     the resulting raster inside the rect, using the resolved cell bg
     color as the glyph color, aligned to the cell's baseline/metrics
     the same way the grid pass would place it.

- Shared font-module entry point (Shared Component in
  IMPLEMENTATION.md): given `(code_point, cell_metrics, font_size,
  weight, style)`, look up (or rasterize on first miss) the same
  raster the grid pass would use. Reuse the existing cache; do not
  build a parallel one.

### Processing flow (numbered, no code)

1. Enter `draw_block_cursor` — existing screen-row / column / focus
   guards run first.
2. Compute the covered cell's fully-resolved style via
   `resolve_cell_style_from_packed` (unchanged).
3. Paint the cursor rect with cursor color (unchanged).
4. If `cursor_glyph_paintable(ch)` is false, exit (unchanged).
5. Ask the font module for the raster of `ch` at the current cell size
   / weight / style. On miss, the module runs the same swash →
   ab_glyph → .notdef fallback the grid uses.
6. Paint the raster inside the rect, positioned by cell metrics (same
   baseline / advance the grid pass uses for a normal cell), colored
   with the covered cell's fully-resolved bg color.

### Preconditions / postconditions

- **Pre**: `draw_block_cursor` is only entered when the block-style,
  focused, visible, blink-on gate has passed (`super::draw_cursor`
  contract, unchanged).
- **Post**: after this function returns, the covered cell shows the
  same glyph identity, baseline, and advance as if the grid pass had
  rendered the character with the resolved bg as its foreground.

## Acceptance Criteria (MANDATORY)

- [ ] AC-1: When `draw_block_cursor` needs to paint a glyph, the raster
      it uses comes from the same rasterizer / cache the grid pass
      uses. Verified by a unit test that resolves the same
      `(code_point, size, weight, style)` from both paths and asserts
      cache-key or raster-identity equivalence.
- [ ] AC-2: When `cursor_glyph_paintable(&ch)` returns false, no glyph
      raster is drawn (only the rect fill). Verified by a unit test
      driving both branches of `cursor_glyph_paintable`.
- [ ] AC-3: The glyph color passed to the overlay path equals
      `resolve_cell_style_from_packed(..., selected).bg` for the
      covered cell — reverse video / selection / dim / hidden still
      apply. Verified by a unit test on the color-plumbing function
      (extract the color-selection step so it is testable without an
      egui context).
- [ ] AC-4: Wide (2-cell) glyph behavior: `block_cursor_rect` returns
      a 2-cell rect, `resolve_cursor_glyph_col` snaps the
      trailing-half column to the leading column, and the glyph is
      requested / drawn exactly once at the leading column.
      Verified by the existing wide-glyph unit tests staying green
      plus one new test asserting the glyph lookup fires once.
- [ ] AC-5: `FontId::monospace(...)` is no longer used inside
      `draw_block_cursor` (no fallback to egui's built-in monospace
      for the overlay glyph). Verified by grep or a compile-time
      assertion — the string must not appear on the covered-glyph
      path.
- [ ] AC-6: Overlay glyph path allocates no new `egui::TextureHandle`
      per frame for a glyph already present in the shared cache
      (NFR1). Verified by a unit test counting texture creations
      across two consecutive resolves of the same glyph.
- [ ] AC-7: The wgpu grid instance-data assembly path is unchanged —
      no cursor-state-dependent fields added or read (NFR2). Verified
      by inspection + the terminal_grid_pass tests staying untouched
      and green.
- [ ] AC-8: The doc comment block above `draw_block_cursor` describes
      the shared-font path and cites the render-cpu-optimization
      invariant (NFR4). Verified by review inspection (spec
      compliance).
- [ ] AC-9: `CARGO_TARGET_DIR=src-tauri/target cargo check
      --manifest-path src-tauri/Cargo.toml` and the same with
      `--no-default-features` both pass. Verified by running them.
- [ ] AC-10: All existing `render::cursor` unit tests remain green
      without behavioral edits (only additions are allowed).
      Verified by running the crate test suite.

## Test Notes

- Unit-testable pieces (add these):
  - Shared-font entry point contract test (AC-1, AC-6): mock or use
    the real resolver with a fabricated font and assert cache-key
    equality between grid and overlay lookups; assert one lookup does
    not create a fresh texture on the second call.
  - Color-selection helper test (AC-3): extract the "which color the
    overlay glyph paints with" step into a pure function taking the
    packed fg/bg/flags/selected inputs and asserting it equals
    `resolve_cell_style_from_packed(...).bg`.
  - Paintability gate test (AC-2): call the paint-decision helper
    with a paintable and a non-paintable code point and assert the
    correct branch is taken.
  - Wide-glyph lookup count test (AC-4): drive the code path with a
    wide glyph and assert the glyph-request helper is invoked exactly
    once, at the leading column.

- The `egui::Painter::text(...)` call itself has no test hook (matches
  existing `cursor.rs` test module philosophy — pure geometry / logic
  is tested; painter I/O is not). MT-level manual visual check covers
  the final on-screen pixels.

- The existing geometry tests (`block_cursor_rect_*`,
  `preedit_underline_runs_*`) MUST stay green with no edits. Any need
  to change them is a red flag (scope creep).

## Out of Scope

- IME preedit rendering (owned by `draw_preedit_overlay`, separate
  issue per SPEC scope).
- Broadening `cursor_glyph_paintable` to include emoji or control
  glyphs (deliberate no-change; see D3 in IMPLEMENTATION.md).
- Any change to the wgpu grid instance-data schema or the grid pass'
  glyph pipeline (violates NFR2).
- Baseline / advance recomputation in the grid pass — the overlay
  must consume whatever the grid pass already computes, not replace
  it.
